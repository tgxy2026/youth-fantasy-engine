## 一、本次发现

### R8 / P1：导入新角色会丢失当前卡片未保存的编辑

- 位置：`src/components/world/CharacterSheet.tsx:156`、`:193`、`:292`。
- 复现：在示例项目主要角色中修改陈渊的“核心性格”，不点击保存；导入另一张角色卡；切回陈渊。
- 实际：字段恢复原值；直接读取隔离 IndexedDB 的原卡记录，也没有刚才输入的内容。
- 原因：`handleImport` 同时设置 `records`、`activeId`、`draft` 为新卡；先声明的 draftRef 同步 effect 已把 ref 更新为新卡，随后切卡 effect 虽然判断应保存旧卡，实际保存的却是新卡。旧草稿被替换。
- 建议：在替换草稿/切换选择前，明确等待当前脏草稿保存成功，并同步对应内存记录；保存失败应保留旧草稿与选择。不要依赖 effect 顺序猜测切换前草稿。同类手工新增、AI 新增路径也应一起排查。
- 复现脚本：`.workbuddy/tmp/review-3.1-card-io-2026-10-16.cjs`。
- 结果日志：`.workbuddy/tmp/review-3.1-2026-10-16-browser.log`，原有 28 项通过，新增草稿保护断言失败；日志含原卡落库值。

### R9 / P1：仅有卡片标题的角色导出丢名字、导入判重失效

- 位置：`src/lib/storage/cardIO.ts:117`；相关创建/重命名路径在 `src/components/world/CharacterSheet.tsx:251`。
- 手工新建卡片会产生合法记录 `{ name: '手工新建角色', data: {} }`；卡片标题与 data 内“姓名”并非始终同步。
- 实际：`cardRecordsToTableRows` 只读取 `data`，导出 CSV 的“姓名”为空；再次导入“手工新建角色”时，已有记录的姓名仍为空，`dupExisting` 为 false。
- 影响：导出的角色无法完整往返；姓名必填校验可能使它无法默认重新导入；同名角色还可能重复创建。重命名后标题与字段不一致的旧数据也应纳入处理。
- 建议：明确卡片标题与姓名字段的统一规则，至少对缺失姓名使用现有卡片名兜底，并让导出、判重、重命名采用一致口径；兼容历史卡片，不能只修新建路径。
- 复现脚本：`.workbuddy/tmp/review-3.1-card-name-2026-10-16.cjs`（隔离页面直接调用真实 schema 与适配函数，不写项目数据）。结果：`exportedName: ''`、`dupExisting: false`。

### R10 / P2：角色专用导入说明没有接入实际下载入口

- 位置：`src/components/sheets/TableImportDialog.tsx:178`、`src/lib/storage/cardIO.ts:184`。
- 已编写并测试 `buildCardImportGuide`，但实际下载入口始终调用通用 `buildImportGuide(tab)`；角色专用函数没有产品调用方。
- 因此，用户下载不到专门补充的卡片姓名、多值引用及立绘不进入 CSV 的说明。纯函数单测通过不能证明界面下载链路已接通。
- 建议：给复用弹窗提供角色说明生成器或内容参数；补真实下载内容断言。
