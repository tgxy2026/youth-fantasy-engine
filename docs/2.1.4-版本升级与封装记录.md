## 一、版本号升级（2.1.3 → 2.1.4）

唯一版本源是 `package.json`；按「只改根版本位、绝不碰依赖自身 version」外科式处理。

| 位置 | 改动 |
|---|---|
| `package.json` 顶层 `version` | `2.1.3` → `2.1.4`（命中 1 处） |
| `package-lock.json` 顶层 `version` | `2.1.3` → `2.1.4` |
| `package-lock.json` 的 `packages[""].version` | `2.1.3` → `2.1.4` |
| `src/lib/env.ts` 注释 | 「正式版为 \`v2.1.3\`」→ `v2.1.4`（纯注释，构建时被剥离） |

`package-lock.json` 里 `"version": "2.1.3"` 共出现 **3 处**：前 2 处是根本体，第 3 处是某个依赖自己的版本号 → **只替换前 2 处**，依赖处原样保留。
`git diff --stat` 恰好 **3 文件 / 4 行（+4 −4）**，无污染。

## 三、封装过程

命令：`node scripts/build-desktop.mjs`（三步：`tsc --noEmit` → `vite build` → `electron-builder` NSIS），**全程无沙箱**。

### 第一次：失败（NSIS 写安装包）

- `tsc` / `vite build` 均通过；`[after-pack] ✅ 元数据与图标写入成功（第 5/12 次尝试）`
- **NSIS 阶段失败**：`Can't open output file` / `Error - aborting creation process`
- 体积闸门正确拦截：`安装包体积异常：0.49 MB，低于阈值 50 MB → 判定为 NSIS 空壳`
- 排查：磁盘剩余 1009 GB（非空间）；tsc/vite 正常；空壳产物可正常删除（非句柄锁死）

### 第二次：成功

- `[after-pack] ✅ 元数据与图标写入成功（第 4/12 次尝试）`
- 日志内可见 `Above command failed, retrying 3 more times` 直至成功 → **本机 NSIS 写入是间歇性失败**，electron-builder 自带重试在第二次跑里救回来了
- 结论：**重跑一次即可**；若重试耗尽（`retrying N more times` 用尽后仍失败），先删掉空壳 `Setup-<ver>.exe` 再重跑
