## 一、为什么要拆

| 指标 | 拆分前 |
|---|---|
| 文件行数 | **1,613 行**（全项目第 2 大） |
| 被引用处 | 69 个文件（`import * as db` 与具名导入混用） |
| 内部结构 | 其实**已经是 22 个注释分段**（项目 / 卷 / 章 / 表单 / 台账 / 迁移 / 导出导入 / 备份…），只是全挤在一个文件里 |
| 主要代价 | 每次改一处都要在 1,600 行里翻找；`git blame` / 冲突 / 阅读成本都在高位 |

**关键判断：它是"被挤在一条走廊里的 22 个房间"，不是"一团揉在一起的逻辑"。** 所以拆分的风险远低于直觉——只要**不动任何一行实现**。

## 二、切分方案（按已有的 `// ===== 段 =====` 精确切，不改语句）

```
src/lib/db.ts                    31 行   门面：只做再导出
src/lib/db/
  idbMigrations.ts              240 行   IndexedDB schema 迁移（getDB 的 upgrade 各段）+ Vdb / Vtx 类型
  core.ts                       434 行   ★底座：连接 / 适配层(idbOps,ops) / 云盘开关 / 当前项目 / touchProject
  projects.ts                   249 行   项目 CRUD / 统计 / 导出导入 / loadAllData
  volumes.ts                     61 行   卷 CRUD + 卷台账（含 VOL_LEDGER_PREFIX）
  chapters.ts                   144 行   章 CRUD + 时光机快照 + 回收站
  tabs.ts                       118 行   表单 / 表格行 / 卡片记录 / 自定义下拉选项
  meta.ts                        44 行   meta / 项目设置 / 每日码字统计
  tavernReports.ts               25 行   酒馆推演报告（项目级数据）
  migrations.ts                 175 行   运行时数据迁移（台账/章节号/地图）+ runMigrations
  backups.ts                    214 行   自动备份 + applyBundleToProject
                                 ─────
                                 1,735 行（比原来多 122 行 = 各模块的 import 头与分层注释）
```

### 依赖方向（严格自下而上，无环）

```
idbMigrations
   └─ core
        ├─ projects ──→ volumes ──→ tabs
        ├─ chapters ──→ meta
        ├─ tavernReports
        └─ migrations / backups        （最上层，可依赖下面全部）
```

**唯一"下沉"的函数是 `touchProject`**：卷 / 章 / 页签 / 备份都要「顺手刷新项目更新时间」。若留在 `projects`，这四个域会全部反向依赖 `projects` 并绕成环——所以它和 `currentProjectId` 一起放进底座 `core`。

## 三、对外契约：76 → 76，逐名比对

**不靠"tsc 通过"作证**（tsc 不会告诉你少了一个没人 import 的导出）。做法是机械比对：

```
① git show HEAD:src/lib/db.ts             → 解析出 76 个导出名（值 + 类型）
② 新门面按规则展开（core/volumes/meta 用显式名单，其余 export *，idbMigrations 不进门面）
③ 集合求差
```

结果：**丢失 0 个、新增 0 个**。

同时用**显式名单**再导出 `core` / `volumes` / `meta` 三个模块——因为它们的内部成员（`ops`、`currentProjectId`、`VOL_LEDGER_PREFIX`、`addDailyWords`）需要跨模块使用，若用 `export *` 会把这 4 个内部名泄漏进公开 API。

### 顺带修正的 7 处失效注释
`desktop.ts`、`desktopCloudSync.ts`、`syncCore.ts`、`CloudFileSyncBar.tsx`、`Desktop.tsx` 里写着「见 `db.ts` 的 mirrorCloudCacheToLocal / saveConflictCopy / makeCloudStoreWrapper …」的指向，已统一改为 `db/core.ts`。**注释指向失效不会报错**，只会让后来的人白找一轮。

## 五、🔴 负面对照（本轮最值钱的两条证据）

### ① 测试内存桩：改对了没有，靠"改错一次"证明
`tests/build-test.mjs` 用 esbuild 插件把 `'./desktop'` 换成内存桩。存储代码下沉一层后相对路径变成 `'../desktop'`，**旧 filter 会漏桩**。

把 filter 临时改回 `/^\.\/desktop$/` 再跑：测试**立刻**报
`ReferenceError: indexedDB is not defined`（走了真实 IndexedDB 分支）。
→ 证明：这个修改是**必需**的，且失败是**响的**（不是静默通过）。改回后 `backup` 测试 14/14 通过。

### ② 审计工具的三重语料净化：门面会"掩盖"死导出
拆分后发现 `audit-scan §1 死导出候选` 里 `setStoreOps` **凭空消失**。追查真因不是重构弄丢东西，而是**工具失明**：

| 污染源 | 为什么不算"有人用" |
|---|---|
| 再导出（`export * from` / 多行 `export {…} from`） | 门面只是把整层名字"提"了一遍 |
| 生成物 `tests/.xxx.test.mjs` | build-test.mjs 打包出的**整份源码副本**，被 import 模块的实现整段抄进来 |
| 工作区临时文件 `.workbuddy/**` | 审计中间产物，出现符号名纯属巧合 |
| 注释 | `audit-dead` 早已去注释，`audit-scan` §1 原先漏了 |

三支脚本已加固（`audit-scan` / `audit-dead` 的 `stripReexport()` + `walkAny` 跳过 dot 前缀；`audit-arch` 增加门面白名单）。
**修复后实测：死导出候选 176 → 237、`audit-dead` B 段 176 → 231**——多出的正是**此前被长期掩盖的真死导出**。

> ⚠️ 特别注意 `stripReexport` 必须是**状态机**：门面的 export 清单是多行写法（`export {\n A,\n B,\n} from './x'`），单行正则会漏掉 —— 这正是第一次加固后仍失明的原因。
