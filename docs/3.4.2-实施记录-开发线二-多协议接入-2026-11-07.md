验收复核（`docs/3.4.2-验收复核-2026-11-07.md`）确认两条偏差，本轮按「补完再发布」路径整改。

### 7.1 D-1｜三家常量协议缺「兼容降级 + 流式转非流式」

**整改前**：`anthropic` / `gemini` / `openai-responses` 只发一次请求，400 直接抛错。规划 §4.F.3 要求降级「按协议分别实现，不得串味」。

| 协议 | 会撞的 400 | 处理 |
|---|---|---|
| Anthropic | 部分模型只接受 `temperature` 0–1；网关不认 `output_config` | 撤参数重发 |
| Gemini | 老网关不认 `responseJsonSchema`；个别模型温度区间更窄 | 撤参数重发 |
| Responses | 推理系模型拒绝 `temperature ≠ 1`（原话含 `with this model`） | 撤参数重发 |

**实现**：新增 `src/lib/aiCore/protocols/shared.ts` 的 `shouldDegradeSamplingOn400()` / `nextWireFlags()` / `initialWireFlags()` / `budgetExhaustedMessage()`，三个 driver 各自带 `WireFlags{ format, sampling }` 逐档撤：先撤被点名的结构字段 → 再撤采样 → 最后才在「说不清」的 400 上撤结构字段。

**判据为什么不能复用 `shouldDegradeOn400()`**：它把 `model` 当硬失败关键词，而推理系模型的原话是 `Unsupported parameter: 'temperature' is not supported with this model.` —— 照那条会被判成「配置写错、别重试」。故新判据先排硬失败（模型名 / 鉴权 / 额度 / 内容政策 / 上下文），再认采样关键词。

**流式转非流式**：`streamGenerateContent` / `response.output_text.delta` / 具名事件族在兼容网关上常不标准 ⇒ 解析不出内容时退一次非流式（`alt=sse` 端点换成 `:generateContent`、`stream:false`）。

**预算**：`MAX_REQUESTS_PER_CALL = 3` 一本账，400 降级与流式重试共用；用尽即停并在报错里写明「已发出 N 次请求」；`disableCompatibilityRetry`（续写规划等严格单次任务）全程只发一次。用量里回填 `attempts`。

### 7.2 D-3｜网页形态没有按 CORS 结果标注协议可用性

**整改前**：三家协议在网页形态照样可选、可保存，界面没有任何「未验证」标注。

**实现**：新增 `src/lib/aiCore/webCors.ts` —— 一张带状态的四态台账（`pass` / `blocked` / `not-run` / `not-applicable`），界面照它说话，不各写判断。

| 落点 | 行为 |
|---|---|
| 编辑表单头部 | 协议名旁出现琥珀徽标「网页未验证」 |
| 协议下拉下方 | 说明「浏览器直连厂商 / 尚未取得通过结论 / 失败可能是跨域 / 密钥浏览器可见」 |
| 模型列表行 | 同一徽标（`title` 挂完整说明）；被 P9 禁掉的本机配置不重复标 |
| Ollama 在网页形态 | 说「不连接本机（产品策略）」，不冒充 CORS 结论 |
| 桌面 / 便携 | 提示函数返回空串，界面逐字不变 |

**状态为何全是 `not-run`（如实）**：本轮浏览器侧一律 `Failed to fetch`，Node 侧 OPTIONS 或超时、或 403 且无 CORS 头，且本机出网走代理 —— `Failed to fetch` **分不清**「跨域被拒」与「网络不可达」。所以既不写「网页可用」，也不写「被 CORS 拒绝」。拿到干净网络后逐家重跑预检，把结论填进 `PROTOCOL_WEB_CORS` 即可，界面自动跟随。

**顺带补上的一条真措施**：Anthropic 官方要求浏览器直连时带 `anthropic-dangerous-direct-browser-access: true`，此前没带 ⇒ 网页形态必被拦。现在仅在 `WEB` 为真时下发（桌面 / 便携请求逐字节不变），模型清单请求同办。
