# 2.3.0 · D4 组件拆分收尾：方案

> 起因：`docs/2.3.0-项目重构必要性评估.md` 阶段 3（D4）——「6 个 ≥1,000 行组件未拆完」。
> 本文是**只读分析产物**：不改任何代码，先定切分表与顺序，请老大拍板后再动手。
> 手法沿用 2.2.1 已验证的 playbook（`docs/2.2.1-巨型组件拆分记录-2026-09-19.md`）：
> `dep-cost` 量化依赖 → 状态搬进 `useXxxModel` → 子组件只收 `model`／props → **实机指纹逐项比对** → 负面对照。

---

## 一、现状：实测 ≥1,000 行的共 **5 个**

评估文档写「6 个」，实测口径下是 5 个（当时那 1 个应是已拆的 `TavernFree`/`TavernControl` 旧值）。逐个量化后长这样：

| 文件 | 行数 | 主块 | 现成切分点 | 外部消费面 |
|---|---:|---|---|---|
| `GeoMapEditor.tsx` | 1,377 | 主组件 127–1007（**881**） | ✅ **7 个子组件**（368 行）+ **14 个纯函数/类型**（110 行） | `App.tsx:22` 默认导入（静态） |
| `TavernCard.tsx` | 1,352 | 主组件 113–1352（**1,240**） | 3 个原子件（41 行）+ 4 段 JSX 分区 | `App.tsx:44` lazy |
| `TavernPlot.tsx` | 1,012 | 主组件 61–1012（**952**） | 10 处分区注释；3 段逻辑（约 210 行） | `App.tsx:42` lazy |
| `useNovelEditorModel.ts` | 1,132 | hook 主体 175–1130（**956**） | ✅ **12 个纯函数/常量/类型**（130 行） | `NovelEditor.tsx:55` |
| `useTavernFreeModel.tsx` | 1,244 | hook 主体 97–1242（**1,146**） | 按功能区（记忆/数值/发送） | `TavernFree.tsx:79`、`TavernFreeSessionList.tsx:11`(type) |

**两条重要事实**（决定了工作量）：

1. 🔴 **零测试耦合** —— `tests/` 里对这 5 个文件**没有任何引用**（不像 D1 那样有「按路径读源码 + 正则断言」，需要同步改）。验收完全靠 `tsc` + `eslint` + `run-all` + `importCycles` + **实机指纹**。
2. 🔴 **需要新写 3 个实机脚本** —— 既有资产只有 `ui-tavern-control` / `ui-table-sheet` / `ui-novel-editor` / `ui-tavern-free` 四支；`GeoMapEditor` / `TavernCard` / `TavernPlot` 三个**没有**，要按 `ui-refactor-check.mjs` 的骨架新写。

## 三、执行顺序（按「切分点明确度 ÷ 验证成本」）

| 序 | 组件 | 理由 | 新增实机脚本 |
|---|---|---|---|
| **1** | `GeoMapEditor` | 切分点全是现成顶层块（7 子组件 + 14 纯函数），零分析成本；静态导入、不涉门控 | `ui-geo-map.mjs` |
| **2** | `useNovelEditorModel` | 头部 130 行纯函数一刀切走；**已有 `ui-novel-editor.mjs`** 可直接当指纹，验证成本最低 | 复用 |
| **3** | `TavernPlot` | 三段逻辑边界清晰（记忆整理/检查点各自成 hook），JSX 也按注释天然分区 | `ui-tavern-plot.mjs` |
| **4** | `TavernCard` | 1,240 行单块最大，但配套件（`TavernCardList`/`StructField`/`DraftDialog`）已在，模式成熟 | `ui-tavern-card.mjs` |
| **5** | `useTavernFreeModel` | 42 state / 20 callback，最易出错；且既有验证最薄，建议放最后、单独一轮并补实弹基线 | 复用（需扩充） |

**节奏**：一件一提交、可独立回滚（沿用 2.2.1 的做法）。若老大要「一次性做完」，也仍是**5 个提交**——只是不用中途停下等确认。

## 四、每件的验收清单（统一）

1. **拆分前**跑实机脚本存基线：`--label=xxx-before`
2. 切分（**纯搬家**，语句一字不改；新文件加 import 头，老的用「同名解构」接回 → JSX 一行不改）
3. `tsc --noEmit` 0 错 ／ `eslint src` 0 problem ／ `run-all` 71-71 ／ `importCycles` 9-9
4. 🔴 **`vite build` 必须跑**（记忆红线：这些组件在 `App.tsx` 的 lazy 分支，新增模块可能被 tree-shake；`GeoMapEditor` 还是静态导入）
5. **拆分后**：`--expect=xxx-before` 逐项比对（结构计数：分区数、左右列子节点数、画布 layer 数、输入框/按钮数、状态栏文案……）
6. **负面对照**：注入一个真故障（多包一层 `<div>` / 改一处计数 / 置空一段内容），证明断言**有牙齿**；然后自动还原并校验字节一致
7. 八支审计扫描器重跑，diff 逐条可解释
8. 文档 `docs/2.3.0-D4-xxx拆分记录.md` + 记忆 + 提交
