## 一、目标（§10.3 #11 原文口径）

1. **AI KP**（守秘人 / 主持人）：不只陪聊，还负责**裁决**与**推进剧情**；
2. **调查**：可「观察 / 交谈 / 取证」，产出**线索**；
3. **同伴**：随行的 NPC，各有立场与**知晓边界**；
4. **秘密与结局选择**：**多条结局**，条件**可判**；
5. **行动有可记录的后果**；不同玩家 / 不同分支拥有**独立经历**；
6. 引用**冻结的世界版本**（#8 世界引擎 × #11 的结合点）。

🔴 落地纪律（§10.3 #11 结合点 · §10.5）：*「基于既有酒馆模式扩展（背景设定 / 剧情推演 / 推演报告 / 自由对话 / 故事剧本 / 角色卡片 + 世界书），**不照抄**对方独立产品线；对方 AVG / AI 小镇 / 文字开放世界**不追**」*。

## 四、设计

### 4.1 跑团局契约（`src/lib/run/runTypes.ts` · 新增）

```ts
export interface RunSession {
  id: string
  schema: 1
  title: string
  /** 模组来源：复用既有故事 / 剧本（可空 = 纯即兴） */
  storyId?: string
  scriptId?: string
  /** 引用哪一份世界包的哪一版（#8 × #11 结合点；可空 = 用当前项目） */
  worldRef?: { worldId: string; version: number }
  /** 玩家角色（复用角色卡）＋ 同伴位 */
  playerCharId?: string
  companions: RunCompanion[]
  /** 线索板 / 秘密 / 结局 */
  clues: RunClue[]
  secrets: RunSecret[]
  endings: RunEnding[]
  /** 行动流水（「可记录的后果」） */
  actions: RunAction[]
  messages: TavernMessage[]        // 复用
  checkpoints?: TavernCheckpoint[] // 复用
  vars: TavernVars                 // 复用（扩展键见 4.4）
  createdAt: number
  updatedAt: number
}
```

### 4.2 KP 主持层（`src/lib/run/kp.ts` · 新增）

- 在既有 `chat()`（`injectUserSystemPrompt` 兜底）之上加**主持人格**提示词：**推进剧情 + 裁决行动 + 不给答案只给线索**；
- **检定协议**（D2）：`行动 → 难度 → 掷值 → 结果档（大成功/成功/擦边/失败）`，结果进 `RunAction`；
- 🔴 **薄封装**：不新造 AI 通道，走既有 `aiParse.ts`（结构化必传 `json:true`），不违反「AI 链路禁裸 `JSON.parse`」。

### 4.3 线索板 × 同伴（`src/lib/run/clues.ts` · 新增）

- **线索**：`{ id, text, source('观察'|'交谈'|'取证'), acquired, linksSecretId? }` —— 获取即入板、可回看、可关联秘密；
- **同伴**：`RunCompanion = { charId, stance, knows: string[], canHelp: boolean }` —— **知晓边界**复用「知情权限」思路，同伴不知道的事不会「知道」。

### 4.4 秘密与结局（`src/lib/run/endings.ts` · 新增）

- **秘密**：`{ id, text, unlocked, revealOn: string[] }`（条件＝线索 id / flag）；
- **结局**：`{ id, name, condition: EndingCondition, reached }`；
- **判定纯函数** `evalEndings(session)`：按已揭露的秘密 + 已获线索 + 变量档位求**可达成结局**，**Tier 化返回**（达成 / 接近 / 未启）；
- 数值扩展：在 `VAR_KEYS` 之外加跑团专用键（**理智 / 声望 / 线索数**），走既有 `VarDef` 机制（D3 关联）。

### 4.5 存档（复用，不新建表）

- 「首次开始」＝建一局 ＋ 落**独立存档**（复用 `checkpoint` 思路）；「继续」＝恢复，「从头」＝另建 —— 与 #11 原文一致；
- 存储落点（D1 关联）：跑团局随项目走还是全局？见决策点。

### 4.6 页签 UI ＋ **与 L5 拆分一起规划**（🔴 §11.1 L5 硬要求）

- 新页签「**跑团**」挂「酒馆模式」组（四处同步：`TabType` / `TABS` / `App.renderContent` / `FEATURE_TIER` ＋ `STRONG_DEPS` 互绑）；
- 🔴 **L5 拆分必须与跑团一起做**（§11.1 L5 原文：「**与 #11 跑团对酒馆页的扩展一起规划** —— 别先拆完再改，否则白拆一次」）：
  - `TavernScript.tsx` 左栏已拆（`TavernScriptTree`，W3-3）；**中栏 / 右栏待拆**；
  - 拆分时**先量依赖**（`assets/dep-cost.mjs`），**按跑团页的实际复用面**决定中/右栏边界 —— 若跑团要复用「剧本字段编辑」或「角色卡张数区」，就按复用点切，而不是按行数硬切。

## 六、🔴 待主人拍板的 4 个决策点

| # | 问题 | 选项 | 可可推荐与理由 |
|---|---|---|---|
| **D1** | 跑团局数据落哪 | A 随项目（`tableRows` 式，进同步/备份）／B 全局（像 `worlds`，跨设备要手动搬） | **A** —— 一局跑团天然属于某本书的世界观；且「独立存档」用 checkpoint 表达，不必新表 |
| **D2** | KP 规则深度 | A 内置**轻量检定**（难度/掷值，AI 裁决，无硬规则书）／B 支持**导入规则书文本**（AI 读规则）／C **纯叙事**（无检定） | **A** —— 有「跑团感」又可控；B 太重（规则书解析＋长上下文），C 少了跑团的判定骨架 |
| **D3** | 秘密与结局怎么定义 | A **结构化表单**（秘密清单 ＋ 结局条件，AI 按条件判定）／B **纯叙事**（AI 自己把握）／C 混合 | **A** —— 「三条结局 / 分支独立经历」的前提是**条件可判、可复现**；纯叙事做不到「不同玩家独立经历」 |
| **D4** | 是否引用**冻结世界版本** | A 复用 **W4-1 世界包**（跑团局引用某封存版）／B 不引用（直接用当前项目/剧本） | **A** —— 正是 §10.3 #11 原文「引用冻结的世界版本」，且 W4-1 刚做完，复用成本低 |

> **既定项**（不单列决策点）：存档复用 `checkpoint`（不新建表）；AI 走既有 `chat()` / `aiParse.ts`（不新造通道）；跑团页签四处同步。
