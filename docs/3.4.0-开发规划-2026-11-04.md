# 3.4.0 开发规划：长篇创作工作台

> 日期：2026-11-04（香港时间）｜状态：规划，尚未实施或验收
> 基线：本次检查 main `31361bb`，当时工作区干净；本规划文件现为未跟踪文件。开发开始时重新核对 HEAD、工作区与最新交接，本文不作为源码冻结证明。

## 一、目标与原则

借鉴 Scrivener 的多视图组织、写作参考、修订历史、收藏集和编译思路，让作者完成「规划选章 → 参考资料 → 写作修订 → 回到规划 → 导出」的连续工作流。以现有数据和入口为唯一事实来源，优先改善发现性、上下文与安全性，不复制其界面或数据结构。核心流程离线可用、不依赖 AI；不改变既有作品内容或默认导出结果。

## 二、当前基线与差异

- 章节规划板已按卷、状态、关键词筛选，展示标题、摘要、状态、字数和更新时间，点击进入正文；只读，并提示状态与正文的明显不一致。正文目录已有卷章拖动排序与序号重算，不能宣称项目缺少排序。
- 正文「本章资料」抽屉已有细纲绑定、关联资料、固定与正文引用，以及来源跳转；先核查固定的作用域、持久化、空间占用和跨章行为，再决定补缺，避免再建一套分屏系统。
- 时光机已有自动、AI 和回滚前留档等来源，当前稿及任意两版对比，界面提示恢复前留档；每章共用 12 版池，优先淘汰自动快照。开发前须核实失败和并发窗口，不能把界面提示当作完整安全证明。
- 灵感夹已按项目存储，支持随手记录、AI 融合和溯源；已有写作联动。投稿 DOCX 已可选章节并有排版预设；正文还支持多种格式与按卷导出。无需重复实现。
- 3.3.5 已发布但整版验收未完成：文件后端连写强杀和章与检查点故障窗口、真实模型双人盲评、当前源码安装包取证仍有缺口。3.4.0 的功能验证不能替代这些遗留项；封装需另有明确授权。

证据入口：`src/lib/app/chapterBoardView.ts`、`src/components/app/WritingWorkflow.tsx`、`src/components/editor/ChapterContextPanel.tsx`、`src/components/editor/useChapterContextData.ts`、`src/components/editor/EditorModals.tsx`、`src/lib/db/chapters.ts`、`src/components/creative/InspirationBox.tsx`、`src/components/dialogs/ExportFormatDialog.tsx`、`src/components/editor/NovelEditorChapterTree.tsx`。以上为本次抽查，不代表已完成全链路审计。

## 三、范围与交付包

### A. 规划板与正文往返（核心）

1. 保持规划板只读与原有排序语义。核对卡片字段、筛选与导航，补齐缺失的来源提示和空态；状态不一致仍只提示。
2. 从卡片进入准确章节；返回时恢复同项目的卷、状态、关键词和滚动位置。已删除章节、项目切换、读取失败分别明确提示；不以旧状态覆盖新项目。
3. 利用已有资料关联展示可验证的细纲或资料入口；关联缺失时显示未绑定，不根据名称猜测关系。人物、伏笔等信息只有现有数据可可靠关联时才展示，否则保留为后续调研项。
4. 不在规划板引入拖动排序；已有正文目录排序保持原入口。若未来需要新增入口，须先覆盖编号、引用、冲突和撤销设计。

验收：两个项目交替、筛选后进入并返回、刷新、目标被删除和读取失败均有明确结果；筛选和位置不串项目，不写入章节内容或顺序。大项目下检查列表响应和滚动性能，以开发前同环境实测为基线，不擅自承诺性能数字。

### B. 本章资料使用体验（核心）

1. 复用现有抽屉、细纲绑定和固定机制。先调查桌面、便携、网页端现有行为，确定「跟随当前章」与「用户固定」在现有模型中的实际语义；仅对确有缺口的部分补充清晰标识、来源跳转、加载与失败状态。
2. 宽屏保证正文和资料同时可读；窄窗口以可收起抽屉呈现，不遮挡关键操作。记录并恢复视图偏好须按现有偏好作用域设计；项目/章节切换时不显示其他项目资料。
3. 本版不新增通用双编辑器；参考内容默认只读，编辑走原入口。现有续写计划已读取本章固定资料；仅打开抽屉不新增发送内容，保持现有选择与发送清单语义，改变发送范围须明确告知并由用户选择。

验收：绑定/解绑、固定/取消、跨章与跨项目切换、目标删除、载入失败、窄窗口与键盘操作；在加载延迟时旧响应不得覆盖新上下文。检查已有正文保存与续写发送清单无回归。

### C. 时光机安全与可理解性（核心）

1. 先核验现有快照、双版本差异和恢复前留档的实际实现；保留已有 12 版与淘汰规则。改善入口、来源、时间、对比对象、恢复范围的说明。
2. 核实恢复前当前编辑器草稿与存储版本的关系；对未保存草稿、异步保存、跨章切换和外部更新建立保护。恢复前留档或保存失败时停止覆盖、保留草稿并提示；恢复执行前再次校验目标归属和基准变化。
3. 命名/备注作为条件项：先核查当前模型、同步、备份和版本容量；仅当能兼容旧快照并完整往返时实施。不得声称手动快照永久保留。

验收：当前稿和两份历史对比、恢复后重开、留档失败、存储失败、作者在途编辑、项目/章节切换、容量满及旧数据；验证恢复前内容可找回，明确单章恢复不等于作品恢复。分别覆盖适用的浏览器及文件后端，不能只凭成功提示判定。

### D. 章节筛选与收藏（增强）

先复用规划板现有卷、状态、关键词筛选。第一版提供用户手动维护的章节收藏集：项目内命名、增删成员、打开原章、显示失效成员；不复制正文、不更改正式顺序，默认按现有叙事顺序显示。项目隔离，删除收藏集不删除章节。动态规则、人物线自动识别及跨章节连续编辑暂不纳入；若发现现有模型不能安全支持收藏集的同步与备份，先完成设计和验证再实施，不以本地临时数据冒充持久收藏。

验收：同一章节属于多个集、空集、重名处理、删章及恢复、切项目、重启、同步冲突和备份还原；明确收藏元数据是否同步及导出，缺失不得静默宣称完整。

### E. 导出方案（增强）

在现有投稿 DOCX 章节选择和排版预设上，先盘点各格式实际范围选择能力。针对确有缺口的格式增加章节范围选择与导出前清单；统一复用现有叙事顺序和导出器，不改变未选择新选项时的原结果。支持保存具名导出方案须按项目隔离章节 ID；跨项目通用的排版偏好继续沿用现有作用域，失效章节须明确列出并由用户处理。清楚说明稿件导出不是完整备份。

验收：单章、跨卷、自由章节、空正文、未计序号、删除后的选择、标题与顺序；各格式以解析后的内容核对，默认路径回归原行为。导出读失败或部分失败须准确提示，不报全量成功。

### F. 随手记与归档（增强）

复用项目灵感夹和现有存储、容量与去重规则，在适合的创作入口提供快捷记录；先保留文字草稿，明确保存成功或失败。提供将灵感关联至章节或打开目标入口的能力，先核实现有数据模型与可恢复路径；不自动生成设定、不静默删除原灵感，不默认发送 AI。若不能安全持久关联，先交付快捷记录和跳转，关联作为后续项。

验收：无模型、项目切换、重复/容量上限、写入失败、连续输入和目标删除；失败保留原输入，关联操作不覆盖原资料。

## 四、数据与兼容约束

- 开工先绘制章节、资料、快照、灵感、设置及同步/备份真实读写链，确定每项数据作用域和所有权。新增持久数据须有旧数据默认值、迁移、回退、删除、同步、导出与恢复策略；无法完整闭环的增强项不伪称完成。
- 所有异步写入在开始时绑定项目、记录及存储上下文；切换项目或章节后的迟到结果不得落到新目标。保护未保存正文和输入；读取失败不当作空数据覆盖。
- 遵循现有统一章节排序及自由章节规则；收藏筛选不改变原结构。隐私和 AI 发送范围沿用既有明确选择与清单，不因新视图暗中扩大。
- 不引入新的复杂编译引擎、剧本格式、完整分屏编辑器或自动剧情关系识别。依赖真实模型、额外账号、安装和发布的验证单列条件，不作为本地通过的推断。


## 复核补充：实现依据与决策门

- **规划板**：现有板包含正文章节和细纲两种视图，并分别限制初始显示 60 条。往返须保存视图、展开状态、筛选、显示数量和滚动锚点；锚点超出初始范围时先加载，再定位，目标消失时保留筛选并提示。现有板的分组排序须与统一叙事序对照测试自由章节和孤儿记录，不能预设已一致。
- **本章资料**：`chapterContext32:<chapterId>` 作为项目设置保存章节绑定，续写计划已读取固定项。核对项目复制、导入为新书与云端下载时项目、章节和资料 ID 的映射；无法映射时明确显示失效，不引用原项目。读取失败与未绑定分开处理，失败时禁止用空绑定覆盖原值。
- **恢复关键窗口**：当前历史窗口使用编辑器草稿对比；恢复回调先对 `active` 留档再更新内容，而窗口调用异步回调后立即关闭。草稿与 `active` 是否一致、在途切章是否安全，须通过复现验证，不直接断言已丢稿。恢复须绑定原项目、章和实际草稿，留档读回核实后才能覆盖；检查写入失败、裁剪、容量满、在途修改和后端非原子中断。完成前禁止重复提交，按真实保存回执报告结果；无法保证时中止并保留草稿。
- **快照备份边界**：项目导出包只包含 AI 来源快照，自动备份不包含快照；参考资料默认不随包，自动备份也不带。其他同步或备份通道须分别核实，不承诺所有历史跨设备存在。删除章节会清理快照，回收站恢复章节不应暗示历史版本也被恢复。命名功能不能暗示永久保留。
- **收藏及导出方案**：先核实新建、复制、导入、覆盖恢复、云端下载为新书及删章恢复的 ID 映射；关联须正确重映射或明确提示失效，不能只改项目 ID。并发沿用现有冲突机制，不静默合并覆盖。方案仅保存选择与排版意图，不保存正文或密钥。
- **导出预览**：明确空章、卷标题、未计序号章节的处理；预览和结果使用同一排序规则。预览后章节变化或删除须重新核对并提示。普通稿件、投稿稿、项目包与自动备份分别说明范围。
- **可用性和性能**：支持键盘、可见焦点、语义标签及加载失败提示，关闭抽屉后焦点返回入口。用隔离的 500 章量级夹具在同机器同数据下记录开发前后打开、筛选、返回、内存和卡顿；无可比基线或有回退须记录原因，不能沿用历史数字当本次结果。
## 五、实施顺序与决策门

1. **P0 基线**：记录最新源码指纹、三端可用性、现有流程、数据流及相关测试；复现 C 的安全窗口，列出差距与风险。检查最新 3.3.5 遗留证据，已有缺陷单独登记，不把它们写成 3.4.0 新功能。
2. **P1 核心纵切**：A → B → C，以一个作品走通选章、查看资料、编辑、快照对比/恢复、返回规划；先保护数据再改善界面。
3. **P2 增强包**：D、E、F 分别进行数据闭环设计与实现；条件不满足时记录阻塞和未覆盖，不借由删减安全要求强行交付。各包独立验收，避免牵连核心流程。
4. **P3 集成与复核**：按最终源码运行类型检查、lint、构建、完整测试及项目适用审计；追加跨项目、在途编辑、故障注入、三端适用链路与长篇性能对照。记录环境、指纹、证据、通过/失败/阻塞/未运行。
5. 更新手册和引导、工作日志、交接及版本质量记录；验收结论区分本版功能、历史遗留与整版发布条件。源码变动后按影响重验；安装包取证和封装按授权边界执行。

## 六、完成标准

核心包 A–C 和增强包 D–F 均须完整交付并验收，方可称规划全部完成；如有阻塞，记录未完成项和影响，只报告已完成部分。不存在未处理的丢稿、跨项目写入、误导性成功或关键导出内容丢失问题。相关自动检查和适用端到端测试通过；外部条件不足的验证如实标记未覆盖。最终发布与整版验收须另按完整质量记录判定。
