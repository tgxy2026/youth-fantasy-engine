## 一句话

## 一、正文编辑：正文列不再被挤成一条缝

最影响写作体验的一处。1440 宽的窗口下，正文区原先只有 **317px**（一行约 25 字），左边两栏吃掉了大半空间。

| 项 | 原先 | 现在 |
|---|---|---|
| 正文列宽度（1440 视口） | 317px | **525px**（一行约 35 字） |
| 设定检索栏默认宽 | 360（大屏 480） | 320（大屏 400） |
| 章节树大屏默认宽 | 300 | 280 |
| 正文列 | 被两栏挤压 | **保底 560px**：窄窗口下检索栏自动让位 |

- 让位只压**渲染宽度**，你手动拖出来的偏好原样留在设置里 —— 窗口放大它就自己回来了。
- **「铺满 / 限宽」开关改了口径**：限宽的实现是给正文列挂上限（768px），正文列本身就比它窄时，这个开关点了**纹丝不动**，是个死开关。现在**默认铺满**，开关只在正文列宽到能看出差别时才出现（≥900px）—— 主流屏上你不会再看到它，4K 屏的能力也没砍掉。

## 二、全站视觉体检：10 处观感与体量

巡检范围：**59 个页签 + 代表性弹窗**，1440×900 逐页真机截图目检。

| 处 | 原先 | 现在 |
|---|---|---|
| 主从双栏右栏空态、时光机空态弹窗 | 只有 `py-8`，贴顶 + 下方 500px 空白 | 撑满容器并居中（弹窗 177px → 320px） |
| 背景设定每节的「删除」、表格「清空全部」 | 常驻红字 / 红按钮，一屏好几处抢眼 | 常态中性灰，悬停才染红 |
| 表格页头按钮（人物关系 / 历史事件等） | 9-10 个按钮放不下就折成 3 行，第二行只剩两个按钮孤零零靠右 | 「导入 / 导出 / 清空全部」收进「更多」菜单 ⇒ **3 行 → 1 行** |
| 表格右侧列被裁切 | 看不出还能往右滑，像渲染坏了 | 有内容没露出时右缘出现渐隐提示，滑到底自动消失 |
| 说明文字 | 9-10px 偏小 | 重灾区统一提到 11px（34 处；小徽标与代码块刻意保留） |
| 创意写作 / 一键拆书 | 内容只占约六成宽，右侧大片空白 | 表单放宽（实测 1053px） |
| 人物关系 | 文件夹头只有「名字 + N 条关系」，右侧全空 | 补**关系摘要**（关系类型去重，最多 3 个 +「+N」），折叠着也一眼看清这人绑了哪几类关系 |
| 地理风物编号 | `G0001-001-001` 折成 2-3 行，行高参差不齐 | 编号列单行不折行，默认宽 110 → 130，行高统一 |

> 打赏致谢名单同时更新（新增两位）。

## 三、全量审计：修掉 2 个真缺陷

这一轮用**强化后的审计工具**（11 个扫描器 + 代码结构检查 + 请求头边界审计 + 六项运行契约）跑全量，修掉两处会咬人的：

### ① 自定义请求头：非单字节值不再放行

给需要额外请求头的服务商（如 OpenCode Go 的 `x-opencode-session`）填头时，**中文等非单字节字符原先能一路填进去**，而实际发请求时才会抛一句看不懂的错。现在配置界面就直接拦下并说明原因（可用英文值或先做编码）。

### ② 章节细纲：切换卡片时旧编辑不再静默蒸发

原先改完一张细纲卡、没保存就去新建或切换，那张卡的编辑会**悄悄消失**：

- 代码里的注释写「同步 effect 声明在下方」，**实际写在上方** —— 顺序反了，切换时读到的已经是新卡而不是要保存的旧卡；
- 写库失败时没有兜底，界面上会多出一条库里根本没有的卡（刷新即消失）。

现在：切换前**先冲刷旧草稿，成功才换选择**；写盘失败就留在原地并出声提示；新建 / 复制 / AI 新增的写库失败同样不切换选择。

顺带给数据安全补了两条实测：**同名条目往返后仍是两条**（不因重名被去重）、**曾用名（别称）导出再导入不丢**。

## 五、安装与数据

- **安装目录 ≠ 数据目录**：作品数据存在 `%APPDATA%\novel-studio`，卸载 / 覆盖安装都不会动它。
- 便携版：解压即用，数据随包走，适合放 U 盘。
- 覆盖安装即可升级，无需先卸载旧版。

## 六、已知事项（如实说明）

- **表格列多时仍需横向滚动**：这是表格的正常机制，本版新增了右缘渐隐提示，但没有改成折叠列。
- **一项运行契约未能在本机取证**：大纲卡「写盘失败时不换选择」的保护**已经实现**，但桌面版是「内存写 + 防抖落盘」，本机造不出写盘失败，需要真实磁盘不可写的环境才能端到端验证 —— 在此之前不算验证通过。
- 应用内「检查更新」只负责下载并拉起安装器，**不会自动替你安装**。
