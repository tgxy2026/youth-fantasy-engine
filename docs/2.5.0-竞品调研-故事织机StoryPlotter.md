# 2.5.0 竞品调研：故事织机（Story Plotter）对比青春幻想引擎

> 调研日期：2026-09-25 ｜ 调研窗口：可可
> 触发：社区用户反馈「故事织机的某些功能比我们更完善」，要求对比评估可吸收借鉴项。

---

## 一、TL;DR 结论

**「故事织机」= Story Plotter**（日本 CreaterSupporter / 开发者 Hajime Hata，2019 年发布，Google Play 100 万+ 安装、3.9 分）。

**本质定位差异**：它是一款**纯构思工具**（素材整理 + 情节编排 + 结构参考），**没有正文写作、没有字数管理、没有 AI 全链路**——写作要导出到 Scrivener 等别处进行。我们（青春幻想引擎）是**全流程工具**（构思 + 写作 + 管理 + AI 辅助 + 存证）。两者不是同类竞品，但它的**构思层设计确有独到之处**。

**最值得吸收的 4 项**（详见第四节）：

| 优先级 | 功能 | 融入位置 |
|---|---|---|
| ★★★ P0 | 结构模板库（三幕式 / Save the Cat 15 拍 / 起承转合等） | 创意写作细纲 + 情节推演画布 + 大纲 |
| ★★★ P0 | 章节配比预测与偏差分析（「预测分量」） | 规划中的 B5 爽点节奏 / 故事线 |
| ★★ P1 | 问答式引导设定（AI 按编剧方法论逐步提问） | 颉文姬 / 角色卡 / 大纲 |
| ★★ P1 | 灵感碎片 → 情节卡片的一键转化链路 | 灵感启发页签 |

**我们明显领先的方面**（对方差评反向印证）：正文写作体验、AI 深度集成与克制、免费云同步与备份、桌面端大项目性能（压测 321 章/101 万字）、上手引导、时间线精度（虚构纪年/负数年份）。

## 四、值得吸收的功能点（按优先级，含落地方式）

### 建议 1（P0）：结构模板库 —— 对方最硬的软实力

**对方怎么做**：把《电影剧本写作基础》（悉德·菲尔德）、《Save the Cat!》等 15 本编剧参考书的方法论做成产品内的**情节模板**，用户选一个模板（如三幕式 / 15 拍表），按每个节拍的「位置百分比 + 定义 + 引导问题」逐格填写，形成骨架后转化为情节。

**为什么值得学**：这是对方评分与口碑的核心来源——把「权威方法论」变成「可填空的脚手架」，极大降低新手构思门槛。我们的创意写作/大纲很强，但**没有内置任何叙事结构参考系**，作者全靠自己拿捏结构。

**落地方式**（融合进现有链路，不另起炉灶）：
1. 内置结构模板数据（纯数据文件，形如 `storyStructures`）：每个模板含若干「节拍」（名称、全书占比区间、一句话定义、引导问题）。首批建议 4 套：**三幕式、Save the Cat 15 拍、起承转合、网文三卷式（含黄金三章）**。
2. 入口三处：
   - **创意写作**工作流：生成细纲前可选「参考结构」，提示词把模板节拍表喂给模型当骨架约束；
   - **情节推演画布**：一键铺出模板节拍为初始节点；
   - **大纲页签**：只读展示所选模板的节拍位置与当前卷章对照。
3. 数据产权注意：**方法论本身（节拍名/百分比/思想）不受版权保护，可放心内置**；但对方产品里的「300 情节模板、5000 描写片段」等**内容库绝不可抓取搬运**，自己撰写或由 AI 生成后再人工审校。

**工作量预估**：模板数据（1 天）+ 三处入口接线（各 0.5~1 天）+ 提示词联调（1 天）。中型。

### 建议 2（P0）：章节配比预测与偏差分析（对应对方「预测分量」）

**对方怎么做**：对每一章预测「应占全书比例」，并可视化**实际情节分布与理想故事线的偏差**（如「中段拖沓」「高潮提前」），辅助节奏把控。

**为什么值得学**：这是对方最具辨识度的独家功能，直击长篇最大痛点——**中段节奏失稳**。我们的数据基础远好于对方（卷-章-字数-爽点标记齐全），做出来只会更好。

**落地方式**（与既有规划天然合流）：
1. 本体并入规划中的 **B5 爽点节奏**：以卷/章字数占比 + 爽点密度为原料；
2. 若 B5 未启动，最小可行版本（MVP）可先挂**故事线页签**：叠加一条「所选结构模板的理想配比曲线」与「实际章节字数/爽点分布」双曲线对比图；
3. 判定口径复用 `lib/wordCountMode.ts` 的字数口径，避免出现第二套统计。

**工作量预估**：MVP（双曲线对比）约 2~3 天；完整版与 B5 合并实施。

### 建议 3（P1）：问答式引导设定

**对方怎么做**：用「问答」逐步确定主题、细化大纲和角色——本质是**引导式访谈**。

**为什么值得学**：与对方「AI 头脑风暴」好评相关（有用户专门称赞其提问引导）；且这正好补我们的空档——我们的 AI 功能是「要指令才干活」，缺一个「AI 主动提问、作者回答、回答沉淀为设定」的**访谈模式**。

**落地方式**：
1. 做成颉文姬（或角色卡/大纲页）的一个轻量模式：「引导访谈」——AI 依当前上下文（角色卡已填字段/大纲已有内容）按编剧方法论逐题提问（主题句、核心冲突、人物弧光、代价与代价的两面），作者口头回答，AI 整理后**走既有「整理产出两道本地兜底」红线**（候选值=库里已有∪本次抽取，给原文依据）；
2. 与规划中的 **C5 读者视角审问**互为镜像：C5 是「读者挑刺」，本项是「导师提问」，共用同一套问答框架可省一份工程。

**工作量预估**：依托既有 AI 层（aiTasks 四处注册、流式、本地兜底），约 2~3 天。

### 建议 4（P1）：灵感碎片 → 情节卡片的一键转化

**对方怎么做**：素材本攒到 ≥4 条灵感时出现「转换故事情节」按钮，把选中的灵感融合成情节条目。

**为什么值得学**：我们的灵感启发、素材资料是「存」得好，但**通向情节/细纲的显式转化链**弱——作者要自己复制粘贴。对方把「量变到质变」做成了一个按钮，仪式感和顺手度都好。

**落地方式**：灵感启发页签增加多选模式，选中若干灵感卡后「融合为情节卡/细纲卡」——AI 按选中内容生成，产出目标直接落**大纲/情节推演画布**；同样过「整理产出两道本地兜底」红线。

**工作量预估**：多选 UI（1 天）+ 生成链路（1~2 天，复用建议 1 的模板可选项）。

### 暂不建议吸收的

| 对方功能 | 不吸收理由 |
|---|---|
| 多体裁支持（TRPG/剧本/漫画分镜） | 定位不同；酒馆模式已覆盖跑团式玩法 |
| 协作分享 | 桌面单机定位，无此场景 |
| 手绘地图 | 我们地图编辑器是结构化路线，更符合网文地理设定需求 |
| 描写片段内容库 | 版权风险 + 与「拆书自建语料」定位冲突；应以一键拆书沉淀作者自己的语料 |

## 五、对方确实做得好的地方（诚实评估）

1. **构思层的「轻」**：灵感碎片随手记、标签颜色、7 种排序、长按多选批量管理——碎片化输入的**摩擦力极低**。我们的灵感启发偏「结构化表单」，随手记的轻盈感不如它。
2. **方法论产品化**：把书变成可填空的模板，教学价值高，对新手极其友好。
3. **多端覆盖**：手机随时随地记灵感（我们纯桌面，通勤/床上记灵感是空白场景——但当前「只出桌面版」立场不变，仅作长期观察项）。
4. **章节配比这个视角**：我们没有同类物，属于真空白。

## 六、避坑清单（对方差评 → 我们的设计守则）

对方 Google Play 差评集中点，逐条对照我们：

| 对方差评 | 我们的守则 |
|---|---|
| 「AI 功能太多，作为创作者感觉被冒犯」 | 🔴 AI 只做辅助的既有立场是对的；新功能（建议 1~4）全部做成**可选、可关、AI 参与处有披露**，绝不默认强推 |
| 「导航不清晰、上手曲线陡」 | 新功能入口必须走既有页签体系，禁止新增孤立页面；HelpPopover 问号与标题同行等 UI 红线照旧 |
| 「大型复杂项目不稳定」 | 新功能数据量预估 + 大库压测（321 章基线不回退） |
| 「同步/备份收费」 | 云同步、备份永久免费是口碑差异点，维持 |
| 「PC 网页版加载不出」 | 桌面版离线可用是我们的天然优势，维持 |

## 七、建议的 2.5.0 落地顺序

结合既有挂账（社区反馈草稿箱已排期），建议顺序：

1. **结构模板库**（建议 1）—— 纯增量数据 + 接线，风险最低、差异化收益最大；
2. **配比偏差分析 MVP**（建议 2）—— 依赖建议 1 的模板数据，顺势而上；
3. **灵感→情节转化**（建议 4）—— 独立性强，可穿插做；
4. **问答式引导**（建议 3）—— 依赖 AI 层联调，与 C5 合并规划更划算。

> 备注：本报告信息基于公开渠道（应用商店多源交叉印证 + Google Play 评价 + 编辑评测），未拿到对方产品源码；「300 模板/5000 片段」为单源信息已标注。如需实机验证，可安装 Android 版体验后再细化落地方案。
