# 青春幻想引擎 3.6.0 开发规划 · 拆书分析与创意写作闭环

规划日期：2026-11-13；同日第二次源码复核。状态：**规划，尚未开发或验收**。本次规划基于青春幻想引擎 `8da6568b181d422f9ac1b7a0f1a70144c50506d9` 与 InkOS `53adac4e974b54dafda975edc4edd07cad364c18` 的静态源码调研；开工时须重新核对实际基线、交接与前置版本。InkOS 为 2.0 开发分支快照，未实跑，其设计不构成我们功能已验证的证据。源码级复核发现、明确的落地契约及任务分解见第 14–18 节，与前文共同构成本版范围。

## 1. 版本目标与边界

围绕作者的实际工作建立一条可审阅、可追溯、可恢复的路径：**拆解作品 → 理解叙事方法 → 选择创作参考 → 规划与比较剧情 → 写作和审读 → 安全落地与继续创作**。作者可以分步使用，既有一键拆书、创意写作和自动连写保持可用。

本版交付六个工作包：A 共同数据与归属基础；B 拆书分析；C 创作参考；D 章节审读记录；E 章节保存与章后整理恢复；F 剧情候选。G 为材料检索的限定验证，不预设引擎替换。各包须满足下文验收，不能仅用界面或模拟模型通过作为版本完成。

本版独立设计实现，不引入 InkOS 源码、提示词、Skill、依赖或运行时。仅研究其分层分析、候选隔离、可追溯审读和状态恢复等思路；将来若考虑代码复用或进程/API 接入，须另作 AGPL 及架构审查。自动发布、开放世界、剧本生产、模型训练和完整向量数据库均不属于本版。

## 2. 现有基础与前置约束

| 能力 | 当前代码事实 | 3.6.0 处理 |
| --- | --- | --- |
| 拆书 | `src/lib/bookbreak/run.ts`：切分、可选写正文（默认开启、只追加）、分块实体抽取、草稿、全书设定与关系；具备单元断点和失败重试。`flow/draft.ts` 合并证据与冲突，关系材料有上限。 | 保留既有默认和语义；增加独立分析与范围说明，不把局部结果称为全书结论。 |
| 创意写作 | `src/lib/ai/aiWorkflow.ts` 组织设定、大纲与逐章写作；`outline/autoContinue.ts` 已有作者裁决、连续性/人设/伏笔自检、必要时修正、正文保存和设定补登。 | 扩展审读可见性和恢复，不重复建设自检；保持当前作者选项和字数预算。 |
| 已知保存顺序 | `autoContinue.ts` 中标题/摘要先生成，正文保存后再抽取补登；摘要异常可回退为空，部分补登异常会变成空结果。 | E 包先确定实际失败路径，区分未做、失败、无结果和成功，不能宣称跨存储原子性已经存在。 |
| 模式 | 3.5.4 ACP 为受控纯文本范围，正式连接仍有前置验收；3.5.5 规划结构化和后台任务。 | 以开工时实际能力为准。A–F 首先走现有 API 任务路径；ACP/MCP 仅在结构化契约、权限、模式租约及真实验证完成后单独接线，不静默回退或绕过门禁。 |

历史启发式 `confidence` 不是事实正确概率。本版必须区分证据命中、来源覆盖与人工判定，不能把模型自评分当成可靠度。旧项目、现有设定及正文不得因升级而自动重写。现有逐章自检成功时，严重/中等问题已通过 `persistCheckReports` 旁路留档；空结果、失败和不符合留档条件的结果会跳过。新设计应衔接现有报告与工单链，不另建互相矛盾的报告真相源。

## 3. 共同契约与数据边界（A，P0）

1. 盘点现有 `flow`、任务台账、`creativeSession`、存储适配、作品导入导出和备份，形成字段与读写矩阵；先复用现有机制，避免创建平行的作者数据源。提交具体数据位置、版本号、迁移与降级方案后实施。
2. 每次任务冻结 `projectId`、存储作用域、运行/单元 ID、输入范围及内容指纹、配置与数据版本；发请求前、接收回调时和采纳写入前核对归属。指纹应覆盖实际使用的正文、设定和其他依赖，且有规范化规则；任何输入变化均保留旧结果但标记过期。指纹不记录密钥或明文。
3. 结果统一区分 `待处理 / 进行中 / 完成 / 部分完成 / 失败 / 已取消 / 已过期`。每个单元分别记录请求、完成、失败、跳过和原因；失败不能当作空结果，取消不能伪装完成。断点必须校验来源、参数、项目和存储身份。
4. 分析结果、参考与分支是候选资料；设定表、大纲和正文是正式内容。写入正式内容须明确目标、展示差异并由作者确认；系统后台处理不能扩大授权范围。关闭页面、切项目或多个窗口并发时，迟到结果不得写入另一项目或覆盖新草稿。
5. 设计项目删除、导出/导入、备份/恢复及旧版回退行为：作者明确保存的结果需在受支持的项目导出中可恢复；运行中的任务不能恢复成正在执行，缺失来源或版本不兼容时只读并提示。临时原文、引用片段及模型凭据默认不进入诊断日志；发送模型前说明范围和接收方，遵守原有授权及取消机制。

**验收：** 用同名不同项目、切项目/存储、并发编辑、取消迟到、原文变化、备份恢复与旧数据迁移验证上述契约；异常存储和配额不足必须可见。确认原有拆书与写作数据不变。

## 4. 拆书：作品分析与证据（B，P0）

### 作者流程

在一键拆书中增加可选「作品分析」，与现有设定抽取结果分开。开始前展示输入来源、计划处理章/块、截断和预计模型调用；作者可单独选择分析维度，也可保持原流程。外部参考作品增加明确的**只分析、不写入项目正文**入口；保留既有正文导入默认与行为，避免改变既有用户预期。原文是否写入项目须在开始前清楚展示，可关闭。

按章节/块生成事件与场景作用、目标与冲突、转折和章末钩子；跨章聚合人物动机与变化、叙事节奏、悬念/线索及其可能回收、叙述视角和方法。先生成可审阅的分析卡，再按用户要求汇总；不能因抽取上限或失败推断全书不存在某内容。

### 结果与控制

- 每张卡包含类别、标题、分析内容、来源章节/块及可核对的原文短引、观察或推测、对应来源指纹、涉及范围和处理状态。原文定位需校验来源和引用；重复匹配、不存在或已变更时显示无法精确定位，不提供错误跳转。无法找到依据的推测可以保留但必须醒目标注，不能作为已证实事实。
- 覆盖面显示计划、实际、失败、跳过及关系/汇总材料截断；支持只重试失败单元。多次运行必须隔离，只有相同来源和配置的有效单元可复用。合并时保留冲突与各方依据，不把时间上的状态变化机械归类为矛盾。
- 审阅卡支持修改、排除、保留及导出；不把推测自动写成事实。已有实体、表单和关系草稿仍走现有判重、勾选和提交，不因增加分析而更改落库策略。

**验收：** 合成的多章节作品含跨章关系、状态自然变化、未回收线索、重复原句和模型编造引用；逐条核对证据定位、覆盖和冲突。测试超上限、无章节标题、失败重试、取消、修改源文、只分析和旧流程回归；任何部分失败不显示全书完成。

## 5. 从分析到创作参考（C，P1，依赖 A/B）

作者从分析卡中选择并改写可迁移的叙事方法，形成有来源、用途和作用范围的「创作参考」；例如节奏、冲突升级方式和信息揭示方式。默认仅作指导材料，不将参考作品的人名、事件、设定或原文自动注入正史。引用原文和资料外发须让作者能查看、取消；来源删除或变更后保留已保存说明并标记来源不可用/过期。

创意写作的设定、大纲或本章写作按作者选择引用参考，界面展示实际范围和预算；未选择不得自动读取。明确区分作者确认的项目设定与外部参考发生冲突时的优先级，正式设定优先，冲突提示作者。采纳为项目内容走原有预览和确认。

**验收：** 自有作品整理和外部参考两条路径分别验证：未选参考不发送、选中后可查看与撤销、跨项目不可见、来源过期可识别、不能自动写正文/设定。检查项目导出与恢复的引用行为及资料权限。

## 6. 创意写作：可追踪审读（D，P0，依赖 A）

在 `autoContinue` 已有自检上记录本章检查的实际范围、发现的问题、证据或定位、适用正文指纹、处理状态和模型调用状态。区分「没有发现」「未执行」「失败/取消」；问题支持查看、忽略并说明、发起修订。保留当前自动修正行为和已有作者裁决设置，不假定当前存在自检或自动修正的独立开关；若新增开关须另行确定默认值与数据兼容，不改变既有默认。修正前后内容和审读版本保持可区分，旧意见不得误标适用于新正文。

审读、修订和采纳必须再次核对项目、章节、正文、选区及运行代次；模型建议不能直接当成事实。记录实际调用次数、预算耗尽与不完整状态，不因增加展示而额外无限重试。历史记录在缺失版本时显示未知，不凭空追溯。

**验收：** 正常、条件不足被跳过、无发现、超时、格式错误、取消、修正失败及预算耗尽均能正确显示；若将来增加自检开关，再验证关闭行为。生成期间编辑、切章/项目、重新生成和同文不同目标均不得采纳旧结果。原自动修正和连写行为回归。

## 7. 章节保存与章后整理恢复（E，P0，依赖 A；先完成故障调查）

1. 逐一梳理正文、标题、摘要、章节总表、设定抽取/补登、任务账本的调用顺序和各存储适配器的真实提交边界；以故障注入记录现状，尤其是摘要为空、正文已保存后补登失败、部分条目成功、取消和应用中断。不能假设现有数据库支持跨对象原子提交。
2. 为每章建立可回读的步骤记录：正文保存、摘要、设定抽取及应用分别有独立状态与目标版本；正文成功但后续失败应显示「正文已保存，章后整理未完成」，不得重新创建章节或报告全部成功。可重复操作以项目、章节、步骤和输入指纹约束，恢复前核对当前正文和作者改动。
3. 有可靠事务时可用事务；跨存储/多步骤无法原子提交时，采用持久步骤记录及明确补偿/重试。重启后提供只重试失败步骤、查看差异或跳过；绝不自动覆盖后续人工修改，也不重新生成已保存正文。并发运行按章节所有权/版本控制，重复恢复不得产生重复实体。
4. 不能持久保存恢复记录时明确降级和风险，停止依赖该记录的自动续跑；备份恢复时不得把未完成步骤误标完成。

**验收：** 在每个提交前后注入失败、取消、关窗口和重启；检查正文、摘要、总表、设定与状态是否对应。覆盖抽取失败、局部落库、重复点击/恢复、正文被改、项目切换及存储失败。网页、桌面、便携各自实跑，不以一种模式替代另一种。

## 8. 剧情候选与选择（F，P1，依赖 A/D/E）

作者给定分歧点和范围后，基于冻结的正式上下文生成 2–3 条候选；展示各自关键事件、人物选择、后果、待解决问题及对作者目标的影响。候选只写独立草稿，不修改正文、大纲、设定或其他候选；可取消、保留和删除。生成前展示范围与预算。

在读取和应用前重算覆盖实际依赖的上下文指纹；过期结果可阅读，但不得直接应用，须重新生成。选中只确定候选；另一个明确操作预览应用到哪一卷/章、字段前后差异，并由作者确认。应用时再做归属和版本检查；只写选中的目标，失败不得覆盖作者新稿。

**验收：** 比较、取消、候选失败、超预算、过期和并发修改；断言生成/选择均不修改正式内容。验证确认前后、应用失败、重复点击和撤销/恢复的真实结果。InkOS 的代码会返回 stale 标记，不能据此假定其界面已禁止所有过期应用；本方案明确要求本项目阻断。

## 9. 材料检索验证（G，P2，依赖 A/C）

盘点现有资料库、上下文装配、关键词/检索与存储实现，先用合成数据比较当前方案与轻量改进：按项目、来源、用途和章节过滤，保留引用定位和预算限制。验证短词、同名、跨章节、空结果、来源删除、重建及大型项目耗时；对照人工标注的召回与噪声。检索索引是可重建派生数据，不是作品事实来源。结果、成本与三模式兼容达不到预先记录的目标时保留现有方案；是否新增检索引擎或 SQLite 另行决策，不作为本版默认依赖。

## 10. 实施顺序、依赖与里程碑

| 顺序 | 工作包 | 完成标志 |
| --- | --- | --- |
| M0 | A 契约、存储与现状故障盘点；复核 3.5.4/3.5.5 基线 | 数据生命周期、归属与迁移设计落定；故障基线可复现 |
| M1 | E 保存恢复基础 + D 审读记录 | 章节中断与迟到保护专项通过，作者能区分审读与整理状态 |
| M2 | B 分析 + C 参考 | 证据、范围、只分析、选择与导出恢复闭环通过 |
| M3 | F 剧情候选；G 检索验证 | 候选隔离与过期阻断通过；检索形成有证据的保留/改进结论 |
| M4 | 统一回归、质量评估、审计与文档 | 全部必交工作包和下述版本门槛通过，未通过项不得标记完成 |

M1 与 M2 可在 A 契约稳定后并行开发，但各包合并前必须检查共享存储与写入边界；F 在 E 的恢复契约稳定后接入。P0/P1 均属于 3.6.0 交付范围，P2 为验证与决策而非承诺替换技术。若任一包不能完成，应记录阻塞并调整版本范围，不能仅凭部分能力宣布整版验收。

## 11. 测试、质量与发布门槛

- **自动化与回归**：围绕业务契约验证证据定位、覆盖统计、状态机、过期判定、幂等和故障恢复，补充已有拆书、创作、项目切换、数据导入导出与模式门禁回归。对最终候选执行项目现行 `npm run verify`、`npm run test:server`、`npm run build` 和适用专项；结果、候选提交、环境及日志必须一致。
- **真实交互**：使用合成短篇及中长篇作品，在网页、桌面和便携分别执行分析、审阅、引用、创作、失败恢复、重启与导出导入；桌面 ACP/MCP 只测本版实际开放的能力。未实跑平台单列为未验收。
- **内容质量**：事先制作带章节事实、线索、人物变化及无证据陷阱的标注样本，由人工核对引用命中、关键事件/线索召回、错误事实、过期与冲突处理；记录样本大小、模型/配置、调用量、耗时和成本。先测现有基线，确定目标与复核标准后对同一数据比较，不能以模型自评或单次演示替代人工检查。
- **数据与安全**：人工修改保护、跨项目隔离、取消迟到、敏感配置不入日志、来源与权限、导出恢复、旧版本回读均须有正反例。大文本/配额不足和离线失败不得丢失已保存正文。
- **最终验收**：冻结候选后完成适用的六维审计、源码发布检查、帮助与更新说明；任何阻塞项、未覆盖模式、真实设备/安装包和模型质量边界如实记录。开发验证、正式安装/覆盖升级与回退、部署/发布分别验收；封装、部署、推送和发布需相应授权。

## 12. 需要实施阶段定案的问题

1. A/E：不同存储模式的事务、步骤记录位置、容量上限、导出和旧版回退如何落地，以 M0 故障调查为依据。
2. B/C：分析卡的章节定位、参考资料保存策略、敏感原文在备份及外发中的默认范围，以用户可见且可撤销为原则。
3. D：现有自动修正和用户确认的交互如何呈现审读前后版本，不能改变既有默认而不经产品决策。
4. F：应用候选支持的目标字段和撤销范围，以实际 schema 与原有撤销能力核实后确定。
5. G：质量样本、目标阈值和检索实现由基线测量结果确定；不先许诺量化提升。

## 15. 数据、指纹与生命周期的实施契约

### 15.1 三类记录与跨项目行为

| 类别 | 持久与流转 | 关键约束 |
| --- | --- | --- |
| 执行台账 | 本机临时任务，沿用现有 taskHeads/taskUnits 与容量限制；不随普通项目包导出，不同步执行权。 | 刷盘成功才标成功；重启 running 变 interrupted，需校验原项目、原输入和代次后手动恢复。跨设备导入不得启动旧任务。 |
| 作者保存成果 | 用户明确保留的分析卡、参考、审读摘要及候选，作为项目级数据进入经过版本化的项目包和相应备份。审读问题接现有报告/工单链，运行摘要可使用独立轻量记录并关联报告，不复制两套问题正文。 | 设计唯一记录 ID、项目 ID、来源 ID、数据版本、内容版本、状态、创建/修改时间与可选引用；对大小、数量和清理策略设置上限，清理前提示，不静默淘汰作者保存项。 |
| 正式数据 | 正文、设定、大纲和既有章节/工单数据。 | 作者审阅并明确采纳后按目标字段写入；作者手工编辑具有独立版本，旧结果无权覆盖。 |

任务产物进入作者成果应为显式保存操作；该操作的完成以作者成果持久写入并读回为准，不能仅凭本机任务成功标志。导入新项目时为项目及关联记录重新映射 ID；来源或目标缺失显示不可用，不以标题/章号匹配替代 ID。删除项目同时清理其成果与本机任务，确认不影响被其他项目引用的独立资料；具体共享归属须在 M0 核查实现。版本未知、记录损坏、缺项或旧包无此字段时，保留原数据并标注不可读/未提供，不将缺失解释成空结果覆盖现有数据。

### 15.2 来源和版本校验

- 建立版本化的来源清单：存储域与项目 ID、源类型、源对象 ID、章节/分块顺序和范围、规范化方案版本、各依赖内容摘要、配置及提示模板版本。正文按原始字符串计位；章节范围明确采用 UTF-16 半开区间，与 JS 字符索引一致。导入文本的规范化、切块边界和行结束符必须记录，不能对规范化后偏移直接跳原始文本。
- 用经跨平台验证的强摘要及长度校验用于新结果过期判断；摘要不可算、缺失或版本未知时当作无法验证并禁止自动应用。摘要不视为保密措施，也不单独作为权限凭证。对实际写入目标同时核对对象 ID 与最新字段原值/版本，并在可实现的提交边界内再次校验；不依赖快速短哈希碰撞一定不会发生。旧台账按旧协议读取，新协议单独带版本，禁止误复用旧结果。
- 证据定位保存来源 ID、版本、区间和短引；先校验区间与原文一致。重复短引不能凭第一次出现猜位置；源文件未保存时可在当前会话验证，重新打开需作者重新提供并验证来源，缺失时保留分析文字和不可定位状态。分块重叠时按来源坐标去重，不能把跨块重复事实当成多次独立证据。
- 对参考、预测和审读分别记录本次**实际读取**的依赖清单，而非项目全部内容；项目编辑无关字段不应使结果无意义地全部失效。清单应包含选用参考、章节、设定、大纲、锚点及其裁剪范围；无法证明全部依赖一致时保守阻断应用。

### 15.3 导出、备份和隐私

M0 列出 `ProjectBundle`、导入、分片备份、恢复、云同步与删除每条代码路径；新增字段需同时覆盖这些路径并实测 ID 映射。作者成果默认不附完整外部原文，只存必要短引、定位和分析；外部素材若经作者主动导入知识库，是否随包遵循原有开关。导出界面列明包含的短引、分析和参考，可选择排除；排除后引用呈不可用，不伪造有效定位。诊断和错误日志只记录有限原因码、计数与非敏感版本信息；不得记录正文、原句、提示词、密钥或可逆的请求载荷。

## 16. 关键工作包的具体落地与边界

### B：分析管线和来源约束

1. **输入与切分**：复用既有 `splitNovelText/chunkText` 和单元台账的可用部分，增加独立 `analysis` 任务类型和配置版本；原正文写入和实体抽取是可选择的既有动作，只分析路径在编排层阻止 `persist`、设定草稿提交及关系写入，不能只依赖隐藏按钮。
2. **逐块与跨章**：逐块产出结构化卡并对证据做本地验证；跨章归并只消费已成功单元、实际纳入的片段和范围清单。合并输出须列出实际输入覆盖、截断和失败；没有覆盖全部来源时，“未发现”限定于已处理范围。长篇按批上限调度，超出保留未处理状态，后续可继续；启动前说明估算是估算，执行中记录实际调用和截断。
3. **作者决策**：草稿状态区分未审阅、保留、排除和人工修改；保留后单独保存到项目成果。旧分析更新为新来源时产生新版本，不自动覆盖人工修订。已保留内容重试、任务中断、来源更换和导出均有明确行为。
4. **验收补充**：验证只分析情况下项目卷、章、设定和关系的存储前后值一致；手工修改后重试不覆盖；长章跨块、重叠、分卷标题、中文标点、重复引用、Unicode 和 CRLF/LF 的定位均需正确或显示无法定位。

### C：可迁移方法的选择与发送

参考卡与项目已存在的灵感条目、结构模板、知识库各有用途，M0 明确关联但不复制原始资料。建立默认不勾选的任务级选择；当来源不可用或过期时不可自动发送。选择后展示**实际入上下文**的参考文字、用途、裁剪和模型接收方；作者撤销后下次请求不带入，已发出的请求无法撤回。为设定奠基、大纲规划和逐章正文逐入口接线，更新 `aiDataSources.ts` 和对应检查，不能只在 UI 勾选而底层未消费或反向自动注入。

### D：旧报告与新运行摘要衔接

沿用现有 `persistCheckReports`、报告页和工单接口；新增运行摘要独立表达三项各自的 completed/failed/cancelled/skipped 和结果数量，报告 ID 为可选链接，不能以 0 条报告推断“无问题”。当正文过短或上下文为空，明确显示 skipped 与原因，必要时提示作者补齐资料；不把现有 requested=0 的 `completed` 当作已审通过。新章生成时先绑定 taskId + 本次临时稿 ID + 指纹，`createChapterAfter` 成功取得实际 chapterId 后再校验绑定；落库失败、并发插章、草稿重写均不按计划章号猜测归属。修正后的新正文与旧报告保持版本关系；报告写入失败、被配额清理和备份不含报告时明确显示，不改变当前自检未完成即暂停的门禁。

### E：保存回执与幂等恢复

- 对正文、摘要、章节总表、实体新增与既有设定变更分别保存意图、目标和结果回执；先捕获原始 `StoreOps`、项目、账号/存储域及任务代次，再开始异步操作。不能在模型返回后重新读取全局当前项目作为目标。将 `extractAndCommitSettings` 的宽泛空返回改为有状态结果，并审计所有调用方（包含改写、章后整理等），避免回归。
- 在首次会产生不可逆写入前持久保存准备记录；正文写入与“正文已创建”回执存在崩溃窗口时，须使用预分配且稳定的章节 ID/操作 ID 或同一存储事务确认结果，不得仅用章名、时间或正文相似度猜测。逐项补登使用稳定操作键及实际写入回执；如目标已被用户修改或写入结果无法确认，暂停并展示差异，不能自动重放。记录失败后不继续下一章，恢复记录和实际写入不一致先核对后处理。
- 明确 `confirm` 中用户取消/跳过与失败不同；`add-only` 与 `auto-update` 分别保存实际选择和完成结果，不因恢复改变策略。摘要生成失败与作者原本留空区分；恢复只操作其原章节及仍可证明未被修改的字段。
- 桌面/便携的确认包含实际 flush；网页和云/本地回退按当前适配器实际回执验证。若不能保证跨步骤原子提交，UI 使用“正文已保存 / 整理待恢复”等分步结果，不宣传整章事务。故障注入须覆盖写入成功但回执丢失、flush 失败、自动切换到本地、重启两次、记录已损坏及另一个窗口争用。

### F：范围与安全应用

首版候选只在创意写作页面展示和保存；应用目标限定为作者明确选定的**已有章节细纲卡字段**，沿用有效模板及字段解析，不自动创建卷/章、不改正文/设定/画布。若目标字段不存在、模板重命名导致映射不唯一，或未能提供字段级预览和条件写入，则只保存为参考，不提供应用。每个字段分别列出旧值、新值与来源，确认时重读并比较；批量应用若后端不支持可靠事务，先逐项提交并展示成功/失败，不宣称一次性原子应用，提供明确的恢复或手工处理指引。撤销仅在现有机制能核验目标仍未变化时提供，否则提供人工差异而非承诺自动撤销。

## 18. 端到端验收场景

1. 用授权的合成参考作品启动只分析，包含重复句、跨章线索、未处理章节和故障单元；取消并只重试失败块。校验覆盖与证据、无正文/设定写入；修改原文后旧分析显示过期。保留一个人工修改过的分析卡，导出导入到新项目后核对来源和映射。
2. 从分析卡保存创作参考，未勾选时抓取设定/大纲/正文三次请求载荷验证不含参考；勾选后查看范围与截断，撤销后再次验证。让外部参考与项目正史冲突，检查提示及优先级；删除来源后保持成果可读但不发送失效引用。
3. 用自有项目创作新章，在自检前后分别模拟空上下文、单项失败、报告写入失败和并发插章；验证跳过不显示通过、强制检查失败暂停、报告不误绑。保存正文后让补登部分成功并中断，重启两次重试；检查只有原章节、已成功项不重复、人工后改不被覆盖。
4. 为同一章节生成多个候选，比较和选中前后校验正文、设定、大纲及画布未变；修改依赖后禁止应用旧候选。恢复到有效状态后对一个已有细纲字段预览并确认，模拟确认后并发修改及写失败，检查作者内容、结果回执和部分失败说明。
5. 同一候选源码在网页、桌面和便携分别执行第 1–4 项的适用闭环，包括退出重启和项目包往返；记录模型、数据集、实际发送范围、调用次数、用量与费用（服务不提供则标未知），附人工质量审阅记录。模式、设备、发布阶段或真实模型缺失均作为未覆盖项，不能由静态审查代替。
