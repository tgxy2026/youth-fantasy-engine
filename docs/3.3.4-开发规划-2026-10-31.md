# 3.3.4 开发规划：跨端可用

编写日期：2026-10-31（香港时间）
状态：规划稿 R1。**本版只做跨端可用（C 组）**，未开工。文中"现状"为 2026-10-31 对工作区 `4b3f47d` 的静态核查结论，不代表已实现或已验证。
前序：3.3.2 发布跨设备接续；3.3.3 规划（写稳 + 收尾）见 `docs/3.3.3-开发规划-2026-10-31.md`，两版各自验收。
适用范围：网页版（账号 / 游客）在手机与平板浏览器、桌面版小窗口、便携版浏览器窗口。

---

## 1. 版本目标与边界

3.3.2 让书跟着人走，3.3.3 让人写得更稳。3.3.4 解决最后一公里：**换个设备、换个屏幕，也能把一章写完。**

一句话目标：**手机上不是"能打开"，而是"能写完并同步出去"。**

### 1.1 本版必做

1. 内容层窄屏适配：55 个页签在 320–430px 下不横向溢出、不靠缩放才能用。
2. 触摸目标达标：主要操作可点区域不小于 44×44px（现状按钮档最大 40px）。
3. 网页版浏览器全屏（Fullscreen API），不再依赖桌面窗口桥。
4. 网页版证据包导出：走可打印页 → 浏览器存 PDF。
5. 端能力差异收敛为**单一真源**，界面提示与手册同源。
6. 本地模型在网页版的边界写清楚，不留"能选不能用"的灰按钮。

### 1.2 不纳入本版

- 移动原生安装包（定位仍是桌面工作台 + 网页版；手机走浏览器）。
- 触屏专属手势（双指缩放、长按菜单、滑动切换页签）——先保证能正常点，再谈手势。
- 平板横屏专用布局（大屏走现有桌面布局即可）。
- 深色 / 字号等主题相关工作（已有）。
- 任何改变数据路径的改动（同步、备份、恢复一律不动本版）。

## 3. C1 手机窄屏（主战场）

### 3.1 分层看问题

导航层已经解决（抽屉），真正的缺口在三处：

1. **内容层**：页签内容区没有断点适配。宽表挤压、工具栏换行、双栏变单栏、弹窗超出屏幕。
2. **触摸目标**：按钮档最大 40px，图标按钮更小，手指点不准。
3. **特定页**：正文编辑器的工具栏、图鉴卡片墙、面板类浮层。

### 3.2 做法

- **断点策略**：不引入 Tailwind 新断点体系（全站零 `md:` 基础，一次性铺开风险大）。改为在既有 `compact`（<900px）之下再分一档 **narrow（<520px）**，用 JS 测宽 + 类集中下发，与现有 `WorkspaceSidebar` 同一套判定口径（同样除以 `currentUiZoom()`）。
- **触摸目标**：`Button` 新增 `touch` 档（最小 44×44），**仅窄屏生效**；桌面端视觉不变。图标按钮在窄屏统一包一层撑高容器。
- **表格**：窄屏统一策略二选一——横向滚动（保留全部列）或卡片列表（每行一张卡）。建议**先横向滚动**（改动小、不丢列），卡片化留给后续按页签评估。
- **弹窗**：`Modal` 在窄屏改为全屏面板（顶部留关闭），避免内容超出。
- **编辑器**：工具栏在窄屏收进「更多」，正文区保持全宽。🔴 注意既有红线：界面缩放用 `offsetHeight` 量尺寸、`vh/vw` 不随 zoom（用 `foldVh()`），窄屏改动不得破坏这两条。

### 3.3 判据

- 320×568（iPhone SE 级别）能完整走完：**登录 → 云端取书 → 写一章 → 保存 → 看到「已同步」**。
- 55 个页签逐个过一遍：无横向溢出、无被裁切、无需缩放即可操作。
- 主要操作触摸目标 ≥44×44；不靠颜色传达状态（图标或文字同时表达）。
- 横竖屏切换后不丢输入、不跳回顶部。

### 3.4 风险

会牵动全站布局 ⇒ 必须有视觉回归基线（改前后逐页签截图对比）+ 结构闸，禁止一次性大改。

## 4. C2 网页版全屏与证据包导出

### 4.1 全屏

浏览器有 Fullscreen API，`lib/app/desktop.ts` 的"无窗口桥就隐藏入口"要改为：桌面走窗口桥，网页走 `requestFullscreen`。

**判据**：Chrome / Edge / Safari 各验一次；进出全屏后编辑器光标与选择区不丢；手机浏览器上全屏隐藏地址栏可用。

**风险**：iOS Safari 对 `requestFullscreen` 支持有限（仅视频元素）⇒ 手机端可能无法全屏，需按实际支持情况降级为"隐藏入口"，不假装可用。

### 4.2 证据包导出

证据包已是自包含可打印 HTML（`evidencePack.ts:10`），网页版只需提供"打开打印页 → 用户另存 PDF"。

**判据**：导出的 PDF 含章节、证据、时间戳；分行分页不截断表格；不承诺与桌面 PDF 逐像素一致。

## 5. C3 本地模型的端边界

网页版在 https 下访问 `http://localhost` 的本机模型会被**混合内容策略**阻断，属浏览器平台限制，不是缺陷。

**做法**：不改代码去绕（不要教用户改浏览器安全设置）。在模型设置页与手册里写清"为什么不能"，配置保留但**明确标注"网页版不可用"**，不留无解释的灰按钮。

**判据**：文案与实际行为一致；hover / 点击能看到原因；桌面版不受影响。

## 6. C4 端能力矩阵（单一真源）

老板键、全屏、PDF 导出、本地模型、离线写作五项在三端不同，当前口径散在三处手册与多处提示里。

**做法**：新建一份端能力矩阵模块（**命名与落点在 P4 开工时定，本文档不预先指定路径，避免引用不存在的文件**），三端 × N 项出布尔与说明；界面提示与手册**都从它取**，禁止各处各写一句。

**判据**：人为改矩阵一行，界面与手册同时变；全仓 grep 不到第二份"老板键不支持"式的硬编码文案。

## 10. 产品口径（定案）

| 项 | 定案 | 说明 |
|---|---|---|
| 最小支持宽度 | **320px** | 覆盖 iPhone SE |
| 窄屏断点 | `compact < 900px`（已有）、**narrow < 520px**（新增） | 与现有判定同源，除以 zoom |
| 触摸目标 | **≥44×44px**（仅窄屏） | 桌面视觉不变 |
| 表格窄屏策略 | **先横向滚动**，卡片化按页签后续评估 | 改动最小、不丢列 |
| 全屏 | 桌面走窗口桥，网页走 Fullscreen API，iOS 不支持则隐藏 | 不假装可用 |
| 证据包导出 | 打印页另存 PDF | 不承诺像素级一致 |
| 与 3.3.3 关系 | **串行：3.3.3 发版后再开工** | 避免同文件冲突 |

## 11. 开工前必须核实的事项

1. 320/375/430 三档下逐页签的真实表现（P0 必须实测，不预判）。
2. iOS Safari 与 Android Chrome 对 `requestFullscreen`、`100vh`、输入法遮挡的实际行为。
3. `WorkspaceSidebar` 的 `compact` 阈值 900px 是否合适（390px 手机上抽屉内容本身是否还挤）。
4. 现有 `overflow-x-auto` 那 1 处之外的宽表清单（需逐页签统计列数与最小可读宽度）。
5. 3.3.3 改动涉及的 UI 文件清单（图鉴、三页签），评估串行开工的等待时间。
