## 1. `model.failure`：假模型的拒答 / 取消 / 超时

新增探针 `scripts/audit/probes/model-failure.cjs`（真便携服务 + 真浏览器 + 本地假模型），
校验器 `scripts/verify/model-failure-evidence.mjs`。三条路径各自的判据：

| 场景 | 怎么造 | 断言（要点） |
|---|---|---|
| 拒答 | 假模型 `mode=refusal` 返回拒答文本 | 界面说明是「内容政策」拒绝且**不是密钥/模型名/参数配置错**；拒答文案不写进正文 |
| 取消 | `mode=slow`（非流式 2.5s）造 2.5s 在途窗口，再触发一次 | 在途那次被中止（服务端记 `abortedAt`）；后一次正常完成；正文无脏数据；之后仍可再触发 |
| 超时 | `mode=hang`（**连响应头都不发**）+ `aiRequestTimeoutSec=30` | 客户端在 **29.998s** 放弃；从未收到一个字；正文无内容；之后仍可再触发 |

### 取消为什么不是「Esc 中断流」

实测两次：**Esc 只 dismiss 已显示的 ghost，不会中断在途请求**（那条 slow 请求仍在 2.5s 正常返回），
而伴写本身走**非流式**请求（请求体 `stream` 为假，服务端记录可查）。
所以取消的正确口径来自代码自己：`fireGhost()` 第一行就是 `ghostAbort.current?.abort()` ——
**新一次触发顶掉在途那一次**，这才是作者真实的取消路径（继续输入 / 连点钢笔键）。

### 本轮踩到的四个坑（都已修）

1. 🔴 **假模型必须先挂 `hang` 在响应之前**：客户端 `fetchWithTimeout` 的超时定时器在**收到响应头**时就被清掉，
   回了头再挂 90 秒界面一声不响。改到 `res.writeHead` 之前 ⇒ 超时准时在 30s 触发。
2. 🔴 **探针也得守条件写**：便携服务 3.2.5 起要求 `If-Match`，旧写法无条件 PUT 直接得 **428**。
   顺手把既有 `ai-refusal-probe.cjs` 一起修了（否则它今天就跑不过）。
3. 🔴 **两套源码指纹**：`audit/context.cjs#sourceFingerprint` 与 `audit/platform/source.mjs#snapshot`
   算出来不一样，用错就会出现「证据明明是这次的，验收却说与当前源码不符」。两个探针统一用 `snapshot`。
4. 🔴 **截图必须与 result-file 同目录**：分开写会让校验器判「缺截图」。

### 一条只记录、不改的观测

**伴写请求超时后界面没有任何提示**（按设计：伴写失败静默、连续失败才熔断提示）。
证据里显式记成 `observations[].id = "timeout.user-message"`，校验器**要求这条观测必须存在** ——
免得下一轮被误当成「已验证有提示」。要不要给超时单独提示属交互决策，需主人点名。

## 2. `layout.affected`：本次 UI 改动涉及的布局

复用并修好 `scripts/audit/probes/workspace-layout-probe.cjs`（全部页签 × 多组窗口/缩放，逐页量主区溢出），
新增校验器 `scripts/verify/layout-evidence.mjs`：

- 指纹必须对、`stale` 必须为假、页面异常必须为空；
- 用例数 ≥ 100、**缩放档 ≥ 3**（只测 100% 等于没测缩放这条红线）；
- 任何一条用例带 `issues` 即失败，并指出「哪一档、哪个页签、溢出了什么」。

实测：**385 条用例（55 页签 × 7 组窗口/缩放）、0 越界、0 页面异常**。

### 顺手修掉的老毛病

`workspace-layout-probe` 原来 `vite.listen()` 之后直接 `goto(45s)` —— 冷缓存下整步红过一次。
补了「轮询首页就绪 + `goto` 120s」。同类问题在 `mono-charts.mjs` 与 `draft-failure.mjs` 上又犯了一次
（`domcontentloaded` 要等模块脚本执行完，机器忙时 60s 顶穿），统一改成
**`waitUntil: 'commit'` + 等 React 真挂上 `#root`（180s）** —— 判的是「首屏可用」，不再受模块编译拖累。
