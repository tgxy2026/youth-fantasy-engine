## 六、本轮方法论增量（下轮可直接用）

1. 🔴🔴 **「catch 体是否为空」是个会失明的判据**：`backup.ts:117` 的 catch **只写了注释**，
   于是既不算"空 catch"（有内容）、也不算"只 log"（没 log）⇒ 扫描器**完全看不见**它，
   而它正是本轮最严重的一处静默失败。**判据应改为「catch 块内是否存在任何*可执行语句*」**，
   并把「catch 里只有注释」单列一节（注释≠处理）。
2. **「声明表 vs 实现」这类矛盾，最可靠的发现方式是横向比对同一功能的两处口径**：
   `CheckTools.tsx:225` 的预算 kind 与 `:384` 的 feature id 就在**同一个文件的两百行之内**，
   只要把两者并排看就会露馅 —— 扫描器不会自动做这件事，属子代理的强项。
3. **修「挂错 id」类问题要顺手补闸**：本轮新增 `consistency-selfcheck` 条目后，
   `tests/aiDataSources.test.ts` ② 与 ③ 两条（表里每条都要被引用 / 界面引用的都要在表里）
   **天然守住了"新增+改引用必须成对"**，零额外成本。
4. **`text-18` 这类"从未生效的类名"值得单独扫**：把 `src/` 里所有 `text-N` / `rounded-N` 与
   `@theme` 的令牌集合求差，即可一次性揪出全部"写了但不存在"的类名（本轮靠子代理人工比对发现）。
