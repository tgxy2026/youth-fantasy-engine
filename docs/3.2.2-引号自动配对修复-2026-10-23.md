# 3.2.2 · 正文引号自动配对 bug 修复（读者反馈，2026-10-23 晚）

> 反馈原文（读者群 @铁骨咸鱼）：「今天正文编辑打引号有 bug，按一下只出后引号，再按一下出很多引号」
> 判定：**真 bug，且在已发布的 3.2.1 里**。根因是 3.2.1 的 T-13 改动方向错了。

## 一、复现（CDP 模拟输入法，隔离资料区）

| 场景 | 修复前 | 期望 |
|---|---|---|
| 非组合态敲 `“` | `“”` 光标居中 ✅ | — |
| **组合态**（输入法）敲一次 | **`““”`** ❌ | `“”` |
| 连续两次 | **`“““”`** ❌ 越打越多 | `“”` → 跳出 → `“”“”` |

## 二、事件序列（实测，这是判决书）

```
compositionstart
compositionupdate            data="“"      value=""
input    composing=true      data="“"      value="“"   caret=1   ← 3.2.1 在这里补 ”
beforeinput composing=false  data="“"      value="​“”"  caret=1   ← 输入法随后提交到我们移动后的光标
input    composing=false     data="“"      value="““”" caret=2   ← 于是多出一个左引号
```

**结论**：组合期间的 `input` 事件里，`value` 是**未提交的预览串**。
此时补右标点并移动光标，输入法提交时就会把自己的字插到我们移动后的位置 ⇒ 每按一次多一个。
所谓"只出后引号"，就是这中间某一步的瞬时画面。

## 三、根因

3.2.1 · T-13 为了修「搜狗/微软拼音打 `“` 不补右半边」，把「组合态一律早退」改成
「组合态也判一次，命中单个左标点就补」。**方向错了** —— 真实原因是当时只靠
`next.length === prev.length + 1`（长度差）判断，而组合态下长度差永远对不上。
正确做法不是"组合态也补"，而是**等提交之后再补**。

## 四、修法（三条，各司其职）

1. **组合态一律不碰 DOM**：`onChange` 里 `if (ev.isComposing) { onContentChange(next); return }`，恢复早退。
2. **判据换成事件自带的 `data`**：`planPunctPair(value, caret, data)` ——
   普通键盘输入 `data` 就是那个字符；输入法提交时 `data` 是被提交的字符；
   粘贴/撤销 `data` 为 null 或长度 >1 ⇒ 不插手。
3. **补一条 `onCompositionEnd`**：有些输入法只把字留在组合里、**不发提交事件**（实测如此），
   只靠第 2 条会一直不补。组合结束时按「光标前的字」再判一次（`planPunctPairAtCaret`），
   两条路径结果相同且幂等。

### 额外：type-over（跳出引号）

原逻辑「后面已有右标点就不补」会让连按的第二下留下一个孤零零的左引号（`““”`），
第三下 `“““”`——这正是读者说的"很多引号"。改成：**在自己刚造出来的那对引号中间再按一次 ⇒ 跳出去**
（删掉刚插入的左引号、光标越过右引号）。
判据刻意收窄：只有「光标前一个字符也是同一个左引号」才跳，所以"回头给已有 `”` 补开引号"不受影响。

连按节奏变为：`“”`（光标居中）→ 再按跳出 → `“”“”`（新开一对）。

## 六、影响面

- 只影响**中文左标点自动补右半边**这一个功能（`“ ‘ 《 〈 「 『 （ 【`）；
- 英文字符、粘贴、撤销、删除、选区替换一律不插手（判据未变）；
- 已在 3.2.1 发布，**修复进 3.2.2**；3.2.1 用户升级后即可。
