## 二、背景：这一族事故的共同形状

三条历史 P0/P1 都不是「崩溃」，而是**静默地让某个动作白做**：

1. **`baseCache` 启动即空** ⇒ 「本地没有、云端有」被判成「另一端新增」⇒ 删掉的项目复活（幽灵项目，四条路径）；
2. **`restoreFromCloudBackup` 绕过 `clearDeleted`** ⇒ 恢复回来的记录被下一次合并按旧墓碑丢弃 ⇒ **恢复被静默撤销**；
3. **拉取失败时清空 cache** ⇒ 兜底镜像拿到空快照 ⇒ **「保住未推送改动」的最后一环被无声抵消**。

共同点：**没有任何报错**，作者看到的是「看起来正常」的界面。所以修法一律是**把判据收口到一处 + 用负面对照钉住**。

## 三、设计

### 3.1 L2 —— `localForMerge()` 单一入口

**问题**：`mergeCaches(base, server, local)` 的第三路 `local` 决定两件事 ——
① `localHasContent`（能否把「本地没有这条」读成「本机删掉了它」）；② 各 store 的 `lo` 取值。
云模式下**内存 `cache` 在首次 `ensureInit` 完成之前是空的**（启动瞬间），只看它会得出
`localHasContent = false`、把整条墓碑闸短路 —— 正是幽灵项目那条链。
而 `localSnapshotProvider`（db 层注入）读的是磁盘上真正的本机库，才是那个窗口期里可信的「本地」。

**改法**：在 `createCloudStore` 闭包内新增

```ts
async function localForMerge(): Promise<SyncStores | null>
// null ＝「注册了回调但读取失败」⇒ 本机状态未知
```

| 调用点 | 收口前 | 收口后 |
|---|---|---|
| `ensureInit` | `localSnapPre ?? cache` | `localForMerge()`；**null ⇒ 中止本次拉取**（在推进 rev 之前），置 error |
| `backgroundPull` | 直接 `cache` | `localForMerge()`；**null ⇒ 中止本次拉取且不推进 rev**（留给下次轮询） |
| 409 冲突合并 | 直接 `cache` | `localForMerge()`；**null ⇒ 停手报错**（绝不拿空 cache 硬合） |

🔴 **null 的处置统一为「中止 + 报 error」**，不硬合：
误判成「删除」会丢云端数据，误判成「新增」会让删掉的记录复活 —— 两侧代价都不对称地大。
未注册回调时退回 `cache`（保守侧，与收口前一致）。

### 3.2 L3 —— 路径闸抽成独立模块 + 真机（node）分支覆盖

**问题**：路径闸（`assertSyncPath`）原先内联在 `main.cjs`，主进程不可在单测里加载 ⇒
「真机桌面路径的校验规则」**只有源码闸、没有行为覆盖**；而 `syncTransport.test.ts` 走 FSA 句柄，
**根本不经它**。

**改法**：
1. 抽出 **`electron/syncPath.cjs`**（规则只有一处；main.cjs 顶部 `require`）；
2. 测试 **`tests/syncPath.test.ts`**：
   - 源码闸：模块存在、规则含「绝对路径 + `.yfe`（或派生名）」、main.cjs **不再内联**、quarantine 命名落放行集；
   - **行为用例**：注入 `window.electronStore` 桩 + **字符串目录句柄**，走 `nodeRead`/`nodeWrite` 分支 ——
     验证正常写盘路径合规、**损坏隔离的 `.corrupt-<ts>` 派生名通过路径闸**、原文件不被覆盖、损坏时 push 拒绝、重复 pull 只隔离一次。

### 3.3 建议 3 —— 恢复 / 回滚 / 镜像三路径

新增 **`tests/syncRestore.test.ts`**（与 `syncGuards` 分工：那边是「防呆」，这边是「动作路径」）：

| 用例 | 锁住的行为 |
|---|---|
| ⑮ 恢复 | `restoreFromCloudBackup` 回滚到检查点 + **清墓碑**（否则下次合并又丢弃 = 恢复被静默撤销）+ 镜像回调带回恢复后的数据 |
| ⑯ 回滚防护 | 恢复后推送撞 409 且重试耗尽 ⇒ 返回 **false** 且状态 **error**（绝不谎报「已恢复」） |
| ⑰ 镜像 | 闩锁期 `onFallback` 收到的快照**非空**（清了就等于静默丢改动） |
