## 🔴 本轮新发现的封装阻塞与根治（重要）

**现象**：`build-desktop.mjs` 连续两次在 electron-builder 阶段失败；日志止于内置 rcedit 连报
`Fatal error: Unable to commit changes`（4 次），**NSIS 阶段完全没有执行**，脚本报「未找到安装包产物」。

**与历史记录的差异**：`novel-studio-packaging` skill 一直记「electron-builder 自己重试 3 次就放弃并
**继续打包**」（2026-09-17 起多次实测）。本轮**不成立** —— 实测连续 3 次（两次全流程 + 一次干净诊断
`electron-builder` 直调），退出码均为 **1**，流程**直接中止**。

**定位过程**：

1. after-pack 钩子第 **1/12** 次即成功，主 exe 体积 **181,097,984** 与基线逐字节一致、含开发组名与版本串
   ⇒ **元数据/图标早已写到位**（主 exe 合格）。
2. 手动用同一个 rcedit（winCodeSign 2.6.0）分别喂**中文路径 icon** 与 **ASCII 路径 icon**，**两次都成功**
   ⇒ 排除「中文路径」与「rcedit 二进制损坏」。
3. 干净诊断跑（`node node_modules/electron-builder/cli.js --win --x64 …`，完整日志落盘）确认：
   after-pack 之后 electron-builder 自己的 `signAndEditExecutable`（rcedit）在**紧接 after-pack 之后**
   连败 4 次即 `exit 1`，NSIS 一步未跑。
4. 结论：electron-builder 内置 rcedit 在 after-pack 刚改写 exe 之后**必失败并中止构建**；
   而这一步的输出（图标 + 版本资源）**after-pack 已经完全覆盖**，属**多余且必失败**。

**根治**：`electron-builder.yml` 的 `win` 段新增 `signAndEditExecutable: false` —— 跳过 electron-builder
内置 rcedit，主 exe 的图标与版本资源**只由 after-pack 保证**。本项目**不做代码签名**，跳过该步无副作用。

**验证**：改配置后重跑，`exit 0`，日志出现
`• building target=nsis file=…Setup-2.7.0.exe` → `打包完成（81.01 MB，体积闸门已通过）`；
主 exe 体积与元数据仍与基线逐字节一致 ⇒ **修复未影响产物质量**。
