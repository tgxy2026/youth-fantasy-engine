# 3.2.3 版本可靠性收口方案

> 编写日期：2026-10-24。状态：分阶段实施中；R0/R1/R2/R3 已有阶段成果，R4 运行补证推进中。原设计与起草基线保留，最新进度见第 12 节。
> 目标：用可重复运行的自动化，收口校对结果协议、保存与恢复、候选应用及多形态运行的可靠性问题。
> 基线：main / c4e2f9b，package.json 为 3.2.2；本次规划前复核 tsc、eslint src tests 通过，全量 305 个测试入口通过。以后以实际扫描与执行数量为准。
> 版本说明：根据用户最新更正，两份方案统一归入 3.2.3；3.2.2 为已发布基线，不覆盖其 tag 和附件。可靠性与大表性能两条工作线共用验收工具，最终汇合为同一版。本方案不修改 package.json，不执行封装、安装、发布或部署。

## 1. 交付目标与范围

完成后，开发者运行一次指定入口，工具自动完成环境检查、隔离数据准备、本地服务启动、故障注入、真实持久化回读、失败取证和汇总。正常通过的项目不逐项要求人工确认。

本轮重点如下，按顺序实施：

| 顺序 | 工作项 | 要解决的问题 | 交付判据 |
|---|---|---|---|
| R0 | 统一自动验收入口 | 脚本散落、固定路径、旧证据被重复使用 | 新克隆在依赖准备好后可独立执行，不依赖某次 .workbuddy/tmp 内容 |
| R1 | 校对结果协议收口 | 修改建议被作为正文替换；数组提示词与对象输出模式不一致 | 建议不可直接替换；可替换文本有显式类型并经过定位校验 |
| R2 | 保存与候选恢复 | 内存接受不等于落盘；异常阶段可能误报成功 | 真实后端失败不丢草稿，恢复后能回读；候选状态与正文一致 |
| R3 | 四种运行配置验收 | 审计执行完成不能代表跨形态行为通过 | 必需运行场景有当次证据，缺环境如实阻塞 |
| R4 | 交付链和少量真机边界 | 封装、原生窗口、输入法存在自动化盲区 | 可自动化部分流水化；剩余项只保留一份短清单 |

不纳入：酒馆秘密知情结构迁移、酒馆协议重写、文风优先级大改、全局信息架构、增量同步、证书购买、生产云端备份运维。它们继续按各自专项管理，避免与本轮合并扩大回归面。

|---|---|---|

当前通用 sourceFingerprint 只遍历 src、electron。后续涉及 server、构建、配置或探针本身时，必须增加相应输入指纹，不能仅凭这个指纹认定全范围证据有效。

## 3. 默认决策：减少实施时反复询问

1. 默认只在本机、隔离目录运行，使用程序生成的虚构稿件，不读取真实书库、生产账号或生产服务器。
2. 默认模型为本地假服务；不消耗真实 API 额度。真实端点作为显式选择的扩展套件。
3. 默认复用现有浏览器和 Electron；缺依赖时输出一次汇总，不自动修改机器级配置或安装第三方桌面工具。
4. 原生安装测试默认只在可丢弃 Windows 虚拟机或专用测试用户中进行，避免覆盖开发者现有安装。
5. 自动化失败先保留证据并归类，不弹出一串确认框，不通过延长超时、反复重试或放宽断言掩盖失败。
6. 本轮保留原有产品保存与确认流程，不因“测试自动化”增加作者日常操作步骤。

## 4. 自动化执行器设计（拟新增）

### 4.1 入口与执行档位

建议新增 scripts/verify/reliability.mjs，使用异步子进程启动，避开本机已记录的 spawnSync / execFileSync 问题。工具进程显式隐藏窗口。

以下命令为实施后的接口约定，当前尚不存在：

~~~powershell
# 默认离线：检查、独立生产构建、本地服务、运行探针、汇总
node scripts/verify/reliability.mjs --profile local

# 验证已明确提供的候选安装包/便携包；不在执行器内偷偷重打包
node scripts/verify/reliability.mjs --profile packaged --artifacts-manifest <清单路径>

# 仅在显式选择后访问配置好的测试端点/原生测试环境
node scripts/verify/reliability.mjs --profile extended --config <本地配置路径>
~~~

local 默认顺序：环境预检 → tsc/lint/分批全量测试 → 新建隔离构建目录 → 校对协议探针 → 四配置保存/恢复探针 → 可靠性探针 → 受影响布局探针 → 现有审计适配 → 汇总。

生产前端构建写入本次 run 目录，不覆盖 dist、release。耗资源的浏览器/Electron 探针顺序运行；不允许多个 Vite 与浏览器压测争用资源后把超时记作产品失败。

### 4.2 隔离与环境预检

- 每次运行分配唯一 runId，保存到 .workbuddy/tmp/reliability-<runId>/。
- 自动分配空闲端口，所有子任务接收明确端口与路径；服务健康检查通过后才开浏览器。
- 浏览器使用独立 profile；Electron 同时隔离 userData、appData，防止旧库迁移探测接触真实目录。
- 便携服务指向新建临时数据根目录；本地网页版显式设置 YFE_DATA、YFE_WWW，启动前断言路径在本次 run 根下。
- 云端配置使用本地真实 server 与临时账号，不伪造 auth/me 响应替代账号隔离验证。
- 只对子进程清除冲突代理与 ELECTRON_RUN_AS_NODE 等环境；远端测试需要代理时使用显式配置，不改全局代理。
- 前置工具检查不输出密钥；日志和请求录制对 Authorization、Cookie、邀请码等脱敏。
- 超时或退出后按本次记录的 PID 关闭进程，不按名称杀死用户全部 Electron/Node 进程；证据保留，不清理历史恢复目录。

### 4.3 状态、指纹与失败处理

每个用例输出 id、suite、profile、status、assertions、durationMs、inputHash、artifactHashes、evidencePaths、reason。

状态统一为 passed / failed / blocked / not-run / not-applicable。失败另记分类：product、environment、harness；工具自身崩溃也不能算 passed。未实现或缺环境的用例不能标为 not-applicable。

报告同时保存 Git HEAD、dirty diff 摘要、运行时版本、平台配置、锁文件哈希、测试脚本指纹和构建资源哈希。按套件记录输入集合：

- 前端/桌面：src、electron、依赖锁、相关构建配置；
- 本地网页版：再加入 server 与服务端配置；
- 工具：加入执行器、探针、夹具、契约清单；
- 包验收：加入所测 exe/zip 与安装后实际资源哈希。

任一输入不匹配则旧证据标为过期；历史结果保留但不计入本次通过。原审计指纹算法保持兼容，新执行器以额外字段扩展，不静默修改历史证据语义。

首次失败自动收集截图、浏览器 trace、控制台、脱敏请求摘要、失败前后存储摘要。环境暂态最多额外重跑一次，保留首次失败并标记 flaky；数据丢失、串项目、正文错误替换等产品失败不自动重试转绿。

退出码约定：0 为所选档位全部必需项通过；1 为确认失败或执行器错误；2 为必需项 blocked / not-run / 证据过期。local 通过的报告只能写“本地自动化通过”，不能写“全部发布验收完成”。

## 5. R1：校对协议和正文应用

### 5.1 已核实的调用链

- src/lib/aiTasks/proofread.ts 的逻辑提示词允许无法直接修复时把“修改建议”写进 fix。
- 同一文件把 fix、建议、suggestion 归入同一个 fix 字段；请求指定 json-object，提示词却要求顶层数组。
- src/components/editor/EditorModals.tsx 的 replaceIssue 使用 iss.fix 替换原文。

因此本项需要提示词、解析、结果类型与按钮行为一起改，不能只换按钮文案。

### 5.2 默认结果契约

新结果采用对象外壳，结构示意：

~~~json
{
  "schemaVersion": 1,
  "issues": [
    {
      "kind": "suggestion",
      "type": "逻辑",
      "quote": "可定位的原文",
      "suggestion": "解释人物改变决定的原因",
      "why": "本段缺少动机过渡"
    }
  ]
}
~~~

另一种 kind 为 replacement，必须包含独立 replacement 文本。模型结果先作为 unknown 校验，再转成内部判别联合类型；只有 replacement 类型进入替换函数。

默认策略：

1. suggestion 只展示建议并提供复制；禁止转换成“一键替换”文本。
2. replacement 要求原文精确定位、替换值非空且不同于原文；删除整段不通过空 replacement 暗示，本轮不开放这种操作。
3. 旧顶层数组和旧 fix 格式可解析，但缺少明确 kind 时按建议展示，不靠关键词猜测是否可替换。历史结果能回看，不能据旧 fix 自动解锁替换。
4. 输出无法解析、结构非法或定位失败时如实报告，不能显示成“未发现问题”。
5. 应用时核对本次报告绑定的项目、章节与正文基线。正文发生变化则停止直接替换，要求重新核对；同句多次出现必须使用已定位的范围，不能任意回退到第一处。
6. 两层校对共存时，已应用编辑导致的位移、相交范围与另一层结果一并失效或重新定位。新增规则覆盖直接校对入口，不能只保护候选面板。

作者在本面板成功应用一条替换后，更新该组结果的正文基线和仍有效的范围映射，允许继续处理下一条；外部编辑或无法安全重定位的相交范围才失效。不能让“基线保护”退化成每改一条都必须重新请求模型。

### 5.3 自动验收矩阵

| 类别 | 自动生成/录制的场景 | 核心断言 |
|---|---|---|
| 正常 | 对象外壳、合法 replacement、合法 suggestion、空 issues | 类型正确；只有 replacement 有可用替换按钮 |
| 旧协议 | 顶层数组、fix、建议、suggestion 别名 | 可显示；无 kind 时不直接替换 |
| 非法返回 | 无效 JSON、错外壳、缺字段、拒答、空回复、未知 kind | 错误可见，不变成“0 问题” |
| 锚定 | 同句重复、找不到引文、重叠引文、正文手改、切章/切项目后迟到 | 只改已确认范围；失效结果不能修改当前正文 |
| 交互 | 连点、取消、跨层应用、刷新后查看旧报告 | 无重复替换、无建议入正文、历史降级一致 |
| 真存储 | UI 应用后保存、关闭重开 | 从 IDB/文件回读正确正文；不是仅检查界面文字 |

使用本地假服务记录真实请求，自动断言提示词与 json-object 一致。用明确的合成样本验证协议，不要求作者先提供文学质量评测集。

## 6. R2：保存失败与候选恢复

### 6.1 四配置保存故障

| 配置 | 注入位置 | 取证方式 |
|---|---|---|
| desktop | 测试引导中拦截目标文件写/rename/flush，或独立临时目录写权限失败 | UI 草稿、主文件/载荷文件、重启回读 |
| portable | 本地 HTTP 失败、连接中断、提交后响应丢失 | 实际便携服务文件与重启回读 |
| web-cloud | 本地真实 server 的失败/配额/会话替换，限临时账号 | 按账号落盘文件、响应与独立会话读回 |
| web-guest | 测试启动脚本在目标 IDB 写事务制造 abort/QuotaExceededError | 关闭连接再读新事务；失败输入仍可导出/重试 |

注入必须限定目标路径、数据库或请求；不在产品中留下可远程触发的故障开关。IDB 注入属于故障模型验证，不能声称真实磁盘写满已验证。

每项统一断言：失败不清 dirty、不误报已保存、失败草稿可重试；恢复后持久化成功；保存中继续编辑不会因旧回执清空新草稿；切项目不会串写。

### 6.2 候选故障点

用明确屏障控制“提交意图落盘前/后、正文写入前/后、回读、回执写入前/后”，不靠随机等待碰运气。每个阶段分别测试失败、应用进程被终止、重新启动核对、重试。

- 意图未持久化：正文不变。
- 正文未写：可重试，不能把候选作废。
- 正文已写而回执未写：进入核对，不重复覆盖作者后续编辑。
- 回读不一致：不报成功；保留原稿/候选/错误线索。
- 重复应用：不会二次覆盖；同章其他候选失效口径一致。
- failureReceipt 如需接入，失败尝试记录落 job，并补查询展示；不得直接挂 candidate 导致可重试失败被 reconcileCrash 判为 discarded。此项不为消除零引用而机械接线。

对可确定阶段的进程终止安排少量独立进程测试，不能把内存异常测试写成真实崩溃恢复已验证。

### 6.3 备份、迁移与导入导出

复用可靠性探针的历史备份迁移与部分导出场景；扩充损坏一个/多个载荷、目标不可写、迁移中断、主 JSON 与 blobs 同时恢复、恢复失败后重试。自动比较记录标识、正文和载荷哈希，不以“导出成功”提示作判据。

原生选目录/保存框默认通过固定返回路径测试文件链路。真实窗口交互在 R4 单独记分，不能与上述结果合并。

## 7. R3：平台矩阵与网络边界

复用 scripts/audit/platform/policy.json，不再手写另一份平台单元总数。当前矩阵为 26 个“契约×配置”单元，运行时从配置展开。

默认 local 档优先填入 boot-store、write-failure、roundtrip 及适用的账号隔离/并发子场景。仅当单元全部必需子场景通过，才更新其 verified；某个子场景有证据不能代表整个单元通过。

- web-cloud 使用两个独立浏览器上下文模拟两设备会话；再用共享 Cookie 的两个标签验证同浏览器场景。这能自动覆盖协议隔离，不声称覆盖两台实体设备与真实公网。
- 会话过期用本地测试服务签发已过期凭证/测试时钟验证，不等待 30 天；测试适配只在隔离服务中生效。
- 网络用本地假模型覆盖鉴权失败、拒答、流式截断、取消、超时、usage 归属。HTTPS、真实代理和真实服务商兼容性使用扩展档，未跑保留未验证。
- 旧证据指纹不符或文件缺失时从报告剔除；不修改历史记录中的数字来拼出满分矩阵。

### 7.1 必需项清单与矩阵适配

拟新增 scripts/verify/reliability.contracts.json，作为本轮档位执行清单；平台/场景名称引用现有 policy.json，不再复制平台定义。默认 local 必需项明确为：R1 全表场景、四配置 boot-store/write-failure/roundtrip、R2 候选各阶段恢复、备份迁移与部分导出、本地 web-cloud 账号隔离/会话替换/过期和双标签并发、假模型拒答/取消/超时，以及本次 UI 改动涉及的布局契约。

清单同时定义样本生成方式、适用配置、证据适配器及最少断言数。执行器启动时核对计划任务数，结束时核对结果数；零样本、少跑、重复 id、缺产物或父进程提前退出均不能通过。

本轮 local 清单通过不意味着 26 单元全部 verified，尤其 network/artifacts 等含真实外部条件的单元。适配器只能更新已有矩阵中确实完整覆盖的单元；extended 缺环境与 local 不适用的范围单独列明，不通过删除矩阵子场景来获得满分。

## 8. R4：交付链自动化与残余人工项目

### 8.1 工程改造

1. 将 .workbuddy/tools 中仍被必需契约依赖的取证逻辑整理到 scripts/audit 或 scripts/verify，共享夹具入库；临时结果仍不入库。新克隆不能依赖个人目录。
2. 为探针统一增加 build-dir、run-dir、port、browser/executable 等参数，消除写死构建目录和特定机器 Node 路径。
3. 构建预检明确检查 rcedit/7zip 来源和可执行性；校验现有工具，不能依赖临时 npm 安装得到的未锁定 vendor。若需新增依赖，固定来源与版本后纳入锁文件。
4. rcedit 顺序保留“构建器退出→补元数据→prepackaged→复验”；在本机不能可靠调用时，自动输出已解析路径的单次恢复入口并标 blocked，不继续发布。

