## 4. 命中盒盘点（口径与缺口）

### 4.1 为什么必须测「生效命中盒」而不是视觉盒

项目从 3.3.1 起在 `src/index.css` 给图标键加了热区：

```css
@media (hover: none) and (pointer: coarse) {
  button[data-button-sizing='icon']::after,
  button[data-button-icon-only='1']::after {
    width: max(100%, 44px); height: max(100%, 44px);
  }
}
```

视觉仍是 32×32，但可点范围已被 `::after` 扩到 44×44。本探针在**粗指针环境**（`pointer: coarse` / `hover: none` 实测均为 true）
取 `max(布局盒, ::after 计算尺寸)` 作为生效命中盒，再判 44。

> 🔴 首轮按视觉盒判定，得出「关键交互 94% 不达标」—— 那是**误报**。加热区判定后：
> 257 个关键动作里有 **182 个视觉小但命中已达标**、15 个视觉本身就够大，真实缺口是 60 个。

### 4.2 三档口径（规划 §3.3 只对第一档是硬判据）

| 档 | 定义 | 本版要求 |
|---|---|---|
| **关键动作** | 保存/同步/关闭/取消/确认/删除/新增/打开项目菜单/界面与数据设置/撤销/恢复/编辑工具/专注模式/继续写作/登录/退出/返回/上下章/行操作 | **≥44×44**，不达标即缺陷 |
| **表格行内** | `closest('table')` 内的输入、下拉、单元格按钮 | 允许靠**行高**达标，但同一行内控件不得互相遮挡 |
| **次要工具栏** | 帮助问号、视图切换、字段设置等辅助入口 | 视觉可小，**但必须有热区**；无热区记为待修 |

## 5. 阈值边界（519/520/521、899/900/901）

在三档连续宽度上量两件事：导航形态、内容字段行的排布。目的是抓「阈值振荡」与「重复折算」。

| 宽度 | 导航 | 字段行排列 | 字段容器宽 | 根溢出 |
|---|---|---|---|---|
| 519 | 抽屉 | 上下（1 列） | 447 | 0 |
| 520 | 抽屉 | 上下（1 列） | 448 | 0 |
| 521 | 抽屉 | 上下（1 列） | 449 | 0 |
| 899 | 抽屉 | 左右并排（2 列） | 803 | 0 |
| 900 | 内联 223px | 左右并排（2 列） | 628 | 0 |
| 901 | 内联 223px | 左右并排（2 列） | 629 | 0 |

结论：

- **导航在 900 处切换**（<900 抽屉、≥900 内联），519→521 三档行为一致，无振荡。
- 900 处字段容器从 803 掉到 628，是**侧栏出现占去的宽度**，属预期；内容仍按自己的容器查询走，没有二次按 window 折算。
- 字段行的断点来自容器查询（`@min-[32rem]/fields`，512px），所以 519/520/521 三档**完全一致** —— 这条正是「内容不看 window」的证据。
- 规划 §3.1-3 要求的两处边界都实测了；UI 缩放 100/125/160% 仍在 S-09，本批未测。

## 6. 能力契约 C4（P0 交付）

新增两个模块（纯解析 + 运行时取值分层）：

| 文件 | 职责 |
|---|---|
| `src/lib/app/capabilities.ts` | 纯函数：9 项能力 × 四态（supported/conditional/unsupported/unknown）、原因码、通道、动作、回退、面向作者的一句话。零 import，可完全伪造输入测试 |
| `src/lib/app/capabilitySignals.ts` | 运行时取值：只调用**既有**判定（`platform.ts` / `desktop.ts` / `fileBackend.ts` / `bossKey.ts`），不新写平台判断表 |
| `tests/capabilities.test.ts` | 32 条：三形态矩阵、策略 vs 平台、桥逐个探、离线三段、`canDo` 闸、账本完整性 |

**已经钉死的三个口径**（规划 §6 要求的「不许混为一谈」）：

1. **产品策略禁用 ≠ 平台不具备**：网页版本机模型是 `policy-blocked`（P9 策略），老板键在浏览器里是 `platform-missing`（没有窗口桥）。把前者说成后者，作者会以为换浏览器就行。
2. **桥要逐个探**：有 `electronStore` 不等于有 `exportPdf`；桌面壳缺 `electronBoss` 时老板键必须是 `unsupported`，**不许**退化成「页面遮挡」（否则作者以为窗口藏了）。
3. **离线三段分开**：已加载可编辑（各形态都 supported）/ 断网冷启动（云端 `needs-online`）/ 保存落盘（云端断网 `conditional` + 重试回退）。

覆盖的 9 项：老板键、全屏、PDF 导出、文件下载、本机模型、离线继续编辑、断网冷启动、保存落盘、跨设备同步。

> 现状：契约已可调用，但界面/设置/手册**尚未接入**（规划把消费者接线放在 P1 骨架与 P3 能力功能）。
> 本版不把「契约写好」当成「界面已一致」—— 那要等入口改成消费同一份解析结果后另记证据。

## 7. 性能基线（1280×800，固定夹具）

协议：示例项目 + 正文编辑，热身后 3 轮；输入每轮 100 字、导航每轮 20 次（5 个页签循环）；每轮单独记 p95。
输入延迟 = 输入事件到下一帧更新；另记 longtask（>50ms）。

| 轮次 | 输入样本 | p50 | p95 | max | >200ms | longtask |
|---|---|---|---|---|---|---|
| 第 1 轮 | 100 | 7.4 | 16.5 | 20.4 | 0 | 0 |
| 第 2 轮 | 100 | 7.2 | 15.0 | 17.2 | 0 | 0 |
| 第 3 轮 | 100 | 11.5 | 15.8 | 20.4 | 0 | 0 |
| **基线（三轮 p95 均值）** | — | — | **15.8** | **20.4** | **0** | **0** |

| 轮次 | 导航样本 | p50 | p95 | max | 失败 |
|---|---|---|---|---|---|
| 第 1 轮 | 20 | 80 | 128 | 128 | 0 |
| 第 2 轮 | 20 | 63 | 158 | 158 | 0 |
| 第 3 轮 | 20 | 86 | 160 | 160 | 0 |
| **基线（三轮 p95 均值）** | — | ~**76** | **148.7** | — | 0 |

判读：

- 输入侧健康：p95 15.8ms、无一次 >200ms、无长任务，离规划 §3.3 的「持续 >200ms 停顿」很远。
- **导航 p95 148.7ms 是本版最需要盯的数**：P1 冻结预算后允许劣化 20%（≈178ms），而本轮 max 已到 160ms。
  若 P2 加触摸热区/行高导致导航变慢，这项会先破线。
- 这把尺子是**同一台机、同一夹具、同一构建**才有意义；换设备或换示例数据都要重记。
