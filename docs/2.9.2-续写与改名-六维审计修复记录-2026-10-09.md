## 二、4 条修复（P1 × 1 + P2 × 3，全部经源码验尸确认，无误报）

### 🔴 P1 · 前文章节的额度分配方向反了（`lib/continuationPick.ts`）

**症状**：`for (const c of flat.slice(idx - n, idx))` 是**旧 → 新** 顺序，`used` 从 0 累加
⇒ **最老的章先吃满额度**；章数一多时，轮到**紧邻的上一章**已经 `room <= 200` ⇒ 被丢进「未带入」。

**为什么是 P1**：本项在注释与文件头里明确写着**兼作衔接参照**（"紧邻上一章的末尾就靠它带进来"），
而丢掉的恰恰是它 —— 衔接直接失效；UI 又只笼统报「前文章节 N 章」，
作者**看不出丢的是最要命的那一章**（不报错、只是接不上）。

**修法**：额度**从紧邻章开始分配**（新 → 旧），分配完再按**叙事序**（旧 → 新）输出。

**负面对照**：注入旧写法 ⇒ 新增的 ⑧b 断言变红，extra 直接打出 `第1章`（＝ bug 现场），
还原后 `sha256` 与注入前**逐字节一致**。

### P2-1 · 预算预览漏算「写作文风」（`components/useJieWenJiModel.ts`）

预览的 `extra` 只算 `摘要 + 前文章节 + 正文末尾`，而**真跑时会多推一个 `【写作文风】` 块**
⇒ 勾了文风档却显示「未超预算」，到真跑时才超 —— **预估骗人**（正是本项目「预算不得静默丢 / 不骗人」的红线）。
**修法**：预览同样加上 `activeFingerprintNote().length`（`fpLen`）。

### P2-2 · `found:false` 产生了却没人消费（`components/useJieWenJiModel.ts`）

`continuationPick` 与 `getContinuationSources` 都承诺「焦点章找不到 ⇒ `found:false`，调用方必须提示」，
但两处调用点都只读另外 4 个字段 ⇒ **「章没定位到」与「作者没勾素材」在界面上不可区分**（红线：未知 ≠ 空）。
**修法**：预览 state 加 `srcFound`，UI 在 `!srcFound` 时如实显示一行；真跑时也 toast 一次。

### P2-3 · 提示词引用了**不存在**的块名（`lib/aiTasks/jieWenJi.ts`）

`P_continue_passage` 第 3 条写「遵守【写作规范】」，而实际拼出的块是 `【项目资料】`
（写作规范作为 `〖写作规范〗` **子段**在里面）—— 模型按名字找不到该块，规则约束力被削弱
（承诺 ↔ 实现不一致；模板疑似从 `P_rewrite_passage` 复制而来，那边确有 `【写作规范】` 块）。
**修法**：改指 `〖写作规范〗`（并写明「本次没带就不必强求」）；
顺带把续写自己的块名 `【文风档】` 对齐 UI 名 → `【写作文风】`。
