# 2.2.0 · 创意写作融合「一键续写」+ 全局收口（2026-09-19）

> 本轮把「AI 一键续写 + 设定补完」并进「创意写作」，并顺手清了服务器时代的残留、
> 调整了两个重流程功能的档位、统一了全项目的数值输入。**版本号未动、未封装。**

## 一、融合：创意写作支持两种起点

### 需求（老大原话）
> 把 AI 一键续写加设定补完功能跟创意写作融合起来；在灵感启发内删除掉它。
> 创意写作不仅要支持一句话想法从零创作，也应该支持根据已有内容进行创作续写。
> 另外我发现：创意写作切页签后保存的内容会消失，也没有接口开始项目的继续续写推进。

### 诊断（第 2 条是真 bug，根因明确）
面板把所有状态放在组件 `useState` 里，而 `App.tsx` 是「切页签即卸载组件」的渲染方式
（`if (activeTab === 'creative-writing') return <CreativeWritingPanel />`）——
切走再回来，**进度、日志、闸门、断点、结果全部重建为空**，长任务等于白跑。
这不是"保存失败"，是**状态根本没有活在组件之外**。

### 做法

| 层 | 文件 | 变化 |
|---|---|---|
| 会话状态 | `lib/creativeSession.ts`（新） | 模块级单例 + `useSyncExternalStore`；**任务跑在 store 里**，组件只订阅与展示 |
| 编排器 | `lib/aiWorkflow.ts` | 新增 `mode: 'scratch' \| 'continue'` 与 `CONTINUE_STAGES`（只有连写一步）；连写执行体两模式共用 |
| 界面 | `components/CreativeWritingPanel.tsx` | 重写：起点分段切换 + 两套参数 + 闸门 + 逐章裁决弹窗 + 设定补全弹窗 |
| 删除 | `components/AutoContinue.tsx` | 删；能力全部并入创意写作 |

**两条起点**：

| 起点 | 流程 | 输入 |
|---|---|---|
| 从一句话创作 | 设定奠基 →「闸门 · 设定」→ 分卷大纲 →「闸门 · 大纲」→ 逐章连写 | 一句话想法 + 卷数 |
| 接着已有内容写 | 逐章连写（+ 设定补完，按策略） | 情节概要（可选） |

**为什么合成一个编排器**：第 ③ 步本来就是同一件事（都是"接着库里最后一章往下写一章"，
都用 `runAutoContinue`）。合并后，断点续跑、进度时间线、去 AI 味儿、设定补完策略、
`onBodyToken` 流式 —— 两条路自动共享，而不是各写一套。

**"继续推进项目"的接口**（老大指出的缺失）：`continue` 起点就是它。项目里已有《章节细纲》卡时，
连写会按章号取当章细纲钉进 prompt 末段（可在面板关掉）——
所以「只保存大纲」之后，切到「接着写」就能把正文补上，**不必重跑设定与大纲**。

### 状态与持久化的边界

- **内存**：闸门 Promise、运行中的 `AbortController`、可续跑的 bag —— 都在 store 里；
- **落盘**（`db.meta`，按项目分键、防抖 1s）：输入参数 / 日志（末 60 条）/ 断点里程 / 结果摘要；
- 🔴 **bag 不落盘**：续跑时前序阶段的产物（设定草稿、大纲）**本来就已经落库**，
  跳过它们是正确行为 —— 不必把一个可能几十条的草稿包塞进本地库。
- 切页签**不会**中断任务（组件卸载与任务无关）；关软件后回来仍能看到"上次写到第 N 章"。

## 五、数值输入统一（老大要求：可自由输入，超范围调回最近边界）

### 根因
原写法一律是 `onChange={e => setX(Math.max(min, Math.min(max, Number(e.target.value) || 1)))}`：
- **打不出超范围的值**：上限 8 时想输 10，第一位 `1` 就被改写；
- **清空不了**：`Number('') || 1` 把空串立刻填回 1，退格重输变成打仗。

### 做法：新建 `components/NumberField.tsx`
- 输入中**只更新文本**；若解析值本来就在范围内则即时同步（推荐值、耗时估算保持联动）；
- **提交时机＝失焦 / 回车**：解析 → 钳到 `[min,max]` → 同步；非法文本回退旧值；
  发生钳制时 `onClamped` 回调一次（界面 toast 告知"已调到上限/下限"）；
- 点按钮会先触发 blur，所以"改完直接点开始"不会漏值；
- 支持 `allowEmpty`（留空语义，如上下文窗口）、`placeholder`、`onCommit`。

### 覆盖清单（有范围约束的设置项 → 全部改）

| 文件 | 处数 |
|---|---|
| `CreativeWritingPanel`（卷数 / 连写章数 / 每章字数） | 3 |
| `BookBreakPanel`（关系整理材料上限 5 项） | 1 组 |
| `AIWriterBudgetPanel`（资料预算基准，且 draft 改受控 number） | 1 |
| `AIConfigPanel`（上下文窗口，可留空） | 1 |
| `EditorModals`（小黑屋目标字数 / 时长） | 2 |
| `WritingGoals`（每日 / 全书目标字数） | 2 |
| `TavernDirectorNoteBar`（插在第几条 / 生效轮数） | 2 |
| `SearchSettingsPanel`（每次取几条；顺带修非受控 → 受控） | 1 |
| `CalendarSelect`（历法数值；防 NaN） | 1 |

### 判定不改（连同理由）

| 位置 | 理由 |
|---|---|
| `Sidebar` 缩放输入 | `applyZoom()` 内部已钳 80~160，输入 500 会被夹住并回显 160 —— 已合规 |
| `StoryDateInput` / `CalendarSelect` 的年月日 | 复合输入，年/月/日有联动（月末天数），不是"一个数值设置" |
| `TableSheet` 的 `col.type === 'number'` 单元格 | **数据录入**（存字符串、无范围约束），不是设置项 |
| `TavernCastDirector`「健谈度」 | 本来就是 `<select>` 分档，打不出越界值 |

### 本轮结论

- 融合达成：**两个起点、一条连写链**；「接着已有内容写」即"继续推进项目"的入口。
- 「切页签内容消失」**根治**（状态活在模块级 store 里，任务不再依赖组件生命周期）。
- 服务器时代的残留（同步码 / 邀请码 / 网页体验版 / HTTP 同步）在产品内清零。
