## 2. 自动探针

新增 scripts/audit/probes/web-guest-save-probe.cjs：

1. 必须显式传入本次生产构建目录，不自动寻找旧 dist。
2. 创建独立 run 目录、Edge 持久 profile 和服务端数据目录；本地真实 server 绑定 127.0.0.1，端口自动选择。
3. 通过真实 /guest 路由获得游客注入，确认 WEB/GUEST 开启而 PORTABLE/Electron 关闭。
4. 程序生成一项目、一卷、一章；通过可见项目入口进入正文编辑，用真实输入和 Ctrl+S 触发保存。
5. 只在本次浏览器中拦截目标章节 put：一组抛配额异常，一组使真实写事务 abort；正常代码、其他库和作者资料均不受影响。
6. 故障期间断言提示可见、输入仍在、独立读取事务仍为旧正文；排除故障后不重新输入，直接重试并回读新正文。
7. 关闭整个浏览器上下文/进程，再以同一隔离 profile 启动，核对 UI 与数据库一致。
8. 关闭本次服务和浏览器，保留三张截图、章节回读 JSON、服务日志与结果 JSON，记录指纹和逐文件 SHA256。

自动化修正：项目打开后的备份提醒是异步出现的。探针等待并实际关闭提醒，不用 force click 绕过遮罩。初次探针在这里被遮罩拦住，属于工具交互准备问题，保留失败记录，不计产品缺陷。

## 3. 场景与证据闸

| 场景 | 核验 |
|---|---|
| initial-flags / fixture-readback | 正确游客标记；显示夹具正文且实际 IDB 一致 |
| quota.failure-visible / abort.failure-visible | 两类异常分别确实触发写失败，并有界面反馈 |
| 两类 failure-preserves-draft | 作者刚输入的文字仍完整显示 |
| 两类 accepted-vs-persisted | 内存输入已变化，但失败事务没有更改已存正文 |
| 两类 retry-readback | 清除故障后无需再次输入即可保存，独立事务读回正确内容 |
| backend-selection | 保存全过程没有请求 /api/data，后端确实为浏览器库 |
| restart-readback | 实际重启浏览器后，正文从隔离 profile 中正确恢复 |
| no-pageerror / unchanged-inputs | 无未捕获页面异常，取证期间源码指纹一致 |

共 14 项运行断言。新 scripts/verify/web-guest-evidence.mjs 消费结果时校验：

- 当前源码指纹、本次构建哈希、配置名称均匹配；
- 场景完整、无重复、无失败、不是零样本，且没有未捕获页面异常；
- runRoot 真正位于隔离目录，证据文件不越界；
- 三张截图、章节快照、服务日志存在并且哈希匹配。

新增 tests/webGuestEvidence.test.ts，13 项正反对照覆盖上述证据判据。它只证明证据闸；真实浏览器行为由运行探针单独证明。
