## 2. 最小命中区（P0 缺口 60 处的处置）

### 2.1 机制（`src/index.css` 新增一段，仍在 `@media (hover: none) and (pointer: coarse)` 内）

| 选择器 | 覆盖 | 为什么这样划 |
|---|---|---|
| `button[data-button-sizing='icon']`、`[data-button-icon-only='1']` | 图标键（3.3.1 已有） | 视觉 23～32px，热区 44×44 |
| `button:where([data-button-sizing='standard']):not(table *)` | **文字按钮**（本批新增） | P0 的 60 处里 47 处是它：h-7/h-8/h-9 = 28/32/36，宽度本来就 60～246，只缺高度 |
| `[data-touch-target='1']` | **手写裸 button**（本批新增） | 全站 353 个手写 button，一刀切会把大卡片和正文小圆点一起撑开 ⇒ 显式标记，宁可漏标由探针查出来 |
| `[data-touch-row]` / `[data-touch-row] > button` | **紧凑行内操作组**（本批新增） | 隐形热区在 15px 间距下会互相覆盖，反而让「删除」抢走「改名」的点击 ⇒ 给**真实** 44×44 盒子，并在触摸下常显（触摸没有 hover） |

三条硬边界（都写进样式注释，防下轮改回去）：

1. **表格内文字按钮不加热区**（`:not(table *)`）—— 表格要整体抬行高才对，属 P2；单给按钮加隐形区会让相邻行互抢点击。
2. **不做「所有 button 一律 44」** —— 只有 `standard` 与显式 `data-touch-target` 两类。
3. **不用 `!important`、不改 padding / 固定宽高** —— 文字按钮仍只用 `::after` 外扩，不撑高工具栏。

另外核过 `position: relative` 的副作用：扫全仓 `Button` 子元素，唯一在按钮**内部**用 `absolute` 的是
`JieWenJi` 的精灵开关（`variant="bare"` ⇒ `sizing=content`，不在本条范围，且自带 `relative`）；
其余 `absolute` 都写在 `Button` 自己的 className 上，特异性高于本条，定位不变。

### 2.3 为什么「删除」优先

P0 把 15×15 条目删除列为最该先修的点：它是**危险操作 + 全站最小命中区**，且完全绕过 `Button`。
本批没有把它改成 `Button`（视觉会从 15px 涨到 24px，行内排布要跟着调），而是先在机制层给它
**真实 44×44 盒子**——危险键宁可占位，也不要一块和邻居重叠的隐形热区。真机误触仍记 S-05。

口径落实（对应规划 §6 三条）：

1. **策略 ≠ 平台**：面板把 `policy-blocked`（网页版本机模型）与 `platform-missing`（浏览器无窗口桥）
   分别显示成「产品策略暂不提供」「当前运行环境不支持」。
2. **桥逐个探**：桌面壳缺 `electronBoss` 时老板键是 `unsupported`，设置页禁用态标题现在直接给
   `cap.detail`（旧版 preload 请更新），不会退化成「页面遮挡」的错觉。
3. **状态会变**：登录/退出、断网、外部退出全屏后重新读快照，不再停在挂载时那一次结论。

> ⚠️ 本批**没有**把 `local-model` 的文案改成从矩阵取：现有 `WEB_LOCAL_MODEL_NOTICE` 已是单句真源
> （4 处消费者 + 2 条路由错误共用），C3 的策略接线与提示复验按规划排在 P3，避免半途改成两套。
