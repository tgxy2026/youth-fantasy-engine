## 一、第 2 项：幽灵索引清理入口

上一轮只接了**检测**（老大当时选的是"只接检测不接清理"），把清理留到本轮，前提是**先设计安全前置**。

### 2.1 为什么不能直接调裸的 `pruneGhost*`

三个裸函数（`pruneGhostSessions` / `pruneGhostFreeChars` / `pruneGhostFreeSessions`）的语义是
「检出即删、不问、不备份」。而幽灵的判据是「索引项在、分条**读不到**」——

> **读不到 ≠ 不存在。**

桌面版数据文件读不出来时（`getDesktopState().writeLocked`，即 db/core.ts 的读失败三态），
**所有**分条都读不到 —— 那一刀下去会把「其实还在、只是读不出来」的索引整片删掉，且不可逆。
这与项目红线「**读数据失败必须锁写盘**」是同一类风险，也是上一轮不做清理的唯一理由。

### 2.2 四道安全前置（实现见 `src/lib/tavern/store.ts`）

| # | 前置 | 收在哪 | 说明 |
|---|---|---|---|
| ① | **写盘锁期间拒绝** | `ghostPruneBlockedReason()` | `DESKTOP && writeLocked` 时直接拒绝并**把原因原样返回给界面**。同构先例：`enableDesktopCloudSync` 在 writeLocked 时也拒绝（那边怕把空数据推上云端） |
| ② | **二次复判** | `pruneGhostsSafely()` | 隔 200ms 各检一次，**只清两次都判定为幽灵的 id**；两次不一致就**不删**并如实回报，让作者先查存储状态，而不是让工具赌一把 |
| ③ | **先备份** | 同上 | 待删的索引项**整条**写进 meta 的 `tavern.ghostBackup.<ts>`。值得备份是因为分条**有可能回来**（云盘同步会把「云端有、本地没有」当另一端新增拉下来 —— 这正是「删了会复活」的另一面），那时恢复索引才有意义；顺带也是一份「我清过什么」的审计痕迹 |
| ④ | **确认框明示影响** | `CheckTools.tsx` | 说清「不影响还能打开的内容」「会复判 + 留备份」「不能从界面撤销」 |

另外：`pruneGhost*` 三个裸函数各加了**可选 `onlyIds`**（不传 = 原行为，向后兼容），
这样安全路径只清"复判确认过"的那批，而不是"自己再 audit 一遍的全部"。

### 2.3 一个设计取舍：不往 `AuditIssue` 上加业务字段

界面要知道"这条 issue 属于哪一组、能清几条"，最省事的写法是给 `AuditIssue`（审计层**公共**类型）加字段，
或让界面去解析 `title` 文案。两者都不好：前者让公共类型知道「酒馆」这种具体业务，
后者**文案一改就静默失配**（按钮凭空消失，且不报错）。

采用：`HealthResult` 单独带出 `tavernGhosts?: TavernGhostInfo[]`，用 **`issueId` 与 issues 关联**。
公共类型一字未动，关联是结构化的。

#### 🔴 删整仓快照之前，先实测了「git 能取代它」

不能拿「我以为 git 里有」当依据。删之前跑了一次对照：

```
git show f5efa63^:src/components/useTavernFreeModel.tsx   vs   bak/useTavernFreeModel.orig.tsx
→ ✅ 逐字节一致（1243 行，就是 D4-5 拆分前那版）
```

**顺带查证救了一次误删**：第一遍我拿 `git show HEAD:...` 去比，结果**不一致** ——
说明那份 `.orig` 不是 HEAD 版而是**拆分前**的版本。改用 `f5efa63^` 才配上。
如果当时看到"不一致"就跳过（或反过来直接删），判断都是错的。

> 📌 三份快照之所以敢删：全部提交都在 git 历史里，且红线禁 `gc` / `reflog expire`（对象不会丢）
> → `git show <commit>:<path>` 随时取回，物理快照是冗余的。

#### 另一个坑：`find` 又撞上了 Windows 同名 exe

第一次查那三个目录"有几个文件"，`find` 解析到了 Windows 的 `find.exe`，报 `参数格式不正确`，
输出"共 0 个文件"——**看起来像空目录，其实 `base-head/` 里有 436 个文件**。
（记忆里早写着「`sort`/`find`/`timeout` 解析到 Windows 同名 exe → 改用 node 脚本」，这轮又踩了一次。）
凡是要递归/统计目录，一律用 node 写。

### 3.2 `setStoreOps` 的导出面：**判断为有意保留**

它是 `db/core.ts` 里 `ops`（必须 export 的模块级活绑定）的**唯一写入口**，
与 `makeCloudStoreWrapper` 等在 `db.ts` 门面里**同一行**导出，属于"存储层基础能力"这一组。

判断依据：
1. 它表达的是一项**真实能力**（存储层支持运行时换后端），是 `enable/disableDesktopCloudSync` 的底层原语；
2. 摘掉的收益只是少一个 export 关键字，而将来若要写"模拟切换后端"的测试还得加回来；
3. ⚠️ 它**经门面导出会被 audit-dead 记成"有外部引用"，因此不会出现在「多余 export」清单里** ——
   所以别指望那份清单替你盯着它。

**已把这段判断写进 `db.ts` 门面的注释里**（不写下来，下一轮还会有人重新问一遍）。
