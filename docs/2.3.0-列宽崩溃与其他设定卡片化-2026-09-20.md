# 表格列宽崩溃修复 + 「其他设定」卡片化（2026-09-20）

> 老大报障（原文）：
> ```
> TypeError: Cannot read properties of null (reading 'col')
> at .../dist/assets/index-C6iK5jCB.js:2754:13823
> 打开其他设定页签，调整表格列宽时报错
> ```
> 追加要求：① **「其他设定」不要做成表格，改成卡片形式**；② **其他有类似功能的地方也检查一下**；
> ③（第二轮反馈）**「功能没问题，文案有问题，全是新建角色」**。

## 一、列宽拖拽崩溃（P0 级：界面直接抛错）

### 1.1 定位：直接读**构建产物**反查，不靠猜

报错给的是压缩后的坐标（`index-C6iK5jCB.js:2754:13823`）。dist 就在仓库里，于是按行切片打印该列附近：

```js
const L = fs.readFileSync('dist/assets/index-C6iK5jCB.js','utf8').split('\n')[2753]
console.log(L.slice(13563, 14083))
```

拿到的正是：

```js
ke(St=>({...St,[Y.current.col]:Ye}))
```

即源码的 `setColWidths(prev => ({ ...prev, [dragRef.current!.col]: w }))` —— **报错列号精确落在那处属性读取上**，root cause 当场确认，无需猜测。

> 方法沉淀：压缩产物的 `行:列` 是**可反查的**（只要有对应的构建产物），比在源码里大海捞针快得多。

### 1.2 根因：updater 是**延迟执行**的，而 `!` 只是 TS 断言

```ts
const onMove = (ev: MouseEvent) => {
  if (!dragRef.current) return                      // ← 这个守卫救不了下面
  ...
  setColWidths(prev => ({ ...prev, [dragRef.current!.col]: w }))
  //                                    ^^^^^^^^^^^^^^^^
  //  React 把这个 updater **排进队列、渲染阶段才调用**；
  //  而 mouseup 早已把 dragRef.current 置空 ⇒ 执行时读 null.col ⇒ 崩
}
```

- `!`（非空断言）**编译后什么都不剩**，没有运行时保护；
- 「上一步 `if` 判过非空」看似成立，实则**两步之间隔着一次 React 调度**；
- 触发条件是**拖完立刻松手**（mousemove 的 update 还没渲染，mouseup 先把 ref 清了）——
  不是每次必现，属于典型竞态。

### 1.3 修法：整份拖拽上下文**同步捕获**到局部量

```ts
const onMove = (ev: MouseEvent) => {
  const d = dragRef.current        // 🔴 同步取一次
  if (!d) return
  const z = Number(document.documentElement.style.zoom) || 1
  const dx = (ev.clientX - d.startX) / z
  const w = Math.max(90, Math.min(640, Math.round(d.startW + dx)))
  setColWidths(prev => ({ ...prev, [d.col]: w }))   // updater 只碰闭包里的 d
}
```

**这不是新发明的写法，而是项目里其余拖拽点早就在用的范式**（见下节）。

### 1.4 同类排查（老大要求）：7 处拖拽全查，只有这一处有问题

| 拖拽处 | 写法 | 判定 |
|---|---|---|
| `useTableSheetModel`（列宽） | updater 里读 `dragRef.current!.col` | ❌ **本次修的** |
| `useSvgPanZoom`（图谱平移/拖节点） | `const d = dragRef.current` + 用局部 `d` | ✅ 安全（本文件即范式来源） |
| `useResizable`（侧栏/窗格调宽） | `setSize(值)`——传**立即求值的值**而非 updater | ✅ 安全 |
| `PlotCanvas`（画布平移/拖卡） | 同 useSvgPanZoom | ✅ 安全 |
| `useGeoMapModel`（地图平移/绘制） | 同上 | ✅ 安全 |
| `JieWenJiSprite`（看板娘拖动） | 同上 | ✅ 安全 |
| `FactionGraph` / `RelationGraph` | 走 `useSvgPanZoom` | ✅ 安全 |

排查手段（两层，缺一不可）：

```bash
# ① 直接找"updater 里读 ref"的形状（单行 + 跨行各扫一遍）
grep -rn "set[A-Za-z]+([a-zA-Z_]+ =>.*\.current" src/
# ② 找全部拖拽监听，逐个回源码看实现
grep -rn "addEventListener('(mousemove|pointermove)'|onPointerMove=" src/
```

另外顺手扫了**另一类同类风险**：延迟回调（`setTimeout` / `requestAnimationFrame`）里读 `ref.current` ——
命中的全是 `.focus()` / `clearTimeout(...)` / 不读 ref 的定时器，**无同类问题**。

## 二、「其他设定」改成卡片形态

### 2.1 设计要点：卡名就是设定名，所以**不要「名称」字段**

`CardRecord` 自带 `name`（独立于 `data`），而 `SettingSearch` 取 `title: rec.name` 当条目标题、
`renderCards` 用 `card.name` 渲染成 `〖卡名〗`。所以：

```ts
id: 'misc-settings', name: '其他设定', group: '世界构建', type: 'card',
modules: [{ name: '设定内容', fields: [ f('内容', '…', '每逢十五月圆…') ] }],
```

- ✅ AI 看到的是 `〖灵力潮汐周期〗` + `内容：…`，干净；
- ❌ 若保留「名称」字段就会变成 `〖灵力潮汐周期〗 名称：灵力潮汐周期` —— **重复一遍**；
- 顺带省掉**编号**（卡片表一律不编号，与角色卡/分卷大纲/章节细纲一致）。

同步清理：`columns` / `displayCol` / `subtitleCol` / `codeRule` 全删；
`autoCode.ts` 的 `'misc-settings': 'MISC'` 也撤掉（不编号后它就是一条**永远取不到的死配置**）。

### 2.2 🔴 数据迁移：两种形态存在**不同的 store**

| 形态 | store |
|---|---|
| 表格 | `tableRows` |
| 卡片 | `cardRecords` |

改 schema 类型**不会自动搬家** —— 不迁移的话，作者先前填好的条目会在界面上**凭空消失**
（数据还在库里，只是没人读）。新增 `migrateMiscSettingsToCards()`：

- `card.name` ← 原「名称」列；`card.data` ← `{ '设定内容::内容': 原「内容」列 }`
- **先写卡、再删原行**（中途失败下次再来）；**复用原行 id** ⇒ 重复跑是覆盖而非新增（幂等）
- 挂在 `runMigrations()` 末尾（与既有的 types→ledger→numbering→geomaps 顺序约束无关）
- ⚠️ 写入的键 `设定内容::内容` 必须与 `resolveSlot('misc-settings','内容')` 一致（schema 改模块名要同步改迁移）
  —— `tests/miscSettings.test.ts` 有一条断言钉住两者相等，改名会当场红

### 2.3 种子与登记点

- `seedData`：3 条示例从**表格行**改为 `card('misc-settings', 名称, i, { '内容': … })`
- `SETTING_SUBTABS` / `aiContext.PRIORITY`：**保持不变**（按 tabId 登记，与形态无关）
- `tests/seedRef` 的「每个表格页签都不空」闸**盖不到卡片表** → 单独补了一条卡片断言

## 三、文案参数化（老大第二轮反馈：「全是新建角色」）

`CharacterSheet` 从 1.x 起**只服务角色卡**，文案里写死了「角色」；2.3.0 新增「其他设定」后
同一个组件也服务非角色卡片表 ⇒ 「新建角色 / 删除角色卡 / 请输入角色姓名」全成了错话。

照 `OutlineSheet` 已有的范式参数化：

```ts
const isCharTab = tab.group === '角色管理'
const noun = isCharTab ? '角色' : '设定'
```

改了 12 处用户可见文案（新建按钮 / 改名弹窗标题与占位 / 删除确认 / 列表与编辑区空态 / 帮助气泡整段分支），
外加 3 处技术注释写准。

🔴 顺带修了一个**功能层面**的问题：「**隐藏已退场**」开关原本无条件渲染，而它的过滤依据是
「人物状态」字段 —— 非角色卡片表没有这个字段，**开关点了也不会有任何效果**。
现在是 `{isCharTab && (…)}`，只给角色卡渲染。

1. 列宽防回退断言用宽泛正则，命中了源码注释里**刻意保留的反例写法**（`[dragRef.current!.col]`，
   写在注释里解释历史 bug）→ 判据收紧到 `setColWidths(...)` 那一行。
