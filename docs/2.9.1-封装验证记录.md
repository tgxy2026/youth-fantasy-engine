## 2. 🔴 新坑一：electron-builder 解压 7zip 工具链被 EPERM 拦死

**现象**（首轮封装，19:58）：

```
⨯ EPERM: operation not permitted, rename
  'C:\Users\…\electron-builder\Cache\7zip@1.0.0\7zip-win-x64-1nrf7.tmp'
  -> 'C:\Users\…\electron-builder\Cache\7zip@1.0.0\7zip-win-x64-1nrf7'
  failedTask=build  (nsisUtil.ts → getNsisElevatePath → downloadAndExtract)
```

- 失败点在 **NSIS 阶段解压 7zip 工具链**：electron-builder 把 tar.gz 解到 `<name>.tmp/`，
  再 rename 成正式目录。rename 时**目标目录并不存在**却被拒 ⇒ 典型的**实时防护持有 `.tmp` 句柄**
  （与 skill 里记的 `fs.rmSync` → safe-delete 是同一类环境问题，表现成 EPERM）。
- ⚠️ **重跑并不能解决**（这不是 NSIS 那种"间歇性写安装包失败"）。
- 好消息：`.tmp` 里的解压内容**其实是完整的**（`bin/7za.exe` 849,920 字节，与 tar.gz 清单一致），
  只是 `.state` 停在 `"extracting"`。

**✅ 正解：走 electron-builder 自己留的逃生门 `ELECTRON_BUILDER_7ZIP_PATH`**

`node_modules/app-builder-lib/out/toolsets/7zip.js` 里，`resolve()` 第一步就是：

```js
const envExec = await resolveEnvToolsetPath("ELECTRON_BUILDER_7ZIP_PATH", "file");
if (envExec != null) return envExec;     // ← 设了就直接用，完全不下载、不解压
```

做法（三步，已固化）：

```bash
# ① 把已解出的 7za 复制到稳定位置（用 readdirSync + copyFileSync 递归；别用 fs.cpSync——会静默杀进程）
node -e "…cp(.tmp 目录 → .workbuddy/tmp/eb-7zip)…"
# ② 实测可跑：.workbuddy/tmp/eb-7zip/bin/7za.exe   →  应打印 7-Zip 24.09 的 usage
# ③ 带环境变量跑封装
export ELECTRON_BUILDER_7ZIP_PATH="<项目>/.workbuddy/tmp/eb-7zip/bin/7za.exe"
node scripts/build-desktop.mjs
```

- 日志会出现 `• resolved ELECTRON_BUILDER_7ZIP_PATH from environment variable` ⇒ 生效标志。
- **顺带自愈**：这次运行还检测到 `nsis-3.0.4.1` 的 stale state（age=126606），
  自动 `marking as corrupted → cleaning up and re-extracting`，**没再报 EPERM**。
  ⇒ 说明卡死的是 7zip 那一环，nsis 那环自愈。

## 3. 🔴 新坑二：`electron-winstaller` 的 vendor rcedit 不支持中文路径

**背景**：脚本退出码 **2**（设计如此），提示「主 exe 元数据缺失（体积 246,238,720）」，
但紧接着报 **「❌ 找不到 rcedit，无法补写主 exe」**。

**根因链**：

1. 脚本从 `%LOCALAPPDATA%\electron-builder\Cache\winCodeSign\*\rcedit-x64.exe` 找 rcedit；
2. 而 **`winCodeSign` 缓存目录整个不存在** —— 因为 `signAndEditExecutable: false`
   让 electron-builder 根本不下载这套签名工具链（本轮日志里那句 `signing with signtool.exe` 是空转）；
3. 现场唯一的 rcedit 是 `node_modules/electron-winstaller/vendor/rcedit.exe`（152,576 字节）；
4. **但它对中文路径直接 `Fatal error: Unable to load file`** —— 同一命令、同一个 exe，
   只把工作路径换成 `C:\rcedit-test\`（纯 ASCII）就**一次成功**：
   体积 246,238,720 → **246,487,040**（与基线逐字节一致）、含 `青春幻想引擎开发组` = true。

**✅ 正解：ASCII 路径补位 + 复制回**

```bash
# ① 复制到纯 ASCII 路径
mkdir -p /c/rcedit-test
cp build/icon.ico /c/rcedit-test/icon.ico
cp "<产物>/win-unpacked/青春幻想引擎.exe" /c/rcedit-test/app.exe
# ② 在 ASCII 路径补写（参数同脚本打印的那条）
./node_modules/electron-winstaller/vendor/rcedit.exe C:/rcedit-test/app.exe \
  --set-version-string FileDescription 青春幻想引擎 --set-version-string ProductName 青春幻想引擎 \
  --set-version-string InternalName 青春幻想引擎 --set-version-string CompanyName 青春幻想引擎开发组 \
  --set-file-version 2.9.1 --set-product-version 2.9.1.0 --set-icon C:/rcedit-test/icon.ico
# ③ 复制回产物目录，再核一次 PE 里的字符串
cp /c/rcedit-test/app.exe "<产物>/win-unpacked/青春幻想引擎.exe"
```

> 📌 skill 里原记的「中文路径 icon 也成功」是**用 electron-builder 的 rcedit-x64.exe** 测的 ——
> 换成 `electron-winstaller` 的 vendor 版就不成立。**判据要看是哪个 rcedit**。
