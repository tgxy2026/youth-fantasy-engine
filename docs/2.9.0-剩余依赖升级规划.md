### 1.4 🔴 安装方式（本环境专属坑，必须按此执行）

**既不能裸 `npm install`，也不能只 `--ignore-scripts`** —— 两条路各有一个坑：

| 做法 | 后果 |
|---|---|
| `npm install`（带脚本） | esbuild 的 `install.js` 用 `execFileSync` 校验二进制 ⇒ **本机 EBUSY** ⇒ 整装回滚（第一批已踩） |
| `npm install --ignore-scripts` | **electron 的二进制不会下载** ⇒ `node_modules/electron/dist` 缺失 ⇒ 打包出**空壳安装包**（2.0.0 事故复现） |

**正解（两步）**

```bash
# ① 先只装 JS 包（跳过脚本，避开 esbuild 的 EBUSY）
npm install --ignore-scripts

# ② 再单独补跑 electron 的安装脚本
ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ node node_modules/electron/install.js
```

> 已核实：`node_modules/electron/install.js` 里 `execFileSync|spawnSync` 命中数 = **0**；机制是 `downloadArtifact()`（`@electron/get`）+ `extract-zip` ⇒ **不受 EBUSY 影响**，但走 GitHub ⇒ 必须挂镜像。
> 项目**无 `.npmrc`**（未配镜像）⇒ 镜像只能用环境变量传。

### 6.3 🔴 连带回归：`@types/node` 被带上 24，导致 tsc 转红

**现象**：`npm install` 之后 `tsc --noEmit` 从 EXIT 0 变 **EXIT 2**，`tests/` 里 7 条报错全是
`TS2550: Property 'at' does not exist … Try changing the 'lib' compiler option to 'es2022' or later`。

**根因**：`@types/node` 是**传递依赖**，版本由 electron 的链条决定 ——
`@electron/get` `2.0.0 → 5.0.0`，其依赖从 `@types/node ^20.9.0` 变成 **`^24.9.0`**（装到 24.19.1）。
而 `@types/node` 的 `index.d.ts` 只 `/// <reference lib="es2020" />`（外加 `esnext.disposable` / `esnext.float16`），
**不再顺带引入 es2022** ⇒ 而本项目 `tsconfig` 的 `lib` 是 `["ES2020","DOM","DOM.Iterable"]`，
`Array.prototype.at`（es2022.array）失去类型 ⇒ 测试代码里几处 `.at(-1)` 立刻报错。

> 也就是说：此前能编译**纯属「搭便车」**（靠 `@types/node@20` 的 reference 顺带带来 es2022），
> 并非 tsconfig 真的声明过。

**修法**：`tsconfig.json` 的 `lib` 显式提到 **`ES2022`**。运行时是 Electron 44（Node 24.18.1 / Chromium 152），
ES2022 全量支持 ⇒ 显式声明才是正解，同时也**摆脱了对 `@types/node` reference 的隐式依赖**。
