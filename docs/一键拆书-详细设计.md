## 2. 数据流与类型定义

```ts
// types.ts
export interface RawChapter { index: number; title: string; text: string }

export type EntityKind =
  | 'character' | 'location' | 'faction' | 'relation'
  | 'worldFact' | 'powerFact';

export interface ExtractedEntity {
  kind: EntityKind;
  name: string;            // canonical 候选
  aliases: string[];       // 别称/外号/曾用名
  confidence: number;      // 0..1（模型自估）
  sourceQuote: string;     // 原文片段（用于引用核对）
  chapterIndex: number;
  // 各 kind 的扩展字段（弱类型，map 阶段强转）
  fields: Record<string, string>;
  // relation 专用
  rel?: { with: string; type: string; detail: string };
}

export interface ChunkResult {
  chunkId: string;
  source: { chapterIndex: number; charStart: number; charEnd: number };
  entities: ExtractedEntity[];
}

export interface DraftRow {
  tabId: string;                 // 目标表（char-main / geography / ...）
  data: Record<string, string>; // 对齐后的字段（含 cr 引用已由 map 解析为名称）
  aliases: string[];            // 顺带写入「别称」字段
  confidence: number;
  sourceQuotes: string[];
  status: 'new' | 'conflict';   // 与已有设定比对结果
  conflictFields?: { field: string; existing: string; incoming: string }[];
}

export interface DraftBundle {
  rows: DraftRow[];
  byTab: Record<string, DraftRow[]>;
  stats: { total: number; byKind: Record<EntityKind, number> };
}

// 进度状态机
export type BreakPhase = 'idle' | 'splitting' | 'extracting' | 'aligning' | 'mapping' | 'validating' | 'preview' | 'writing' | 'done' | 'cancelled' | 'error';
```

```ts
function cnToNum(s: string): number { /* 简易中文数字→阿拉伯，支持 0-9999 */ }
```

- 命中 → 切割为 `RawChapter[]`（标题取捕获组 + 余文）。
- 若检测到的章节数 `< 2` → 退化为 §3.2 兜底分块（无章节纯文本）。

### 3.2 兜底分块（固定 token + 重叠）

```ts
const CHUNK_TOKENS = 1200;
const OVERLAP_TOKENS = 100;

// 中文字≈1 token；英文词≈1.3 token
function estTokens(s: string): number {
  const cn = (s.match(/[一-鿿]/g) || []).length;
  const en = (s.match(/[A-Za-z]+/g) || []).length;
  return cn + Math.ceil(en * 1.3);
}
```

- 优先在**段落边界（空行）**切，避免句中切断；块上限 `CHUNK_TOKENS`，相邻块重叠 `OVERLAP_TOKENS`（回推为字符数 ≈ overlap/中文字比）。
- 每块记录 `charStart/charEnd`，供引用核对回定位。

## 4. 抽取 Prompt 模板初稿（prompts.ts + extract.ts）

### 4.1 系统提示词（固定）

```
你是一个小说设定抽取引擎。任务：从给定正文片段中，提取可填入写作软件设定表的**结构化事实**。
铁律：
1. 只输出 JSON，不要任何解释性文字，不要代码块围栏。
2. 严格使用下面指定的字段键名，不得增删改名。
3. 绝不编造：每条实体必须附带一段**真实出现在原文中的片段**（sourceQuote）。
4. 描写一律**第三人称**。
5. 同一人物若以不同名字出现，合并到同一对象，并把其它名字列入 aliases。
6. 拿不准的字段留空字符串，不要猜。
7. confidence 自评 0~1：原文明确写出=0.9+；推断=0.5~0.7；纯猜测≤0.3。
```

```
1. 把指向同一实体（同 name 或 name 互为 aliases）的对象合并为一个，aliases 去重合并。
2. 合并时字段取「信息更完整」的一份；若两块对同一字段给出**明显矛盾**的值（如两个不同境界），保留双方并标记 conflictFields。
```

## 5. 实体对齐 / 别名归并（align.ts）

### 5.1 canonical 选择

- 每个实体保留 `name` + `aliases[]`。
- 归并规则：同 `name` 或 `name ∈ 他人 aliases` → 合并；canonical = 出现频次最高 / 最早正式名。

### 5.2 相似名阻断（来自 AI Reader V2 经验）

```ts
function editDistance(a: string, b: string): number { /* Levenshtein */ }

// 仅当「编辑距离 ≤ 1 且 长度 ≥ 3」且无语义冲突时才自动合并；
// 冲突示例：「林雷」vs「林雷风」 → 不合并，标记 status='conflict' 待人工。
```

### 5.3 借力 schema（关键，降低难度）

- 合并后的 `aliases` **直接写入角色卡「别称」字段**（schema 已支持：正文出现别称即识别同人）。
- 地理 / 势力 / 关系的跨表引用列（`cr('地理位置','geography','名称')` 等）由 `map.ts` 在写入时把名称解析为目标表已有行的引用——**根治同名异写**，无需抽书层做名称消歧。
- 关系表 `人物A/人物B`：映射时查已对齐 canonical；若命中现有角色卡 `name` 或 `别称` → 填引用；否则进「建议新建角色」列表。

### 6.2 写入通道

- 草稿阶段只构建内存 `DraftBundle`，**不触达 db**。
- 预览确认后，逐条调用对应 `saveXxx`。
- `cr()` 引用：map 阶段把名称解析为「目标表已有行 name」；若目标行尚不存在（本批新建），按批次依赖顺序写入（先 nations/geography，后 relations/char 引用它们）。

### 6.3 冲突处理

- 写入前比对：若目标表已存在同名（或别称命中）行，且某字段已填且与 incoming 不同 → `status='conflict'` + `conflictFields`。
- 用户三选一：**保留已有 / 采用新 / 合并文本（拼接）**。绝不静默覆盖。

## 7. 校验与置信度（validate.ts）

### 7.1 原文引用核对

```ts
// 每条 entity.sourceQuote 必须在原文本中 includes 命中；不匹配 → 降置信度 + 标红
const hit = rawText.includes(entity.sourceQuote.trim());
```

### 7.2 冲突检测

- 同一 canonical 多块对同字段给出矛盾值（归一化后不等）→ `conflictFields.push`。

### 7.3 置信度启发式（MVP 简单版）

```ts
let c = 0.6;                       // 基础
if (quoteHit) c += 0.2;           // 引用命中
if (multiChunkConsistent) c += 0.2; // 多块一致
if (conflictFields.length) c -= 0.3;
c = Math.max(0, Math.min(1, c));
```

- `confidence < 0.5` → 进「建议」区，**不进主草稿**（预览中灰显，需手动提升才写入）。

## 8. 草稿预览 / 校对 UI（components/）

### 8.1 入口位置（定案）

新增独立页签 **「智能拆书」**，注册到 `schema.ts` 的 `TABS`（归入「工作面板」组，与 酒馆模式 同组；`SETTING_SUBTABS` 无需改动，因它不是设定子页）。
理由：功能横跨角色/世界/大纲多模块，独立入口比埋进某单模块顺；复用现有 `TabDef` 机制零侵入。

### 8.2 面板布局

```
┌─────────────┬──────────────────┬───────────────────────┐
│ 原文导入区   │ 运行控制          │ 草稿结果（按模块分组）  │
│ ·粘贴/上传txt │ ·开始抽取         │ ·角色 / 地理 / 势力     │
│ ·章节树预览   │ ·进度条+中止      │ ·关系 / 世界 / 力量     │
│              │                  │ 每条可展开：原文引用+置信度│
├─────────────┴──────────────────┴───────────────────────┤
│ 冲突列表 + 「写入项目」(逐条 / 全部可信)                    │
└──────────────────────────────────────────────────────────┘
```

### 8.3 交互

- 每条：行内编辑 / 舍弃 / 标记冲突。
- 批量：全选可信(≥0.5)写入 / 仅写入无冲突。
- **写入前弹确认**：列出「将新建 N 条 / 将更新 M 字段」，确认后才落 db —— 满足「绝不自动覆盖」红线。

## 11. 风险与开放问题（需老大拍板 / 实测）

1. **本地 27B 对百万字长篇的抽取质量**：先用 5–10 万字样本实测，再决定是否需云端大模型兜底。
2. **worldbase/power 是 form 单条**：多世界观要素落点规则（§6.1 末段）——固定字段内填对应字段，溢出进 material-library，需老大确认。
3. **prompt 与真实列名漂移**：加测试断言锁输出键（仿 `tests/paramGuide.test.ts`），防止 schema 改了 prompt 没跟。
4. **角色分级判定**：抽取出的角色落 char-main / char-secondary / char-npc 的自动分级规则（按出场频率/戏份），MVP 可默认全落 char-secondary，人工再升降级。
5. **地理「层级归属 / 所属地图」**：若抽到地图格档，需先建 geomaps 默认图（参考 migrateGeoMaps），MVP 可暂不强求。
