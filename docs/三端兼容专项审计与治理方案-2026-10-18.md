## 1. 专项目标

定位修改某一形态后对其他形态产生的回归，特别是错误后端、错误能力假设、账号串写、持久化误判和发布版本不匹配。输出可定位的候选、形态影响清单和验收矩阵；治理允许有理由的差异，不把三端强制改成同一实现。

工具已落地：`scripts/audit/platform/`。原11个通用审计入口、参数及报告路径不变。新增入口：

```powershell
node .workbuddy/tmp/audit-platform.mjs --matrix
# 同等入口
node .workbuddy/tools/audit-platform.mjs --matrix
node scripts/audit/run.mjs --platform --matrix
```

这套工具检查运行形态；`src/lib/audit/platformCheck.ts`处理投稿平台预检，职责不同，本次不修改它。

## 2. 先明确四个正式运行配置

| 配置 | DESKTOP | PORTABLE | WEB | WEB_GUEST | 后端及数据落点 |
|---|---:|---:|---:|---:|---|
| 桌面安装版 | true | false | false | false | desktopStore；IPC写用户数据目录JSON |
| 便携版 | false | true | false | false | portableStore；localhost服务写应用目录data |
| 网页云端账号 | false | **true** | true | false | portableStore；同源HTTP写账号隔离目录 |
| 网页游客 | false | false | true | true | idbOps；当前origin的IndexedDB |

开发预览另列一行作对照，不能替代任一正式形态。网页云端复用了HTTP适配层，`PORTABLE`在这里表示传输/存储选择的一部分，不能独自解释成产品名称。`!DESKTOP`也不能独自解释成“网页版”。

平台常量在模块求值时读取注入值，必须验证实际HTML/preload注入与前端初始化的先后；只在页面启动后修改window标记不能证明首启正确。

## 3. 工具做什么

### 3.1 源码扫描与模型推演

- TypeScript AST检查静态/动态Node依赖进入共享前端、绕过平台模块读标记、直接调用原生桥、绕过HTTP适配器访问数据、固定localhost请求及刷新附近的持久化确认候选。
- 对`PORTABLE`便携文案分支结合祖先条件推演，重点找网页云端被当成便携的路径；未知条件不假装已证明不可达。
- 从真实源码提取`DESKTOP / PORTABLE / WEB / WEB_GUEST / WEB_CLOUD`与`ops`初始化表达式，在隔离上下文推演四配置加dev；不执行应用模块、不访问数据库。
- 盘点平台消费者、原生桥、HTTP调用、监听地址、服务端注入、构建与部署文件。
- 核对三处外置store白名单：桌面只有backupPayloads是登记的差异；便携/云端另含vecRows、kbDocs、kbBodies。差异本身不报数据丢失，未经登记的变化要求复核。
- 发布脚本只测ping/首页而未核对版本或构建摘要时，提出交付候选；不把200当成版本匹配。

规则编号PLT-01至PLT-10，候选标记P1/P2优先级、文件/行号、影响配置及责任域。它们是复核线索，不自动认定为真实故障。复杂控制流、别名传播和封装调用可能漏检，运行取证不可省略。

### 3.2 检查范围与源码指纹

扫描`src / electron / server / scripts / portable / public`及package、HTML、Vite等入口配置；包含未提交源码。指纹覆盖上述源码、治理策略和应用图片/图标/字体资产。排除用户data、backups、logs、隐藏凭据、生成的dist/release及node_modules；不扫描实际稿件、Cookie或服务器密钥。

支持指定基线辅助查看改动归属：

```powershell
node .workbuddy/tmp/audit-platform.mjs --matrix --base 5bdf32e
```

基线diff只用于优先级和影响清单，不缩小全量扫描；git未跟踪文件仍参与源码扫描和指纹，未必出现在git diff清单中。读取git失败明确记录blocked。

### 3.3 运行证据契约

共8组、26个最低配置单元，每个单元包含多个场景。没有实测记录就保持unverified；源码模型匹配只记model-matched。

| 组 | 配置 | 必查点 |
|---|---|---|
| 启动与后端 | 四配置 | 首启标记、真正选中的后端、写后重启读回 |
| 写入失败 | 四配置 | 内存接受与实际落盘分开；失败不清dirty、不刷新；可导出；恢复后重试读回 |
| 账号隔离 | 网页云端 | A/B账号、游客转账号、同浏览器切账号后的旧标签页、会话过期/被替换 |
| 并发与关页 | 便携/网页云端 | 两标签并发、登录替换、保存中关页；sendBeacon返回true不算服务端已保存 |
| 网络与模型 | 四配置 | 远端/本机模型、搜索、取消/超时；实际目标环境下的CORS、HTTPS及本机服务可达性 |
| 数据互通 | 四配置 | 格式版本、sidecar、敏感项剥除、恢复失败保全 |
| 能力与UI | 四配置 | 文件/PDF/字体/更新/代理能力及准确文案；不支持时有可执行替代 |
| 交付物 | 桌面/便携/网页 | 构建版本、静态资源、注入时序、失败回滚 |

26个单元是功能最低矩阵，不等于OS/浏览器覆盖完毕。便携版按声明支持的Windows、macOS、Linux重复执行；网页版按实际支持的浏览器、HTTP/HTTPS部署配置执行，记录具体版本。

## 4. 推荐检查顺序

### A. 固定基线和能力清单

记录commit、未提交改动、版本、实际交付物及部署配置。识别正式四配置和dev；记录HTTP后端复用、向量存储及备份档位等已知差异。旧交接与当前源码冲突时，以用户最新指令和当前代码为准，分别注明“源码观察”与“部署事实”。

### B. 先跑只读源码专项

运行上述入口，阅读`report.json`和`report.md`。先复核P1候选，再检查平台注册消费者、sidecar及交付盘点。即使候选为0，也不能省略后续取证。

### C. 隔离启动与能力验证

- 桌面：临时用户数据目录启动实际安装/打包程序，确认preload、IPC和最终数据路径。
- 便携：临时应用根目录、独立端口及data目录启动；确认只监听预期本机地址，异常Host/Origin不能读取稿件。
- 网页云端：测试环境的两个临时账号；网页游客：独立浏览器上下文。不使用真实用户作品做写入/故障实验。
- 验证“内存变了”“持久化成功”“跨设备同步完成”三种状态的区别。`await put()`不一概视为落盘；写入锁、配额413、认证401、断网/断电模拟分别验证。

### D. 账号切换与并发优先

重点验证：同浏览器A标签保留旧库，另一个标签登录B后，A继续写入时不得把旧库写入B。单会话只约束token有效性，不自动证明共享Cookie下的旧标签安全。游客转登录应明确保留、迁移或导出的路径，不能静默覆盖任一侧。

再查双标签同时保存、退出登录时在途请求、会话替换后的重试、保存中关页。只弹提示的tabGuard需登记为策略取舍；不能写成“已防止覆盖”。之前暂缓的桌面双设备验收继续单独记录，不能据此把网页账号隔离算作通过。

### E. 跨形态数据互通

构造最小虚拟项目：两卷、正文/摘要、角色/设定、快照、回收站及sidecar。执行四配置之间的导出再导入，比较稳定字段与数量。检查旧版/当前版/未知新版/截断包；不支持的格式应在覆盖原数据前明确拒绝。敏感配置不得混入跨端共享包；桌面独立向量库的既定边界要按清单判定，不要求与便携物理存储一致。

### F. 网络与UI差异

分别核验模型、搜索、PDF、字体枚举、文件路径、代理、更新。桌面主进程桥与浏览器直发需分别测；保留超时、取消和鉴权提示。网页从服务器加载不代表AI请求也由服务器代理；本机模型地址在用户电脑上验证，不能用服务器能连通替代。

### G. 交付与回滚

检查三种交付物，版本号之外还应记录前端构建摘要、后端提交/协议版本及实际加载静态资源。分别模拟只更新前端、只更新后端、旧缓存标签页和部署失败；回滚应保持数据目录不动。只有ping与首页200不足以证明前后端配套。

当前源码的远端部署健康检查未见构建标识比较，专项将其列为PLT-10候选。建议后续提供build-info/构建清单及匹配检查；本次不改部署脚本、不自动上线。

### H. 销账、回归与交付结论

所有候选逐条归类：真实冲突、误报、设计差异、延期风险。修复后运行受影响的配置和共享路径；若只涉及源码静态/工具调整，则如实注明没有执行项目测试或真实运行验收。完整取证再讨论发布；部分通过不写全量通过。

## 5. 差异与调整治理机制

1. **集中登记**：`policy.json`登记配置模型、适配器、sidecar差异、责任域、最低运行矩阵。它是审计契约，不修改应用运行逻辑。
2. **修改前列影响**：涉及平台标记、后端、网络出口、数据格式、鉴权或构建时，提交流水应列出影响的四配置、刻意不变的行为和需要补验的单元。
3. **能力入口收口**：建议后续业务改动逐步通过集中runtime-kind/capabilities适配器表达原生文件、HTTP存储、账号身份等能力。不要为统一而把WEB与PORTABLE强行互斥；旧调用按功能逐步治理。
4. **故障语义统一**：写入结果明确accepted/persisted及错误；关页/刷新/账号切换只能依赖相应持久化确认。协议版本、sidecar及导入导出变更必须联动消费端。
5. **责任分域**：平台适配、存储同步、网页版鉴权、模型网络、构建发布分别有责任域；具体人员由本次实施者填写，工具不替用户指定。
6. **差异有期限**：误报/允许差异/延期须写负责人、具体理由、到期时间及当前源码指纹。deferred仍未完成，不靠永久目录豁免“消掉”风险。
7. **证据可追溯**：记录实际环境、正样本、必要场景、产物路径和SHA256；源码/服务端/构建/策略变化后旧记录失效。产物存在和哈希正确不证明其内容真实，仍由复核者核验。

## 6. 治理记录格式

```json
{
  "sourceFingerprint": "本轮report.json中的sourceFingerprint",
  "decisions": [
    {
      "id": "本轮finding的id",
      "status": "accepted-difference",
      "owner": "实际责任人",
      "reason": "具体说明该差异为何安全、边界及复查条件",
      "expiresAt": "2026-11-18T00:00:00+08:00"
    }
  ],
  "runtime": [
    {
      "id": "boot-store",
      "profile": "web-guest",
      "status": "passed",
      "samples": 1,
      "scenarios": ["initial-flags", "backend-selection", "restart-readback"],
      "environment": "实际OS/浏览器版本/环境标识",
      "artifact": {"path":"本轮实际证据文件路径","sha256":"该文件实际SHA256"}
    }
  ]
}
```

decision允许confirmed/false-positive/accepted-difference/deferred；运行记录允许passed/failed/blocked/deferred。缺少证据不传假passed，保留unverified。重复ID、过期指纹、缺场景/样本、产物哈希不符都不能报通过。

```powershell
node .workbuddy/tmp/audit-platform.mjs --matrix --evidence .workbuddy/tmp/platform-ledger.json
```

报告目录：`.workbuddy/tmp/platform-audit/<UTC时间戳>/`。退出码：0=本策略规定的证据齐全且候选销账；1=模型不符、已确认缺陷或运行失败；2=仍有候选、未验、受阻或延期。不把0解释为所有OS、浏览器和线上部署永久可靠。
