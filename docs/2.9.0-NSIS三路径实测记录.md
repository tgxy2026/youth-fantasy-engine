### 3.2 ③ 老版本覆盖升级 ⚠️ 无法自动化（需人工）

已装 2.8.3 时执行 `/S /currentuser` → 安装器**创建了可见向导窗口**
（标题 `[青春幻想引擎 安装]`、hwnd≠0），进程命令行确认是
`yfe290.exe /S /currentuser`（**`/S` 确实传进去了**），但向导仍出现并等待交互。

⇒ **结论**：这是 electron-builder **assisted installer（`oneClick: false`）的固有行为** ——
静默参数不能跳过「检测到已安装」时的向导确认。真实用户双击后点「下一步」即可，**非缺陷**。

**待人工确认的观察点**：点开 2.9.0 安装器后，向导的「安装目录」是否**默认带出旧版目录**
（这是判断「覆盖升级是否沿用旧目录」的唯一可靠方式）。

### 3.3 ① 默认装 ⚠️ 未能干净验证

不带 `/D` 时安装器**没有**落到默认路径 `%LOCALAPPDATA%\Programs\青春幻想引擎`，
而是**装回了上一次的目录**。这正是「安装器会沿用旧目录」的行为（见 §四·2），
但被 §四·1 的传参污染带到了错误路径上 ⇒ 该路径的干净验证需先清除路径记忆（人工或后续补测）。

### 3.4 卸载 ⚠️ 无法自动化

- 走 `QuietUninstallString`（`Uninstall 青春幻想引擎.exe /currentuser /S`）与 `/S` 两种形式
- 均 **934 ms 内 exit 0，且零动作**（目录、注册表键、快捷方式全部不变）
- 临时目录出现 `~nsu.tmp`（卸载器副本目录），但副本未完成工作
- ⇒ 非交互会话下卸载器无法工作，**需人工点一次**（或走「设置 → 应用 → 卸载」）

## 四、两条关键发现（都是工具/环境的，不是产品的）

### 4.1 🔴🔴 Git Bash (MSYS) 会破坏路径参数里的反斜杠

实测证据（安装器**实际收到的命令行**）：

| 传入写法 | 实际命令行 | 后果 |
|---|---|---|
| `'/D=D:\novel-studio'` | `/D=D:novel-studio` | 反斜杠被吞（`D:` 后缺 `\`）→ **注册表 UninstallString 写坏** |
| `/D=D:\Program Files\novel-studio`（不加引号） | `/D=D:\Program Filesnovel-studio` | `Files` 与 `novel-studio` 之间的 `\` 被吞 → 装到 `D:\Program Filesnovel-studio` |
| `"/D=D:\Program Files\novel-studio"`（加引号） | 值被破坏 | NSIS 把 `/D` 值当**相对路径**拼到 `$INSTDIR` 后 → 嵌套成 `...\Program Files\novel-studio\Program Files\novel-studio` |

⇒ **纪律**：
- 在 Git Bash 里给 NSIS 传 `/D=`，**只可用「无反斜杠且无空格」的路径**，且**不加引号**、值放最后；
- **带空格的路径无法通过 Git Bash 可靠传递** ⇒ 要么写**纯 ASCII 的 `.bat`**（内容原样、不经 MSYS），要么交给人工；
- 传参污染会**持久化进注册表**（`UninstallString` / `DisplayIcon` 路径变坏）⇒ 影响后续「设置 → 应用」卸载。
  **本轮已手工修正该键的 3 个值**（改为正确的 `D:\novel-studio\...`，并确认卸载器文件真实存在）。

### 4.2 ✅ 安装器会沿用上一次的安装目录（正面证据）

在**不带 `/D`**、且**无任何安装记录**（注册表卸载键已删净）的情况下，
安装器仍把文件装回**上一次的目录**（而非默认路径）。

⇒ 这正是「**覆盖升级不漂移**」的直接证据：升级时会沿用旧目录，
漂移只可能来自外部传入的错误 `/D`。**`allowToChangeInstallationDirectory: true` 不触发回滚判据**。
