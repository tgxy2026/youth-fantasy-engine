# 2.7.3 ·「自定义词条」改造方案（待拍板）

> 起因：社区反馈（2026-10-03）——「前端不能自定义词条，放进去还是太麻烦了；有谁懂我点进 asar 文件想手动魔改，然后在一堆代码里看到 7000 行雷霆小说的绝望感」。
> 本文先把**核实到的事实**摆出来，再给出打算怎么做；主人拍板后才动代码。
> 同批另一条反馈（Ctrl+S 在六个页签无反应）已修完并提交：`23ee193`。

## 一、核实结论（都是源码里读出来的，不是猜的）

| # | 核实项 | 结论 | 证据 |
|---|---|---|---|
| 1 | 「7000 行雷霆小说」是什么 | `src/data/seedContent.ts` —— **7664 行**的示范项目《吞天神脉》正文（21 章全文），纯字符串常量 | `wc -l` = 7664；首行注释「示范项目 · 正文内容」 |
| 2 | 词条库在哪 | `src/data/materialData.ts` —— **5730 行**的内置素材库（人物设计 / 故事结构 / 世界框架 / 情绪爽点 / 描写笔法 五类） | `MATERIAL_CATEGORIES` 常量 |
| 3 | 为什么不能自定义 | 素材页**在设计上就是只读**：界面顶部写着「内置写作参考素材库 · 只读」，帮助里明确「内容为内置素材，不能编辑」 | `MaterialLibrary.tsx:27 / 29 / 34` |
| 4 | 两块数据怎么进包的 | 都是**静态 import** ⇒ 打进主 bundle。所以打开 asar 里的 js，第一眼就是整部小说 | `seedData.ts:9`（静态 import CH1…CH21）、`MaterialLibrary.tsx:14`（静态 import MATERIAL_CATEGORIES） |
| 5 | 已有可自定义的入口吗 | 项目内的「术语表」等表格页签**本来就能自定义**；但那是「这本书的设定」，不是「我的素材词条库」 | `schema.ts` 的 terms 页签 |
| 6 | 全局 KV 存储有没有 | 有：`db.getMeta / db.setMeta`（跨项目全局，随云盘同步与备份） | `src/lib/db/meta.ts:7 / 11` |

**一句话定性**：不是「功能坏了」，是**这条路径从来没被开通过** —— 内置库写死在代码里，作者唯一能自己加东西的办法就是改 asar。而 asar 里又塞了一整部小说，翻都不好翻。所以要做两件事：**开通路径**（自定义词条）+ **把小说挪开**（不再碍眼）。

## 二、方案 A：我的词条（开通路径）

### A-1 数据层（新文件 `src/lib/myTerms.ts`，纯逻辑，住 lib 层）

```ts
export interface MyTerm {
  id: string
  title: string        // 词条名（如「血魔教」「听雪剑」）
  body: string         // 正文（可多段）
  tags: string[]       // 标签（如「势力」「法宝」）—— 供搜索与分组
  catId: string        // 所属分类（默认「未分类」）
  updatedAt: number
}
export interface MyTermCategory { id: string; name: string }
```

- **CRUD**：`listMyTerms()` / `saveMyTerm()` / `deleteMyTerm()` / `listMyCats()` / `saveMyCat()` / `deleteMyCat()`
- **存储**：单个 meta 键 `material.myTerms.v1`（结构 `{ cats: MyTermCategory[], terms: MyTerm[] }`）
  - ⚠️ 这个键**不含密钥**，不需要进 `EXCLUDED_META_KEYS`（那张表只管含密钥的全局 meta）
- **导入 / 导出**：`exportMyTerms(): string`（JSON）、`importMyTerms(json, mode)`
  - `mode` 两种：`merge`（同名覆盖、其余保留）/ `replace`（整包替换）—— 导入前在弹窗里让作者选，别静默覆盖

### A-2 界面层

素材资料页的分类页签**末尾多一个「我的词条」**（其余五类保持只读，不动）：

```
[人物设计] [故事结构] [世界框架] [情绪爽点] [描写笔法] [我的词条 ✎]
```

「我的词条」内部三栏（与现有的「世界设定」母子面板同一套观感）：

| 区域 | 内容 |
|---|---|
| 左栏 | 我的分类（默认「未分类」+ 自建分类），可新增 / 改名 / 删除 |
| 中栏 | 词条列表 + 搜索框（按标题与标签搜） |
| 右栏 | 编辑区：标题 / 正文 / 标签，右上「保存」「删除」；未保存时与别处一样显示「有未保存的改动」 |
| 页头 | 「导入 JSON」「导出 JSON」两个按钮 |

- 空态要写清楚：**「这里是你自己的词条本，内置的五类是只读的」** —— 免得作者以为又是一个不能编辑的库。
- 保存快捷键：直接复用本轮刚收敛的 `useSaveHotkey`（一行搞定，不会重蹈 Ctrl+S 那个漏挂的坑）。

### A-3 归属层（**这一条要主人拍板**）

| 选项 | 存储 | 适合什么 | 代价 |
|---|---|---|---|
| ① 跨项目全局 | `db.getMeta` | 人名 / 功法 / 地名这类**通用积累**，换书也能用 | 不随单本书导出 |
| ② 跟项目走 | 项目级 KV | 只属于这一本书的词条 | 换书要重建 |
| ③ 两层都要 | 两处各存 | 通用模板 + 本书词条 | 改造量最大，界面要分区显示 |

可可倾向 **①**：作者嫌「放进去麻烦」，一套跨书复用的素材库才省事。

## 三、方案 B：把内置数据挪出主包（治「7000 行绝望」）

**思路不是删内容**（示范项目还要用），而是**改成动态 import** —— vite 会把它们切成**独立 chunk**，主 bundle 立刻瘦身；翻包时看到的是 `seedContent-xxxx.js` 这种一眼能认出的数据块，而不是混在业务代码里的小说。

| 步骤 | 改什么 | 风险 |
|---|---|---|
| B-1 | `src/lib/seedData.ts:9` 的静态 import → 函数内 `await import('../data/seedContent')` | **零风险**：`createDemoProject()` 本来就是 `async`，两个调用方早已 `await` |
| B-2 | `src/components/MaterialLibrary.tsx:14` → `useEffect` 里动态加载，加载中显示 `LoadingState` | 低：该组件已有 loading 态可复用 |
| B-3 | 跑 `vite build` 看产物：确认多出两个独立 chunk、主 bundle 体积下降 | 低 |

⚠️ 顺带确认两条闸：
- `tests/structureGates` ③-a「`src/data/**` 不得有运行时 import」—— 本方案是**别人 import 它**，方向相反，不违规；
- 闸①的 `SIZE_FROZEN` 冻结上限（seedContent 8300 / materialData 6300）保持不变，只准降不准升。

## 四、方案 C（可选，默认**不开**）：词条进 AI 上下文

作者加了词条，下一步多半会想「写正文时让 AI 照着我的词条写」。

- 做法：我的词条库加一个开关「写正文时带上我的词条（默认关）」，打开后按 `aiContext` 的口径注入。
- ⚠️ 这是**新增 AI 功能**，必须走项目的四处注册纪律：`aiTasks` 门面 / `aiDataSources` / `aiWriterBudget` / 界面挂 `AIDataSourceNote`。
- 默认关的理由：词条多了会挤占上下文额度，不该默认替作者做决定。

## 五、验收方式

1. `tsc --noEmit` + `eslint src tests` + 全量单测（外层逐个跑、判退出码）
2. `vite build` —— 确认 B 的 chunk 真的切出来了（这一步不能省，删/改 import 必跑）
3. 实机（走 `novel-studio-ui-livecheck`）：新建词条 → 保存 → 切页签再回来还在 → 导出 JSON → 清空 → 导入 → 恢复
4. 结构闸：新增「我的词条」面板若带保存按钮，要进 `HOTKEY_PANELS` 白名单
