## 二、已修复（17 个文件）

### P0-1 🔴 误导性口径「全程本地模型，原文不外发」（违反项目红线）

- `src/lib/schema.ts:813`（一键拆书的 description）
- `src/components/NovelEditor.tsx:1593`（AI 伴写说明）

这两处都承诺「不外发」，而功能本身**支持云端模型**——作者据此决定要不要拿未发表稿子来用时，会得到错误的安心。
已改为与 `aiDataSources` 一致的诚实口径：**「只发给你当前选定的模型：本地模型不出本机，云端会上传到该服务商」**。

**并补了闸**（`tests/aiDataSources.test.ts` 新增 ⑧ 节）：循环 `TABS`，禁止页签说明里出现
`全程本地 / 不外发 / 不上传 / 绝���外发 / 纯本地`。
⚠️ 判据不能含「不出本机」——正确口径里也会写「本地模型不出本机」。

> 为什么会有这条漏网：原有的 `aiDataSources.test.ts` 已经锁了这个口径，
> 但它**只扫 `AI_DATA_SOURCES[id].excludes`，没扫页签 description**，误导文案是从这条缝里溜过去的。

**负面对照**：临时把违规文案写回去跑闸 → 确认真的 FAIL；随后自动还原（已复核还原成功）。

### P0-2 🔴 自动备份失败完全不可见（静默失败）

`src/lib/backup.ts` 两处只 `console.warn`。用户以为「每 5 分钟一份、留 30 份」在保护他，
实际可能一份都没存成功（磁盘满 / 数据文件只读 / 桌面写盘失败），等要恢复时才发现。

- `lib/backup.ts`：新增 `BackupFailure` 记录 + `takeBackupFailure()`（**取走即清空**，同一条最多提示一次）
- `src/App.tsx`：新增 30 秒轮询，取到失败即 toast（8 秒），提示尽快「导出备份」到外部文件

🔴 为什么不直接在 lib 里弹 toast：`showToast` 住在 `components/dialogs`，
**lib → components 属反向依赖**，会被 `importCycles` 闸拦下。故 lib 只记录、UI 层展示。

## 四、判定不改（附理由，避免下轮重复提案）

| 项 | 理由 |
|---|---|
| `getBoundingClientRect` 10 处 | 全是定位/拖拽坐标：下拉浮层定位、`clientY` 判插入位置、SVG 缩放锚点。与 `clientY` 同坐标系，界面缩放下依然正确 |
| 4 处裸 `JSON.parse` | 全在 try/catch 内且有 toast 反馈（`BackupManager` / `ProjectHub` / `cardFile` / `presets`） |
| 酒馆 `TavernPlot` / `tavern/prompt.ts` 未走 `promptGuard` | 那里作者设定**就是角色扮演前提**，不是待隔离的不可信数据；包 nonce 块会改变语义，且需重跑实弹才能判断影响 |
| `FactionGraph` 十六进制色 | 「同盟=绿 / 敌对=红」是**语义色**，本就该固定，不该随主题变 |
| 8 个面板「缺 AI 就绪守卫」 | 都没有禁用态，但每个都有 catch → toast / setError，用户看得见报错。属 UX 优化，不是 bug |
| 术语多写法（大纲 / 总纲、设定集 / 设定表 等） | 语义可能本就不同，属产品决策，不由审计擅自统一 |
| 剩余 3 处 `ghost` | 均为 `iconOnly`（既有约定） |
