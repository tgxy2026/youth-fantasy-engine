## 青春幻想引擎 v3.2.0 —— AI 改稿，看得见、管得住、能核对

本版**不新增页签**，只解决一件事：**AI 改过的稿子，你到底能不能信。**

以前它改完直接覆盖正文，你只能事后去「时光机」翻旧稿，也说不清"改完到底改好了没"。
3.2.0 把这条链路拆成你能看见的四步：**先审 → 再应用 → 改完复检 → 报告留档**。

### 这次多了什么

- **候选审阅**：AI 产出的稿子先放「创作轨迹 → 候选审阅」，你决定应用还是放弃。
  **应用前会比对正文** —— 你在期间自己改过这一章，它会拒绝，绝不覆盖你的编辑。
  整章改写的产出也会登记到这里，关掉页面 / 切页签后仍找得回。
- **改完复检**：执行完逐章修订，每章标题旁多一句 `复检：原问题已清` / `还剩 N 条没解决` / `复检没跑成`。
  用的是本地五个检查引擎，**不耗 AI 额度**。以前标「已完成」只代表改过了，现在能知道改好了没。
- **检查报告留档与回看**：只有查到「冲突 / 注意」级问题才留档，**全绿的书一份都不存**。
  每条带来源、章名快照、引文与「引文 N/M 可定位」。
- **证据快照**：报告落库那一刻就把引文与段号记下来 —— 回答的是"当时到底有没有证据"，
  而不是"现在还能不能定位"。
- **诊断不再报喜不报忧**：工单顶部显示「已检 X/Y 章 · 发现 N 个问题 · 留档 N 份」，
  **没检成的章会点名列出**，不会再出现"诊断完成、没有问题"其实漏检了一半的情况。
- **实体保留自检**：改写后哪些已登记的人物 / 势力名没再出现，章标题旁提一句并说明属于哪个页签。
  **只提示不判定** —— 少提一次名字常常是合理润色，丢没丢设定你自己判断。
- **结构化输出开关**：可声明端点支持 JSON 结构化输出（`response_format` / `format`），JSON 类任务更稳。
  **默认关**；开了若端点报 400，会自动撤掉对应参数重试一次。
- **请求预算**：整章改写一条最多 6 次、一次性任务最多 3 次，到顶就停并如实告诉你停在哪。
- **网络卡住不吞字**：流式停滞超时会中断，并把**已收到的片段**带出来，说明「已收到 N 字未采用」。
  **半截正文不会整章落库** —— 覆盖一半比不落更糟。

### 升级前请先备份

本版新增两个数据 store（修订任务与工作产物），IDB 版本迁移会自动完成；
老数据没有本版新加的字段时一律**退化显示**，不猜、不编（例如老报告没有章名快照 ⇒ 回看用当前章名）。
工作产物（候选正文、检查报告）是**本地专属**，不上云、不进同步。

### 本版没做的

- 计划与实际的自动核对（`planCompare`）、世界差异对比（`worldDiff`）—— 方案里属后续里程碑。
- 大表虚拟化：一张表 1000 条 × 60 自定义字段仍然慢（打开约 17 秒），**登记 3.2.x 专项**。
  章节列表**本来就有虚拟化**：500 章 / 101 万字打开正文编辑页 264ms。

### 已知限制（如实写）

1. **复检结论不跨刷新**：任务中心的运行结果只在当次会话内可见；刷新后要看结论请去「检查报告」。
2. **引文定位率可能很低**：伏笔 / 文风类问题的引文多来自设定表比对，不是正文原句，
   所以显示「引文 0/3 可定位」是如实的，**不代表问题不存在**。
3. **实体保留自检只报告**：不判定"丢没丢设定"，也不阻断落库。
4. **主包体积** 1.67MB（gzip 540kB），网页版首屏偏慢；出厂数据已单独分包。
5. **未验证项**：真实端点三处对照、24 个固定样本对照、双设备同步、桌面 / 便携往返 ——
   逐条见发布验收记录。
