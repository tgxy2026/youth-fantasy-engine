## §3 与需求冲突 / 口径不明的三处（含原因与建议）

### 冲突 1 🔴「推荐新建项目」会废掉创意写作的「续写模式」
需求第 5 段说"推荐新建项目避免冲突"，第 12 段又说创意写作"如果是续写创作，就需要去读取项目中已有的设定材料"——**强制新建 = 续写无从谈起**。
→ **建议按功能分开**：拆书强提示新建（要往正文写整本书的卷章）；创意写作分「从零创作（建议新建）」与「续写（必须用现有项目）」。
→ **老大 09-18 决定：两边都只做软提示**，不检测、不拦、不分模式。

### 冲突 2 ⚠️「按模型窗口推荐导入数据量」的**口径要校正**
拆书是**逐章 / 逐块抽取**，单次 prompt 只有一章（≤ `maxUnitChars` 默认 4000 字），所以**导入量本身不会撞模型窗口**；真正受限的是**调用次数与总耗时**。
→ 界面文案必须写成「预计 N 次调用 · 约 X~Y 分钟 · 推荐单次导入 ≤ Z 字」，**别写成"最多能喂多少字"**，否则用户以为是一锤子读完。
→ 唯一真受窗口硬限的是"一次读完整本给整体判断"那种整体性抽取（本流程不做）。

### 冲突 3 🔴 form 型目标（世界观 / 力量体系 / 书籍定位）与「逐章增量写入」冲突
它们是**整项目单条**；逐章往同一个 form 里累加会越写越长、并覆盖用户手改内容。
→ **建议分两层**：条目级（人物/地点/物品/势力/术语/情节）逐章增量写；**全书级**（定位/世界观/力量体系）放到流程末尾**汇总一次**，采用"累积合并 + 来源标注 + 不覆盖用户手改过"。

## §4 P0 已落地（提交 `43bda87`）

### 4-1 写入正文（`src/lib/bookbreak/persist.ts`）
- `planVolumes(sp, opts)`：**纯函数**，把切分结果分层为「卷 → 章」。
  - `isVolumeTitle()`（`split.ts` 导出）判定「卷X」是**卷边界**；该条自带正文落成「卷首」章
  - 卷边界之前的章归入默认卷（`volumeTitle` 或「导入原文」）；末尾空卷丢弃
- `persistSplitToChapters(sp, opts)`：写 `Volume` / `Chapter` + `syncChapterMaster` 同步该卷台账。
  - 🔴 **只追加，绝不覆盖**：新卷接在已有卷之后，序/号接续（`chapterSeqMap` 取已有最大号 +1）
  - 🔴 **重复导入守卫**：同名卷 + 同章数 + 同章标题集合 → 判「已导入过」整体跳过
  - 🔴 **中止返回半成品**：`aborted=true` + 已写入统计，不留脏数据
  - 导入章节状态 = **「完稿」**（原文本来就是写完的文本；改这个常量要同步面板说明）
- ⚠️ **本章概要不在此填**：概要属于「正文 → 卷台账 → 章节细纲卡」那条勾稽链，与创意写作的回填是同一套逻辑，留到 P2 统一设计。

### 4-2 导入量 / 耗时推荐（`src/lib/bookbreak/recommend.ts`）
- `adviseImport(sp, cap, opts)` → 预计调用次数 / 耗时区间 / 推荐单次导入字数 / 三级提示
- 分级：`ok`（≤40 次）/ `large`（41~120，建议先跑 5~10 万字）/ `too-large`（超硬顶 120 或切分被截断）
- 🔴 分级必须用**未钳制**的调用次数判断——用钳制后的值会让"超上限会被截断"报成"偏多"（**测试抓到过**）
- 单次耗时粗估：本地 20~40s/次、云端 8~18s/次（区间取宽，宁保守勿乐观）

### 4-3 管线与界面
- `run.ts` 阶段序：**split → persist → extract → draft**（persist 放最前，用户马上能在正文编辑看到框架）
- `BookBreakOptions` 新增 `persistToChapters`（**默认 true**）与 `volumeTitle`
- 面板：写入开关（默认勾选）+ 新建项目软提示 + 预览显示「将写入 N 卷 M 章」+ 完成后的落库摘要
- `split.ts`：单段超长的硬切**退到最近句末标点**（回溯窗口 = 块末 40%，下限 200 字）
