# 2.9.3 · 窄窗口布局塌陷修复（2026-10-09 主人截图反馈）

> 现象（主人原话）：「缩小窗口时页面显示异常」。
> 截图里中栏「历史事件」的标题与说明被压成**一条竖缝**（逐字竖排），
> 顶部工具栏右端（保存 / 表格 / 时间轴 / 历法规则）被裁掉。

---

## 1. 定位（真浏览器量宽度，不猜）

用真实 Chromium 打开 dev server，切到「历史事件」页，在 1280 / 1100 / 1000 / 900 四档视口下
量 `main` 与页头各子容器的 `getBoundingClientRect().width` 与 `scrollWidth`：

```
视口 1280 · main w=1056 (scrollW 1153)
  HEADER w=992 sw=1121 :: mb-5 flex items-start justify-between gap-4 sticky …
    DIV w=0    sw=45   :: min-w-0                            ← 标题容器被压成 0 宽（文字竖排）
    DIV w=1105 sw=1105 :: flex items-center gap-2 shrink-0    ← 工具条 1105px 且不可压缩
```

一眼看出问题：**页头是 `justify-between` 两栏，右栏 `shrink-0`（1105px 不让步），
左栏只有 `min-w-0`（能被压到 0 宽）**。可用宽度不足时，标题与描述承担了全部压缩 ⇒ 塌成竖缝；
工具条本身又比容器宽 ⇒ 右端被外层 `overflow-hidden` 裁掉。

⚠️ 关键事实：**默认 1280 窗口下就已经不足**（工具条 1105 > 内容区 992），
「缩小窗口」只是把「裁掉右边」升级成「标题也塌了」。

---

## 2. 根因（一个 bug 家族，四处）

同一个写法复制到了四个地方，全都是「`justify-between` + 右栏 `shrink-0` + 左栏可压缩」：

| 位置 | 现状 |
|---|---|
| `TableSheet.tsx` 页头 | 🔴 工具条 1105px（历史事件表按钮最多）⇒ 默认窗口就塌 |
| `CharacterSheet.tsx` 页头 | 🔴 需 992px，1000px 窗口（内容 728px）必塌 |
| `TavernControl.tsx` 页头 | ⚪ 需 812px，暂未暴露，但结构一样 |
| `Sidebar.tsx`「界面缩放」行 | 🔴 侧栏内容区仅 192px、该行需约 210px ⇒ 标签被压成一个字宽（主人截图里也能看到） |

---

## 3. 修法：**放不下就折行**（不改宽屏版式）

```diff
- <header className="… flex items-start justify-between gap-4 …">
-   <div className="min-w-0">
+ <header className="… flex flex-wrap items-start justify-between gap-x-4 gap-y-2 …">
+   <div className="min-w-[14rem] flex-1">
      …标题 / 说明…
-   <div className="flex items-center gap-2 shrink-0">
+   <div className="ml-auto flex flex-wrap items-center justify-end gap-2">
      …工具条按钮…
```

三条各自的作用（缺一条都不对）：

- `flex-wrap` ＋ `gap-y-2`：一行塞不下时，工具条**整体落到第二行**（而不是把标题挤没）；
- 左栏 `flex-1`（flex-basis 归零）＋ `min-w-[14rem]`：
  - basis 归零是为了**让换行判断不受那段长描述影响** —— 否则它的 max-content（`max-w-3xl` ≈ 768px）
    会让**宽屏也误判成"放不下"**、平白折行；
  - `min-w-[14rem]` 是**保底**，从此不再被压成 0。
- 工具条 `ml-auto` ＋ 去掉 `shrink-0` ＋ 内部 `flex-wrap justify-end`：
  - 它在宽屏不受影响（空间够就不压缩）；
  - 折行后独占一行时会被压到行宽、内部按钮再按需折行，且始终靠右。

侧栏那处同理：`flex items-center gap-2` → `flex flex-wrap items-center gap-x-2 gap-y-1`，
并把「界面缩放」标签加上 `shrink-0`。

**宽屏下三组 class 都不生效 ⇒ 版式与改动前逐像素一致。**

## 4. 验证

| 项 | 结果 |
|---|---|
| `tsc --noEmit` / `eslint src tests` | 0 / 0 problem |
| 全量单测 | 168 全绿 |
| 实机 · 四档宽度（1920/1600/1280/1100/1000/900） | `main` 的 `scrollWidth == width`，**无一处横向溢出** |
| 实机 · 三页页头体检（1280 与 1000） | 无 `scrollWidth > width`、无子项被压到 < 60px |
| 实机 · 侧栏「界面缩放」标签 | 由约 14px（竖排）恢复为正常宽度 |

判据（写进脚本，避免"看着顺眼"就算过）：
`hdr.scrollWidth > hdr.width + 1` 或任一子项宽度 `< 60` ⇒ 🔴 仍异常。

---

## 5. 两点如实说明

1. **默认 1280 窗口下，「历史事件」页的工具条现在会折成两行** —— 这不是新引入的「丑」，
   而是原来被裁掉的那部分按钮**现在可见了**（工具条实际 1105px > 内容区 992px，客观放不下）。
   要单行只能削减按钮（如把统计文字 / 低频按钮收进「更多」），属产品决策，本轮**不做**。
2. 本页的表格本体一直是好的（`overflow-x-auto`，设计如此，HelpPopover 里也写了
   「整体超出页面时表格底部出现横向滑条」）—— 坏的只有页头。
