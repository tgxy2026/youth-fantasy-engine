# 3.2.2 · 角色管理（及同类表单）窄宽度标签列方案

> 起因：3.2.2 平板适配验收时人工看 768×1024 截图，**角色管理**是可挑剔的一处 ——
> 标签列占约 1/3 宽、字段说明在左列换行 2–4 行。功能可用，但不够"协调美观"。
> 本文只给方案与改动点，**未改代码**，等主人选一个再动手。

## 一、现状（实测）

| 项 | 实测值 |
|---|---|
| 触发两列布局的容器宽度 | `@min-[32rem]`（512px） |
| 标签列宽度 | **固定 160px** |
| 768×1024 窗口下正文区宽 | 约 720px（探针记录 `mainWidth: 720`） |
| 标签列占比 | 160 / 720 ≈ **22%**，加上 `gap-4` 视觉上接近 1/4–1/3 |
| 左列内容 | **字段名（13px）+ 字段说明（`field-desc`，多行）** |
| 说明换行 | 长说明（如"信息档位：决定「谁看得到」与「谁先占上下文预算」…"）换 **3–4 行** |

代码位置：`src/components/common/SchemaFieldGrid.tsx` 第 58 行

```tsx
<div className="px-3 py-3 grid grid-cols-1
     @min-[32rem]/fields:grid-cols-[160px_minmax(0,1fr)] gap-2 @min-[32rem]/fields:gap-4 ...">
  <div>
    <div className="text-13 font-medium text-ink-100">{aliasLabels[key]}</div>
    {field.desc && <div className="field-desc mt-1">{field.desc}</div>}   {/* ← 撑高的元凶 */}
  </div>
  <div>
    <AutoTextarea ... />
    {!val && field.example && <div className="field-example ...">示例：…</div>}
  </div>
</div>
```

🔴 关键：**换行不是因为字段名长**（"性命等级"只有 4 字），而是**说明文字挤在 160px 的左列里**。

## 二、三个方案

### 方案 A（推荐）：窄容器把说明挪到输入框下方，标签列收窄

宽容器不变；窄容器（如 `@max-[44rem]/fields`）下：
- 左列**只留字段名**，宽度 160px → **110px**；
- 说明移到输入框下方，`line-clamp-2` + `title` 悬停看全文。

```tsx
<div className="px-3 py-3 grid grid-cols-1 gap-2
     @min-[32rem]/fields:grid-cols-[110px_minmax(0,1fr)] @min-[32rem]/fields:gap-4
     @min-[44rem]/fields:grid-cols-[160px_minmax(0,1fr)]">
  <div>
    <div className="text-13 font-medium text-ink-100">{alias}</div>
    {field.desc && <div className="field-desc mt-1 hidden @min-[44rem]/fields:block">{field.desc}</div>}
  </div>
  <div>
    <AutoTextarea ... />
    {field.desc && (
      <div className="field-desc mt-1 @min-[44rem]/fields:hidden line-clamp-2" title={field.desc}>
        {field.desc}
      </div>
    )}
    {!val && field.example && ...}
  </div>
</div>
```

- ✅ 保留"左列找字段名"的扫读习惯；字段名基本一行；输入框宽度增加 50px
- ✅ 说明仍可见（不丢信息），只是移到更宽的位置
- ⚠️ 说明从"标签下方"变成"输入下方"，位置变了，需要作者适应一次
- 改动量：**1 个文件 1 处**，纯 Tailwind 容器查询，无逻辑改动

### 方案 B：窄容器整体上下堆叠（标签在上、输入在下）

```tsx
@max-[44rem]/fields:grid-cols-1        /* 单列，标签与输入各占一行 */
```

- ✅ 字段名可用宽度最大，彻底不换行
- ⚠️ 每行高度 +40% 左右，13 个字段的卡片会明显变长，扫读变慢（作者要滚动更多）
- ⚠️ 与"宽屏两列"的视觉差异最大，切换窗口时跳动感强
- 改动量：同样是 1 处，但体验取舍最激进

### 方案 C：最小改动 —— 说明降到 10px + 限 2 行 + 悬停看全

```tsx
{field.desc && <div className="field-desc mt-1 text-10 line-clamp-2" title={field.desc}>{field.desc}</div>}
```

- ✅ 改动最小，所有宽度一致（不引入新断点）
- ⚠️ 治标：160px 仍是 160px，只是少换几行；长说明仍被截断（靠悬停才能读全）
- ⚠️ 说明字号降到 10px 会牵连 `themeContrast` 闸（小字对比度本就偏紧）

## 三、推荐：A

理由：**问题出在"说明和标签挤在一个窄列里"，不是"两列布局"本身**。A 只把说明挪到它该在的位置
（输入框下方、可用宽度 500px+），既解决换行，又不牺牲扫读效率，改动还只在一个文件的一处。

B 的代价（面板变长、滚动变多）大于收益；C 只是把症状压小。

## 四、如果选 A，落地步骤与验证

1. 改 `SchemaFieldGrid.tsx` 一处 class（上方代码块）；
2. 影响面：`SchemaFieldGrid` 是**表单类页签的公共组件**（作品信息 / 世界设定 / 角色卡 / 部分设定表），
   不是角色管理独有 —— 所以改动会同时改善其他表单，符合"项目内全部页签"的要求；
3. 验证：
   - 布局探针重跑（55 页 × 7 组），要求仍是 0 越界；
   - **新增一档容器宽度**（如 640）进探针，覆盖 A/B 的断点边界；
   - 768 / 1024 / 1280 三档各截 角色管理 + 作品信息 + 世界设定，人工比对；
   - `themeContrast` / `visualToolbarA2G` / `structureGates` 全跑（说明位置变了，别撞视觉闸）。
4. 风险：低（无逻辑改动），但**属于视觉决策**，所以先出方案不直接改。

## 五、顺带发现（不属于本方案，供参考）

`field.desc` 与 `field.example` 在**空值**时同时出现，一行里可能堆三段灰字（说明 + 示例 + 提示），
窄宽度下更挤。若主人愿意，可以把"示例"也收进 `title` 或折叠 ⓘ —— 但那是另一件事，本文不动。
