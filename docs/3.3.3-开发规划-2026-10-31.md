## 1. 版本目标与边界

3.3.2 解决了「书跟着人走」。3.3.3 解决两件事：**写的时候有人替你盯质量（A）**、**用得着的角落不再空着（B）**。

一句话目标：**让作者在写到第 100 章时，仍然相信这本书是自己的。**

跨端可用（C）的内容完整保留在 §5，作为 3.3.4 的底稿，**本版不实施**。

### 1.1 本版主题

| 主题 | 一句话 | 用户可感知的变化 |
|---|---|---|
| **A 把长篇写稳** | 从"生成时禁止注水"升级为"生成后能查出注水与空转" | 章节体检多两项：重复/注水报告、推进度报告 |
| **B 收尾与补洼地** | 把 3.3.2 的尾巴收干净，把三个薄页签补起来 | 云端有新版本能一键更新本机；写作规范/进度/灵感素材不再是空表 |
| **C 跨端可用**（移交 3.3.4） | 手机浏览器从"能打开"变成"能写完一章" | 本版不做；底稿见 §5 |

### 1.2 本版必做

1. 重复与注水检测：在既有 `manuscriptCheck` 基础上扩到**跨章、段落级、语义级**，输出可定位的报告。
2. 剧情推进度检测：判断「这一章结束后，故事发生了什么变化」，只报告不代改。
3. 模型能力不再靠硬编码家族表，未知模型不得被误判成"不支持 JSON"。
4. 拆书失败只重跑失败单元，不整卷重来。
5. 云端有新版本时，提供「更新本机」入口（先自动备份，二次确认）。
6. 过期注释治理并**加自动闸**：注释里引用的 `docs/` 路径必须存在，防止再腐坏。
7. AI 长任务跨重启可续（至少拆书与创意写作两条）。
8. `写作规范` / `写作进度` / `灵感素材` 三页补齐辅助能力。
9. 图鉴卡片墙从只读变可编辑（F3/F4 范围）。
10. 字段类型转换与真删除（能无损才转，其余走新建字段搬运）。

### 1.3 不纳入本版

- **整个 C 跨端可用**（手机窄屏适配、网页版全屏与证据包导出、本地模型端边界、能力矩阵统一）——移交 3.3.4，底稿见 §5。
- 实时协作、光标共享、跨账号共享编辑；文本自动合并。
- 移动原生安装包（定位仍是桌面工作台 + 网页版；手机走浏览器）。
- 社交化能力（拼字房、战队、排行榜、稿费预测、平台一键发布）——与"单人本地优先"定位冲突，明确不做。
- 🔴 **任何形式的"去 AI 味 / 规避 AI 检测"**：不做改写规避、不提供"降 AI 率"建议。允许做的是**如实自检**（报告句式单调、重复度高），且报告措辞不得暗示"可以骗过检测"。
- 端到端加密承诺、跨端恢复正在运行的 AI 任务。
- 自动替换本机正文（云端更新一律要用户点）。

### 2.1 外部对标结论（2026 年 10 月检索）

- 行业竞争点已从"能不能生成"转向"写到 100 章后还记不记得"；MemoryArena 基准：外部记忆层方案完成率约 80%，纯长上下文约 45%。

## 3. 主题 A：把长篇写稳

### A1 重复与注水检测（深化，非新建）

**问题**：现有只查章内重复 3 字词组（≥3 次），抓不到三类真实注水：① 跨章反复用同一句式/口头禅；② 段落级"形容词+心理独白"堆砌而无事件；③ 语义重复（换词不换意的同义复述）。

**目标**：一章体检给出「重复与注水」报告，每条能**定位到段落**，作者自己判断改不改。

**做法**
- 跨章层：把最近 N 章（默认 10 章）纳入统计，输出"这一章新出现 / 仍在重复"的词组与句式，避免每章都报同一批词。
- 段落层：本地统计每段的"事件密度代理指标"——动词句占比、对话句占比、专有名词出现数、感官词占比；对异常段给出**中性描述**（"本段以修饰与心理描写为主，未出现新事件名词"），不打分。
- 语义层：可选 AI 复核（走现有 `rewrite`/`audit` 通道），只对本地挑出的候选段做二次判断，控制成本。
- 全部结果进 `Observation` 模型，与四引擎共用展示与台账（`checkLog`）。

**判据**
- 合成语料（人工灌水 30%）能定位到被灌水的段落，漏报不超过 2 段/万字。
- 对正常章节不得刷屏：默认只报密度最高的前 5 条，可按需展开。
- 同一章重复跑两次，结果一致（纯函数、无随机）。
- 不出现"建议删除""影响评分"等措辞；不改正文。

**风险**：误报伤害信任 ⇒ 采取**高精度低召回**，宁少报；报告可整项关闭。

### A2 剧情推进度检测（全新）

**问题**：AI 最容易写出"有场面没推进"的章节。现有「情节推演」是往前推演，没有回看"这一章到底改变了什么"。

**目标**：回答一个问题——**这一章结束后，和开始相比，故事有哪些不可逆变化？** 没有变化就提示"疑似空转"。

**做法**
- 抽取"变化清单"：主角目标推进/受阻、关系变化、掌握信息变化、资源或地位变化、地点变化。
- 优先复用**章后整理**已产出的状态变更（设定变更页签），没有时再用一次轻量 AI 抽取。
- 与「章末钩子」区分：钩子是"读者还想不想看下一章"，推进度是"这一章有没有往前走"。两者都低才提示。
- 输出形态：三条以内的事实清单 + 一句结论（有推进 / 推进偏弱 / 未见推进），**不下"水章"结论**。

**判据**
- 人工标注 20 章（10 章空转、10 章有推进）作为金标；结论与人工一致率不低于 80%，"未见推进"的精确率不低于 70%（宁漏不错）。
- 判定必须能给出依据（引用了哪几段），不能只给结论。
- 纯本地可跑（无模型时不崩，降级为"未检测"而不是"通过"）。

**风险**：误判会激怒作者 ⇒ 文案一律用"可能""未见"，并提供"我不认同"的反馈入口（仅本地记录，不上传）。

### A3 模型能力表可维护

**问题**：`modelCapabilities.ts` 靠静态家族表推断上下文窗口与 JSON 支持，新模型上线即误判；误判表现为"任务莫名失败"，用户看不懂。

**做法**
- 三级来源：内置表 → 用户覆盖（设置里可手填窗口/是否支持 JSON）→ 运行时探测结果缓存。
- 探测只做**一次**且可跳过：发一个极小的 JSON 测试请求，记录成功/失败与耗时。
- 任务失败时，把"我们以为这个模型支持什么"如实展示出来，让作者知道该改哪。

**判据**：未知模型不再直接判"不支持 JSON"；覆盖设置生效且重启保留；探测失败不影响正常对话。

### A4 拆书只重试失败单元

**问题**：`BookBreakPanel.tsx:577` 明确"不支持只重试失败单元"，一次失败整卷重跑，直接烧钱。

**做法**：按单元（章/段）记录状态与结果，成功的落缓存；重试只发失败单元。

**判据**：50 章中第 37 章失败 → 重试请求数只等于失败单元数，其余章节不重复请求；重试结果与首次成功单元合并后结构完整。

## 4. 主题 B：收尾与补洼地

### B1 云端有新版本时补「更新本机」

**问题**：本机干净、云端前进时，界面只给「下载为新书」「导出云端这一版」（`CloudSyncPanel.tsx:903-918`）。想让这本就地更新，作者得另存副本再手工替换。

**做法**：在该分支增加「用云端这一版更新本机」——复用已有 B3-2 覆盖实现（`restoreBundleToProject` + 覆盖前 `createAutoBackup`），二次确认写明"本机这本将被替换，已自动备份一份"。

**判据**：更新后正文逐字一致、`projectId` 不变、绑定基线钉到该版、备份可在「备份」里找回；覆盖前不允许存在脏改动（有则转冲突流程）。

### B2 过期注释治理 + 自动闸

**问题**：已发现至少两处注释与代码不符（`syncAuto.ts:91` 说 B3-2 未做、`syncClient.ts:14` 说保存流程没调 enqueue，实际 3.3.2 已改用 `updatedAt` 轮询）。注释腐坏会让后来者按错误前提改代码——本版已因此浪费一轮核查。

**做法**
- 逐条核对 `src/`、`server/` 中"未接线/尚未实现/还没做"类断言，与实现对齐或删除。
- 扩展 `scripts/release-check.mjs` 的 `check-doc-refs`：把**源码注释里引用的 `docs/…` 路径**也纳入存在性检查，纳入发布门禁。

**判据**：全仓注释中的 `docs/` 路径 0 缺失；人为制造一条失效路径时门禁变红。

### B3 AI 长任务跨重启可续

**问题**：`aiTaskCenter` 只做内存态，拆书跑到一半关软件即全丢。

**做法**：先只做**拆书与创意写作**两条（体积可控），落盘内容限定为"进度 + 已完成单元结果引用"，不把整本原文塞进 meta。分期：先持久化进度，再持久化产物。

**判据**：跑到一半强杀进程 → 重开软件能看到"上次未完成，继续/丢弃"；继续只补剩余单元；丢弃清理干净不留垃圾。

### B4 三个薄页签补齐

现状：`写作规范`（纯表单，无 AI 无导入）、`写作进度`（7 列流水，AI 上下文都不进）、`灵感素材`（7 列表，无去重、无跨表引用）是 55 页签里最浅的三个。

**做法（统一口径，不各写一套）**
- 三页都接 `TableSheet` 通用能力：导入导出、AI 整理（抽取/补全）、引用跳转。
- `写作规范`：增加"从正文反推规范"（作者写完几章后，让 AI 归纳实际写法）——只建议不覆盖。
- `写作进度`：增加进度看板（日均/存稿/预计完结），复用 `pace` 任务；明确它仍不进 AI 上下文预算，避免拖慢。
- `灵感素材`：增加去重与"转成设定/大纲条目"的一键通道（与灵感转化现有能力对齐）。

**判据**：三页都能导入导出且回读一致；AI 整理结果需人工确认才落库；写作进度页仍不进入上下文预算（结构闸断言）。

### B5 图鉴卡片墙 F3/F4

按 `AtlasView.tsx:7` 已列的范围做：就地编辑、图片上传、卡片密度、侧栏宽度拖拽、层级树联动。

**判据**：卡片就地改字段后表格侧同步可见；图片上传后重开仍在；密度与侧栏宽度刷新后保留；层级树点选与卡片高亮联动。

**风险**：图片上传会推高单项目体积 ⇒ 需与云端 200MB 配额联动提示，超出时明确告知。

### B6 字段类型转换与真删除

`AtlasFieldManager.tsx:8-9` 列明未做。**做法**：类型转换提供"能无损才转"的白名单（文本↔长文本、数字↔文本），其余走"新建字段 + 搬运"；真删除需二次确认并说明数据不可恢复。

**判据**：转换后旧值不丢（超长截断要提示）；真删除不动其他字段数据。

### B7 桌面端 prompt 对话框（低优先）

当前无调用方，属"补坑"。仅当本版其他功能需要"输入一句话"时顺手实现，不单独排期。

## 5. 主题 C：跨端可用（**移交 3.3.4，本版不实施**）

> 本节保留完整设计，作为 3.3.4 的底稿。**3.3.3 不动这里任何一行代码** —— 布局类改动与 A/B 的内容/数据类改动混在同一版，出问题时无法判断成因。

### C1 手机窄屏 320–430px

**问题**：手机浏览器能打开，但侧栏与入口大量折叠（3.3.2 实机在 399×794 视口下已观察到）。

**做法**：侧栏改抽屉（汉堡按钮 + 遮罩）、顶部工具条收敛为两行以内、触摸目标不小于 44px、表格型页签在窄屏改卡片列表、正文编辑器工具栏折叠为"更多"。

**判据**：320×568（iPhone SE 级别）能完整走完：登录 → 云端取书 → 写一章 → 保存 → 看到"已同步"；无横向滚动；不靠颜色传达状态。

**风险**：会牵动全站布局 ⇒ 必须有视觉回归基线 + 结构闸，逐页签过一遍。

### C2 网页版全屏与证据包导出

- 全屏：浏览器 Fullscreen API 可实现，不必依赖桌面桥接（手册现在写"依赖桌面窗口桥接"，需一并更正）。
- 证据包导出：网页版改为"生成可打印页 → 浏览器打印为 PDF"，不承诺与桌面 PDF 逐像素一致。

**判据**：Chrome / Edge / Safari 各一次真机；全屏进出后编辑器选择区不丢；导出件含章节、证据、时间戳。

### C3 本地模型的端边界说明

网页版在 https 下访问 `http://localhost` 的本机模型会被浏览器混合内容策略阻断，属平台限制而非缺陷。**做法**：不改代码去绕，改为在模型设置页与手册里写清楚"为什么不能"，并保留配置不删。

**判据**：文案与实际行为一致；不再出现"能选但不能用"的灰按钮而无解释。

### C4 能力差异文案统一

老板键、全屏、PDF、本地模型四项在三端能力不同。**做法**：建一份"能力矩阵"单一真源，界面提示与手册都从它取，避免各处口径不一。

## 9. 产品口径（**已定案，2026-10-31，按建议默认值执行**）

| 项 | 定案 | 说明 |

## 10. 版本切分（**已定案：A + B 归 3.3.3，C 归 3.3.4**）

| 版本 | 范围 | 交付后的对外说法 |
|---|---|---|
| **3.3.3（本版）** | A 把长篇写稳 + B 收尾与补洼地 | 「写到 100 章还有人替你盯：查重复注水、查剧情空转；云端能一键更新本机」 |
| **3.3.4（下一版）** | C 跨端可用（§5 底稿） | 「手机上也能写完一章：窄屏不挤、能全屏、能导出」 |

切分理由：A/B 改的是**内容与数据**，C 改的是**布局**。混在一版同时出问题时，无法判断是数据路径还是渲染布局引起——3.3.2 已经吃过「改了没生效、不知道是哪层」的亏。

两版共同的硬前提：**P0 校准 + P1 收尾先做**，B2 的注释治理是后续所有工作的地基。

3.3.4 开工前需另立规划，把 §5 的 C1–C4 展开为批次与验收矩阵；本规划不作为 3.3.4 的验收依据。
