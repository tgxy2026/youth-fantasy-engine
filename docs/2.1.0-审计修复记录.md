## 2 · 第 1 批 · 数据安全

### 2.1 🔴 P0　桌面版"读不到数据文件"被当成空库 → 覆盖真实数据

| 层 | 改动 |
|---|---|
| `electron/main.cjs` | `readDataFileSync()` 改为返回**三态**：读到内容 / `missing:true`（首次使用，正常）/ `读失败 + error`。`store:load` 透传 `missing` 与真实 `error`（此前恒为 `null`，导致渲染层两条分支都进不去）。 |
| `src/lib/desktop.ts` | 新增 `writeLocked` / `writeLockReason`：读取失败、JSON 损坏、文件为空三种情况**一律锁写盘**；`flushDesktop` / `flushDesktopSync` 锁定期直接返回；新增 `unlockDesktopWrite()`（带破坏性说明）。 |
| `src/components/DesktopWriteLockBanner.tsx` | **新增**：常驻红色告警条，说明"原文件未被改动 + 已暂停保存"，给出三条自救路径（打开数据文件夹 / 重试读取 / 仍用当前内容继续，后者二次确认）。 |
| `src/App.tsx` | 三个分支（启动空屏 / 项目管理页 / 主界面）都挂上横幅；**锁定时不再自动播种示范项目**（避免制造"好像有数据"的假象）。 |

> 关键点：原代码在 `desktop.ts` 注释里承诺「原文件不会被覆盖」，但没有任何代码实现该承诺 —— 现在"锁"是真的锁。

### 2.2 P1　关窗同步写盘失败被吞

`src/lib/desktop.ts`：`flushDesktopSync()` 现在检查 `saveSync` 的返回值。主进程写失败时返回 `{ok:false}` 而**不抛异常**，旧实现不查返回值也照样把 `dirty` 清掉 → 等于静默丢掉最后一次编辑。现在失败即保留 `dirty` 并写入 `lastError`。

### 2.3 P1　恢复备份"先清空、再写回"

`src/lib/db.ts` `applyBundleToProject()`：顺序改为 **① 收集现有键 → ② 写入备份数据 → ③ 写入全部成功后才删除旧记录 → ④ 更新项目元数据**。

⚠️ 配套细节：以 key 为标识的存储（`formData` / `settingsKV` / `dailyStats`）新旧键**可能同名**，删除时必须排除本次刚写入的那些，否则会把新数据一起删掉 —— 已加过滤。

### 2.4 P1　启动流程无异常兜底

`src/App.tsx`：启动 IIFE 包上 `try/catch/finally`，**保证 `setBooted(true)` 必定执行**；失败时渲染可读的错误页（原因 + 重新加载 + 备份指引），不再永远黑屏。

## 3 · 第 2 批 · AI 手感

### 3.1 P1　变量行未剥离 + 「无变化」被误报

`src/lib/tavern/engine.ts`：判据从"有没有实际变化"改为 **`parsed.text !== reply`（解析器有没有把那一行剥掉）**。

- `〔数值〕无变化` 是协议允许的写法 → 认得出、剥掉、**不报错**；
- 解出操作但夹取后无变化 → 同样剥掉；
- 真正认不出（正文一字未动）才提示作者。

### 3.2 P1　记忆栏标题用子串匹配

`src/lib/tavern/memory.ts` `matchSectionTitle()`：改为**归一化 + 行首整词匹配**。归一化按「先剥包裹符号、后剥序号」的顺序（模型常写 `〖一、长期摘要〗`）；标题后必须紧跟分隔符或行尾 —— 这样"关系状态从疏远转向缓和"这类**正文**不会再被当成栏标题。

> ⚠️ 尾部**不做**无条件剥离，否则会把内容自带的「（他说的）」右括号削掉。

### 3.3 P1　总结用的角色背景缺栏

`src/components/TavernFree.tsx`：`charContext` 从"世界/内核/做不到/知识边界"四个字段改为 **`renderFreeCharacter(c)` 四章全文**（与冷启动同源）。总结提示词要求"以〖角色背景〗为事实基准"判断关系，而关系就写在 2.4 —— 旧实现等于让模型在不知道对方是谁的前提下重写「关系状态」。

### 3.4 P1　总结/审校/起草不跟随面板默认模型

`src/lib/tavern/provider.ts`：`resolveTavernProvider()` 在未显式传第二参时，**自己读控制面板的默认模型**兜底。

> 一处改动，10 个调用点同时受益（summarize / daily / world / script / revise / draft / import / interview / report）。此前只有"对话轮次"两处传了它，"留空 = 跟随默认模型"这句承诺在其它功能上根本不成立。
> 依赖方向已核验：`provider → settings → {db, prompt, protocol, postRules, budget}`，**不成环**（依赖图复查确认无新增循环）。

### 3.5 P2　星号动作套出双层括号

`src/lib/tavern/postRules.ts`：`pr-star-action` 改成分支匹配 ——

```
pattern:     \*(?:（([^*\n]*?)）|([^*\n]+?))\*
replacement: （$1$2）
```

星号里已经是 `（括号）`（被上一条规则从半角转过来、或模型本来就写全角）时**只去掉星号**，不再套第二层。
配套：新增 `LEGACY_DEFAULT_POST_RULES`，`settings.ts` 的 `upgradeLegacyDefaults` 用**关键字段全等**判断"作者没动过"才升级（改过顺序/开关/正则的一律不碰）。

## 5 · 复核后判定「不改」的项（附理由）

审计扫描出的问题里，有几条**经复核不适合直接改**，列出来避免下次重复提案：

| 项 | 不改的理由 |
|---|---|
| `Modal.tsx` 的 × / `NovelEditor.tsx` 上一章·下一章 | **纯图标键静止态无框是本项目的既有约定**（审计时已确认「透明边框」类断言只应针对有文字的按钮）。我曾误改后已回退。 |
| 4 处 `fixed bottom-6 right-6` 保存悬浮球 | 对"高频保存"有实际可用性价值；且零散改 4 处样式的视觉风险大于收益。建议将来**抽一个共享的页面级 FAB 组件**统一处理，而非逐处改。 |
| `desktopCloudSync` 的 4 个孤儿导出、`db.getAllReports` | 无引用，但疑似**预留 API**（同步模块的对外接口）。删除的收益（少几行）小于风险（万一有动态调用/将来要用）。 |
| `seedCards` 示例块里的 markdown 加粗 | 与协议"不得使用 markdown"确实冲突，但改动会牵动**示范卡升级锚点**（`LEGACY_SEED_EXAMPLES`），建议随下次示范卡版本一起处理。 |
| 剧情模式会话记忆（幽灵功能） | 属 **A/B 设计决策**（补实现 / 摘干净），等老大拍板，不擅自决定。 |
| `addDailyWords` 读改写竞态 | 并发保存多章时码字统计会互相覆盖（**统计偏小，不丢正文**）。要修得在 store 层加增量接口，属结构性改动，建议单独立项。 |
| 便携版 flush 边缘丢最后一次编辑 | 概率低（需"正在写盘"与"立刻卸载"同时发生），且改动牵动 FSA 的 flush 语义（swap），风险大于收益 —— 建议先观察，等有实际反馈再动。 |

## 6 · 修复过程中被测试拦下的两处（值得记下）

1. **`tavernMemory` 回归**：我把标题匹配改成行首命中后，`〖一、长期摘要〗` 这种"包裹在序号外面"的写法认不出了 → 六栏全解析失败。
   根因：归一化顺序应是**先剥包裹、再剥序号**；且尾部不能无条件剥离。
2. **`tavernPrompt` 回归**：我曾把 `historyBudget()` 的 `memory` 形参改成"忽略值"，测试立刻报错。
   复核后确认：**那个形参是有意设计**（语义＝未含在 `system` 里的记忆），不是遗留垃圾 → 已回滚为原行为，只把"别再扣两遍"的警告写死进注释。

> 教训：`replace_all` 之前必须确认**每一处都符合同一前提** —— `subtitleCol` 那次我顺手把「灵感素材」表也改了，而它的列名**本来就叫「类型」**（不在改名迁移范围内），已单独回退。
> 另一条：本项目**同时存在 CRLF 与 LF 两套换行符**（`App.tsx` 是 CRLF、`db.ts` 是 LF），跨行锚点必须先探测文件自身的 EOL。
