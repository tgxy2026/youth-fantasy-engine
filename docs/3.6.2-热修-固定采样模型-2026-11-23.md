# 3.6.2 网页版热修：固定采样模型（Kimi 等）400（2026-11-23）

> 触发：用户反馈「接 Kimi 一直报 400，invalid temperature 要求为 1，是不是网页版的问题」。
> 结论：**不是网页版的问题**；桌面版同一份代码同一结果。已在网页版修复并上线（版本号仍 3.6.2，
> 桌面/便携等 3.6.3 一起发）。

---

## 1. 现象

```
400 invalid temperature: only 1 is allowed for this model
```

任何 AI 功能（续写、取名、校对、拆书…）全挂。

## 2. 根因（两层，第一层让第二层失去兜底）

**① 默认温度就不是 1，而这些模型把采样参数钉死**

Kimi 的 `kimi-k2.*` / `kimi-k3` 是推理模型：Moonshot 把 temperature / top_p / 惩罚项
固定成定值，官方口径是**不要传**（不传 → 服务端默认 → 200）。而本项目：

| 场景 | 实际下发 |
| --- | --- |
| 文字创作（默认「标准」档） | 0.85 |
| 「稳」/「活」档 | 0.7 / 1.0 |
| 结构化 JSON 任务（校对/审读/拆书/抽取） | **0.3（固定，不受档位影响）** |

同类还有 OpenAI `o1/o3/o4`、`gpt-5`、DeepSeek `deepseek-r1` / `deepseek-reasoner`。

**② 400 降级判据把"温度不对"误判成"模型名写错"**

代码本来有 `full → noToggle → bare（撤温度）` 的降级链，但第一步 `shouldDegradeOn400`
用单词 `model` 判硬失败。用 Kimi 原话实测：

```
文案：「invalid temperature: only 1 is allowed for this model」
shouldDegradeOn400          = false   ← 判"配置错了，别重试"
shouldDegradeSamplingOn400  = true    ← 本该走这条
```

`shouldDegradeSamplingOn400` 是 3.4.2 为同一类问题加的，但只接到了 Anthropic / Gemini /
Responses 三家协议上，**OpenAI 兼容通道漏了**。于是降级一次都没跑，用户直接看到原始 400。

## 3. 修复

**A · 固定采样模型一律不下发采样参数（首次请求即生效）**

`src/lib/aiCore/protocols/shared.ts` 新增 `FIXED_SAMPLING_RE` / `usesFixedSampling()`：

```js
/(^|[/_\-. ])(kimi-k2(?!-instruct)|kimi-k3|kimi-for-coding|o1|o3|o4|gpt-5|deepseek-r1|deepseek-reasoner)(?=$|[-_. ])/i
```

- `openaiChat.ts`：命中时 `flags.sampling = false` —— **不发** temperature / top_p / 惩罚项。
- 为什么是"不发"而不是"改成 1"：不同服务商对"必须显式 1"与"必须不传"口径不一致，
  只有"不发"两边都成立（Moonshot 官方文档也这么建议）。
- 🔴 **`kimi-k2-instruct` 显式排除**：它同属 K2 家族但接受任意温度（官方推荐 0.6、不强制）。
  上游就有实现按 `kimi-k2*` 前缀一刀切、把 instruct 系温度也钳死的教训，这里留了回归断言。

**B · 收紧 400 硬失败判据（兜住没识别到的模型）**

`HARD_CONFIG_FAIL_RE` 里 `model` 改成只认"模型确实不存在"的说法
（`model … not found` / `no such model` / `unknown model` / `invalid model` / `model name`
/ `does not exist`），并补上 `messages`、`auth`。
另外 `nextOpenAIFlags` 改为：采样被**明确点名**时直接撤采样，不再先白发一次"撤思考开关"。

**C · 界面如实说明**

`TemperatureField` 增加 `model` 参数：命中固定采样模型时显示
「这个模型固定了采样参数（服务端只接受默认值）：上面三档对它不生效，请求也不会发送温度」。
否则作者按了「活」毫无变化，只会以为软件坏了。

## 4. 验证

| 项 | 结果 |
| --- | --- |

| ├ 识别覆盖 | kimi-k2.5/2.6/0905/turbo/thinking、kimi-k3、kimi-for-coding、`moonshotai/` 前缀、o1/o3/o4、gpt-5、deepseek-r1/reasoner |
| ├ 反例 | `kimi-k2-instruct`、`moonshot-v1-*`、`kimi-latest`、`deepseek-chat`、`gpt-4o`、qwen3、claude、gemini、空串 |

| ├ 端到端 C | 表里没有的模型（`some-gateway/kimi-pro`）+ Kimi 风格 400 → 自动降级救回 |
| └ 端到端 D | kimi-k3 的 JSON 低温任务（0.3）同样不带温度 |
| 回归 | `streamProtocol` 26、`structuredOutputWire` 19、`protocolDegrade` 33 全过 |
| 全量 | **512 / 512 passed** |
| 类型 / 风格 | tsc 0、eslint 0 |
| 线上产物 | 主包 `ModelSettingsPanel-Cv3P7Fwy.js` 含新提示文案；`ai-05NtP-9y.js` 含模型规则 |
| 线上页面 | 构建时间 2026-11-23 08:01、关于页 **6/6**、无 pageerror |

> 过程中修掉两处"测试帮我们抓到的真问题"：
> ① 首版把 `model not found` 收紧过头，`model \`fake-404\` not found` 这种带名字的写法匹配不到
>   → `streamProtocol` / `structuredOutputWire` 各红一条（各多打一次请求），已放宽为 `model[^\n]{0,40}not found`；
> ② 首版替换 `shared.ts` 时误删了 `OpenAIFlags` 接口，tsc 立刻报出来，已补回。

## 6. 仍然存在的边界

| 项 | 说明 |
| --- | --- |
| `kimi-latest` 等未列入的旧模型名 | 不硬判，交给 400 降级兜底（会多一次请求，但能通） |
| `deepseek-r1-distill-*` | 被前缀匹配，采样不会下发（该蒸馏版其实支持温度，属保守处理） |
| 桌面 / 便携版 | 本次只发网页版；桌面用户要等 3.6.3 |
| 其它"固定 top_p"的服务商 | 只要 temperature 报错就能被 B 兜住；若只报 top_p，`SAMPLING_REJECTED_RE` 也认 |
