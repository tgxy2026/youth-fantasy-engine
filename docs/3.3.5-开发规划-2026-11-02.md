# 3.3.5 开发规划：作品安全与可信创作

编写日期：2026-11-02（香港时间）  
状态：规划，尚未实施或验收。基线：3.3.4 发布提交 `a1c1478`；开工时重核 HEAD、工作区及源码指纹。前序：[3.3.4 开发规划](3.3.4-开发规划-2026-10-31.md)、[发布说明](归档/3.3/3.3.4-更新说明-发布版.md)。

## 1. 目标与范围

围绕一个结果：作者能知道 AI 使用了什么资料，审阅并决定是否应用结果；作品在中断、冲突和备份恢复时有清楚、可验证的保护。优先利用既有实现，优化提示词与有边界的创作工作流，以评估结果决定是否推广。

| 包 | 交付 | 优先级 |
|---|---|---|
| A 恢复与保存 | 创意连写恢复三态、隔离环境下中断/冲突及失败保护 | P0 |
| B 上下文可控 | 一个正文生成入口的实际发送清单、选择、固定、来源和候选确认 | P0 |
| C 提示词与工作流 | 分层提示词、分步骤生成、可回退及评估驱动优化 | P0 |
| D 备份与进出 | 保存/备份状态准确，隔离还原及现有导出覆盖核验 | P1 |
| E 质量评估 | 中文样本、基线与盲评流程，驱动 C 迭代 | P0 配套 |

用户已明确放弃本版实体手机和平板验证：不安排采购、借用或把真机作为完成门槛；不把模拟结果说成真机通过。第二台物理设备、生产账号、真实付费模型、断电测试及双人评审如不可得，记录为未覆盖，不能靠模拟替代。可用隔离账号、本机双实例、可控端点和故障注入完成可执行部分。本版不创建原生 App，不部署模型，不做全站 AI 工作流重写，不默认引入多智能体、向量数据库或全自动写书。

## 4. A：恢复、保存与冲突

**A1 连写恢复**：以隔离示例项目与受控假模型使章节真正落库，在章节成功落库与检查点写入的不同位置注入失败或终止受控进程；保留步骤与回读证据。覆盖：不改正文可继续；改已记录正文阻止并说明；删除已记录章阻止并说明；读取失败、无效/旧断点、章数或目标变化均不误继续。续跑前再次核对原项目、章节和证据，旧回执不能写入新项目。校验后到写入前若数据变化，需再次拒绝或采用现有可靠串行机制。

**A2 事务策略**：先测三个存储后端现有语义和最坏窗口。若不能用现有机制证明章节与检查点原子提交，继续明确提示可能重写最后一章，禁止宣传 exactly-once；不能承诺未证实的绝不漏写或绝不覆盖。若发现丢稿风险，优先修复并按实际需要评估事务接口与迁移，独立设计和回归，不以本规划预先认定所有后端可实现原子性。

**A3 同步冲突**：在受控本地服务和隔离账号、双标签/双实例可实现的范围，测确认期间本地编辑、远端版本推进、读写/备份失败、取消及重试；确保旧请求不得静默覆盖新稿，冲突保留可恢复副本或草稿并给可理解选择。桌面共享目录并发若环境支持则单独验证；记录后端和范围，不称为物理跨设备验收。

验收：三态及失败路径有真实数据回读，所测后端及窗口均标明；模拟强杀不等同断电。发现恢复可能丢失已确认数据为阻断，未完成的架构或外部证据须如实列出。

## 5. B：让作者控制实际发送资料

**首条纵切链路**：P0 盘点后选择现有正文生成/续写中具备候选审阅的一条入口，在基线中固定入口和调用链；本版至少完成这一条端到端，不承诺所有 AI 功能同步接入。复用本章资料、上下文装配和候选机制。

1. 发送前列出本次任务、当前章节及可定位的资料来源；按实际装配结果标识完整、截取、未带入及原因。展示字符预算或明确估算，不能把字符数当准确 token 或价格。
2. 作者可对适用资料勾选、排除或固定；明确本次生效范围与是否持久化。固定资料超过预算时不静默裁掉：提示超限并让用户调整或取消，不绕开模型上限。必需系统指令不可被资料选择绕过。
3. 预览与发送使用同一份冻结快照：包括项目/章节、资料内容及版本、提示词版本和装配结果。资料、章节或作者选择变化时提示重新生成预览；不可显示 A 清单却发送 B 内容。无可定位来源时如实标注，失效/删除来源提示并阻止错误跳转。
4. 资料是待处理数据，分隔其内容与系统/任务指令；不能把设定里的指令当更高权限。此措施减少混淆，不声称完全防止提示注入。
5. 结果先作为候选展示，支持拒绝或确认应用；应用前重新核对项目、章节和原文版本，有新编辑则保留草稿并要求重新审阅。任务取消、失败、切项目及迟到回执均不写错作品。

验收：拦截受控端点的实际请求，与 UI 清单逐项比对完整/截取/丢弃；覆盖空资料、超预算、固定冲突、来源变化、同名项目、项目切换、迟到结果及取消。用户材料和凭据不写入默认日志；不得为了可追踪默认保存完整正文或密钥。

## 6. C：提示词与创作工作流

**选定场景**：与 B 共用一个正文生成入口，以「本章计划 + 已确认设定 + 邻近正文 → 本章候选」为最小闭环。先保持现有入口和自定义提示词兼容，再针对评估失败项迭代；其他功能仅列后续扩展，不视为本版已优化。

### C1 提示词结构

按优先级组织任务规则、作者明确要求、已确认事实和参考正文；明确章节目标、视角、时间、已知人物状态、边界、输出格式与信息不足时的处理。使用分隔符区分指令和作品资料；冲突先提醒作者或输出待核实项，不擅自改写既定设定。正文生成要求自然中文、遵循指定视角和场景目标，避免将检查清单直接写进正文；不以固定措辞或模仿特定在世作者代替质量。

保留已有提示词稳定 ID 和用户覆写；升级不覆盖自定义内容。新增变量需有兼容默认值、变量校验和清晰缺失提示；旧覆写缺新变量时仍安全运行或明确提示，不静默丢失。提供恢复默认和版本可识别的对照；不上传或泄露用户自定义提示词。

### C2 有界工作流

默认流程：收集资料与预算 → 作者核对 → 单次生成候选 → 作者审阅/应用。必要时提供**可选**计划/一致性检查，检查输出只是建议，须带可追溯依据或标注无依据；用户可跳过，不能自动改设定。每一步明确输入、输出、取消和失败恢复，解析失败保留可读原结果且不写入正文。模型支持结构化输出时按能力选择并做本地校验；不支持时使用受控文本及解析降级，禁止把有效 JSON 等同事实正确。

记录请求次数、耗时、可得的用量及失败类型；不额外记录正文/密钥。限制自动重试：同一失败步骤最多一次可配置重试，取消后不再重试，副作用写入不得因重试重复执行。模型调用属于外部服务，界面明确本次发送范围；无真实端点条件时仅验证链路，不宣称质量提升。

## 7. E：以评估驱动优化

- 建立经授权或自行构造的中文评估集，覆盖至少 12 个场景，含不同题材、短/长设定、人物关系、时间顺序、伏笔、冲突设定、信息不足与注入式资料；按作品分开开发集与保留集，保留集至少 4 项，不用于调提示词。记录样本许可与脱敏方式，不使用真实书库。
- 先冻结 3.3.4 的入口、默认提示词、模型参数和上下文基线；逐轮只记录关键变化，在同一模型、参数、样本及预算下成对比较。留存提示词版本、匿名样本 ID、调用次数、用量、延迟、失败和候选结果；不以模拟结果代表真实模型质量。
- 人工评审量表：设定遵循、人物/视角一致、情节衔接、语言可读性、任务完成度各 1–5 分；单列严重矛盾、虚构既定事实、人工修改量和是否可用。两位评审独立盲评、打乱 A/B 顺序并记录分歧；严重问题须附作品内依据。评估结果包括各项分布、分歧和成本，样本少时不推断普遍提升。
- 候选默认方案入选条件：保留集无新增未解释的严重矛盾，整体可用性相对基线不下降，且至少一项预先指定的弱项改善；如样本不足以判断，保留旧默认并继续优化。阈值为项目决策规则而非统计显著性结论。仅有一位评审或无真实模型时标记探索性/待评估，不能标记双人盲评或质量达标。

## 8. D：备份、还原与作品进出

1. 盘点桌面、便携、网页账号/游客的保存、自动备份、手动备份、导出及还原的实际范围和限制；将“上次成功保存”和“上次成功备份”分开，仅在对应操作成功且必要持久化确认后显示时间。失败、未启用、未知及进行中需明确区分；不以计划时间伪装成功。
2. 使用隔离样本覆盖正文、章节结构、设定、图片及适用元数据；逐一说明备份与导出的包含/不包含项。采用现有格式与导入路径，除非盘点发现必要缺口，不擅自引入新格式。导入前校验格式、版本和大小，预览影响；覆盖前取得明确确认并提供可恢复备份。损坏、不兼容、空间不足和中途失败不能破坏已有作品或假报成功。
3. 在干净隔离环境执行备份→恢复→重开逐项比较；导出则按其宣称范围读取或导入验证，不把正文导出称作完整备份。保留目录、版本和差异结果；不接触真实作品。

## 9. 实施顺序与依赖

- **P0 基线**：核对 3.3.4 当前源码、现有入口和后端、恢复窗口、提示词覆写与导出矩阵；冻结评估样本及现状结果。交付可复现的基线及待确认清单。
- **P1 安全底座**：A1–A3 与 D 的高风险失败保护，先完成受控回读和故障复现，再修复；决定是否需要更大事务改造。
- **P2 创作纵切**：B 的实际发送清单及候选保护，接 C 的默认单次工作流。先贯通、再加可选检查，不把所有入口同时改造。
- **P3 优化与还原**：按 E 的开发集迭代 C，完成 D 的备份还原与导出覆盖；冻结方案后评估保留集。
- **P4 集成验收**：当前源码指纹下运行项目类型检查、lint、完整测试、构建和适用审计；补跑受影响的浏览器/后端链路及恢复矩阵。源码变化后按影响重新验证，不沿用旧指纹作为最终证据。

每包列实际证据、版本/环境、通过、失败、未覆盖；未运行的不填通过。过程中如需引入新的模型调用费用、实际账号、安装或发布，按当时授权边界处理。已发布版的回归优先于扩展新能力。

## 10. 验收与发布判定

## 11. 2026-11-02 源码复核与修订

本节对上文有冲突的表述具有优先效力。以下是源码静态复核结果，尚未进行本版运行验收。

### 11.1 现有能力与兼容纠正

- `ChapterContextPanel.tsx` 已明确提示：本章固定资料只方便查看，不会自动加入 AI 请求。新方案必须保持旧固定的默认语义；可将其显示为待选，由作者明确选择发送，不得升级后自动发送。发送选项须说明本次或持续生效范围。
- `requestBudget.ts` 已有按实际模型窗口的请求预算、输入输出预留、估算来源和 `MaterialManifest`；`contextAssembler.ts` 已记录完整、裁剪和丢弃。优先复用并接通实际入口，分别展示字符和估算 token，不能把估算当精确计费。`promptGuard.ts` 已有随机边界机制，须核对并复用，不声称可以完全防止提示注入。
- `AIAssist.tsx` 已调用 `buildProjectContext`，可作为 P0 首选调查入口；其候选审阅及写入契约尚需核实。若不满足，选择已有更合适的正文入口并记理由，不假称已经贯通。
- `BackupManager.tsx` 中迁移包导入是新建项目，备份恢复是覆盖当前项目；两种流程分别设计及验收。`db/backups.ts` 中知识库是独立恢复步骤，失败可能不影响主恢复成功，应明确报告部分成功、缺失内容和处理方式。
- 恢复可能重生成内部 ID，比较时以内容、顺序、关联与可访问性为准，不能机械要求 ID 相同。加密迁移包验证正确/错误密码、取消和损坏文件，禁止记录密码。

### 11.2 操作快照和故障边界

生成前按顺序解析实际 provider、能力与模型参数，固定任务、资料和预算，由作者确认后发送。确认后若项目、章节、身份、存储代次、模型路由、参数、提示词、资料或选择变化，预览失效并要求重新确认。重试不得重新取不同内容却沿用旧清单。

清点现有各层重试并统一预算，防止叠加；仅对明确可重试错误生效，鉴权、参数错误和取消不自动重试。超时可能已被服务端处理，可能产生额外费用，须提示结果未知；禁止把超时等同未执行。所有状态区分进行中、成功、失败、取消及结果未知，保存、落盘、云端确认与下载触发各自定义，不能互相冒充。

| 操作 | 验证点 | 判据 |
|---|---|---|
| 连写恢复 | 章写入前、落库后检查点前、检查点后、切项目和恢复前再修改 | 重开回读章节与断点，记录重复、缺失及作者修改；无法确认时保守阻止，不能静默覆盖。强杀和异常注入分开记录。 |
| AI 请求与应用 | 确认后数据变化、发送中取消、流中断、迟到回执、应用前编辑、写入失败 | 实际请求与确认清单一致；过期候选不覆盖新稿，失败保留草稿；应用回执未知先回读核对，不盲目重放。 |
| 恢复与迁移 | 预备份、读取分片、写入中断、独立知识库恢复和重开 | 覆盖前建立并回读验证可恢复备份，失败中止覆盖；对部分恢复如实提示。后端若不能保证失败时可恢复，列阻断而不是仅增加提示。 |
| 云端冲突 | 下载、确认、远端推进、写入失败、断网及响应丢失 | 检验版本前置条件、实际回读与草稿归属；409/428 拒绝不能单独证明有效写入并发完整通过。 |

测试采用隔离项目、目录和账号，受控进程明确记录 PID；强杀只针对本次启动且精确匹配的进程，匹配失败即停止。保留失败证据，不清理用户数据或已有证据；无法安全执行的项目标记未覆盖。

### 11.4 评估决策补充

P0 预先指定保留集主要指标为任务完成度的双人平均评分，严重矛盾单列；开发集至少 8 项、保留集至少 4 项只是最低试验规模，不能据此声称统计显著。保留集仅用于最终比较；若用于调优，作废并重建未接触保留集。独立盲评保留两人原分和分歧，再记录协商结论；报告逐题差值、均值和范围。固定实际模型版本、参数、提示词、资料、预算和时间；在可行时每题每版至少重复两次，无法固定随机性时说明。无真实模型基线不得宣称质量改善；可完成设计和假模型流程验证，但默认替换上线与否须明确决策。
