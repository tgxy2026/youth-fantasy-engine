## 二、方案 B：接着已有内容写时，往下**续排细纲**

### 解决的缺口

上一轮核查发现：续写 9 章时**章节台账会自动跟上**，但**《章节细纲》卡不会新增** ——
第 22 章起 `outlineFor` 返回空，连写静默退化成"自由发挥"，而界面不告诉你这件事。

### 做法（与「从零创作」的分工）

新增 `aiExtendOutline`（`lib/aiTasks.ts`）：

| | 从零创作 | 接着写（本次新增） |
|---|---|---|
| 任务 | `aiGenerateOutline` | **`aiExtendOutline`** |
| 输入 | 设定摘要 | 已有细纲尾部（最后 6 章）+ 正文进度 + 设定/总纲资料 |
| 产出 | 卷 + 全部章 | **第 fromNo 起的 N 章**（卷只在跨卷时给 `newVolume`） |
| 落库 | `commitOutline` | **同一个 `commitOutline`**（按同名卡跳过，已有章不会被重排/覆盖） |

**🔴 续排起点看「正文写到哪」，不是「细纲最大章号」** —— 要写的是**正文的下一章**；
细纲可能已经被作者排到更远（那是他自己排的），按细纲最大号起排会越排越远。
另外：**下一章已有细纲时直接跳过**（`outlines.has(fromNo)`），并如实说明"第 N 章起已有细纲，无需续排"。

### 入口：产出目标

「接着已有内容写」现在也有「这一次要产出什么」：

- **只做大纲规划** → 按已有细纲往下续排 N 章，**不写正文**（这一档不跑设定抽取 —— 没有新正文可抽）
- **大纲 + 正文** → 先续排细纲再连写（每章照常走设定抽取 / 补登 / 更新）
- 外加一个开关 **「先续排细纲：已开启 / 已关闭」**（仅「大纲 + 正文」时显示）——
  作者自己已把细纲排好时，关掉即可按已有细纲直接写（＝原行为）

阶段表相应拆成两张：`CONTINUE_STAGES`（只有连写）与 `CONTINUE_OUTLINE_STAGES`（续排细纲 → 连写）。

## 三、整章改写：**动作 × 章位置** 双重分治

### 为什么要分

改**历史章**的风险不是文字质量，而是**污染设定**：旧章里的境界 / 身份 / 关系一改，
后面已经写好的正文与设定表就全对不上了 —— 而且是静默对不上（没有任何报错）。

### 只看"是不是最新章"不够（同日第二轮修正）

四个动作对设定的影响完全不同，只按章位置分治会漏掉两种真实风险：

| 动作 | 会不会动设定 | 历史章要防什么 |
|---|---|---|
| 润色 | 不会（不增删情节与信息） | 防"顺手把泛指写成专指"（「一位老者」→「青云宗长老」） |
| 扩写 | **会** —— 补细节时容易把描写升级成设定 | 🔴 凭空造设定：「一柄剑」→「师父所赠的断岳剑」—— 设定表里没有、后文也不知道 |
| 精简 | **会** —— 删句子时可能删掉设定交代 | 🔴 丢信息：「得自青云宗的储物戒」→「储物戒」—— 来历删掉后文就断了 |
| 改写 | 会 | 改叙述方式时连带改了设定类内容 |

反过来，「最新章」也不能无差别放开：润色本来就不增删情节，却被 `LATEST_RULE` 授权
"可重排场景 / 可改写局部走向"，是**越权授权** —— 与动作规则打架时，模型会挑宽松的那条。

于是纪律从"按章分"升级为「**动作 × 章位置**」矩阵（两条 RULE 各登记进「模型设置 → AI 提示词」，可自行修改）：

| | 历史章（`CHAPTER_REWRITE_HISTORY_RULE`） | 最新章（`CHAPTER_REWRITE_LATEST_RULE`） |
|---|---|---|
| 通用红线 | 设定类内容一律冻结：不改身份 / 关系 / 境界 / 实力 / 品级、势力与地点归属、物品来龙去脉、术语用法；不改事件因果结果、不新增事件、不埋伏笔；不借台词透露新信息 | 与前文设定不冲突；保留原文的章末钩子 |
| 润色 | 只换字不换事（不许把泛指写成专指） | **同样只换字不换事** —— 不因是最新章就放开走向 |
| 扩写 | **描写层可加、信息层不可加** | 细节与设定信息都可补 |
| 精简 | 只删冗余与注水过渡；**承载设定交代的句子一律保留** | 同上 |
| 改写 | 只改叙述方式与文字 | 四种动作里**只有这一档**可放开手脚 |
| 落库后 | **不跑**设定同步（它不产生新设定） | **必跑**一轮设定同步 |

判定章位置的方式不变：候选列表按真实叙事顺序排，**最后一个就是最新章**（`idx === cands.length - 1`）。

### 最新章落库后的设定同步

复用连写那套 `extractAndCommitSettings`（本轮从 `autoContinue.ts` 导出）：
抽取本章实体 → 按 `strategy` 处理（`add-only` 只新增 / `auto-update` 新增 + 安全写回 / `confirm` 弹候选）。
**`confirm` 在改写场景降级为 `add-only`** —— 它需要弹勾选窗，而改写没有这个交互，
降级成"只新增"比静默什么都不做更符合预期，也不会误改已有设定。

界面上会按**当前动作 + 章位置**给出对应的纪律提示（`RW_SCOPE_NOTE`，与提示词侧同一个矩阵）：
历史章＝琥珀字（其中润色为中性灰，它本来就不动设定）、最新章＝绿字，
不让作者改完旧章才发现对不上。

## 四、选章改为**可搜索的卷章树**

原来是个扁平下拉：章节一多就没法用，也看不出章属于哪一卷。

## 五、创意写作里"设定"该怎么处理（口径）

老大这轮把口径收敛成一句话：**从零创作与接着写是同一套流程，唯一差别是"起点有没有历史信息"**
—— 从零创作的历史为空，所以先跑「设定奠基 + 分卷大纲」把基础设定冷启动出来；
接着写的历史已存在（正文 + 设定表 + 可选细纲），直接进逐章连写。
**「每章抽取设定 → 新增的补登 → 已有的更新」是两种起点共用的一环，不是接着写专属。**

| 组合 | 抽取 / 补登 / 更新设定 |
|---|---|
| 从一句话创作 → 只做大纲规划 | ⬜ 不走连写；设定来自「设定奠基」的草稿（闸门①人审后落库） |
| 从一句话创作 → 大纲 + 正文 | ✅ 每章抽设定 / 新增补登 / 已有更新（**与接着写是同一套实现**） |
| **接着写 → 只做大纲规划**（续排细纲） | ⬜ **不涉及** —— 没有新正文可抽，这一档不跑 |
| **接着写 → 大纲 + 正文** | ✅ 每章抽设定 / 新增补登 / 已有更新（**与从零创作是同一套实现**） |
| 整章改写 → 历史章（任意动作） | ⬜ **不跑** —— 动作层已冻结设定，它不产生新设定 |
| 整章改写 → 最新章 | ✅ 落库后补跑一轮（否则下一次「接着写」会读到旧设定） |

### 途中修掉的一处

`startLabel` 的旧写法只判了起点（`mode === 'continue'` → 「接着写」），**没跟上新增的「接着写 + 只做大纲规划」这一档**
—— 按钮仍显示「接着写」，实机按「开始规划」找不到按钮直接崩。
四格（起点 × 目标）文案现已补齐：从零/接着 × 大纲规划/大纲+正文 → 开始创作 / 开始规划 / 接着写 / 开始排细纲。

### 一处诚实说明

本轮**没有**跑"改完历史章后设定确实没变"的实弹对照（那要点一次真改写、约 3 分钟）。
历史章的冻结是靠**提示词硬约束 + 界面明示**，而"历史章不跑设定抽取"这条路径由单测锁住
（`creativeModes` 里对 `if (r.isLatest)` 的断言）。若需要实弹证明，下轮可补一次对照实验。

## 七、同日第二轮：纪律升级为「动作 × 章位置」+ 异常判定改口径

老大复核后指出两处没对齐：

**① 冻结设定不该只挂在"改写"这一档上。** 润色确实不影响设定，但**扩写与精简同样会**
（老大原话："这个也要注意进行限制了"）—— 扩写容易凭空造设定、精简容易删掉设定交代。
已把 `src/lib/aiTasks.ts` 的两条 RULE 重写为**按动作分节**的矩阵（见第三节表格）。

**② 异常判定的基准错了。** 原判据是 `text.length < 原文 × 0.35`，对**精简**是结构性误判 ——
原文 3800 字压到目标 1200 字只占原文 31.6%，**必定**触发"结果明显偏短、已锁住替换"，
作者要的就是这个字数，却永远替换不了；反过来**扩写**方向的严重缩水漏判
（原文 2000 / 目标 6000，只返回 1500 ＝原文 75%，不报异常）。

现在基准改为**期望字数**（`chapterRewrite.ts` 新增 `expectedRewriteWords` / `isSuspectRewrite` 两个纯函数）：

| 动作 | 期望字数 | 判定 |
|---|---|---|
| 润色 | 原文长度 | 低于 60% 期望或高于 3 倍期望 → 锁住替换 |
| 扩写 / 精简 / 改写 | 面板填的目标字数 | 同上 |

原文 ≤600 字的短章不套用该保护（正常波动也会碰线，锁了反而碍事）。

### 顺带对齐的
- 界面与帮助文案统一口径：两起点是同一套流程，唯一差别＝有没有历史信息；「每章设定同步策略」写清固定三步（抽取 → 新增补登 → 已有更新）；
- 连写设置的折叠状态两起点一致（原先从零创作默认收起，强化了"这是接着写专属"的错觉）；策略说明补上每章固定三步；
- 改写纪律提示条改为按「动作 × 章位置」输出（历史章＝琥珀字、其中润色为中性灰；最新章＝绿字）；
- `aiDataSources.ts` 的 `chapter-rewrite` / `creative-writing` 说明同步，`schema.ts` 的页签说明同步；
- `tests/chapterRewrite.test.ts` 的异常保护断言由**镜像公式**改为**直接调真实函数**（镜像会随实现悄悄漂移），
  补上"精简不误判 / 扩写缩水要判 / 精简越改越长要判"三个对照用例，另加 ⑨ 节锁住「动作 × 章位置」矩阵不被回退。
