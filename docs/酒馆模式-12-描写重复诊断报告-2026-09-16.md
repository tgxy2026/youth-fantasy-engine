# 酒馆模式 · #12 描写高度重复 —— 根因诊断报告

> 对应清单条目：`docs/酒馆模式-优化清单-2026-09-16.md` **#12**（动作描写高度重复，如「指节因过度用力而泛白」高频）
> 老大原话要求：**「核实问题产生的原因，到底是我们系统参数设置的重复惩罚不够，还是因为角色卡设置的问题，导致那一段话反复出现」**
> 诊断日期：2026-09-16　|　状态：**根因已定位（静态核实完成）**，调优方案待老大拍板

---

## 一、结论先说（一句话版）

**不是「重复惩罚不够」，也不是「角色卡把指节锚成了标志动作」。**

真正的因果是三层叠加：

| 层 | 判定 | 一句话 |
|---|---|---|
| **① 协议层** | 🔴 **主因（驱动源）** | 协议正文有一条硬指令「用动作、停顿、**身体反应**代替情绪标签」——**命令模型每轮必须交出一个身体反应**，但全文**没有任何一句约束它的多样性**或**限制出现频率** |
| **② 参数层** | ⚠️ **不是强度问题，是射程问题** | 项目下发的 `repeat_penalty = 1.05`，其**射程只有 64 个 token（≈50 个汉字）**。跨轮复读发生在几千 token 之前，**物理上永远不在惩罚范围内** —— 调到 1.5 也没用 |
| **③ 角色卡层** | 🟡 **放大器（非源头）** | dev 卡的动作样本落点**偏向手部**（楚楠卡 14 条动作行里 6 条手部，43%），给模型立了「这个作品的情绪都发生在手上」的 few-shot 榜样 |

而**老大感受到的「重复」，本质是「语义 / 句式模板重复」，不是「字面 token 重复」** ——
这恰恰是 `repeat_penalty` **在数学上就治不了**的那一类（它只看 token id 的重复）。

### 证据 2 · 64 token 射程 —— 这是本次诊断的关键（官方文档 + 源码）

**Ollama 官方文档（Modelfile 参数表）原文：**

> `repeat_last_n` — Sets how far back for the model to look back to prevent repetition.
> **(Default: 64, 0 = disabled, -1 = num_ctx)**

**llama.cpp 采样器实现（`src/llama-sampler.cpp`，经官方源码分析确认）：**

> **Penalties**：Applies repetition, frequency, and presence penalties to discourage token repetition.
> - Repetition Penalty：Multiplies logits of recently used tokens by `penalty_repeat`
> - Frequency Penalty：Subtracts `penalty_freq × count` from logits
> - Presence Penalty：Subtracts `penalty_present` if token appeared before
> **Scope: Last `penalty_last_n` tokens（or -1 for entire context）**

**两个结论：**

1. 🔴 **`repeat_penalty` / `frequency_penalty` / `presence_penalty` 三者共用同一个窗口** ——
   所以项目设的 `presence_penalty: 0.55` **射程同样只有 64 token**，同样够不到上一轮。
2. 🔴 **窗口外的东西「完全不受惩罚」**，权威分析原话：

   > *"Anything that scrolls out of that window **stops being penalised entirely** — which is why a long generation can **loop at a period longer than the window** and the penalty never notices."*

**换算成中文场景：**
```
64 token ≈ 50 个汉字 ≈ 半句话到一句话
```
「指节因为过度用力而泛白」（10 字 ≈ 12–15 token）如果出现在**上一轮回复**里，
它距离当前位置通常已有 **300–800 个 token** —— **它在窗口外。惩罚器根本看不见它。**

> 这解释了为什么老大体感「怎么调都没用」：**不是没拧够，是这个旋钮够不着那个地方。**

### 证据 3 · 为什么「调高 repeat_penalty」是错误方向（三重风险，有明确依据）

**(a) 项目自己的参数手册已经把它定义成危险区**

`src/lib/tavern/paramGuide.ts:86` `GUIDE_REPEAT_PENALTY`：

| 区间 | 档位名 | 手册写的效果 |
|---|---|---|
| 0.5–1 | 鼓励重复 | 低于 1 等于「奖励」重复用词 |
| **1–1.1** | **极轻** | **1 等于不惩罚；1.05 左右只轻微压住复读** ← **✅ 推荐段，项目默认 1.05 正在此段内** |
| 1.1–1.35 | 明显 | 复读显著减少，但模型开始刻意换词（烟 / 香烟 / 烟卷）|
| 1.35–1.7 | **过强** | 连「的、了、他」这类高频虚词都会被回避，**句子变生硬、绕口，甚至不成句** |
| 1.7–2 | **破坏性** | 输出质量断崖式下降 |

→ **出厂值 1.05 完全落在推荐段内，不是「偏低」。** 往上调是直接走进「过强 / 破坏性」两档。

**(b) 机制层面：调高只会伤「句内」的高频词，伤不到「跨轮」的短语**

权威分析指出，`repeat_penalty` 是**乘性惩罚**，作用在窗口内 token 的 logit 上：

> *"It sees token ids... The penalty cannot see structure."*
> *"A penalty of 1.2 costs a token sitting at logit 12 about 2.0 logits, a token at 3 about 0.5... so **the same setting is a mild nudge for a marginal token and a serious demotion for the model's favourite**."*

窗口只有 64 token 时，窗口内重复最多的是**虚词、标点、结构词**。
调高 `repeat_penalty` = 惩罚这些词 = 句子变形。
而老大真正在意的「跨轮短语复读」**依然在窗口外，一分未减**。

**(c) 参数不可跨模型迁移**

> *"It also means **the setting does not transfer between models**, because models differ in the scale of their logits before softmax; 1.15 on one can be as aggressive as 1.3 on another."*

→ 在本机 27B 上调出来的「好值」，换个模型就是另一个效果。**这类调参不可沉淀为产品默认值。**

### 证据 4 · 真正的源头：协议里那条「每轮必须交身体反应」的硬指令

**`src/lib/tavern/protocol.ts:123`（v1.9 现役正文，B7「说人话」段）全文：**

```
B7 说人话：不念设定。情绪激烈时句子变短、变碎、逻辑断裂。
少用形容词，用动作、停顿、身体反应代替情绪标签。      ← 🔴 就是这一条
比喻要从角色自身的生活经验里长出来。
```

**这条指令做了什么：**
- ✅ **强制**每轮必须产出一个「身体反应」来表达情绪
- ❌ **没有**要求动作的多样化
- ❌ **没有**限制同一类动作的出现频率
- ❌ **没有**给「不写肢体动作」留出口

**全文扫描结果 —— 协议里没有任何反重复约束：**

| 搜索项 | `protocol.ts` 命中情况 |
|---|---|
| 「重复」 | 2 处，**但都是**指「不要在状态块里用别的写法重复数值」（:169 / :1127）—— 与描写无关 |
| 「多样」 | **0 处** |
| 「不要复用」 | **0 处** |
| 「换个说法」 | **0 处** |
| 「同一个动作」 | 4 处，但都是旧版协议里的「不要既写进【 】又写进（ ）」—— **格式去重**，不是**内容去重** |

**同时，格式层只限了「数量上限」，管不了多样性：**

```
protocol.ts:151    · 动作与神态：最多 2 行
```

→ 限了「最多两行」，**没限「这两行不许和前几轮重复」**。

**因果链闭环：**

```
协议命令「每轮用身体反应代替情绪标签」
        ↓
模型每轮必须产出一个肢体动作（不能只写停顿、不能只写沉默）
        ↓
它能想到的「克制 / 紧张」类身体反应，在中文语料里最高频的搭配
就是手部（指节泛白、攥拳、掌心出汗、手腕绷紧）
        ↓
repeat_penalty 射程 64 token，看不到上一轮 → 无从阻止
frequency_penalty 从未开启（默认 0）→ 没有词频惩罚
        ↓
上下文里前 9 轮的动作全是手部 → in-context 自我强化
        ↓
老大看到的：每轮都来一次「指节 / 手部紧张」
```

## 三、对老大原问题的直接回答

> **Q：是「系统参数设置的重复惩罚不够」，还是「角色卡设置的问题」？**

**A：都不是。** 精确地说：

| 命题 | 判定 | 依据 |
|---|---|---|
| 「重复惩罚**强度**不够」 | ❌ **错** | 1.05 在手册推荐段内；往上调只伤句内虚词、让句子生硬，**对跨轮复读零作用**（射程 64 token，跨轮在射程外）|
| 「**射程**不够」 | ✅ **对，但它是「帮凶」不是「主犯」** | `repeat_last_n` 从未下发 → 默认 64 → 跨轮复读在物理盲区；且 `frequency_penalty` 从未开启 |
| 「角色卡把指节锚成了标志动作」 | ❌ **证据不足，排除** | 卡里只有 1 处「指节」（敲屏幕，非泛白），**没有那个短语** |
| 「角色卡让动作落点偏手部」 | 🟡 **部分成立（放大器）** | 楚楠卡手部占 43%；苏念卡把「紧张」唯一绑到手部 |
| **「协议强制每轮交身体反应」** | 🔴 **主因（驱动源）** | `protocol.ts:123` 硬指令 + 全文无任何多样性约束 |

**一句话**：**模型不是「复读」，它是在「认真完成协议布置的作业」——
作业要求「每轮必须用身体反应表达情绪」，但没告诉它「同一个反应不许用第二次」。**

## 四、调优建议（按优先级，P1 零风险直击主因）

### 🥇 P1 · 改协议（零参数风险，直击主因）——**首推**

**落点**：`src/lib/tavern/protocol.ts` v1.9 正文（改完走 v1.10 协议升级：正文版号 + `PROTOCOL_VERSION` + v1.9 全文补进 `LEGACY_PROTOCOLS` + 两处断言）

**改法 A（推荐，改 B7 那条指令本身）**：
```
现：少用形容词，用动作、停顿、身体反应代替情绪标签。
改：少用形容词。表达情绪可以用**很多种**方式 —— 一句停顿、句子突然变短、
    答非所问、话说一半改口、把动作做一半停住、直接说反话……
    **不要每轮都靠肢体动作**；一天里手部动作（攥、捏、抠、指节）尤其容易写腻，
    连续几轮内用过一次就换一处，或者干脆这一轮不写手。
```

**改法 B（在 O4「结尾留钩子」附近加一条独立的元规则）**：
```
O5 不许复读自己：同一个身体反应、同一类小动作（手、眼神、呼吸、喉结），
   不许在连续三个回合里重复出现。上一轮写过了，这一轮就换落点，或者用别的办法写。
```

**为什么首推它**：
- 🔴 它治的是**语义层**的重复——而语义重复是 `repeat_penalty` 数学上就碰不到的（它只看 token id）
- ✅ 零副作用，不动任何采样参数（不会连带伤及句子质量）
- ✅ 与既有红线同源：本来就该在协议输出规范里定（清单 #12 也写了「与 #7 第三人称描写规范同源，可一并纳入」）

**验证成本**：改完跑 `tests/tavernPrompt.test.ts` + `tavernSettings.test.ts`（版本断言）+ 1 次实机对话。
**⚠️ 注意**：改协议必须走「三处同步 + 两处断言」，且 `protocol.ts` 一个文件里躺着 8 份历史协议全文，`Edit` 会撞重复锚点 —— 用脚本「只在 `PROTOCOL_CORE` 段内替换」。

### 🥈 P2 · 参数层：**换旋钮，不是拧大**

**核心动作：把 `repeat_last_n` 纳入下发，并新增 `frequency_penalty`；`repeat_penalty` 保持 1.05 不动。**

| 参数 | 现状 | 建议 | 理由 |
|---|---|---|---|
| `repeat_penalty` | 1.05 | **保持不动** | 已在手册推荐段内；往上调进「过强」档，伤虚词 |
| **`repeat_last_n`** | ❌ 未下发（默认 **64**）| **下发 512** | 唯一能碰到「跨轮复读」的旋钮。512 token ≈ 400 汉字 ≈ 最近两三回合 |
| **`frequency_penalty`** | ❌ 未下发（默认 **0**）| **试行 0.1–0.3** | 专门治「某词反复出现」，按出现次数线性惩罚，比 `repeat_penalty` 更适合本症状 |
| `presence_penalty` | 0.55 | **建议下调至 0.3 或 0** | 它的语义是「出现过就扣分」→ 逼模型**换词**。但**换词 ≠ 换动作**：不能用「指节」就换「掌心 / 手腕 / 攥紧」——**语义簇没变，字面变了**。它可能正在**帮忙制造「换个说法继续写手」的观感** |

**⚠️ 窗口不是越大越好**（权威分析明确警告）：
> *"Setting it very large is not free either... a wide window means more of the vocabulary is under penalty at once, which **flattens the distribution generally** rather than discouraging anything in particular."*

→ 建议 **512**，不要直接上 `-1`（=全上下文）。`-1` 会让整个词表都被压，输出普遍变呆。

**配套改动**（若采纳）：
1. `src/lib/tavern/params.ts` → `toOllamaOptions()` 加 `repeat_last_n`、`frequency_penalty`
2. `src/lib/tavern/types.ts` → `TavernParams` + `TAVERN_DEFAULTS` + `ResolvedParams` 加字段
3. `src/lib/tavern/paramGuide.ts` → **新增 `GUIDE_REPEAT_LAST_N`**（目前该文件里**没有这个参数的档位定义**，`GUIDE_SAMPLING` 只有 repeatPenalty / presencePenalty 两项）
4. `src/components/TavernControl.tsx` → 控制面板加输入框（剧情 / 自由两处）
5. `src/lib/tavern/settings.ts` → `DEFAULT_TAVERN_SETTINGS` + `upgradeLegacyDefaults`
6. ⚠️ **两模式默认值都要给**，且值必须落在新 `GUIDE_REPEAT_LAST_N` 的推荐段内（有测试闸）

**预期效果（要老实说）**：调参能减轻**字面**复读，但**治不了「每轮一个手部动作」的语义重复** —— 因为模型换词就绕过了 token 惩罚。**所以 P2 是 P1 的补充，不是替代。**

清单 #12 原文要求：「**无论何种根因，建议先做一次对照实验**：固定对话内容，分别只动参数 / 只改卡，对比「指节泛白」出现频次再下结论」。

### 实验设计

**控制变量**
- 载体：本机 `orcarouter/Qwen3.8-27B-Uncensored:q6_K`（Ollama 0.34.1）
- 固定 `seed`（保证可复现，避免采样噪声误判）
- 固定 `temperature 0.95 / top_p 0.92 / top_k 60 / num_ctx 32768`
- 固定同一段对话历史（**建议 6 轮，且刻意让前 4 轮各出现一次手部动作** —— 制造 in-context 强化，复现真实场景）
- 固定 system（用真实的 `buildFreeSystem` 产物）

**四组对照**

| 组 | 变量 | 期望验证 |
|---|---|---|
| **A · 基线** | 当前出厂参数（`repeat_penalty 1.05`，无 `repeat_last_n`）| 复现「指节 / 手部」高频 |
| **B · 只动参数（拧大）** | `repeat_penalty 1.05 → 1.4` | 🔴 **预期「无改善」**——用来证伪「惩罚不够」这个假设 |

| **D · 只动提示词** | A 的参数 + 协议加 O5 反重复约束（P1 改法） | 检验主因假设 |

**判定指标**
- 主指标：`手部动作行数 ÷ 动作行总数`（每组跑 5 次取均值）
- 副指标：`指节`/`攥`/`捏`/`抠` 等词的**跨轮出现次数**（同一词在第 n 轮和第 n-1 轮都出现 = 1 次复读）
