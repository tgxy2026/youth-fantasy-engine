## 2. 现状：链路已通到什么程度

这是本方案最关键的发现 —— **不需要新造管道**：

```ts
// aiCore/chat.ts · CallOpts
temperature?: number
/**
 * 额外采样参数（键名用**目标接口的原生名字**，值必须是数字）。
 * … openaiChat 只转发白名单内的键，其余丢弃，免得把 Ollama 专有字段发过去被端点拒掉。
 */
extraOptions?: Record<string, number>
```

- **本地**：`ollamaChatRaw` → `options: { temperature, ...(o.extraOptions ?? {}) }` ⇒ 任意 Ollama 原生键都能进
- **云端**：`openaiChat` → `{ temperature, ...openaiSampling(o) }`，
  白名单 `OPENAI_SAFE_SAMPLING = ['top_p', 'presence_penalty', 'frequency_penalty']`
  ⇒ 误传 Ollama 专有键会被**静默丢弃**（安全，不会 400）
- `temperature` 已支持从 provider 读：`opts.temperature ?? (opts.json ? JSON_TASK_TEMPERATURE : (config.temperature ?? DEFAULT_TEMPERATURE))`

🔴 **唯一的缺口**：`chat()` 装配处写的是 `extraOptions: opts.extraOptions` ——
**只从调用方（各 AI 任务）取，不从 provider 取**。所以"在模型配置里填的参数"目前下不去。

## 3. 实现方案（三步，都不动现有链路语义）

### 3.1 数据 · `AIProvider` 加一个字段

```ts
/** 文本生成微调（2.9.2）。键名用语义名（与酒馆一致），下发时按 local/cloud 转原生键。 */
sampling?: {
  topP?: number; topK?: number
  repeatPenalty?: number; repeatLastN?: number
  frequencyPenalty?: number; presencePenalty?: number
}
```

### 3.2 装配 · `chat()` 加一层兜底

```ts
// 与 temperature 同一范式：显式传入优先，否则用 provider 配置
extraOptions: opts.extraOptions ?? samplingOptionsOf(config)
```

`samplingOptionsOf(config)`：
- `config.local === true` ⇒ 转 Ollama 原生键：`top_p / top_k / repeat_penalty / repeat_last_n / frequency_penalty / presence_penalty`
- 否则 ⇒ 只转云端白名单那三个（`top_p / presence_penalty / frequency_penalty`）

> 🔴 **命名陷阱**（酒馆 `params.ts` 已专门标注）：界面叫「重复惩罚」，内部是 `repeatPenalty`，
> 到 Ollama 是 `repeat_penalty` —— **少了 "ition"**。同一个参数两个名字，实现时别弄混。

### 3.3 界面 · 「自定义系统提示词」下方加一个区块

- 6 个参数，**滑块 + 数字输入**（酒馆控制面板已有成熟样式可参照）
- **云端模型下灰显** `topK` / `repeatPenalty` / `repeatLastN` 三项，并注明「仅本地模型生效」
  （与「上下文窗口按模型两态化」同一范式）
- 每个参数配一句人话说明（写什么、调大会怎样）
- 🔴 **留空＝不下发** —— 与「自定义系统提示词留空则不注入」同一哲学，保证**升级后行为一字不变**

## 4. 🔴 要挑选的参数（请主人拍板）

按「对文本效果的实际影响 × 是否两端都认」筛：

| 参数 | 作用 | 本地 | 云端 | 建议 |
|---|---|---|---|---|
| `temperature` 温度 | 发散度 | ✅ | ✅ | **已有**（`AIProvider.temperature`），复用不重复 |
| `topP` 核采样 | 只从累计概率前 P% 的词里选 | ✅ | ✅ | ✅ **搬** |
| `topK` | 只从概率最高的 K 个词里选 | ✅ | ❌ | ✅ **搬**（云端灰显） |
| `repeatPenalty` 重复惩罚 | 压复读 | ✅ | ❌ | ✅ **搬**（云端灰显） |
| `repeatLastN` 重复回看窗口 | 惩罚的回看词元数 | ✅ | ❌ | ✅ **搬**（云端灰显）—— 酒馆实测「不显式给，Ollama 默认只回看 64 词元 ≈ 50 汉字，跨轮复读罚不到」 |
| `frequencyPenalty` 词频惩罚 | 按词频扣分 | ✅ | ✅ | ✅ **搬** |
| `presencePenalty` 新话题倾向 | 已出现的词再提就扣分 | ✅ | ✅ | ✅ **搬**（酒馆实测：这个参数影响明显，且有反直觉现象，值得让作者自己调） |
| `numCtx` 上下文窗口 | 加载多少上下文 | ✅ | ❌ | ❌ **不搬** —— 「模型配置」里**已有**「上下文窗口」字段（且是窗口唯一真源），重复 |
| `contextBudget` | 酒馆的注入预算 | — | — | ❌ **不搬** —— 酒馆专有，与主应用无关 |

⇒ **搬 6 个**：`topP` / `topK` / `repeatPenalty` / `repeatLastN` / `frequencyPenalty` / `presencePenalty`

**默认值建议**（新模型不填时）：**全部留空（不下发）**，只在界面上用灰字提示常见区间
（如温度 0.8–1.0 偏创意、0.3 偏稳定）。理由：一旦给死默认值，等于**悄悄改变所有存量模型的行为**。

---

## 5. 待拍板的三个点

1. **参数集合**：是否就按 §4 的 6 个（可增可减）
2. **默认值**：是否采纳「留空＝不下发」（可可推荐），还是给一套默认值
3. **生效范围**：这些参数**全局生效**（所有走该模型的 AI 功能），
   与「自定义系统提示词」同层 —— 确认一下是否符合预期
   （⚠️ 酒馆模式**不受影响**：它有自己的一套参数与继承链，本次不动它）
