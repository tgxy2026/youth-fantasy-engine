# 2.9.2 控制面板「保存入口」缺失 · 核实与修复（2026-10-09）

> 主人反馈：酒馆模式 → 控制面板 → **「我的档案」录入信息后没有保存按钮，切换其它页签数据直接被清空**。

---

## 1. 核实结论

**不是逻辑 bug，是「漏挂两处既有入口」。** 逐项核实如下：

| 核查项 | 结果 |
|---|---|
| 保存按钮是否存在 | ✅ **存在** —— `TavernControl.tsx` 页头右上角，`disabled={!dirty \|\| saving}`（无改动时是**灰的**，但一直在 DOM 里） |
| 录入后按钮会不会亮 | ✅ **会** —— 录入后 `disabled:false`，且页头出现「**有未保存的改动**」提示 |
| 保存是否真的生效 | ✅ **有效** —— 实测「建 3 份档案 → 填名 → 点保存 → 切页签往返」，界面与 IDB 数据**全都完好** |
| 为什么体感是「没有保存按钮」 | 🔴 本页内容高 **6575px**、滚动容器是 `main`（`overflow-y:auto`）。滚到「二、我的档案」时（`main.scrollTop≈2290`），页头保存按钮的 `top = **-2413**` —— **在视口上方 2413 像素**，完全看不见 |
| 为什么切页签会丢 | 编辑是「内存态 + 手动保存」，**未点保存**就切页签 ⇒ 组件卸载、改动丢失。设计如此，但此前**没有任何可见的保存入口**可点（Ctrl+S 虽可用，作者无从得知） |
| 是否为 2.9.0 引入 | ❌ **不是** —— 2.9.0 对相关文件只有 `4cd0e34` / `8d68b33` 两次「上下文窗口长度」改动，**未碰档案区**；保存链路本身正常 |

---

## 2. 根因：两处既有入口**都漏挂了**

项目里「长页面 + 手动保存」的页签有一套固定写法。**四个同类页都挂了，只有控制面板一样都没挂**：

| 入口 | 范本页 | 控制面板（修复前） |
|---|---|---|
| 页头**吸顶**（`sticky top-0 bg-ink-900/95 backdrop-blur py-3` + `zIndex: Z.pageBase`） | `TableSheet` / `FormSheet` / `OutlineSheet` / `CharacterSheet` | ❌ 漏 |
| 右下角**浮动保存球** `components/SaveFab.tsx` | 同上四个页 | ❌ 漏 |

📌 `SaveFab` 的组件注释里就写着它是「**页面很长时方便**」用的 —— 正是为这个场景而备。

---

## 3. 修复内容

**文件**：`src/components/TavernControl.tsx`（4 处 / +12 −1）

1. `import { Z } from '../lib/zLayer'`
2. `import { SaveFab } from './SaveFab'`
3. header 补齐吸顶那一串 —— 🔴 **不加 `mb-5`**（本页外层是 `space-y-4`，加了会双重间距）
4. 末尾加 `{dirty && <SaveFab onClick={() => void save()} label="保存修改" />}`（沿用它「有未保存改动才出现」的既有语义）

## 6. 可复用的排查经验（已入 REF）

- **「某页缺了某个入口」先横向 grep 同类页**：`grep -rn 'SaveFab\|sticky top-0' src/components/*.tsx` ——
  通常不是新页写错了，而是「四个范本都挂了、新的那个漏了」，比逐行读新页快得多。
- **量「按钮是否滚出视野」用 `getBoundingClientRect()` 与 `window.innerHeight` 比**，
  别只看「DOM 里存不存在」（本轮按钮一直在 DOM 里，`disabled` 才是「灰」而非「无」）。
