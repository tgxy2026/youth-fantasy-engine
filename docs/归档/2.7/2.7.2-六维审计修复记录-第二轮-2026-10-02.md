## 三、P0（3 条，全部已修）

### P0-1 导入 / 恢复备份后，多套条目的「活跃态」全丢
- **位置**：`db/projects.ts:importProject`、`db/backups.ts:applyBundleToProject`
- **机制**：备份里 `settings` 存着「哪些条目活跃」（`worldSubActive::<tabId>`，值是 `cardRecords` 的 id 数组）；而 cardRecords 落到新项目时**全部换新 id**（`uid()`）。原样搬 value ⇒ 数组 100% 悬空 ⇒ `splitActive` 全丢 ⇒ 所有条目集体退化为「已完结」，AI 上下文只剩一行「当前没有活跃的政权」，**且无任何报错**。
- **修法**：新增 `remapSettingValue(key, value, cardIdMap)`（放 `projects.ts` 导出，`backups.ts` 复用），两处搬 `settingsKV` 时把 id 数组过一遍映射；映射表里没有的旧 id 丢弃。
- **负面对照**：把 `remapSettingValue` 短路成原样返回 ⇒ **4 条断言立刻变红**，其中端到端那条直接复现 bug 症状「活跃 0 / 共 1，当前没有活跃的政权」。

### P0-2 酒馆「结束本轮对话」的事务边界仍漏一笔：① 的记忆
- **位置**：`tavern/roundEnd.ts`
- **机制**：上一轮只把 ②b 的 `saveFreeChar` 推迟到提交点，理由写的是「①②③ 里只有 ②b 会写会话之外的持久状态，记忆与日记都写在本会话内」。**这句推理是错的** —— `store.saveMemory` 的键是 `tavern.free.mem.<charId>`，**不带 sessionId，是跨会话全局键**。
- **触发**：① 成功写记忆 → ③ 设定审查被作者中止（`isCancelled` 上抛）→ 会话未归档（endedAt 未写、水位线未推）→ 作者重试 ⇒ ① 拿到**同一批消息**、而 `prev` 已是含这批事件的档案 ⇒ 同一段剧情被并进档案**第二次**。日记有 `sessionId` 幂等兜着，记忆没有 ⇒ 不可逆。
- **修法**：记忆与日记的落库一并移到提交点（`for (const m of memories) …` + 日记循环），①②③ 任一中止 ⇒ 一条都不落。
- **附带**：`useFreeRoundEnd.ts` 的界面文案「已中止收尾 —— 没有写入任何内容」原本是失实的（记忆已写），现在为真。

### P0-3 `ParallelSetSheet` 的「AI 补全」禁用逻辑完全失效
- **位置**：`components/ParallelSetSheet.tsx:63`
- **机制**：`const aiReady = useAIReady()` —— 返回的是 `{ ready, label }` **对象**，对象恒为真值 ⇒ `disabled={!aiReady}` 恒 false，没配模型也能点开弹窗、走进内部才炸；`title` 的降级提示永远不会显示。
- **同类坑项目里已踩过一次**：`PaceAnalysisPanel.tsx:45` 专门留了警告注释，本轮新组件又踩。
- **修法**：`const { ready: aiReady } = useAIReady()`。

## 八、本轮新增的可复用教训

1. **子代理报告的误报要分类**。本轮 31 条里坐实 24 条，误报有共性：**「结构改动只改了读取侧、没改写入侧」** —— 并列结构改完后 `aiContext`/`exporter` 都不读 formData 了，但 `flow/commit` 按 `tab.type === 'form'` 照写不误。审「改了数据结构的提交」时必问一句：**所有写入侧都跟着改了吗**。
2. **上一轮的修复可能有「错误推理」留下的漏网**。P0-2 的根因是上轮注释里写了一句「记忆写在本会话内」—— 修复时没怀疑这句话本身。**注释里的因果判断也是要审的对象**。
3. **对象当布尔**：hook 返回 `{ ready, label }` 时，`const x = useX()` + `disabled={!x}` 恒失效。项目已踩过一次并在别处留了路标，仍会重犯 ⇒ 这类应进结构闸（扫 `useAIReady()` 不带解构的调用）。
4. **行内按钮闭包里的 `s` 不会被自动用上**。`map` 里写 `onClick={() => delSub()}` 极自然，但 `delSub` 闭包捕获的是外层的 `sel` —— 编译器不报错、测试不覆盖，只有实机点得出。**新组件的行内操作一律显式传 id**。
