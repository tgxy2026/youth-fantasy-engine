# 一键拆书 · 末尾「整理关系」阶段（2026-09-19）

> 承接老大 2026-09-19 的三条要求：① 去掉圈号 ② 确认两个工作流的产出层级 ③ 势力关系改 AI 整理
> ④ 新增模型设置页签 —— 本篇是随后「**把关系整理补进工作流**」的执行记录（创意写作不加）。

## 一、做了什么

在一键拆书流水线**末尾**加了第六个阶段「整理关系」（`relations`），落库后产出《人物关系》《势力关系》
两表草稿，**并进同一份草稿包**，与实体草稿一起勾选、一次写入。

```
切分 → 写入正文 → 逐块抽取 → 整理草稿 → 汇总全书设定 → 整理关系 → 你审阅 → 写入
```

### 为什么关系不能像实体那样逐章抽

关系是**两两事实**：一句「萧景行与萧景炎反目」要同时定住两个人，还要知道是否已登记、
A-B 与 B-A 是不是同一条（无序对）。逐章抽只会抽出一地半截关系（原文写着「师父」——
谁的师父在那一段里没写），而且每章都判一次重、每章都可能写半条。所以这一步的形态必须是
**整本看完 + 对齐已有条目，末尾一次收敛**。

### 关键实现（三处）

| 位置 | 内容 |
|---|---|
| `lib/bookbreak/relations.ts`（新） | 阶段主体：材料拼装 → 两次调用（两表各一次）→ 两道本地校验 → `DraftRow[]` |
| `lib/organizeRows.ts`（新） | 把「AI 整理」的执行体从弹窗里**下沉**到 lib —— 弹窗与流水线共用同一套候选值注入 / 项目资料打包 / 判重，不让两处漂移 |
| `lib/flow/commit.ts` | 新增**第二条判重路径**：无「名称」列的表按 `dedupKeys` 组合判重（无序对排序比较） |

另把 `resolveOptions` 从 `components/CustomSelect.tsx` 迁到 `lib/customOptions.ts`（组件侧再导出，
既有调用方零改动）：它决定「某列有哪些合法取值」，四个消费方必须同一口径，而 AI 整理住在 lib，
lib 不得反向依赖 components（分层红线）。

## 二、实测逼出来的两类脏数据（都不是猜的）

用本地 Ollama `qwen3:4b-instruct` 真跑（不进仓库的临时 provider），同一段 400 字测试正文：

### 第一轮：模型把势力 / 地点写进了人物列

```
陈渊 · 苏念 | 萧景行 · 苏念 | 陈渊 · 青岚宗 | 萧景行 · 青岚宗
苏念 · 萧家 | 陈渊 · 萧家 | 陈渊 · 青岚宗山门 | 苏念 · 苏家
```

「青岚宗」「萧家」是**势力**，「青岚宗山门」是**地点** —— 正是老大上轮亲自点出的那个病
（「中州萧家被录进人物关系」）。根因：**拆书时角色卡与《国家势力》还几乎是空的**
（抽出的实体草稿还没落库），按库算出来的候选值是**空名单**，模型手里没有名单只能自己编。

**修法①：候选值 = 库里的已有名字 ∪ 本次刚抽出、还没落库的同类实体**
（`allowedOverride`，人物取「人物」类实体、势力取「势力」类实体，都含别称）。
**修法②：产出后本地校验关键列是否在名单里，不在就丢**（`filterRowsByRoster`），并如实计数。

### 第二轮：带项目资料后，模型拿资料里本书没提到的势力互相编关系

prompt 已写明「只登记材料中明确写出的关系、项目资料不得用于推断」，**4B 小模型照样不听**：

```
中州萧家 · 血魔教 | 中州皇朝 · 青岚宗 | 中州萧家 · 中州洛家
```

这三个势力名我的测试正文里**一个字都没提**，它们来自项目已有的《国家势力》表 ——
模型把「资料里有这个名字」当成了「它们之间有这层关系」。

**修法③：要模型给出「依据」原文片段，本地核对那段话确实逐字存在于材料里**
（`evidenceInMaterial`，与实体抽取的 `evidence` 同一判据）。摘不出原文的条目一律丢弃。

### 最终效果（同一段文本，第三次实机）

```
《人物关系》1 条（丢弃 4 条：名字不在名单里或给不出原文依据） · 《势力关系》1 条
关系草稿：陈渊 · 苏念 | 青岚宗 · 中州萧家     ← 后者对应原文「萧家与青岚宗结盟」
```

**少而准**：留下的是真关系，丢掉的是编的，且界面**如实交代丢了几条、为什么**
（节点摘要 + 草稿区文案）。作者不会误以为「这本书没有关系」。

## 三、顺手堵掉的一个数据风险

关系表**没有「名称」列**（列就是 人物A / 人物B），而 `commit` 的判重是「按名称列找同名条目」——
对它们**恒判"不存在"**。后果很具体：**作者在草稿页点两次「写入项目」就登记两条同样的关系**
（图谱里随即多一条重复边）。

补法：`DraftRow.dedupKeys`（本表按哪几列组合判重）+ `commit` 第二条判重路径，
无序对表排序后比较（A-B = B-A）。`previewCommit` 走**同一个**函数，
保证「写入前预览说的」与「实际发生的」一致。

## 五、判定与边界

- **创意写作不加这一步**：它是从零写正文的链路，插一步整理会打断节奏（老大已认可这个取舍）。
- **材料是「实体清单 + 开篇样本」，不是全文**：前面的抽取阶段已经逐章读懂过原文，
  拿它的成果当输入比重读几十万字便宜两个数量级；材料带上限是硬要求（撞窗口＝静默截断）。
- **关系整理不额外记额度**：与表格页的「AI 整理」同一口径（那边本来就不计额度）；
  面板开关处已写明「多两次模型调用」。
- **已知边界（未做）**：材料按每类前 50 条截断，超长篇的关系召回会下降；
  作者可到《人物关系》/《势力关系》页用「AI 整理」自行指定章节继续补 —— 节点摘要里也写了这条出路。
