## 一、方法与验收标准（先定，再动手）

拆 1000+ 行组件＝「搬 JSX + 搬 props」。`tsc` 能抓漏传的 prop，但**答不出一个问题**：
渲染出来的东西是不是还一模一样。所以验收不靠"tsc 过了"，靠三层：

| 层 | 手段 | 判据 |
|---|---|---|
| 类型 | `tsc --noEmit` | 0 错（漏传/错名 prop 必报） |
| 渲染 | **Edge 实机指纹比对** | 与拆分前 **16 项逐项一致** |
| 行为 | **Edge 实机真点交互** | 收起/展开、选中、切换章节都正常 |
| 判别力 | **负面对照**（故意改坏 → 期望 FAIL） | 两次都如期响了 |

指纹 = 页面上可数的结构化事实：左栏按钮数、角色行数、分组行数、编辑器叠层数与各层 padding、
工具栏按钮数、目录树卷数、各处 `main` 文本长度。**少渲染一个元素、多包一层 div 都会现形。**

## 二、两个拆分（都已 Edge 验证通过并保留）

### 拆分 1 · TavernCard 左栏 → `TavernCardList.tsx`

`TavernCard.tsx` **1488 → 1341 行**（新组件 208 行）。

抽的是左栏列表（按故事分区树 + 建卡/AI 入口 + 导入导出入口）。
选它的依据是先量化了各候选块的**外部依赖数**：左栏 18、右栏表单 119、编辑区 240 —— 左栏最小。

- `groups` / `toggleStory` / `charRow` **只被左栏使用**，一并搬走（留在父组件里就是纯噪声）。
- 🔴 `openIds` **故意留在父组件**：父级还有个 effect 会在故事增删后收敛它（清理已不存在的 id），
  状态归属不能跟着 JSX 一起走。
- `FREE_GROUP` 改从新组件导出，避免同一字面量在两处漂移。

### 拆分 2 · NovelEditor 左侧章节树 → `NovelEditorChapterTree.tsx`

`NovelEditor.tsx` **1910 → 1754 行**（新组件 239 行）。

抽的是章节树（卷/章渲染 + 拖拽重排 + 宽度拖拽 + 导出与新建入口），并把只被它使用的 `STATUS_DOT` 一起搬走。

- **搬视图不搬状态**：`dragKind` / `dragId` / `overKey` / `expanded` / `chapterSeqs` / `chapterPane`
  全部留在父组件作为 props 传入 —— 父组件别处还在读它们（拖拽落点判定、导出、状态栏）。
- JSX 用脚本**从原文逐行抽取**并统一减 4 空格缩进，不手抄（避免转录错误）。
- ⚠️ 该文件是 **CRLF**，补丁脚本按实测换行拼锚点（否则整文件重写、diff 爆炸）。

## 四、我自己写错的两条断言（值得记）

1. **假设章节树初始是收起的** → 断言「点展开键应让行数变化」。实测示范项目默认展开（21 章可见），
   点一下没有变化 → 假 FAIL。改成**往返**断言（收起再展开回到原状），与初始态无关。
2. **假设「点完章节标题会变」** → 点第一行时它**已经是当前章** → 假 FAIL。
   改成「取第二行的章名，点它，断言标题**等于那一章的名字**」。

→ 交互断言的期望值要**从页面现场取**，别写死假设；结果离奇时先排除自己的脚本。
