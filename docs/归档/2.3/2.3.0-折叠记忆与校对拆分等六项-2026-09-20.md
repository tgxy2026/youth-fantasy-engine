## 二、逐项说明

### ① AI 伴写默认关闭 —— 复核结论：已经是默认关闭

代码本来就是「**存过 `'1'` 才开**」：

```ts
const [companion, setCompanion] = useState(() => localStorage.getItem('novel-companion') === '1')
```

`novel-companion` 这个键**只有作者点总开关时才会被写**（全仓库唯一写点在 `NovelEditor.tsx`），
所以全新环境 / 老库（从未开过）一律是**关**。实机复核：清空 localStorage 后进编辑器，
钢笔标注「AI 伴写：已关闭」，且 `localStorage.getItem('novel-companion') === null`（不是写了 `'0'`）。

⚠️ 本轮**没有改这段逻辑**，只在 `tests/companionRefresh.test.ts` 里把它钉死：
判据必须是 `=== '1'`，**不许**写成 `!== '0'` —— 后者在老库上会**默认打开**，
而那正是老大想要的反面。

> 若老大在实际使用中看到"开着的"：那一定是之前点开过（本机 localStorage 记住了）。
> 点钢笔弹窗最下面的总开关即可关掉；关掉后跨会话保持关闭。

### ② 折叠状态跨会话记忆 —— 新增 `lib/uiPrefs.ts`

**为什么要收进一个模块**：项目里有 5 处树状 / 分组折叠，诉求完全一样。各写一遍
`useState` + `localStorage` 有两种腐烂方式：语义反了（一处存"展开的"、一处存"折叠的"）、
读取不校验类型（存数组读成对象，静默失效、界面回到默认展开）。

**🔴 最要紧的一条约定：一律存「偏离默认的那一侧」。**
侧栏存的是「**已折叠的分组**」而不是「已展开的分组」—— 这样以后新增分组时，
老用户的存量记录里没有它 → 落到默认值（展开）；反过来存「已展开的」的话，
新分组会因为"记录里没有"而**一上来就是收起的**。

| 接入点 | 存什么 | 首次默认 |
|---|---|---|
| 侧栏 · 分组 | `sidebar-collapsed-groups`（已折叠的组名） | 无记录＝空集合＝**全展开** |
| 侧栏 · 章节总表下的卷列表 | `sidebar-volume-open`（布尔） | 展开 |
| 表格页 · 上下级树 | `table-collapsed:<页签id>`（已折叠的行 id） | 全展开 |
| 模型设置 · 提示词条目 | `prompt-expanded`（已展开的条目 id） | 全收起（与旧行为一致） |
| 草稿审阅 · 分组 | `draft-review-collapsed` | 全展开 |

要点：
- 所有键带 `yfe-ui:` 前缀（`tests/uiPrefs.test.ts` 有断言），**不进项目数据**、不跟导出/云同步走；
- 空数组是**合法状态**（"我把所有分组都折叠了"），不能被当成"没记录"退回默认值；
- 树折叠**按页签分键**（国家势力的折叠不影响历史事件）；
- 读失败（隐私模式 / 配额满 / 脏 JSON）一律静默退回默认值，不让界面崩。

### ③④ 深度校对拆两块 + 判定加严

**拆分的实质收益不是"少点一次按钮"，而是文字层不再读设定资料**：

| | 文字层 | 逻辑层 |
|---|---|---|
| 查什么 | 错别字 / 语病 / 标点 | 逻辑矛盾 / 设定冲突 |
| 读设定资料 | **不读**（省掉每块几千字注入 → 更快） | 读（约 6000 字预算） |
| 分块大小 | 2200 | 3500（判前后矛盾要更宽的视野） |
| 与设定冲突时 | 只报「同段内写法不一致」 | 报「与设定资料哪一条冲突」 |

两处入口（编辑器「校对（本章）」弹窗、颉文姬诊室）都改成**两个并列按钮**，
结果分区显示、各有各的进度与报错；「替换此条」会**同时重锚定两块**的下标
（正文变了，另一层的坐标也一起漂 —— 只重锚定自己那块，切过去再点就是定位失败）。

> 颉文姬面板所有 AI 请求共用一个取消器，所以那里**同一时刻只允许跑一块**（按钮互斥）。

**加严的三处**（原提示词写着「宁可少报，不可误报」，模型把"我拿不准"直接当成了"不报"）：

1. **必须逐句读完**，明确禁止跳读 / 只看开头结尾；
2. 判据改成「**读起来确实有错或高度可疑就报**」，犹豫的在 `why` 里注明「疑似」；
   同时**把"不许编造"写得更硬**（放宽判据最怕变成瞎报 —— 而瞎报的 `quote` 在正文里定位不到、
   会被系统直接丢掉，等于白烧一轮 token）；
3. 给出**易漏清单**：同音字（的｜地｜得、在｜再、做｜作、末｜未、已｜己、象｜像、需｜须、帐｜账…）、
   形近字（戊｜戌｜戍、辨｜辩｜辫…）、多字漏字词序、语病五类、标点六种、专名前后不一致。

**提示词同步**：两条提示词就地声明在同一文件、登记进门面 `PROMPT_ORDER`
（＝模型设置页的显示顺序），改文案会**自动出现在「模型设置 → AI 提示词」里**，无需另做改动。
新增的那条若漏登记只有 warn、界面上看不出来，所以测试里专门断言了注册表内容。

顺带定下一条新约定：**提示词里不写 markdown 星号**（模型会模仿输出格式，正文就会混进 `**`），
要强调就用「」。测试有断言。

### ⑤ 伴写「换一句」（Ctrl/Cmd+Enter）

**问题**：同一个前文永远得到同一句 —— 因为同前文 + 同参数命中了 ghost 缓存
（这是**有意设计**：反复停笔不该重复烧 token）。所以"换一句"必须**绕开缓存**，
光绕开还不够：模型在同样的前文上多半会给出同样的续写，所以还要**把上一句喂回去要求换写法**。

```ts
const refreshGhost = () => {
  const key = ghostKey(before)
  ghostCache.current.delete(key)     // ① 绕缓存
  ghostFail.current = 0              // ② 重置熔断
  ghostDismissed.current = null      // ③ 清 Esc 抑制（作者主动要一句新的，不该被上次拒绝挡住）
  void fireGhost(before, at, key, ghost?.text ?? '')   // ④ 把上一句当 avoid 传下去
}
```

`aiInlineSuggest` 新增 `avoid` 入参，注入位置**在「去 AI 味」规则之前**——
那条纪律必须钉在 system 末尾才有效（项目红线）。提示词要求「换一个切入点或动作，
不要只把词换掉、不要同义改写」。

键位分工：`Alt+\` ＝ "还没看到建议，现在就算"（命中缓存就复用，省 token）；
`Ctrl+Enter` ＝ "这句我看过了，换一个"。两者都保留。

### ⑥ 世界构建 · 「其他设定」页签

**为什么需要**：前面六张表都是有结构的，写不进任何一张的零散设定
（天气历法的土规矩、货币兑换、民俗禁忌、某个不上台面的潜规则）过去只能硬塞进某张表的备注，
或者干脆不记 —— 结果是 **AI 读设定时看不到它，正文里却已经写了**。

形态刻意最简：**编号（MISC）+ 名称 + 内容** 两列纯文本，不做结构校验、不设枚举、**不加任何依赖**。
**默认不勾选**（`FEATURE_TIER` 里显式标 `optional` —— 写出来而不是省略，
是为了让读 schema 的人知道这是有意的产品决定，不是"忘了登记"）。

示范项目里播种了 3 条示例（玄脉品级划分 / 灵石兑换比率 / 望剑城收剑之制），
既让作者看到它长什么样，也满足种子闸「每个表格页签都不该是空的」。

### 页签变化涉及的全部同步点

| 同步点 | 处理 |
|---|---|
| 左侧菜单、功能勾选弹窗、使用指南、数据健康检查 | ✅ 自动（都从 `TABS` 派生，无需手工登记） |
| `SETTING_SUBTABS`（编辑器左侧设定检索栏的「世界构建」子项） | ❌ 已手工加上 |
| `PRIORITY`（AI 上下文优先级表，**红线**：新增资料型页签必须登记，否则进不了预算、只能被兜底追加到最末） | ❌ 已手工加上 |
| 正文引用名内联高亮 | ⚠️ **自动纳入**（凡「世界构建」组里带主名称列的表格都会高亮其名称）—— 所以 tips 里提醒"名称尽量起得具体"，泛称会让正文到处亮。高亮开关默认关闭，噪声影响可控 |
| AI「本次会读哪些数据」说明 | ✅ 现有条目的 `excludes` 用的是"等"字概括，不需要逐条改 |

### 实机（真实 Chromium + 线上模型 `Qwen/Qwen2.5-14B-Instruct`）

三段脚本共 **54 条断言，全部通过**：

| 脚本 | 覆盖 | 结果 |
|---|---|---|
| `ui-prefs-misc.mjs` | 折叠记忆（分组 / 卷列表）+「其他设定」页签 + 伴写默认关闭 | **24 / 24** |
| `ui-proofread-companion.mjs` | 校对两块（文字层真跑）+ 伴写开关链路 | **19 / 20**（唯一 FAIL 见下方排查记录，非产品问题） |
| `ui-companion-refresh.mjs` | 伴写停笔出建议 + Ctrl+Enter 换一句 | **11 / 11** |

**关键实测**

- **折叠记忆**：点折叠 → 刷新 → **仍是折叠** ✓；再展开 → 刷新 → **仍展开** ✓；
  卷列表同样 ✓。localStorage 里依次是 `["世界构建"]` → `[]`（空数组是合法状态，没被默认值顶掉）
- **其他设定**：侧栏出现、表头 编号 / 名称 / 内容、直读 IndexedDB 有 3 行（MISC0001–0003，键名与 schema 一致）
- **伴写默认关闭**：清空 localStorage 后钢笔标注「已关闭」，`novel-companion` 键为 `null`
- **校对两块**：两个按钮独立可点；文字层实测**检出 2 处真问题** ——
  「咱哥俩劈柴也一样活**!**」半角感叹号、「**管事的陈管事**是个四十来岁的干瘦汉子」语义重复。
  **加严确实生效了**（旧判据下这两条大概率不会报）
- **换一句**（本轮核心）：
  - 旧建议：「陈渊的心跳如擂鼓，震得识海嗡嗡作响。他咬紧牙关，忍受着那股从血脉深处涌来的炙热。」
  - Ctrl+Enter 后：「陈渊浑身一震，那声音像是穿越了千年的风沙，直击他的心灵深处。」
  - 且**新增 1 次 `/chat/completions` 请求** → 确认绕开了缓存、不是复用旧句

**⚠️ 排查记录（值得记一笔）**：伴写的 ghost 一开始怎么都不出、`/chat/completions` **零请求**，
连查 5 轮才定位到真正原因 —— **脚本选错了元素**：

`document.querySelector('textarea')` / `page.locator('textarea').first()` 取到的是页面上第一个
textarea（某个侧栏输入框，150 字符），而**正文 textarea 是另一个**（4617 字）。
于是"把光标移到文末"这步作用在了错误的元素上，正文的 caret 恒为 0 →
伴写判定「光标后还有正文」→ 静默不发请求。**产品本身完全正常。**

判据其实早就摆在眼前：脚本读到 150 字符，而校对面板显示「已校对 4617 字」—— 那时就该发现。
改用 `textarea.novel-textarea`（正文 textarea 的类名；⚠️ 高亮层与 ghost 叠层是
`div.novel-textarea`，必须带标签名）后，一次通过。
