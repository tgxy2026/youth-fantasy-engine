## 1. C2.1 全屏（浏览器不再缺席）

### 1.1 之前的真实缺口

桌面安装版有窗口桥（`desktop.ts` 的 `setFullScreen` / `isFullscreen` / `onFullscreenChange`，F11/ESC 在渲染层接管）。
网页版与便携版**没有任何全屏入口** —— `Sidebar.AppearanceToggles` 用 `HAS_WINDOW_BRIDGE` 门控，手册里也写着
「网页版没有窗口桥接，不显示这一项」。于是"手机/网页能不能全屏"只能靠猜。

### 1.2 现在怎么做

| 文件 | 职责 |
|---|---|
| `src/lib/app/browserFullscreen.ts` | 纯运行时层：`browserFullscreenSupported()`（`fullscreenEnabled` + `requestFullscreen`）、`browserFullscreenActive()`（认 `fullscreenElement`）、`enter/exitBrowserFullscreen()`（返回 `ok / denied / unsupported`）、`onBrowserFullscreenChange()`（`fullscreenchange` + `fullscreenerror`，返回退订） |
| `src/lib/app/useAppFullscreen.ts` | 唯一状态来源：桌面桥 → 浏览器 API → `none`；状态只由事件校准；失败留 `error` 供界面提示 |
| `src/components/app/Sidebar.tsx` | `AppearanceToggles` 改成消费该 hook：有通道才显示入口；按形态切换说明（桌面 F11/ESC vs 浏览器 Esc）；被拒/无 API 弹一次 toast，指向「专注模式」 |
| `src/lib/app/capabilities.ts` | 桌面全屏从 `unknown / not-implemented` 改成 `supported / ok`；浏览器保持 `conditional`（API 存在 ≠ 本次获准） |
| `src/lib/help/articles/look.ts` + `registry.ts` | 手册改口径（网页/便携也走 Fullscreen API）；`revision 1→2`、`verifiedAgainst 3.3.4`、`reviewedAt 2026-11-02`、`CONTENT_VERSION 5→6` |

三条硬口径（都写进注释与测试）：

1. **不按平台名硬编码**：没有 `if (Safari)`、`if (iOS)`。iOS Safari 的 `requestFullscreen` 长期只对
   `<video>` 生效这类事实写在注释里，行为一律由运行时结果决定（失败即 `denied`/`unsupported`）。
2. **状态只认事件**：`fullscreenchange`（Esc、系统退出、别的脚本改 DOM）+ `fullscreenerror`（被拒）；
   不乐观显示"已全屏"，卸载时退订（§10.1「不能遗留监听器」）。
3. **全屏根 = `documentElement`**：所有 Portal（菜单、确认、下拉、toast）都挂在 body 下，
   把根换成编辑区会让这些浮层在全屏里消失（§10.1 第一条）。

## 2. C2.2 证据包打印

### 2.1 之前的真实缺口

`EvidenceExportDialog` 在非桌面形态下把「存为 PDF」做成**下载 HTML** + 一句「打开后按 Ctrl+P」。
用户点了「存为 PDF」却拿到一个 `.html` 文件 —— 这是要把"做不到"说清楚，但还能做得更好。

### 2.2 现在怎么做

| 文件 | 变化 |
|---|---|
| `src/lib/audit/printPage.ts`（新） | `openPrintPage(html)`：**同一帧内** `window.open('', '_blank')`（保住用户激活，避免被拦）→ `opener = null` → `document.write/close` → 250ms 后 `focus() + print()`；返回 `opened / blocked / unsupported` |
| `src/components/audit/EvidenceExportDialog.tsx` | 非桌面：先走打印页；`blocked / unsupported` 时退回下载 HTML 并说明步骤。桌面仍走主进程 PDF；主进程通道不可用时也先试打印页 |

四条纪律（对应规划 §4.2 / §10.1）：

1. **只写本机刚生成的自包含 HTML**（`renderDoc(view.doc(), 'html')` 的返回值，转义已在导出层做完），
   不接受外部 HTML、不读远程正文/凭据；
2. **不用 Blob URL**：写入后立刻 revoke 会导致空白页（§4.2 点名过），这里直接 `document.write`；
3. **断开 opener**：打印页不能反过来操作原窗口；
4. **不谎报**：按钮与提示写「打印 / 另存 PDF」，toast 只说明"打印页已打开、在对话框里选另存为 PDF"，
   网页/便携路径不再出现「已保存 PDF」。
