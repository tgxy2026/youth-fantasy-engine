## 1. 版本目标与交付范围

3.3.1 让作者在进入具体功能时知道“这里做什么、从哪里开始”，遇到问题时既能自行查阅，也能让颉文姬根据内置手册回答；处理校对结果时能直接找到原文，复制失败时有明确补救；浏览图鉴、角色和大纲时可用方向键连续查看条目。

| 需求 | 本版交付 | 作者看到的变化 |
|---|---|---|
| 新手引导细化 | 首次进入页签的聚焦引导、随时重看、关闭自动引导 | 首次进入角色、大纲、正文等页签，分步认识关键区域和基本用法 |
| 颉文姬新增答疑 | 双助手入口、离线使用手册、本地检索、基于手册的 AI 问答及来源跳转 | 不配模型能查手册；配好模型后能问“这个功能怎么用”，并查看回答依据 |
| 左下角缩放布局 | 独立说明标题，下方自动按钮与百分比控件同排 | “页面缩放”单独一行，下面一排完成自动适配与手动比例调整 |
| 校对定位与复制优化 | 校对条目定位原文、统一替换/复制语义、复制失败补救 | 无需复制后自行搜索原句；复制是否成功有反馈，受限时可手动取用文本 |
| 适用页签方向键导航 | 图鉴网格与详情支持上下左右；角色、大纲目录支持方向键选项切换 | 打开图鉴详情后连续按键查看上一条/下一条，不必每次返回列表点击 |
| 网页版本地模型连接与回退 | 排查并尝试修复浏览器连接本机/局域网模型；无法可靠支持时禁用网页版本地配置及调用 | 支持条件与诊断明确；不再出现可以配置、却一直无法使用的本地模型入口 |
| 网页手机屏幕适配 | 网站响应式布局、手机导航、触摸操作、软键盘及小屏编辑适配 | 用手机浏览器直接打开网站，可阅读、编辑、保存和使用主要功能，无需安装手机应用 |

上述七项均为本版必做；网页版本地模型项以“验证修复后支持”或“验证不可支持后完成禁用”二选一交付，不能只留下待排查。第 12 节中文标点根因专项继续按原有要求处理。普通表单、表格、卡片页可以复用引导模板，但必须提供各页自身的用途与示例；不能只完成几个样板页就标记“全部完成”。本文属于仍在使用的开发文档，保留在 `docs` 主目录，完成使用后再按实际情况归档。

本版不包含：通用联网客服、自动操作项目的智能代理、远程手册后台、用户文档上传管理、向量服务配置、编辑器内核更换、整套导航重做。新增答疑能力只解释用法；校对沿用作者主动逐条替换的处理方式。进入页面、开始业务任务、应用内容仍由作者明确操作。

移动端不制作 APK/AAB、IPA 或应用商店安装包，不新增原生/混合应用壳；本次也不默认增加 PWA 安装、推送、后台常驻或整站离线写作承诺。

### 2.2 统一内容来源

建立一份内置帮助内容注册表，提供三种呈现：页签引导、手册文章、AI 检索片段。

```text
功能定义与实际页面 → 人工核对的帮助内容注册表
                         ├─ 页签聚焦步骤
                         ├─ 使用指南 / 颉文姬手册
                         └─ 本地检索 → 相关片段 → AI 回答 → 来源原文
```

页签名称、可见性和模板标签从现有功能定义解析；操作顺序、保存方式、AI 前提等说明需要人工核对。不能直接把旧说明全文复制后当作现行手册，也不能用模型自动生成的介绍充当产品事实。

## 3. 首次进入页签的聚焦引导

### 3.1 作者使用流程

1. 新用户完成或跳过首启向导，正常进入项目。
2. 首次真正进入某个页签，等页面数据与目标区域就绪后，出现简短聚焦引导。项目默认打开的写作面板也适用。
3. 采用淡化背景、描边高亮与说明卡片，解释“区域作用、如何开始、结果在哪里”；常规页以 3～5 步为目标，关于/指南等简单页面可为 1～2 步，不为凑步数重复说明，不逐字段讲解。
4. 每步提供“上一步 / 下一步 / 跳过本页”，最后一步显示“完成”；入口或卡片提供“查看完整手册”。首步提供“关闭自动引导”，之后可在帮助设置恢复。
5. 完成或跳过后，同一功能不重复自动弹出。以后可从页头“本页指引”或手册中的“重看引导”主动启动。

旧用户升级后不重走创建项目向导。首次进入项目给出一次轻量说明，可关闭自动引导；未关闭时，对尚无观看记录的页签按同一规则展示。说明条不叠加在首个聚焦卡片之上。

“首次”按成功进入功能计算，包含侧栏点击、写作面板快捷入口、搜索定位和程序内合法跳转，不按鼠标点击次数判断。但带明确章节/记录定位目标的跳转优先完成定位，本次只显示可继续的引导提示；不抢焦点盖住作者刚找到的结果。浏览器恢复、项目重新打开也不能绕过已完成/已跳过记录。

### 3.2 引导内容合同

每个可访问页签必须回答：

| 内容 | 要求 |
|---|---|
| 这页解决什么问题 | 用作者能理解的一句话说清用途，避免只解释按钮名称 |
| 从哪里开始 | 聚焦真实入口，说明前提；空页面时明确“先新建什么” |
| 怎样完成最小操作 | 介绍添加、编辑、选择、保存或生成的主要步骤 |
| 结果在哪里 | 说明记录、报告、候选、建议段等落点；保存方式按实际页面描述 |
| 与其他功能的关系 | 给出一条相关页面或手册链接，如角色档案与人物关系、大纲与正文 |
| 使用条件 | 区分本地可用、需要模型、需要选中章节或已有数据的功能 |

示例：

| 页签 | 拟定聚焦步骤 |
|---|---|
| 主要角色 | 档案列表及新建入口 → 基本资料与分组 → 角色摘要和关联信息 → 保存方式及手册入口 |
| 伏笔追踪 | 登记入口 → 埋设/回收相关字段 → 状态筛选和检查入口 → 与章节的关系 |
| 正文编辑 | 章节目录/空态建章入口 → 正文编辑区 → 保存状态 → 颉文姬及工具 → 本章资料和设定检索 |
| 模型设置 | 模型配置入口 → 服务地址/模型/密钥说明 → 连接验证 → 用途路由；只解释，不自动测试或调用模型 |

这些是内容设计示例。实际目标和文案以开工时页面为准；不得为展示引导创建记录、填入正文、修改模型配置或触发 AI 请求。

### 3.3 首次、跳过与重看规则

记录使用稳定 `guideId + guideRevision`，不使用中文标题、DOM 序号或项目 ID 作为功能身份。

| 状态 | 自动进入时 | 主动重看 |
|---|---|---|
| 无记录 | 自动引导开启时展示 | 可用 |
| 已完成 | 不再自动展示 | 从第一步重看 |
| 已跳过 | 不再自动展示；不标记“已学会” | 从第一步重看 |
| 因切页/弹窗/目标失效中断 | 不写成完成；当前停留不反复重启，下次进入可重看或重新开始 | 可用 |
| 自动引导关闭 | 所有页签不自动展示 | 本页指引与手册照常可用 |

记录在本机偏好域内，网页版按服务端已经提供且可验证的稳定账号标识隔离，游客使用独立空间；不能以显示昵称当身份。当前 `uiPrefs` 本身没有账号命名空间，不能仅复用它的全局布尔键就宣称隔离完成。若当前前端拿不到稳定标识，先补最小身份接入；身份未就绪时只存会话内记录，不落到共享账号键。桌面/便携版沿用当前本机使用身份，没有账号时按本机 profile 记录，不新增登录要求。

不同项目中相同功能共享学习状态；每个分卷不重复教学。暂不跨设备同步，不进入小说内容、项目导出或 AI 上下文。按功能独立更新记录，多个挂载实例或窗口保存时不能用旧集合覆盖其他功能的完成状态；同窗口偏好通知与跨窗口存储变化同步开关和终态。跨设备是否看过不作保证。

仅文案修订不重置完成记录。真正新增的操作可增加引导修订版本，并给老用户一个可选的“了解新功能”入口，避免升级后全部重播。提供“重置本页”与“重置全部引导记录”，不影响业务数据和缩放等其他偏好。存储不可用时使用会话内记录，避免本次打开期间反复弹出。

### 3.4 触发、定位与浮层行为

- 在导航通过可见性与保存屏障、目标页完成挂载后触发。导航失败、模块加载失败、隐藏页签不能提前记为已访问或已完成。
- 使用语义化 `data-guide` 锚点或等价的稳定注册机制，不按中文文字、样式类名和第几个按钮查找目标。重复组件的目标需限制在当前页面及有效记录范围内。
- 定位以实际可见区域为准；处理页面与内部容器滚动、固定页头、分栏拖动、窗口变化、抽屉和 80%～160% 界面缩放。避免将 CSS 缩放系数重复乘除造成高亮偏移。
- 进入引导可滚动目标进入视野，但不替作者切换记录、展开敏感业务操作或改业务状态。引导期间记住的滚动现场仅在同页同上下文仍有效时恢复。
- 惰性加载、无章节、空列表、折叠分组或自定义模板导致目标缺失时，采用声明的空态目标、区域说明或跳过该步骤；必须能退出，不无限等待不存在的锚点。页面级故障则停止并让故障恢复界面优先。
- 保存失败、确认对话框和既有模态窗口优先。引导被打断后只保留当前有效页面的待启动信息；用户已经开始键入时不突然弹出，显示可继续的轻提示。
- 引导每次启动绑定项目/页签/运行标识；切项目、退出项目、切页或卸载后清理监听与待启动任务，旧回调不能在新页面拉起引导。
- 小窗口优先使用底部说明卡片；仍无足够空间时降级为可滚动的本页说明，保持步骤与退出操作可达，不为了高亮占满可编辑区域。

聚焦引导默认采用“讲解模式”：只允许操作引导卡片，不让背景点击误触真实删除、生成或写入。涉及实际动手的步骤先退出讲解，由作者操作后再主动重看，不做要求真实写入才能继续的强制任务。

键盘要求：Tab/Shift+Tab 可遍历卡片，Escape 等同跳过本页；步骤变化可被读屏感知。结束后焦点返回原触发器，自动触发时返回合理页头入口。背景变暗不能只是视觉遮罩而仍可被键盘操作；使用现有浮层归属体系处理焦点约束。中文输入法组合输入优先，避免 Escape 关闭候选词时误退引导。支持减少动态效果，多主题下不只依赖颜色区分高亮。

### 3.5 触发状态与页内功能覆盖

统一触发状态为“待页面就绪 → 可启动 → 讲解中 → 完成/跳过/中断”。页面就绪由目标页显式注册或现有加载状态确认，不能只用固定延时推测。建议目标等待上限为 3 秒；加载仍进行时继续等待真实加载结束，页面已就绪但锚点仍缺失时转声明的替代步骤，不反复计时重启。运行时的等待与中断不当作持久化完成记录。

| 事件 | 状态与操作要求 |
|---|---|
| 首次进入且导航抽屉尚未关闭 | 等抽屉关闭且目标页面可见后再启动，不能聚焦隐藏侧栏实例 |
| 已开始编辑、输入法组合输入或搜索定位 | 延后为“查看本页指引”轻提示，不自动夺焦点 |
| 点击引导中的“查看完整手册” | 结束当前引导为中断，打开该页文章，保留“重看引导”入口；不写成跳过/完成 |
| 手动点击“本页指引” | 先提交或结束当前行内编辑；校验当前上下文后启动，不能引发未完成编辑被卸载 |
| 点击关闭、跳过或有效 Escape | 都按“已跳过”处理；被新模态覆盖、页面卸载则按中断处理 |
| 从手册点击“重看引导” | 记录待重看目标，经正常导航和保存屏障进入目标；确认成功后关闭帮助浮层并启动。保存失败则留原页，保留帮助文章与阅读状态 |
| 重复挂载、连点重看、延迟回调 | 同一窗口只存在一个引导控制器和一组监听，启动幂等；只响应最新有效运行标识 |

覆盖分成“页签认识”和“页内操作帮助”两层：

- 每个页签的首次引导介绍核心工作区，不在首次进入时连续播放所有工具教程。
- 编辑器工具、检查工具子功能、候选审阅与修订、世界引擎、素材资料和酒馆内部模块、按模板录入中的 AI 补全/对话引导，以及备份/导入/导出/同步等额外入口，均纳入功能清单，每项要能找到使用步骤和结果说明。
- 复杂子流程提供独立的手动子引导或上下文帮助；覆盖台账必须写明采用哪种方式及入口，不能把一段页签总述算作所有子功能已覆盖。首次点击子工具可显示一条可关闭的入口说明，不新增连续自动遮罩。
- 需要先选择章节、角色、记录或模型的操作，优先讲清前置条件；重看不能自动创建所需数据。页头没有统一标题区时，在实际工具区放同等可达的帮助入口。

## 4. 颉文姬双助手与内置使用手册

### 4.1 助手入口与呈现

点击颉文姬后，展示两种明确的服务入口：

| 入口 | 职责 | 所需条件 |
|---|---|---|
| AI 编辑助手 | 现有校对、润色、审读、简报、整理等编辑能力 | 本地功能按现状可用；AI 增强按现有模型要求 |
| 使用答疑助手 | 查阅内置手册、搜索操作方法、围绕手册进行 AI 答疑 | 阅读与搜索不需要模型；AI 回答需要可用模型 |

编辑器里的“颉文姬”工具按钮继续直接打开编辑助手。精灵统一承担双入口选择；非编辑器页面不再只有“前往正文编辑器”。去编辑器的动作使用现有导航，不强行关闭未保存草稿。

双入口选择需能用键盘打开、选择并关闭。精灵当前主要使用指针事件，开发时补语义化按钮及 Enter/Space 操作；保留拖拽、双击收边与位置偏好，拖动结束不得误打开助手。悬停说明、点击说明和实际两个入口保持一致。精灵隐藏、收边或触摸设备无悬停时，页头/使用指南中的同等入口仍可直接使用。

界面统一用“使用答疑助手”称呼常驻入口，内部区分“查手册”和“问 AI”；模型未配置也显示完整手册。现有按模板录入的“对话引导”、创意写作与酒馆对话分别服务创作，不能与软件答疑混用会话或自动带入它们的设定上下文，入口文字说明各自用途。

答疑助手在宽窗口为侧边面板，小窗口为可滚动对话框或抽屉，复用现有弹层机制。帮助面板打开与关闭保留正文 DOM、草稿和选区等工作现场；布局容不下两助手时切换前台面板，但不能把关闭面板等同取消后台任务。

关闭/隐藏颉文姬后，仍可通过“使用指南”、页头帮助和本页指引进入手册或答疑。项目管理页也提供手册入口，未打开项目时可读全局操作说明；依赖项目的跳转提示先打开项目。

以上为内容编排目录，不是静态页面总数。最终从 `TABS + EDITOR_TAB + getVolumeTabs()` 与额外入口生成覆盖清单；机构、模板改名等也从实际定义解析。内部数据表不当成用户可访问页签，动态分卷页归一到同一教程功能族。

动作执行当下重新校验目标仍存在、当前项目仍允许、动态分卷仍有效；不能只凭打开文章时的快照或一次 `tabVisible` 判断。失效时保持文章可读，禁用对应动作并说明原因。帮助需要获知导航的实际完成/失败，可补最小回调或完成通知，不以点击按钮或当前 `navigate` 的同步返回推断保存成功，不更换导航框架。

### 4.3 内容模型与维护方式

建议使用随应用构建的类型化内容文件；目录可按功能组拆分，索引由相同注册表生成。概念字段如下，实施时沿用项目类型习惯：

| 字段 | 作用 |
|---|---|
| `articleId / sectionId / revision` | 稳定文章身份、段落定位、内容修订 |
| `title / summary / aliases / keywords` | 展示、作者常用问法与本地检索 |
| `tabIds / featureFamily / availability` | 关联页签、动态页归一、平台及项目适用条件 |
| `sections / prerequisites / aiRequirement` | 经核对的操作正文、前提与 AI 要求 |
| `relatedArticles / actions` | 相关文章及经过校验的界面操作链接 |
| `guideId / guideRevision / guideSteps` | 共享说明、聚焦目标、空态分支与步骤次序 |
| `verifiedAgainst` | 内容最近核对的软件版本，用于维护与验收 |
| `contentVersion / supportedAppVersions` | 标记整套内容版本与适用软件范围，校验目录、正文、索引属于同一内容版本 |
| `featureIds / sourceLocations / reviewedAt` | 对应页内子功能、源码核查入口与最近人工核对时间，不对作者界面展示源码信息 |

短引导与完整手册允许有长短差异，但入口名、保存语义、前提、结果去向共用同一事实字段。模板变化只替换官方字段定义提供的展示名，不读取作者小说正文填充手册。

新增/移除页签、改名、入口迁移、保存规则或结果落点变化时，同次修改对应帮助内容并更新覆盖检查。手册内容版本随软件版本发布，不依赖远程更新服务。

### 4.4 手册体验、内容质量与加载恢复

- 目录和结果可按标题、别名、用途查找；结果呈现功能名、匹配段落、入口路径与适用条件。结果片段不能把“需要模型/不能覆盖原文”等限定条件截掉。
- 面板内查看文章、跳来源及返回搜索时，保留当前查询、已选文章和滚动位置。提供文章内返回与清空搜索；关闭后本次会话再开仍能继续阅读，切账号后清理阅读状态。复制回答/操作步骤为可选显式动作，不后台写剪贴板。
- 手册中的操作事实以当前已交付功能为准；规划中的功能不进入发布手册事实段。创作建议标为“建议”，不能把“建议先填某表”写成软件强制前提。示例使用内置虚构内容，不引用作者的实际作品或密钥。
- 统一说明每项操作是手动保存、自动保存、仅生成候选还是直接改数据，并分清导出作品、项目备份、参考资料与云同步的范围。空态、模型错误和功能受限提示可链接到对应文章。
- 手册目录、正文和索引使用同一构建版本；网页残留旧资源导致版本不一致时，停止据此生成 AI 回答，给出重新加载帮助资源的入口，并保留可读的匹配版本文章。会话旧回答携带当时内容版本，不能悄悄替换其引用原文。
- 不把“应用已加载”等同于所有惰性手册分块已缓存。内容包必须随安装/便携产物提供；网页版进入帮助后预备好完整本地可查内容，核实所需资源已加载再承诺本次会话离线可查。断网时不得在点击未缓存文章后才无限等待。
- 帮助内容加载失败显示可重试的错误与随主程序保留的最小快速开始/缩放说明；索引失败可退回目录阅读，AI 通道失败可退回本地搜索。帮助渲染异常只影响帮助区域，不能让写作页面崩溃或卸载。
- 手册内容域能独立于项目数据库和 AI 配置读取；项目尚未打开、数据迁移失败或模型设置读取失败时，仍可打开全局快速开始/故障说明。确实无法启动应用的故障不宣称由应用内手册解决。
- 帮助正文及模型回答优先使用现有安全文本渲染；需要富文本时限制为受控格式，不执行原始 HTML、脚本或自定义协议。文章动作只从注册表解析，普通外链沿用现有外部打开规则。

## 5. 离线检索与 AI 答疑

### 5.1 未配置模型时

答疑助手默认显示目录、搜索框、当前页面帮助和常见问题。作者可以直接阅读或输入自然语言问题，本地返回相关文章及匹配段落，并注明“本地手册检索结果”。不显示假装由 AI 生成的聊天回答，不要求先配置模型才能打开帮助。

内置文章、索引与图标随应用提供，不需要下载向量模型或调用外部嵌入服务。桌面版、便携版在本机应用可启动时断网可读；网页版在应用资源已成功加载的前提下，手册查询不再请求网络。首次离线打开网页及整站离线缓存能力不属于本版承诺。

### 5.2 本地检索方案

首版采用面向中文的本地全文检索：标题/别名/关键词权重高于正文，支持中文片段匹配及常用表达映射，如“放大字、界面变大”关联页面缩放。当前页签作为相关性加权，不把检索限制死在当前页。

按文章段落切分结果，保留标题、路径、稳定来源 ID 与适用条件。初始目标取 3～5 个相关片段；阈值与权重根据固定问答样本调优，不能只靠一个未经验证的分值判断“找到了答案”。低命中时推荐分类和可选关键词，不能硬凑文章。

不把作者项目资料、正文、模型密钥、原有项目参考资料库混入索引。当前页签、题材标签、已启用功能和运行形态等最小上下文可在本地用于排序和可用性判断；原始项目 ID 与作品名称不需要发送给模型。

### 5.3 配置模型后的回答链路

```text
作者主动提问 → 本地检索与适用条件判断
               ├─ 依据不足：直接提示未找到，提供相关手册，不请求模型
               └─ 依据足够：问题 + 必要对话上下文 + 手册片段
                             → 现有模型调用链
                             → 校验来源引用与界面动作
                             → 回答 + 对应原文 + 可用跳转
```

模型指令要求：只根据本次给定手册解释软件用法；先直接回答，再给步骤与适用条件；不确定就说明手册未覆盖。问题超出软件使用范围时给出范围提示，不编造按钮、菜单和已有能力。含糊问题在本地检索阶段先提供明确的相关主题供选择；依据足够时，模型也可基于文章追问，依据不足不能为澄清问题额外请求模型。

回答建议采用“回答内容＋使用到的来源 ID＋对应依据摘录”的受约束结构。来源 ID 必须来自本次实际召回片段，摘录需能在片段原文中定位；界面链接从注册表生成，不能采用模型随意输出的路径、URL 或脚本。引用不存在、摘录无法定位或结果无法解析时，回退到相关文章并提示无法核对。自动校验只证明引用有效，不能证明推论正确；回答与来源的语义一致性还须通过固定样本人工评测，不能只附一条无关来源就算有依据。

每次 AI 回答显示“AI 根据内置手册整理”，附文章标题与段落入口。点击来源能在手册中打开原文；“前往功能”和“重看引导”是独立按钮，使用当前上下文校验可见性及导航保存屏障。阅读来源不应强制离开当前编辑页。

首版采用先完整接收、后解析与引用校验、再显示回答的顺序，生成中只展示状态与停止入口；不将未校验的流式文字当作正式答案。若日后增加流式预览，必须明确未核对状态，校验前不生成可点击动作，不作为本版必做。

例：作者在角色页问“如何检查角色有没有写崩？”回答可指出现有相关审读能力、所需模型和入口，列出对应手册来源；不能声称已经分析过当前角色，也不能直接发起检查。

### 5.4 模型、上下文与失败处理

- 模型解析复用既有 `utility` 路由；显示实际使用的模型。只有配置可用且作者提交问题时才调用，不因打开手册、切页签或显示推荐问题而调用。
- 开发建议初始上限：最近 6 轮必要对话、最多 5 个手册片段；最终受当前模型可用预算约束。问题超限给出明确提示，长历史先裁剪旧轮次，不静默截断最新问题。
- 每次用户提交至多发起一次答疑**逻辑调用**；答疑层不增加自动重问、JSON 修复请求或失败后的换模型请求。当前公共模型层可在参数不兼容时降级重试，一次逻辑调用最多 3 次实际请求（`MAX_REQUESTS_PER_CALL`），因此不能把“一次生成”宣传为“只发一次网络请求”。沿用公共上限，记录实际尝试次数；未来公共上限变化必须同步预算说明和检查。模型失败可由作者主动重试，算新提交。具体输入/输出预算复用现有机制，开工时记录实际数值与可用模型兼容性。
- 用户主动发送的问题会按现有配置交给模型服务，输入框附近简短说明这一点。请求只包含问答需要的信息；不自动附加正文、角色资料或业务选区。手册静态事实与用户问题均按数据处理，不能允许提问改变来源校验和权限。
- 默认会话仅在内存保留，不新增云端聊天存储；同账号跨项目可继续软件用法问答，但当前页上下文每次重新计算。切账号、登出时清空会话与在途结果；延迟返回不能串到另一用户。
- 状态至少区分：本地检索、AI 生成中、完成、依据不足、未配模型、调用失败、用户停止。超时、拒答、限流和网络错误沿用现有错误呈现，不转写为“手册没有答案”。
- 停止操作以底层取消能力为准。能中止则接现有取消接口；只能停止接收时如实标注，不能承诺请求或计费已终止。关闭面板保留会话及任务状态，不能重复请求；清空/退出产生的旧响应不得回填新会话。
- 无模型、无依据、断网、模型失败时，目录、已加载文章和本地搜索继续可用。推荐问题点击后先填入输入框，由作者提交。

### 5.5 连续追问、调用归属与配置变化

| 情况 | 具体规则 |
|---|---|
| “那怎么保存”“这个也需要模型吗”等追问 | 以最近一次已验证回答的文章主题和作者问题作本地检索补充，重新召回来源；不能只把上次回答发给模型而不检索，也不另发模型请求改写检索词 |
| 问题跨功能或作者切页后继续提问 | 显示当前参考主题；显式提问主题优先于当前页权重。主题仍不确定则先本地澄清，不能默认“这个”就是新打开页面 |
| 多轮历史 | 只保留必要用户问题和已验证回答；失败输出、未校验流和无依据猜测不进入后续上下文。旧引用如不在本次片段中，重新召回或不作为本轮事实 |
| 连点发送、Enter 与按钮同时提交 | 同一会话同时仅有一条在途生成，提交幂等；生成中可编辑下一问题，提交需等待或显式停止，不隐式排队计费；输入法 Enter 先服从组合输入 |
| 取消/清空后立即新提问 | 每次提交绑定会话代次与请求 ID，过期响应、finally 状态和旧引用都不能覆盖新轮次 |
| 没配模型，随后配置完成 | 返回助手后重算可用模型，无需重启或重建项目；原搜索和问题输入保留，不自动补发 |
| 在途期间修改或删除模型 | 本次请求使用提交时配置快照；下一次重新解析用途路由。不能把旧返回标成新模型，也不能自动再次请求 |

软件答疑属于应用级服务，调用上下文明确使用现有 `scope: 'global'`、`projectId: null` 并记录答疑任务类型/调用 ID。打开哪个项目不能改变它的归属，不把答疑 usage 计入正在运行的拆书、写作或审校任务。复用现有取消和状态基础设施时，也不能临时替换全局 usage 订阅，导致业务任务丢用量。

不新建小说候选、正文快照或项目检查报告来存放答疑。可以沿用现有运行统计记录模型、耗时、真实/估算用量、结束原因及实际尝试次数；不额外把问题全文、回答全文或提示词摘要持久化。需要核查公共账本是否自动留存这些字段；“会话仅在内存”不能只靠答疑组件不写数据库实现。清空会话不等同删除已有统计或撤销模型服务侧记录，界面文案按实际范围描述。

答疑专用系统指令不叠加小说写作规范、题材创作提示词、项目参考资料及模型的附加创作系统提示词。当前 `chat()` 会注入模型附加提示词，需要增加仅对答疑生效的调用级隔离选项，默认保持其他任务原行为，不能直接修改用户存储的模型配置。模型认证仍通过原配置与请求头完成；“不发送密钥内容”指不把密钥夹入问答消息，不影响正常鉴权。

模型服务兼容以现有 Ollama 与 OpenAI 兼容通道为范围，并受第 13 节的平台本地连接能力策略约束；不能因为桌面可用就推断网页版也可调用。支持原生结构输出时按声明使用，不支持时可接收文本形式的 JSON 并做同样的本地解析。协议降级不能跳过答案/引用校验；截断输出、空回答、无来源和超预算都进入明确失败或手册回退，不追加一次模型调用补答案。

## 6. 左下角页面缩放布局

### 6.1 目标排布

```text
页面缩放  ⓘ
[ 自动 ]  [ −  100 %  + ]
```

第一行只保留说明标题与帮助入口；自动适配按钮从标题行移到第二行，与百分比调整组成同一排。两组对齐、间距统一、整体高度协调，不在标题行放操作控件，不让比例控件单独占另一排。

“自动”意为“界面跟随窗口适配字号和元素大小”，不改变操作系统窗口尺寸。帮助说明继续解释这一区别，避免把功能描述为自动调整真实窗口大小。

### 6.2 行为与兼容

| 操作 | 预期行为 |
|---|---|
| 点击自动 | 立即按当前窗口计算，设置自动模式并呈现选中态，之后随窗口变化重算 |
| 点击减/加 | 沿用现有每次 10 个百分点的步长与 80%～160% 范围，进入手动模式 |
| 输入百分比 | 沿用 `NumberField`：范围内有效变更可即时生效并进入手动模式，超范围在回车/失焦时处理；未改变有效值的聚焦/失焦不强制切换模式 |
| 手动模式改变窗口大小 | 保持作者选定的比例 |
| 自动模式改变窗口/全屏状态 | 复用现有 resize 跟随机制，数值与实际界面同步 |
| 重启或切主题 | 沿用既有缩放偏好与模式，不新建同义设置键 |

不修改现有 `autoZoom()` 计算规则；其自动取值当前为 100%～140%，不等同于手动可调范围。界面布局复用 `applyZoom` 及 `--ui-zoom`，不引入浏览器缩放或独立字体缩放。

常规侧栏、收窄后的侧栏、移动式导航抽屉中都保持操作同排。空间不足时减少装饰间距、采用紧凑控件或扩大设置容器的有效宽度，不把数字裁成一位，也不把百分比控件换到第三行。至少完整显示三位数字与百分号，按钮命中区域满足现有触摸控件规范；不以不断缩小字体解决拥挤。

保留可读标签、键盘操作和边界反馈；“自动”有可感知的选中态，百分比输入有明确名称。验收同时检查全局输入样式优先级，防止旧有内边距覆盖导致数字显示不全。

### 6.3 最小宽度与输入事件顺序

现有侧栏最小宽度为 200 CSS px，常规初始值 224 CSS px；小窗口导航抽屉复用 300 宽度的 `Modal`。以控件容器的实际内容宽度验收，不仅看显示器分辨率。自动按钮与减号、三位数输入、百分号、加号在 200 CSS px 侧栏下也需同排，不裁切、不横向滚动、不用省略号替代数值；扩大容器不能作为绕过当前最小宽度的唯一方案。

当前 `NumberField` 在输入有效且处于范围内时即可通知父组件，并非所有输入都等到回车/失焦才生效。本版保持该合同，修正文案歧义：有效变更可即时生效，超范围在提交时钳制，非法文本/空值按原合同恢复；单纯聚焦/失焦或输入同一有效值不另行改变模式。不要为这次排布修改全局 `NumberField` 的行为。

重点验收焦点失去与按钮点击的先后关系：输入框还在编辑时点“自动”，即使 blur 先提交过手动值，最终也必须是自动模式与自动计算值；点击加/减则以本次已生效/已提交的有效值变化一次，避免旧闭包或重复事件加两次。输入到一半碰上窗口 resize 不覆盖编辑文本；切为手动后跟随事件不能晚到再覆盖用户值。

以 80%、100%、130%、160% 分别检查侧栏拖窄和导航抽屉，以及高 DPI 系统缩放下的显示；应用 CSS 缩放、系统显示比例和浏览器自身缩放分别记录，不能混为同一个百分比。辅助技术至少能读到“跟随窗口自动调整”、当前选中态、百分比与增减操作名称。

## 7. 校对反馈：直接定位原文与复制可靠性

### 7.1 反馈来源、问题与范围

来源：2026-10-26 用户提供的 QQ 群反馈截图。反馈核心为“校对有替换和复制两种选择”“复制还得回原文找，有点太麻烦了”“有时候会不给复制”。只记录产品问题，不将群成员身份、群内其他消息写入产品手册或样本。

据此新增两个目标：校对结果与正文建立直接定位联系；复制有真实结果反馈且失败后仍能取用文本。反馈不能直接证明故障发生在哪个发布版本、哪种校对或运行形态，开工时分别在工具弹窗和颉文姬诊室复现并记录；不把建议类不能替换误判成复制故障。

| 本次静态核查 | 规划处理 |
|---|---|
| “校对（本章）”工具弹窗按结果类型/失效状态显示“替换此条”或“复制建议”，未看到逐条“定位原文”入口 | 每条有引文的结果增加明确定位入口，复制与替换不再互相替代 |
| 颉文姬诊室的文字层/逻辑层结果主要提供替换，操作与工具弹窗不一致 | 两处共用动作语义及位置解析；不能只修截图猜测的一处入口 |
| `copyText()` 已有旧接口兼容分支，但现代 API 存在而调用抛错时直接返回失败，不会进入该分支 | 核查权限、用户手势、运行形态和模态焦点；完善有界回退与手动复制，不笼统宣称完全没有兜底 |
| 既有 `applyProofReplacement()` 与 `reanchorIssues()` 已保护多义引文及过期结果 | 沿用替换保护，抽取或补充只读定位解析；不能为“好找”而放宽误替换保护 |

必做范围为两处 AI 文字层/逻辑层校对结果及公共复制工具涉及的回归。本地错别字结果有单条准确范围时复用同样定位入口；只有词频汇总的结果先按多处匹配规则处理，不假定每个词只出现一次。不扩大到整套全文搜索重做，也不新增自动批量采纳 AI 建议。

### 7.2 每条校对结果的统一操作

```text
问题类型 / 当前状态
原文引句 → 替换文本或修改建议
原因与必要上下文
[ 定位原文 ]  [ 替换此条（符合条件时） ]  [ 复制替换文本 / 复制建议 ]
```

| 结果状态 | 定位原文 | 替换 | 复制 |
|---|---|---|---|
| 替换类，目标有效 | 可用 | 保留“替换此条”，点击时再次校验 | “复制替换文本”，仅复制 `fix` |
| 建议类，目标有效 | 可用，作者可直接回原句手工修改 | 不提供，不能把建议句写进正文 | “复制建议”，仅复制 `suggestion` |
| 已失效或原句已不存在 | 说明失效，不跳往猜测的位置 | 禁止 | 文本存在时仍可复制，保留“旧结果”标识 |
| 原句重复且无有效精确位置 | 明确“多处匹配”，可让作者选择带上下文的候选位置；无法确定则提示重新校对 | 不凭第一处命中替换 | 不受位置歧义影响 |
| 无可用复制文本 | 视引文是否可定位决定 | 按现有判据 | 禁用并说明原因，不复制空字符串或 `undefined` |

问题引句附近显示少量前后文，帮助作者辨认；复制按钮的默认内容与标签严格一致，不悄悄夹带解释、原句或 Markdown 标记。如提供“复制原句/完整问题”，应作为明确命名的次操作。点击复制不触发替换、重新校对或模型请求。

### 7.3 定位与正文处理流程

1. 结果携带实际所属项目、章节及生成时正文依据；不能仅凭当前活动章节和引句去定位。定位按“有效 `at` 且对应引文逐字一致 → 当前正文唯一完整命中 → 多处匹配/未找到明确处理”执行，仍需遵守已失效结果不能擅自复活的规则。
2. 只读定位同时适用于替换类和建议类，不能借调用有写入副作用的替换函数实现定位，也不能因为 `kind` 不是替换类就剥夺定位能力。字符偏移以编辑器实际文本口径处理，核对换行、中文及含 emoji 的内容，不能混淆字符数与 JavaScript 字符串下标。
3. 点击“定位原文”后，正文滚动到命中范围并选中或清晰高亮，使作者能够直接修改。长章、固定工具栏、正文内部滚动、专注模式与 80%～160% 缩放下仍应可见，不只移动了页面外层滚动条。
4. 宽窗口侧面板能同时展示正文时保留结果列表；工具校对弹窗或窄窗口遮挡正文时，暂收起结果界面再定位，并提供明确的“返回校对结果”入口。保留会话内结果、当前条目、已处理状态及列表位置，返回不重新调用模型。该动作不会把关闭面板当成取消校对任务。
5. 编辑器统一消费定位请求，并协调弹窗关闭的焦点返回；完成定位后，原文选区不能被旧弹窗触发器抢走。结果列表的前后条导航可作为增强，逐条定位与返回是本版必做。
6. 任务期间已切章/切项目或原章被删除时，不把旧结果应用到当前章。若仍允许查看所属章节，通过既有离页保存屏障明确进入，成功后再定位；无法进入时说明原因。仅定位不改正文、不触发业务写入，也不把问题标为“已修复”。
7. 作者主动替换时继续使用现有精确校验、两层结果重锚定及失效处理，保持编辑器既有保存和撤销机制；再次点击不能重复替换。作者手工修改后，旧结果在定位与替换前重新核对，不拿旧索引跳转到别的文字。

### 7.4 复制成功、失败与手动补救

继续以 `copyText()` 为统一入口，核查所有本次接入的调用方，保留其返回成功/失败的合同，不在两个校对界面各实现一套剪贴板工具。

- 显式点击或键盘激活后，在有效用户手势中尝试现代剪贴板 API；调用前不插入与复制无关的等待。剪贴板受限、不安全上下文或 API 缺失等情况按实际能力处理，开发时区分原因。
- 自动兼容回退至多尝试一次旧接口，核对模态窗口的焦点范围、临时文本控件是否处于有效作用域及清理行为。现代 API 抛错后的回退是否可用必须实测，不循环请求权限，也不把旧接口支持当成所有浏览器的保证。
- 只有写入接口明确成功才显示“已复制”。失败时在当前结果条目附近给出“自动复制失败，可手动复制”，保留文本，不弹成功提示、不移除条目；区分复制失败与替换/定位失败。
- 自动方式均失败时，提供可选择的只读文本区域或当前模态内的手动复制面板，完整显示待复制内容，允许 Ctrl/Cmd+C 及系统长按复制。该入口不得因浮层的 `inert`、选区恢复或全局禁用选择而无法使用。
- 复制/关闭补救面板后返回合理焦点，不清除正文草稿和已存选区；临时 DOM、监听器和定时器在完成或卸载时清理。对连点、组件卸载和结果列表重排按稳定条目身份处理，不能将另一条误标为已复制。
- 故障排查与验收使用隔离的非敏感固定文本，不额外上传正文，不为验证复制而触发 AI，不将复制成功与模型配置绑定。

### 7.5 与引导、手册及开发证据衔接

在校对页内帮助、正文引导及手册中同步说明“定位看原文 → 作者决定手改/替换 → 复制作为独立取用方式”的流程，讲清替换类与建议类区别、重复引文与失效结果处理。答疑知识库也需能回答“如何跳到校对问题原文”“为何不能替换”“复制失败怎么办”。这些条目在功能实现并核对后才进入发布手册，不提前宣传为现有能力。

开工先分别记录两个入口的现状与复制故障复现条件，随后给出定位目标、焦点/返回链路、复制成功/失败及正文是否改变的证据。本需求必须包含实际操作验证，不能只凭增加按钮或单测 mock 返回 `true` 判完成。

## 8. 方向键导航：图鉴详情优先、按页签语义接入

### 8.1 目标与适用范围

支持用户使用键盘方向键区的 ↑、↓、←、→ 切换当前浏览对象，重点解决“打开一个图鉴详情后，还需要反复返回列表才能查看其他条目”的问题。使用 `KeyboardEvent.key` 的语义处理普通方向键；数字小键盘锁定状态不作为本版前提。

| 页面/区域 | 本版范围 | 规则与边界 |
|---|---|---|
| 种族生物、物品资源、国家势力、地理风物的图鉴视图 | 必做，四个页签全部接入 | 卡片网格支持上下左右空间移动；详情支持四键连续切换当前查看条目 |
| 主要角色、次要角色、NPC 角色、其他设定的对象目录 | 必做，复用当前实际呈现的目录 | ↑/↓ 选择上一/下一条并更新详情；←/→ 仅在已有树目录时承担折叠/展开，不强行改成跨页签切换 |
| 分卷大纲、章节细纲的对象目录 | 必做 | ↑/↓ 依目录当前顺序切换；有层级时←/→遵守展开/收起及父子项规则，叶项不另派操作 |
| 正文章节目录、其他独立对象列表 | 开工盘点后按已有能力补缺 | 已有键盘行为优先；仅在目录有焦点时处理，不在正文输入区改动光标规则，不把额外对象列表全部承诺为本版必做 |
| 表格单元格、下拉列表、日期选择、地图/画布、正文编辑区 | 本版不新增覆盖式方向键切记录 | 保留光标、数值、选项、滚动或画布操作；不通过全局监听抢占 |
| 顶层项目页签/主导航 | 保留当前交互 | 本需求是适用区域内的条目导航，不绑定方向键在全软件任意跳页 |

P0 为上述必做区域登记“已有/缺失/冲突/无需改动”及实际入口。有现成树键盘合同的直接复用并补回归，不平行新增第二套相反按键逻辑。

### 8.2 图鉴卡片网格与详情的按键合同

区分卡片二维排列和详情连续阅读，避免窄窗隐藏网格后仍按不可见列数跳过多个条目。

| 焦点所在位置 | ↑ | ↓ | ← | → |
|---|---|---|---|---|
| 可见图鉴卡片网格 | 上一行同列 | 下一行同列 | 当前行前一张 | 当前行后一张 |
| 图鉴详情的只读条目导航区 | 上一条 | 下一条 | 上一条 | 下一条 |
| 一维对象目录 | 上一条 | 下一条 | 树目录收起/返回父项；普通列表不接管 | 树目录展开/进入子项；普通列表不接管 |
| 输入、编辑、选择控件 | 沿用控件原行为 | 沿用控件原行为 | 沿用控件原行为 | 沿用控件原行为 |

网格移动依据当前实际列数和卡片位置：←/→不跨行绕回，↑/↓不凭固定三列/四列计算。最后一行不足列、最上/下行或最左/右列没有目标时停在原条目，不补跳到其他行的末项，不循环到列表另一端。只有一列时网格↑/↓移动，←/→停留；详情的四键规则不变。

详情四键统一按当前结果序列移动，↑与←等价、↓与→等价，不切字段分组、不切其他页签；到首尾停留，并通过禁用的上一条/下一条按钮及“第 N / M 条”说明边界。显示简短提示“↑/← 上一条，↓/→ 下一条”，宽窗侧详情和窄窗覆盖详情采用相同规则。

**选择与焦点流程：**

1. Tab 进入卡片集合时落在当前有效卡片，无选中项时落首张；采用一个可顺序 Tab 进入的活动项，其余项由方向键到达，避免上百张卡片成为连续 Tab 停靠点。
2. 未打开详情时，网格方向键只移动卡片焦点；Enter/Space 打开该卡片。鼠标/键盘打开详情后，焦点移到有名称与操作提示的详情导航区，用户可立即用四键连续查看，不必先点击其他开关。
3. 详情已经打开、作者将焦点返回可见卡片网格时，网格方向键同时更新选中卡片和对应详情，保持卡片、名称、图片、字段来自同一条目。焦点留在卡片，不在每次切换后被抢回详情。
4. 从详情导航区切换条目后，焦点留在该区，新详情从顶部开始阅读；读屏简短播报名称与 N/M，不每次朗读全部字段。方向键导航不改变编辑态、不自动提交写入。
5. 关闭或返回列表后，滚动并聚焦最后查看的有效卡片；窗口仍为覆盖模式时不聚焦被遮挡列表。卡片已不存在则返回合理的列表入口或邻近有效项，不留下焦点在 body。

详情提供可点击且有明确名称的“上一条 / 下一条”，与键盘共用同一个目标解析与切换入口，保证触摸、读屏及不使用快捷键的用户也能连续浏览。Enter/Space 服从当前按钮语义，Escape 仅在导航作用域且无更高优先级浮层时返回列表，不用它强行撤销正在编辑的字段。

### 8.3 顺序、筛选与布局变化

- 图鉴只在 `AtlasView` 当前筛选、排序后的 `orderedRows` 中导航，复用现有编号/名称/最近修改排序；不重新查询全库，不跳入已隐藏条目，也不改变行顺序、导出顺序或项目数据。
- 使用稳定条目 ID 关联焦点与选中状态，不长期保存数组下标。筛选、排序或数据更新后重新计算 N/M 与相邻目标；如果当前条目仍在结果中，保持该 ID。没有当前条目时先进入列表选项，不用旧下标指向另一个对象。
- 结果为零时禁用导航并显示空态；一条时所有切换均停留。只读条目被筛除/删除时，关闭失效详情并将焦点放回有效列表入口；若存在未处理编辑状态，先按 8.4 的草稿保护处理，不直接卸载。
- 卡片密度、主导航宽度、详情展开、窗口尺寸和应用缩放可能改变网格列数。以实际网格布局重测，保留当前条目身份；网格按键使用最近有效布局，布局未稳定时暂不执行空间移动，避免跳错列。详情连续阅读不依赖可见网格列数。
- 仅把新聚焦卡片滚动到所属容器可见范围，避免每次将整个工作区跳回顶部。窄窗详情切换不自动回到列表；显式返回后才恢复列表现场。
- 角色与大纲目录依据各自当前搜索、筛选、展开状态和展示顺序导航；树中折叠后隐藏的项不进入↑/↓序列。目录项切换复用现有选择入口，不能另外直接写选中 ID 绕过保存或编辑检查。

### 8.4 输入避让、草稿保护与异步边界

方向键只由有焦点的当前导航区域处理，不注册在整个 `window/document` 上无条件换条目。至少遵守以下规则：

- `input`、`textarea`、`select`、`contenteditable`、数字框、下拉/组合框、滑块、表格编辑器、树/菜单等已有方向键控件优先；只读文本阅读/滚动区域也保留原生滚动和文字选择，不因位于详情内部而抢键。
- Ctrl/Alt/Meta/Shift 等组合方向键、输入法组合输入及兼容的组合键标记、子控件已经 `preventDefault` 的事件不作为条目切换。中文输入法候选词选择不能切换图鉴。
- 新模态窗口、菜单、图片选择/裁切/预览或引导浮层打开时，后台图鉴和目录不响应。焦点在其他页签、搜索框、正文或隐藏实例上时，不凭“最后访问图鉴”继续监听切换。
- 详情进入编辑态时，方向键不触发条目导航。即使焦点移到详情标题，仍须明确保存或结束编辑后才能按键换条目；有未处理草稿、保存中、图片压缩/上传/移除在途等会被切换影响的状态时，阻止新增导航并给一次清晰提示，不按一次方向键就自动保存或撤销。
- 当前 `AtlasDetail` 按条目 ID 重新挂载，切换会重置局部编辑快照及状态。新切换入口必须统一核对这些状态及父级共享草稿，不能只检查焦点是否是输入框。完成保存后要有真实成功状态，不能仅以 `await` 返回或吞掉错误的回调判成功；失败保留原对象、草稿与焦点。
- 图片异步任务及延迟详情结果绑定原项目/页签/条目/会话代次；旧回调不能更新或清除新条目的状态。优先沿用当前图鉴与工作现场机制；不为新增按键复制正文或图片数据到持久化偏好。
- 在可安全只读切换时，按住方向键可连续浏览，但每个有效事件最多前进一项、不启动异步排队；编辑或保存阻断期间不积压目标，解除阻断后不能突然连续跳过数条。按键与按钮、鼠标入口共用防重入和归属检查。
- 仅在当前导航区域确实接管该键时阻止默认行为；达到导航边界仍停留于当前导航区域，不把一次按键同时用于换条目和滚动页面。离开区域或关闭页面立即清理监听及待执行定位。

### 8.5 引导、手册与实施落点

图鉴首次引导增加“用方向键连续浏览”的短步骤，并说明网格二维移动与详情上一/下一条的差异；角色/大纲说明目录方向键及编辑时避让。页头或导航区帮助入口可随时查看，AI 答疑复用相同规则，不承诺全软件任意位置都支持四键切换。

建议在现有公共交互工具中复用或补充焦点排除、边界解析和条目切换判据，由页面提供可见条目与布局信息。图鉴统一由 `AtlasView` 协调选中、列表与详情，`AtlasCard`/`AtlasDetail` 提供语义化焦点和动作；角色/大纲目录按当前实际组件接入。公共工具不隐式访问数据库、不写业务内容、不新增全局热键系统。

### 10.3 问答评测与发布门槛

建立不少于 40 条经人工核对的固定问题：正常操作 12、同义/口语表达 8、前置条件/未启用/平台差异 8、无依据/范围外/含糊问题 6、引用伪造与指令干扰 6。每条记录期望文章、关键事实、不得声称的行为和预期失败方式。

该 40 条是起始基准，不能替代全功能内容核对。额外补不少于 8 组各含 2～3 轮的连续追问，覆盖省略主语、切页、跨文章、修改模型和无依据的后续问题；多轮单列结果，不掺进单轮分母提高通过率。

拟定门槛：可回答样本的 Top-5 召回率至少 90%；AI 正确解释并有直接来源支持的回答比例至少 90%，由人工判定并记录模型与参数。隐私请求边界、非法动作、伪造来源、保存屏障、跨账号隔离等硬性用例必须全部通过。未达标时补内容、调检索或修验证，不把“有引用”直接计作“答案正确”。

| 指标 | 分母与判定 |

| Top-5 召回率 | 分母为预先标注“手册可回答”的固定问题；去重后的前 5 篇文章包含全部必需文章才算该题命中。同文多个片段不能占成多个文章名额 |

每轮验收冻结题集与期望，再运行待测内容版本；新增别名或修改期望须记录原因并全量复跑，不删除失败题来满足比例。即使总体达到 90%，关键数据保存/恢复与模型费用说明仍不得遗留已知错误。

检索性能目标：在记录型号的基准机器上，固定查询集本地检索耗时 P95 ≤ 150ms；单列内容/索引首次加载耗时。该值是待测目标。引导期间检查定位不抖动、无持续全页扫描，退出后监听和观察器被清理；不能因帮助模块让输入和主导航明显卡顿。

## 12. 待彻查：中文标点自动配对的根因（来自 3.3.0 用户反馈）

### 12.1 现象（2026-10-27 用户反馈）

- 搜狗输入法：打出 `，` 之后再按双引号键，期望得到 `“”` 且光标停在两引号之间；**实际只出现 `”`**。
- 用户补充要求：不止逗号，其他标点也要一并核对（3.3.0 已按标点族普查，见 12.3）。
- 现场取证（3.3.0）：`scripts/verify/frontend-punct-pair.mjs` **20/20、stale=false**，8 组配对（`“”`/`‘’`/`《》`/`〈〉`/`「」`/`『』`/`（）`/`【】`）× 多种前置上下文（逗号/句号/汉字/行首/换行/空格）全部通过；正常收尾（前面已有未闭合开标点）不被改写。

### 12.2 作者判断（本条为规划依据，不用逐输入法适配）

> 「我认为目前的输入法基本都有符号补全的功能，按理说应该不需要单独给文本编辑器和输入法做适配，根本原因估计还是我们的文本编辑器有问题，等到 3.3.1 彻查修复一下；现阶段方案作为临时修复方案上线，后续彻底处理一下。」

即：**主流输入法自带成对标点**，应用层再加一层"补右半边"本质上是重复实现，且会与输入法的智能规则打架（例如搜狗按「前一个字符是标点 ⇒ 这里该收尾」直接上屏 `”`，我们只认左标点就永远补不上）。3.3.0 的兜底是**止血**，不是终局。

### 12.3 3.3.0 临时修复（已上，作为对照基线）

- `lib/editor/punctPair.ts`：左标点补右（3.2.0 起）+ **右标点兜底**（`planPunctPairFromClose` / `…AtCaret`）：
  只有当「光标前是右标点」且「此前没有未闭合的同一个左标点」时，才把它换成一对并把光标放中间。
- 在 `NovelEditor` 的 `onChange`（`InputEvent.data`）与 `onCompositionEnd`（按光标）两条路径上各判一次，幂等。
- 单测 `tests/punctPair.test.ts` **240 项**；浏览器专项上表 20 项。

### 12.4 3.3.1 要彻查的方向（按可疑度排序）

1. **组合态里对受控 textarea 的 value 回写**：`onChange` 里只要 `onContentChange(next)` 就会触发 React 用 state 重写 `value`。IME 组合期间这会不会打断输入法的提交、或让输入法认为"用户在编辑"从而按自己的规则改写上屏字符？需要在真实输入法下抓 `compositionstart/update/end` + `beforeinput/input` 事件序列对照。
2. **`compositionend` 后立刻 `setSelectionRange`**：光标被应用移动后，输入法若仍持有未完全提交的缓冲，可能把字符插到错位处。要确认是否该延后到下一次 `beforeinput` 之后。
3. **是否本来就该"什么都不做"**：如果主流输入法普遍自带补全，正确做法可能是**移除应用层补右**，只保证"不吞字、不重复、不改写输入法上屏内容"。需要用真实输入法矩阵验证「删掉补全后是否仍然成对」。
4. **输入法设置差异**：「中文标点时使用英文标点」、全角/半角、智能引号开关，会改变上屏字符；应用侧不宜按字符猜意图。
5. **兼容矩阵**：搜狗 / 微软拼音 / 微信 / 百度 / 手心，各测三条序列 —— `，` + `"`、汉字 + `"`、`《` + 书名、以及关闭输入法标点补全后的同一序列。

### 12.5 验收与边界

- 证据：真实输入法下的**事件序列日志 + 录屏**，不接受只靠 CDP `insertText` 模拟（3.3.0 的 20 项就是 CDP 形态，只能证明应用侧逻辑，不代表真实 IME）。
- 若结论是"应用层不该补"：移除兜底与补全两条路径，回归"不吞字/不重复/不改写"，并保留本次的单测作为**反例基线**（说明为什么不能按字符猜）。
- 🔴 不引入逐输入法分支；不改 schema 与存储键；不因该修复改动保存/草稿语义。

## 13. 网页版本地模型：先尝试修复，无法可靠支持则禁用配置

### 13.1 用户需求与交付决策

来源：2026-10-28 用户反馈“网页版似乎无法连接本地部署的模型”，要求在 3.3.1 尝试解决；若解决不掉，网页版禁用配置本地模型的功能。

本项是确定的开发任务，但修复是否可行尚未验证。先复现、分层定位并验证最小可行路径，再根据证据收口，不预设“所有网页版必然不能连本地”，也不在未验证时继续宣传支持。

| 结论 | 本版交付 |
|---|---|
| A：在明确承诺的支持环境可重复连接 | 修复请求/配置/权限提示等实际缺口；说明浏览器、部署协议、本地服务和允许来源等前提，能力不满足的环境明确限制 |
| B：没有可重复、安全且可维护的支持方案 | 网页版禁用本地模型新增、编辑保存、启用/设为当前、测试/获取列表及实际调用；说明原因，引导使用可达的在线端点或桌面/便携版 |

P9 的可行性阶段在 P0 后执行，支持条件及是否进入 B 分支在 P4 完成前记录。只做提示、不落实修复或禁用，不算完成。依赖关闭浏览器安全检查、非默认实验开关、长期临时试验或不安全暴露服务的“能通”，不算 A 分支通过。

### 13.2 平台与“本地模型”的定义

- 网页版同时包括 `WEB_CLOUD` 和 `WEB_GUEST`。便携版虽然也运行在浏览器里，但其页面来源与运行方式不同，单独验收；`WEB_CLOUD` 同时具有 `PORTABLE` 标记，平台判断必须优先判 `WEB`。
- 本项本地目标包括用户访问网页的同一台设备上的 Ollama、LM Studio/LocalAI 等 OpenAI 兼容服务，以及用户明确配置的局域网模型服务。`localhost`、回环 IPv4/IPv6 和私网地址须纳入地址规则，不只看预设名称或 `type === 'ollama'`。
- 服务品牌、开源模型名称、是否免密与物理网络位置不是同一概念。合法可达、有鉴权的公网 HTTPS 自建服务可按远程端点处理，不因运行的是本地部署软件就一律误禁；不能以“OpenAI 兼容”标签绕过本地目标限制。
- 明确浏览器直连与服务器代发的真实路径：网站服务器的 `localhost` 是服务器自身，不是作者电脑。不得把请求简单转到云端代理，就宣称解决了访问作者本机的问题。
- 按标准 URL 解析并核对协议、主机、端口及已有本地标记；对无效或无法确定适用性的配置给出可解释状态，不靠字符串前缀和任意主机探测猜测网络位置。公开域名可能解析到私网，不能仅因地址以 HTTPS 开头就保证可用。

### 13.3 先复现，再区分失败层次

开工记录实际网页地址/协议、页面安全上下文、浏览器及系统版本、云端/游客身份、模型服务类型/版本、目标地址、用户主动执行的动作、浏览器错误、请求/预检与服务端收到的情况。日志去除密钥、认证头、账号和作品正文。

| 排查层次 | 需要验证的事实 |
|---|---|
| 服务与地址 | 服务是否启动、绑定哪一地址、端口是否正确、IPv4/IPv6 是否匹配；同机与局域网场景分开 |
| 请求路径 | 获取模型列表、测试连接、普通生成、流式生成实际由浏览器还是服务器发出；各入口是否使用同一配置 |
| 跨域与预检 | 服务是否允许网站的确切来源、方法及必要请求头，OPTIONS 是否成功；自定义鉴权头是否触发额外预检 |
| 页面部署策略 | HTTP/HTTPS、证书、混合内容判断、CSP `connect-src`、Permissions Policy 等是否影响请求；以实际部署响应和浏览器证据为准 |
| 本地网络权限 | 浏览器版本、受支持的权限机制、用户允许/拒绝及企业策略；权限 API 不可用时不能直接判定模型故障 |
| 模型协议 | Ollama 模型列表/聊天端点与 OpenAI 兼容的 `/models`、`/chat/completions` 路径是否正确；可列模型不等于可生成 |
| 应用状态 | 是否错误地把配置存在当成连接可用、是否将网络失败全归为密钥错误，以及停止/重试是否重复请求 |

浏览器对本地网络访问的策略会演进。Chrome 官方说明本地网络权限与安全上下文相关，并区分回环、私网及混合内容情形；Edge 也有对应适配说明。因此不把旧 PNA 预检经验或“HTTPS 页面不能访问任何 HTTP 本地地址”写成一刀切结论，实施时复核当前浏览器文档并实测。[Chrome 本地网络访问说明](https://developer.chrome.com/blog/local-network-access)、[Edge 本地网络访问适配](https://learn.microsoft.com/en-us/deployedge/ms-edge-local-network-access)

Ollama 官方提供 `OLLAMA_ORIGINS` 配置允许来源的方式；若证据指向此处，手册只指导作者允许本应用的确切来源并在需要时重启服务，不默认推荐对所有网站开放。[Ollama 允许额外网页来源](https://docs.ollama.com/faq#how-can-i-allow-additional-web-origins-to-access-ollama)

### 13.4 修复路径与范围限制

优先修正已有前端请求、端点拼接、环境判断、来源配置指引及正常权限交互。需要网页部署响应头调整时，先完成可审阅配置与隔离验证；真实部署仍按发布授权执行，本轮规划不直接改线上。

- 获取列表、连接测试和实际生成都必须通过同一平台能力检查；错误提示区分服务未启动、地址问题、已观察到的来源/权限拒绝与模型认证失败。浏览器仅给出泛化网络错误时如实提示“暂不能区分”，不捏造具体根因。
- 仅在作者点击“连接/测试/获取模型”等明确动作后接触指定本地地址，不在加载项目、打开手册或页面刷新时扫描端口、尝试常见地址或弹权限请求。用户拒绝后不循环索权。
- 不使用 `mode: 'no-cors'` 作为模型 API 解决办法，不伪造 `Origin`、浏览器保留头或响应侧 CORS 头；不要求关闭安全检查、接受不可信证书、将服务无鉴权暴露公网或把正文发往第三方公共代理。
- 本版不隐含新增浏览器扩展、独立常驻桥接服务、隧道平台或复杂设备配对系统。可记录其后续可行性，但若只有引入这些新组件才能解决，3.3.1 按 B 分支交付，避免无限扩大任务。
- A 分支必须覆盖生产等价网页来源和支持环境，而非仅在 Vite/localhost 开发页面、curl 或 Node 请求成功。允许有限、明确的环境前提，但不能删掉失败环境记录来宣称全面支持。

### 13.5 无法修复时的禁用合同

1. **入口一致**：模型设置、首启 AI 配置、预设选择、免密本地兼容选项、手填端点和相关快捷入口采用同一能力策略。灰显并说明限制，不保留一个可以正常保存、随后每次调用必失败的表单。
2. **旧配置保留**：已有本地配置、备份导入或跨形态带来的配置可显示为“网页版不可用”，不擅自删除、不清空密钥或改写端点；可按现有方式删除或迁移到桌面/便携环境，不能继续设为网页当前模型或用于生成。普通字段编辑不能绕过禁用策略重新启用。
3. **调用前拦截**：统一限制模型列表、连接测试、生成、流式、工具调用及本地嵌入请求。用途路由、酒馆独立模型选择和旧对象引用也需校验，不只隐藏设置按钮。需要检查并复用最靠近实际发送的公共入口，避免仅 UI 限制。
4. **就绪状态真实**：配置存在但受平台限制时明确提示不可用；不得当作被删除配置触发静默回退，也不自动换成收费联网模型。作者主动选好可用远程模型后再恢复相应 AI 能力。
5. **其他形态不误伤**：桌面版和便携版保留已有本地模型配置与调用；在线模型、本地手册、本地非 AI 检查及手动创作不因禁用受到阻断。
6. **状态可解释**：能力至少区分“可尝试连接”“需配置/授权”“当前环境不支持”“版本统一禁用”。浏览器权限或服务状态变化需重新检查，不用一次失败永久判定所有端不支持；版本采用 B 分支时则按统一策略限制，不允许某个入口自行探测后绕过。

建议禁用文案：“当前网页版暂不支持连接本机或局域网模型。你可以配置可通过网页访问的在线模型，或使用桌面版/便携版连接本地模型。已有配置会保留。”若 A 分支仅特定环境受限，则文案准确指出当前条件，不能误报为全版本禁用。

### 13.6 验收、证据与手册同步

使用隔离账号、测试 profile、可控本机模型 API 模拟服务验证请求与错误路径，再在已有授权条件下验证真实本地模型；不能借用作者真实书库、自动消耗模型额度或改变作者机器上的服务配置。真实浏览器的本地网络权限与生产等价网页来源必须有证据，普通 fetch mock 不能代替。

A 分支至少证明：在承诺的 Windows 桌面浏览器与明确部署条件下，网页云端/游客均能重复获取列表、显式测试、完整生成、停止并正确处理服务重启/权限拒绝；本地 Ollama 与本地 OpenAI 兼容通道分别记录结果。未验证浏览器/移动端不默认继承支持结论；手机上的 `localhost` 指手机自身，不能描述为访问电脑本地模型。

B 分支至少证明：两种网页模式、首启/设置、手填地址、旧配置、导入和各模型引用都无法发出被禁用的本地模型请求，旧配置未被删除，在线模型及桌面/便携回归正常。网络计数用于证明拦截发生在请求前，不以按钮灰色截图替代。

开发台账给出根因分类、支持矩阵、实际浏览器/服务版本、源码及部署配置版本、选择 A/B 的理由和 N01～N12 证据。若真实条件不足且尚不能证明 A，不能当作修复通过；3.3.1 以经过验收的 B 分支收口，后续有可靠方案再另行开放。

最终同步模型设置与首启说明、相关页签引导、使用手册、AI 答疑来源和发布记录：说明哪个运行形态能连接哪些端点，配置前提与失败补救是什么。发布手册不能一处仍写“本地模型均支持”，另一处却已禁用。

## 14. 网页版手机屏幕适配：直接访问网站，不制作手机安装包

### 14.1 需求、范围与当前基础

来源：2026-10-29 用户要求在 3.3.1 增加移动端适配，主要面向网页版访问；不单独制作 Android 或 iOS 软件安装包，只提供网站的手机屏幕适配。

交付形态是同一网站在手机浏览器中的响应式体验，复用现有账号、数据、模型和业务逻辑，不另建移动端书库或独立业务版本。覆盖网页云端与网页游客，包含登录、注册、密码找回等实际存在的独立页面、项目管理、首启流程和全部项目内可访问页签。不能把普通平板/小窗口适配、只有首页能显示、或浏览器缩小后的桌面布局当作完成。

R6 核查基线为 `1e994d6`；本文及可靠性脚本另有未提交工作，本次仅修改本文。现有 `index.html` 已声明 viewport，`WorkspaceSidebar` 按有效宽度提供抽屉，正文已有章节目录/设定检索抽屉；这些机制继续复用。本轮没有执行手机模拟或真机测试，尚不能据此声称手机端可用。

### 14.2 布局与操作规范

| 区域 | 手机适配要求 |
|---|---|
| 页面框架与导航 | 小屏采用紧凑页头与菜单/设置入口，优先释放正文宽度；复用抽屉，不保留占据大量宽度的完整桌面侧栏。菜单能滚到所有已启用页签 |
| 主从页面 | 角色、图鉴、大纲等按“列表 → 详情 → 返回”单列切换；保留所选对象、筛选、列表位置及未提交草稿，不在手机上硬挤两栏 |
| 页头与工具栏 | 保留名称、保存状态和常用操作，其他操作进入具名菜单；不能把保存失败、冲突、AI 状态等关键事实隐藏到不可见位置 |
| 表单与设置 | 标签和输入区按可用宽度排列；长说明折叠或进入帮助，数字、下拉、密钥配置和提交按钮不被截断。缩放设置仍保持“标题＋同排控件”合同 |
| 表格 | 保留全部启用字段和真实数据语义；宽表可在表格容器内横向滚动，配合可达的详情/单元格编辑入口，不把整个页面撑宽，不为适配默默删列或复制一套数据 |
| 图鉴与图片 | 卡片列数随实际宽度调整，详情全宽阅读；提供可触摸的上一/下一条与返回，图片完整查看、上传、更换、取消和错误处理可用 |
| 地图与画布 | 核对选择、平移、缩放、连接和属性编辑的触摸入口；依赖鼠标/悬停的关键动作给等价按钮或菜单，避免把全部手机屏幕当成禁止滚动的拖拽区 |
| 弹窗、下拉与帮助 | 宽度限制于当前可用视口；长内容内部可滚动，关闭/返回和关键操作可达，处理安全区域；新浮层不能将输入框、正文或上一层出口完全遮住 |

断点按实际可用宽度和内容需求确定，不只靠设备名称或 User-Agent。最小目标宽度为 320 CSS px，主测 360～430 CSS px；竖屏优先，横屏仍可操作，手机横屏不能被误当成足以摆放所有桌面分栏的条件。

页面主框架不得出现意外横向溢出；表格、地图和画布等确有二维内容的区域允许局部滚动/缩放，但操作提示与退出入口必须可见。标题、长名称、URL、长段落与校对引文都要纳入压力样本。

常用触摸操作的命中区域拟定至少 44×44 CSS px，可通过按钮外层增加点击区域而不强迫图标变大；紧凑排列仍需避免相邻误触。交互不依赖 hover、右键、双击或实体键盘。保留浏览器缩放、系统文字选择、长按复制与正常页面滚动，不用禁止缩放或全局拦截触摸来掩盖布局问题。

### 14.3 正文编辑、软键盘与输入法

1. 手机正文以单栏编辑为主，章节目录、设定检索、本章资料和 AI 面板按需打开。工具栏可折叠/收进菜单，但保存入口和真实状态始终可达；不为了适配更换编辑器内核。
2. 软键盘打开、收起，浏览器地址栏展开、收起和横竖屏切换时，按实际可视区域重算布局，保证光标附近正文、当前输入与必要的提交/保存操作能看到。不只给所有区域固定 `100vh`；若引入额外视口 API，需能力检测并提供回退。
3. 视口变化不得通过强制 blur、重新挂载编辑器、重设正文值或自动收缩界面缩放来解决遮挡；不能打断中文组合输入、移动选区或制造布局/缩放循环。聚焦输入时只做必要的滚动定位，避免每键入一个字就将页面滚回顶部。
4. 验证中文输入、换行、标点配对、选区拖动、复制/粘贴、撤销/恢复、长文滚动和切章。与第 12 节输入法专项共用事实及证据，不另造按手机输入法品牌分支的补丁。
5. 编辑中切页、切章、关闭抽屉、打开手册或定位校对原句，继续经过既有草稿/保存保护。手机更改只影响视图和操作入口，不另建一套保存、撤销或正文缓存协议。

安全区域、浏览器工具条与软键盘分别取证。底部固定工具条、Toast、答疑输入框和模态按钮不得互相覆盖；键盘出现后不能把可编辑区压成零高，也不能让“关闭”变成只能通过刷新退出。

### 14.4 手机浏览器的数据、文件与后台边界

- 云端账号沿用现有保存/同步机制；跨设备查看前按实际同步结果说明，不把手机适配宣传成新增实时协作。游客数据沿用浏览器本地存储，不承诺自动同步到电脑或其他浏览器。
- 上传图片、选择资料、导入备份、导出作品/备份使用浏览器支持的文件选择和下载流程，明确成功/失败/取消。不能要求手机具备桌面固定路径、任意文件系统访问或桌面 IPC；图片异步处理仍绑定原项目和记录。
- 网络变慢/断开、会话过期、切后台、锁屏及系统回收页面分别验证。未保存就不显示成功，返回前台后重新核对真实任务和保存状态；不能把浏览器后台运行、关闭后任务继续执行或未落盘草稿恢复写成必然保证。
- 保留现有可用的重试、失败草稿和恢复机制；无持久化/服务端依据时如实说明任务中断或需要重新操作，不伪造“后台仍在运行”。适配不引入本版之外的离线写作同步系统。
- 手机模型配置遵守 P9 和第 13 节。手机上的本地回环地址不是电脑的回环地址；本地连接被禁用时，手机入口和各调用层也必须一致执行，不以移动布局另行放开。

### 14.5 与 3.3.1 其他功能共同交付

新手聚焦引导在手机上使用合适的说明卡片/底部面板，目标不可见时降级为可读步骤，不要求靠 hover 或鼠标完成。手册、AI 答疑和校对界面提供可滚动全宽面板，打开/关闭保留编辑现场；校对定位后能回到原结果，复制失败可直接选择文本。

方向键能力是可选的外接键盘操作，所有手机必需动作均有等价触摸入口。图鉴必须在没有实体键盘的情况下连续浏览；手机表格/地图不能以“接上鼠标或键盘后可以使用”作为完成标准。

P0 将现有页面清单扩为“页面/功能 → 手机布局 → 触摸入口 → 输入/保存 → 独立网页或项目内 → 证据与未验范围”的覆盖表。P10 先完成正文、表格、图鉴样板，再推广表单、卡片、画布、模型设置、酒馆及其余页面；不得只改样板后标全部完成。公共组件改造同步回归桌面、平板、小窗口和便携版。

### 14.6 验收范围与完成条件

自动化覆盖 320/360/375/390/430 CSS px 竖屏及 667×375、844×390 横屏，使用触摸配置检查布局、点击、滚动与基本流程。全页覆盖基础布局，代表页面再测长文本/宽表/无图与有图/空态/多记录/多主题/舒适与紧凑密度；无需所有维度做笛卡尔积，但失败应扩展同类页面复验。

至少使用一台 Android 手机的 Chrome 和一台 iPhone 的 Safari 验证真实触摸、软键盘、中文 IME、横竖屏、安全区域、文件/图片、复制与后台返回，记录型号、系统/浏览器版本、实际视口及网页部署版本。主机上的窄窗截图、桌面模拟触摸或其他浏览器成功，均不能代替这两类真机结论；微信/QQ 等内置浏览器未验则单列，不默认宣称支持。

完整走查路径为“手机打开网站 → 登录或游客进入 → 新建/打开项目 → 阅读与编辑设定 → 新建/编辑章节并实际保存 → 查看图鉴并连续换条目 → 使用引导/手册/答疑与校对 → 文件操作 → 返回并核对数据”。模型和账号使用隔离测试条件，保存要实际回读，不只看成功提示。

以 M01～M15 和全页覆盖表作为验收依据。没有 Android/iPhone 真机条件时标记待验收，不写成已完成；网站手机适配完成不代表已提供任何 Android/iOS 安装包。同步更新使用手册中的手机操作路径与限制，本文继续保留在 `docs` 主目录。
