# 青春幻想引擎 3.3.5 更新说明

> 一句话：**这一版让创作生成透明可信，让你的作品数据在任何异常、冲突与还原场景下都有确定性保护。**  
> 核心攻关「作品安全与可信创作」：续写实际发送清单透明装配、正文防篡改自动转候选保护、连写恢复三态判定与断点回滚、还原前强制自动预备份，以及中文长篇创作评测基线。

---

## 一、实际发送清单透明可控：AI 到底吃了什么资料，一目了然

以前点击续写时，作者往往不清楚后台到底拼装了哪些世界设定、大纲卡片或前文字数，容易担心模型越权伪装或隐式吃光上下文。

3.3.5 在颉文姬续写中落地了第一条全链路透明的「创作纵切」：

| 机制 | 以前的做法 | 3.3.5 的处理 |
|---|---|---|
| **实际发送清单** | 点击直接发送，不知带了哪几条设定 | 请求前展示完整发送清单，逐项标明章节正文、续写要求、参考资料、本章固定资料（Pinned）的装配状态（完整 / 裁剪 / 未带入及原因） |
| **字符与 Token 分离计量** | 字符数与 Token 混淆或模糊估算 | 字符与估算 Token 分离呈现，明确标注混合估算依据，超额时不静默裁剪核心规则并如实提示调整 |
| **本章固定资料** | 无法针对当前章临时指定特定资料 | 继承 ChapterContextPanel 固定语义，显式勾选「本章固定资料」后带入，清单内清晰标识 |
| **分层提示词与隔离栅栏** | 设定资料与系统规则混在一起容易提示词注入 | 使用 `<<<A-START-SECTION: ...>>>` 作者隔离栅栏封装资料与正文，严防设定伪装指令越权 |

## 二、冻结快照与正文防篡改：你写你的，AI 写 AI 的，绝不静默覆盖

当 AI 正在流式续写时，如果你突然灵感爆发在编辑器里自己修改了正文，以前的系统可能会在生成完成时直接覆盖你刚刚打下的字。

3.3.5 引入了**冻结快照比对与正文防篡改审阅候选机制**：

1. **预览与发送共用冻结快照**：预览清单后若你修改了勾选、正文或切章，快照指纹自动失效，要求重新确认，杜绝“显示 A 清单却发送 B 内容”；
2. **正文并发修改自动转候选**：若在生成期间检测到正文指纹发生变化（TOCTOU 冲突），系统**绝不直接覆写正文**，而是自动将本次续写产出保存为待审阅候选稿（沉淀至 `candidateStore`），界面弹出黄色冲突提醒，作者可在稍后比对并决定是否采纳。既不冲掉作者的新改动，也不丢弃 AI 的生成成果。

## 三、连写恢复三态判定与极端异常回滚

长篇连写往往跨越数小时甚至数天，遇到意外关机或异常退出时，需要安全可信的恢复机制：

- **细化为三态判定**：
  - `resumable`（平滑继续）：章节序列、字数、设定完好，一键无缝接着写；
  - `review-needed`（审阅确认）：检测到分卷调整、前置章有新增待核验、或尾随多出章等，呈现差异清单，作者审阅确认后继续；
  - `blocked`（严重破坏拦截）：检测到焦点章被删、字数严重倒流退回或散列严重不匹配，强制阻断，防范盲目生成破坏创作上下文。
- **存储异常内存即时回滚**：当连写检查点写入遇到磁盘满或 IndexedDB 异常时，内存立即回滚至上一有效检查点，彻底防范内存与磁盘状态分叉；多会话并发写互斥保护，正文并发抢写主动拦截。

## 四、还原覆盖前强制自动预备份（安全底座）

无论是导入备份包、版本还原还是云端覆盖，数据覆写都是最高风险的操作：

1. **覆盖前强制自动预备份**：在执行任何数据还原与覆盖前，系统强制先自动创建名为 `[还原前自动备份] ...` 的安全快照（完整包含现有参考资料与知识库），校验快照只读有效性；
2. **时间戳保持**：还原时完整保留历史原始 `updatedAt` 时间戳，解决云同步因时间戳变动产生的伪「云端更新」或覆写丢失隐患；
3. **部分成功透明报告**：知识库与复杂载荷导入如遇个别分片异常，明确返回 `partial` 状态码、成功/总数计数和失败原因，不再静默伪充全量成功。

## 五、中文长篇创作评测基线与评估集

- **12 个典型中文评测场景**（`evalDatasets335.ts`）：
  - 覆盖仙侠修真、末日悬疑、赛博武侠、古风宫闱、硬核科幻、高武玄幻等 6 种以上长篇题材；
  - 包含对抗性指令注入、设定矛盾（战力崩坏、人物死而复生）等边界测试。
- **五维盲评流水线**：
  - 材料保真度（Faithfulness）、情节连贯性（Continuity）、文风拟合度（Style Fit）、指令遵循（Instruction Following）、矛盾控制（Contradiction Control）五维评分工具。

## 六、边界与已知限制（如实透明说明）

依据《3.3.5 开发规划》规范，本版实测与客观条件边界如下：

1. **工程门禁全绿**：全量 414 门自动化单元测试 100% 通过，六维全量静态审计 0 候选缺陷，浏览器续写纵切端到端探针 27/27 全绿，本地全链路可靠性流水线 29 项 passed。
2. **客观条件限制声明**：
   - 实体物理手机和平板已依用户决定明确豁免（纯逻辑与响应式均经测试覆盖）；
   - 外部商业付费大模型、跨物理设备二次联调、物理断电等因环境限制未做伪造打卡，系统保持客观透明记录（`verdict.code=2: required evidence incomplete`）。
