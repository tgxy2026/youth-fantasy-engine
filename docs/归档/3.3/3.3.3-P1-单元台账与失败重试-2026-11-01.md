## 1. 先修的真缺陷：抽取失败被当成「本章没有设定」

`src/lib/bookbreak/run.ts` 原用 `aiExtractSettingEntities()`。它在内部 `catch` 后返回 `[]`，
于是**请求失败、解析失败与"合法空结果"完全相同**；`run.ts` 里的 `failedUnits.push(...)`
只可能被抛出的异常触发，而那条路径永远走不到。

⇒ 改用 `aiExtractSettingEntitiesWithStatus()`：

| 状态 | 处理 |
|---|---|
| `completed`（含合法空数组） | 结果落盘 → 标 `succeeded` |
| `failed` / `partial` / `incomplete` 等 | 记 `failed` + 有限原因码（`parse-invalid`、`timeout` 等），**不塞空结果** |
| `cancelled` | 记 `cancelled` 后抛中止（流程记 cancelled，不记失败） |

这条不修，A4「失败单元重试」就没有输入，B3「只补剩余」也会把失败单元当成功跳过。

## 3. 核心契约

### 3.1 身份（原文变了不会错用旧产物）

- 原文指纹：`t1:` + FNV-1a(全文) + 长度；**台账不存原文**。
- 配置指纹：`c1:` + 稳定序列化哈希，只含**影响抽取**的参数
  （`maxChunks / maxUnitChars / maxUnits / chunkTokens / titleSamples / 协议版本`）。
  界面开关（写入正文 / 汇总设定 / 整理关系）**不进指纹** —— 否则关掉一个开关就丢掉已完成进度。
- 任务 id：`bookbreak-extract:<hash(projectId, 原文指纹, 配置指纹, 协议版本)>`，
  确定性推导 ⇒ 同一本书同一套参数重跑自然落到同一条任务。
- 单元键：`hash(原文指纹, 配置指纹, 协议, 下标, 单元文本指纹)`。

### 3.2 状态与恢复

```
pending → running → succeeded | failed | cancelled | interrupted
failed → running（仅作者显式「只重试失败单元」）
succeeded 终态（要重跑 ⇒ 换任务 / 从头重跑）
running 重启后一律降 interrupted（结果本来就没落盘）
```

| 入口 | 会跑哪些单元 | 不会跑哪些 |
|---|---|---|
| 继续抽取（只补剩余） | pending / interrupted / cancelled | succeeded（复用）、**failed（不自动重试）** |
| 只重试失败单元 | 仅 failed | pending / interrupted / cancelled / succeeded |
| 从头重跑 | 全部（先删本任务私有产物） | — |

### 3.3 写序与执行权

- `beginUnit` → 模型 → `settleUnit`（结果与 `succeeded` **同一条记录一次写入**）→ 合并进批次。
  没有"标了成功却没有产物"的窗口；桌面/便携要等 `flush` 成功才返回。
- `claimTask` 递增 `generation` 并写 `ownerId`；每次写前重读任务头比对，
  旧执行者的晚回包抛 `TaskExecutionLost`（界面/管线据此停写，结果照常交付但不覆盖别人）。
- `freshStart` 先清任务私有产物再建头；删项目按 `projectId` 级联清理两个 store。

### 3.4 容量与降级

- 每项目最多 5 个拆书记录、单任务 20 MiB、合计 50 MiB，按 UTF-8 实字节累计。
  超限**暂停并给出可操作原因**（去清理旧记录），不淘汰未完成任务。
- 存储本身不可用（隐私模式 IDB 打不开 / 数据文件只读）⇒ 台账返回 `null`，
  拆书退回"只在内存里跑"的旧行为；结果里 `unitSummary.attached=false`，界面如实写
  「本次进度未落盘，重启后不能接着跑」。配额超限**不走降级**，必须让作者看见。

## 4. 界面变化（BookBreakPanel）

- 只有当前原文与台账指纹对得上时才显示「本机留有这份书的拆书记录：已成功 X/Y · 失败 F · 中断 I」。
  重启后需重新导入同一份原文（台账不存原文）；对不上就是另一个任务，不会冒充可续跑。
- 主按钮：`继续抽取（只补剩余 N）`；只有失败单元时改为「没有待补单元」并禁用。
- 次按钮：`只重试失败单元（M）`、`从头重跑（丢弃断点）`、`丢弃本机记录`。
- 失败清单优先显示本次结果，否则显示台账留存（重启后仍能查到位置与原因码）。
- 文案删去旧的「本页暂不支持只重试失败单元」。

## 6. 未做 / 待验（不得当通过）

1. **真机强杀**：请求途中、结果落盘前后、状态更新前后强杀重开 —— 需桌面/便携实机。
2. **双窗口竞争**：两个窗口同时接管同一任务的现场证据（单测只覆盖 generation 拒绝）。
3. **容量压测**：100 章 × 5000 字 + 结果字节逼近 20/50 MiB 的耗时与暂停路径。
4. **降级路径实机**：隐私模式 / 只读数据文件下"本次不留断点"的提示。
5. **A-06 请求计数**：50 单元第 37 失败 → 重试请求恰为 1 的全链路计数（需可控模型桩）。
6. 任务结果**未外置** sidecar（与 `revisionPayloads` 同级放主库）；大书写盘体积需 P0 压测后决定。
7. 创意写作尚未接同一台账（本包只接拆书；B3 的另一半在后续批次）。

## 7. 风险与取舍

- 台账 id 是确定性推导：同一本书 + 同一套参数只保留**一条**任务记录。
  要保留两次独立运行的结果，得改参数（配置指纹变化）或先丢弃旧记录 —— 当前是有意的。
- `taskHeads` / `taskUnits` 进 `LOCAL_ONLY_STORES`：云同步、项目包、另一台设备都不会带它们；
  整库数据文件（本机备份）会带，导入后也不会自动续跑（必须作者重新导入原文并点继续）。
- 执行权是**任务级代次**，不是跨进程锁：两个窗口都可能在跑模型调用，
  但只有代次最新的一个能把结果写进台账。这一点在界面文案与验收里都要如实说。
