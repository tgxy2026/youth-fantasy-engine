# 3.7.6 版本开发规划方案 · 各类表单页签自定义字段完善与强化

**日期**：2026-11-28 · **基线**：`3.7.6`（HEAD `6052d4f`，门禁 `tsc 0 / eslint 0 / 534/534`）
**目标**：围绕全站各类表单、卡片与表格页签的「自定义字段」功能，先彻底消除已核实的链路割裂与数据错乱隐患，再借鉴业界动态表单与 Schema 演化最佳实践，分阶段补齐并强化表单/卡片页签的自定义字段能力。

---

## 一、背景与当前项目状态核实

1. **已完成前置（Q-11 / Q-12，2026-11-28）**：
   - **Q-11**：统一设定条目取名入口（`src/lib/settings/rowTitle.ts`）、补全 `effectiveSearchMeta` 的 `atlasField.label` 与 `fieldAlias` 兜底、为 `AtlasFieldManager` 接入内置字段同名/近义拦截（`src/lib/atlas/fieldNameGuard.ts`），并在 `dataHealth.ts` 第 6 类提供「合并到内置 / 归档字段」修复。
   - **Q-12**：核实多页签自定义字段在定义（`atlasSchema::<tabId>`）、显示名（`fieldAlias::<tabId>`）、模板（`projectTemplate32:<tabId>`）、行数据（按 `tabId` 索引）四层完全隔离，新增 `tests/atlasTabIsolation.test.ts`（22 条）。
2. **现状割裂与已核实隐患（本轮调研结论）**：
   - **覆盖面不均**：仅 4 个图鉴表格（`races` / `items` / `nations` / `geography`）有轻量「字段设置」+「模板」；3 个角色卡（`char-main` / `char-secondary` / `char-npc`）仅能通过「套用模板」加自定义字段；5 个纯表单页签（`positioning` / `worldbase` / `power` / `master` / `style`）、3 个其他卡片页签（`misc-settings` / `volume-outline` / `chapter-outline`）以及 15 个常规表格页签完全不支持自定义字段。
   - **5 处已核实隐患**：
     1. `src/lib/search/search.ts` 仅硬编码读取 `races` / `items` 的 `atlasSchema`，漏掉 `nations` / `geography` 及全部 `TemplateDef`；且标题仍使用旧回退逻辑，未接入 `resolveRowTitle`。
     2. `TemplateFieldEditor.tsx` / `TemplateManagerDialog.tsx` 未接入 `builtinFieldNameConflict` 同名校验，模板侧仍可造出与内置列同名的字段，复发「同条记录两套名字」错乱。
     3. `TemplateFieldEditor.tsx` 开放了全部 12 种 `TemplateFieldType`，但 `consumers.ts` 的 `customTypeOf` 仅映射 6 种基础类型，导致选择 `date` / `calendar` / `tableRef` / `character` / `characters` / `other` 时在卡片/表格中静默退化或不可用。
     4. 角色卡 CSV 导出/导入（`CharacterSheet.tsx` + `cardIO.ts`）仍只展开静态 `tab.modules`，未消费 `EffectiveTemplate`，导致模板自定义字段在 CSV 往返中丢失。
     5. 图鉴页签在「字段设置」与「模板」双轨切换（尤其是「放弃自定义模板」后）可能留下页面不可见但 `row.data` 仍存在的孤儿 `cf_*` 数据。

## 二、业界最佳实践借鉴与架构对齐

结合动态表单（JSON Document + Centralized Registry）与 Notion / Airtable Schema 演化的成熟实践，提炼四条落地原则并对齐本仓库既有规范：

| 业界实践 | 对齐本项目的设计与强化点 |
| --- | --- |
| **1. 存储键不可变契约（Immutable Field Keys）** | 坚持 `cf_<uid>` 永不改变、仅改 `label`；所有消费面（表格、卡片、纯表单、检索、AI、导出）统一以 `EffectiveTemplate` / `sourceKey` 为唯一真源，禁止按显示名反查数据。 |
| **2. 软删除优先与孤儿数据治理（Soft Delete & Orphan Lifecycle）** | 延续「归档优先、不删值」；同时在 `dataHealth` 增加**孤儿 `cf_*` 键体检**（如放弃模板或导入老包后 `row.data` / `formData` 中存在当前定义已不可见的 `cf_*` 有值字段），给出只读提示与「恢复可见 / 安全归档」路径，杜绝数据静默隐身。 |
| **3. 严格类型边界与无损演化（Safe Type Evolution）** | 不允许在编辑器中创建无控件支撑或只读占位类型（如 `other`）；类型转换继续坚持「逐值可逆预览 + 不可逆整批阻止 + 写前自动备份」，不做 Notion/Airtable 式的静默截断强转。 |
| **4. 中心化校验与修订号防漂移（Versioned Contract）** | 写入侧统一收口领域校验（同名冲突、`appliesTo` 非空数组、配额与长度上限），并沿用 `revision` / `semanticDigest` 拦截异步任务或 AI 旧基准回写。 |

## 三、分阶段开发规划

### 阶段一（P0）：止血与全链路一致性闭环（优先交付）

目标：消除已核实的 5 处 Bug 与数据错乱隐患，确保现有支持自定义字段的 7 个页签（4 图鉴 + 3 角色卡）在编辑、检索、导出、体检全链路行为一致。

1. **P0-1 · 模板侧接入同名/近义冲突拦截**
   - 在 `TemplateFieldEditor.tsx`（或 `TemplateManagerDialog.tsx` 创建/改名提交前）复用 `builtinFieldNameConflict`（`src/lib/atlas/fieldNameGuard.ts`），拦截与当前页签内置字段（含别名）同名或名称类近义的自定义字段。
   - 同步核查 `dataHealth.ts` 第 6 类检查：目前第 289 行 `if (!isAtlasTab(t.id)) continue` 仅扫描了图鉴 4 表，需评估并按需扩展至已套用模板的角色卡页签，检测历史遗留的同名冲突。
2. **P0-2 · 设定/全文检索真源对齐（`src/lib/search/search.ts`）**
   - 将硬编码的 `['races', 'items']` 替换为 `ATLAS_TABS` 全量，并同步读取 `loadTemplateDef`；
   - 表格类检索标题统一走 `resolveRowTitle`（`src/lib/settings/rowTitle.ts`），彻底消灭空内置名回退到编号的残留；
   - 角色卡检索正文按 `EffectiveTemplate`（`purpose: 'search'`）过滤已归档或关闭搜索权限的字段，并带上可读字段名。
3. **P0-3 · 模板字段类型收敛与控件对齐**
   - 在 `TemplateFieldEditor.tsx` 中：对 `source === 'custom'` 的字段，禁止选择 `other`（只读占位）及当前暂无自定义控件/目标元数据的类型（或明确收敛为受 `AtlasCellInput` 完整支持的六大基础类型：`text` / `textarea` / `number` / `select` / `multiSelect` / `boolean`）；内置字段保留其既有类型展示。
4. **P0-4 · 角色卡 CSV 导出/导入对齐有效模板**
   - 扩展 `src/lib/storage/cardIO.ts` 与 `CharacterSheet.tsx`：导出与生成导入模板/引导时，优先读取 `EffectiveTemplate`（含模板新增的 `cf_*` 字段、自定义分组字段与最新 `label`），与 `TableSheet` 保持同口径（同时保留按存储键兜底映射，兼容旧 CSV）。
5. **P0-5 · 孤儿自定义字段检测与双轨提示**
   - 在 `TemplateManagerDialog.tsx` 放弃自定义模板前，若检测到模板内存在 `atlasSchema` 中没有的已填 `cf_*` 字段，弹出明确受影响条目数提示；
   - 在 `dataHealth.ts` 中新增「已失效/孤儿 `cf_*` 键」检查项（排在既有检查之后，不打乱历史忽略 id），为作者提供查看位置与「写回定义恢复显示」的安全入口。

### 阶段二（P1）：扩展「纯表单」与其余「卡片/大纲」页签的自定义字段能力

目标：让作者在核心创作设定页签中也能自由追加自定义字段，且不破坏既有的 `模块::字段` 存储结构与母子世界同步机制。

1. **P1-1 · 适用范围规划**
   - **第一批（纯表单页签）**：`positioning`（作品信息）、`worldbase`（世界设定）、`power`（力量体系）、`master`（全书总纲）、`style`（写作规范），以及共用 `SchemaFieldGrid` 的子世界/平行设定表单（`WorldSetSheet` / `ParallelSetSheet`）。
   - **第二批（其余卡片/大纲页签）**：`misc-settings`（其他设定）、`volume-outline`（分卷大纲）、`chapter-outline`（章节细纲）。
   - *注*：15 个业务逻辑强驱动的常规表格页签（如 `relations`、`chapter-master`、`foreshadow`、`timeline` 等）结构与代码逻辑强耦合，本版暂不开放自由加列，维持 `FieldAliasButton` 改名。
2. **P1-2 · 统一轻量扩展机制（复用而非另起炉灶）**
   - 复用 `cf_<uid>` 存储键（直接存入 `formData` / `CardRecord.data`），字段定义沿用轻量 Schema（按 `tabId` 隔离存储，带 `revision` 锁与写前备份），支持分组归属（挂载到表单已有模块或自定义模块）、六种基础类型、说明/示例、排序与归档恢复。
   - 改造 `SchemaFieldGrid.tsx` 与 `OutlineSheet.tsx` / `CharacterSheet.tsx`：内置字段继续走原控件，自定义字段统一复用 `AtlasCellInput`（或适配表单宽度的同源控件），实现「表单页只渲染一套网格、无样式漂移」。
   - **子世界/平行设定与进度统计边界（二次复核补记）**：
     - `WorldSetSheet` 与 `ParallelSetSheet` 共享母页签（`worldbase` / `power`）的 `tab.modules`，其子世界记录存在 `subTabIdOf(tab.id)` 对应的 `CardRecord` 中，因此子世界必须**继承母页签的自定义字段定义**（按 `tab.id` 读取 Schema，不按 `subTabId` 另建一套）。
     - `FormSheet.tsx` 的进度统计 `filledCount` 目前按 `Object.values(data)` 计数，引入可归档自定义字段后必须改为**仅按当前未归档有效键集合计数**，防止归档/孤儿 `cf_*` 键导致出现 `12 / 10 项已填` 的统计错乱；离开前草稿补存与清空确认同步对齐。

### 阶段三（P2）：AI、语义索引、检索与导出全链路联动强化

1. **AI 补全、上下文与语义索引解锁（二次复核补记）**：
   - `src/lib/semantic/fieldRules.ts`（第 112 行）与 `src/lib/ai/atlasContext.ts`（第 83 / 137 行）目前均以 `!isAtlasTab(tab.id)` 截断，导致即便是已支持 `TemplateDef` 的角色卡页签，其自定义字段的 `aiReadable` / `aiWritable` / `archived` 权限也未接入统一通道。需将其与纯表单/卡片自定义字段一并打通：
     - `FormSheet`、`OutlineSheet`、`CharacterSheet` 构造 `AITemplateFill` 的 `fields` 列表及 `aiContext` 时，纳入未归档且允许 `aiRead` / `aiWrite` 的自定义字段（带 `type` / `options` / `unit` / `description` / `example` 提示）；
     - `fieldRules.ts` 对有自定义字段/模板的页签按 `EffectiveTemplate` 过滤索引字段，避免关闭「允许 AI 参考」或已归档的字段泄漏进向量索引。
2. **设定检索与正文引用**：纯表单与大纲页签的自定义字段自动进入 `SettingSearch`（含 `effectiveSearchMeta` 扩展至 `form` 类型）与章节上下文参考，支持按显示名检索与跳转定位。
3. **全量导出/备份/世界观打包兼容**：确认项目备份、云同步（`settingsKV` 默认随项目走，不进 `EXCLUDED_META_KEYS`）、世界观打包（`worldPack.ts` / `worldImport.ts`）与文档导出（TXT/Markdown/Word）均完整携带表单自定义字段定义与值，旧版本导入时保持保守降级不覆盖。
