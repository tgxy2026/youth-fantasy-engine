## 1. 版本目标与边界

**目标（四条，各自可判定）**

| # | 目标 | 判定方式 |
| --- | --- | --- |
| G1 | 正史变更有记忆：大纲/正文/设定任一变更，受影响的未来章、候选、推演、对照报告都能被标记 | 四条变更路径各有负向断言（变更前无标记→变更后有标记→处置后清除）；休眠代码接线后 `tests/generationInvalidationGate.test.ts` 的 gap 记账关闭 |
| G2 | 追踪补全：物品流转逐笔可查、设定状态按章可回溯 | 「东西送人了正文还写旧持有者」能被连续性检查检出；「第 N 章时某角色什么状态」能从演变记录程序化回答 |
| G3 | 观察不评判：节奏曲线与投稿体检全部是事实呈现，无评分无评级 | 新增立场断言（沿 `tests/platformCheck.test.ts` 禁词模式）：新面板源码与产物文案不含「评分/评级/排名/合格」类词 |
| G4 | 语音灵感可用且隐私如实：录音→转写→灵感夹，音频去向明示 | 真机走通一条；未配置转写服务时录音入口如实说明不可用原因；音频只发往作者自配服务 |

**边界（本版不做）**

- **不突破「不评分」红线**：W5 曲线只用本地确定性指标（密度/间隔/占比/波动），W6 体检只汇总既有定性结论。AI 评分持久化与全书评级不做（D1 已拍板维持红线）。
- **不做应用内任务链/技能包**（D2 已拍板）；不做多分支并排推演视图（现有剧情候选列表已算弱对比，扩视图另议）。
- **不做酒馆↔小说情绪数据桥**：酒馆心情数值是扮演会话状态机，与正文追踪隔离是既有设计，本版不打通。
- **不做 EPUB 封面/CSS/选章体系扩展**：只修孤儿章缺陷（W8），形态打磨另议。
- **不做任何自动写库**：W3/W4 的新抽取一律走「候选→作者勾选确认」，沿 `chapterPostProcess.ts:11-15` 铁律（只追加不覆盖、未登记只提示不凭空建条目）。
- **不做静默录音**：录音必须作者显式点击开始/结束，界面有进行中指示。
- **不改 3.6.4 已提交契约**：字数口径（text/text-punct）、排行按项目抵扣、搜索替换范围口径。

**贯穿纪律**

- 先红后绿；涉及存储/落库的改动必须附失败路径断言。
- 每包结束跑：`typecheck` / `eslint --max-warnings 0` / 相关专项 / 全量单测。
- 收工跑：`node scripts/audit/self-check.mjs` + 六维与全量审计 + `node scripts/release-check.mjs --source-only`。
- 改文案必须同步改断言（`tests/uiStatusCopy.test.ts` 等文案闸）；改审计工具后必须重跑审计。
- 新增页签/表必须过 migrationGuard 与备份往返（JSON 导出→导入不丢新表）；新增 settingsKV 键必须确认云同步覆盖。
- 验证范围如实记录：局部通过≠版本验收；跑不了的写「未跑」并说明卡在哪。
- 封装/部署/推送/发布须用户明确口令；审计运行期间不改工作树。

#### W1.2 开发内容

1. **db 收口点变更通知（R1 修正后的统一地基，W1/W2 共用）**：
   - 新增：src/lib/db/changeBus.ts —— 零依赖轻量通知器（订阅/发射，同步注册、异步消费），db 层只发事实 `{ pid, kind: 'form'|'row'|'card'|'chapter', tabId, recordId }`，**不做任何业务判断**，避免 db↔revision 循环依赖。
   - 四个收口点接线：`src/lib/db/tabs.ts` 的 `saveFormDataFor`:37 / `saveTableRow`:71 / `saveCardRecord`:112，`src/lib/db/chapters.ts:31` `saveChapter`。写库成功后发射；**发射失败不得影响保存结果**（try/catch 隔离，保存是主路径，打标是旁路）。
   - 新增：src/lib/revision/changeWatch.ts —— 应用启动时注册消费者，按 tabId 分流：大纲三类→W1 影响标记；正文/设定→W2 过期接线。**批量写合并**：导入/AI 整理/MCP 批量写入会连发几十上百条，消费者按项目 300ms 防抖合并成一次分析，不逐条跑。
2. **大纲变更影响标记**：消费者收到总纲（`master`，form）/卷纲（`volume-outline`，row）/细纲（`chapter-outline`，card）变更后调 `analyzeFutureImpact`，reason 分别为「总纲变更」「卷纲变更」「细纲变更」，证据用变更前后字段值（沿 `buildChangeEvidence` 口径；form/row/card 三类各取各的读法）。
   - 细纲变更：沿现有章号维度（> 该章的未开写章）。
   - 卷纲变更：影响范围 = 该卷全部未开写章（章号维度换算成卷范围，`futureImpact` 增加可选 `volumeId` 过滤，纯函数扩展）。
   - 总纲变更：影响范围 = 全部未开写章；**已写章节只列「建议复核清单」不自动打标**（已写章是否受影响是语义判断，确定性规则判不了，如实呈现给作者）。
   - 空变更（保存未改值）不打标：消费者比对前后值，相同则跳过。
3. **兑现注释承诺**：`commitPost`（章后整理确认入库）成功后调 `analyzeFutureImpact`，reason「章后整理」（此路径不经 changeBus，整理落库走 `applyPostProcess` 内部多次写，逐条发射会风暴，直接在确认成功后调一次）。
