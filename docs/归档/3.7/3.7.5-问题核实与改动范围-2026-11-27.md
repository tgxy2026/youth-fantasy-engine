## 1. 逐条核实

### Q-01 · 小窗口背景透明度没有规范

**实测**（`grep -rhoE "bg-ink-[0-9]+/[0-9]+"` 全仓统计）：

| alpha 组合 | 出现次数 | 组合 | 次数 |
| --- | --- | --- | --- |
| `bg-ink-900/40` | 125 | `bg-ink-850/95` | 15 |
| `bg-ink-800/60` | 84 | `bg-ink-800/70` | 14 |
| `bg-ink-850/40` | 58 | `bg-ink-800/50` | 14 |
| `bg-ink-900/60` | 55 | `bg-ink-900/70` | 11 |
| `bg-ink-900/50` | 37 | `bg-ink-850/88` | 8 |

- 不同 alpha 值合计 **57 种**（`sort -u` 精确计数）；另有 `bg-ink-900`（434 处）等实色。
- **`.ws-surface`（index.css:732）只定义阴影**，不提供背景色 —— 所以每张卡各自写透明度，这正是"随机"的来源。
- 主题共 **9 套**：dark / mono / eye-care / midnight / sepia / dusk-violet / porcelain / pine-ink / peach-note。浅色系（eye-care / sepia / porcelain / peach-note）若沿用暗色的 0.55，会透出背景纹理导致正文对比度不足 ⇒ **令牌必须按主题给不同值**。

**改法**：
1. `index.css` 的 `@theme` 增加 4 个语义变量，每个主题各给一组：`--yfe-l1`(容器) / `--yfe-l2`(内容卡) / `--yfe-l3`(卡内块) / `--yfe-l4`(浮层)。
2. 新增 4 个工具类 `.yfe-surface-1..4`（背景 + 边框 + `backdrop-filter` 磨砂；L1 不加磨砂）。
3. 新增 `src/lib/ui/surface.ts` 导出类名常量，**禁止新代码写任意 alpha**（可在结构闸加一条：新增 `bg-ink-*/非标准值` 报警）。
4. 按"容器=2、卡内块=3、浮层=4、页面底=1"替换；**输入框 / 徽标 / 进度条等小块不动**（它们本来就该是点缀）。

**风险**：浅色主题对比度（需 4 个浅色主题逐一目视）；表格 sticky 表头必须保持实色（现在是 `bg-ink-800` 实色，改造时不能跟着变半透明，否则滚动时下面行会透出来 —— 源码 :814 已有这条注释）。

**建议不纳入本轮**：图纸/画布（地图编辑、情节推演）的画布底色，它们是内容区不是卡片。

### Q-02 · API 模式页左右两栏失衡

**根因**：`src/components/settings/AIConfigPanel.tsx:76`

```ts
const LIST_GRID = 'grid grid-cols-1 xl:grid-cols-[minmax(0,1fr)_20rem] gap-x-6 gap-y-5 items-start'
```

- 左栏 `minmax(0,1fr)` 在宽屏没有上限 ⇒ 「添加本机模型 / 添加联网模型」被拉成一米长；
- 右栏写死 `20rem`（320px）⇒ 三个用途下拉 + 超时输入被挤。
- 该常量**只在这一处使用**（:541），所以改动是局部的，不会误伤其它设置页。

**改法**：
- `xl:grid-cols-[minmax(0,1fr)_minmax(19rem,24rem)]`，`2xl:grid-cols-[minmax(0,1.6fr)_minmax(21rem,28rem)]`；
- 两个「添加…模型」按钮在 `sm` 以上改**并排两列**（现在各占一整行）；
- 左栏列表加 `max-w-[52rem]`，避免超宽屏继续拉长。

**风险**：低。需在 1280 / 1440 / 1920 三档宽度目视。

### Q-03 · 沉浸式阅读模式（新功能）

**现状核实**：
- **没有**任何阅读器组件（全仓无"阅读模式"实现）。
- 正文数据：`Chapter.content`（`types.ts:198`）为纯文本；编辑器是"textarea + 高亮叠层"，**不是 HTML 渲染** ⇒ 阅读器可以直接按段落渲染纯文本，无需处理 XSS。
- 卷章数据齐备：`db.getAllVolumes()` / `db.getChapters()`（或按项目取），章节有 `order`、`excludeFromNumbering`、`status`。

**入口一**：`ProjectHub.tsx:845–862`，现有两个 `size="md"` 按钮（打开项目 primary / 编辑项目 secondary）在同一 `flex gap-2.5` 行内。加第三个按钮后，卡片左半区（封面 212px + 文字区）在 1440 宽下约剩 300–360px，三个按钮（约 96+88+88 + 间距）刚好 —— 需要把三枚按钮统一改 `size="sm"` 或压缩 `px`，**实测后再定**，否则会换行。
**入口二**：`NovelEditorChapterTree.tsx:295–320`，章节栏头部是图标按钮组（导入 / 新建卷 / 新建章节 / 更多），插入一枚 `BookOpen` 图标按钮即可，无文字。

**新组件建议**：`src/components/reader/ReaderModal.tsx`
- 结构：`Modal` 全屏（`width="full"`）+ 左侧 240px 卷章列表（复用现成的卷章树数据，只读）+ 右侧正文（`max-w-[46rem] mx-auto`，行高 1.9，首行缩进可关）。
- 交互：滚轮原生滚动；滚动到距底 ≤ 24px 且**停留 300ms** 才自动跳下一章（防触控板惯性误触发）；到最后一章提示"已是最后一章"。
- 只读：不写库、不触发 `touchProject`。
- 可选（待定）：字号三档 / 护眼与暗色跟随主题 / 进度记忆（存 `uiPrefs`）。

**风险**：中。主要风险是"自动跳章"与用户手动回滚的冲突，以及长章节（2 万字）滚动性能 —— 纯文本段落渲染通常没问题。

### Q-04 · NPC 角色立绘位置

**根因链**（已逐行确认）：
1. `src/lib/templates/render.ts:178`：`isBasic: g.label.includes('基础信息')`；
2. `char-npc` 只有一个模块，名为 **`NPC档案`**（`schemaTabs/part1.ts:259`）⇒ `isBasic=false`；
3. `CharacterSheet.tsx:1075` 只在 `isBasicMod` 时把立绘放进右侧栏；
4. 于是落到 `CharacterSheet.tsx:1085` 的兜底分支 —— 渲染在所有模块**之后**，整行横铺 ⇒ 就是您截图里"跑到最底下、右侧一大片空白"。

**改法（推荐 A）**：把判定放宽为"第一组也算基础组"：`isBasic: g.label.includes('基础信息') || g.order === 0`。
- 与既有逻辑自洽：同文件 231 行默认展开就写的是 `g.isBasic || index === 0`；
- 只影响角色卡三页签（`isCharacterCardTab` 才渲染立绘），其他卡片页不受影响；
- 改后 `1085` 的兜底分支基本成为死代码，可保留作防御。

**改法（不可取 B）**：把 NPC 模块改名成「一、基础信息」——会改存储键 `模块名::字段名`，**老数据全部读不出来**，否决。

### Q-07 · 新增一行不跳到新行

**根因**：`useTableSheetModel.ts:596 addRow()` 只做 `saveTableRow` + `setRows([...rows, row])`，**没有任何滚动**；而表格用虚拟行窗口（`useRowWindow`），末尾新行很可能**不在渲染区间**，所以即使滚到底也未必看得见。

**现成能力**：`useRowWindow.ts:224 revealId(id)`（滚动 + 扩展窗口），已被 `focusRowId` 路径复用（`useTableWorkspaceScroll.ts:88`）—— 不需要新写滚动算法。

**改法**：`addRow` 成功后把 `row.id` 记为一个 `pendingRevealId`，`TableSheet` 在 rows 更新后 `requestAnimationFrame` 里调用 `rowWindow.revealId(id)`；判定"是否已在可视区"由 `revealId` 内部完成（已在视野则不滚，正好符合您要的"内容少就不跳"）。

**影响面**：同 Q-06 的 18 表 + 卷台账（同组件）。
**风险**：低–中。需验证两件事：① 新增后滚动不被 workspace 视图恢复（capture/restore）覆盖回原位；② 人物关系页新增后仍自动展开「未命名关系」分组（现有逻辑 :607）。

### Q-08 · 分栏表单卡片高度不齐

**根因**：`src/components/common/SchemaFieldGrid.tsx:50–54`

```tsx
<div className={`... ${twoColumn ? 'grid grid-cols-1 xl:grid-cols-2 gap-5 items-start' : ...}`}>
  {modules.map(mod => (
    <section ... className="... rounded-xl ... h-full ws-surface">
```

- `grid` 的一行里所有卡片共享行高；`h-full` 让**短卡也撑到行高** ⇒ 卡片内部尾部出现大片空白（截图 1 的观感）。
- 若去掉 `h-full`，短卡就会**露出页面背景**（截图 2 的观感）—— 这就是您说的"两种都不好看"。

**改法（已定方案 A 的落地形态）**：把网格改成**多列流**（CSS `columns`）：

```
columns-1 xl:columns-2 gap-5 [column-fill:balance]
section { break-inside: avoid; }   /* 卡片不被拆到两列 */
```

- 效果：卡片高度**按内容自然收尾**，下面立刻接同列下一张 ⇒ 既没有卡内空洞，也没有背景裸洞；
- DOM 顺序不变 ⇒ 键盘 Tab / 读屏仍按 一、二、三、四（满足已定约束）；
- 视觉上从"两两并排"变成"报纸分栏"（左列 一、二；右列 三、四），这是唯一的观感取舍。

**影响面**：`SchemaFieldGrid` 被 3 个组件复用 ⇒ 覆盖 6+ 表单页（作品信息 / 全书总纲 / 写作规范 / 世界设定 / 力量体系 / 制度四页 / 子世界表单）。**一处改、全站生效**。
**风险**：中。需实测：① `@container/fields` 容器查询与 `columns` 共存；② `divide-y` 行分隔在多列下是否仍正确；③ 窄屏单列回退；④ 打印/导出不受影响（导出不走这个组件）。
