# 3.7.6 第二批开发规划方案 · 全链路真源对齐与上下文隔离强化

**日期**：2026-11-28 · **基线**：`3.7.6`（第一批自定义字段完善与强化已完成，门禁 `tsc 0 / eslint 0 / 535/535`）
**目标**：将第一批巡检发现的 5 项全链路脱节与异步上下文隐患全部闭环——打通设定集导出、AI 主上下文、世界观打包导入、语义向量索引与自定义字段/模板真源的统一对齐，并收口后台/聚合链路的显式 `projectId` 隔离边界。

---

## 一、背景与现状核实

在完成第一批（P0–P3）自定义字段完善与强化后，项目内「表单 / 卡片 / 表格」三类页签均已具备自定义字段与模板能力；但全仓巡检核实发现，仍有 5 条下游消费与底层数据链路未完全对齐到 `EffectiveTemplate` / `atlasSchema::<tabId>` / 显式 `projectId` 真源：

1. **全书设定集导出（`src/lib/storage/exporter.ts` 第 517–567 行）**：
   - 纯表单页签只遍历静态 `tab.modules`，漏掉纯表单 `cf_*` 自定义字段与 `fieldAlias` 显示名；
   - 表格与卡片页签直接遍历 `Object.entries(data)`，将 `cf_<uid>` 原始键直接暴露进 Markdown 设定集，且未过滤已归档字段。
2. **AI 上下文组装（`src/lib/ai/aiContext.ts` 第 332、428、489–522 行）**：
   - `table` 分支对图鉴页签调用 `loadAtlasFieldsForAI` 读取权限与显示名，但 `form` 与 `card` 分支（`renderForm` / `renderCards`）未消费 `TemplateDef` 或 `atlasSchema::<tabId>`，导致角色卡模板和纯表单自定义字段的「允许 AI 参考 / 归档」开关及自定义显示名在主上下文注入时未生效。
3. **世界观打包导出与导入（`src/lib/world/worldPack.ts` 第 91–130 行、`src/lib/world/worldImport.ts` 第 111–165 行）**：
   - 仅对 `isAtlasTab(spec.tabId)` 附带并重映射 `atlasFields` 定义；`worldbase` / `power`（`form` / `sub`）及 `misc-settings`（`card`）只导出 `data` 里的 `cf_*` 值而漏带字段定义，导入到新项目后变成无定义的孤儿键。
4. **语义向量索引范围（`src/lib/semantic/indexer.ts` 第 311–333 行）**：
   - 主索引循环只收集 `table` 与 `card`，未收集 `form` 类页签（`positioning` / `worldbase` / `power` / `master` / `style`），致使第一批刚在 `fieldRules.ts` 为纯表单补齐的索引规则暂无实际索引条目落地。
5. **隐式全局项目读取（`db.getFormData` / `getTableRows` / `getCardRecords`）**：
   - 后台与聚合链路（`aiContext.ts`、`exporter.ts`、`worldPack.ts`、`indexer.ts`、`search.ts`）仍广泛依赖隐式全局 `currentProjectId`，在异步长任务或快速切书时存在与 `FormSheet` 3.2.2 同源的上下文竞态面。

## 二、业界最佳实践借鉴与架构对齐

结合 **Local-First 应用显式租户/项目 ID 传播** 与 **RAG 向量索引字段级权限控制** 的业界最佳实践，确立四条强化准则：

| 业界实践 | 对齐本项目的改造准则 |
| --- | --- |
| **1. 显式 ProjectId 透传，禁止隐式全局路由** | Local-First 应用跨 `await` 切书时，隐式全局状态极易产生上下文污染（Tenant Bleeding）。所有聚合/后台入口必须在同步首行捕获 `pid = db.getCurrentProjectId()`（或由调用方显式传入），内部全链改走 `getFormDataFor(pid, ...)` / `getTableRowsFor(pid, ...)` / `getCardRecordsFor(pid, ...)` / `getSubSetsFor(pid, ...)`。 |
| **2. RAG 前置过滤与字段级脱敏（Pre-Filtering & Field Scrubbing）** | 权限过滤必须在文本入块（Chunking）和注入 LLM Prompt 之前完成（Pre-Filtering），绝不依赖后置裁剪；读取配置失败时宁可降级为「仅公开内置字段 + 显式警告」，绝不放行未确认/受限自定义字段。 |
| **3. 导出/迁移必须「数据 + Schema 定义」成对同行** | 跨项目打包（`worldPack`）与文档导出（`exporter`）不能只搬运裸 JSON 键值对；打包必须附带用到的 `atlasFields` 并按「同定义复用、异定义重发 ID + 重映射数据键」原则合并，文档导出必须翻译 `cf_*` 为可读 `label` 并跳过已归档键。 |
| **4. 统一真源投影（Single Projection Layer）** | 导出、AI 上下文、世界观打包与检索共同消费 `EffectiveTemplate` / `resolveModuleCustomFields`，禁止各模块各自手写 `Object.entries` 或 `tab.modules` 循环。 |

---

## 三、分阶段开发规划

### 阶段一（B2-P0）：导出、AI 上下文与世界观打包真源对齐

1. **B2-P0-1 · 全书设定集导出对齐（`src/lib/storage/exporter.ts`）**
   - 抽出统一的字段解析辅助：
     - **纯表单页签**（含子世界）：加载 `fieldAlias` 与 `atlasSchema::<tabId>`（`resolveModuleCustomFields(..., { purpose: 'detail' })`），内置字段优先使用别名显示，未归档自定义字段按所属模块（或「自定义字段」兜底节）附加格式化输出（复用 `formatCustomValue`），忽略已归档或已失效的 `cf_*` 键。
     - **表格与卡片页签**：对 `isAtlasTab` / `isTemplateTab` / `supportsModuleCustomFields` 页签加载对应 `EffectiveTemplate` / `atlasSchema` / `fieldAlias`，按可读 `label` 输出并过滤归档字段，彻底消灭设定集里出现 `cf_xxx` 原始键的问题。
2. **B2-P0-2 · AI 主上下文接入表单与角色卡自定义字段（`src/lib/ai/aiContext.ts` + `src/lib/ai/atlasContext.ts`）**
   - 🔴 **行数红线约束（二次复核补记）**：`aiContext.ts` 当前已达 **1144 行**（距 `structureGates` 1200 行硬上限仅差 56 行），新增的字段解析与权限投影辅助**必须落在 `atlasContext.ts`**（或独立小模块），不得在 `aiContext.ts` 内堆砌逻辑。
   - 核实 `renderCards` 内部复用 `renderForm(tab, r.data, o)`，因此只需在 `renderForm` 中支持传入预解析的 `customFields` 与 `aliases` 即可同时覆盖 `form`、`card`、`renderActiveSubSets` 与 `renderActiveParallelSets`：
     - 纯表单 / `misc-settings` / 活跃子世界 / 平行设定：走 `resolveModuleCustomFields(cfg, { purpose: 'aiRead' })` 与 `fieldAlias` 显示名，仅注入未归档且 `aiReadable === true` 的自定义字段；
     - 角色卡（`char-*`）：优先读取 `TemplateDef`（`resolveTemplateCached(..., { def, purpose: 'aiRead' })`），按 `aiRead` 权限过滤并按最新 `label` 输出，并用 `formatCustomValue` 格式化。
3. **B2-P0-3 · 世界观打包与导入全覆盖（`src/lib/world/worldPack.ts`、`src/lib/world/worldImport.ts`）**
   - `collectWorldPack`：将 `atlasFields` 收集范围从 `isAtlasTab` 扩展到所有 `isAtlasTab(spec.tabId) || supportsModuleCustomFields` 的 `form` / `sub` / `card` 页签（按实际用到的未归档 `cf_*` 过滤）。
   - `importWorldPack`：抽取共用的 `mergeImportedAtlasFields(projectId, tabId, atlasFields, owner)` 辅助函数，同时服务 `table`、`form`、`sub` 与 `card` 四种形态；导入时同样执行「完整定义一致复用、否则重发 `newFieldId()` 并重映射 `data` 键」，保证跨书导入不串键、不丢定义。

### 阶段二（B2-P1）：语义向量索引覆盖 `form` 类设定页签

1. **B2-P1-1 · `indexer.ts` 接入纯表单设定与子世界**
   - 在 `src/lib/semantic/indexer.ts` 索引收集循环中新增 `tab.type === 'form'` 分支（覆盖 `positioning`、`worldbase`、`power`、`master`、`style` 及活跃子世界 `subSets`），通过已有的 `loadFieldRules(pid, tab)` 获取权限规则。
   - 对 `form` 条目同样执行内置 + 自定义字段 `aiReadable` / `archived` 过滤与 `isPrunedForAI` / `isSecretRow` 守卫（绝密或终结条目不入向量索引）。
2. **B2-P1-2 · `collectIndexDocs` 适配与分块**
   - 将纯表单模块与自定义字段按模块分段格式化为语义检索块（带页签名与模块名标题），沿用既有分块上限与增量哈希去重机制，不改变现有 `table` / `card` / `chapter` 的索引格式与版本号兼容边界。

---

### 阶段三（B2-P2）：显式 `projectId` 收口（消除异步切书竞态）

1. **B2-P2-1 · 补齐缺失 `*For` 底层接口与核心聚合链路显式 `pid` 化**
   - **底层接口核实与补齐（二次复核补记）**：
     - `db/tabs.ts` 与 `db/worldSets.ts` 已具备 `getFormDataFor`、`getTableRowsFor`、`getCardRecordsFor`、`getSubSetsFor`、`getActiveSubIdsFor`；
     - 但 `db/volumes.ts`（`getAllVolumes`）、`db/chapters.ts`（`getAllChapters`）与 `settings/fieldAlias.ts`（`loadAliases`）目前**缺少显式 `pid` 版本**，需先补充 `getAllVolumesFor(pid)`、`getAllChaptersFor(pid)` 与 `loadAliasesFor(pid, tabId)`（原无参版委托给 `*For(getCurrentProjectId(), ...)` 保持兼容）。
   - 将本批涉及的 5 个核心模块入口统一收口为显式 `pid` 传递，消除跨 `await` 读取全局 `currentProjectId` 的隐患：
     - `src/lib/storage/exporter.ts`（`buildSettingCompendium` / `exportSettingCompendium` 入口捕获 `pid` 后全链走 `*For(pid, ...)`）；
     - `src/lib/ai/aiContext.ts`（入口捕获 `pid` 并透传给 `renderActiveSubSets`、`renderActiveParallelSets`、`idsUpToAnchor` 等各段渲染器）；
     - `src/lib/world/worldPack.ts`（入口捕获 `pid` 后全链走 `*For(pid, ...)`）；
     - `src/lib/semantic/indexer.ts`（已接收 `pid`，将内部 `db.getTableRows` / `db.getCardRecords` / `db.getFormData` / `db.getAllChapters` 改为 `*For(pid, ...)`）；
     - `src/lib/search/search.ts`（入口捕获 `pid` 后全链走 `*For(pid, ...)`）。
