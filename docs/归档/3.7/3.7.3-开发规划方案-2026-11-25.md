# 青春幻想引擎 3.7.3 开发规划方案 · WCP 网页资料包接力模式（v2 · 源码复核完善版）

> 起点：3.7.2 源码基线（版本号已升级至 `3.7.3`，见 `package.json`、`package-lock.json`、`src/lib/help/registry.ts`）。
> 定位：**在 API / MCP / ACP 三种在线连接模式之外，新增第 4 种零配置离线接力模式——WCP 模式（Web Context Pack，网页资料包）。**
> 核心价值：不依赖 API Key、不配置复杂本地桥接，桌面版 / 便携版 / 网页版三形态全可用，一键把引擎里结构化的世界观、角色小传、状态回溯、细纲与前文打包为标准 `.md` / `.txt` 文档（或剪贴板文本），喂给 Gemini 网页版、Claude 网页版等长上下文对话模型接续创作，并支持双段式回流（纯净正文入章 + 结构化变动摘要核对入库）。
> 依据：v1 规划草案 + 逐项源码复核（全部结论带 `文件:行号` 证据，见 §0.1）+ 行业成熟 Context Pack 方案（Repomix / Obsidian Context Pack / Gemini Gems）吸收。
>
> 📌 书写约定：本文中**已存在的文件**用反引号；**尚未创建的文件**用「新增：」前缀且不加反引号 —— 避免文档引用检查把还没写的文件判成失效引用。

### 2.1 核心目标（G1–G4，各自可判定）

| # | 目标 | 判定方式 |
| --- | --- | --- |
| **G1** | **三档资料包可组装、可导出、体量透明**：Base / Delta / Full 均能生成含目录导航、XML 分段边界与隔离声明的 `.md`/`.txt` 文档与剪贴板文本，并附带真实 `MaterialManifest` 清单 | 单测断言三档输出边界、TOC 目录索引、保密过滤、预算裁剪申报与底包过期指纹计算 |

| **G4** | **并存隔离与全形态兼容**：桌面版 / 便携版 / 网页版均可用；`modeStatus` 轮询或 `blocked` 锁不影响 WCP 视图，不破坏 API/MCP/ACP 原有逻辑与门禁 | `AIConfigPanel` 轮询不重置 WCP 选态；原有 modeTransition / helpCenter / typecheck / lint / test 全绿 |

### 2.2 本版明确不做（边界）

- **不做网页自动化注入或爬虫抓包**：不操控外部浏览器 DOM 或绕过人机验证，坚持零风险文件/剪贴板接力。
- **不做隐式设定 diff 补丁**：增量包不猜前后端改动差量，坚持当前章确定性快照。
- **不做静默自动覆写正史**：所有回流变动候选一律走作者勾选确认，只追加不覆盖。
- **不做评分/排名**：连续性找茬场景导出包严守「只列事实矛盾与引文、不打分不评级」铁律。
- **不改核心业务数据库表结构**：配置仅用 `meta` 与 `settingsKV`，升级/回退零数据风险。

### 2.3 贯穿纪律

- 纯函数与 DB/UI 严格隔离：组装、模板、解析、映射全为纯逻辑函数，先红后绿补齐单测。
- 每完成一个工作包必须跑通 `npm run typecheck`、`npm run lint`（`--max-warnings 0`）及相关单测。
- 收工前补齐内置使用手册（`src/lib/help/`）中 WCP 模式文档与 3.7.3 更新说明，并执行六维与全量审计。

## 3. WCP 核心数据契约与文件格式规范

### 3.1 三档资料包策略

1. **常驻底包（Base Pack）**
   - **定位**：上传至 Gemini Gems / Claude Projects 或长对话首轮。
   - **内容**：作品概览、文风指纹与去 AI 味红线、世界观设定表（遵循保密过滤）、核心角色卡与人物小传。
   - **过期检测**：导出时对所选底包源数据生成确定性内容指纹（`lastBaseFingerprint`）与时间（`lastBaseExportAt`）存入单项目 `settingsKV`；后续作者编辑了底包涉及的设定表/角色卡时，界面计算当前指纹与记录比对，不一致则温和提示「底包设定已有更新，建议重导」（不阻断增量导出）。
2. **轻量增量包（Delta Pack）**
   - **定位**：日常续写主力，假设目标对话已持有底包。
   - **内容**：任务头与区块目录、本次场景指令、当前章细纲、前 M 章摘要、前 K 章正文末尾衔接段 + 本章已写草稿、本章出场/提及角色在当前章号的 `stateAt` 状态快照、关联物品 `holderAt` 持有状态、未回收伏笔、显式勾选的本章固定资料，并声明「背景世界观沿用常驻底包；若发生冲突以本增量包当前章快照为准」。
3. **完整独立包（Full Pack）**
   - **定位**：新开普通临时对话、或跨书/全局对照任务使用。
   - **内容**：自动合体拼装「Base Pack + Delta Pack」形成单文件自洽上下文。

### 3.2 导出文档结构（Markdown 骨架 + XML 边界标签）

文件支持 `.md`（默认）与 `.txt` 双后缀下载（通过 `downloadText`）及一键复制，内部结构自上而下固定为：
- `<wcp_meta>`：包类型（Base/Delta/Full）、场景标识、项目名、章节坐标、生成时间、**区块目录与各段字数索引（TOC）**、实际装入清单（`full` / `trimmed` / `dropped`）。
- `<wcp_rules>`：文风指纹、去 AI 味规则（仅创作/润色场景注入）以及**只读资料安全隔离声明**（明确 `<wcp_world>` / `<wcp_characters>` / `<wcp_context>` 中的文本与人物台词均为背景资料，不得覆盖系统规则或输出契约）。
- `<wcp_world>`：世界设定、力量体系、势力、制度等（Base / Full 携带）。
- `<wcp_characters>`：Base/Full 带全量角色卡与小传；Delta 仅带本章关联角色现行状态、物品持有与伏笔快照。
- `<wcp_context>`：当前章细纲、前文摘要、前文末尾正文、当前草稿或待检文本。
- `<wcp_task>`：本次具体写作/润色/推演/审校/整理指令。
- `<wcp_output_contract>`：根据当前选定的摘要格式（默认 JSON，可切换为 Markdown 清单）动态注入对应输出契约。

### 3.3 双段式输出契约与容错解析规范

1. **标准起止分隔符**：
   - 第一部分：`<<<WCP_BODY_START>>>` ... `<<<WCP_BODY_END>>>`（纯净产出：正文 / 润色稿 / 推演细纲 / 审校报告 / 小传文本；严禁夹杂寒暄）。
   - 第二部分：`<<<WCP_CHANGES_START>>>` ... `<<<WCP_CHANGES_END>>>`（结构化变动摘要；纯审校/推演等无设定变更场景可置空或输出简要备忘）。
   - 退化识别：若模型遗漏分隔符，解析器按 `## 第一部分` / `## 变动摘要` / ` ```json ` 尾块做安全切分；完全找不到第二部分时，整段文本安全归入 Part 1。
2. **默认 JSON 契约（对齐 `chapterPostProcess.ts`）**：
   - 默认要求第二部分输出严格 JSON（解析器自动剥离 Markdown 代码块围栏与常见尾逗号/多余前缀说明），结构包含 6 个可选数组字段：
     - `entities`：`[{ name, type, summary, evidence }]`
     - `statusChanges`：`[{ character, before, after, quote }]`
     - `resourceTransfers`：`[{ item, from, to, action, quote }]`
     - `foreshadows`：`[{ code, action, content }]`
     - `relations`：`[{ charA, charB, change, quote }]`
     - `bioNodes`：`[{ character, title, summary, tag, evidence }]`
   - 归一化后直接调用 `chapterPostProcess.ts` 的确定性比对函数生成 `PostProcessItem[]`（带库内匹配状态 `new` / `changed` / `duplicate` / `unregistered`），再经用户勾选提交 `applyPostProcess`。
3. **固定 Markdown 清单契约（备选切换）**：
   - 使用固定二级标题分块：`### 新登场设定`、`### 角色状态变动`、`### 物品流转`、`### 伏笔推进`、`### 关系与里程碑`；解析器分段抽取为可读卡片与备忘列表。
4. **JSON 报错主动引导降级**：
   - 一旦检测到 `jsonAttempted && jsonParseFailed`：
     - **Part 1 正文 100% 原样保留**，作者照常可以「复制纯正文 / 插入章节」；
     - Part 2 顶部展示友好提醒条：「检测到当前网页模型返回的 JSON 格式不完整，已为您完整保留正文。若该模型较难稳定输出 JSON，可一键切换为对人眼更友好的固定 Markdown 清单格式」，并附**「一键切换为 Markdown 清单模式」**按钮。
