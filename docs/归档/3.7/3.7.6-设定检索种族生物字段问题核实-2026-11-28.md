## 3. 根因（到行）

### 3.1 标题退化为编号

`src/components/settings/SettingSearch.tsx:262`

```ts
const displayCol = tab.displayCol ?? (isPair ? '人物A' : colNames[0])
```

`displayCol` 是 **schema 静态常量**（`'名称'`），不看当前有效列/模板/图鉴配置。

同文件 `:273`

```ts
const displayVal = (displayCol && r.data[displayCol]) || filled.find(([, v]) => v && v.trim())?.[1] || ''
```

「名称」为空就回退到 `filled`（`Object.entries(data)`，按对象键插入顺序）的第一个非空值 —— 新增行最先写入的是自动编号，于是**标题变成 `R0007`**。

### 3.2 自定义字段在检索里显示原始键 `cf_xxx`

`src/lib/templates/effectiveSearchMeta.ts:70`

```ts
labels: Object.fromEntries(cols.map(c => [c.name, c.templateLabel ?? defaultLabelOf(c.name)])),
```

`atlasColumnsOf` 给自定义列带了 `atlasField`（其中 `label` 才是作者起的「种族名」），这里只读 `templateLabel`，漏了 `c.atlasField?.label`；`defaultLabelOf('cf_xxx')` 只能返回原键。

⇒ 表格/图鉴的表头读 `atlasField.label` 所以**显示正常**，只有设定检索显示 `cf_…`。这解释了「表单和图鉴正常、只有检索不对」。

### 3.3 为什么「新旧并存」

- 内置「名称」列仍在有效列里（`atlasColumnsOf` 内置列原顺序 + 自定义列追加末尾，`src/lib/atlas/columns.ts:52-85`）；
- `pickKnownKeys`（`settingSearchFields.ts:98`）只过滤「无效键」，**不做同义/同名合并**；
- 自定义字段与内置字段**没有任何同名校验**（全仓 grep 无 duplicate/同名拦截）。

于是同一条记录里「名称」与「种族名」两个字段都列出来，值一新一旧。

### 3.4 为什么只有种族生物

因为**只有这张表被作者加了自定义「名称类」字段**（用户项目里新数据写进了自定义列，老数据留在内置列）。地理风物/物品资源没有这个改动，所以看起来正常。

## 5. 建议处理方案（待主人拍板，本轮未实施）

### P1 · 显示层（低风险，先止血）

1. `effectiveSearchMeta` 的 `labels` 增加 `c.atlasField?.label` 兜底 → 自定义字段显示作者起的名字。
2. 标题取值抽成纯函数 `resolveRowTitle(tab, data, meta)`：
   - ① `displayCol` 有值 → 用它；
   - ② 否则在 `meta.keys` 里找 label 含「名称 / 标题 / 事件名称 / 章节标题」的键；
   - ③ 再否则第一个非空值；
   - ④ 都空才 `（未命名）`。
   同一函数供检索、本章引用、高亮共用，避免四处各写一遍。

### P2 · 预防（配置层）

- 新增自定义字段时，若显示名与任一内置字段**同名或近义**（名称/标题/编号），拦截并提示「请用『内置字段显示名』改名，新增同义字段会让数据分裂成两套」。
- 已有同名字段不静默改写，只在字段设置里标黄提示。

### P3 · 数据修复（可选，需人工确认）

- 数据健康检查增加一条：同一行存在「显示名相同的两个键」→ 列出表名、记录名、两个值与来源。
- 提供「合并到内置列」的动作：**只追加不覆盖**（内置为空才写入）、逐条勾选、先备份。

### 验收判据

1. 复现脚本（`probe-repro-race.mjs`）里 `R0007` 行标题显示「测试种族甲」，不再显示编号。
2. 展开字段显示「种族名」而不是 `cf_xxx`。
3. 标准示范数据三种表标题/副标题不变（回归）。
4. 表格、图鉴、AI 上下文、导出行为零变化（只改检索取值）。
