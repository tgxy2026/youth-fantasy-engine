## 二、覆盖安装如何同步到老项目（三条保障）

### 背景

`features` 只对**自定义项目**有意义（完整项目的 `tabVisible()` 恒为 `true`）。
老项目若当初在「自定义项目」里**取消勾选**过「关于打赏」，其 `features` 数组里就没有 `about` ——
覆盖安装（保留旧数据、只换程序）后那个页签就永远不会出现，作者也无处可开。

### 保障 ①（结构性）：`tabVisible()` 对锁定项直接放行

```ts
if (ctx.type === 'full') return true
if (LOCKED_IDS.includes(tabId)) return true      // ← 新增
return ctx.features.includes(tabId)
```

与 `resolveFeatures()` 的「锁定项恒在」保持一致：**即便某个项目的 features 里没有它，页签也不会凭空消失**，
不依赖任何迁移是否跑过。同时不越权 —— 没勾的可选模块仍照旧不可见（有断言钉住）。

### 保障 ②（数据性）：启动期迁移 `migrateLockedFeatures`

```ts
// App.tsx 启动引导（与 migrateProjectTypes / migrateLegacySearchKey 并列）
await db.migrateLockedFeatures(LOCKED_IDS)
```

- 🔴 **必须挂在启动期、而非 `runMigrations()` 的项目段**：后者排在 `if (!currentProjectId) return`
  **之后**，只在「打开某个项目」时执行；而本迁移要遍历**全库所有项目**、与「打开哪个无关」。
- 口径：**只补不改**（仅合入缺的 locked id，作者自己关掉的可选模块绝不动）、
  只处理 `projectType === 'custom'`、**幂等**（无可补即不写库、返回 0）。
- 🔴 `lockedIds` 由调用方传入，**db 层不 import schema** —— `schemaShared.ts` 会 `import './db'`，
  反向引用会直接成环（`tests/importCycles` 会红）。真源仍是 `schema.LOCKED_IDS`。
- 🔴 通用而非只补 `about`：以后再有模块升为 locked，**不需要**另写一条迁移。

### 保障 ③（导入侧）：手动导入老备份

靠保障 ① 保证当次可见；下次启动由保障 ② 补齐数据。
