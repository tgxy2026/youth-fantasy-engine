## 五、两条遗留问题（都已定位，未擅自改）

### ⑤ 内存态跨项目短暂残留（低危）

切到 B 的当下，B 的面板会显示 A 的「已中止 / 继续写作 / 设定奠基 已中止 15 秒」。
刷新即消失，且不会写入 B 的库。

**根因判断**：`loadSession(pid)` 的清理依赖「`hydratedFor !== pid` 才重读」，
而切换过程中 `db.setCurrentProject()` 与 React 挂载的先后顺序没有保证 ——
面板可能拿着**旧 pid** 调用了一次 hydrate，于是本次清理被 `hydratedFor === pid` 提前返回跳过。

**建议修法**：`abortRunIfProjectChanged()` 里在停止任务的同时把**会话类字段**一并清空
（`resume / progress / result / log / summaries`，即 `SESSION_BLANK`），
使"切项目后面板干净"不再依赖 hydrate 的时序。

### ⑥ 想法（seed）在"填完立刻开始"时会丢（中危，既有边界）

实测：填完想法 **600ms** 就点「开始规划」→ 1 秒防抖未到 ⇒ 想法没落盘；
随后任务中止，全程没有一次 `persistNow` 写入 inputs ⇒ A 的会话仍是初始空值（`seed: ""`）。

**这不是本次修复引入的**（`persistNow` 本来就是 1s 防抖），但**本次新增的"切项目即中止"是一个新的中断点**，
会让它更容易被触发。

**建议修法**：`abortRunIfProjectChanged()` 在停止前**先 flush 一次**，且 flush 必须写到
`runProjectId`（**不能**用 `db.getCurrentProjectId()` —— 那个值此刻可能已经换项目了，
`persistNow` 正是动态读它，这是同一个病根）。
