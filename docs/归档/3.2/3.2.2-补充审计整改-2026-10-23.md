## 二、已修复（15 条）

### P1 · 数据可靠性（5 条）

#### ✅ D1 — 同资料区双开静默覆盖
- **现场**：两个进程同资料区，A 写 `AUDIT-A` 已落盘，B 在旧稿上写 `AUDIT-B` 后磁盘只剩 B，两个窗口都显示"已保存"。
- **核实**：`electron/main.cjs` 确实**没有** `requestSingleInstanceLock`。
- **改法**：`app.whenReady()` 之前取单实例锁；拿不到锁 ⇒ `app.quit()` + 顶层 `return`（不建窗口、不注册 IPC）；
  拿到锁 ⇒ 监听 `second-instance`，把已有窗口还原/显示/聚焦。
- **保留开关**：`--multi-instance` 可放行多开 —— **只为审计回归**（要验证"双开不互相覆盖"必须真起两个进程，
  单实例锁下第二个进程会直接退出、造不出现场）。⚠️ 锁的作用域是 userData 目录，不同 `--user-data-dir` 互不影响。
- **未证明**：未在真机起两个进程实测（验证方法是：A 存盘后点 B 的图标，期望**第二个进程退出、A 被聚焦**）。

#### ✅ D2 — 便携数据回迁桌面后项目打不开
- **现场**：便携端写盘保留**记录数组**，桌面归一化 `{...rows}` 展开得到 `{"0":…}`，项目列表看得见、按 id 查不到。
- **核实**：`storeOps.normalizePortableData` 确实是 `{ ...(rows) }`，无数组分支。
- **改法**（`storeOps.ts`）：
  1. **数组形态** ⇒ 按各 store **真实主键**重建索引（`projects.id` / `formData.tabId` / `meta.key` …）；
  2. **已被污染的文件**（键全是 `0/1/2` 纯数字）⇒ 也按记录里的真实 id 救回来；
  3. **无主键的记录不丢**（放 `__nokey_<序号>`，`getAll` 仍能列出，与便携端"行数组里躺着一份"等价）。
- **同源收敛**：`PORTABLE_KEY_FIELDS` / `keyOfRecord` **上移到 `storeOps.ts`**（数据格式所在地），
  `fileBackend` 改为 re-export —— 原先要用的地方只能反向 import 后端，会成环。
- **验证**：`tests/dataFileReject.test.ts` 新增 9 条（数组重建 / 非 id 主键 / 污染修复 / 正常形态不误改 / 缺主键不丢）。

#### ✅ C1 — 备份写失败仍出现"可恢复"的假备份；导出不完整却称完整
- **现场一**：外置写失败只告警、正常返回 ⇒ `createAutoBackup` 的 await 过关 ⇒ 照样登记元数据。
- **现场二**：2 份历史备份坏 1 份 ⇒ 整批读取中断 ⇒ **两份都没带走**，界面仍写"这就是完整副本"。
- **改法**：
  1. `sidecar` 新增 **`putStrict`**（失败即抛），`createAutoBackup` / `createFrozenVersion` 的载荷写改走它 ——
     **载荷没落盘就绝不登记元数据**（手动备份按钮已改为弹出"备份没有写成：…（现有备份未受影响）"）；
  2. `collectSidecarForExport` 改为**逐条读** `per-id` 记录 + 返回 `{data, issues, complete}`，
     一条坏掉只丢那一条；
  3. `exportDesktopData` / `exportPortableData` 回传 `missingSidecar`，**只有 `complete` 才敢说"完整导出"**，
     否则明确写"有 N 份历史备份读取失败，没有被带进这份文件 —— 这不是完整备份"（红色提示，12s）。
- **验证**：`tests/sidecar.test.ts` 新增 12 条（严格写抛错 / 普通 put 仍不抛 / 好的照常带走 / 缺失被列出 / complete 判定）。

#### ✅ C2 — 更改资料位置只搬主 JSON
- **核实**：`blobRoot()` = `dirname(dataFile())/blobs`，而 `store:setDataPath` **只写主 JSON**。
- **改法**：新增 `copyBlobsAlong()` —— 递归复制外置目录 → **逐份校验字节数** → 全过才写主 JSON 与位置配置。
  任一步失败 ⇒ 返回错误、**不切配置**（原位置保持可用）。「恢复默认位置」同样处理。
  目标已有数据（adopted）时**不搬**（两套备份混进同一 blobs 会互相覆盖），并在界面明说"本机历史备份未混入"。
- **验证**：迁移成功回传 `copied`，界面提示"已迁移，N 份历史备份一并搬走并校验通过"（延迟 1.2s 再重载，否则提示看不见）。
- **未证明**：未在真机迁移到空目录后逐份恢复（期望：每份历史备份都能恢复）。

#### ✅ C3 — 退出项目时表单草稿写错项目键
- **核实**：`FormSheet` 卸载补存走 `saveFormData()`（拼全局 `currentProjectId`），而 `exitProject()` 先把它清成 `''`。
- **改法**：`FormSheet` **挂载时绑定 pid**（`pidRef`，换项目会因 `key={proj-…}` 整体重挂），
  卸载补存 / 切页签补存 / 显式保存 / 读取**全部改走带 `For` 的版本**；
  `WorldSetSheet` 同族问题一并修（新增 `saveSubSetFor`，母级与子级都走显式 pid）。
- **验证**：`worldPack` 回归（53/53）—— 注意 `saveSubSetFor` **刻意不对空 pid 早退**，否则会改掉 `saveSubSet('')` 的既有契约。

### P1 · AI 可信度（2 条）

#### ✅ A2 — 校对全部失败却显示"未发现问题 ✓"
- **核实**：`runProofread` 单块异常 `continue`，返回值里**没有任何失败痕迹** ⇒ 界面把"0 处"当通过。
- **改法**：
  1. `ProofreadResult` 增加 `failedChunks` / `totalChunks` / `cancelled`，失败与取消分别记账；
  2. 界面**先判覆盖**：全段失败 ⇒ 红字"本次未完成校对：所有分段都没能拿到结果…下面的 0 处不代表没有问题"；
     部分失败 ⇒ "部分已校对：N/M 段完成，其余 K 段失败未检查"；
     只有 **真校过 + 无失败 + 未取消** 才出现绿色"未发现…✓"；空正文另给说法；
  3. 全段失败时任务**降级为 failed** ⇒ 任务中心不再弹"已完成"。
- **验证**：`tests/proofreadSplit.test.ts` 新增 8 条（三环都钉：记账 / 界面覆盖判定 / 降级）。
- **未证明**：未用真实 401 端点端到端复跑（静态判据 + 代码路径已锁）。

#### ✅ A1 — 字数校准丢失历史章冻结规则与作者要求
- **核实**：`enforceWordRange()` 只收 body/target/cfg，首轮的 `scopeRule`（历史章冻结）与 `o.requirement` 全没带下去；
  补写默认 user 还写着"情节要实质推进"。
- **改法**：新增 `invariants` 参数 —— 补写与压缩**两个阶段都原样重申**，并声明"优先级高于篇幅目标"；
  有冻结约束时补写目标改为"**只在本章已有内容范围内补足细节**，不新增剧情事件、不新造专名"。
  改写侧拼出 `invariants = scopeRule + 作者本次要求`，**两个调用点**（续写分支、字数校准）都传。
  不传 ⇒ 行为与改造前逐字一致（老调用零影响）。
- **验证**：`tests/chapterRewrite.test.ts` 新增 8 条（含"无约束时保持原措辞"的反向守卫）。

### P2（5 条）

#### ✅ D3 — 整书恢复后旧快照失联（时光机查不到）
- **核实**：恢复时每章换新 id（`uid()`），快照刻意不删，但**没有重映射**。
- **改法**：恢复后按 `chMap` 把本项目的快照 `chapterId` 重指到新章；**对应不上的保持原样**
  （不删、也**绝不按标题猜** —— 同名章会串档）。
- **未证明**：未真机走"有快照 → 整书恢复 → 点时光机"（纯逻辑已就位）。

#### ✅ D4 — 写盘失败时"保存出错"与"已保存"并存
- **核实**：编辑器底部只看 `savedFlash`（= 内存提交成功），与真实落盘无关。
- **改法**：编辑器订阅真实落盘状态（`getDesktopState` / `getPortableState` + 订阅），状态栏改为
  **磁盘结论优先**：有错 ⇒ 红字"未写入磁盘"（hover 显示原因）；待写 ⇒ "正在写入…"；才轮到"已保存"。
  同时把底层错误翻成人话：`EPERM/EACCES` ⇒ "文件只读或没有写入权限（被设为只读、或被杀软/同步盘占用）—— 请恢复写权限后重试"，
  另覆盖 `ENOSPC` / `EBUSY` / `EROFS`，原始错误附在括号里。

#### ✅ D6 — 加密迁移包密码错误时提示空着
- **核实**：`crypto.subtle.decrypt` 抛的 `OperationError` 在 Chromium 里 **message 是空串**。
- **改法**：解密失败统一翻成"密码错误或文件已损坏（解密校验未通过）—— 已有项目未受影响，请确认密码后重试"；
  Base64 字段损坏另给一句；三处"导入失败："补 `|| '未知原因（原数据未改动）'` 兜底。

#### ✅ C4 — 照示例填 `http://` 代理被拒
- **核实**：主进程 `clean()` 白名单**没有 `/`**，而校验正则要求 `scheme://` ⇒ 洗成 `http:…` 后必失败；
  反而裸 `127.0.0.1:port` 能过。
- **改法**：白名单加 `/`（注入面仍由下面那条严格正则兜住，不接受多规则语法）。

#### ✅ C6 — 30 秒超时只覆盖到响应头
- **核实**：`finally { clearTimeout(timer) }` 只包了 `fetch`，正文读取无保护（审计实测等 33.0s）。
- **改法**：定时器的 `finally` 包住**整个请求 + 读正文**（含 `arrayBuffer` 兜底路径）；
  新增 `netTimedOut` 标记，超时与其它错误分别报（undici 中断不一定叫 `AbortError`），文案改为"请求超时（30s，含等待响应正文）"。

#### ✅ A9 — 保存一条提示词会清掉别的未保存草稿
- **核实**：`reload()` 内部无条件 `setDrafts({})`。
- **改法**：`reload({ dropAllDrafts })` 默认**保留**草稿；保存/还原只 `dropDraft(该条)`；
  只有「全部还原」才清全场。

### U2 · 可访问名称与点击目标（1 条，含 5 处）
- 章节标题 → `aria-label="章节标题"`；
- 新建 / 编辑项目的书名 → `label htmlFor` + `input id`（**真正关联**，不是只靠视觉相邻）；
- 请求超时 / 正文写作资料预算 → `NumberField` 新增 `ariaLabel` 透传；
- 问号按钮点击区从 `p-0.5`（实测约 19.7×19.7）改为 `p-1.5`（≈25×25），**图标大小不变**。
