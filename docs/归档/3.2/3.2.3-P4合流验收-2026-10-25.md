## 3. 性能：本批的关键结论

1. **打开**：medium P50 12,199ms → **175.6ms**、large 从「180s 打不开」→ **195.9ms**（行窗口化 + 取数放大修复）。
2. **保存**：guest **60ms**（原先 450ms 是探针自己每轮 `getAll` 整表回读造成的，不是产品慢）。
3. **滚动**：单步 **24.9~29.9ms**（原本 113ms 是「每步 1/40 全表 + 自动化往返」的错误口径）。
4. **便携保存是真慢**：整库过 HTTP + 原子写盘，P50 ≈ 0.86~0.95s、偶发 1.5s（Defender 扫描时 rename 重试）。
   已按后端分开定阈值，并修掉「rename 失败静默丢保存」（见 `3.2.6-便携写盘重试-2026-10-25.md`）。
5. **DOM**：medium/large 节点 125,340 → **6,652**，挂载行 300/1000 → **12~15**，堆 142MB → 57~65MB。

longbook 正文、100 行批量保存）见 [P0 冻结基线](3.2.3-P0冻结基线-2026-10-25.md)。

## 4. 本批修掉的真缺陷（不是工具问题）

| # | 缺陷 | 后果 | 修复 |
|---|---|---|---|
| 1 | 便携服务 `rename` 失败不重试，异常逃出请求处理器 | 一次保存被**静默丢弃**，界面永远「正在保存」 | 退避重试 + 回 500 + `portableWriteFailure` 10 条断言 |
| 2 | `compare` 只算差值不判相对退化；无阈值夹具永远判不通过 | 「慢 5 倍也没超上限」会被放过；small/tree/mixed 等于没闸 | `REGRESSION_LIMITS` + 按指标噪声地板，判定顺序 相对→绝对 |
| 3 | 筛选用例查询词写死 `-条目01` | small（编号 0001~0030）一条不命中，整轮判失败 | 查询词从夹具数据推导 |
| 4 | 树形夹具首行断言直接用 `matching[0]` | 层级序与筛选序不同，必然误判 | 按「父级不在结果集内」的根规则独立算期望首行 |
