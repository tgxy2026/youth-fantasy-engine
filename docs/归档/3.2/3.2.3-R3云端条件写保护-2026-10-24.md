# 3.2.3 R3：云端整库条件写保护（第一阶段）

> 接续 899da25 和已立项的方案 B。修改源码与自动验收，不部署、封装或修改版本号。仅用本地临时账号及隔离数据目录取证。

## 1. 解决的问题

同一账号的两个窗口各自保留整库快照，后保存的旧快照原先可以覆盖另一窗口已经保存的内容。现在云端整库提交必须携带读入时的版本：第一窗口提交成功后，第二窗口的旧版本返回 409，服务端不写入，第二窗口保留可导出的草稿。

本轮只接云端整库数据。桌面存储没有改动；便携服务尚未接条件写，保持原行为。当前云端按单个 Node 服务进程运行，不能据此声称多服务进程共享目录或 sidecar 数据也已有版本保护。

## 2. 服务端协议与兼容

| 操作 | 行为 |
|---|---|
| GET /api/data | 返回正文、ownerId、revision 和同值强 ETag；首次空库 404 也返回版本 |
| PUT / POST，缺 If-Match | 428 REVISION_REQUIRED，拒绝旧客户端无条件写入 |
| If-Match 与当前版本不符 | 409 DATA_CONFLICT，保留当前磁盘内容 |
| 正确版本 | 按账号串行执行比较、原子替换，再返回新 ETag |
| 请求在途发生会话替换 | 开始实际提交前重新鉴权，拒绝过期会话 |
| 数据读取故障 | 明确 500，不把读取异常直接抛出导致服务退出 |

版本由账号 ID 与实际文件内容的 SHA256 组成，带双引号作为强 ETag。不同账号即使正文相同，版本也不同；空库和已有内容使用不同编码。版本跟随真实正文，不另写 revision 文件，不修改 data.json 格式，也不需要迁移旧书库。服务重启后原版本仍可用。

比较与写入处于同一账号队列中；不能先比较、等待其他请求写入后再拿旧权限落盘。队列异常会释放，下一请求仍能运行。文件内容完全相同的再次提交不会产生新的内容版本。

前后端需要配套使用：新服务拒绝旧页面的无条件 PUT/POST；新页面遇到缺少版本或账号不符的响应会停写。不能通过忽略 428、自动补最新版本或去掉 If-Match 兼容旧写者。回滚到旧服务会失去保护，不能把“数据格式可回滚”写成“并发保护仍成立”。本轮未实际部署或执行回滚。

## 3. 前端失败与接续

- 读入时验证 ownerId 与页面启动账号一致，保存时带读入的版本；成功回执更新版本，保留已有的写入序号守卫。
- 409/428 后进入保存冲突状态，停止自动和手动提交，后续输入仍留在本窗口；通用读锁解除及导入不能绕过冲突。
- 常驻提示要求先导出当前数据，再重新打开并合并。实际导出取本窗口内存，包含冲突草稿，不自动刷新或用云端内容替换本地输入。
- 网络响应丢失时保留 dirty。下一次先回读：若服务端仍是原版本，可重试；若服务端精确保存了刚才请求的字节，可确认该提交并继续保存新输入；若内容已被另一写者改变，则停写保留草稿。账号切换或缺少版本不能通过这条接续路径授权写入。
- 云端退出不再使用无法携带 If-Match 的 sendBeacon，也不以“已排队”确认保存。无冲突且无在途请求时尝试带前置条件的同步 PUT，只有成功状态及有效 ETag 才清 dirty；冲突、请求在途或结果不确定时保留 dirty 并触发离开守卫。
- 多标签提示按形态分开：云端说明旧版本会被拒绝，便携版继续明确整库覆盖风险。

## 4. 自动验证

`tests/cloudConditionalWrite.test.ts` 启动实际本地 server，使用真实 HTTP/TCP 和临时账号，共 30 项检查：空库与账号绑定、无条件 PUT/POST 拒绝、同基线并发只一份提交、陈旧 POST、跨账号版本、重启、读写故障和队列恢复、会话替换，以及真实 fileBackend 的冲突/导出/在途编辑/退出守卫。

网络负面对照使用实际 HTTP 中继，在提交前或实际提交后断开 socket；没有伪造成功 fetch 返回值。冲突后继续编辑、导出及等待一个自动保存周期，验证草稿保留且请求停止。

生产浏览器探针扩到 38 项，在同一浏览器会话内开两页并真实操作编辑器：第一窗口落盘，第二窗口收到 409，错误常驻可见，第二窗口输入仍在，服务端保留第一窗口内容。随后实际下载 JSON，核对其中是第二窗口草稿，并验证停止重试和离开守卫。新增导出文件与截图必须通过实际文件、隔离路径和 SHA256 校验。

原有 413/500 故障探针也适配条件写：测试 bootstrap 通过本次子进程私有 IPC，在实际服务端账号队列内安装/撤销故障目录，排空在途写，暂停后续写，恢复不可变的原始基线再释放。否则测试把文件暂时移走会被正确识别成外部版本变化，不能继续拿它冒充普通写盘失败。没有新增产品 HTTP 故障开关；恢复期间不可能覆盖成功的产品写入，草稿仍必须由真实保存链落盘。

复现入口：

~~~powershell
node tests/build-test.mjs cloudConditionalWrite
node scripts/verify/reliability.mjs --profile local
~~~

新增契约 identity.cloud-conditional，门槛 30；storage.web-cloud-save 门槛由 31 调到 38。新增测试已归入唯一分批清单。

## 5. 完成范围与下一步

本轮不提升 concurrency/web-cloud 为 verified：beforeunload 是真实处理函数上的合成事件，未证明真实浏览器在途关页、跨设备实体操作或全部退出兜底。便携版仍无条件写，sidecar 版本保护、多服务进程、自动内容合并、刷新后恢复未导出的冲突草稿也不在本轮完成范围。

下一步优先将便携服务及退出链路接入同等前置条件，再补真实关页证据；多进程需要跨进程锁或数据库事务，不能沿用单进程队列作承诺。仍保留其余可靠性契约与大表性能工作线，不用本轮部分成果替代整版收口。
