## 三、本轮发现并完成的整改

| 问题 | 处理 | 复验 |
|---|---|---|
| 拖入文件时浏览器可能在 `drop` 阶段清空 `DataTransfer.types`，导致图片区漏接且全局防导航失效 | 新增 `hasDroppedFilePayload()`，在 `drop` 时以实际 `files.length` 兜底；图片区和全局 guard 共用该判据 | `imageDrop` 回归用例通过；全量 297/297 |
| A1 资料抽屉打开时与编辑区、检索列争用横向空间；固定尺寸在界面缩放下会挤压或越出视口 | 抽屉打开时暂收检索列，关闭后恢复；抽屉固定于视口，并用 `foldZoomLength()` 折算边距和宽度；窄窗提高正文可用宽度 | 9/9 布局组合通过，最小正文有效宽度 420 px |
| A1 原引用侧栏没有章节资料绑定、手动固定、细纲匹配建议和稳定记录跳转 | 新增资料抽屉与数据 hook；名称、别称、编号只产生人工可选建议；稳定记录 ID 跳转；细纲切换复用原有草稿安全保护 | 8/8 示范项目操作通过；项目恢复检查通过 |
| Lint 提示 `CustomSelect` 清理函数读取可变 `payloadRequestRef.current` | 移除清理函数里的序号读写；两个异步 effect 用局部 `alive` 标记拦截卸载后的回调，并由新请求序号淘汰过期请求 | `npx eslint src tests` 0 warning；类型检查与全量 297 项测试通过 |

## 五、优化项

1. 主包为 1,698.47 kB（gzip 548.26 kB），高于 700 kB 构建提示线；另有 `src/lib/tavern/script.ts` 动态导入与静态导入并存，导致该动态导入不能拆分代码块。按既有决策作为 3.2.x 体积优化，不阻断本轮代码回归。
2. 1280×720、125% 界面缩放下正文可用宽度为 420 px，当前布局可用但偏紧；后续可评估更窄抽屉或按需遮盖式面板。
3. 细纲用途目前根据字段名称、别名和说明识别；若要避免命名歧义，可在模板字段定义中增加显式用途元数据。
4. L4 的 1000 行×60 字段大表格仍有约 17 秒打开耗时，按既有性能决策延期至 3.2.x；500 章/百万字/200 载荷容量基准已有达标记录。
