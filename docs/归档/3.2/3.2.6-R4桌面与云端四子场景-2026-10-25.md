# 3.2.6 · 桌面与云端补齐 roundtrip 四子场景（2026-10-25 13:20）

> 承接 [格式版本闸与四子场景](3.2.6-R4格式版本闸与四子场景-2026-10-25.md)（便携 / 游客）。
> 本轮把同样四个场景搬到 **desktop** 与 **web-cloud**，矩阵 `roundtrip/*` 四格**全部点亮**（10 → **12 / 26**）。

## 1. 两个探针各加什么

| 场景 | desktop（29/29） | web-cloud（47/47） |
|---|---|---|
| `sidecars` | 用真实 IPC `payloadWrite` 播一份备份载荷 → 导出必须**内联**、导入后必须**拆回且内容逐字节一致** | 与便携同构：`/api/blob` 播一行 `vecRows` → 导出内联、导入后拆回 |
| `secret-stripping` | **关掉应用 → 直接往 `data.json` 写一行 `aiProviders` → 重新启动**（证明应用真的从文件读到它），再导出 | 走页面自己的登录会话：`/api/data` 条件写注入密钥 → reload → 导出 |
| `schema-version` | 导出文件改 `fileVersion: 999` → 导入被拒 + `data.json` 逐字节未变 | 同（判据为服务端文件字节） |
| `restore-failure` | 结构损坏 JSON → 被拒 + 数据未变 | 同 |

两处设计上的取舍：

- **桌面侧车只播 `backupPayloads`**：桌面与便携的外置清单本就不同 —— 便携把 `vecRows/kbDocs/kbBodies` 内联进整库
  （U 盘要自包含），桌面把它们留在两个独立 IDB、只外置备份载荷。所以断言必须按各自的清单来，不能照抄。
- **密钥种子的注入方式**：桌面没有"服务端接口"可走，唯一能证明"应用从文件读到了这枚密钥"的方式就是
  关掉应用 → 改文件 → 重启。web-cloud 则走页面自己的会话，与产品同一条接口，不动磁盘。

## 2. 矩阵提升方式（避免跑两遍探针）

桌面与云端都是**同一轮探针**同时产出 `boot-store` / `write-failure` / `roundtrip` 的证据。
`reliability.mjs` 里新增：把同一份 runtime 文件复制成 `<prefix>-runtime.json` 再各自 `promoteRoundtrip()`，
既不用跑两遍 Electron/浏览器，也保证两份证据来自**同一轮源码与构建**（比"重跑一次"更强）。

`promoteRoundtrip()` 仍会拿 `payload.scenarios` 与 `policy.json` 逐项比对：四场景缺一即这一步失败。

## 4. 边界（别当已验）

- `storage.four-profiles` **仍 blocked**，欠项已缩小到：**在途编辑、切项目、关窗时的写失败**（四配置都没覆盖），
  以及安装包 / 实体设备的真实环境。
- 桌面探针的文件选择器目的地仍是桩（原生弹窗无法自动化）；web-cloud 用的是临时账号与本地服务，不是生产环境。
- `sidecars` 只证明"该内联的在内联、该外置的在拆回"，**没有**证明外置文件损坏时的降级行为。
