# 3.2.3 · R4 端到端导出→导入（桌面 + 云端）

> 日期：2026-10-24｜执行：可可｜基线 `main` / `ec4c9ca`
> 目的：`storage.four-profiles` 一直 blocked 的**唯一剩余理由**是「各配置端到端导出→导入」。
> 本轮把桌面与云端两条路真正走通（真进程、真 UI、真文件），并接进统一验收。
> 版本号仍 3.2.2；未封装、未发布、未部署。

## 1. 为什么"格式层往返"不够

已有 `storage.roundtrip`（15 断言）验的是 `normalizePortableData` 对**数组/键化两种形态**的归一化与幂等 ——
那是**纯函数层**，它证明不了这些：

- 导出按钮点下去，**文件真的落到了磁盘/下载目录**吗？
- 导入走过的**确认框、文件选择、整库替换、页面重载**链条真的能跑完吗？
- 导入之后**重启应用**，数据还在吗？

所以要的不是再写一遍归一化，而是真的点按钮、真的读文件。

## 2. 桌面：Electron 里的完整闭环

`scripts/audit/probes/desktop-save-probe.cjs` 新增 4 条（探针 15 → **19**）：

| 检查 | 做法 | 断言 |
|---|---|---|
| `roundtrip-export` | 点「导出数据文件」（原生保存框的目的地打桩到临时目录） | 导出文件里本章正文 = 当时的草稿 |
| `roundtrip-changed` | 在编辑器里把正文改成别的，Ctrl+S，等**磁盘**变化 | 库确实已不同于导出那一刻 |
| `roundtrip-import-readback` | 点「导入数据文件」→ 确认框「继续导入」→ 选那份文件 → 应用 `location.reload()` | 页面正文与磁盘正文都回到导出时的内容 |
| `roundtrip-restart-readback` | 关掉 Electron 再启动 | 仍是导出时的内容（证明导入真的落了盘） |

中间那条 `roundtrip-changed` 是关键：**不改库就直接导入，"导入回到导出那一刻"什么都证明不了** ——
看起来绿，其实可能是"本来就没变"。

## 3. 云端：浏览器真实下载 + 真实选文件

`scripts/audit/probes/web-cloud-save-probe.cjs` 新增 3 条（探针 28 → **31**）：

| 检查 | 做法 |
|---|---|
| `roundtrip-export` | 点导出 → 捕获浏览器 `download` 事件 → 存到临时目录，校验正文 |
| `roundtrip-changed` | 改正文并 Ctrl+S，等**服务端** `data.json` 变成新内容 |
| `roundtrip-import-readback` | 点导入 →「继续导入」→ 捕获 `filechooser` 上传那份文件 → 等 `load` → 重新进编辑器，页面与服务端都回到导出时内容 |

## 4. 一个时序坑（第一轮就是这么超时的）

点「继续导入」之后，页面**还停在编辑器里**，导入成功才会 `location.reload()`。
如果按"编辑器 textarea 还在不在"判断"是否回到编辑器"，会**立刻判成"已经回来了"**，
然后 reload 一来又被打回项目中心 —— 后面等 textarea 就是 45 秒超时。

正确做法：监听下一次 `load` 事件，等 reload 真的发生，再重新走「打开项目 → 正文编辑」。

## 5. 新契约 `storage.e2e-roundtrip`（跨证据聚合）

桌面与云端各自跑在不同进程里，结果分别落在 `desktop-runtime.json` 与 `web-cloud-runtime.json`。
"各配置端到端往返"是一个**整体结论**，不能靠两边各自说"我这边过了"。

`scripts/verify/e2e-roundtrip.mjs` 只做三件事，且**不生产任何证据**：

1. 两边**都必须有**完整的往返检查项，**有且仅有一次**，且全部为真（缺一项就失败）；
2. 两边的 `sourceFingerprint` **必须一致** —— 防止把上一轮的桌面证据和这一轮的云端证据拼在一起；
3. 任何一份缺失或不可读 ⇒ 直接失败，不返回"看起来还行"的数字。

输出只有一行 `E2E_ROUNDTRIP ok=7`，验收器只认这个汇总；没有汇总就判红（不猜）。

## 6. 边界：矩阵 `roundtrip/*` 仍然**不点亮**

`policy.json` 里 `roundtrip` 单元要求的四个子场景是：

| 子场景 | 状态 |
|---|---|
| `schema-version`（格式版本兼容/迁移） | ❌ 未验 |
| `sidecars`（外置大块数据一起往返） | ❌ 未验 |
| `secret-stripping`（导出剔除本机密钥） | ❌ 未验 |
| `restore-failure`（导入损坏文件的拒绝与保护） | ❌ 未验（Node 层有 `guestImportShape` 的部分覆盖，但不是端到端） |

所以：**端到端导出→导入本身已验**，但 `roundtrip/desktop`、`roundtrip/web-cloud` 仍未点亮 ——
一个子场景有证据不代表整单元通过（方案 §7 原话）。矩阵仍是 **6/26**。
