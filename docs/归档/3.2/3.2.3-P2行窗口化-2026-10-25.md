# 3.2.3 · P2 行窗口化（2026-10-25 17:00）

> 承接 [P1 行级读取上提](3.2.3-P1行级读取上提-2026-10-25.md)：那轮把取数放大消掉后，medium 首屏仍有 12.7 s、
> large 要 254.7 s —— 结论是瓶颈在**渲染**（22,200 / 74,000 个单元格全量挂 DOM）。本轮就做这一层。

## 1. 做了什么

| 文件 | 改动 |
|---|---|
| `src/components/sheets/useRowWindow.ts`（新增） | 行窗口化 hook + 纯函数 `computeRowWindow`（区间、上下占位、钉住行、变高行估高） |
| `src/components/sheets/TableSheet.tsx` | tbody 首尾各一个「撑高度」的空行，中间只渲染窗口内的行；阈值 `ROW_WINDOW_THRESHOLD = 80` |
| `src/components/sheets/useRowFocusHighlight.ts`（新增） | 跳转聚焦的高亮 + 滚动，改成**有界轮询**（目标行可能还没挂载） |
| `src/components/sheets/useTableSheetModel.ts` | 把上面两段挂上（主文件再涨就会被闸 ① 拦下，所以抽成 hook） |
| `tests/rowWindow.test.ts`（新增） | 纯函数 6 组断言：空表、顶部、滚到底、变高、钉住、超高行 |

设计要点：

- **不改表格结构**：仍是普通 `<table>` + sticky 表头 + `table-fixed` 列宽；只是用一条 `colSpan` 空行顶住高度。
  `<tr>` 做绝对定位在浏览器里不可靠，所以不走「绝对定位虚拟列表」那条路。横向拖拽平移、`divide-y` 分隔线、
  右侧渐隐提示全部不受影响。
- **行高实测**：正文格会自动长高（最多 78px），所以高度必须实测缓存；量尺寸一律 `offsetHeight`
  （界面缩放时 `getBoundingClientRect` 会按 zoom 折算，拿去算位移会错位）。
- **小表不动**：≤ 80 行全量渲染，行为与以前完全一致，减少回归面。
- **跳转聚焦**：目标行可能在几百行之外，直接拉窗口等于把上千行挂回 DOM（实测过一次：指针在第 3 行、
  视口在第 800 行时挂 809 行）。现在改成「近处（≤60 行）拉伸窗口；远处先让容器滚过去，
  高亮侧用 20×60ms 有界轮询接住」。

## 2. 两个坑（都实测踩过）

1. 🔴 **钉住行不能无限拉伸窗口** —— 见上，跨几百行会把虚拟化抵消掉。纯函数里加了 `pinLimit = 60`。
2. 🔴 **滚动位置不能 rAF 节流** —— 取证工具「滚到底再读最后一行」只用 2 帧等待，
   rAF 节流会差一帧读不到末行。单次计算是 O(行数) 次加法（1000 行微秒级），直接同步 `setState` 即可。

## 4. 顺带修掉一个工具的假绿

`--mode compare` 遇到环境/夹具/阈值/指纹不兼容时，异常被 catch 吞掉、状态仍是 `baseline-recorded`，
执行器据此 **exit 0** —— 等于「比不了也算过」。现在 compare 失败必须落 `failed`；
因为动了执行器，`MEASUREMENT_VERSION` 升到 **2**，v1 的旧基线不再可比（有意如此，不是回归）。
修完实测：拿 v1 基线跑 compare → **exit 1 / status failed**（`table-performance-aXbl3F`）。

## 6. 边界（别当已验）

- **只做了行窗口化**，没做列虚拟化（方案里也明确不纳入）；74 列仍全量挂，宽度方向靠横向滚动。
- 未验：真实输入法在窗口边缘的候选框定位、实体设备、安装包；`tree/mixed` 的完整折叠/控件交互回归仍属 P0 余项。
- 高度缓存按行 id 存，改草稿导致行高变化时会重算；极端情况下（一次性粘贴超长文本）滚动条长度会有一次跳变。
- P0 余项（项目冷启动、筛选/清筛选、远端定位、连续滚动分布、A/B 交错、longbook 正文、批量保存压力、阈值冻结）仍未做。
- 可靠性线（local 26 passed / 4 blocked、矩阵 14/26）是 `0708681` 的历史结果；本轮改了源码，P4 合流必须重采。
