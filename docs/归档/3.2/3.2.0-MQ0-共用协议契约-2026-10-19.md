## 1. 为什么先冻结契约

方案 §11.1 把 MQ0 定为「共用协议先行」：WQ1（结果状态）、WQ7（请求归属）、
WQ5（输出结构）、WQ6（流式取消）都要改同一条模型调用边界。**先把状态域和
关联对象的形状定死，再逐个入口迁移**，否则会出现「结果状态各说各话、usage
串账、候选过期判不准」三种新坑。本文件就是那块「图纸」。

## 2. 四个状态域（§17.1，禁止合并）

| 域 | 回答的问题 | 枚举 | 硬规则 |
|---|---|---|---|
| HTTP/流尝试 | 一次请求传完没、退没退 | `AttemptEndReason` | 传输结束 ≠ 业务完成；200 后的错误事件归 `http-error`，不当成功 |
| Q1 步骤结果 | 这项检查/生成有效没、覆盖多少 | `StepResultState` | **合法空结果才算「未发现问题」**；`[]` 与解析失败必须可区分 |
| 持久化任务 | 任务还能不能继续、是否等作者 | `TaskRunState` | 执行壳停了可以有 `awaiting-review` 产物 |
| 候选/提交 | 能不能应用、写了没 | `CandidateState` | 正文 `applied` 不保证问题已修复；`needs-reconcile` 表示主记录已写、派生未结清 |

反模式（写入契约即禁止）：用一个 `status: string` 贯通四层；把 `partial`
显示成「通过」；把未知 usage 填 0。

## 3. WQ1 契约：可区分、可汇总（§16.2）

1. **解析三态**：`valid`（含合法 `[]`）/ `repaired`（只保留验证完整的条目，
   丢弃条目进 `diagnostics.droppedIndex`）/ `invalid`。缺键、非预期对象、
   残缺 JSON、不可恢复文本 **不是**「无问题」。
2. **执行六态**：`completed / partial / failed / cancelled / skipped / incomplete`，
   附 `coverage`（requested/completed/failed/skipped + `uninspected`）。
   摘要文案固定为「完成 X/Y 项，发现 N 条问题」；有缺项时**不得**显示全面通过。
3. **连写自检暂停规则**：本次已启用且承诺执行的必选项失败/未完成 ⇒ 暂停后续
   自动应用、保留草稿（最小检查点，B3）、允许重试/审阅/明确跳过。
   启动前声明资料不足的子检查记 `skipped` 且**始终显示未检**；运行中才发现
   不足 ⇒ 更新 coverage 并要求本次处置，不得伪装完成。
4. **取消传播**：用户取消立即传播，不得被 catch 改成空结果继续连写。
5. **评分缺失**显示「未评分」，禁止填 0 分。

## 4. WQ7 契约：并行归属与真实用量（§16.8）

1. **关联对象**：每次任务显式传 `RunAssociation{projectId, taskId, stepId,
   callId, attemptId}`；任务外单次调用也有独立 `callId`。按 ID 分发回执，
   **废除**「全局最近一次装配 / 当前运行任务」作为归属依据（`aiContext.ts`
   的 `lastAssembly` 与 `usage.ts` 单订阅即此反模式的现存实例）。
2. **contextSnapshot**：装配函数直接返回快照给本次调用；账本只存
   `sourceRefs` 摘要、`included/trimmed/omitted`、`retrieval`、`fieldBasis`
   摘要与 `promptVersion/promptOverrideDigest`。**不存完整正文与密钥**；
   完整提示词仅作者主动开启本机复盘时保存，可删除。
3. **usage 真实性**：从非流式响应与流式尾包提取服务端值；Ollama 按实际返回
   读取。拿不到 ⇒ `'unknown'`，估算另列。降级/重试**逐次计数**（`attemptSeq`），
   降级两次就是两条记录。
4. **旁路原则**：用量/诊断写入可失败而不打断生成；候选载荷、提交意图与主记录
   持久化是关键路径，失败必须停止相应应用。
5. **账本额度**：每项目诊断明细上限 500 条已结束记录或 8 MiB，轮换时不删
   活动任务与被引用依据；**候选全文不进账本额度**。

## 5. 提交回执（§3.3，MQ0 只冻结形状）

`CommitReceipt{operationId, candidateId, state, mainRecordPersisted,
derivedSettled, reconcileHint, committedAt}`。

- 唯一 `operationId` + 主记录提交标记**同一持久化**生效；「原文恰好相同」
  不能推定已应用，同文无标记需人工核对。
- 派生失败 ⇒ `needs-reconcile`，文案「正文已保存，台账待补齐」，只重试派生。
- 主记录写入后取消：不回滚正文，仅停止后续模型请求，按 §3.3 结清核对。

## 7. 冻结纪律与变更流程

1. 变更只能「新增可选字段 / 新增枚举值」；改义、删字段、改必填性视为破坏性
   变更，须更新本文档 + 点名全部实现方 + 提交信息列受影响调用点。

   （`importCycles` 闸与 G3 门面纪律的延伸）。

   §6 清单被各工作包认领。**未认领的入口不得静默沿用旧形状。**
