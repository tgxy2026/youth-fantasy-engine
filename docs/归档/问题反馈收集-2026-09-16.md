## 代码核实记录（2026-09-16，针对 #1）

> 方式：静态代码链路追溯（未跑实机）。结论分「你的猜测是否成立」与「真实成因」两层。

### 一、你的猜测（"没有给模型提供返回并存储数值的入口"）—— **不成立**
- 返回 + 存储入口**存在**：
  - `TavernFree.tsx:642-652`：每轮 AI 回复落库前，调 `refreshSessionVars(...)` → 内部 `extractSessionVars`（一次**单独的结构化调用**，专门干"算数值"这一件事，不让主回复顺手写）。结果写回 `session.vars` 并 `store.saveFreeSession`。
  - `roundEnd.ts:161-194`：「结束本轮对话」时**兜底**再算一次（修过"新会话无 vars 导致整段跳过、数值永远空"的坑）。
- 所以模型**不是**没有入口，而是走"每轮单开一次小调用"的路线（见 `varsRefresh.ts` 头注释：主回复抢不过 3.5KB 格式协议，遵守率实测极低，故拆出来）。

### 二、真实成因（收敛到"显示门控 + 设置不同步"）
1. 右栏 `本场状态` 渲染 `<TavernVarsPanel vars={session.vars} varKeys={varKeys}/>`；面板在 `varKeys.length === 0` 时**只显示占位文字**"没有开启任何状态项。去「控制面板 → 八、本场数值」里勾选，这里就会显示。"（`TavernVarsPanel.tsx:111-117`）。→ 用户看到的"右侧没显示数值"极可能就是这段占位。
2. `varKeys = varsEnabledKeys(tavernSettings)`（`TavernFree.tsx:173-176`）。`varsEnabledKeys` 逻辑正确（`engine.ts:173-176`：主开关关→空，否则 `VAR_KEYS` 减 `off`）；默认 `enabled:true, off:[]` → **5 项全开**（`settings.ts:202-206`，测试 `tavernVars.test.ts:237` 断言"默认 5 项"）。
3. **症结（最可疑）**：`TavernFree` 只在挂载时读一次 `getTavernSettings()`（`TavernFree.tsx:211`，依赖 `[refreshStories]`），之后 `tavernSettings` 锁在 `useState` 内；`getTavernSettings`/`saveTavernSettings` 是**纯异步读写**，**全仓 grep 无 `subscribe`/`emit`/`visibilitychange` 重读机制**。控制面板 `save()` 落库后 toast 明说"下一轮对话即生效"（`TavernControl.tsx:536`）。
   - 推论：若用户在**某次会话已打开时（或打开前）**于控制面板开启「本场数值」，已挂载的对话页 `varKeys` 不刷新 → 右栏一直显示占位文字（= "没显示数值"）。**重新打开会话/页面会重读、正常显示**。
4. 次要可能（≠本次症状）：即便显示修好，若「总结模型」(`summaryProviderId`) 未配置，`refreshSessionVars` 抛错会静默回退原会话（`varsRefresh.ts:81`）→ 数值恒为初值 0（显示"好感 0"而非不显示）。属另一类问题。

### 三、待你定夺的下一步
- 若认同"设置不同步"为真因：修法是在 `TavernFree` 增加"返回页面/切换会话时重读 `getTavernSettings()`"（或加 settings 变更事件订阅），而不是改数值机制——数值机制本身没问题。

### 四、#4 重构后已解决（2026-09-16，随 #4 一并处理）
- **真因收敛**：① `createFreeSession` 从不初始化 `vars`（`store.ts:536-552`，会话对象里根本没有 `vars` 字段）；② `refreshSessionVars` 的 `catch` 把抽取失败**静默吞掉**（`varsRefresh.ts`），一失败就回退到「初值 0」的会话对象 → 右栏看到的永远是 0、且对话再多也不动。两层叠加 = 用户说的「始终不显示 / 不更新」。
- **修法（并入 #4 的设计）**：角色状态改为**存角色卡**（`FreeCharacter.vars: CharVars`，权威源、跨会话累积），会话 `session.vars` 退化为「每轮工作副本」。
  - 打开 / 新建会话时 `seedSessionVarsFromCard` 若主角色卡已有 `vars`，就把会话种子化成卡片里的真实值 → 右栏不再卡在 0，而是显示上一场累积后的状态。
  - 每轮刷新（`refreshSessionVars`）与收尾（`roundEnd`）算完都把**新值 + 新备注**回写卡片（`persistCharVars`），失败不再清零、而是保留上一轮已知值。
- **现状判定**：#1 的「不显示 / 不更新」已被 #4 方案消除（返回会话能看见上轮数值、对话会持续改写并落卡）。
- **遗留建议（非阻塞）**：全新角色（卡片尚无 `vars`）首场仍从 0 起算、首轮刷新后才有值——这是设计既定行为，非 bug；若想让「首场即显示面板框架」更顺，可在 `createFreeSession` 直接注入一个 `emptyVars` 工作副本（待定，非必需）。建议老大于 dev server 实机复验一遍自由对话：开本场数值→聊两轮→结束→重开会话，看右栏是否显示累积后的好感/信任。
