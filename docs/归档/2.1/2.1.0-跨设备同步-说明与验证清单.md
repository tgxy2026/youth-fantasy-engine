# 2.1.0 跨设备数据同步 · 说明与验证清单

> 面向桌面版（2.1.0）。网页版服务器同步已于 2026-09-15 下线，云盘文件同步是**唯一**的跨设备途径。

## 一、两个入口的本质区别

左下角数据坞（项目内则内嵌在侧栏底部）里并排两块东西，**看着都是"把数据放云盘"，机制完全不同**：

| 对照项 | ① 本机存储 → 数据文件位置（🔄 按钮） | ② 云盘文件同步 → 选择同步目录 |
|---|---|---|
| 落盘文件 | `novel-studio-data.json`（**明文**整库） | `青春幻想引擎-同步数据.yfe`（**加密**） |
| 同步粒度 | **整个文件**（谁后写谁赢） | **逐条记录**（按主键做三路合并） |
| 冲突处理 | 无 —— 云盘会自己生成 `.conflict` 副本，但**软件不知道** | 保留本地改动 + 云端那版另存为本地副本 + 界面弹提示 |
| 每日备份 | ❌ 无 | ✅ 有（当天首次同步时生成，可一键回滚） |
| 断网 / 网盘没就绪 | 写入直接失败 | 自动回退本机存储，编辑不丢 |
| 空库防护 | ❌ 无 | ✅ 有（拒绝空推覆盖云端；启动时云端为空则不切换） |
| 敏感数据 | AI 模型的 apiKey 等**明文落盘，并被云盘一起搬走** | 敏感 meta **被排除在同步载荷之外** |
| 多设备同时编辑 | ⚠️ 危险：整库互相覆盖 | 相对安全：合并 + 冲突副本 |
| 界面反馈 | 保存状态点（已保存 / 待保存 / 出错） | 状态徽标（同步中 / 已同步 / 离线 / 同步失败） |

**一句话概括**：

- **①＝把数据库文件扔进云盘**。零机制，云盘只是个搬运工，软件对"文件级冲突"一无所知。
- **②＝用同步引擎 + 云盘当传输通道**。有记录级合并、有每日备份、有断网兜底。

## 二、哪个场景用哪个

| 你的场景 | 用哪个 | 原因 |
|---|---|---|
| 单台机器换存放位置 / 挪到别的硬盘 | **①** | 跟跨设备无关，纯粹改路径 |
| 手动备份：定期把库复制一份到网盘存档 | **①** | 要的就是一个完整可打开的文件 |
| 家里台式 ↔ 办公室笔记本**轮流**用（绝不同时开） | ① 勉强可用，但**必须极小心** | 必须"改完 → 关软件 → 等云盘传完 → 再开另一台"，顺序错一次就是整库覆盖 |
| **两台设备交叉改同一份稿子** | ✅ **②** | 这是它唯一的正经用途 |
| 想要"改错了能回退一步" | **②** | 有每日滚动备份 |
| 不想把 apiKey 之类的配置传到云上 | **②** | 敏感 meta 不上传 |

### 🔴 两者**不要叠加**

把 ② 的同步目录同时当作 ① 的数据文件位置，会发生：

1. 云模式下主数据是 `.yfe`，那个明文 `novel-studio-data.json` **只在"推送失败"时才被更新**（它是兜底镜像，不是主数据）→ 另一台设备读到它只会得到一份陈旧或半吊子的库；
2. apiKey 这类敏感字段会**明文上云**（②本来是专门把它们排除掉的）。

**结论：二选一，用 ②。**

## 三、验证清单（双设备）

### ⚠️ 三条前提

- 必须用**打包版**：dev 浏览器里 `DESKTOP` 是运行时探测（读 `window.electronStore`），恒为 false，两块功能都点不动；
- 必须**两台设备**：同一台机器选两个不同目录**不构成同步**，那是两个互不相干的实例；
- 两台设备都装**同一个云盘客户端**并登录**同一账号**（坚果云 / WPS 云盘 / OneDrive / 百度网盘）。

### 阶段 A · 开启（设备 1）

1. 打开软件 → 左下角数据坞 → 「云盘文件同步」→ 点「选择同步目录」
2. 选云盘里的一个文件夹（建议先新建 `我的小说同步/`）
3. **预期**：
   - 提示「云盘文件同步已开启…」，界面自动重载
   - 状态徽标变绿 + 显示出目录名
   - 去该目录看：应出现 `青春幻想引擎-同步数据.yfe`；**用记事本打开是乱码**（这是加密正常的证据）
   - ❌ 若出现 `.conflict` 副本或明文 json → 云盘层面在打架，停下来排查

### 阶段 B · 第二台设备接入

4. 等云盘客户端显示「同步完成」—— **这一步别抢**
5. 设备 2 打开软件 → 同样「选择同步目录」→ 选**同一个**云盘文件夹
6. **预期**：
   - 状态徽标变绿
   - **能看到设备 1 的项目**（不是空库、没有新建项目引导）
   - ❌ 若显示成空库 / 冒出示范项目 → 正好命中我们刚修过的空快照守卫，报我

### 阶段 C · 双向同步（核心）

7. **设备 2 改一处**（新建一章，写几个字）→ 等状态徽标回到「已同步」→ 等云盘传完
8. **设备 1 不关软件**，等一会儿（引擎是轮询拉取远端）
   - 预期：设备 1 上能看到设备 2 新建的章节
   - ❌ 看不到 → 记下来（可能是轮询间隔或云盘未传完）
9. **反向再来一次**：设备 1 改 → 设备 2 等 → 应能看到

### 阶段 D · 冲突处理（可选，但强烈建议）

10. 两台都**暂停云盘客户端**（模拟断网）
11. 在**同一章同一段**各自改**不同**的内容
12. 两台都恢复云盘 → 等同步
13. **预期**：
    - 各自保留自己的改动
    - **弹出提示「检测到同步冲突：云端那一版已另存为本地副本，你的本地修改未被覆盖」**
    - ❌ 若一边改动无声消失且没有任何提示 → 报我

### 阶段 E · 备份与断网兜底

14. 点「从备份恢复（日期）」→ 弹确认框 → 确认后应回滚到该检查点
15. 暂停云盘客户端 → 随便改点东西 → **关软件** → 重开
    - 预期：改动还在（断网兜底生效），状态显示离线/回退

### 单机也能验的（不必两台设备）

- 开启 / 关闭流程、目录选择、`.yfe` 文件生成、加密形态（记事本打开是乱码）
- 状态徽标的各状态切换
- 备份按钮是否出现
- 关闭同步 → 应切回本机存储，项目数据不丢

## 四、常见现象对照

| 现象 | 原因 |
|---|---|
| 第二台设备打开是空的 | 云盘还没把 `.yfe` 传下来 → 等同步完成再开 |
| 两边改动互相覆盖 | 用的是 ① 而不是 ②，或两台同时编辑 |
| 云盘里冒出一堆 `.conflict` 文件 | ① 的特征（文件级同步必然如此）→ 改用 ② |
| 界面提示「离线」 | 云盘目录不可写 / 网盘客户端被暂停 → 此时编辑会回退本机存储，不丢 |
| 换了同步目录后数据不对 | 换目录**不会**自动搬旧数据；应先用原目录，或从备份恢复 |
