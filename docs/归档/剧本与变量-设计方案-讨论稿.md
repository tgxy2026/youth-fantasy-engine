# 剧本 + 变量（C2 第二步）· 设计方案讨论稿

> **状态**：仅方案，未改代码。老大确认后按选定项实施。
> **范围**：①「剧本编辑」页签（自由对话专用）；② C2 第二步「变量 + AI 输出增量」。
> **不做**：C1 向量记忆、C3 立绘表情（老大 2026-09-14 定：放弃开发）。

---

## 0. 一页看完

**剧本**解决的是「角色卡只给了人，没给戏」：卡里有身份、性格、记忆，但没有"此刻我们在哪、为什么在这儿、这一场想干嘛"。
成熟产品的答案是一致的 —— 把「场景（scenario）」和「开场白（first_mes）」从人设里**拆出来单独一份**。我们照这个拆。

**变量**解决的是「关系推进只能读文字」：C2 第一步已经把这些**只读**摊在状态栏上了，
第二步让 AI 每轮吐一点点增量，把它们变成**会动的数**。

两件事的共同点：都**只服务自由对话**，都**不动角色卡**（卡的语义是"这个人是谁"，剧本与变量是"这一场怎么样"）。

## 1. 调研：成熟产品怎么定义「一场戏」

| 参照 | 关键做法 | 对我们的启示 |
|---|---|---|
| **SillyTavern 角色卡 V2/V3** | `scenario`（此刻处境：地点/关系/为什么在这）＋ `first_mes`（开场白）＋ `alternate_greetings`（多开场可切换） | **场景 ≠ 传记**：Scenario 只管"此刻"，背景归 Description。开场白是**杠杆最高**的字段（模型照它的篇幅、语气、视角写下去） |
| **CrushOn「五行故事卡」** | 谁（今天是谁＋2 个可识别特征）／Ta 想要什么（具体短期目标）／你是谁／刚发生了什么（变化）／什么不该变（边界） | 这就是「**简单剧本**」最省事的骨架，五行足够，多了反而僵 |
| **Apprendly 剧本→RolePlay 模板** | Scenario（核心挑战）／玩家角色与目标优先级／AI 角色背景动机／触发式指令／开场示范 | 「**目标**」与「**边界**」值得单独成栏；"触发式反应"我们不做（那已经接近脚本引擎） |
| **AI Haven / OnlyKin 综述** | 好剧本＝角色＋场景＋关系＋声音＋记忆＋**场景目标**＋开场白；「给角色一个现在就要的东西」 | 一场戏要有**意图**，否则模型只会描述气氛、戏不往前走 |
| **章节化（chapter handoff）** | 真正发生变化后**开新会话**，用一句话交接（"桥那件事三天后…"） | 我们已经有"会话"这一层，不必再造章节 —— **一场会话＝一场戏** |

**结论**：我们的「简单剧本」＝ ST 的 `scenario + first_mes`，加上 CrushOn 的「目标 / 边界」两栏，共 6 栏。

## 2. 剧本设计（6 栏）

| # | 栏 | 回答什么 | 注入 | 备注 |
|---|---|---|---|---|
| 1 | **名称** | 这是什么戏 | 否 | 列表展示用 |
| 2 | **情境** | 此刻在哪、为什么在这儿、刚发生了什么 | ✅ | 就是 ST 的 scenario；**刻意只管此刻**，背景交给角色卡与背景设定 |
| 3 | **开场白** | Ta 说的第一句 | ❌ | 渲染成对话第一条消息，**不进 system**；用协议的输出规范（对白纯文本／（）动作／【】环境） |
| 4 | **你的位置** | 你在这一场里是谁、与 Ta 的关系、你想做什么 | ✅ | 有「我的档案」但那是"你本人"；这一栏是"**这一场**你演谁" |
| 5 | **这一场的目标** | 一个主要目标（可选次要） | ✅ | 给方向，不锁死。**这就是"固定的情节窗口"**落点 |
| 6 | **不要发生** | 这一场不该出现什么 | ✅ | 例：不要提分手 / 不要离开书店 / 不要引入新角色 |

可选（不做也行，先留桩）：**参考开场**（第二条开场白，作者可切换，对应 `alternate_greetings`）。

### 2.1 数据归属与存储

- **剧本库 = 全局**（meta，跨项目）：它跟角色卡同性质 —— 是"玩法模板"，不绑某一本书。
- **会话引用 + 快照**：
  - `FreeSession.scriptId?` —— 引用哪份剧本（列表/回看用）；
  - 加载时把 6 栏**快照**进会话（`scriptSnapshot`）—— 剧本被改或被删，这一场也不会变样。
  - 🔴 为什么不只存引用：剧本是可编辑的，只存引用的话，作者改一次剧本，**所有历史会话的设定都会被悄悄改写**。
- 与现有 `scene` 的关系：`scene`（地点/时间/在场/描述）是**手填版的开场设定**，先保留兼容；
  新逻辑统一走剧本，`scene` 由剧本的第 2 栏派生（地点/时间仍在会话上留一份，供状态栏显示）。

### 2.2 入口与交互（按老大 2026-09-14 的要求）

- **「剧本编辑」页签**（原先的占位）＝ 剧本列表 + 6 栏编辑器 + 「AI 起草」（沿用背景设定那套：一键生成 → 人工微调）。
- **「新建对话」弹窗**：把原来的开场手填区**换成剧本选择器**：
  - `<不设剧本（留空）>` ← 默认，等于以前的"什么都不填"，直接开口聊；
  - 或选一份已有剧本 → 自动带出情境/开场白/目标/边界；
  - 旁边给一个「去新建剧本」的快捷跳转（否则作者找不到写的地方）。
- 留空时：没有开场白（不渲染第一条消息），用户直接说第一句 —— 与今天的"不填场景"行为一致。

## 3. 变量设计（C2 第二步）

### 3.1 变量从哪来

**建议：一组内置变量，作者可逐项关闭，不开放自由定义**（先这样，理由见下）。

| 变量 | 类型 | 范围 | 说明 |
|---|---|---|---|
| 好感 | 数值 | 0–100 | 这一场里 Ta 对你的好感 |
| 信任 | 数值 | 0–100 | 与好感刻意分开：可以喜欢但不信任 |
| 心情 | 文本 | ≤12 字 | 短标签（"微妙的动摇"）。已在 `DailyState.mood` 有先例 |
| 当前地点 | 文本 | ≤12 字 | 会变的场景信息；状态栏直接显示 |
| 剧情进度 | 数值 | 0–100 | 相当于剧本「目标」的完成度 |

- 为什么不做自由定义：变量要**进提示词**（告诉模型有哪些数、怎么用），自由定义等于让作者写协议，
  与"少参数、好默认值"的取向相反；而且自定义数值没有语义，模型不知道"金钱 320"意味着什么。
- 作者要控制的是**开/关**与**初始值**，不是"再发明几个数"。（若以后确有需要，再开放"追加 1–2 个自定义"。）

### 3.2 AI 怎么吐增量（协议改动 —— 本方案最需要谨慎的一处）

- 在协议里加**一条**：每轮回复的**最后一行**，若数值有变化，追加一行
  `〔数值〕好感 +2；心情 微妙的动摇`
- 前端解析规则（**严格**，宁可不认也不误吃正文）：
  1. 只认**最后一行**，且必须以 `〔数值〕` 开头；
  2. 只认白名单变量名（好感/信任/心情/当前地点/剧情进度）；
  3. 数值必须带符号（`+2` / `-3`）或 `=` 直接赋值，超出范围的**夹到边界**；
  4. 解析成功 → 那一行**从正文里剥掉**（不显示、不进记忆）；解析失败 → **原样保留**（绝不吞正文）。
- 冲突风险：协议已用 `〔〕` 表示"状态块"（角色内心状态）。`〔数值〕` 是它的**子类型**，
  正文里出现"〔数值〕"这种组合的概率极低；再加"最后一行 + 白名单"两道闸，误伤面很小。
- 频率与幅度（防"AI 刷数值"）：
  - 默认**每 3 轮**才允许更新一次（可配），避免每轮 ±1 把额度浪费在数字上；
  - 单轮幅度上限 **±5**（可配），0–100 硬夹；
  - 变化在状态栏显示为**带箭头的差量**，并在会话里留一条可回看的记录。

### 3.3 存哪、回滚怎么办（🔴 最容易埋雷的一处）

- 变量是**会话级**（"这一场的好感"），不是角色级 —— 换一场戏本来就该重新开始。
- **必须与消息、记忆水位线一起被带走**：
  - 检查点 `TavernCheckpoint` 加 `vars`；
  - 回滚 / `undoSnapshot` 加 `vars`；
  - 分支 `branchSession` 复制 vars。
  三者只要漏一个，就会出现"回到那一刻了、数值却还是未来的"这种最难查的错
  （与当时"记忆没跟着回滚"是同一类 bug，那次已经吃过一次）。
- 记忆里**不写数值**（记忆是"发生过什么"）；数值由变量单独承载，两者不互相抄。

### 3.4 界面

- 状态栏（C2 第一步已有）加一段「数值」：每个变量一行 —— 名称 + 进度条 + 当前值 + 最近一次差量。
- 变量可**手改**（作者随时纠正模型）：就地输入 + 一条「重置为初始值」。
- 会话里保留一份**变动历史**（第 N 轮：好感 62 → 64），可回看。

## 4. 工程量与顺序建议

| 步骤 | 内容 | 依赖 |
|---|---|---|
| 1 | 变量：数据层 + 协议一条 + 解析 + 夹取 + 回滚联动 + 测试 | 无 |
| 2 | 变量：状态栏展示 + 手改 + 变动历史 | 步骤 1 |
| 3 | 剧本：数据层（全局 meta）+ 6 栏编辑器 + 页签 | 无 |
| 4 | 剧本：新建对话选择器 + 快照 + 注入层 | 步骤 3 |
| 5 | 剧本：AI 起草（沿用背景设定那套） | 步骤 3 |

建议 **1 → 2 → 3 → 4 →（5）**：先把变量跑通（它是协议级改动，越早暴露问题越好），再做剧本。
