# 3.6.2 网页版热修：固定采样模型（Kimi 等）400（2026-11-23）

> 触发：用户反馈「接 Kimi 一直报 400，invalid temperature 要求为 1，是不是网页版的问题」。
> 结论：**不是网页版的问题**；桌面版同一份代码同一结果。已在网页版修复并上线（版本号仍 3.6.2，
> 桌面/便携等 3.6.3 一起发）。

---

## 1. 现象

```
400 invalid temperature: only 1 is allowed for this model
```

任何 AI 功能（续写、取名、校对、拆书…）全挂。

## 2. 根因（两层，第一层让第二层失去兜底）

**① 默认温度就不是 1，而这些模型把采样参数钉死**

Kimi 的 `kimi-k2.*` / `kimi-k3` 是推理模型：Moonshot 把 temperature / top_p / 惩罚项
固定成定值，官方口径是**不要传**（不传 → 服务端默认 → 200）。而本项目：

| 场景 | 实际下发 |
| --- | --- |
| 文字创作（默认「标准」档） | 0.85 |
| 「稳」/「活」档 | 0.7 / 1.0 |
| 结构化 JSON 任务（校对/审读/拆书/抽取） | **0.3（固定，不受档位影响）** |

同类还有 OpenAI `o1/o3/o4`、`gpt-5`、DeepSeek `deepseek-r1` / `deepseek-reasoner`。

**② 400 降级判据把"温度不对"误判成"模型名写错"**

代码本来有 `full → noToggle → bare（撤温度）` 的降级链，但第一步 `shouldDegradeOn400`
用单词 `model` 判硬失败。用 Kimi 原话实测：

```
文案：「invalid temperature: only 1 is allowed for this model」
shouldDegradeOn400          = false   ← 判"配置错了，别重试"
shouldDegradeSamplingOn400  = true    ← 本该走这条
```

`shouldDegradeSamplingOn400` 是 3.4.2 为同一类问题加的，但只接到了 Anthropic / Gemini /
Responses 三家协议上，**OpenAI 兼容通道漏了**。于是降级一次都没跑，用户直接看到原始 400。

## 3. 修复

**A · 固定采样模型一律不下发采样参数（首次请求即生效）**

`src/lib/aiCore/protocols/shared.ts` 新增 `FIXED_SAMPLING_RE` / `usesFixedSampling()`：

```js
/(^|[/_\-. ])(kimi-k2(?!-instruct)|kimi-k3|kimi-for-coding|o1|o3|o4|gpt-5|deepseek-r1|deepseek-reasoner)(?=$|[-_. ])/i
```

- `openaiChat.ts`：命中时 `flags.sampling = false` —— **不发** temperature / top_p / 惩罚项。
- 为什么是"不发"而不是"改成 1"：不同服务商对"必须显式 1"与"必须不传"口径不一致，
  只有"不发"两边都成立（Moonshot 官方文档也这么建议）。
- 🔴 **`kimi-k2-instruct` 显式排除**：它同属 K2 家族但接受任意温度（官方推荐 0.6、不强制）。
  上游就有实现按 `kimi-k2*` 前缀一刀切、把 instruct 系温度也钳死的教训，这里留了回归断言。

**B · 收紧 400 硬失败判据（兜住没识别到的模型）**

`HARD_CONFIG_FAIL_RE` 里 `model` 改成只认"模型确实不存在"的说法
（`model … not found` / `no such model` / `unknown model` / `invalid model` / `model name`
/ `does not exist`），并补上 `messages`、`auth`。
另外 `nextOpenAIFlags` 改为：采样被**明确点名**时直接撤采样，不再先白发一次"撤思考开关"。

**C · 界面如实说明**

`TemperatureField` 增加 `model` 参数：命中固定采样模型时显示
「这个模型固定了采样参数（服务端只接受默认值）：上面三档对它不生效，请求也不会发送温度」。
否则作者按了「活」毫无变化，只会以为软件坏了。

## 3.5 第二版：不再靠"猜模型名"（同日上午追加）

> 作者提出关键质疑：**按模型名判断再全也有漏网** —— 中转站把模型改名、私有部署、
> 手填 `kimi-latest`，一律认不出；而且"降级兜底"是每次调用都重新试错，白花一次请求。
> 要求：撞到报错就提醒用户关掉这些参数，并在设置页给一个勾选项。

于是加了第二层（A 保留为"省掉已知必撞的一次"，不再是唯一防线）：

| 层 | 机制 | 触发时机 |
| --- | --- | --- |
| ① 模型名 | `FIXED_SAMPLING_RE` | 请求前（已知型号） |
| ② **作者开关** | `AIProvider.disableSampling`（新增字段，默认关） | 请求前（**任何**端点/中转站都适用） |
| ③ **会话记忆** | `lib/aiCore/samplingGuard.ts` 内存 Set | 撞过一次 400 之后 |

- **③ 会话记忆**：驱动层因"采样被拒"撤掉参数时，把 `provider.id + model` 记进内存；
  同一端点后续调用**首次就不发**，不再每次都多打一次。只存内存不写用户配置
  （写配置要过 `saveProviders` 的存储上下文守卫，而且在 AI 调用链里偷改用户设置不合适）；
  刷新即清，代价只是重新试一次。
- **② 作者开关**：`请求里彻底不带 temperature / top_p / 惩罚项`。位置在「模型设置 → 采样参数」，
  温度三档下方。撞过之后这里会显示黄条：「上次调用时这个端点拒绝了自定义采样参数（本次已自动跳过）。
  勾上上面这一项，之后就不用每次多试一次。」
- **错误文案引导**：真到"连裸请求也失败"那一步，400 文案不再是"可能是参数不被接受"，而是直接写
  「到「模型设置 → 采样参数」勾选「不发送采样参数」后重试」，并点明哪些模型会这样。
- **四协议全覆盖**：OpenAI 兼容 / Anthropic / Gemini / Responses 都尊重这个开关与会话记忆。
- 语义细节：记忆键含 **model** —— 同一端点换了模型（`kimi-k2.6` → `deepseek-chat`）会重新判断，
  否则换到支持温度的模型上会白白不发温度；取消勾选会清掉记忆，避免"永远不敢发"。

**验证（追加后）**

| 项 | 结果 |
| --- | --- |
| `fixedSampling` | **62 条全过**（新增 E/F/G/H/I 五组） |
| ├ E | 勾了开关 ⇒ 普通模型（deepseek-chat）也不发温度 |
| ├ F | 名字认不出的中转站：第一次撞 400 降级成功 → **第二次只打 1 次且不带温度** |
| ├ G | 取消勾选后记忆清除，重新真实试一次 |
| ├ H/I | Anthropic 同样尊重开关；撞 400 降级后第二次直接不发 |
| 全量 | **512 / 512** |
| 线上界面 | 选「Kimi 月之暗面」预设后，采样区下方确实出现：
「不发送采样参数（温度 / top_p / 惩罚项）」+ 推理模型说明 |

**过程中被测试抓到的两处**

1. 会话记忆是全局的，**泄漏到了 `protocolDegrade` 的后续用例**：用例①撞过 400 后，
   用例③（`disableCompatibilityRetry`）的首次请求已经不带温度 → 不再 400 → 断言"应当抛错"假红。
   修法：记忆键加 model，并在该测试的 `reset()` 里清掉三个协议 × 三个模型的组合。
2. 首版把 `listSamplingRejected()` 导出但没人用 → `deadExports` / `auditSelfCheck` 直接红，
   已删除（不留"以后再用的死导出"）。

## 6. 仍然存在的边界

| 项 | 说明 |
| --- | --- |
| 未列入模型的第一次调用 | 仍会撞一次 400，但**立即自动降级成功**，并把该端点记进会话记忆；作者勾上开关后彻底不再试 |
| 会话记忆不跨刷新 | 有意为之（不擅自改用户配置）。作者不勾开关的话，下次开页面会重新试一次 |
| 同一端点换模型 | 记忆键含 model，会重新判断 —— 换回支持温度的模型时温度照常生效 |
| 桌面 / 便携版 | 本次只发网页版；桌面用户要等 3.6.3 |
| 只拒绝 top_p 而不拒绝 temperature 的服务商 | 撤"采样档"时 temp 与 top_p 一起撤；错误文案里认 `top_p` / `sampling` / `unsupported parameter` |
