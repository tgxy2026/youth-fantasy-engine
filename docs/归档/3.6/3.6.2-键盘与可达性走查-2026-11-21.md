# 3.6.2 键盘与可达性走查（2026-11-21）

> 依据：[3.6.2 开发规划](3.6.2-开发规划方案-2026-11-21.md) W6
> 本文分三部分：**已用静态检查钉住的事实**、**发布后补测的自动化项**（§3–§4）、**明确仍未验的项**（§5）。
> 🔴 一律区分「自动化判定的」与「人判读的」：静态检查不能代替"真的按 Tab 走一遍"，
> 自动化也不能代替"焦点顺序合不合理"。

## 1. 已静态验证（可回归）

这些结论由 `tests/a11yDialogGate.test.ts` 守护（21 条断言，扫描 285 个 tsx）：

| 项 | 结论 |
| --- | --- |
| 自己声明 `role="dialog"` 的位置 | **4 处**：`src/components/dialogs/Modal.tsx`（基座）、`src/components/app/BossOverlay.tsx`、`src/components/help/GuideOverlay.tsx`、`src/components/community/CommunitySquare.tsx` |
| 三件套（`aria-modal` / Esc 出口 / 焦点还原） | 4 处**全部齐全**：Boss 与 Guide 自己处理，Modal 交给 `src/lib/app/overlayScope.ts` |
| `overlayScope` 的实现 | 处理 `Escape`、Tab 焦点陷阱（含 `shiftKey` 反向）、关闭时把焦点还原到触发元素 |
| 容器焦点还原的健壮性 | 还原前判 `isConnected` —— 触发元素可能已被移除（列表按钮），此时不回落到已脱离文档的节点 |
| 正 `tabIndex`（会打乱 Tab 顺序） | 全仓 **0 处** |
| 焦点可见样式 | `src/index.css` 有全局 `button:focus-visible, a:focus-visible, [tabindex='0']:focus-visible`（2px amber 描边 + 2px 偏移） |
| 输入法组合期的 Esc | Guide 与 Community 都判了 `isComposing` —— 中文输入法按 Esc 取消候选词时**不会**误关面板 |

### 本轮实际修的一处

**`src/components/community/CommunitySquare.tsx`（投稿广场浮层）**原先有 `role="dialog"` + `aria-modal`，
但**没有键盘出口、也不接管焦点**：键盘用户打开广场后只能靠 Tab 一路摸到关闭按钮，关闭后焦点掉回 `body`。

已补：Esc 关闭（跳过输入法组合期）、打开时把焦点移到容器、关闭时还原到触发元素。

> 刻意**不做焦点陷阱**：广场是长滚动容器，把 Tab 锁在首屏反而让人到不了下面的投稿流。
> WCAG 2.1.2 要求的是「不能被键盘困住」，Esc 随时可退出已满足这一点。

## 2. 命中区尺寸（静态推算）

| 控件档位 | 实际尺寸 | 与 WCAG 2.2（24×24） |
| --- | --- | --- |
| `size="xs"` | 高 24px + 左右内边距 8px | **刚好达标**（24 是下限） |
| `size="sm"` | 高 32px | 达标 |
| `size="md"` / `lg` | 36px / 40px | 达标 |
| 图标键（`iconOnly`） | 32×32 | 达标 |
| 触摸设备 | `index.css` 有 44×44 热区规则（`data-button-icon-only` / `data-button-sizing="icon"`） | 达标（AA 推荐值） |

⚠️ **已实测（2026-11-21 晚）**：项目中心与正文页的 `xs` 档按钮里，最小的是 **51×22「清空」**，
高度比 WCAG 2.2 的 24px 下限低 2px；其余（图标键 32×32、「紧凑」41×32、「自动」46×32）都达标。
`Button` 的 xs 高度是全局口径，发布后零散改容易牵连别处布局，故**记入技术债、未擅自调整**。

## 3. 三条主流程的键盘走查

> **2026-11-21 晚补测**：发布后用已安装的 3.6.2 桌面版跑了一轮**自动化驱动**
> （`scripts/verify/keyboard-zoom-walkthrough.mjs`，不是人按的，所以只判"可判定项"）。
> 流程 ① 的 1/3/4 有实测；**②③ 与 ①的弹窗两步仍未验**，如实留空 —— 不把"没测"写成"通过"。

### 流程 ①：写一章 → 保存 → 导出

| 步 | 操作 | 预期焦点 | 实测 |
| --- | --- | --- | --- |
| 1 | 项目中心按 `Tab` | 焦点依次落在项目卡片 → 打开按钮，可见 amber 描边 | **✅ 自动化**：连按 14 格无一次落到 `body`、无零尺寸、无视口外焦点。序列：项目管理怎么用 → 创建示范项目 → 导入已有项目 → 投稿广场 → 新建小说项目 → 外观 → 帮助 → 收起左下角工具栏 → 紧凑 → 舒适 → 云端账号未登录 |
| 2 | 打开项目后按 `Tab` 进侧栏 | 侧栏当前项可聚焦，回车切换 | **未验**（只验了"焦点有落点"，没验回车切换与侧栏内部顺序） |
| 3 | 进正文编辑器，`Tab` 到正文区 | 焦点进入编辑区，可直接输入 | **✅ 自动化**：`textarea.novel-textarea` 可点入并正常输入（中文正文，`delay: 20`） |
| 4 | `Ctrl+S` 保存 | 底部提示「已保存」，焦点**不被抢走** | **✅ 自动化**：保存后 `document.activeElement` 仍是 `textarea.novel-textarea`，页面出现「已保存/已同步」 |
| 5 | 打开导出弹窗（工具 → 导出） | 焦点进入弹窗面板；`Esc` 关闭后**回到导出按钮** | **未验**：试了 外观/帮助/模型设置/后台任务/备份 都打不开 `role="dialog"`，本轮没取到浮层入口 |
| 6 | 弹窗内 `Tab` | 焦点在弹窗内循环，不会跑到背后 | **未验**（同上；这项目前由 `a11yDialogGate` 21 条 + `overlayScope` 单测兜着） |

### 流程 ②：改设定 → 正文检索命中

| 步 | 操作 | 预期焦点 | 实测 |
| --- | --- | --- | --- |
| 1 | 设定检索页，`Tab` 到搜索框 | 可直接输入；输入法候选正常 | **未验**（本轮未走这条流程） |
| 2 | 结果列表 `↑/↓` 或 `Tab` | 能到达结果项并回车打开 | **未验** |
| 3 | 打开的详情面板 `Esc` | 关闭并把焦点还给结果项 | **未验** |

### 流程 ③：问 AI → 采纳 / 放弃

| 步 | 操作 | 预期焦点 | 实测 |
| --- | --- | --- | --- |
| 1 | 打开颉文姬面板 | 焦点进入面板；`Esc` 退出并还原 | **未验**（需要真实模型响应与已配置的 AI 通道） |
| 2 | 剧情候选面板，`Tab` 到「应用」 | 可聚焦、有可见描边 | **未验** |
| 3 | 应用后 `Tab` 到「撤销」 | 可达；撤销后焦点不丢失 | **未验** |
| 4 | 放弃某条候选 | 列表刷新后焦点**不落到 body** | **未验** |

## 4. 界面缩放

> **2026-11-21 晚补测**：132% 是应用自动适配档（`--ui-zoom: 1.32`，应用内档位只有 80%~160%），
> 200% 靠 Chromium 缩放复现（用户按 `Ctrl` + `+` 就是这条路）。
> 截图在 `.workbuddy/evidence/w6-2026-11-21/`：`03-zoom-auto.png`、`04-zoom-200.png`、`05-zoom-200-dialog.png`。

- [x] **无横向溢出**：132% 与 200% 两档都是 `scrollWidth === innerWidth`
- [x] **200% 下关闭按钮可点**：浮层关闭按钮 32×32，几何上完全在视口内
- [ ] 弹窗标题栏与底部按钮不重叠 —— 只验了关闭按钮位置，没做逐像素重叠检查
- [ ] 颉文姬面板与正文区不互相遮挡 —— 未验（需要开 AI 面板）
- [ ] 表格工具栏在 200% 下换行而不是被裁掉 —— 未验（没进表格页）
- [ ] 侧栏折叠后主区宽度仍可用 —— 未验

## 5. 明确未验（不写成通过）

| 项 | 原因 |
| --- | --- |
| 流程 ②③、①的弹窗两步 | 需要真实模型响应 / 没取到浮层入口；自动化只覆盖了项目中心 Tab、正文输入、`Ctrl+S` 焦点保持 |
| 焦点顺序"是否最合理" | 序列已记录（见 §3 流程①第 1 步），但"顺序合理"是人的判断，脚本不下结论 |
| 弹窗标题栏与底部按钮逐像素重叠 | 本轮只做了"关闭按钮可点"，没做重叠检测 |
| 读屏器（NVDA / VoiceOver）朗读顺序 | 本轮未做；`aria-*` 齐全不等于朗读顺序正确 |
| `xs` 档文字按钮宽度 | **已量**：最小 **51×22「清空」**，高度低于 WCAG 2.2 的 24px 下限 2px（记入技术债，未擅自改全局档位） |
