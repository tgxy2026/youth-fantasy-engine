## 二、L4：不引组件测试工具，改「把判定抽成纯函数」

**为什么不装 React 测试工具**（当时判断，写在这里以免后人重复纠结）：
- 零覆盖的 8 个组件里，**只有 2 个是数据安全相关**，其余 6 个是纯展示 —— 为 2 个组件引入
  jsdom ＋ testing-library 一整条依赖链（体积、CI 时间、维护面）并不划算；
- 更要紧的是：这两个组件的**真问题不在渲染，而在判定** ——
  把它们抽成纯函数后，判定能被**逐条断言**，覆盖率比「挂载组件断言 DOM」更实。

### L4-a `BackupReminder` —— 第三条判据入 lib

三条触发条件里，①② 早在 lib 且被 15 条测试覆盖；**③「确有数据可丢」只活在组件的 `useEffect` 里**
（`hasProject || 项目列表非空`）—— 组件没有测试 ⇒ 这条边界从没人守。

新增 `shouldRemind({ exportOverdue, dismissExpired, hasProject, projectCount })`：
- 🔴 四个输入**全部显式传入**（连 ①② 也不在函数里现读 localStorage）⇒ **真纯函数**，
  断言不需要伪造时间或存储信号，短路顺序也一目了然；
- 组件只负责取数（`isExportOverdue()` / `isDismissExpired()` / 必要时查项目列表）。

### L4-b `DesktopWriteLockBanner` —— 六分支判定入 lib

它背后是桌面版最要命的一条红线：**读不出数据文件就别写盘，否则内存里的空库会覆盖磁盘上的真实数据**。
而判定原先内联在 `initDesktopStore` —— 它依赖 `DESKTOP`（模块级 const，读 preload 注入）与 IPC 桥，
**测试环境注入不了** ⇒ 这条红线从来没被测试守过。

新增 `decideDataFileLoad(r): DataFileOutcome`（`empty` / `ready` / `lock`），六条分支全部收进来；
`initDesktopStore` 只施加副作用（锁写盘 / 装载数据）。三条经验教训随判定一起搬进注释：

| 教训 | 出处 |
|---|---|
| **`missing` 未知时不能当「首次使用」放行**（否则空库覆盖真实文件） | 2026-09-17 P2-11 |
| **解析成功 ≠ 是本软件的数据文件**（漏 `isPortableDataFile` = 静默覆盖，不是报错） | 2026-09-20 P1-2 |
| 任何「读不出来」一律 `lock`，绝不静默当空库 | 本次收口 |

## 三、L5：先量化，只切「依赖最少的那头」

### 3.1 量化（`dep-cost.mjs`，组件范围 61–906）

| JSX 区块 | 行数 | props 面（组件作用域 + 导入） |
|---|---|---|
| header 标题＋计数 | 24 | **0** |
| 工具行（新建/导入/导出/保存） | 34 | 12 |
| **左栏 故事→剧本树** | **68** | **9** ← 可拆实体里最窄 |
| 中栏 设定 / 剧本六栏 | 178 | 11 |
| 右栏 AI 起草 / 故事信息 | 204 | **24** ← 最宽 |

### 3.2 执行：只抽左栏（`TavernScriptTree.tsx`）

- **依据**：左栏 props 面 9、且高度内聚（只读列表、只发回调，不碰写操作与业务规则）；
- **结果**：`TavernScript.tsx` **906 → 847 行**；左栏 68 行独立成组件，props 命名改 `onToggleOpen` / `onOpenStory` / `onOpenScript`。

### 3.3 🔴 为什么不一次拆完（**转入 W4-3**）

§11.1 L5 原文要求「**与 #11 跑团对酒馆页的扩展一起规划 —— 别先拆完再改，否则白拆一次**」。
而量化结果正好印证了这条：

- **右栏（AI 起草 / 故事信息）props 面最宽（24）**，且它正是跑团扩展会动的地方
  （推演 / AI KP / 互动分支都长在那）；**先拆 = 白拆**。
- 中栏（178 行、props 11）与右栏同属「编辑 + AI」区，一并留到 W4-3 更省一次改动。

⇒ **W3-3 只交付左栏这一刀**；中栏 / 右栏的拆分列入 **W4-3 的可执行清单**（量化数据已备好）。
