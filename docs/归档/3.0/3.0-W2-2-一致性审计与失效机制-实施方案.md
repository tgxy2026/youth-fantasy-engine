## 一、目标（方案 §10.3 #4 原文口径）

1. **显式触发**：按任务配置或作者触发，**非后台自动跑**。
2. **一致性审计**：跨章核对事实 / 状态 / 伏笔 / 关系等冲突。
3. **失效机制**：正文改动后审计结果**标记为未知、需重跑**，**不自动重试**
   （避免拿旧报告给新稿盖章）。
4. **保障边界**：版本 / 作用域 / 结构 / 状态转换 / 写回规则由**确定性代码**检查；
   语义层面（隐喻、潜台词、未登记伏笔、文学效果）仍需**模型 + 作者判断**。

🔴 结合点（§10.3 #4 末）：*「基于现有 `dataHealth` + 优化工单升级为『按章审计 + 正文指纹失效』，
沿用方案 C 的『不常驻 / 静默跑 / 只报数』口径。」*

## 三、设计

### 3.1 按章审计留痕（`src/lib/chapterAudit.ts` · 新增）

```ts
export interface ChapterAuditRecord {
  chapterId: string
  chapterTitle: string
  /** 🔴 结果绑定的正文指纹（复用 W1-1 的 chapterFingerprint） */
  fingerprint: string
  at: number
  /** 只报数，不存全文（方案 C 口径：结果不做「第二个数据源」） */
  counts: { continuity: number; foreshadow: number; sensitive: number; typos: number; style: number }
  /** 汇总待处理条数（面板顶栏同口径 countActionable） */
  actionables: number
}

/** 纯函数：这份报告对当前正文还作不作数 */
export function checkAuditFresh(
  record: ChapterAuditRecord,
  ch: Pick<Chapter, 'title' | 'content' | 'wordCount' | 'updatedAt'>,
): { fresh: boolean; reason: string }

saveChapterAudit(report, chapter)          // 跑完留痕
readChapterAudit(chapterId)                // 读留痕
loadChapterAuditStatus(chapterId, chapter) // 读 + 判失效，一次取
```

- 存储：项目级 `settingsKV`，键 `chapterAudit`，值 `Record<chapterId, ChapterAuditRecord>`；
  **上限 300 条**（超出按 `at` 淘汰最旧）。
- 🔴 **失效判据（纯函数）**：`chapterFingerprint` 不符 ⇒ `fresh=false`，
  reason = 「正文在上次体检后改过」；无记录 ⇒ `fresh=false`，reason = 「还没有体检过」。
  ⚠️ 指纹含 `updatedAt`（W1-1 同口径）—— 改坏又改回原样**也算改过**，宁可重跑一次。
- 🔴 **不自动重跑**：`fresh=false` 只是**标注**，重跑一律由作者点按钮。

### 3.2 UI（挂既有「本章体检」面板 · 不新建页面）

`ChapterCheckPanel.tsx`：
- 跑完 ⇒ `saveChapterAudit`（留痕）；
- 切章 / 载入 ⇒ `loadChapterAuditStatus`：
  - **有效**：显示「上次体检：N 分钟前 · 待处理 X 项」；
  - **已过期**：显示醒目的一行「⚠️ 正文在上次体检后改过，这份结果已过期 —— 请重新体检」
    （**不自动重跑**，不挡任何操作）；
  - 无记录：不显示（保持现有空态引导）。
- 帮助弹窗补一句口径说明。

## 五、边界与红线（照做）

- 🔴 **不自动重跑、不后台静默跑** —— 只有作者点按钮才跑（方案 §10.3 #4 首条）。
- 🔴 **只报数不存全文** —— 留痕只记计数与指纹，不把问题列表落库（避免变成「第二个数据源」）。
- 🔴 **不新建页面** —— 挂在既有「本章体检」面板上。
- 🔴 复用 `chapterFingerprint`（不另发明一套指纹）。
- 🔴 留痕失败静默 —— 绝不能因为写不进台账而让体检本身失败。
- 🔴 语义层面的判断仍归模型 + 作者（本模块只做「结果有效性」这类确定性的事）。
