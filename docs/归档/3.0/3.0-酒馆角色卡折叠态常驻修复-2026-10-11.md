# 酒馆模式 · 角色卡片左栏「故事折叠态」不能常驻 —— 修复记录

> 日期：2026-10-11 ｜ 触发：主人哥哥实机使用反馈 ｜ 版本：3.0.0

## 一、问题（作者原话）

> 在酒馆模式组角色卡片这里，角色卡片可以是自由和挂载到某一个故事下面的状态，
> 当角色卡片挂载到故事下面之后，是可以进行折叠的。但是我发现，**折叠状态并不能常驻**。
> 如果我点击保存并刷新了这个页签之后，**原本已经折叠的列表就会被重新展开**。

## 二、根因

`useTavernCardModel.ts` 里 `openIds`（哪些故事展开着）是**纯内存 state**：

```ts
const [openIds, setOpenIds] = useState<string[]>([])
```

而 `load()` 每次都被写成「把**还没见过的**故事全部补进展开集合」：

```ts
setOpenIds(prev => {
  const known = new Set(prev)
  const fresh = ss.map(s => s.id).filter(id => !known.has(id))   // ← 罪魁
  ...
  return fresh.length ? [...prev, ...fresh] : prev
})
```

**内存态 + 每次重挂 state 归零** ⇒ 切走页签（组件卸载）再切回来时 `prev` 是空的，
于是 `fresh` 就是全部故事 ⇒ **作者手动收起的分组统统被重新展开**。

> 这条逻辑在**同一次挂载内**是对的（`save()` 后 `load()` 时 `prev` 还在，是 no-op）；
> 只有**组件重挂**才会暴露 —— 所以静态读代码很容易看漏。

## 三、修法（照项目既有约定，不发明新机制）

折叠态是**界面偏好** ⇒ 走 `src/lib/settings/uiPrefs.ts`（localStorage，跨会话记忆、
不随项目导出/同步走）。该模块有一条铁律：

> 🔴 **一律存「偏离默认的那一侧」** —— 侧栏存「已折叠的分组」，因为默认是展开的。

按这条口径落地：

| 页面 | 默认态 | 存哪一侧 | 键 |
|---|---|---|---|
| **角色卡片**（本次报的） | 全**展开** | **已收起** | `yfe-ui:tavern-card-collapsed` |
| **故事剧本**（同类缺陷，一并修） | 全**收起** | 已展开 | `yfe-ui:tavern-script-open` |

> ⚠️ 两页方向**相反**，代码注释里互相都写了「别抄错」。

### 具体改动

**新增两个纯函数**（`uiPrefs.ts`，避免换算逻辑在组件里手写而漂移）：

```ts
expandedIdsOf(allIds, collapsed)   // 展开 = 全集 − 已收起
collapsedIdsOf(allIds, expanded)   // 收起 = 全集 − 展开（写盘用）
```

**`useTavernCardModel.ts`**：

- 新增 `CARD_COLLAPSED_KEY`、`collapsedRef`（持久化的已收起集合）、`groupIdsRef`（当前全集）。
- `load()` 改为：算全集 → 剪掉已不存在分组的残留记录 → `展开 = expandedIdsOf(全集, 已收起)`。
- `setOpenIds` 包一层持久化 setter，**签名保持 `Dispatch<SetStateAction<string[]>>` 不变**
  ⇒ 子组件 `TavernCardList.tsx` **一个字都不用改**（搜索 / 展开逻辑零风险）。
- 写盘规则：`已收起 = collapsedIdsOf(全集, 新展开集合)`。

**`TavernScript.tsx`**：改用 `usePersistedSet('tavern-script-open')`（默认收起 ⇒ 直接存展开即可），
`toggleOpen` / 新建故事 / 新建剧本三处改写为 Set 更新。

### 效果

- 作者收起的故事：切走再回来**仍收起** ✅
- **新出现的故事**：不在「已收起」记录里 ⇒ **自动展开** ✅（这正是"存偏离默认那一侧"的价值）
- 故事删除后残留的 id：`load()` 顺手剪掉，不会在 localStorage 里越攒越多

## 四、验证

- 纯换算边界：全展开 / 部分收起 / **全收起也合法**（不能退化成"没记录→全展开"）/ 顺序保留 / 死 id 容错 / 补集往返自洽；
- 🔴 **回归语义**：模拟重挂再算一次 —— 收起的仍收起、**新故事自动展开**；
- 静态接线：两个组件都用了 uiPrefs、各存对的那一侧、`load()` 里已无「盲目补 fresh」的旧写法。

## 五、🔴 教训

1. **"默认展开 + 每次 load 补 fresh" 是这类 bug 的通用形态**：只要状态是内存态，
   重挂就必然全展开。凡是**受控折叠**，一律持久化，且**存偏离默认的那一侧**。
2. **持久化 setter 保持原签名**，能把「改状态源」的影响面锁在 hook 一层 ——
   子组件完全不用动，也不破坏它自己的搜索/展开逻辑。
3. **同一类缺陷要扫同类页面**：剧本页有完全相同的形态（它甚至连"默认展开"都没有，
   纯内存 `[]` ⇒ 每次重挂全收起），一并修掉。
