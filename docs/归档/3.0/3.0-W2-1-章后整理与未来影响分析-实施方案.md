## 一、目标（方案 §10.3 #3 原文口径）

1. **章后整理**：每章写完后，把本章带来的「**事实、人物状态、关系、伏笔**」变化作为独立任务整理；
   作者确认需保留的内容，为下一章准备依据。
2. **未来影响分析**：「**未来演化边界**」—— 已写历史保持稳定；上游（已写正文 / 设定）变化
   使旧的「未来计划」失效。
3. **中断恢复**：章后候选中断后可恢复，**已有候选不重复调用模型**。

🔴 结合点（方案 §10.3 #3 末）：*「已有设定变更 / 伏笔追踪 / 知情权限 / 改写后设定同步 ⇒
章后整理做成挂在既有能力上的**统一入口闭环**，不新建孤立页面。」*

## 三、设计

### 3.1 章后整理（`src/lib/chapterPostProcess.ts` · 新增）

**一条统一流水线**：`抽取（AI）→ 比对（确定性）→ 报告 → 作者勾选 → 落库`。
🔴 与 `settingLedger` 同一条铁律：**AI 只抽候选，「是否已登记 / 是否变化」一律由确定性代码判**。

```ts
export type PostProcessKind = 'entity' | 'foreshadow' | 'relation' | 'status'

export interface PostProcessItem {
  kind: PostProcessKind
  key: string                    // 列表 key
  status: 'new' | 'changed' | 'registered'   // 待补登 / 有变化 / 已登记无需动
  label: string                  // 展示名（实体名 / F0001 / 人物A×人物B / 人物名）
  detail?: string                // 一句话说明（AI 给）
  evidence?: string              // 原文证据（可溯源）
  targetTabId?: string           // 落库目标表 / 卡（界面可改）
  payload?: Record<string, string>  // 待写入字段（仅安全字段）
}

export interface PostProcessReport {
  chapterId: string
  chapterTitle: string
  fingerprint: string            // chapterFingerprint(本章) —— 结果绑定正文
  at: number
  items: PostProcessItem[]
  notes: string[]                // 说明（如「本章无正文，已跳过」）
}
```

**三类新抽取**（**合并为一个 AI 任务**，省调用、省 prompt 维护）：

```ts
// aiTasks/postProcess.ts（新增）
aiExtractChapterChanges(body, title, opts): Promise<{
  foreshadows: { code?: string; content: string; action: '埋设' | '回收' }[]
  relations:  { a: string; b: string; type?: string; change: string }[]
  statuses:   { name: string; state: string; evidence?: string }[]
}>
```
- 走 `json: true`（项目红线），统一 `aiParse`。
- **确定性比对**：
  - `foreshadows` ↔ `foreshadow` 表（按编号 / 内容归一化名）：命中 ⇒ `changed`（可登记到章节总表）、未命中 ⇒ `new`（提示先去伏笔追踪登记，**不凭空建**）。
  - `relations` ↔ `relations` 表（同对同向同类型）：命中 ⇒ `changed`（追加「演变轨迹 / 触发事件」）、未命中 ⇒ `new`。
  - `statuses` ↔ 角色卡「人物状态」字段：不同 ⇒ `changed`。

**落库**（`applyPostProcess(report, chosen)`）：
| 类 | 落点 | 安全边界 |
|---|---|---|
| entity | 复用 `commitEntities`（设定表 / 角色卡） | 只填名称 + 一句话 + 首现章，其余留空 |
| foreshadow | 章节总表 `埋设伏笔编号` / `回收伏笔编号`（**追加不覆盖**） | 只追加编号，不动伏笔表属性 |
| relation | `relations` 表「演变轨迹 / 演变触发事件」（**追加**） | 不覆盖「关系现状」等属性列 |
| status | 角色卡「人物状态」字段 | 只在变化时写，逐条确认 |

**幂等 / 断点**：报告记入 `aiRuns`（`kind: 'post-process'`，复用 W1-1 账本）；
正文指纹变化的旧报告**标 stale**（复用 `chapterFingerprint` / `checkBasisStale`）。

### 3.2 未来影响分析（`src/lib/futureImpact.ts` · 新增）

**「未来演化边界」的定义（本项目落地口径）**：
> 已写章节（正文已存在的）**冻结**；章纲卡（`chapter-outline`）中**章号 > 已写最大章号**的条目
> = 「未来计划」。当**上游变化**（某章正文被改写 / 设定被改）时，这些「未来计划」**标记为待重审**。

```ts
export interface ImpactMark {
  chapterNo: number        // 受影响的未来章号
  fromChapterNo: number    // 因哪一章变化而失效
  reason: string           // 原因（正文改写 / 设定变化）
  at: number
}

analyzeFutureImpact(fromChapterNo, reason): Promise<ImpactMark[]>   // 纯计算 + 落库
readImpact(): Promise<ImpactMark[]>                                  // 读标记
clearImpact(chapterNo?): Promise<void>                               // 作者处置后清标记
```
- 存储：**项目级 `settingsKV`**，键 `futureImpact`（`db.getSetting/setSetting` 自带 `<pid>::` 前缀）。
- 触发：`applyChapterRewrite` 成功后（**唯一会覆盖作者正文的路径**，与 W1-1 同一处）+ 章后整理确认后。
- 🔴 **只标记 + 提示，绝不自动改章纲内容**（沿用「AI 只辅助」红线）。

### 3.3 UI（挂既有入口 · 不新建孤立页面）

**颉文姬「补登」模式 → 升级为「整理」模式**（`JieWenJiLedger.tsx` → 扩为四区块 + 未来影响）：
- 四类分区（实体 / 伏笔 / 关系 / 状态），各带计数徽章，勾选后一键落库；
- **未来影响**区块：列出受影响的未来章号 + 可跳转章纲卡 + 「已处理」清标记；
- 保留原「补登」全部行为（**零回退**）。

## 五、边界与红线（照做）

- 🔴 **AI 只抽候选**：是否已登记 / 是否变化 → 确定性代码判（`settingLedger` 同款铁律）。
- 🔴 **只追加不覆盖**：关系「演变轨迹」、章节总表「伏笔编号」一律追加；属性列绝不自动改。
- 🔴 **不凭空建条目**：伏笔 / 关系未登记时只**提示**，不自动新建（与 `backfillOutlineEvent` 的
  「绝不新建细纲卡」同口径）。
- 🔴 **未来影响只标记**，不自动改章纲。
- 🔴 走 `chat()`（自动注入系统提示词）、结构化必传 `json: true`、解析走 `aiParse`（禁裸 `JSON.parse`）。
- 🔴 记账失败静默，绝不打断创作（沿用 W1-1）。
- 🔴 不新建孤立页面；不改 `docs/优化清单.md` 与历史文档。
