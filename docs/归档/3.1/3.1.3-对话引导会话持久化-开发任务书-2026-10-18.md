## 1. 背景：现存问题（已核实的事实，不要再重复探索）

项目里共有 6 处 AI 对话/工具窗口，其中 **5 处有持久化或为一次性工具，只有「对话引导」聊完即丢**：

| 窗口 | 文件 | 状态存放 | 退出后 |
|---|---|---|---|
| 对话引导 InterviewChat | `src/components/creative/InterviewChat.tsx` | `useState(() => emptyInterview())`（第 51 行）+ `input`（52） | ❌ **全丢**，无确认 |
| AI 补全（fill 模式） | `src/components/ai/AITemplateFill.tsx` | useState + 草稿本 | 输入/结果丢；草稿本保留 |
| 灵感工具 AI 对话 | `src/components/ai/AIAssist.tsx` | `ChatSession[]` → settingsKV `aiChatSessions`（第 44 行） | ✅ 保留 |
| 酒馆模式 | `src/components/tavern/TavernPlot.tsx` | `store.saveSession()` | ✅ 保留 |
| AI 整理 AIOrganize | `src/components/ai/AIOrganize.tsx` | useState | ❌ 丢（一次性工具，可接受） |
| 检查工具 AI 分析 FeedbackAIPanel | `src/components/ai/FeedbackAIPanel.tsx` | useState | ❌ 丢（一次性工具，可接受） |

**真实痛点**：作者被「聊聊主角设定」，AI 问到第 8 个问题（性格缺陷？核心动机？），电话来了切出去；回来点「对话引导」→ 从第一个问题重来，之前答的全要重答。切页签同理会丢（组件卸载）。

---

## 2. 目标（两件事，一起交付）

### A. 会话持久化（主修）
对话引导的 `InterviewState` 按作用域存进项目 settingsKV，重开时恢复，并让作者自己选「继续」还是「重新开始」。

### B. 关闭确认（防误关）
有对话内容且尚未填回表单时，关闭弹窗要先问一句，避免手滑丢会话。

## 4. 实现规格

### 4.1 存储键与结构

新增 `src/lib/creative/interviewStore.ts`（纯函数层，**不 import any component**）：

```ts
const PREFIX = 'interview::'

/** 作用域 → 存储键；scope 为空时返回 '' 表示不存档 */
export function interviewKeyOf(scope: string): string

export interface InterviewArchive {
  state: InterviewState
  updatedAt: number      // 最后一次落盘时间戳（恢复提示显示「X 分钟前」）
  applied: boolean       // 是否已填回表单（true 时下次打开直接丢弃）
  subject: string        // 恢复提示用：「上次在聊『主要角色』」
}

export async function loadInterviewArchive(scope: string): Promise<InterviewArchive | null>
export async function saveInterviewArchive(scope: string, a: InterviewArchive): Promise<boolean>
export async function clearInterviewArchive(scope: string): Promise<void>
/** 超过 7 天的存档视为过期，读取时直接清掉并返回 null（避免陈年会话突然冒出） */
export const INTERVIEW_ARCHIVE_TTL_MS = 7 * 24 * 3600 * 1000
```

🔴 必须走 `@/lib/db` 的 `getSetting / setSetting`（项目门面），**不要**直接 import `./db/meta`——门面是唯一存储入口，绕过去会让将来的迁移漏一处。
🔴 settingsKV 天然按项目隔离（`${pid}::interview::<scope>`），**不要**自己拼 pid。
🔴 参考现成实现：`src/lib/editor/freeDraft.ts`（同一套「极薄一层」的写法，含失败不阻断界面的约定）。

### 4.2 InterviewChat 改造

新增 props：
```ts
/** 存档作用域（由调用方给稳定值）；不传则不持久化（例如一次性试聊） */
persistScope?: string
/** 恢复提示里的主语（默认用 subject） */
persistLabel?: string
```

行为：
1. **打开时**：`loadInterviewArchive(persistScope)`
   - 有存档且 `turns.length > 0` 且 `!applied` → 在对话区顶部渲染一条提示条：
     > 「上次聊到第 N 轮（X 分钟前）· 继续上次 / 重新开始」
   - 点「继续上次」→ `setState(archive.state)`，提示条消失
   - 点「重新开始」→ `setState(emptyInterview())` 并 `clearInterviewArchive`
   - **默认不自动恢复**（避免作者以为从零开始，实际带着旧对话）
2. **每轮成功后**（`runTurn` 返回后）：`saveInterviewArchive(scope, { state: next, updatedAt: Date.now(), applied: false, subject })`
   - 🔴 异步落盘：**先 `setState` 再落盘**，落盘失败只 `console.warn` 或静默，**绝不阻断对话**（存档不是关键数据）
   - 🔴 同一 scope 的落盘必须**串行**（复用 freeDraft 的写法：模块级 Promise 链），否则后写的会被前写的覆盖
3. **关闭时（B 方案）**：
   ```ts
   const requestClose = () => {
     if (state.turns.length > 0 && !applied) {
       confirmDialog({
         title: '对话还没填回表单',
         message: '关掉后这段对话会保留存档，下次可以继续；现在要关闭吗？',
         confirmLabel: '关闭',
         cancelLabel: '继续聊',
       }).then(ok => { if (ok) { void saveInterviewArchive(...); onClose() } })
       return
     }
     onClose()
   }
   ```
   🔴 **禁用原生 `window.confirm`**（项目红线），统一用 `@/components/dialogs/dialogs` 的 `confirmDialog`。
   🔴 说明文案要讲清「会保留存档」，不要吓人。
4. **onApply 成功后**：`clearInterviewArchive(scope)`，然后交给调用方的 `onApply`。

## 5. 红线（项目专属，必须遵守）

1. **切页签＝卸载组件**：任何长任务状态不能只放 useState；本方案靠 settingsKV 存档解决，不需要模块级 store。
2. **异步落盘**：`await` 之后才 `onChange`（本处不涉及表单回调），同源串行，卸载后不再 setState（`alive` 守卫）。
3. **禁原生弹窗**：一律 `confirmDialog` / `showToast`。
4. **lib 层禁 import components**：`interviewStore.ts` 只能 import `@/lib/db` 与类型。
5. **文案全中文**，不出现 `cf_`、`scope` 之类的内部词。
6. **不伪造验收**：没跑过的场景写「未验」，不要写「已通过」。

## 6. 测试要求

新增 `tests/interviewPersist.test.ts`（纯函数单测，不碰 DOM）：

| 用例 | 断言 |
|---|---|
| 键生成 | `interviewKeyOf('')` → `''`；`interviewKeyOf('outline::abc')` → `interview::outline::abc` |
| 序列化往返 | `save → load` 后 `turns/filled/done` 逐字一致 |
| 过期清理 | `updatedAt` 设为 8 天前 → `load` 返回 `null` 且已清库 |
| applied 标记 | `applied: true` → `load` 返回 `null`（不恢复已填回的会话） |
| 空会话 | `turns: []` → `load` 返回 `null`（不提示空白存档） |
| 串行 | 连续两次 `save`（不同 state）→ 最终库里是**第二次**的内容（不倒退） |
