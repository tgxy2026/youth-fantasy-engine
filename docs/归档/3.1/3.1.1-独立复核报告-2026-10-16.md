## 一、需要修复的问题

### V1 / P2：大小写不同的同名请求头被拼接，鉴权覆盖失败

- 位置：`src/lib/aiCore/headers.ts:85`。
- `mergeHeaders` 使用 `{ ...base, ...allowed }`，对象键区分大小写。默认 `Authorization: Bearer original` 加自定义 `authorization: Bearer replacement` 后，实际 Headers 值变成 **`Bearer original, Bearer replacement`**，而非预期的 `Bearer replacement`。
- 已在真实浏览器中使用模拟 fetch 复现：`chat()`、`listOpenAIModels()` 及 `buildEmbedRequest()` 三处都出现拼接；普通 `x-opencode-session` 可以正常传递。探针未向外网发送请求。
- 影响：界面承诺的“覆盖默认鉴权”对常见小写写法失效；不同大小写的重复自定义头同样可能被拼接，导致服务拒绝请求。
- 建议：按大小写无关的头名去重/覆盖；保留无自定义头时的既有行为。补跨大小写、重复头及三个请求出口的回归。
- 证据：`.workbuddy/tmp/review-3.1.1-header-probe.cjs`、`review-3.1.1-header-probe.log`。

### V2 / P2：编辑已有配置时切换 OpenCode Go 预设，没有初始化必需会话头

- 位置：`src/components/settings/AIConfigPanel.tsx:704`。
- “添加联网模型 → OpenCode Go”调用 `providerFromPreset`，会生成 `x-opencode-session`；但编辑区的平台下拉框只更新地址、local 和名称，没有相应初始化。
- 复现：添加一个普通 DeepSeek 配置草稿，再在平台下拉框选择 OpenCode Go。地址已改为 Go，界面也声称“已默认生成”会话 ID，但请求头行数实际为 **0**。
- 影响：通过该入口迁移配置的用户仍需手工补头，否则重现该功能原本要解决的缺会话头错误。
- 建议：两个预设入口共享必要默认配置逻辑；对已存在的有效会话 ID 应保留，同时让自定义头编辑器反映实际配置。
- 证据：`.workbuddy/tmp/review-3.1.1-preset-switch.cjs`、`review-3.1.1-preset-switch.log`。该探针复用了原 10 项 UI 检查，改走下拉框入口后 7 通过/3 失败；三条失败来自同一初始化遗漏，不能当成三个独立缺陷。

### V3 / P2：请求头语法和值未校验，允许保存浏览器无法发送的配置

- 位置：`src/lib/aiCore/headers.ts:49`、`:63`；调用方 `src/components/settings/CustomHeadersEditor.tsx:40`。
- 当前只检查禁止头清单，没有检查头名 token 语法及值中的非法字符。真实探针输入 `bad name: x` 与 `x-review: line1\nline2` 后，二者进入 `allowed`，`rejected` 为空；浏览器 `new Headers(...)` 随即抛 `Invalid name`。单独含内嵌换行的值也应拒绝。
- 影响：编辑区不提示具体错误，配置可以进入请求出口后才失败；长串非法配置可能被误诊为网络或服务商问题。
- 建议：校验头名及值，逐行显示具体原因；明确空名编辑草稿的处理，合法配置再落库。增加非法名称、换行、字符范围测试。
- 证据同 V1 探针与日志。此项与 V1 的大小写合并是两个不同问题。

### V4 / P2：图表“无彩色”通过，但未达到严格纯黑白，透明度仍产生灰色

- 位置：`src/components/world/RelationGraph.tsx:335`、`:344`；同类路径还有 `FactionGraph.tsx:302`、`:310`、`GeoMapEditor.tsx` 的淡化和文字、`WritingGoals.tsx` 的目标线与网格。
- 在真实示例项目切到 mono，关系线 `stroke = rgb(0, 0, 0)`，但 `strokeOpacity = 0.5`；关系标签的父组 `opacity = 0.6`。白底合成后是灰色，属于明确的透明度混色，不是字体抗锯齿。
- 原 `verify-mono-charts.cjs` 明文把黑色的不同透明度视为允许，仅比较 RGB 通道是否相等；因此原 **28/28** 与“严格二值颜色”并不等价。新增不透明度断言后 **28 通过/1 失败**。
- 建议：mono 分支消除有效绘制路径上的非 1 透明度（含祖先组），悬停与淡化通过线型、粗细、符号等区分；补不透明度/合成颜色检查，不能只检查有没有彩色。
- 证据：`.workbuddy/tmp/review-3.1.1-strict-mono.cjs`、`review-3.1.1-strict-mono.log`。
