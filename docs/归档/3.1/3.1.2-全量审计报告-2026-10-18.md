## 二、修复的真实缺陷（2 处）

### ① headers.syntax 失败契约 —— 非 ByteString 头值没有拦

- **判据**：`sanitizeCustomHeaders` 必须拒绝「非法头名 / 嵌 LF / 嵌 NUL / 非 ByteString 值」四类，`rejected` 非空、`allowed` 为空、且剩余项能被 `new Headers()` 接受。
- **病灶**：`rejectValueReasonOf()` 只查了 CR/LF/NUL。中文值（码位 > 0xFF）一路放行 —— 而 `new Headers()` 会直接抛 TypeError，作者要等到真发请求时才看到一句看不懂的报错。
- **修法**（`src/lib/aiCore/headers.ts`）：逐字符扫码位，>0xFF 即拒绝并给出可执行的原因（「头值只能是单字节字符（中文等需先做 URL 编码或改用英文值）」）。逐字符而非正则范围，避免把 emoji 代理对误判成两个合法字符。
- **验证**：4 类边界 + emoji + 合法值放行，**6/6 全绿**（`.workbuddy/tmp/check-headers.mjs`）；契约转 passed。

### ② draft.switch 候选 —— 注释与实现相反，旧草稿会静默蒸发

- **判据**：「同一操作替换选择与草稿，未见显式冲刷旧草稿；核对未保存及保存失败路径」。
- **病灶**（`src/components/outline/OutlineSheet.tsx`）：切换 effect 的注释写「draftRef 同步 effect 声明在下方」，**实际写在上方**。React 按声明顺序执行 effect ⇒ 新建 / 复制 / AI 新增这类「`setActiveId` + `setDraft` 同批次」的操作会先把 ref 刷成新卡，切换 effect 再去读就拿到新草稿 —— 旧卡未保存的编辑**既不落库、也被顶掉**。此外 `await saveCardRecord()` 失败时无 catch，会出现「界面多一条库里没有的卡」或「异常无人接管」。
- **修法**（7 处，同一文件）：
  1. `draftRef` 同步 effect 移到切换 effect **之后**（注释同步改正，并写清为什么）；
  2. 新建 / 复制 / AI 新增：`saveCardRecord` 包 try/catch，**写库失败就不切换选择**（也不关 AI 弹窗），并 toast 出声；
  3. 上移/下移落库失败出声（界面顺序已动，不能无声留下库内不一致）；
  4. 切走时的兜底保存失败也 toast（原来是 `void` 静默）；
  5. 新增 `switchTo(id)`：左栏点击改为**先冲刷旧草稿、成功才换选择**，失败留在原地并提示 —— 对应运行契约 draft.failure 的「不换选择、不丢原编辑」。
- **验证**：真机 CDP 采集 preserve-storage / preserve-selection 两条（编辑 → 切走 → 切回，值仍在、选择确实换过）。

### ③ coverage.chart 候选 —— 误报，已销账

`NovelEditor.tsx` 被判「mono 感知组件未登记进图表清单」。它只是**用 mono 决定段首缩进参考线的颜色**，自身没有任何显式绘图（AST 清单里 `explicitDrawing=false`）。图表清单是 mono 二值校验的采样对象，把编辑器登记进去反而会要求它提供绘制样本 ⇒ 不补登记，按 dismissed 销账。

## 四、遗留（如实记录，不伪造绿灯）

**draft.failure 的 save-failure 场景无法在本环境取证**：桌面/便携版的 `ops` 是「内存写 + 防抖落盘」，`put()` 在内存层即 resolve，落盘失败由独立通道（写入锁横幅）上报，**切换路径上构造不出失败**（实测：临时替换 `IDBObjectStore.prototype.put` 抛错，调用次数为 0，因为 Electron 里根本不走 IDB）。

- 保护逻辑已按契约实现（`switchTo` 先冲刷、失败留在原地并出声），但**未端到端跑通过**；

- 在此之前该契约只能标 `blocked`，不能报绿。
