## 1bis. 宽表格「左键按住拖动平移 + 表头冻结」（同日追加需求）

**主人口径（2026-10-17）**：世界构建 / 创作管理两组里比较大的表格，
① 看右侧信息不用再「滚到表格底部 → 拖横向滚动条 → 再滚回来」，改成**左键按住表格左右一拖**即横向平移；
② 表格一长往下翻，**表头（列名 + 筛选框）不许消失** —— 冻结表头，只滚动内容区。
**按键经主人 review 拍板收窄**：原口径「左键或右键都能拖」⇒「保留一个常用的就好」⇒ **只认左键**
（右键就是系统菜单，本表格本来也没有自有右键菜单）。

**实现**（改的是**全组共用**的 `TableSheet.tsx` ⇒ 两个目标组 13 张表一次全覆盖，其它组的表格也一并受益）：

| 件 | 文件 | 说明 |
|---|---|---|
| 抓手 | `src/lib/app/usePanScroll.ts`（新） | 通用 hook：`ref` + 4 个处理器 + `dragging`；只认左键；阈值 4px |
| 接线 | `src/components/sheets/TableSheet.tsx` | 滚动容器挂 `ref`/`data-table-scroll` + 拖拽光标（`cursor-grab` / 拖拽中 `cursor-grabbing select-none`）；表头 `<tr>` 加 `sticky top-0 z-10`、每个 `<th>` 补不透明背景；容器 `overflow-x-auto overflow-y-auto` + `maxHeight: foldVh('62vh')` |
| 闸 | `tests/tableSheetPan.test.ts`（新，20 条，A 批） | 目标组页签覆盖、只左键 + 反向守卫（无右键口子）、阈值、排除区、click 抑制、sticky 与不透明表头、`maxHeight` 非 `height`、hook 调用顺序 |

**四个必须处理的冲突**：
1. **单击编辑 vs 拖拽** —— 位移超 4px 才算拖拽；没超就是普通点击（该进单元格照常进）。拖拽一旦成立，随后那次 `click` 在**捕获阶段**被吃掉，否则会「拖完表格顺手点开某个单元格」。
2. **列宽手柄 / 表头筛选框** —— `th` 右侧的 `cursor-col-resize` 拖柄标了 `data-nodrag`，表头的 select / input 是表单元素 ⇒ 这两类区域的 mousedown **不启动平移**（否则拖表格会顺手改列宽、打断筛选聚焦）。
3. **表头透出** —— `sticky` 的 `tr` 若只有半透明/无背景，滚动时下面几行会从表头透出来 ⇒ 每个 `th` 都补 `bg-ink-800`。
4. **短表不留大片空白** —— 用 `maxHeight` 而非 `height`：行数少时表格自适应，行数多（超过 62vh）才出现内部滚动条。

**实机证据**（dev + 真 Electron + CDP `Input.dispatchMouseEvent`，`世界构建 / 国家势力`：16 列 × 8 行，横向溢出 2360>1567、纵向溢出 942>636）：

| 验证 | 结果 |
|---|---|
| 左键按住拖 240px | `scrollLeft 0 → 239.9` ✅ 真的平移（不是「看起来像」） |
| 表头冻结 | 内容区滚到 306px 后，表头与容器顶偏移 **0** ✅ 钉住；表头背景不透明（rgb(238,244,233)） |
| 单击单元格 | 仍能正常打开行内编辑器 ✅ 阈值没误伤点击 |
| 列宽手柄 | 人为拖宽一列制造横向溢出成功，且拖拽平移与手柄互不抢 ✅ |

## 3. 关键技术决策（都是真机/真读源码换来的）

### 3.1 图标必须解包到真实路径（不能留在 asar）

`electron-builder.yml` 的 `files` 只含 `electron/**` + `dist/**`，`electron/icons/*.ico` 会进 asar；
而 `.lnk` 的 `IconLocation` 是 **Windows 资源管理器自己读**的 —— **读不了 asar 内路径**。
⇒ 首次/每次切换把 `.ico` 写到 `<userData>/app-icons/`，快捷方式指向该真实文件。**打包配置零改动。**

### 3.2 🔴 每次切换写**新文件名**（否则「点了没反应」）

复用同一路径改写图标时，资源管理器**常常不刷新**。故文件名带时间戳（`fantasy-20261017001129.ico`），
换路径即触发壳层重载；同时清理同预设旧文件（只留最新一个）。

### 3.3 🔴 升级后必须自愈

应用内更新是「下载 Setup → 拉起安装器」，NSIS（`createDesktopShortcut: always`）会**重建快捷方式**、
图标打回默认。⇒ 主进程启动时读 `<userData>/app-icon.json`，比对 `.lnk` 当前图标是否仍指向该预设的解包文件，
不一致就重写一次。**判据严格**（只在「确实不再指向」时才动手），避免每次启动都写新文件。

### 3.4 🔴 还原默认的基准＝**快捷方式自己指向的主程序**（真机自检抓到的坑）

最初用 `process.execPath` 当默认图标。真机一跑（`--app-icon-selftest`）立刻暴露：
**开发模式下那是 `node_modules/electron/dist/electron.exe`** —— 点「恢复默认」会把桌面快捷方式指到开发者的壳上。
改为读 `.lnk` 的 `target`（安装版真实路径 `D:\Program Files\YouthFantasyEngine\YouthFantasyEngine.exe`），
dev / 安装版 / 换目录三种情况天然都对。**结论：这类「路径真源」必须取自壳层本身，不能取自运行时自我认知。**

### 3.5 三套图标的「一致大小」＝按内容外接框归一化

实测源图内容占比：**默认 80%**（主人「偏小」的感受成立）/ 幻想 96% / 典雅 95%。
直接各缩到 256 会得到三个视觉重量不一的图标 ⇒ 生成器统一按**内容外接框（alpha>64）缩放到画布 88%** 后居中。
选 88%（而非 94%）的理由：默认那套是**实心圆角方块**（bbox 密度 0.98），另两套是自由形状（0.74 / 0.62）——
方块顶到 94% 会在桌面上显得比另两个重，88% 是三套观感最接近的一档。

### 3.6 不碰主 exe 的图标（明确不做）

`YouthFantasyEngine.exe` 的图标是 **PE 资源**：改它要 rcedit 重写二进制，会偏离主 exe 体积基线
（**246,487,040**）并可能影响覆盖更新。⇒ 本功能只动 `.lnk`，界面上如实写明「程序自身图标不变」。
闸里有**反向守卫**：内核出现 `rcedit` 即失败。

---

## 4. 边界与不做

- ❌ **不做**用户自定义上传（主人口径）；❌ **不做** exe 自身图标；❌ **不做**主题/皮肤打包（那是另一件事）。
- 非 Windows（便携版 / 渲染层跑在浏览器）**隐藏入口**（`appIconSupported()` 双判：有桥 + 平台为 Windows）。
- 设目标用户桌面没有快捷方式（便携版用户自建 / 手动删过）：应用时如实返回失败，不假装成功。

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| 覆盖安装后图标被重置 | 启动自愈（3.3） |
| 资源管理器不刷新 | 每次切换写新文件名（3.2） |
