## 二、P1（2 条，全部修复）

### ① 正文自动保存会把刚改的标题写回旧值（反向：标题落库会把正文写回旧稿）

`src/components/editor/useNovelEditorModel.ts`（`commitContent` / `updateMeta`）＋ `src/lib/db/chapters.ts`（`saveChapter`）

- **病灶**：`commitContent` 用**渲染闭包里的 `active`**（上一次落库的整章快照）组装 `next`，而 `saveChapter` 是**整对象 put**（不做字段合并）；`updateMeta` 同样用闭包 `active` 整章延后 600ms 写。
- **两条复现链**（静默、无报错）：
  - 打字（t=0 排 2s 自动保存）→ t=0.8 改标题（meta 0.6s 后落库）→ t=2.0 自动保存用旧快照 ⇒ **标题跳回旧值**，输入框当场回退；
  - 打字 → 改标题 → 两者交错时 meta 作业写回**旧正文**，且界面仍显示新稿 ⇒ **库与界面分叉，重启即丢**。
- **修复**：
  1. 新增 `db.patchChapter(id, patch)`：**只覆盖 patch 里出现的字段**（读-改-写在同一函数内，落库后共用 `afterChapterWrite` 做码字增量/快照）；
  2. `commitContent` / `updateContent` / 切章冲刷：基准**现读 `chaptersRef`**，落库前在队列内再读一次；
  3. `updateMeta` 只走 `patchChapter(patch)`，物理上不碰正文；
  4. 状态回写也改成**字段级合并**（不再整章替换，避免把旧标题写回界面）。

### ② 关窗时最后 ≤2 秒的正文从未落库（写盘返回成功、毫无提示）

`src/App.tsx`（beforeunload/pagehide）＋ 新增 `src/lib/editor/draftFlush.ts`

- **病灶**：正文保存是 **2 秒防抖**；关窗不触发 React 卸载（编辑器只在卸载时冲刷）；`App` 的 `beforeunload` 只 `flushDesktopSync()` —— 草稿此时**还没进 store**，写的是旧快照。
- **修复**：
  1. 新增模块级登记器 `registerEditorDraftFlush / flushEditorDraftNow`（与 sync 层 `onSyncConflict` 同模式）：编辑器挂载时注册「立刻落草稿」；
  2. `beforeunload`：`flushDesktopSync()` → `flushEditorDraftNow()` → 再 `flushDesktopSync()`（微任务在任务结束前跑完，桌面内存 store 来得及）；
  3. 便携版 `pagehide`：先落草稿再发 beacon；
  4. 编辑器自己再挂 `pagehide` / `visibilitychange(hidden)`，切走应用/最小化也主动落一次。

## 七、🔴 本轮教训

1. **整对象 put + 闭包旧快照 = 静默互相覆盖**：`saveChapter` 这类「整章写」接口，只要调用方手里是渲染闭包里的快照，就必然存在字段回滚。⇒ **凡「只改一部分」的写入一律字段级 patch**，并在队列内现读一次。
2. **「保存成功」不等于「数据在盘上」**：`flushDesktopSync` 返回成功，但草稿还在防抖窗口里 —— 关窗路径必须先把上游（编辑器草稿）落进 store，再写盘。
3. **effect 依赖数组里的「数据数组」是隐形触发器**：`chapters` 每次保存都换引用 ⇒ 依赖它的 effect 会被动重跑。⇒ 一次性消费类 effect 必须用 ref 记账，不能靠数据数组驱动。
4. **环境坑（本轮实际踩到）**：**Python 文本模式写文件在 Windows 会把 LF 转 CRLF**（`io.open(...,'w')` 默认 universal newlines），而本仓工作区是 LF —— 一次脚本编辑就能把整文件「全行改动」，还让按 `\n` 匹配的闸集体误报。⇒ 脚本改源码一律 `newline=''`（或 node 侧 `replace(/\r\n/g,'\n')` 兜底）。
