## 1. 版本目标与完成条件

在“种族生物”和“物品资源”页签中，提供表格／图鉴两种视图。用户可在同一份条目资料上配置自定义字段，并在表格、图鉴、搜索、AI、导入导出及三端保存中完整使用。

本版完成必须能够演示：

1. 旧项目不重新填写即可切换图鉴；无图条目仍可浏览，点击后查看、编辑完整资料。
2. 给魔兽新增“食性”，给丹药新增“副作用”；字段按类别显示，切换视图和重启后内容一致。
3. 把自定义字段改名、归档、恢复；原数据保留，名称与上级关系等原有能力正常。
4. AI 能参考、按要求补全自定义字段；仅整理已有资料时，不凭空补造缺失设定；返回内容须校验、预览、确认后应用。
5. 项目导出到另一端，字段定义、选项、条目值与图片完整；CSV 能往返文字资料，图鉴资料包能携带配置与图片。
6. 黑白主题、窄窗口、键盘操作、保存失败与项目切换均有明确且经过验证的行为。

## 3. 产品交互规格

### 3.1 页签布局

顶部设置“表格／图鉴”切换。保留新增、字段设置、搜索、筛选与更多入口；批量操作沿用现有操作位置。

- 默认首次进入仍为表格，避免升级后突然改变旧用户操作习惯。
- 图鉴主体为卡片网格；宽窗口点击卡片打开右侧详情，列表与详情各自滚动。
- 内容可用宽度不足 960px 时详情占满主体区域，显示返回；侧栏默认 420px、允许在 360～600px 内调整，最终不得挤出主体。
- 卡片密度提供紧凑／标准／宽松。卡片统一图片区域，图片等比完整显示；不强制裁切。
- 从详情返回保留筛选、排序、滚动和选中条目；连续查看相邻条目使用当前可见结果的顺序。
- 资料提及或搜索结果跳转到行时，若当前为图鉴则定位卡片并打开详情，不强行切回表格。

### 3.2 卡片及详情

| 对象 | 默认卡片内容 | 详情默认分组 |
|---|---|---|
| 种族生物 | 主图／占位、名称、类别、威胁等级、分布区域、能力特性短摘要 | 基本资料、能力与弱点、生态与社会、契约关系、剧情关联、补充资料 |
| 物品资源 | 主图／占位、名称、类别、品级、能力效果短摘要、已填的持有者 | 基本资料、来源与效果、限制代价、持有与流转、剧情关联、补充资料 |

名称及类别保留；可配置附加摘要字段最多 3 项，每项最多显示两行，完整内容进入详情。长名称允许两行并提供完整名称提示。品级沿用作者文本，不新增固定稀有度体系。

默认收起未填字段；提供“显示未填写字段”以便补全。无图／无摘要／全部自定义字段为空时，卡片仍显示名称和可用标签；字段数为零时不出现空分组。

详情默认浏览，点击编辑进入表单；支持保存、取消和当前保存状态。编辑内容沿用共享草稿机制，不能额外产生一份与表格脱节的资料。

### 3.3 层级与类别

- “上级”是现有条目树，“类别”是筛选维度，分开显示。
- 分类导航提供全部、仅当前节点、包含下级；父条目本身可有完整图鉴，不能一律当文件夹隐藏。
- 上级关系继续沿用既有防环、名称引用、子条目编号及删除引用检查，不改为新的图鉴专属关系系统。
- 类别新增、改名、停用复用现有自定义选项。改名同时检查字段适用范围、已填类别值和当前筛选；同名合并须预览确认。
- 条目更改类别后，不适用的字段值保留；详情提供“其他类别已有内容”折叠区供查看和清理，避免隐藏后误以为丢失。

### 3.4 偏好与配置归属

项目级：字段定义、选项、分组、默认顺序、适用类别、卡片摘要字段、表格列及详情默认显示、AI 开关。

本机持久偏好：视图、卡片密度、侧栏宽度；使用 yfe-ui: 工具，键至少包含 projectId 与 tabId；网页版再按账号／游客命名空间隔离，退出登录不能留下其他账号条目内容。

临时状态：搜索词、当前筛选、选中条目、滚动、编辑输入。视图内共享，退出页面后不承诺恢复搜索；搜索条件变化导致选中条目不在结果时，提示并关闭详情，不跳到另一个条目。

## 4. 字段模型与统一解析层

### 4.1 系统字段与用户字段边界

- 编号、名称、上级、保密等级、类别及当前持有者等带内置语义的字段，保留存储键、类型、引用与验证规则。
- 可修改显示名、调整允许的展示位置；编号／名称等必要识别内容不能从所有操作界面中彻底隐藏。
- 普通预设字段可以显示改名、隐藏、排序，但本版不改变其底层类型或实际含义。
- 自定义字段可以新增、改名、排序、分组、配置适用类别与 AI 选项；归档／恢复为常用删除方式。
- 隐藏不等于保密，也不等于不参与 AI；界面为这些选项分别解释。自定义字段不得越过条目原有保密与可见范围。

### 4.2 存储建议

新增 `src/lib/atlas/` 领域模块，以下类型为拟实施契约：

```ts
type AtlasTabId = 'races' | 'items'
type CustomFieldType = 'text' | 'longText' | 'number' | 'select' | 'multiSelect' | 'boolean'

interface AtlasFieldDefinition {
  id: string                 // cf_<uid>；创建后不变，同时作为 row.data 键
  label: string              // 可改显示名；不得与同表其他有效显示名冲突
  type: CustomFieldType
  description: string        // 解释含义；供人和 AI 共同参考
  unit?: string
  options?: string[]
  appliesTo: '*' | string[]   // 类别当前值；改名由服务层同步维护
  groupId: string
  order: number
  tableVisible: boolean
  detailVisible: boolean
  searchable: boolean
  aiReadable: boolean
  aiWritable: boolean
  archived: boolean
}

interface AtlasSchemaConfig {
  formatVersion: 1
  revision: number
  fields: AtlasFieldDefinition[]
  groups: { id: string; label: string; order: number }[]
  builtinPresentation: Record<string, {
    groupId?: string; order?: number; tableVisible?: boolean; detailVisible?: boolean
  }>
  summaryKeys: string[]
}
```

配置存于项目级 `atlasSchema::races`／`atlasSchema::items` 设置；通过按显式 projectId 操作的接口读写，不能让异步任务依赖届时的 currentProjectId。创建配置时不回写所有旧条目。

另以项目设置 `atlasCapabilities` 记录 `formatVersion: 1`、`minWriterVersion: '3.1.3'` 与实际启用能力。该标记供本版及后续版本检查，不宣称旧客户端会执行它。配置与能力标记须进入项目 settings 导出、备份与同步，不进入敏感元数据排除清单。资料包和世界包分别在其格式元数据中声明同样的能力需求。

自定义值存于 `TableRow.data[field.id]`，沿用字符串字典：文本原文、数字规范字符串、布尔 `'true'／'false'`、多选为 JSON 字符串数组。未填写统一为空字符串或缺键，不把 0／false 当空值。格式化、验证、比较和排序必须经过同一套转换函数。

所有行保存采取合并而非按当前可见列重建 data；保留隐藏、归档、其他类别及未来版本未知的值。自定义 ID 不能随显示名改变，不能使用用户可编辑名称作存储键。

现有字段别名仍由 fieldAlias 负责；自定义字段 label 为唯一名称来源，不能再给它套第二层别名。内置字段默认显示分组与用户配置合并后再输出，不直接改静态 TabDef。

### 4.3 字段统一服务

建议接口：

- `loadAtlasSchema(projectId, tabId)`：校验版本、读取配置、返回空配置的合法默认；读取失败显示错误，禁止用默认配置覆盖原值。
- `resolveAtlasFields(tab, config, aliases, category, purpose)`：产出稳定 key、显示名、类型、来源、适用与权限信息；purpose 为 table／detail／search／aiRead／aiWrite／export。
- `parseFieldValue / validateFieldValue / formatFieldValue`：统一类型转换和格式化。
- `buildAtlasSearchText / serializeAtlasForAI`：输出可读文本，不泄漏 cf_ 内部键及图片载荷。
- `commitAtlasPatch({ projectId, tabId, rowId, baseRevision, baseUpdatedAt, patch })`：校验项目、字段版本、行基准及字段权限后合并保存；过期时要求刷新／重新确认。

非 races／items 调用继续返回原始 schema 行为，避免一次改变全部表格。不要修改全局静态 TABS 或原位追加 columns，以免跨项目字段泄漏。

### 4.4 默认限制与输入规则

以下是本版初始实施值，开发阶段用容量和可用性验证；如需修改，必须同步实现、界面提示和测试：

| 项目 | 初始值／规则 |
|---|---|
| 自定义字段 | 每页签最多 60 个未归档字段；归档项仍计入配置大小限制 |
| 字段名称 | 1～20 字；去首尾空白；检查内置别名、自定义名及归档同名恢复冲突 |
| 字段说明／单个长文本值 | 分别最多 500／10000 字 |
| 短文本／数字 | 短文本最多 200 字；数字须有限值，保留规范小数，不使用浮点结果回写用户原值 |
| 下拉选项 | 最多 50 项，每项 40 字；去空、去重；多选保持用户选择顺序 |
| 新字段默认 | 可搜索、可供 AI 参考；AI 填写默认关闭，作者可以显式开启 |
| 公式及脚本 | 所有字段按文本数据处理，不执行表达式、HTML 或脚本 |

## 5. 配置变更、草稿及失败恢复

### 5.1 编辑顺序与状态

切换表格／图鉴不卸载共享草稿。选择另一条资料、切换项目、执行类别批量迁移或修改字段配置时，有未保存内容则提供保存后继续／放弃／取消；保存失败停留原处并保留输入。

行和字段配置的异步读取／保存均捕获 projectId、tabId 和请求序号；旧项目响应不能更新新项目界面，不能因为切换时全局项目 ID 改变而写错项目。

### 5.2 操作规则

| 操作 | 实施行为 |
|---|---|
| 改名、分组、排序、显示开关 | 仅修改定义；保留值；刷新字段缓存、搜索索引及 AI 字段清单 |
| 归档 | 保留定义和值；默认不进普通展示、搜索和新 AI 请求；归档管理中可查看恢复 |
| 恢复 | 校验名称冲突后恢复；不自动改写原值 |
| 文本／长文本互换 | 允许预览转换；长转短超限不截断，列出待处理条目 |
| 其他类型转换 | 本版不做原位转换；创建目标字段，预览复制并逐项处理不合法值，原字段保留可归档 |
| 删选项 | 展示引用数量；选择替换或保留历史值，历史值显示标记且不再作为新选项 |
| 永久删除 | 二次确认影响数；生成可恢复备份，再清理值和定义；失败不宣称成功 |

类别批量改名、字段永久删除、跨项目合并等跨记录变更，需要可恢复的迁移过程：

1. 捕获配置 revision 及受影响行基准，预览冲突和修改数。
2. 创建备份并验证可读；备份失败不执行破坏操作。
3. 用项目级串行队列执行，记录带操作 ID 的 before／after 及进度；遵守现有存储后端的批量和持久化确认能力。
4. 中断后检测未完成操作，提示继续或回滚；禁止把分步写入描述为跨端数据库事务。
5. 成功后更新 revision，失效缓存和 AI 待应用结果；旧结果必须重新校验。

恢复日志建议存为项目设置 `atlasMigration::<operationId>`，保存操作类型、状态、备份引用、目标字段／类别、受影响 rowId、进度和基准摘要；大块 before 内容从已验证备份恢复，不把整份图片库重复嵌入日志。未完成操作存在时，相关结构修改暂时锁定，阅读与导出仍可用。配置写入失败不得先更新成功缓存；需要保留原配置和用户尚未保存的修改。

多设备并发同步现有同代覆盖限制仍然存在。本版做项目内操作串行、基准冲突提示与恢复备份，不宣称解决跨设备协议级并发；字段配置同步冲突必须保留双方副本，禁止静默按名称合并。

## 6. 图片方案、容量和三端约束

### 6.1 第一版存储决策

为控制改动面，第一版使用 TableRow 顶层可选 `atlasImage` 对象，保存压缩后的图片 dataURL、MIME、宽高与实际字节数；不塞进 row.data，不新建媒体 store，不修改现有 sidecar 白名单。

```ts
interface AtlasImage {
  dataUrl: string
  mime: 'image/webp' | 'image/png' | 'image/jpeg'
  width: number
  height: number
  bytes: number
}
// TableRow 增加 atlasImage?: AtlasImage
```

所有重建 TableRow 的导入、AI、保存、同步和世界包路径均须核查并保留 atlasImage。只读图鉴不得回写空图片或创建无意义元数据。

### 6.2 初始规格

- 本地上传 PNG／JPEG／WebP，原文件上限 8MiB；检验实际解码与格式，不仅依赖扩展名。
- 等比缩至最长边不超过 1024px，不放大小图，不裁切；保留透明背景。
- 压缩目标为每张编码后 dataURL 不超过 200KiB，逐档降质量／尺寸；达不到则拒绝保存并提示换图，不能返回超限结果继续写库。
- 项目图鉴图片编码后总量初始硬上限 32MiB，达到 80% 提示；计算两个页签全部条目及替换时的净增量。云端剩余配额不足时，使用更小的可用额度。
- 界面图片按需解码和加载；查看大图复用已保存图片，不额外保存原图或另一份缩略图。
- 图片替换成功后再移除原值；失败保留原图。移除图片纳入正常草稿／保存流程。

这是以容量上限换取小范围存储改造的明确取舍：图片仍会增加整库读写、备份和同步体积，懒加载只能改善显示与解码，不能消除整库载荷。上传前显示压缩后体积及项目用量，容量超限时条目文字编辑仍正常。

**图片存储是开发阶段首个技术验证点。** 在 UI 全量开发前，用接近图片总量上限的数据测量三端保存、重载、备份和同步；若无法达到第 11 节门槛，先提交外置媒体方案及工期调整，再继续图片交付，不能以扩大限制或跳过真实保存测量代替解决。外置媒体会涉及 Electron、HTTP 服务、IDB、备份及权限白名单，不能临时只给网页端加文件路径。

### 6.3 安全与离线

不接受任意本地文件路径或远程链接作为持久主图，不上传原图到第三方，不把图片 dataURL 发给文字 AI。桌面版与便携版离线可用；游客图片留在本地 IDB；云端沿用用户目录和登录鉴权，不产生跨账号可访问的图片地址。

文本按照 React 安全文本渲染；图片拒绝 SVG／HTML 及无法解码内容。新功能日志不得记录字段全文、图片载荷或账号凭据。

## 7. AI 接入实施规格

### 7.1 建立入口覆盖清单

开发先搜索所有读取 races／items、遍历 row.data、遍历 tab.columns 的调用点，至少覆盖：

1. 表格 AI 填写／单条补全。
2. AI 整理、去重与文本批量导入。
3. 设定上下文拼接及相关 AI 问答、创作辅助入口。
4. 全文／设定检索及用于 AI 的检索文本。
5. 世界资料引入后再次进入 AI 的路径。

清单逐项注明读取／填写／仅内置语义，不以修改一个组件作为“AI 已兼容”。

### 7.2 读取与上下文预算

- AI 读取字段包含稳定 key、显示名、类型、说明、单位、允许选项和值；内置字段保留原 key，展示名可附带解释。
- 过滤保密、不可见、归档、不适用或 aiReadable=false 的字段；有历史值的其他类别字段默认不自动注入。
- aiWritable=false 但 aiReadable=true 时可作参考；反过来允许仅作为输出目标提供字段规则，不把旧值作为参考发送。
- AI 字段及资料文本属于数据，不作为系统指令拼接；自定义说明不能覆盖工具权限和输出约束。
- 沿用已有上下文预算，先选相关条目与字段，再截取长值；记录省略数量并在预览可见，不把全库图鉴无条件塞入每次请求。
- 在现有 token 估算之后应用预算，不另造“所有字段都能读到”的无限上下文承诺。

### 7.3 回填与模式

每次任务捕获 projectId、tabId、rowId、配置 revision、目标行基准和允许写入 key 列表。模型只返回获准字段的值；本地校验类型、长度、选项、保密范围、适用类别，未知 key 和不合法值列入错误，不能静默写入。

提供两种明确模式：

- **整理已有资料**：提示词要求仅使用提供资料，缺依据留空；预览标记模型声明的依据，无法自动证明依据充分时不宣称已验证。人工确认仍为最终关口。
- **创作补全设定**：用户主动选择后允许生成新设定；结果显著标识为创作候选。

所有结果先预览差异并选择应用；新建条目也先预览。编号等系统维护字段不向模型开放。应用前再次比对配置与内容基准；字段已归档、类别已变、项目已切换或条目已修改时停止旧结果直接覆盖，提供重新生成或逐项复核。

自定义字段不自动获得人物关联、克制图、战斗计算等软件语义；名称相似也不自动映射为内置字段。

## 8. 搜索、导入导出、世界包与恢复

### 8.1 搜索与资料提及

搜索用统一格式化文本，返回可读字段名、命中摘要和稳定条目 ID；数字 0、布尔否、多选均可检索，主图载荷和内部键不进入索引。字段名称／值／可搜索开关／归档状态改变后重建受影响记录索引，避免已删除内容继续命中。

资料提及继续围绕名称与别称反查，不把每个自定义文本字段都当作实体别名。搜索结果在图鉴中可定位，保密范围与原功能一致。

### 8.2 三种导出职责

| 格式 | 保存内容 | 边界 |
|---|---|---|
| 项目备份／项目导出 | 完整定义、归档字段、所有值、图片、必要迁移元数据 | 可恢复真实项目；不带本机布局、账号状态及凭据 |
| CSV／批量表格 | 当前选择的文字字段，默认有效字段；可选择归档字段 | 不保存图片与字段类型说明，明确提示不作为完整备份 |
| 图鉴资料包 JSON | formatVersion、tabId、字段定义、类别依赖、选定条目和图片 | 用于跨项目共享与完整图鉴往返，不含账号及无关项目设置 |

CSV 导出使用用户能理解的唯一列名；导入提供列映射，不能只凭同名自动覆盖定义。多选统一转义规则，往返保持顺序；单元格换行、逗号、引号必须正确解析。现有 CSV 解析对字段内换行支持有限，本版新增长文本后必须补齐并回归旧格式，不能直接截断长设定。

外来列可以映射到现有字段、创建自定义字段或忽略；创建操作须预览类型和选项，并一次确认。导入后的编号继续由现有规则生成。针对表格软件公式注入，导出需提供安全文本处理且能按明确标记正确回导，不以破坏原始字符串换取安全。

### 8.3 资料包与世界包合并

- 先校验 formatVersion、字段／图片上限、项目配额、类型和引用，后写库；不完整／超限包在修改目标项目之前拒绝。
- 同字段 ID 且定义兼容可复用；同 ID 不同义、同名不同类型必须提示。用户可选择映射、另建字段或跳过，并展示影响数。
- 字段另建时重映射条目 data 键、summaryKeys 等定义内引用；项目复制／完整恢复时则保留项目内部字段 ID，不把它当 rowId 重映射。
- 重映射条目 ID，同时处理图片随行、层级名称及原有世界包溯源；字段适用类别与目标类别对应关系须在预览明确。
- 世界包抽取按实际选中条目携带必要定义和图片；引入不能仅复制 row.data 而遗漏配置。世界包不开放改写对方项目级字段配置的隐式权限。
- 导出“当前可见结果”与“全部条目”需要明确选择；不把筛选结果误称完整备份。

### 8.4 旧项目、旧版本与未来数据

- 没有配置和图片的旧项目视为合法默认，首次阅读不触发大规模迁移。
- 本版遇到比自己更新的字段格式时，保留原始内容，阻止图鉴结构修改，给出升级说明；不能解析失败后保存空配置。
- **无法让已经发布的旧版本自动识别 3.1.3 格式标记。** 3.1.3 提供最低读写版本信息及首次启用提示，但不承诺旧版编辑安全。
- 首次启用自定义结构前生成可恢复备份；降级建议恢复启用前备份。需要给旧版使用时另导出兼容副本，说明扩展字段及图片不在兼容副本能力范围，原项目不变。
- 升级、导入和恢复失败后原项目保持可用；新项目导入失败须清理或隔离本次创建的临时项目，不能删除其他项目数据。

## 9. 三端兼容与主题无障碍

复用现有平台适配层和 StoreOps，不在图鉴组件里直接判断端别、访问 Node 文件系统或自行请求本机端口。

| 配置 | 必核验内容 |
|---|---|
| 桌面版 | Electron 保存确认、重启读回、离线图片、备份恢复、原角色立绘不受影响 |
| 便携版 | HTTP 后端保存失败与重试、数据目录读回、服务重启、路径不绑定上传源文件 |
| 网页云端 | 当前账号数据隔离、配额失败、登录失效、刷新后读回、旧页配置冲突 |
| 网页游客 | IDB 持久化、浏览器配额失败、游客到项目导出、账号切换不串缓存 |

云端 WEB 与 PORTABLE 可能同时为真，不能按三个互斥布尔值设计。新增内容进入现有三端专项审计和运行证据，不修改原审计工具入口。

主题及操作要求：

- 适配现有所有预制及自定义主题；纯黑白下界面文字、边框、状态均遵守二值规则，上传图片保留原色。
- 威胁等级／品级以文字和形状表达，不能仅靠颜色；焦点清晰可见。
- 卡片可键盘聚焦与打开；详情关闭后焦点回到原卡片；编辑弹层正确管理焦点及 Escape，未保存时遵循草稿规则。
- 在 200% 缩放及窄窗口下，不出现详情操作按钮被遮挡或页面整体横向溢出。

### 11.2 实机验收清单

四配置各运行下列主流程，保留存储读回和截图／日志证据：

1. 打开旧项目，切图鉴，添加条目，无图可用，上传主图，保存并重启／刷新读回。
2. 新增六类型字段，类别限定，改名／隐藏／归档／恢复，表格与图鉴一致。
3. 搜索、筛选、树形导航、详情编辑、取消、保存失败、跳转资料提及。
4. 导出项目与图鉴资料包，在其他配置导入；核对数量、稳定字段对应、内容及图片。
5. 运行 AI 参考与补全；先预览后应用；执行中修改字段或切换项目，旧结果不能覆盖。
6. 标准主题、自定义主题、纯黑白主题及窄窗口；键盘、长名称、空字段和大量字段。

网页版另核验两账号隔离、登录失效与配额失败；游客另核验本地配额及导出；桌面／便携另核验服务或应用重启及离线数据。

### 11.3 容量与性能目标

使用独立生成的测试项目，不接触用户真实资料。记录机器、后端、构建类型、网络条件、数据规模和至少三次结果，不能拿开发服务器热缓存成绩代替发布构建。

- 基础规模：每页签 1000 条、60 个有效自定义字段，包含长文本；图片测试达到项目上限附近。
- 表格和图鉴首屏显示目标 ≤2秒；已加载数据的搜索／筛选更新目标 ≤300毫秒；打开普通详情目标 ≤200毫秒。
- 图片接近预算时，普通文字保存至当前后端确认目标 ≤2秒；云端在往返延迟约100毫秒、上行20Mbps的受控条件下目标 ≤5秒。不能只测组件状态“已保存”。
- 备份、整库同步及首次冷启动单独记录耗时与字节量，对比无图基线；超过无图基线两倍且额外超过5秒时，分析并给出结论，不自动判绿。
- 若数据体积使上述目标无法满足，按第6节先调整存储方案或重新确认容量边界；不能用卡片分页掩盖整库写入成本。

### 11.4 工程门禁与证据

实施收尾执行类型检查、lint、按项目指南的全量批次测试与相应构建；保留真实命令、退出结果与失败归因，不照抄历史测试数量。发布构建检查与真实封装／部署区分，后者需用户指令。

沿用现有通用审计及三端专项入口：

```text
npm run typecheck
npm exec -- eslint src tests
powershell -NoProfile -ExecutionPolicy Bypass -File tests/run-batches.ps1 all
node scripts/audit/run.mjs --probes
node .workbuddy/tmp/audit-platform.mjs --matrix
```

命令成功不替代人工使用流程；静态模型匹配不等于四配置实机通过。证据分“通过／失败／未执行／受阻”，已暂缓的双设备同步验收不得写成已通过；新增字段同步往返必须单独取证，否则版本保留该验收未完成状态。

## 12. 风险、取舍与交付资料

| 风险 | 处理方式 |
|---|---|
| 静态 columns 与原始 data 遍历两种链路并存 | 先建统一解析层及调用点清单，逐项接入；结构检查防止新路径绕过 |
| 图片嵌入拖慢整库保存 | F0 提前测量；压缩和项目预算硬拦截；不达标先调整媒体方案 |
| 配置变动与 AI／草稿同时发生 | revision、行基准、显式项目作用域及确认前重验 |
| 字段改名、类别改名造成数据不可读 | 自定义字段稳定 ID；类别原字符串迁移有预览、备份和可恢复记录 |
| 旧版本或未知格式回写丢值 | 不承诺旧版安全；启用前备份、兼容副本、未知值保留和新客户端写入保护 |
| 世界包／CSV 只带值不带定义 | 明确格式职责；资料包完整导出；映射预览与往返检查 |
| 灵活配置导致界面膨胀 | 六种基础类型、类别范围、折叠空字段、摘要数量限制；复杂关系后置 |
| 与3.2.0共享文件发生覆盖 | 记录依赖及共享文件；先集成本版字段读取契约，再推进后续调用方 |

开发结束必须交付：

1. 实施记录：逐任务的实现位置、实际设计偏差与原因。
2. 字段及资料包格式说明：版本、编码、映射、限制和恢复方法。
3. 测试与审计报告：四配置覆盖矩阵、容量测量、源码指纹、未验项。
4. 用户更新说明：图鉴入口、自定义字段、AI 开关、容量及旧版兼容提示。
5. 交接摘要：已完成、未完成、受阻和后续候选分别列明，不以“全量通过”掩盖未做的真实验收。

**版本结论判据：好浏览、可自定义、AI 使用可控、资料搬运与保存完整。四项都满足，才视为3.1.3达到本次讨论的预计目标。**
