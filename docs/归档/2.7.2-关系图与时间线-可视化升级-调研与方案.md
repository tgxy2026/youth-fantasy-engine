# 关系图与时间线 · 可视化升级 —— 调研与方案

> 版本：2.7.2 规划稿（版本号待定）
> 日期：2026-10-02
> 目标：**在引用数据完全不变的前提下**，提升四个视图（人物关系 / 势力关系 / 历史事件轴 / 故事时间线）的视觉表现力与信息密度。
> 状态：⏳ 待主人拍板范围后实施。

---

## 一、背景与目标

主人哥哥反馈：四个可视化视图「能用，但简陋、单调，看起来不舒服」。核心诉求是**更好的视觉效果**，且**引用数据不变**——不新增表、不新增列、不改现有字段语义。

这意味着改造的着力点只有两处：
1. **现有字段的可视化利用率**（大量字段闲置着没被画出来）；
2. **视觉语言本身**（形状、色彩、层次、动效、交互）。

## 二、现状诊断

### 2.1 四个视图的实现底细

| 视图 | 文件 | 渲染方式 | 布局算法 | 交互 |
|---|---|---|---|---|
| 人物关系 | `RelationGraph.tsx`（287 行） | 纯 SVG | **手写力导向**（FR 变体，320 次迭代，O(n²) 斥力），上限 80 节点 | 平移/缩放/节点拖拽/悬停高亮/点击收起 |
| 势力关系 | `FactionGraph.tsx`（285 行） | 纯 SVG | **纯圆环**（均分圆周，**无力的**） | 平移/缩放/节点拖拽/悬停/点击开成员面板 |
| 历史事件轴 | `HistoryTimeline.tsx`（388 行） | DOM 绝对定位 + SVG 叠层 | 单行水平轴，`SLOT_W=240` **等距** | 状态筛选/悬停/点击弹窗 |
| 故事时间线 | `StoryTimeline.tsx`（519 行） | DOM 绝对定位 + SVG 叠层 | 多泳道，`SLOT_W=240` **等距** | 轨道显隐/状态筛选/悬停/点击弹窗/时间倒流告警 |

三处共用的基础设施：
- `useSvgPanZoom.ts`（两图共用的平移/缩放/拖拽 hook，2026-09-14 审计统一）；
- `storyDate.ts`（时间键换算、`assignOverlapColors` 区间着色、`spanLinePath` 时长线）；
- 主题令牌 `--graph-*`（`index.css`，暗/浅两套，已就位）。

### 2.2 五个「简陋感」的根因

**根因 A：节点没有类别编码——全部同色纯圆。**
人物图与势力图的节点都是一个「圆 + 内圆 + 下方文字」，颜色只区分「常态/悬停/选中」三态，**与内容语义无关**。而角色卡的「所属势力」、《国家势力》的「类别」这些天然的分组信息**完全没被用上**。

**根因 B：边只编码了「关系类型」这一维。**
弧线颜色按类型哈希取色，但**线型、粗细、方向**都没有编码信息；关系的「强度/现状」（关系现状列）、「演变轨迹（按卷）」全部闲置。悬停时也只能看到类型名，看不到关系详情。

**根因 C：势力图是纯圆环，没有结构感。**
`FactionGraph` 把节点均匀排在圆周上——节点一多就挤成一圈糖葫芦，既看不出「谁跟谁抱团」，也和人物图的力导向**不是一套视觉语言**（直线 vs 弧线、药丸标签 vs 裸文字、半径算法不同）。

**根因 D：时间轴是「等距」的——时间流逝感丢失。**
两张时间线都用 `SLOT_W=240` 固定间距排列事件组。这是可视化设计里明确点名的**「等间距谬误」**：相隔一万年与相隔一天的两个事件，在轴上占同样的宽度。读者无法从图上感受到「时间的长短」。

**根因 E：轴的视觉存在感几乎为零。**
时间轴本体是一条 `strokeWidth=1.5`、透明度 0.35 的灰线，没有**刻度、年代标尺、里程碑、现在标记**。卡片才是全部，轴只是背景。

### 2.3 直接后果

- 关系图看不出「阵营分布」，只能看出「谁连得多」；
- 势力图节点一多就糊，看不出「势力集团」；
- 时间线只能当「卡片列表」看，无法当「时间地图」用；
- 四个视图彼此**不成体系**——两图两轴各画各的，风格割裂。

## 三、联网调研：行业最佳实践

> 调研来源：AntV G6 官方示例、Visual Complexity《Design Principles for Beautiful and Readable Network Maps》、DataField《Visualization Gallery》、Lucen Software 时间线指南、少数派 Aeon Timeline 评测、国内同类产品（墨韵 / 云上写作 / WordTree）产品资料。

### 3.1 关系图（Network Graph）

| 实践 | 行业做法 | 依据 |
|---|---|---|
| **按类别/阵营着色** | G6 官方「哈利波特人物关系网」范例：节点按**阵营**着色（霍格沃兹/凤凰社/食死徒/中立各一色） | 行业标准手法，一眼看出阵营分布 |
| **分组凸包** | 用 convex hull 包裹同社群节点，配群组标签 | Visual Complexity：先聚类再布局，减少跨簇交叉 |
| **节点尺寸** | 按度数映射，但**限制在 3–5× 区间**内，避免枢纽过度主导 | 同上 |
| **边曲率** | 弧线曲率 ≈ 0.15–0.25 × 边长，用来分离平行边 | 同上 |
| **边捆绑** | 毛球区把同簇间的边捆成束 | 同上 |
| **力导向参数** | link distance 70–120px、斥力/引力按密度调参 | 同上 |
| **确定性布局** | 固定随机种子或按度数播撒初始位置 | 保证同一份数据每次打开长得一样（本项目已是确定性） |
| **标签** | 节点文字置于节点下方 12px、字号 14px | G6 范例 |

### 3.2 时间线（Timeline）

| 实践 | 行业做法 | 依据 |
|---|---|---|
| **避免等间距谬误** | **物理间距应匹配实际时间间隔**；跨度悬殊时用对数/分段比例 | Lucen：「When March and April take up the same space as the entire 1990s, you're distorting reality」 |
| **泳道（Swimlane）** | 多线叙事用泳道并列展示，同一时间轴对齐 | Lucen / Deckary：咨询业标准做法 |
| **色彩编码** | 一个类别一个色，全程一致；**避免彩虹** | Lucen：「Assign specific colors to distinct categories and use them consistently」 |
| **视觉层次** | 主要事件比次要事件更突出；里程碑单列 | Deckary：里程碑是注意力的锚 |
| **渐进披露** | hover/click 才展开细节 | Lucen：「show key details first, with additional information available on demand」 |
| **现在标记** | 「正在进行」的事件跟随时间线推进到「现在」 | Aeon Timeline 特性 |

### 3.3 国内同类产品做法

| 产品 | 可视化特色（可借鉴） |
|---|---|
| **墨韵** | 世界观**三栏视图**（层级树 + 关联图谱 + 详情面板）；关系图支持「**动态演变事件**」（如"第10章决裂"） |
| **云上写作** | 关系图自动标注「**交互事件与影响路径**」；创作分析含「**命运交集、登场统计**」 |
| **WordTree** | 关系图可为角色绑定「**阵营 / 年龄 / 角色弧光进度**」；「关系弧线的变动本身是剧情节奏的镜子」 |
| **Aeon Timeline** | 「**地铁视图**」——理清各人物在特定时间段有无交集；事件可拖拽调时间 |

### 3.4 调研结论

1. **本项目的关系图最大短板 = 缺类别编码**（行业范例毫无例外都按阵营/社群着色分组）。
2. **时间线最大短板 = 等距非等比**（可视化设计里的经典反模式）。
3. 本项目的**泳道、区间着色、确定性布局**已经踩在正确路径上——不是推倒重来，而是**补齐缺的那几维编码**。
4. **不需要引入外部库**：G6/d3 体积大、与项目「零依赖手写 SVG」的传统冲突，且有打包 tree-shake 风险；所需效果手写 SVG 完全做得到（渐变、滤镜、凸包都是原生能力）。

## 四、改进方案（引用数据不变）

> 🔴 铁律：**只消费现有字段**。所有新增视觉编码都必须能映射回已有的 schema 列，不新增表/列/字段。

### 4.0 统一视觉语言（总纲）

先把四个视图拉齐成一套语言，再各自增强：

| 元素 | 统一规则 |
|---|---|
| 节点形状 | 圆（关系图）；「圆 + 类别色环」（新增类别维度） |
| 节点配色 | 常态=类别色；悬停=加亮；选中=强调描边 |
| 边 | 统一**弧线**（曲率 0.18 × 边长）；颜色=关系类型；线型=关系性质 |
| 标签 | 统一药丸底（现在势力图是裸文字） |
| 时间轴 | 加刻度 + 年代标尺；卡片统一色带 + 图标 |
| 动效 | 入场描边绘制（`stroke-dashoffset`）、悬停过渡；**不引入 JS 动画库**，走 CSS |

---

### 4.1 人物关系图 —— 按「所属势力」着色 + 分组凸包

**数据来源（全部现有）**：`relations` 表「人物A / 人物B / 关系类型 / 关系现状 / 演变轨迹（按卷）」+ 角色卡「所属势力 / 人物状态 / 身份定位」。

| 改进项 | 做什么 | 消费字段 |
|---|---|---|
| **① 节点按阵营着色** | 读三张角色卡的「所属势力」→ 同一势力的人物同色；无势力的用中性色 | 角色卡「所属势力」 |
| **② 群组凸包** | 同一势力的节点外面套一层半透明凸包轮廓 + 势力名标签 | 同上 |
| **③ 人物状态标记** | 「未登场」人物 → 节点用**虚线描边**（一眼看出还没出场的人） | 角色卡「人物状态」 |
| **④ 边线型双编码** | 关系类型 = 颜色；性质 = 线型（敌对/恩怨 → 虚线；CP感情线 → 细双线；主仆 → 带箭头） | `关系类型` |
| **⑤ 悬停详情卡** | 悬停节点/边 → 浮出「关系现状 + 知情度 + 演变轨迹」摘要 | `关系现状`/`知情度`/`演变轨迹` |
| **⑥ 尺寸归一** | 节点半径限制在 3–5× 区间（现在 7–20px 已是 2.8×，微调即可） | — |

**风险评估**：🟢 低。着色与凸包都是渲染层，不动布局算法；凸包用现有节点坐标算凸壳（Andrew 单调链，O(n log n)），80 节点无压力。

---

### 4.2 势力关系图 —— 从「圆环」升级为「力导向 + 类别编码」

**数据来源（全部现有）**：`faction-rels` 表「势力A / 势力B / 关系类型 / 关系现状」+ `nations` 表「名称 / 类别 / 上级 / 实力等级 / 与主角关系」。

| 改进项 | 做什么 | 消费字段 |
|---|---|---|
| **① 布局换成力导向** | 复用人物图的 FR 算法（抽成公共函数）→ 有关系的势力自然抱团 | — |
| **② 节点按类别着色** | 读《国家势力》「类别」（王朝/宗门/世家/商会/魔道/隐秘组织/神族/城池）→ 一类别一色 | `nations.类别` |
| **③ 节点尺寸按实力** | 「实力等级」有值时映射尺寸（无值退回按度数） | `nations.实力等级` |
| **④ 层级就近吸附** | 「上级」链上的子势力，力导向中额外加一根弱弹簧拉向父节点 | `nations.上级` |
| **⑤ 视觉语言对齐人物图** | 边改弧线、标签加药丸底、图例统一 | — |
| **⑥ 悬停关系详情** | 悬停边 → 显示「关系现状」 | `关系现状` |

**风险评估**：🟡 中。布局算法更换会改变节点位置（但拖拽状态与交互逻辑不变）；需实机确认 80+ 势力时的收敛速度。

---

### 4.3 历史事件轴 —— 加刻度 + 年代标尺（可选等比模式）

**数据来源（全部现有）**：`history` 表「事件名称 / 历法 / 发生时间 / 结束时间 / 状态 / 上级 / 距今时长 / 已发布章节是否提及」。

| 改进项 | 做什么 | 消费字段 |
|---|---|---|
| **① 轴体升级** | 主轴加粗 + 加**年代刻度线**（按历法规则推刻度，如每十年一小格） | `历法`/`发生时间` |
| **② 时间比例模式** | 提供「等距 / 等比」**双模式开关**（默认保持等距，老手感不变；等比让间距按实际时间差） | 同上 |
| **③ 事件层级** | 「上级」有值的事件 → 卡片顶部标注父事件（或轴上画连接线） | `上级` |
| **④ 状态视觉强化** | 状态色带加渐变；「已变更」加角标 | `状态` |
| **⑤ 发布状态标记** | 「已发布章节是否提及」有值 → 卡片加一个小「已入正文」徽章 | `已发布章节是否提及` |
| **⑥ 悬停联动** | 悬停卡片 → 轴上对应圆点放大 + 时长线条加亮（现在已有部分，补齐） | — |

**风险评估**：🟡 中。等比模式是**新的时间轴数学**（`interpolateX` 需要从「等距插值」改为「按 time key 比例」），需仔细验算跨历法场景；建议**先做等距模式下的轴体/刻度/层级**，等比作为二期。

---

### 4.4 故事时间线 —— 泳道视觉重构 + 呼应嵌套

**数据来源（全部现有）**：`timeline` 表「章节号 / 线/轨道 / 历法 / 发生时间 / 结束时间 / 时节季节 / 主角当前境界年龄 / 地理位置 / 本章关键事件 / 时间线检查」。

| 改进项 | 做什么 | 消费字段 |
|---|---|---|
| **① 泳道背景升级** | 泳道交替底色 + 左侧标题栏加类别色条（现在只是文字） | `线/轨道` |
| **② 轴体升级** | 每泳道的轴加刻度 + 章节号标尺 | `章节号` |
| **③ 境界/年龄轨迹线** | 「主角当前境界/年龄」有值时，在泳道上方画一条**折线轨迹**（成长可视化） | `主角当前境界/年龄` |
| **④ 时节标记** | 「时节/季节」作为次要标注（如角落小字） | `时节/季节` |
| **⑤ 倒流告警视觉统一** | 已有「倒流」角标，改为更醒目的红色脉冲边 | `时间线检查` |
| **⑥ 时间比例模式** | 与历史轴共用同一个「等距/等比」开关 | — |

**风险评估**：🟡 中。③境界轨迹线需要解析「境界/年龄」文本（可能是自由文本，需要容错）；建议**先做①②⑤（纯视觉）**，③作为增强项。

### 4.5 全局增强（四视图共享）

| 改进项 | 说明 |
|---|---|
| **统一动效语言** | 入场时边/线做「描边绘制」动画（`stroke-dasharray/offset`），悬停做平滑过渡；纯 CSS，不引库 |
| **统一空状态** | 四个视图的空状态插画与文案统一（现在势力图有图标、其他没有） |
| **统一提示条** | 顶部说明条样式统一（字号/颜色/间距） |
| **图例统一** | 两图的图例样式统一（药丸/位置/间距） |
| **导出** | 可选：关系图/时间线导出 PNG（现有画布导出能力复用） |
