## 二、优先级与实施顺序

1. **P0 互斥真源与安全恢复**：统一进程所有权和可信恢复，解决配置标记创建失败、遗留锁、迁移与在途任务；先制定清晰故障状态与不可自动恢复边界。
2. **P0 桌面、便携与调用接线**：同一权威服务接入两种运行入口，覆盖全部 Agent 调用和 API 模型请求，按完整任务持有租约；确保无绕过路径。
3. **P0 模式切换体验和多窗口**：真实状态驱动 UI、配置和帮助；切换可等待、可取消并正确报告阻断与恢复，保留草稿及配置。
4. **P1 数据一致性与领域扩展**：先建立跨窗口/云同步写入保护，再按领域开放地图、画布等能力；每个领域实施与测试一并完成。
5. **P1 客户端与交付验证**：隔离桌面和便携端逐层联调，逐个客户端记录能力差异；待源码稳定后重新构建、核对并执行完整测试与审计。封装、安装、发布、推送、部署分别遵守当次明确授权。

## 三、待开发：API 与 Agent 互斥

### 3.1 真源、所有权与启动

- [ ] 明确互斥范围（同一宿主/资料区、多 profile、不同目录和多设备）及共享数据边界；不得把本机文件锁描述为跨设备锁。盘点桌面 `userData`、自定义数据路径、便携 `data`、浏览器和多个实例如何取得同一权威状态。（同一资料区的单宿主所有权已实现；多 profile / 多设备仍未验证）
- [x] 将模式服务接入 `electron/main.cjs` 和 `scripts/portable-server.mjs`，同一资料范围只能有一个可信宿主；指定 IPC / 同源传输、调用方身份和所有权生命周期，失败时阻断，不静默退回无闸兼容路径。
- [x] 处理旧配置：确认旧宿主真正停止后才能初始化；损坏、未知版本、未完成切换、残留锁不能误认为首次使用。迁移不得自动授予 Agent 权限、修改 API 密钥或覆盖作品；为每一类旧状态给出可验证结果。
- [x] 设计遗留锁、pending 标记及模式中断的可信恢复：确认原进程和任务终止、展示待核对信息、备份证据、明确用户操作与可回退结果；不可仅凭 PID 或超时自动删锁。覆盖标记无法创建、写入/同步/删除失败及重启仍读取旧授权的漏洞；避免以清除标记伪装修复。
- [ ] 核对 Windows 文件共享语义、锁归属、异常退出与目录权限；明确正常退出和启动失败时服务器、租约、持锁的关闭顺序。（正常与失败关闭顺序已实现；Windows 文件共享与断电实测未做）

### 3.2 两方向运行闸与任务生命周期

- [x] 盘点并接入全部模型请求：`src/lib/aiCore/chat.ts` 与协议 driver、`src/lib/semantic/embed.ts`、酒馆独立 provider、模型测试/能力探测、模型列表与卸载等网络路径；逐项定义 Agent 模式是否允许，检索直接 `fetch` 和桌面网络代理旁路。
- [x] 连接统一宿主的 API 租约：覆盖完整任务而非仅响应头；流式响应消费、取消确认、重试、后台索引和多步任务均在租约期内。请求失败、取消、连接丢失或结果不明时按实际完成状态释放或保留，不能凭超时假定任务终止。
- [x] Agent 调用、只读/写入/重放、开启连接及授权变更均由同一模式闸仲裁；确保旧配置已启用、独立只读桥、其他宿主进程和多窗口均不能绕开已定义的模式边界。
- [x] 实现 API→Agent 与 Agent→API：先拒绝新任务、持久化切换状态并回读、等待旧租约排空、确认旧方向停止及目标就绪、提交并回读稳定状态；异常/取消/崩溃失败关闭并可恢复。校验目标和切换 ID，处理重复、并发、迟到回执。
- [x] 明确网页版无本机宿主时的产品行为和限制，不以页面 state 或本机服务缺失时默认放行来宣称互斥。

### 3.3 UI 和用户可见行为

- [x] 显示实际稳定/切换中/阻断状态、正在等待的任务、错误和安全恢复入口；支持取消等待但不把未确认任务当作已结束。多窗口和重启后必须读取宿主真源。
- [x] API 与 Agent 设置、帮助、连接提示词、第三方 MCP 规范同步实际行为；未完成前继续明确“Agent 连接设置”，不可宣称互斥已生效。
- [x] 切换不改变模型、密钥、项目授权、正文草稿或手工编辑；区分 Agent 自身模型与引擎 API 模型，说明 Agent 模式下不可用的引擎模型能力。

## 四、待开发：Agent 能力与一致性

每个领域先核对业务保存入口、草稿与在途屏障、项目/动作授权、参数白名单、版本冲突、幂等和回读，再接界面刷新与测试；不开放通用数据库写入作为替代。

| 领域 | 待办与出口 |
| --- | --- |
| 跨窗口与同步 | 建立可证明的写入协调或原子版本条件；覆盖桌面多实例、便携多标签、云同步和其他设备，无法保证时拒绝写入并提示；验证后到窗口和同步开启期间的竞态。 |
| 地图 / 画布 | 设计对象级创建、修改、删除及引用完整性；处理图片/坐标、画布未保存草稿、打开页面、布局与刷新，冲突不得覆盖人工编辑。现有地图摘要和画布读取不代表写入可用。 |
| 世界包 / 备份恢复 | 设计跨项目目标身份、授权、覆盖确认、ID 重映射、依赖和回滚；恢复前预览及持久化校验，禁止把破坏性操作伪装为普通写入。 |
| 酒馆与创作/检查任务 | 划定手动任务、模型使用及互斥关系；增加任务生命周期、进度、取消、结果确认、幂等和资源上限。现有检查工具和报告读取仅是部分能力。 |
| 既有写入补齐 | 对设定表/卡、章节、分卷、灵感、世界设定核对字段、自定义模板、删除与引用、恢复、同页草稿和版本；按缺口逐项实现，不把单页锁称为跨设备 CAS。 |
| 发现与兼容 | 以 `tools/list` 和实际校验为契约真源，同步参数 schema、授权、错误和文档；清晰标记未开放能力及客户端差异。 |

- [ ] 持久化和生命周期：首次安装、旧启用/禁用配置、损坏/未知版本、中断记录、锁已占用或残留、标记创建/同步/清除失败、磁盘满/只读、进程崩溃与重启；人工恢复保留证据且不会误放行。真实断电及 Windows 文件锁行为分别实测或标注未覆盖。
