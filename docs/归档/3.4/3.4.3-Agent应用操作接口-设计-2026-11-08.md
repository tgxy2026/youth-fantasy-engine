# Agent 操作引擎接口：开发设计（2026-11-08）

## 目标与现状

用户希望通过 Antigravity 等 Agent 下指令，让 Agent 能在青春幻想引擎中创建设定、录入正文，并继续支持已有 API AI 功能。可写 MCP 工具与宿主写入服务已于 2026-11-08 第二轮实现并通过隔离测试（见实施记录 §12）；真实客户端挂载、桌面 IPC 实机闭环与安装包验收仍未完成，不能称为整版验收。

## 首批能力

1. 查询：按明确项目 ID 列出项目、设定栏目、章节及可写能力，响应携带可用于冲突检测的版本。
2. 创建设定：指定项目、栏目、名称、字段和请求 ID；字段须按栏目 schema 校验，由引擎分配记录 ID。
3. 录入正文：指定项目、章节、预期版本和正文；首期优先创建新章节或追加，覆盖现有正文作为独立动作，不将追加误当覆盖。明确返回实际章节 ID、保存状态与新版本。
4. 状态查询：查询请求是否已接收、保存成功、冲突或失败；重试相同请求不能重复创建或重复追加。

Agent 只有在用户主动开启连接并选定允许操作的项目及动作后才有写权限；默认只读。允许用户明确授权后执行直接写入，不要求每次操作都重新确认。不得暴露文件系统路径、通用脚本执行、删除作品或任意数据库读写。
此外，引擎必须处于 **Agent 模式**（与 API 模式互斥）才会放行工具调用；API 模式下宿主返回 `MODE_BLOCKED`，不会进入页面或写入账本。模式切换与恢复见 [互斥模式设计](3.4.3-API与Agent互斥模式设计.md)。

## 关键工程约束

- **写入必须进入正在运行的引擎宿主**：外部进程不能直接改 JSON 文件。桌面 IPC、便携本地服务和浏览器各自的持久化机制不同；直接改文件会与引擎内存、自动保存及云同步竞争。
- **固定归属**：每次请求携带 projectId 和连接会话身份，提交前后核验用户与项目未切换；不能使用异步完成时的 currentProjectId 作为归属。
- **草稿与并发**：编辑中的未保存草稿、异步保存、其他窗口及云同步可能与 Agent 竞写。仅先读取再普通 put 或比较 updatedAt 后写入并不构成原子 CAS。需要明确的串行化/事务或持久化版本前置条件，并与现有编辑器保存屏障协作；无法证明无冲突时拒绝且保留双方内容。
- **持久化确认**：写入结果仅在底层存储确认后报告成功；超时、断连或结果不明应允许凭 requestId 查询，不可盲目重复写入。失败保留原输入并明确原因。
- **可恢复与 UI 同步**：修改正文前保留可恢复版本；成功后通知当前界面刷新，不能覆盖用户正在编辑的草稿。设定字段按引擎真实 schema 与主键关系写入，保留章节统计、索引等派生行为。
- **授权与边界**：服务仅本机、按连接会话隔离，非浏览器同源页面或任意进程不能凭猜端口调用；作用域和过期/撤销可见；不收集 Agent 软件的登录凭据。协议错误、授权失效和过期请求均失败关闭。
- **风险分离**：Antigravity 官方客户端通过 MCP 调用本地工具，与将订阅凭据包装成第三方模型 API 是不同路线；需核实当期厂商条款和应用内工具权限。系统蓝屏未定位，不重启此前独立 ACP 运行时。

## 分阶段交付与验收

- P0：确认本地宿主边界、各平台权限与保存确认；模拟项目切换、草稿未保存、存储失败、重复请求及并发写入。不能把当前普通读改写宣称为原子 CAS。
- P1：隔离夹具完成创建设定与创建/追加章节的有限工具及持久化回读，包含失败注入、撤销授权、重复请求、超时重试和脏草稿冲突测试。
- P2：接入桌面与便携客户端、连接管理和状态提示；在合成项目上实测 Agent → 工具 → 引擎 → 持久化 → 界面闭环，不使用用户真实作品作为测试数据。
- P3：在明确授权及风险边界后验证实际应用联通、恢复和多窗口竞争；基础代码与门禁完成后按用户授权封装测试版；发布、部署和推送另行处理。每一层的结果分别记录，不能用假服务或局部通过冒充完整验收。

本文件规定开发边界与验收。首批可写工具与宿主服务已实现：`src/lib/agentHost/contract.ts`、`src/lib/agentHost/executor.ts`、`src/lib/agentHost/host.ts`、`scripts/agent-host/core.mjs`、`scripts/mcp/yfe-agent.mjs`、桌面主进程 / 便携服务接线与设置界面。现有只读桥继续保留为独立能力；旧 ACP 后端试验代码已按新方向移除；原始测试与崩溃证据仍保留。真实客户端、真实作品与安装包仍未验证（见实施记录 §12.4）。

## 多 Agent / 模型兼容与测试版授权（用户追加）

- 用户要求不限 Antigravity，尽可能覆盖主流 Agent 软件和 AI 模型；基础代码开发完成后，**已授权封装一个版本用于实际测试**。此前未完成基础代码时不得提前封装；此授权不自动等于发布、推送或部署。
- 优先采用开放标准 MCP 工具接口：本机 stdio 与按需实现的 Streamable HTTP 是不同传输能力，须分别实现和验证；协议遵循其版本协商、工具 schema、错误返回与工具权限规范。MCP 连接发生在**Agent 客户端与引擎工具之间**，不等于任意模型原生支持 MCP；模型还必须通过支持工具调用的宿主使用。不得宣传“兼容所有模型”。
- 输出客户端矩阵：名称、版本、操作系统、传输方式、工具发现、读取、设定创建、正文写入、取消/故障、结果及已知限制。先以受控标准客户端跑契约，再逐个实测实际客户端；无法实际运行的标注未验证，不将协议理论兼容写成通过。
- 覆盖既有 API 模型模式与外部 Agent 工具模式的差异：前者仍使用原先接口及计费；后者使用各自宿主和模型的授权、能力与费用，独立管理，不提取/转发 OAuth 凭据。
- MCP 官方依据：https://modelcontextprotocol.io/docs/getting-started/intro 、https://modelcontextprotocol.io/specification/2025-06-18/basic/transports 、https://modelcontextprotocol.io/specification/2025-06-18/server/tools 。

## 2026-11-08：面向全面接入的能力盘点

用户进一步要求各类 Agent 可以使用引擎各项功能。按领域逐项开放、按真实实现标记状态，不以“支持 MCP”代替功能或客户端验收。

| 领域 | 当前工具 | 后续工作 |
| --- | --- | --- |
| 项目和章节 | 查询项目、卷和章节；创建章节、读取、追加、覆盖正文 | 创建卷、章节元信息与顺序等；补齐当前界面同步、跨窗口与云同步的并发保护 |
| 设定卡与大纲卡 | 发现栏目、分页列卡、读取卡、创建设定卡 | 更新、归档/删除前需草稿屏障、字段冲突检查和恢复；项目自定义模板按真实 schema 适配 |
| 作品信息 / 世界设定 / 总纲等表单 | 发现基础栏目、读取已保存表单 | 表单修改需要草稿保护、版本冲突检测和保存后界面同步 |
| 人物关系 / 势力 / 地理 / 伏笔等表格 | 发现基础表、分页读取当前项目行的可见基础列 | 增改需处理自定义列、引用和编号规则、草稿与派生数据 |
| 地图、画布、世界引擎、酒馆、创作工具、素材、检查、备份等 | 地图/地点/格子、情节画布、世界包引入、备份恢复、回收站恢复已开放；酒馆与 AI 长任务在 Agent 模式不可用 | 底图图片替换、灵感单条删除、素材与项目删除仍未开放；每项须保持业务契约、权限、可恢复性与验收 |

## Codex 测试与通用客户端

用户指定先以 Codex 客户端与引擎测试版联调，同时仍需兼容更多主流 Agent。引擎设置提供 Codex TOML 配置生成选项并保留通用 MCP JSON；初始化消息说明调用约束。2026-11-08 已用真实 Codex CLI 和临时配置对隔离测试版验证发现、读写、撤权拒绝、重复请求及旧版本冲突；另借助测试控制器停止并重启引擎，验证真实 Codex 收到断连错误后重放同一请求并读回。该结果不代表自动重启，其他客户端尚待实测；未自动修改用户 Codex 配置。以 HANDOFF 最新测试记录为准。

配置依据：[OpenAI 官方 MCP 文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)（stdio、`config.toml` 的 `mcp_servers`、`command`、`args`）；支持配置不等于客户端或全部模型已验收。

只读返回已保存的 store 数据，不包含页面尚未保存的输入；表格目前不返回隐藏列、图片或自定义列，发现信息为基础 schema，不能视作自定义模板完整映射。需要明确启用本地连接后读取；写入仍须授权对应项目和动作。

请求账本只记录写入：同一 requestId 绑定工具及参数摘要，不同内容复用拒绝；过期 pending 变为结果不明，损坏账本拒绝启动，旧版缺少摘要的记录需人工核对。为避免遗忘导致重复执行，不自动淘汰记录，账本会随写入增长，须后续设计可审计的清理和容量管理；旧版本已经淘汰或丢失的记录无法追溯。该机制仍不是跨进程、跨窗口或云同步的原子幂等保障。
