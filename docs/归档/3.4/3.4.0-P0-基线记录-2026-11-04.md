## 2. P0 核查结论（逐包，全部来自本轮源码抽查）

### A. 规划板与正文往返

- 现状：规划板状态（展开、视图、卷 / 状态 / 关键词、两个 60 条上限、滚动位置）全部是 `useState`，**随写作面板卸载一起消失**；点卡片只是 `onNavigate('editor', id)`，回来无任何锚点。
- 写作面板 `load()` **没有 catch**：读库失败时 Promise 静默 rejected、`loaded` 永远 false ⇒ 页面永久停在「加载中…」，没有重试入口。
- 结论：规划 §三 A.2 的「恢复卷、状态、关键词与滚动位置」「目标删除/读取失败分别提示」此前**均未实现**；A.1/A.3/A.4（只读、原排序、状态不一致只提示、无拖动排序）已满足，本轮未改语义。

### B. 本章资料

- 现状：绑定与固定按章存在 `chapterContext32:<章 id>` 项目设置里；续写计划只读取显式勾选的固定项（`continuationPlan`），打开抽屉不会扩大发送范围 —— 与规划描述一致。
- 缺口（均已复现于源码）：
  1. `useChapterContextData` 读绑定失败时也把 `bindingLoaded` 置 `true`，固定/解绑按钮随之可用 ⇒ 一次点击就会用空绑定**覆盖库里原记录**（违反规划 §四「读取失败不当作空数据覆盖」）。
  2. 资料目录整体读失败时，固定项一律显示「记录已删除或暂时不可用」——把「没读出来」说成「已删除」。
  3. 保存失败只置一行错误文案，界面仍显示已保存的绑定（乐观更新不回滚）。
  4. 抽屉固定 18rem 浮层：1440 视口下与限宽正文列重叠近百像素；无 Esc 收起、收起后焦点不回入口；页签每次换章重置。
- 结论：数据模型与「只读参考」定位无需重建，属**安全性与可用性补缺**。

### C. 时光机

- 现状：每章 12 版共用池、优先淘汰最旧自动快照；来源可区分 AI 留档。
- 缺口：
  1. `restoreSnapshot` 用渲染闭包里的 `active.content` 留档 ⇒ 若 2 秒防抖窗口内还有未落库输入，**恢复前的真实草稿没被留住**；
  2. 留档后直接 `updateContent(content)`（乐观 UI + 后台队列），写盘失败时界面已显示「已恢复」；
  3. 调用方不 await，弹窗立即关闭，失败连提示都没有；
  4. 不校验目标章 / 快照是否仍在（12 版池会淘汰旧版，切章也可能发生）。
- 结论：恢复路径此前**不具备可核实的失败语义**；本轮按其真实风险重做为事务。
