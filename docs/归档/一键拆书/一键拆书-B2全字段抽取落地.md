| 项 | 结果 |

## §1 与详细设计的偏差（三处，都必须说清）

### 1.1 「第二遍」用**确定性代码**做，不是再调一次模型 🔴

设计 §4.3 是「把所有块的 JSON 喂给模型做合并校验」。**没有照做**，理由：

- **不可靠**：09-18 的 C 方案实测证明，让模型复核一份 JSON 清单，精度只有约 60%，
  且**提示词两句话之差就从「剔 33 条」翻成「剔 0 条」**（见 `docs/2.2.0-C方案复核实验记录.md`）。
  合并是**破坏性**操作（合并错了要人工拆回来），不能交给这种稳定性的环节。
- **不可扩展**：60 块 × 2-4KB 的输入远超预算；拆批又引入"批间再合并"的递归问题。

**现在的做法**：`flow/draft` 里三步确定性合并 ——
① `mergeEntities` 同名/别称跨章合并 → ② `foldNameVariants` 同物多写法归并 → ③ 字段级 `mergeExtraField`。
冲突不猜，交作者。

**代价（如实记录）**：跨块的**语义同一性**识别不了（正文里「玄真子」与「国师」指同一人，
字符串规则看不出来）。留作将来的**可选**模型遍，默认关。

### 1.2 form 型（世界观 / 力量体系 / 书籍定位）本轮不做

`worldbase` / `power` 是**整项目单条**的 form 型页签，而 `flow/commit` 只有 card / table 两条写入通道。
按需求文档的说法它们是"该填的地方"，但落地需要**新增 form 通道 + 末尾汇总阶段**（逐章增量写单条会越写越长、
还会覆盖作者手改的内容）—— 另开一批，不在本轮硬塞。

### 1.3 关系表（`relations` / `faction-rels`）本轮不做

设计 §6.1 里有 relation kind（人物A/人物B + 关系类型）。那是**新增一类实体 + 新表映射 + 双向引用解析**，
同样另开一批。本轮人物卡里的「人际关系」是**文本字段**（`relations` slot → 「人际关系」列），已经能用。

## §2 实现要点

| 改动 | 文件 | 说明 |
|---|---|---|
| 字段键**从映射表派生** | `aiTasks.ts` ← `flow/fieldMap.ts` | 提示词里的字段清单由 `KIND_MAP[*].slots` 生成，`SLOT_HINT` 只管中文措辞 → **「schema 改了 prompt 没跟」在结构上不可能发生** |
| `EXTRACT_FIELDS_SPEC` / `EXTRACT_SYS_FULL` | `aiTasks.ts` | 追加进 system 的「应补全的字段」段（含一条人物示例） |
| 解析抽成纯函数 | `aiTasks.parseExtractedEntities()` | 顶层/`fields` 子对象、英文键/中文列名、relations 的数组与字符串都认；**只认该类型 slots 声明的键**（给「地点」塞 identity 一律丢） |
| 字段合并与冲突 | `flow/draft.mergeExtraField()` | 空→写；归一化相同→略；**包含→取长的、不算矛盾**；否则取长的 + **只有硬事实字段**才记冲突 |
| 落点优先级 | `flow/draft.fieldsOf()` | **slots 先落、desc 让位**（人物的 descFields 与 slot identity 都指「身份定位」，identity 更准）；`descKey` 仍指向那一格，界面摘要不空 |
| 抽取改流式 | `aiTasks` + `bookbreak/run.ts` | B2 输出是 B1 的数倍 → 非流式必撞 180s 总超时墙；顺带把「已收到 N 字」显示进节点时间线（节流 120 字） |
| 补 `age` slot | `flow/fieldMap.ts` | 实测发现角色卡有「年龄/性别」列却**没有对应 slot** → 该字段永远抽不到。补上后由一致性闸验证（见 §4） |
| 耗时估算上调 | `bookbreak/recommend.ts` | 云端 `8~18s/次` 实测为 **~51s/次**，上调为 `25~60`（本地 `60~150`） |
| 说明文案同步 | `BookBreakPanel` / `aiDataSources` | 写明"补全设定字段"与"冲突不替你猜" |

## §3 实测（示范项目自己的 6 章 · 29,163 字 · 9 次抽取调用 · 446.1s）

### 3.1 字段填充

| 分类 | 条数 | 平均字段数 |
|---|---|---|
| 人物 | 14 | **8.4** |
| 势力 | 1 | 9.0 |
| 地理 | 11 | 6.3 |
| 物品 | 15 | 6.8 |
| 术语 | 22 | 5.4 |
| 种族 | 1 | 7.0 |
| **合计** | **64** | **6.6** |

对照 B1：那时每条只有 名称 / 别称 / 描述 / 首次出场 四格。

### 3.2 字段冲突（只在硬事实字段报）

13/64 条（20%）共 14 处，全部落在 `类别 / 实力境界 / 品级` 上，例如：

- `陈渊`：实力境界 `淬体境` ⇄ `淬体一重巅峰` ／ `聚灵一重`（阶段性推进，作者定夺）
- `桂花糖`：类别 `丹药` ⇄ `食物` ／ `物品`（模型自己都不确定 —— 正好暴露给作者）
- `混沌吞天诀`：品级 `未知` ⇄ `顶级` ／ `残篇`

**为什么要收窄**：初版对所有字段报冲突，6 章样本上 **23/61 条（38%）** 被标成「有冲突」，
点开大半是「壮实，嗓门大」vs「身板结实」这类互补描述、或「陈渊：兄长」vs「陈渊：兄妹」这类同义写法，
真矛盾（境界从「废脉」跳到「淬体一重」）反而被埋掉。

### 3.3 字段级「已知答案对照」：32.5%（下限）

口径：拿项目里**已登记的设定**当标准答案，草稿的每个字段值去那条已登记值里找**互相包含**的值。

- 名字命中登记表的草稿 17 / 64；这些草稿的 151 个字段值中 **49 个命中 → 32.5%**
- ⚠️ **这个数是下限**，因为口径是严格包含：抽取的「瘦，旧布衣洗得发白」与已登记的「瘦削但筋骨匀称」
  语义吻合却判不中；已登记的「姓名」列甚至写着解释（`陈渊：深渊之渊，父望其深沉`）也会判不中。

**抽样人工核对（6 条）发现三类真问题**：

1. ✅ **结构字段准**：`青岚宗.类别=宗门`、`青岚宗.掌权者=掌门青玄子`、`王铁柱.别称=铁柱` 都与已登记一致
2. ⚠️ **字段错位**：`王铁柱.外貌特征=四仰八叉睡姿，怀中抱馒头` —— 把**场景/动作**当成了外貌
3. ⚠️ **漏字段**：`年龄/性别` 项目卡里有、抽取没有（本轮已补 `age` slot）；
   `萧景行.首次出场=第1章` 而项目登记是第 3 章（**把"提及"当"出场"**）
4. 🔎 **项目自己的标准答案有脏数据**：`陈瑶` 的已登记「年龄/性别/外貌特征」写着
   `20岁/男，身材魁梧、剑眉星目`，而抽取的「六岁、梳双丫髻」反而更合理 ——
   **对照法要留一分怀疑给"标准答案"**。

## §4 测试与闸

| 用例 | 条数 | 覆盖 |
|---|---|---|
| `tests/extractFields.test.ts` | 20 | ①**一致性闸**：键清单 == fieldMap slots、每个键都在 prompt 里且有中文提示、无死提示；②解析容错（英文键/中文列名/`fields` 子对象/relations 两种形态）；③🔴 负面对照：给「地点」塞人物字段必须丢弃 |
| `tests/draftFields.test.ts` | 17 | 冲突检测（含置信度 −0.3）、**包含不算冲突**、**叙述型字段不报冲突**（含反面对照）、identity 优先于 desc 且同列不重复、表格型字段落点 |
| `tests/extractAliases.test.ts` | 10 | 原别称解析 + 新增「🔴 抽取请求必须 `stream:true`」（B2 流式不变量） |
| `tests/importCycles.test.ts` | 9 | 新增**类型边擦除**（`import type` 不产生依赖边）+ 5 条擦除器自检 + 依赖边数量下限 |

**闸的价值当场演示过**：补 `age` slot 时忘了在 `SLOT_HINT` 加提示，
`extractFields` 立刻报 `FAIL 每个字段键都有中文提示 :: 人物/age` —— 正是它该拦的东西。

## §5 下一批（按需求文档与设计的剩余项）

1. **form 通道**：`worldbase` / `power` / 书籍定位 → 流程**末尾汇总一次**（不逐章增量），加来源标注 + 不覆盖手改
2. **关系 kind**：`relations` / `faction-rels` 两张表 + 名称→引用的解析（先建 nations/geography 再写引用）
3. **语义级跨块同一性**（可选模型遍，默认关）：识别「玄真子」=「国师」这类字符串看不出的同指
4. **提示词再收紧**：字段错位（场景→外貌）；「首次出场」需以**实际出场**而非提及为准
5. **章节概要回填**：正文定稿后回填「章节细纲」卡（老大已定口径）
