## 二、统一方案（三层）

```
L1 调色板单一真源   src/lib/palette.ts      ← 本轮新建，全部词组色收口于此
L2 主题变量         src/index.css           ← 已有（6 套主题 × ink/amber/danger/success/info）
L3 闸门             tests/structureGates ⑨  ← 本轮新增，防它再散开
```

### L1 · `src/lib/palette.ts`（新建）

**纯常量模块**：不 import 任何东西（尤其不 import `db` / React / DOM）⇒ lib 与 components 都能引用，Node 单测可直接读。

导出的色板：

| 导出名 | 用途 |
|---|---|
| `REL_EXTRA_PALETTE` | 关系类型扩展色板（20 色，两张关系图共用） |
| `REL_PRESET_COLORS` | 人物关系内置 8 类语义色 |
| `FACTION_PRESET_COLORS` | 势力关系内置 5 类语义色 |
| `GROUP_PALETTE` / `GROUP_NEUTRAL` | 关系图节点分组色板 / 无分组中性色 |
| `MAP_LAYER_COLORS` / `MAP_SPACE_FALLBACK` | 地图图层色 / 区域兜底色 |
| `PLOT_TYPE_COLORS` | 情节画布卡色（6 类） |
| `BEAT_COLORS` | 结构节奏节拍色板（8） |
| `GOAL_ACTUAL_COLOR` | 写作目标实际累计线色 |

🔴 **所有值是迁移前的原值逐字搬运 —— 观感零变化**。调整色值属于「改设计」，须先说明再动。

原持有者一律改为 `import` + 再导出（`export { X }`），**既有引用一律不破**：

- `lib/relationColors.ts`、`lib/graphGrouping.ts`、`components/geoMapGeometry.ts` 三个模块**保留同名导出**（`REL_EXTRA_PALETTE` / `GROUP_NEUTRAL` / `LAYER_COLORS`），只是值改为从 `palette.ts` 取；
- `RelationGraph` / `FactionGraph` / `PlotCanvas` / `StructurePacePanel` / `WritingGoals` / `GeoMapEditor` 六个组件改为引用具名常量。

### L2 · 主题变量（既有，无需改动）

`src/index.css` 已用 CSS 变量 + `<html data-theme>` 实现 6 套主题（dark / eye-care / midnight / sepia / dusk-violet / porcelain），全站颜色走 Tailwind 的 `ink-*` / `amber` / `danger` / `success` / `info`。**本轮不动它。**

### L3 · 闸门 `structureGates ⑨`

> ⑨ 裸色值只许出现在 `lib/palette.ts` 与三处「主题 / 文档定义」

白名单**只有四处**，且各有理由（它们不是在「用色」，而是在「描述一套主题 / 文档」）：

| 白名单 | 理由 |
|---|---|
| `src/lib/palette.ts` | 真源本体 |
| `src/components/CustomThemeDialog.tsx` | 自定义主题预设 —— 作者要自定义的**就是色值本身** |
| `src/lib/theme.ts` | 内置主题注册表 + 换肤预览色块 |
| `src/lib/tavern/exportDoc.ts` | 导出文档自带的内联 CSS —— 必须自洽，**不随 App 主题** |

🔴 判定用**只剥注释、保留字符串**的 `stripComments`：色值恰恰住在字符串里，
若连字符串一起剥（用现成的 `stripCommentsAndStrings`）就等于把要查的东西擦干净 —— **闸会永远全绿**。

## 四、U1 判定不改（豁免，免下轮重复提案）

| 处 | 判定 | 理由 |
|---|---|---|
| `Button.tsx` 的 `text-white`（solid 按钮字色） | **豁免（红线）** | 实心按钮字色**只能固定 `text-white`** —— `ink-*` 是主题变量，浅色主题下翻车。已有 `themeContrast` 闸守着 |
| `bg-black/40`、`bg-black/60` | **豁免** | 是**遮罩层**（modal / 全屏遮罩），语义是「把底下压暗」，与主题明暗无关 |
| `text-white/90`、`/85`、`/70` | **豁免** | 都是**压在图片 / 深色遮罩上的文字**，白字是唯一正确解；换成主题色反而会在浅色主题下看不清 |

⇒ U1 的 12 处**没有一处需要改**。它们之所以被扫描器列为候选，是因为扫描器只认类名、不认语境。

## 五、U3 阶梯落地（2026-10-04 主人拍板「全部采纳」·**已实施**）

`audit-ui` 的判断是对的：某个值出现 8 次 ⇒ 缺的不是「逐个改」，而是**一条阶梯**。命名会占用 Tailwind 已有的数字档（`w-11` 已是 2.75rem=44px），故本轮定下口径：**minWidth/maxWidth/borderRadius 用数字键，spacing 用带单位键**。

| 原任意值 | 出现 | 落地类名 | 配置键（`tailwind.config.js`） |
|---|---|---|---|
| `min-w-[90px]` | 8（4 文件） | `min-w-90` | `extend.minWidth['90']='90px'` |
| `min-w-[200px]` | 2 | `min-w-200` | `extend.minWidth['200']` |
| `max-w-[85%]` | 6（4 文件） | `max-w-85` | `extend.maxWidth['85']='85%'` |
| `rounded-[2px]` | 6 | `rounded-2` | `extend.borderRadius['2']='2px'` |
| `rounded-[3px]` | 6 | `rounded-3` | `extend.borderRadius['3']='3px'` |
| `w-[11px]` / `h-[11px]` | 8 / 7 | `w-11px` / `h-11px` | `extend.spacing['11px']` |
| `w-[14px]` / `h-[14px]` | 5 / 5 | `w-14px` / `h-14px` | `extend.spacing['14px']` |
| `w-[10px]` | 4 | `w-10px` | `extend.spacing['10px']` |
| `w-[128px]` | 2 | `w-128px` | `extend.spacing['128px']` |
| `h-[3px]` / `gap-[3px]` / `mt-[3px]` | 2 / 2 / 2 | `h-3px` / `gap-3px` / `mt-3px` | `extend.spacing['3px']` |
| `pr-[calc(1.5rem+8px)]`、`md:pr-[calc(2rem+8px)]` | 各 2 | **保留为例外** | 与特定 padding 绑定，抽 token 反而更难读 |

**共落地 65 处 / 17 文件**（14 种模式）。低频单次项（`z-[9999]`、`grid-cols-[140px_1fr]`、`max-w-[92vw]`、`leading-[1.9]` 等）一律保留为例外。

⚠️ 落地时**必须实测产物 CSS 含新类** —— 类名写对但 Tailwind 未生成＝样式静默丢失。本轮已用 Tailwind CLI 编译并逐个核过 14 个类（见 §七）。

## 六、后续开发约定（**新代码按这个写**）

1. **要用颜色，先看 `lib/palette.ts`** —— 有就直接引用；没有就先加进去（并在此文档登记），不要在组件里写字面量。
2. **主题色走 `ink-*` / `amber` / `danger` / `success` / `info`**，不要写 `gray-*` / `white` / `black`（遮罩与图上白字除外，见 §四）。
3. 加了裸色值，`structureGates ⑨` 会**当场报出文件与处数** —— 不是"建议"，是闸。
4. **尺寸 / 圆角要新档，走 `tailwind.config.js` 的 `extend`**：数字维度用数字键（`min-w-90` / `max-w-85` / `rounded-2`），`spacing` 必须用**带单位键**（`w-11px`，绕开 `w-11`=2.75rem 冲突）—— 别在组件里写 `w-[11px]`。加了新档要在此文档登记。
