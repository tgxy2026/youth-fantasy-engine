## 1. #013 语义检索 / 向量 RAG 长程记忆（P1）

### 1.1 目标
把「相关章节召回」从**词频/人物共现**升级为**语义召回**：当前章写到什么，就按「意思相近」去全书里捞历史片段、设定条目、事件，再按既有预算机制注入。

> **定位是「补一层」，不是「换掉」**：结构化选材（`aiContext` 的 PRIORITY / 保密等级 / ROW_CAP）继续做主干；语义召回只在 `focusChapterId` 存在时补一条〖语义召回〗段。

### 1.2 现状挂载点（精确坐标）

| 位置 | 现状 | 说明 |
|---|---|---|
| `src/lib/aiContext.ts:757` | `buildProjectContext(opts)` | 上下文总装配，**唯一入口** |
| `src/lib/aiContext.ts:686` | `findRelatedChapters(focusChapterId, limit=8)` | 现有「相关章节召回」——**要被语义版补充/替换**的点。打分＝人物共现 ×2 + 叙事邻接（+2 / +1），按分降序取前 N |

### 1.3 新增模块（建议目录 `src/lib/semantic/`）

```
src/lib/semantic/
  embed.ts      // 嵌入传输（Ollama / OpenAI 兼容两条分支）
  store.ts      // IndexedDB 向量存储 + 增量管理
  chunk.ts      // 切块 + 内容哈希
  recall.ts     // 余弦 + 召回编排
  settings.ts   // 嵌入模型配置读写
```

**`embed.ts`**

```ts
export interface EmbedConfig { type: 'ollama' | 'openai'; baseUrl: string; apiKey?: string; model: string }
export interface EmbedResult { ok: boolean; vectors?: number[][]; dim?: number; error?: string }
export async function embedTexts(texts: string[], cfg: EmbedConfig, signal?: AbortSignal): Promise<EmbedResult>
```
- Ollama 分支：`POST {baseUrl}/api/embed`，body `{ model, input: string[] }` → `{ embeddings: number[][] }`
- OpenAI 兼容分支：`POST {baseUrl}/embeddings`，body `{ model, input: string[] }` → `{ data: [{ embedding }] }`
- 批量上限 32 条/请求；**永不抛**，失败返回 `{ok:false, error}` 便于降级（对齐 `webSearch` 的「永不抛」风格）
- 内部复用 `fetchWithTimeout`，超时建议 30s

**`store.ts`**

IndexedDB 新 store `embeddings`（keyPath `id`），索引 `projectId`、`refKey`：

```ts
interface EmbedRow {
  id: string            // `${projectId}::${kind}::${refId}::${chunkIdx}`
  projectId: string
  kind: 'chapter' | 'summary' | 'setting' | 'kb'
  refId: string         // 章节 id / 卡记录 id / 文档 id
  chunkIdx: number
  text: string          // 原文片段（召回后直接注入，免二次读库）
  hash: string          // 内容哈希，增量判据
  vec: ArrayBuffer      // Float32Array 的 buffer（IndexedDB 原生支持，省空间）
  dim: number
  model: string         // 嵌入模型名 —— 换模型必须整库重建
  updatedAt: number
}
```
API：`putMany` / `getByProject(projectId, kinds?)` / `removeByRef(refId)` / `clearProject(projectId)` / `stats()`。
🔴 **维度守卫**：查询前比对 `model` 与当前配置；不一致 → 视为索引失效，提示「嵌入模型已变更，请重建索引」。

**`chunk.ts`**
- `chunkChapter(content: string, opts?): { idx: number; text: string }[]` —— 按段落聚合到 ~400 字，重叠 80 字（保上下文连续）
- `hashOf(text: string): string` —— 同步 djb2/FNV，避免引入 `crypto` 异步依赖

**`recall.ts`**
```ts
export interface RecallHit { kind: EmbedRow['kind']; refId: string; text: string; score: number }
export function cosine(a: Float32Array, b: Float32Array): number
export async function recallRelevant(query: string, opts: {
  projectId: string; cfg: EmbedConfig; topK?: number; kinds?: EmbedRow['kind'][]; minScore?: number; signal?: AbortSignal
}): Promise<RecallHit[]>
```
流程：`embedTexts([query])` → 取候选 → 余弦 → 排序 → `topK` + 阈值过滤。
**大库优化**：先用 `search.ts` 的 `tokenize` 把候选缩到 N 条 chunk，再算余弦（避免全库逐条点积）。

### 1.4 接入点（改哪里）

1. **`aiContext.buildProjectContext`** 新增选项：
   ```ts
   /** 语义召回：仅在 focusChapterId 存在且索引可用时生效 */
   semantic?: boolean
   ```
   在现有「相关章节召回」之后（`aiContext.ts:841-860`）追加一段：
   ```
   若 semantic 为真：
     hits = await recallRelevant(当前章正文前段/摘要, {...})
     hits 过锚点白名单（idsUpToAnchor）
     push('语义召回', 渲染 hits)
   错误/空 → 静默跳过（不记 dropped，不阻断）
   ```
2. 🔴 **S/D 剔除必须先于切块**：建索引时，D 级整行不切；S 级在**角色视角**下整行不切（复用 `isPrunedForAI` / `isSecretRow` 与 `renderOpts.hideSecretRows`）。**绝不允许先嵌入再过滤**——那等于把 D 级内容送出去了。
3. **索引维护** `rebuildIndex(projectId, opts)`：走 `aiTaskCenter.startTask({ ownerTab, kind: 'semantic-index', writes: ['embeddings'] })`，逐章 embed + 进度回调 + 可中止；增量按 `hash` 跳过未变块。
4. **触发时机**：手动按钮（默认）；可选项「章节保存后自动索引本章」**默认关**（否则每次保存都花嵌入额度）。

### 1.5 界面落点
- **工作面板 → 模型设置**：新增「嵌入模型（可选）」块 —— 从 `providers` 挑选，或填 `baseUrl + model`；存 `meta.aiEmbedding`。未配置 ⇒ 全局「语义检索」开关置灰并注明原因。
- **索引状态**：同一块内显示「已索引 N 章 / M 块 · 模型 X」，旁挂「重建索引」按钮 + 进度条（任务中心进度）。

### 1.6 降级与风险（🔴 逐条）

| 风险 | 处置 |
|---|---|
| 未配置嵌入模型 / 索引为空 / 调用失败 | **静默回退现方案**（关键词 + 结构化选材），功能不阻断、上下文不报错 |
| **保密等级泄漏** | 🔴 S/D 剔除**前置于切块**；单测显式覆盖 |
| 换嵌入模型导致维度不符 | `model` 写进行记录；不匹配即判失效，提示重建 |
| 存储体积 | 1000 章约数千块 ×（1024 维 float32 = 4KB）≈ 十几 MB，可接受；提供「清空索引」 |
| 性能（大库点积） | 关键词粗筛 + `topK` 上限；建索引在任务中心后台跑 |
| 口径合规 | 发给**当前选定的嵌入模型**，与既有口径一致；**不得**宣传「全程本地」 |

### 1.7 单测（新增 `tests/semanticRecall.test.ts`）
1. `cosine` 边界（正交=0、同向=1、零向量不 NaN）
2. `chunkChapter` 覆盖完整且不重复、重叠正确
3. `hashOf` 稳定；内容变则 hash 变（增量判据）
4. **D 级内容不进任何 chunk**、S 级在角色视角下不进 chunk（负面对照：去掉过滤 → 精准变红）
5. `recallRelevant` 在 `embedTexts` 失败时返回空数组且不抛
6. 维度/模型不匹配 → 视为失效

### 1.8 工作量与验收口径
**L**（新增 5 个模块 + 1 个 store + 3 处接入 + 1 处 UI + 1 个测试文件；影响全链路上下文）。

验收：① 配好嵌入模型 → 建索引 → 索引块数 > 0；② 打开某章，上下文「已带入」里出现〖语义召回〗；③ **断开嵌入服务**再跑 → 上下文照常生成、无报错、无〖语义召回〗段；④ 把某个 D 级条目放进设定表 → 检索该内容**召回不到**。

### 2.3 数据结构

新增 `src/lib/aiRouting.ts`：

```ts
export type TaskRole = 'create' | 'review' | 'utility'
```

|---|---|---|

🔴 **分三批迁移**（每批跑全量单测）：① 解析层 + 设置 UI 先行；② `utility` 批（风险最低，批量任务本来就是「便宜模型」场景）；③ `create` / `review` 批。
酒馆链路**不动**（它有三层链与专用就绪判据，`tests/uiUxGuards.test.ts` 已钉住「TavernFree / InterviewChat 不许用全局就绪 Hook」）。

### 2.5 额度的处理（最容易踩的一处）

现状：额度按**单一模型指纹**联动。多用途下必须明确：

- **正文写作额度基准**改为「按 `create` 用途的模型」算（`currentModelAdvice` / `syncWriterBudgetToModel` 内部把 `activeId` 换成 `routing.create || activeId`）。`create` 留空 ⇒ 与现状**逐字一致**。
- 🔴 **各 kind 的系数（`WRITER_BUDGET_KINDS`）一个都不动** —— 它们本来就按任务类型分系数，无需为路由再拆。
- 酒馆额度仍按酒馆链（`defaultProviderId || activeId`）—— 保持现状（老大 2026-10-04 已拍板「保持不变」）。

### 2.6 界面落点
- **模型配置页（`AIConfigPanel`）**：列表行加「用途」徽标（`create`/`review`/`utility`，可能多个）。
- 新增小节「**AI 用途路由**」：三个下拉（创作 / 审校 / 批量整理），选项＝各 provider + **（跟随当前模型）**；改动走 `persist` 同一套「先落盘再 `onChange()`」时序（2.8.0 刚修过的竞态，别退回 fire-and-forget）。
- `AIReadyInfo.label` **保持单值「当前模型」语义不变**（路由只在内部解析）—— 避免连锁改动。

### 2.7 风险
- 路由模型被删 / 被改窗口 → 必须回落到当前模型，且**不弹错**。
- 就绪判据：路由模型不可用时，是「回落」还是「判不 ready」？**定为回落**（宁可退到当前模型，也不让按钮变灰）。
- 调用点漏改 ⇒ 该任务仍走全局模型（**不报错，只是没生效**）—— 迁移清单必须逐条核销。

### 2.8 单测（新增 `tests/aiRouting.test.ts`）
1. 留空 ⇒ 解析结果 === `getActiveProvider()`（零行为变化）
2. 指定 ⇒ 解析到指定模型
3. 指定但 id 不存在 ⇒ 回落当前模型
4. `loadRouting` 空库返回全 `''` 且不写库
5. 三域各调用点走对应 role（源码断言，防回滚）

### 2.9 工作量与验收口径
**S~M**（1 个新模块 + session 加 1 个函数 + 3 批调用点迁移 + 1 处 UI）。

验收：① 三个下拉全留空 → 行为与现在**完全一致**；② 「批量整理」指向便宜模型 → 跑一次 AI 整理，确认请求打到那个模型（看模型名/日志）；③ 删掉被路由的模型 → 该任务回落当前模型且不报错。

## 3. #015 文风指纹（P3）

### 3.1 目标
作者投喂 1~2 段参考文本 → 提炼「文风指纹」（句长分布 / 用词倾向 / 节奏 / 修辞习惯）→ 存为可命名的**文风档**，供伴写 / 续写 / 改写注入。

### 3.2 现状挂载点（底座已齐，不用从零）

| 位置 | 现状 | 复用方式 |

`buildRadarQueries`：组合 `「<题材> <平台> 热门 <年>」` / `「<题材> 网文 趋势」` / 每个 tag 一条 → 去重、上限 6 条（控制成本）。

### 6.4 流程
1. `getSearchSettings()` → `searchBlockedReason()` 提前判定；`mode === 'off'` 或缺 key ⇒ 返回 `{ok:false, error:'未配置联网检索'}`，界面**引导去设置**（不静默失败）。
2. 逐条 `webSearch(q, settings, signal)` → 合并去重（按 url）。
3. `renderSearchResults` → 拼 prompt → AI 归纳（新提示词 `market-radar`，`json: true`、温度 0.3）。
4. 产出 `RadarReport`，**`disclaimer` 必填**；界面展示分区 + 来源链接列表。

### 6.5 界面落点
- **作品信息页页头**加「市场雷达」按钮 → 弹窗：输入预填作品信息已有的题材 / 平台 → 跑（可中止，走 `aiTaskCenter`，kind `market-radar`）→ 报告分区展示 → 可「采纳为标签 / 赛道建议」写回作品信息。
- 四处注册：提示词 `market-radar` + `aiDataSources`（取数＝联网检索结果，非项目资料）+ `AIDataSourceNote`；预算加到 `WRITER_BUDGET_KINDS`（若独立）。

### 6.6 风险（🔴）
- **联网依赖**：无网 / 未配置 ⇒ 明确提示，**不静默失败**、不阻塞其它功能。
- **口径**：报告须标注「来自联网检索 + 模型归纳，供参考」，**不得呈现为确定结论**。
- 🔴 **红线**：**严禁**引导跟风 / 洗稿 / 抄袭 —— 只做「趋势参考」；提示词里明写「只给趋势与机会点，不提供可复制的内容」。
- 成本：6 条检索 + 1 次 AI 归纳，**由用户主动触发**，不做后台自动跑。

### 6.7 单测（新增 `tests/marketRadar.test.ts`）
1. `buildRadarQueries` 去重、条数上限、空输入不崩
2. `mode === 'off'` ⇒ 直接返回 `{ok:false}` 且**不发任何请求**（注入假 transport 断言零调用）
3. 检索失败 / 无结果 ⇒ `ok:false` 且带中文原因，不抛
4. `disclaimer` 恒非空
