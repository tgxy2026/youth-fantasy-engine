## 四、🔴 四个「不实测就发现不了」的坑

### 4.1 `min-w-<数字>` / `max-w-<数字>` 在 v4 会落到 spacing 倍数上（**语义静默改变**）

产物实测：
```css
.min-w-90{min-width:calc(var(--spacing) * 90)}   /* = 22.5rem = 360px，而 v3 的 min-w-90 是 90px */
.max-w-85{max-width:calc(var(--spacing) * 85)}   /* = 21.25rem = 340px，而 v3 是 85%      */
```
v4 **没有** `minWidth` / `maxWidth` 这两个 theme 命名空间，数字键会落进 spacing 阶梯。
⇒ 16 处调用点改成显式任意值 `min-w-[90px]` / `min-w-[200px]` / `max-w-[85%]`（版本无关，最稳）。

**对照：**`rounded-2/3`（`--radius-*` 命名空间存在，实测 `border-radius:var(--radius-2)`）、
`w-11px`/`h-3px`/`gap-3px`（`--spacing-*` + 带单位键，实测取值正确）**都正常**，
所以只有 min/max 这一组需要动。

### 4.2 🔴🔴 v4 的自动源探测范围**远大于** v3 的 `content` 白名单

**现象**：`src/` 里早已没有任何 `min-w-90`，产物 CSS 却重新生成了它（还带着上面那个错值），
且 CSS 从 63 kB 涨到 **103 kB**。

**根因**：v3 的 `content` 是显式白名单（`./index.html` + `./src/**/*.{ts,tsx}`）；
v4 默认**扫描整个项目**（只排除 `.gitignore` 命中项）⇒ 下面这些都会被当类名候选：
- `docs/*.md`、`.workbuddy/memory/*.md`（**文档正文里写着 `min-w-90` 这类历史类名**）
- `.workbuddy/tmp/verify-clone-*/`（**一个历史克隆副本，里面有整套旧源码**）

**修法**（`src/index.css` 顶部）：
```css
@import "tailwindcss" source(none);
@source "../index.html";
@source "./**/*.{ts,tsx}";
```
改完：3 条假规则全部消失，CSS 回到 101 kB。
> 教训：**这一条在 v3 时代不存在**（白名单天生收口），是 v4 引入的新风险面。
> 只要仓库里还有任何「含类名字符串的非源码文件」，就会静默生成垃圾规则。

### 4.3 `rounded-sm` / `backdrop-blur-sm` 的档位被 v4 整体下移了一格（**值真的变了**）

v4 的尺度整体改名：`rounded → rounded-sm`、`rounded-sm → rounded-xs`（同族还有 shadow / blur / drop-shadow）。
但**实测**下来本项目受影响极小：

| 类名 | 用量 | v4 是否仍生成 | 结论 |
|---|---|---|---|
| `rounded` | 229 | ✅ 生成，`border-radius:.25rem`（**同 v3**） | 无需动 |
| `shadow` | 2 | ✅ 生成（同 v3 值） | 无需动 |
| `blur` / `backdrop-blur` | 3 / 10 | ✅ 生成，`blur(8px)`（同 v3） | 无需动 |
| `outline-none` | 124 | ✅ 生成，`outline-style:none` | 语义即「去掉默认轮廓」，设计另有 focus ring ⇒ 符合原意 |
| `rounded-sm` | 1 | ⚠️ `--radius-sm` = **0.25rem**（v3 的 sm 是 0.125rem） | 改 `rounded-xs`（=0.125rem）保值 |
| `backdrop-blur-sm` | 1 | ⚠️ `--blur-sm` = **8px**（v3 的 sm 是 4px） | 改 `backdrop-blur-xs`（=4px）保值 |
| `shrink` | 0（源码里没有） | ❌ 未生成（v4 移除了裸 `shrink`） | 无害：`flex-shrink:1` 本就是默认值 |

⇒ 只有 **2 处**需要动，都已改并复验变量值。

### 4.4 注释里写 `*/` 会提前闭合 CSS 注释（自伤）

可可第一版注释写了 `.workbuddy/tmp/verify-clone-*/` 与 `./src/**/*.{ts,tsx}` ——
其中的 `*/` 会**提前闭合注释**，后面的中文变成 CSS 内容 ⇒ `CssSyntaxError: Unknown word`。
⇒ 注释里描述路径通配要避开 `*/` 序列（写成 `.workbuddy/tmp/` 下的历史克隆目录 这种说法）。

## 五、与 v3 的等价性核对（selector 级 diff）

写了个对比工具 `.workbuddy/tools/tw4-css-diff.cjs`（**用 postcss 真解析**，别自己正则切花括号 ——
v4 把工具类包进 `@layer utilities{…}`，嵌套会骗过朴素解析，首版因此误报 174 个「缺失」）。

**结论**：

| 类别 | 内容 | 判定 |
|---|---|---|
| A. 基线有、新产物没有 | `container` / `ring` / `ring-1` / `min-w-90` / `min-w-200` / `max-w-85` / `shrink` | 全部良性：`container` 是 v3 把 `exporter.ts` 里 XML 字符串中的单词误当类名生成的**假工具类**；`ring`/`ring-1` 实际都在（v4 合并成选择器列表，工具首版漏判）；其余是**有意改名** |
| B. 同名但声明不同 | 逻辑属性（`margin-inline`/`inset-block`）、变量间接引用（`var(--radius-*)`/`var(--container-*)`）、
`translate/rotate/scale` 改独立属性、`animation:var(--animate-*)` | **等价写法**，非值变化 |
| C. 新产物独有 | v4 主题变量 + `@property` 声明 | v4 正常产出 |

**逐项复核过的关键值**：`--radius-2:2px` ✅、`--radius-3:3px` ✅、`--text-9:9px` ✅、
`--color-ink-900:rgb(var(--ink-900))` ✅、`--spacing:.25rem` ✅、`--radius-xs:.125rem` ✅、`--blur-xs:4px` ✅。
