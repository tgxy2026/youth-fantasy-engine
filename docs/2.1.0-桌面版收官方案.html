根因：同一条工具条上，其它按钮用的是「工具条规格」手写 class，而重置按钮用了 Button 组件的标准尺寸 variant="secondary" size="md"，自然比旁边大一整圈。

改动前后

// 改前 —— 标准按钮尺寸，比同行大一圈

// 改后 —— 与同行「精 / 粗 / 绘制地图」逐字一致的规格
<Button variant="bare" onClick={fitView}
        className="inline-flex items-center gap-1 h-7 px-2.5 rounded-md border border-ink-700

        title="重置视图（内容居中）">

为什么不用 variant="ghost" 统一？ 项目红线是「静止无边框的按钮不可用 ghost 表达」——但这里走的是 variant="bare" + 手写 border border-ink-700，静止态有可见边框，与同行按钮同源，合规。
验证：tsc --noEmit 0 错。

② 左下角同步设置窗口为何看不见 —— 已定位

结论：不是功能丢失，也不是数据问题 —— 是 #032 重构把旧入口合并进了新组件，而新组件在「dev 浏览器」环境下必然不渲染。

时间线

阶段左下角是什么dev 浏览器里可见？
#032 之前 桌面版 / 便携版各自的独立入口 否（平台标志不成立同样不渲染）
e1d970b 之后
refactor(#032)		 统一为新建的 DataDock.tsx（数据坞） 否 ← 你看到的现象

根因代码

DataDock.tsx:31-37 用三块平台标志做门控，三块全假时整块 return null：

const showLocal = DESKTOP || PORTABLE   // dev 浏览器：window.electronStore 不存在 → false
const showCloud = CLOUD_FILE_SYNC       // = DESKTOP || PORTABLE（desktopCloudSync.ts:40）
const showWeb   = WEB                   // vite.config.ts 显式注入 false

if (!showLocal && !showCloud && !showWeb) return null   // ← dev 里必然走到这里
关键区分：DESKTOP 是运行时探测（desktop.ts:60 读 window.electronStore），不是构建期常量。所以：
· 打包后的桌面版里它是 true → 正常显示 ✅
· dev 浏览器里它是 false → 整块消失 ❌
源注释写明了这是有意设计（"避免留下一个空面板边框"），但它让 dev 环境永远看不到同步入口。
修法（随第 1 件一起做）：清理掉网页版 / 便携版后，门控只剩单一平台，本来就要重写。顺带引入 dev 判定，让预览环境也能看到数据坞： 
// 清理后：桌面版是唯一目标平台，门控可以彻底简化
// 并让 dev 浏览器也显示（便于界面验证），功能项按能力降级提示
const showDock = DESKTOP || import.meta.env.DEV

🔴 清理时必守的两条红线

  1. tree-shake 门控：项目踩过「组件只在某平台门控分支被引用 → 整模块被摇掉」的坑，约定是"门控须用需该模块的平台并集"。清理后只剩单平台，这个风险反而消失——但每删一块门控都要跑一次 vite build 确认产物没缺页面（曾发生过产物静默缺失）。
  2. server/ 目录与服务器：里面除了网页版后端，还有反馈服务 feedback-server.mjs + systemd 单元 + nginx 配置，线上在跑。删代码库里的目录 ≠ 下线服务器，这两件事要分开决策。

④ 地图列表（多地图）

先看清现状：为什么"只能有一张地图"

// "地图"并不是一个实体 —— 它就是 geography 表的所有行
// 每一行有一个「地图格子」列，存序列化格坐标："gx,gy;gx,gy;…"
row.data['地图格子']   // ← 这就是一张"图"的全部数据

// 而编辑器把**整表所有行**画进同一个坐标系：
const G = 36                        // 格子屏幕边长
const [cellKm, setCellKm] = useState(1)
db.setSetting('geoMapCellKm', n)    // 格档：项目级单个值，全表共用

所以不是"编辑器不给你存第二张"，而是数据层压根没有"地图"这个概念——所有地理条目共享一个坐标系、一个格档。视图坐标 {x,y,k} 甚至不持久化（刷新即重置）。

两个方案

方案 A · 轻量分组 推荐

  • 数据结构：新增项目级 setting geoMaps（[{id, name, cellKm}]）作为地图清单；geography 表新增一列「所属地图」（存地图 id）。
  • 为什么地图清单要单独存：若靠"从行的列值去重"推导，一张图的地点全删光后地图就会凭空消失——清单必须能独立存在。
  • 格档：由项目级单值改为每张地图各自持有（geoMaps[i].cellKm），沿用它现在的语义。
  • 迁移：现有 geography 行全部归入 default 地图（名「默认地图」），格档沿用现值 → 老项目打开后与现在完全一致，零感知。
  • UI：左侧新增地图列表（地图名 + 地点数、新建 / 重命名 / 删除）；右侧画布只画当前地图的行。删除非空地图需二次确认（地点会一并移回默认地图，不删数据）。
  • 工程量：加 1 列迁移 + 编辑器改造；不动 schema 表结构、不加侧栏页签。

方案 B · 独立「地图」表

  • 新建 TabDef：地图（名称 / 格档 / 画布范围 / 备注），geography 用引用列指向它。
  • 优点是结构化、可挂更多字段（画布尺寸、底图、说明）；代价是动 schema.ts 表定义 + 侧栏多一个页签 + 跨表引用校验（dataHealth 的悬空引用检查要认这张表）。
  • 适合"地图要当正式资产维护（配底图、配说明、导出）"的诉求。
需要你定的两件事：
① 走 A 还是 B？（默认建议 A：改动可控、老项目零感知）
② 一张地点行能否同时属于多张图？（例如"九州图"和"北境详图"都要标同一个城市）——A 方案下这是"单归属"，若要"多归属"就得把「所属地图」改成多值列，复杂度上一档。
