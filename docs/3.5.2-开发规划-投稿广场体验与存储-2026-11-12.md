## 一、版本定位与范围

投稿广场是引擎内的轻量交流社区。3.5.2 以已有浏览、投稿、审核、评论和管理功能好用为目标，同时增强服务端数据保护。暂不增加私信、关注、复杂通知、多层评论或多服务器集群；是否迁移存储根据隔离压测和后续决策确定。网页和桌面按适用能力验收；便携版维持当前不支持广场的边界。

当前已提交 `275a7ec`，本轮修复尚未提交。工作区另有他人的 3.4.3 / 3.5.0 / 3.5.1 文档归档变动，原样保留、未纳入本轮修改。

| P0-2 检查命令泄漏 | `inspect --json` 原样输出 `data`/`normalized`，合成正文与昵称进入 stdout | `inspectCommunity`/`verifyBackup` 默认只返回统计与诊断，内部快照需显式 `includeData`；CLI 不请求；投票/档案/排行错误标签不再使用 uid | 模块与 CLI 的 inspect/verify、JSON/非 JSON、成功/失败输出均用合成正文/昵称/账号标记检查；清单不含正文 |
| P0-3 恢复遗漏新增 | `diffVisibility` 只遍历备份中的帖子；当前新增公开帖不在变化清单，恢复后直接消失 | 双向比较：`would-remove`（当前有、备份无）、`content-changed`；评论/投票/举报/档案/排行当前独有记录计数；默认拒绝，显式接受后才切换 | 新增公开帖 + 评论：拒绝时 live 不变；接受后按预览移除；恢复结果摘要与预览一致；演练 26/26 |
| P0-4 跨进程一致性 | 备份不要求停写、无锁；读取多个文件之间可发生业务写入，混合快照仍报成功 | 备份必须 `--confirm-stopped`；读取前统一记录 8 文件 stat、读取后统一复核，发现变化/新增/消失即 `CONCURRENT_WRITE` 拒绝；恢复切换前再次检查 live 变化 | 两进程强制交错（备份 CLI + 独立写入进程）**4/4**：退出码 1、`CONCURRENT_WRITE`、无正式目录；单进程故障注入同样拒绝 |

### P0 修复的边界

- 一致性边界是「停写快照 + 读取前后文件状态复核」，不是热备、不是跨文件事务、不是断电持久性证明。
- 恢复仍要求停写；备份目录权限、加密、异地副本、定时任务与告警均未在生产启用。
- `atomic.mjs` 未加 fsync；单文件 rename 只证明不会读到半个文件，不证明断电后一定落盘。
