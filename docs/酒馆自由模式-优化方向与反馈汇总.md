## 一、总体架构变动：故事 / 剧本 / 角色 三层树状

### 1.1 三层关系
```
故事（Story）            ← 决定「这个世界什么样」= 世界基本设定
├─ 剧本（Script）×N      ← 决定「这一个场景发生什么事」（故事的子节点）
└─ 角色（Character）×N   ← 归属于某个故事，对话时套用该故事的世界观
```
- **故事与剧本**：父子结构，一个故事下可拥有多个剧本。
- **故事与角色**：角色必须归属于某个故事；故事与故事之间并列（兄弟节点）。
- **剧本与角色**：剧本是场景，角色是参与者；两者都挂在故事下，互不从属。

### 1.2 必要流程（硬性约束）
- 使用「自由对话」**之前，必须先创建故事**并填写整体世界观设定 → 创建故事是必要前置步骤。
- 新建角色卡时**必须选择**该角色属于哪个故事（必填字段，无故事不能建卡）。
- 新建对话时**必须先选故事**，再在该故事拥有的角色下分配参与角色。

### 1.3 树状结构落点
| 区域 | 树结构 |
|---|---|
| 酒馆模式页签顺序 | **故事剧本（原「剧本编辑」，改名）** 在**上**，**角色卡片** 在**下**（09-16 要求对调） |
| 故事剧本页 | 故事（父）→ 剧本（子） 折叠树 |
| 角色卡片页 | 故事（父，并列）→ 角色（子） 折叠树 |
| 自由对话·左侧对话列表 | 故事（父）→ 对话（子） 折叠树 |

## 二、UI 与交互改造清单（09-16 新方向）

### 2.1 页签顺序与改名
- 酒馆模式组内：把「剧本编辑」**上移**到「角色卡片」**上方**。
- 「剧本编辑」页签**改名为「故事剧本」**。

### 2.2 故事剧本页改造（新增「故事」层）
- 顶部新增「故事」层：填写**这个世界的基本设定**（即原角色卡第1章世界设定迁移至此）。
- 故事与剧本父子结构，支持一个故事下多剧本。
- 故事内容支持 **AI 起草 + 对话引导式填写**（沿用既有 `draftScript`/`parseScriptDraft` 思路，扩展到故事层）。

### 2.3 角色卡片改造
- **移除**完整的世界设定（已迁到故事层），**只保留「角色与设定的关系」**这部分，避免重复。
- **新建角色卡必须选故事**（归属）。
- **展现/编辑形式字段化**：由「宽泛标题 + 大段文本框」改为**细化字段填表**。
  - 例：第2章人物档案 2.1 外在，原为一个文本框 → 拆为 `姓名 / 年龄 / 外貌 / …` 等详细字段，并加 **「其他」** 作兜底可填字段（预设未覆盖时用户自补）。
  - 其余章节（内核/语言/关系/做不到/知识边界等）按同类思路字段化。
- 角色卡最下方、记忆之下**新增「日记」窗口**（见 2.5）。

### 2.4 自由对话面板改造
- **角色状态区**：只显示**由 AI 扮演的角色**，不再显示由用户扮演的角色。
- **左侧对话列表**：新建对话先选故事 → 再在该故事角色下分配；对话与其归属故事做**树状折叠**。
- **右侧面板**：不再显示角色当前记忆，改为显示角色**当前状态**（好感、心情等基本信息，即 `vars`）。

### 2.5 日记窗口（角色卡内新增）
- 位置：角色卡最下方、记忆之下。
- 内容：记录角色**每次对话中发生的事件与总结**。
- 关键约束：**日记内容本身不作为原始资料注入 AI 模型**；只提供一个**总结**告诉用户发生了什么，用户可随时回顾。

## 三、记忆与设定整理流程重构（⚠️ 冲突·09-16 为准）

### 3.1 旧流程问题（来自反馈 #3/#4）
- 实时自动整理记忆耗时长、聊天多了频繁触发，拖累体验。
- 多角色分别整理时人物关系不准。

### 3.2 新流程（09-16 决定）
- **删除**「实时记忆整理」与「整理记忆 / 更新设定」按钮及功能。
- **新增「结束本轮对话」按钮**：用户点击后，才触发 AI 进行**记忆整理 + 设定更新**全流程。
- 整理频率：从「对话中实时/频繁」改为「**仅本轮对话结束时一次性**」。

### 3.3 提示词精简要求（09-16）
- 修改 AI 整理记忆 / 更新设定的提示词：在**不遗漏重要信息、不失真**前提下，**描述尽可能精简**，以节省本地算力与上下文字数。
- 与反馈 #3 中「提示词精简」方向一致，并被 09-16 采纳为正式要求。

### 3.4 与昨日反馈的冲突处理
| 昨日条目 | 冲突点 | 09-16 裁定 |
|---|---|---|
| 反馈#3「增量+整体两段式 / 触发灵活化 / 手动触发」 | 09-16 更彻底：**完全取消实时**，不论增量与否，统一「结束本轮对话才整理」 | **09-16 为准**（#3 的触发方式子建议被推翻，仅「提示词精简」子建议保留并采纳） |
| 反馈#4「多角色分别更新记忆关系不准，或放弃该设计」 | 09-16 用「故事归属 + 结束本轮才整理 + 角色状态只显 AI 角色」重构多角色处理，未放弃 | **09-16 为准**（保留多角色，改为结构化归属 + 结束时统一整理） |
| 反馈#5「换记忆整理模型缓解」 | 09-16 未提及；因整理改为低频，「资源占用」压力下降，但换模型仍是可选优化 | **不冲突，留作后续可选**（见第六部分） |

## 四、角色卡新填写格式 + AI 填写提示词（09-16 交付物）

> 本部分在「角色卡系统改造完成后」作为填写规范使用。格式基于 09-16 字段化方向。

### 4.1 角色卡字段结构（新格式 spec）

| 区块 | 字段 | 说明 |
|---|---|---|
| 归属 | 所属故事 | 必填，下拉选已有故事 |
| 角色与设定的关系 | 在世界中的定位 / 与核心设定关联 | 仅保留此部分（世界设定已在故事层） |
| 第2章·人物档案 | | |
| 2.1 外在 | 姓名 / 别名 / 年龄 / 性别 / 身份种族 / 外貌 / 体型 / 衣着 / **其他** | 原大文本框拆分 |
| 2.2 内核 | 性格关键词 / 核心价值观 / 渴望 / 恐惧 / 伤口 / 不肯说的秘密 / **其他** | |
| 2.3 语言 | 口头禅 / 说话风格 / 常用语气 / **其他** | |
| 2.4 关系 | 关系列表（对象+关系+态度，可多条）/ **其他** | |
| 2.5 做不到 | 能力边界 / 不会做的事 / **其他** | |
| 2.6 知识边界 | 不知之事 / 认知范围 / **其他** | |
| 第3章·扮演规范 | 视角 / 底线 / 进度锁 / 尺度 / **其他** | |
| 第4章·示例对话 | 若干条示范（问答对） | |
| 记忆 | 由 AI 在「结束本轮对话」时整理（右侧不显示） | |
| 日记 | 每次对话事件总结（不注入 AI，供用户回顾） | 新增 |

### 4.2 一份填写示例（样例角色「云昭」，演示字段化写法）

- 所属故事：示例故事·云州江湖
- 角色与设定的关系：云州本地出身，受「灵脉枯竭」设定影响，自身灵根受损
- 2.1 外在：姓名=云昭；别名=无；年龄=19；性别=女；身份种族=人族·散修；外貌=清瘦、左眉骨旧疤；体型=中等偏瘦；衣着=灰布劲装、旧皮革护腕；其他=惯用左手
- 2.2 内核：性格关键词=疏离、较真；核心价值观=欠的债必须还；渴望=修复灵根；恐惧=再次连累同伴；伤口=三年前师门被灭；不肯说的秘密=当年逃走时锁了门；其他=无
- 2.3 语言：口头禅=「……再说」；说话风格=短句、少寒暄；常用语气=平；其他=无
- 2.4 关系：对象=师妹阿禾 / 关系=幸存同伴 / 态度=愧疚 protective；对象=用户 / 关系=初识雇主 / 态度=戒备但守约；其他=无
- 2.5 做不到：能力边界=灵力仅够自保；不会做的事=见死不救；其他=无
- 2.6 知识边界：不知之事=皇室秘辛；认知范围=云州周边；其他=无
- 第3章：视角=第一人称；底线=不主动害人；进度锁=初遇用户；尺度=普通；其他=无
- 第4章：示例对话（略，按既有格式）

### 4.3 AI 填写角色卡提示词（系统/internal 用）

```
你负责为新角色卡各字段填写内容。严格遵守：
1. 每个字段只写要点，用短语或短句；禁止散文体、禁止修饰性废话、禁止重复或冗余描述、禁止过度修辞。
2. 信息必须准确、可操作，能直接指导扮演；不写「他是一个……」式开场白，直接给属性值。
3. 未覆盖的信息归入「其他」字段，不得硬塞进无关字段。
4. 语言精简：单字段建议 30–60 字以内，能短则短。
5. 只依据用户提供的素材与所属故事的设定填写，不臆造与故事世界观矛盾的内容。
6. 关系字段用「对象 / 关系 / 态度」三段式逐条列出。
```

## 五、保留的调研建议（09-15，未与 09-16 冲突，可采纳）

> 以下为 09-15 沉浸感调研的 6 条建议，未被 09-16 推翻，可作为后续增强项。

1. **会话时间线 + 时间跳跃**（故事感 ★★★★★）：`FreeSession` 加轻量时间轴（第几天/时段/地点）作新层注入 system；扩 R4 元指令 `[[跳过三天]]`/`[[翌日清晨]]`。空层不占额度；别每轮强制报时。
2. **情节推进器**（故事感 ★★★★☆）：低冲突超 N 轮时，输入区上方给 `TavernEchoHints` 式提醒，作者点才进上下文；复用 `TavernDirectorNote`；不替用户写对白；可关。
3. **记忆分层**（一致性 ★★★★☆）：`summarize.ts` 拆事件/关系/主题三层；`parseMemoryText(…,limits)` 已支持分块。⚠️ 与 09-16 不冲突——可成为「结束本轮对话」整理时的内部格式。
4. **环境感官描写强化**（沉浸感 ★★★☆☆）：协议/角色卡指引补「非对白括号至少含一处环境感官」；system 常驻场景氛围词。
5. **本场目标进度可视化**（故事感 ★★★☆☆）：剧本六栏「目标/不要发生」做成状态栏 checklist，复用 `vars` 写入关口。
6. **防 Yes-Man / 允许角色有坏日子**（一致性 ★★★☆☆）：角色卡示例对话补指引「Ta 不必总同意你」；纯提示词技巧。

**避坑（仍有效）**：数值化关系温度（红线禁）/ VN 立绘随情绪切换（写作工具非 Galgame）/ 重型向量 RAG（本地 27B 提示词级够）。

## 六、测试反馈归档（09-15 实测，原样保留 + 冲突标注）

### 反馈 #1　控制面板上下文预算与用量明细不一致
- 现象：控制面板上下文预算改 32000，用量明细仍显 24000。
- 待排查：显示计算异常？还是配置未生效？
- 状态：未解决，待查 `用量明细` 计算逻辑。

### 反馈 #2　本场数值在多角色+用户扮演其一时不显示
- 现象：只看到角色/关系/雷/纪念日/待办，看不到好感/信任/剧情节点。
- ⚠️ 冲突·09-16 为准：09-16 明确「角色状态只显示 AI 扮演角色」——故用户扮演的角色其数值不显示属预期；多角色+用户扮演其一 → 仅显示另一 AI 角色的数值。#2 疑问由此解答。

### 反馈 #3　记忆整理耗时长/频繁触发（合并 22:13/17/20）
- 原建议：触发灵活化 / 提示词精简 / 增量+整体两段式。
- ⚠️ 冲突·09-16 为准：09-16 取消实时整理，改为「结束本轮对话」一次性整理；仅「提示词精简」子建议被采纳。

### 反馈 #4　多角色分别更新记忆关系不准
- 原态度：需解决，否则放弃该设计。
- ⚠️ 冲突·09-16 为准：保留多角色，用「故事归属 + 结束本轮才整理 + 角色状态只显 AI 角色」重构。

### 反馈 #5　考虑换「记忆整理模型」缓解资源占用
- 想法：控制面板已区分日常模型与记忆模型，换记忆模型能否减占用、提效果。
- 状态：**不冲突**，09-16 整理改为低频后压力下降，换模型仍可作后续可选优化。
