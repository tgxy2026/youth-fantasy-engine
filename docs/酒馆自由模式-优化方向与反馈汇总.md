## 一、总体架构变动：故事 / 剧本 / 角色 三层树状

### 1.1 三层关系
```
故事（Story）            ← 决定「这个世界什么样」= 世界基本设定
├─ 剧本（Script）×N      ← 决定「这一个场景发生什么事」（故事的子节点）
└─ 角色（Character）×N   ← 归属于某个故事，对话时套用该故事的世界观
```
- **故事与剧本**：父子结构，一个故事下可拥有多个剧本。
- **故事与角色**：角色必须归属于某个故事；故事与故事之间并列（兄弟节点）。
- **剧本与角色**：剧本是场景，角色是参与者；两者都挂在故事下，互不从属。

### 1.2 必要流程（硬性约束）
- 使用「自由对话」**之前，必须先创建故事**并填写整体世界观设定 → 创建故事是必要前置步骤。
- 新建角色卡时**必须选择**该角色属于哪个故事（必填字段，无故事不能建卡）。
- 新建对话时**必须先选故事**，再在该故事拥有的角色下分配参与角色。

### 1.3 树状结构落点
| 区域 | 树结构 |
|---|---|
| 酒馆模式页签顺序 | **故事剧本（原「剧本编辑」，改名）** 在**上**，**角色卡片** 在**下**（09-16 要求对调） |
| 故事剧本页 | 故事（父）→ 剧本（子） 折叠树 |
| 角色卡片页 | 故事（父，并列）→ 角色（子） 折叠树 |
| 自由对话·左侧对话列表 | 故事（父）→ 对话（子） 折叠树 |

## 二、UI 与交互改造清单（09-16 新方向）

### 2.1 页签顺序与改名
- 酒馆模式组内：把「剧本编辑」**上移**到「角色卡片」**上方**。
- 「剧本编辑」页签**改名为「故事剧本」**。

### 2.2 故事剧本页改造（新增「故事」层）
- 顶部新增「故事」层：填写**这个世界的基本设定**（即原角色卡第1章世界设定迁移至此）。
- 故事与剧本父子结构，支持一个故事下多剧本。
- 故事内容支持 **AI 起草 + 对话引导式填写**（沿用既有 `draftScript`/`parseScriptDraft` 思路，扩展到故事层）。

### 2.3 角色卡片改造
- **移除**完整的世界设定（已迁到故事层），**只保留「角色与设定的关系」**这部分，避免重复。
- **新建角色卡必须选故事**（归属）。
- **展现/编辑形式字段化**：由「宽泛标题 + 大段文本框」改为**细化字段填表**。
  - 例：第2章人物档案 2.1 外在，原为一个文本框 → 拆为 `姓名 / 年龄 / 外貌 / …` 等详细字段，并加 **「其他」** 作兜底可填字段（预设未覆盖时用户自补）。
  - 其余章节（内核/语言/关系/做不到/知识边界等）按同类思路字段化。
- 角色卡最下方、记忆之下**新增「日记」窗口**（见 2.5）。

### 2.4 自由对话面板改造
- **角色状态区**：只显示**由 AI 扮演的角色**，不再显示由用户扮演的角色。
- **左侧对话列表**：新建对话先选故事 → 再在该故事角色下分配；对话与其归属故事做**树状折叠**。
- **右侧面板**：不再显示角色当前记忆，改为显示角色**当前状态**（好感、心情等基本信息，即 `vars`）。

### 2.5 日记窗口（角色卡内新增）
- 位置：角色卡最下方、记忆之下。
- 内容：记录角色**每次对话中发生的事件与总结**。
- 关键约束：**日记内容本身不作为原始资料注入 AI 模型**；只提供一个**总结**告诉用户发生了什么，用户可随时回顾。

## 三、记忆与设定整理流程重构（⚠️ 冲突·09-16 为准）

### 3.1 旧流程问题（来自反馈 #3/#4）
- 实时自动整理记忆耗时长、聊天多了频繁触发，拖累体验。
- 多角色分别整理时人物关系不准。

### 3.2 新流程（09-16 决定）
- **删除**「实时记忆整理」与「整理记忆 / 更新设定」按钮及功能。
- **新增「结束本轮对话」按钮**：用户点击后，才触发 AI 进行**记忆整理 + 设定更新**全流程。
- 整理频率：从「对话中实时/频繁」改为「**仅本轮对话结束时一次性**」。

### 3.3 提示词精简要求（09-16）
- 修改 AI 整理记忆 / 更新设定的提示词：在**不遗漏重要信息、不失真**前提下，**描述尽可能精简**，以节省本地算力与上下文字数。
- 与反馈 #3 中「提示词精简」方向一致，并被 09-16 采纳为正式要求。

### 3.4 与昨日反馈的冲突处理
| 昨日条目 | 冲突点 | 09-16 裁定 |
|---|---|---|
| 反馈#3「增量+整体两段式 / 触发灵活化 / 手动触发」 | 09-16 更彻底：**完全取消实时**，不论增量与否，统一「结束本轮对话才整理」 | **09-16 为准**（#3 的触发方式子建议被推翻，仅「提示词精简」子建议保留并采纳） |
| 反馈#4「多角色分别更新记忆关系不准，或放弃该设计」 | 09-16 用「故事归属 + 结束本轮才整理 + 角色状态只显 AI 角色」重构多角色处理，未放弃 | **09-16 为准**（保留多角色，改为结构化归属 + 结束时统一整理） |
| 反馈#5「换记忆整理模型缓解」 | 09-16 未提及；因整理改为低频，「资源占用」压力下降，但换模型仍是可选优化 | **不冲突，留作后续可选**（见第六部分） |

## 四、角色卡新填写格式 + AI 填写提示词（09-16 交付物）

> 本部分在「角色卡系统改造完成后」作为填写规范使用。格式基于 09-16 字段化方向。

### 4.1 角色卡字段结构（已落地版 · 2026-09-16 实装）

**实现方式（关键决策）**：`FreeCharacter` 的第 2、3 章**仍存为十二个字符串字段**，
界面把它按「小项」拆成表格填写，两者靠 `cardFields.ts` 的 pack/unpack 往返。
好处是记忆整理、设定更新、提示词渲染一条都不用改；**认不出来的老内容一律落进「其他」，绝不丢字**。

存进库的文本长这样（一行一项）：

```
外貌：短发，左手腕有道旧疤
穿着：同一件洗旧的灰色围裙
其他：习惯把手插进围裙口袋
```

| 章节 | 字段（路径） | 小项 | 兜底 |
|---|---|---|---|
| 1 | world（角色与设定的关系） | 不拆：世界设定已移到故事层，这里只写角色与世界的关系 | — |
| 2.1 | profile.externals | 称呼 / 性别与年龄 / 外貌 / 穿着 / 随身物件 | 其他 |
| 2.2 | profile.core | 性格 / 在乎什么 / 内在矛盾 / 怕什么 / 眼下想要 | 其他 |
| 2.3 | profile.speech | 句子长短 / 口癖 / 称呼别人 / 情绪外露 | 其他 |
| 2.4 | profile.relations | 与用户 / 与其他角色 / 当前状态 | 其他 |
| 2.5 | profile.cannot | 能力上限 / 性格硬伤 | 其他 |
| 2.6 | profile.knowledge | 不知道的 / 知道的范围 | 其他 |
| 3 | conduct.perspective | 人称 / 能写什么 | 其他 |
| 3 | conduct.bottomLine | 碰不得的话题 / 碰了会怎样 | 其他 |
| 3 | conduct.paceLock | 当前阶段 / 推进速度 / 解锁条件 | 其他 |
| 3 | conduct.rating | 尺度 / 语言界限 | 其他 |
| 4 | examples（示例对话） | 不拆：沿用扮演协议的输出格式 | — |

### 4.2 一份填写示例（样例角色「云昭」，可直接照抄格式）

```
所属故事：云州江湖
world（角色与设定的关系）：云州本地散修，灵根受损，受「灵脉枯竭」影响只能靠接活维生。

externals：
称呼：云昭
性别与年龄：女，19
外貌：清瘦，左眉骨一道旧疤
穿着：灰布劲装，旧皮革护腕
随身物件：一枚断了的师门玉牌
其他：惯用左手

core：
性格：疏离、较真
在乎什么：欠的债必须还
内在矛盾：想回头找师妹，又怕连累她
怕什么：再次害身边的人
眼下想要：凑钱修复灵根

speech：
句子长短：短句，很少超过十个字
口癖：收尾常带一句「……再说」
称呼别人：叫「你」，不叫名字
情绪外露：不外露，气到极点反而平静

relations：
与用户：初识雇主
与其他角色：师妹阿禾——三年前幸存的同伴
当前状态：戒备但守约

cannot：
能力上限：灵力只够自保
性格硬伤：做不到见死不救

knowledge：
不知道的：皇室与守脉宗的秘辛
知道的范围：云州周边与散修圈的传闻

perspective：
人称：第一人称
能写什么：只写她自己的动作与感官，不替用户编排反应

bottomLine：
碰不得的话题：别问三年前师门那晚
碰了会怎样：岔开话题，再问就直接走人

paceLock：
当前阶段：点头之交
推进速度：慢，至少十几次相处才到能托付的程度
解锁条件：她主动说起三年前的事，才算进入下一阶段

rating：
尺度：日常向
语言界限：可带粗口，不带人格羞辱
```

### 4.3 AI 填写角色卡的提示词

> ⚠️ **提示词的真源在代码里，不在本文档**：`src/lib/tavern/draft.ts` → `buildCardDraftSystem()`。
> 这里抄一份是为了让你「读着改」；真正生效的是代码，**两处不一致时以代码为准**。
>
> 🔴 第 2、3 章的小项清单由 `structFieldLines()` **从 `cardFields.ts` 的模板自动生成**。
> 手写一遍迟早和界面对不上（界面加了一格、提示词没提 → 就会出现「界面有这格、AI 从来不填」的怪事）。
> **要加 / 改小项，只改 `cardFields.ts` 一处**，下面这份清单会跟着变。

`buildCardDraftSystem()` 产出的系统提示词（`{{…}}` 是模板自动生成的部分）：

```
你在帮一位小说作者做角色扮演用的角色卡。作者会给一句话想法（可能是一个已有作品里的角色，
也可能是他自己的原创），你按下面的四章模板把它填成一张可直接使用的卡。

〖语言风格 —— 这一条优先于文采〗
- 只写事实与结论：一条一行，主谓宾说清就停。不许抒情、不许散文式烘托、不许形容词堆砌。
- 不许重复：同一件事换个说法再说一遍，是这里最常见的废话。
- 拿不准的栏写「待作者补充」，不要用空话填满。

〖四章各写什么〗
- world（第 1 章 · 世界）：不写世界本身（世界观写在故事层），只写角色与这个世界的关系 ——
  Ta 的身份、处境、常去的地方，以及这个世界怎么影响 Ta。一到三句即可。
- 第 2 章 · 人物档案 与 第 3 章 · 行为规范：每一栏都按小项分条写，一行一项，形如「外貌：短发」。
  不要写成一整段。模板里没有、但又确实该写的，放进该栏的「其他」小项。可用的小项：
{{structFieldLines() 生成，展开见下}}
- examples（第 4 章）：示例对话。见下面的写法要求。

〖第 4 章「示例对话」的写法（必须严格遵守，模型会照它模仿）〗
- 对白：纯文本，不带说话人名字，也不要把名字单独写成一行；
- 动作 / 神态 / 心理：用（）包住；
- 动作、神态、心理与客观环境：全部用全角括号（ ）包住；
- 指代角色一律用「Ta」；
- 写 2–4 组来回，短句为主，别写成小说段落。

〖依据什么写〗
- 作者的想法里点名了某个已有作品的角色 → 按那个角色的公认设定写；细节记不准就写得保守些，
  不要编造具体情节（编错比写少更坏）；
- 原创角色 → 顺着作者给的信息写，别替他定身世、结局、隐藏秘密这类重大设定。

〖长度〗每一栏尽量控制在 120 字以内（examples 除外，它按 2–4 组对话写）。这些内容每轮都进上下文，
写太满会把对话历史挤没。

〖输出格式〗只输出一个 JSON 对象，不要代码块、不要围栏、不要任何解释：
{"name":"…","world":"…","externals":"…","core":"…","speech":"…","relations":"…","cannot":"…","knowledge":"…","perspective":"…","bottomLine":"…","paceLock":"…","rating":"…","examples":"…"}
```

`{{…}}` 展开后（＝ `cardFields.ts` 当前模板，改模板这里就变）：

```
  · externals（2.1 外在）：可用小项 称呼 / 性别与年龄 / 外貌 / 穿着 / 随身物件 / 其他
  · core（2.2 内核）：可用小项 性格 / 在乎什么 / 内在矛盾 / 怕什么 / 眼下想要 / 其他
  · speech（2.3 语言特征）：可用小项 句子长短 / 口癖 / 怎么称呼别人 / 情绪外露程度 / 其他
  · relations（2.4 关系）：可用小项 与用户的关系 / 与其他角色的关系 / 当前关系状态 / 其他
  · cannot（2.5 做不到的事）：可用小项 能力上限 / 性格硬伤 / 其他
  · knowledge（2.6 知识边界）：可用小项 哪些事Ta不知道 / Ta的消息来源 / 其他
  · perspective（视角与人称）：可用小项 人称 / 能写什么 / 其他
  · bottomLine（底线清单）：可用小项 碰不得的话题 / 碰了会怎样 / 其他
  · paceLock（进度锁）：可用小项 当前关系阶段 / 推进速度 / 什么时候能往前走 / 其他
  · rating（尺度）：可用小项 尺度 / 语言界限 / 其他
```

用户侧消息（`buildCardDraftUser`）＝ 作者的一句话想法（经 `promptGuard.authorBlock()` 用随机 nonce 包住）
＋ 可选素材 ＋ 「请按四章模板填写，直接输出 JSON。」

**设定更新（`revise.ts`）走的是另一条提示词**，但刻意要求同一套语言纪律与同一套小项：
「after 必须沿用同一套小项、其余行照抄，**不许把分条改写成散文**」——
否则 AI 一次整段替换，界面上那些小格当场塌成一坨。

> 配套实现：`src/lib/tavern/cardFields.ts`（模板与往返）、`src/components/TavernCardStructField.tsx`（界面）、
> `draft.ts` 的 `buildCardDraftSystem`（起草提示词，清单由模板自动生成的）、
> `revise.ts` 的 `buildReviseSystem`（要求 AI 更新设定时沿用同一套小项）。

## 五、保留的调研建议（09-15，未与 09-16 冲突，可采纳）

> 以下为 09-15 沉浸感调研的 6 条建议，未被 09-16 推翻，可作为后续增强项。

1. **会话时间线 + 时间跳跃**（故事感 ★★★★★）：`FreeSession` 加轻量时间轴（第几天/时段/地点）作新层注入 system；扩 R4 元指令 `[[跳过三天]]`/`[[翌日清晨]]`。空层不占额度；别每轮强制报时。
2. **情节推进器**（故事感 ★★★★☆）：低冲突超 N 轮时，输入区上方给 `TavernEchoHints` 式提醒，作者点才进上下文；复用 `TavernDirectorNote`；不替用户写对白；可关。
3. **记忆分层**（一致性 ★★★★☆）：`summarize.ts` 拆事件/关系/主题三层；`parseMemoryText(…,limits)` 已支持分块。⚠️ 与 09-16 不冲突——可成为「结束本轮对话」整理时的内部格式。
4. **环境感官描写强化**（沉浸感 ★★★☆☆）：协议/角色卡指引补「非对白括号至少含一处环境感官」；system 常驻场景氛围词。
5. **本场目标进度可视化**（故事感 ★★★☆☆）：剧本六栏「目标/不要发生」做成状态栏 checklist，复用 `vars` 写入关口。
6. **防 Yes-Man / 允许角色有坏日子**（一致性 ★★★☆☆）：角色卡示例对话补指引「Ta 不必总同意你」；纯提示词技巧。

**避坑（仍有效）**：数值化关系温度（红线禁）/ VN 立绘随情绪切换（写作工具非 Galgame）/ 重型向量 RAG（本地 27B 提示词级够）。

## 六、测试反馈归档（09-15 实测，原样保留 + 冲突标注）

### 反馈 #1　控制面板上下文预算与用量明细不一致
- 现象：控制面板上下文预算改 32000，用量明细仍显 24000。
- 待排查：显示计算异常？还是配置未生效？
- 状态：未解决，待查 `用量明细` 计算逻辑。

### 反馈 #2　本场数值在多角色+用户扮演其一时不显示
- 现象：只看到角色/关系/雷/纪念日/待办，看不到好感/信任/剧情节点。
- ⚠️ 冲突·09-16 为准：09-16 明确「角色状态只显示 AI 扮演角色」——故用户扮演的角色其数值不显示属预期；多角色+用户扮演其一 → 仅显示另一 AI 角色的数值。#2 疑问由此解答。

### 反馈 #3　记忆整理耗时长/频繁触发（合并 22:13/17/20）
- 原建议：触发灵活化 / 提示词精简 / 增量+整体两段式。
- ⚠️ 冲突·09-16 为准：09-16 取消实时整理，改为「结束本轮对话」一次性整理；仅「提示词精简」子建议被采纳。

### 反馈 #4　多角色分别更新记忆关系不准
- 原态度：需解决，否则放弃该设计。
- ⚠️ 冲突·09-16 为准：保留多角色，用「故事归属 + 结束本轮才整理 + 角色状态只显 AI 角色」重构。

### 反馈 #5　考虑换「记忆整理模型」缓解资源占用
- 想法：控制面板已区分日常模型与记忆模型，换记忆模型能否减占用、提效果。
- 状态：**不冲突**，09-16 整理改为低频后压力下降，换模型仍可作后续可选优化。
