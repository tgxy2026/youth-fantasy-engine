# 3.0 · 主题边框对比度修复（2026-10-10）

> 触发：作者反馈「部分预设主题下，边框颜色不明显」。
> 范围：`src/index.css`（主题变量）＋ 55 个组件（边框类名迁移）＋ `tests/themeContrast.test.ts`（新增双闸）。
> 状态：**已完成**（tsc 0 / eslint 0 / 全量单测 180 全绿 / 真机实测通过）。

---

## 一、根因（两条，各自独立）

### ① `ink-800 / ink-850` 被当成描边色用 —— 浅色主题下等于没画

`ink-800` / `ink-850` 在设计里的职责是**「面」**（`bg-ink-800` 是输入框底、卡片底；248 处），
它**不是描边色**。但全站有 **129 处** 把 `border-ink-800` 当边框 / 分隔线用（另有 5 处 divide）。

浅色主题的两个「面」与页面底几乎同色，于是这些边框在视觉上**完全消失**：

| 主题 | 面板底 ink-900 | 当边框用的 ink-800 | 对比度 |
|---|---|---|---|
| 护眼 eye-care | 241 246 236 | 238 244 233 | **1.02** |
| 羊皮卷 sepia | 246 239 226 | 243 236 222 | **1.03** |
| 青花 porcelain | 242 247 252 | 238 244 250 | **1.03** |
| 桃笺 peach-note | 253 245 245 | 252 246 245 | **1.00** |

> 深色主题下也偏弱（ink-800 vs ink-900 = 1.07~1.22），只是「勉强能看见」，所以反馈集中在浅色系 —— **这正是"部分主题"的来源**。

### ② 描边主色 `ink-700` 本身偏低（1.29~1.46）

`ink-700` 才是全站描边主色（约 740 处引用），修复前各主题与面板底的对比度：

| 主题 | 修复前 | 修复后 |
|---|---|---|
| 暗夜 dark | 1.29 | **1.50** |
| 护眼 eye-care | 1.34 | **1.49** |
| 午夜蓝 midnight | 1.44 | **1.50** |
| 羊皮卷 sepia | 1.42 | **1.51** |
| 暮山紫 dusk-violet | 1.41 | **1.49** |
| 青花 porcelain | 1.39 | **1.50** |
| 松烟墨 pine-ink | 1.46 | **1.50** |
| 桃笺 peach-note | 1.33 | **1.51** |

> 同时顾到「面板套面板」的嵌套面：ink-700 vs ink-850（142 处）与 vs ink-800（139 处）。
> ink-800 那一档下限刻意更松（1.20）—— 该面本身已由「面与面的边界」承载了一层分离。

## 二、修复

| # | 改动 | 量 |
|---|---|---|
| 1 | `border-ink-800` → `border-ink-700`；`divide-ink-800` → `divide-ink-700` | 134 处 / 55 个文件 |
| 2 | 八个主题的 `--ink-700` 按「保持色相、向 ink-600 插值」求解到 **ink-900 对比度 1.50** | 8 处（`src/index.css`） |

**为什么不是删 ink-800**：它作为「面」的用途（248 处背景）是正确且必要的，错的只是把它当描边。
**为什么改 ink-700 而不是新增 `--ink-border`**：全站描边已统一走 ink-700，新增 token 要改 700+ 处调用，得不偿失。

> 🔴 自定义主题（母版派生）**自动受益**：`applyCustomTheme` 运行时从母版读 `--ink-*` 再派生，母版改了它就跟上，无需再改派生算法。

## 三、防回退（新增两道闸，落在 `tests/themeContrast.test.ts`）

原有闸**只判文字**，边框一条都没测 —— 而边框出问题不会报错，在作者惯用的那个主题下也未必看得见。

1. **边框对比度闸**：每个主题都要过三档下限 ——
   `ink-700` vs `ink-900 ≥ 1.45`、vs `ink-850 ≥ 1.35`、vs `ink-800 ≥ 1.20`。
2. **源码闸**：`.ts / .tsx` 里**禁止出现** `border-ink-800` / `divide-ink-800`。
   > 对比度闸只能约束「变量取值」，管不住「类名怎么用」—— 故直接扫源码堵住这条路。
   > ⚠️ 范围只限 `.ts/.tsx`：`index.css` 的注释里为讲清缘由会提到该串，不该被误伤。

闸数：**23 → 32 passed / 0 failed**。

## 四、验收

- **三闸**：`tsc` 0 ／ `eslint` 0 problem ／ 全量单测 **180 全绿**；
- **真机实测**（真 Electron，6 个主题各遍历页面上全部 `border-ink-700` 元素，算「描边色 vs 其实际落地面」的对比度）：

  | 主题 | 边框元素数 | 最低 | 中位 |
  |---|---|---|---|
  | eye-care | 75 | 1.40 | 1.42 |
  | dark | 75 | 1.34 | 1.43 |
  | midnight | 75 | 1.24 | 1.40 |
  | porcelain | 75 | 1.35 | 1.42 |
  | peach-note | 75 | 1.43 | 1.45 |
  | pine-ink | 75 | **1.24** | 1.39 |

  最低的 1.24 出现在「深色主题 + `bg-ink-800` 上的小片」（午夜色 / 松烟墨），与闸里 ink-800 档的 1.20 下限一致。
- **DOM 校验**：改后页面上 `[class*="border-ink-800"]` 命中数 = **0**；`border-ink-700` 的实测颜色与各主题新值逐一吻合
  （dark `rgb(50,50,72)` / eye-care `rgb(196,205,189)` / porcelain `rgb(194,205,217)` / peach-note `rgb(218,199,200)`）。

> 📌 未改动：`ink-800 / ink-850` 作为「面」的取值（248 + 158 处背景）。浅色主题下这两个面与页面底仍很接近 ——
> 但那属于「层级区分 Weak」的另一个话题（面板靠边框识别已足够），本次不扩大范围。
