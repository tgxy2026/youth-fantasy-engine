## 1. 目标与范围（对齐规划书，不扩不缩）

- **目标**：从角色、地点、术语等资料项快速找到相关章节，减少手工搜索往返。
- **范围**：先复用现有数据与检索能力，提供提及结果及章节跳转；名称别名**手工维护**，结果**允许误报**。**不可**在未确认时自动合并同名实体——本方案所有产物均为只读展示，不做任何自动改写/合并。
- **明确不做**：常驻「提及次数」角标、自动实体消歧、跨资料类型聚合视图、语义级提及（先做字面匹配，语义召回留 3.1.x）。

## 2. 方案总览

```
角色卡标题行 / 表格行操作列
        │  新增「提及」图标按钮（放大镜，悬停显现）
        ▼
  MentionPanel（Modal，版式参考 FullTextSearch）
        │  入参：资料名 + 别名（readAliases 现成工具）
        ▼
  lib/search/mentions.ts（新·纯函数域）
        │  直读 getAllChapters() → title/summary/content 逐章匹配
        ▼
  结果列表：章节标题 + 命中次数 + snippet，按卷/章顺序排列
        │  点击
        ▼
  onNavigate('editor', chapterId) 跳转正文（P0-A 已铺好的通道）
```

**三条设计决策**（探查结论支撑）：

| 决策 | 选择 | 理由 |
|---|---|---|
| 别名存哪 | **不新增存储**，复用 schema 已有「别称」字段 + `lib/settings/aliases.ts` 的 `readAliases(tabId, data)` | 角色卡（`一、基础信息::别称`）与表格（`别称`列）早有此字段且带填写指引；`readAliases` 支持顿号/逗号/分号/空白分隔，已有 4 处消费方。零存储改动 ⇒ 不动 DB 版本/迁移/SYNC_STORES/桌面 KEY_PATHS/备份清单，完全避开「改数据结构必问写入侧」风险面 |
| 匹配引擎 | **直读章节正文做 includes 匹配**（新模块），不建倒排索引 | 百万字级 `indexOf` 是原生快速路径（实测量级 ms）；复用 `SearchEngine` 需先 build 全库 tokenize（慢）且有索引滞后；直读天然实时，打开面板即最新 |
| 结果呈现 | Modal 结果面板（参考 `FullTextSearch.tsx:80,122-146` 版式），不做常驻角标 | 两个 Sheet 组件均无 onChange、无数据变更广播；按需计算不落库 ⇒ 无刷新问题、无性能常驻成本 |

## 3. 详细设计

### 3.1 反查模块 `src/lib/search/mentions.ts`（新，纯函数域，不 import components）

```ts
export interface MentionHit {
  chapterId: string; chapterTitle: string
  volumeId?: string            // 供按卷分组（若有）
  hits: number                 // 该章命中总次数（名称+别名合计）
  matchedTerms: string[]       // 命中了哪些别称（用于结果徽标）
  firstSnippet: string         // 首个命中处上下文（复用 search.ts makeSnippet 思路）
}
export async function findMentions(name: string, aliases: string[]): Promise<MentionHit[]>
```

- 入参 `name` 为空则返回 `[]`；别名去重、去空、过滤与 name 相同项；
- 匹配策略：**大小写不敏感的整串包含**（`toLowerCase().includes()`），中文天然整词；英文名过短（≤2 字符）时要求单词边界，避免 `ed` 命中 `edition` 类噪声——误报容忍度内的必要收敛；
- 每章统计：`hits` 累加、`matchedTerms` 记录命中别称、`firstSnippet` 取首次命中前后各 30 字；
- 排序：先按卷序再按章序（项目既有章节顺序），不按命中数——作者找「哪一章写了」，章序比热度更有意义；
- 上限：单资料返回章节数不设硬限（300+ 章项目最坏情况也就全命中，渲染分批见 3.3）。

### 3.2 UI 入口（两处，均为悬停显现的小图标按钮）

| 位置 | 文件 | 挂点 |
|---|---|---|
| 角色卡列表项标题行 | `src/components/world/CharacterSheet.tsx:446-448` | 删除按钮同行的 `flex items-center gap-2` 内，放大镜图标，`opacity-40 group-hover:opacity-100`（与删除按钮同款显隐） |
| 表格设定行操作列 | `src/components/sheets/TableSheetRow.tsx:77-113` | 「打开正文/删除/AI补全」竖排按钮区内，放大镜图标 |

- 表格行取名称：`displayCol` 列值（relations 表用「人物A」——人物关系行天然是两个资料的提及，按钮对该行主名称生效）；
- 角色卡取名称：`rec.name`；别名统一经 `readAliases(rec.tabId, rec.data)`。

### 3.3 结果面板 `src/components/app/MentionPanel.tsx`（新）

- 外容器直接复用 `components/common/dialogs/Modal.tsx`（`align="top" topOffset="12vh" width="xl" bodyClassName="!p-0"`，与 FullTextSearch 一致）；
- 结果项版式复用 FullTextSearch 的 `Button variant="bare"` 行：来源徽标（章节所属卷）+ 标题 + snippet + 回车图标；**额外**显示命中次数徽标与命中别称徽标（`matchedTerms`）；
- 空态：该资料在正文中暂无提及（`EmptyState` 现成组件）；
- 加载态：`LoadingState`；匹配为异步（读全库章节），面板打开即跑；
- 分批渲染：结果超过 50 章时「显示更多」按钮分批（复用 WritingWorkflow 的分批思路），保证 300+ 章项目不卡；
- 点击结果：`onNavigate('editor', chapterId)` 关闭面板跳正文。

- `TableSheetRow` 已有 `onNavigate`（`TableSheet.tsx:39-48` 透传），零改动；
- 新模块 `mentions.ts` 走 `lib/db` 门面读章节（`getAllChapters` 现成），不碰 schema。

## 5. 验收口径

1. 角色卡点「提及」⇒ 列出该角色（含别称）出现的全部章节，点击跳转到对应正文；
2. 表格设定行（术语/地点）同上；relations 行对「人物A」生效；
3. 别名维护：在卡片「别称」字段填「小渊、渊哥」后，正文出现别称的章节能被召回（手工改字段即生效，无需额外配置）；
4. 误报容忍内：子串误命中可接受，但英文短词（≤2 字符）不得制造大量噪声；
5. 性能：300+ 章/百万字项目，打开面板到结果呈现 ≤ 1s（实测记录）；
6. 旧项目/备份/便携版兼容：纯读现有数据，无迁移；
7. 自定义项目模块边界：被隐藏页签的资料（`tabVisible` 为假）不出现入口——沿用页签自身显隐，不另做判断；
8. 门禁：tsc/eslint/四批单测全绿 + 新增负向控制测试。

## 7. 请主人拍板的三个点

1. **入口形态**：悬停显现的放大镜小按钮（与删除按钮同款显隐）是否合适，还是要更醒目的常驻按钮？
2. **relations 行语义**：人物关系行按钮对「人物A」生效、忽略「人物B」，可以吗？（一行两个资料，避免一个按钮语义分裂）
3. **结果排序**：按卷/章自然序（而非按命中热度）——符合「找哪一章写了」的场景，确认？

## 8. 实施修正与实机发现（2026-10-15，晚于上文定稿）

- **拍板 ② 的实际落点修正**：relations 页签不走扁平 `TableSheetRow`，而是 `TableRelationGroups` 文件夹视图（`TableSheet.tsx` 按 `tab.id === 'relations'` 分流）——加在 TableSheetRow 上的入口在该页签是死代码。已把放大镜补到文件夹行卡，入口由 `TableSheet` 透传 `onOpenMentions`。
- **文件夹视图的目标人物**：同一行关系会同时归入 A、B 两人的文件夹。行卡按钮目标取**所在文件夹的人物**（而非恒取人物A）——文件夹语境下这行已按该人归档，一只按钮语义不分裂；若主人要求字面「人物A」，改一行即可。详见实施记录 P1 专段。
- **relations 无「别称」列** ⇒ 关系行入口只按主名称检索，不合并角色卡别称（如实申报的限制，后续增强候选）。
- 实机验证 32 项断言全绿；细节与踩坑记录见 `3.1-开发实施记录-2026-10-15.md` P1 专段。
