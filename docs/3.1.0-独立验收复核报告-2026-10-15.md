## P1：发布前应修复

### R1：云端不可用时，恢复收尾会用陈旧缓存覆盖本机，并删除离线新增章节

位置：`src/lib/db/core.ts:284–287`；关联 `src/lib/sync/syncCore.ts:942–956`。

恢复流程仅阻止“正在同步”，允许处于离线/错误状态时恢复。此时存储包装层将读写切到本机，恢复章节先正确写入本机。但 `persistAfterRestore()` 只判断同步功能是否启用，就在 `flushDesktopCloud()` 后对旧云缓存执行 `overwrite=true` 的全量镜像。

`flushDesktopCloud()` 返回 `Promise<void>`；底层在不可用时可以正常返回，不能据此认定推送成功。旧缓存因此覆盖刚恢复的章节，`mirrorDeleteExtra()` 还会删除旧缓存中没有的本机新增记录，影响超出选中的冲突章节。

**已复现（受控离线注入）**：保持真实存储包装层、恢复流程和镜像函数，仅把云端不可用、flush 正常无结果返回、缓存快照设为旧版。恢复返回 `warnings=[]`，章节正文从应恢复的 `RESTORED SERVER` 退回 `original local`，额外的 `NEW OFFLINE CHAPTER` 消失。

修复建议：明确区分“推送成功”“不可用”“仍有在途推送”等状态；本机回退模式下保留本机为权威，禁止旧缓存全量覆盖/清理。恢复收尾应限定受影响记录，避免单章恢复修改其它项目与记录。

复现：`node .workbuddy/tmp/review-3.1-cloud.cjs`。探针只在打包内存中注入故障状态，不修改产品模块；这是离线故障模拟，不是双设备实机结论。

### R2：恢复期间切换项目，原章节可能被写入另一个项目

位置：`src/lib/db/syncConflicts.ts:65、81–89`；关联 `src/components/app/SyncConflictCenter.tsx` 的可关闭弹窗。

入口先按当前项目验证归属，随后异步建立全项目备份和章节快照。最终写入却重新读取可变的全局 `currentProjectId`，没有验证它仍等于入口项目。弹窗在 busy 时仍可关闭，项目切换可能发生在备份等待期间。

**已复现**：在写入备份载荷的等待点将当前项目由 A 切到 B，恢复不报错，A 的章节被保存为 `projectId=B`，而其 `volumeId` 仍指向 A 的分卷，产生跨项目错配。

修复建议：入口捕获项目 ID 和后端身份，后续全程使用捕获值；写入前再次校验上下文，变化时中止。界面恢复期间应限制关闭和切换，数据层仍需独立保护。

### R3：冲突后的摘要、分卷或顺序修改未被恢复保护识别

位置：`src/lib/db/syncConflicts.ts:77–89`。

冲突后修改检查只比较正文、标题和状态，未比较摘要、分卷、顺序及冲突版本指纹。后面的 `latest.updatedAt` 比较只能检测备份期间的新变化，不能检测恢复开始之前已经发生的变化。最终用整个 server 对象覆盖，丢弃这些后续修改。

**已复现**：冲突后仅修改摘要为 `NEW AUTHOR SUMMARY` 并更新 `updatedAt`，恢复仍成功，摘要被改回 `server summary`。

修复建议：对全部会被覆盖的业务字段或完整版本指纹做一致性检查；若仅恢复正文，则必须明确恢复范围并保留其它字段。保留恢复前备份不能替代“避免无提示覆盖”的保护。

R2/R3 复现：`node .workbuddy/tmp/review-3.1-probes.mjs`。

### R4：纯黑白主题使实心主按钮变成白底白字

位置：`src/index.css:357–370`；关联 `src/components/common/Button.tsx:78–79`。

主按钮真实类名同时包含 `bg-amber`、`text-ink-900`、`hover:bg-amber/90`。黑白主题中 ink-900 为白色；而 `[class*='bg-amber/']` 会无条件匹配 class 字符串中的 hover 变体，静止状态也把按钮背景覆盖为白色。因此“开始生成”“采纳本章”“替换该章正文”等实心主按钮文字不可见。

**已复现（真实浏览器）**：使用真实 Button 组件的服务端渲染结果与本次生产构建 CSS，在隔离 Edge/Chromium 中读取计算样式：文字 `rgb(255,255,255)`，背景 `rgb(255,255,255)`，opacity=1。截图中第一枚按钮只有空白轮廓。

修复建议：直接为黑白主题定义主按钮明确的白底黑字和状态样式，避免用整个 class 字符串中的片段推断当前颜色状态；同时检查主按钮不同变体和伪类组合。

复现脚本：`node .workbuddy/tmp/review-3.1-ui.cjs`。结果：`.workbuddy/tmp/review-3.1-theme-results.json`；截图：`.workbuddy/tmp/review-3.1-theme.png`。该浏览器检查使用生产 CSS 和真实组件，但不是完整应用页面操作。

### R5：恢复落盘失败后仍会自动刷新

位置：`src/components/app/SyncConflictCenter.tsx:81–85`；关联 `src/lib/db/syncConflicts.ts:100`。

底层持久化返回 false 时，恢复函数仅附加“尚未写入磁盘”告警；界面随后仍无条件在 500ms 后 `location.reload()`。本机恢复结果可能只在内存，刷新会使恢复失效，也使用户来不及处理告警。`flushDesktop()` 在写入失败、写锁或已有在途保存时均可能返回 false。

**证据类型：代码路径核实**。已核查持久化失败返回值与界面无条件刷新；本轮未对真实磁盘制造写入故障。

修复建议：以结构化结果区分主操作、云推送、本机落盘和附带统计；没有确认持久化时禁止自动刷新，保留当前状态并提供重试/导出入口。统计告警与落盘失败不应共用一个无法区分的字符串列表决定后续动作。

## P2：功能与显示问题

### R6：短英文名的提及摘要可能展示不符合匹配规则的位置

位置：`src/lib/search/mentions.ts:112–119`。

计数对两字符英文词使用单词边界，摘要位置却重新用无边界的 `indexOf` 查找。同章先出现 `edition`、较远处再出现独立的 `Ed` 时，章命中数为 1，但摘要截在 `edition` 附近，真正的 `Ed` 不在摘要中。

**已复现**：正文 `edition + 90 个分隔字符 + Ed enters`，搜索 Ed 返回 hits=1，但摘要只有 edition 附近文本。另一个改进点是多个别称命中时应按实际位置选择最早命中，而非按查询词排列顺序选择。

修复建议：匹配阶段同时返回有效首次命中的位置和长度，计数、摘要复用同一匹配规则。

### R7：纯黑白主题的禁用按钮仍呈灰色

位置：`src/components/common/Button.tsx:155` 与 `src/index.css` 的 mono 状态覆盖。

通用按钮仍使用 `disabled:opacity-50`，黑白主题没有消除此整体透明度。真实浏览器测得禁用按钮文字原色为黑色、元素 opacity=0.5，白底合成后呈灰色，截图可见。

这与规划要求“禁用状态以线型/图标/文字区分，保持纯黑白”的口径不符。建议改用虚线边框、状态文字等方式，保留原生 disabled 语义。

## 优化空间与范围差异

1. **冲突记录管理**：当前全量读取并渲染记录，无分页/类型筛选、保留期限和大小上限；旧冲突正文会累计增大单文件数据量。建议先提供筛选和体积显示，自动清理政策仍需产品确认。
2. **章节规划板**：更新时间及状态与正文不一致提示尚未补齐；工作面板仍读取整章正文，与规划中的元数据优先策略存在差距。应使用长篇样例测量，再决定数据投影与惰性加载方案。
3. **严格黑白覆盖范围**：实施记录主动保留图谱语义色、图表细线透明度和装饰图案。规划书原要求覆盖应用绘图与交互状态；应把这一范围差异交给用户确认，不能仅因五个常用页面验收通过就认为全部范围已完成。
4. **测试质量**：目前主题单测大量检查变量、类名或规则片段在位，无法覆盖 R4 的实际级联结果；恢复测试主要使用单一内存后端，缺少离线切换、跨项目等待、元数据改动和落盘失败分支。应将本轮复现整理为稳定的行为测试。
5. **发布验收边界**：可可报告明确保留打包版冲突中心 UI 与真实双设备同步待验。本轮也未完成这些场景，当前不应标记“所有发布门槛通过”。非章节原位恢复、版本号开发期保持 3.0.4 等已有取舍不另算缺陷。
