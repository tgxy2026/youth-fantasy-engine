## F-01 · 项目卡片底部按钮偏小

**现状**（`src/components/app/ProjectHub.tsx:626-672`）
- 容器：`grid grid-cols-6 gap-1 w-full max-w-[188px]`（6 个槽 ≈ 每格 29px）
- 6 个按钮全是 `iconOnly size="xs"`，即 **24×24**，图标 14~15

**改法**
1. 六个按钮 `size="xs"` → **`size="sm"`**（`h-8 w-8` = 32×32）
2. 图标：14 → **16**；主键（打开项目）15 → **17**；删除 15 → **17**
3. 容器 `max-w-[188px]` → **`max-w-[236px]`**，`gap-1` → **`gap-1.5`**（6×32 + 5×6 = 222，留 14px 余量）
4. 保持 `grid-cols-6`、不换行、不出卡片（卡片本身 p-5，右列宽度够）

**验证**：桌面实机截「我的作品」1440/1280 两档；断言 6 键同一行、卡片矩形内（`getBoundingClientRect` 右边界 ≤ 卡片右内边）。

## F-02 · 界面缩放控件太长

**现状**（`src/components/app/Sidebar.tsx:388-412`）
- 行1：`界面缩放 + ?` ，右端是「自动」`toggle xs`（h-6）
- 行2：`grid grid-cols-[1.5rem_minmax(0,1fr)_1.5rem]` ⇒ 中间的数字框吃掉全部剩余宽度，条被拉满

**改法（合成一行 + 固定宽度）**
- 行1 只留「界面缩放 + ?」，不再放「自动」
- 行2 改为**一条自适应宽度的胶囊**：`[自动] │ [−] [130] [%] [+]`
  - 全部 `size="xs"`（h-6=24px）⇒ **高度天然对齐**；容器 `h-7 px-2 gap-1`，内部 `items-center`
  - 数字框固定 **`w-11`（44px）**，不再 `minmax(0,1fr)`
  - 整条 `w-fit`（约 150~158px），**不再撑满侧栏**
- 「自动」保留 toggle 选中态；点它仍走 `toAutoZoom()`（切回跟随窗口）
- 保留能力：−/+ 步进（±10）、数字框直接输入（NumberField 的 80~160 钳制不变）、`%` 单位显示

**验证**：桌面实机截侧栏；断言两控件 `offsetHeight` 相等（都 24）、条宽 < 170、侧栏 200 与 224 两档都不换行。

## F-03 · 「AI 伴写」与同组其它项格式不一致

**现状**（`src/components/editor/NovelEditor.tsx:300-360`）
- 它是 `<details><summary>`：`rounded px-2 py-1.5 text-12`，**没有固定行高**、右侧是 `text-10` 状态
- 同组其它项是 `<Button variant="ghost" size="sm" className="w-full !justify-start">`（h-8、px-3、图标 14、整行 hover）

**改法**
1. `summary` 类名向 ghost 行看齐：`flex h-8 w-full items-center gap-2 rounded px-3 text-12 text-ink-200 hover:bg-ink-700`
2. 图标 14 保持、`text-ink-200` 同色；**去掉默认三角**（`[&::-webkit-details-marker]:hidden` + 右侧补一个 `ChevronDown`，展开时旋转）
3. 状态文字（`未配置模型/已开启/已关闭`）仍在右侧，但改成与整行同基线（`text-10 text-ink-500`），不再单独占位
4. **展开区内容不变**（建议长度 / 去 AI 味 / 参考写作规范 / 文风补充 / 总开关），只是缩进对齐到 `px-3`
5. 仍挂在「辅助创作」组内（`companionTools` 位置不动）

**验证**：桌面实机展开「工具」，截「辅助创作」组；断言伴写行的 `offsetHeight` 与其它 ghost 行相同（32）、左边距一致；点开/收起正常，开关仍生效。

## F-04 · 地图默认缩放与区域名字号

**现状**
- 初始视图写死 `{ x: 0, y: 0, k: 1 }`（`useGeoMapModel.ts:55`），而 `fitView()`（:323，按内容外框 +120 padding 算 k）**打开时没被调用** ⇒ 这就是「默认缩放很奇怪」的来源
- 区域名字号在 `GeoMapEditor.tsx:264`：`Math.max(cellKm >= 10 ? 10 : 13, fsBase - depth * 2)`

**改法**
1. 打开地图并拿到 bbox 后**调用一次 `fitView()`**（内容占可视区约 75%~85%），仅当**本次会话还没手动调过缩放**时执行；手动调过则记住并尊重
2. 空图（无任何地点/图形）保持现在的 `k=1`
3. 区域名字号：把「精比例」档的下限抬高（`cellKm >= 10 ? 10 : 13` → 分别 **12 / 15**），并让 `fsBase` 随 `depth` 递减更缓（`- depth * 2` → `- depth * 1.5`）
4. 🔴 **待复现确认**：「粗比例 / 精比例」我按「地图精度档（cellKm 粗/细）」理解；若你说的是「缩放远/近」，那第 3 条改成「字号随 k 反向补偿」（`fontSize = base / sqrt(k)` 之类）。改前我会先在示范项目里复现确认再下手。

**验证**：桌面实机打开示范项目的地图，截「刚打开」「放大两档」「缩小两档」三张；断言首屏内容占可视区比例落在 70%~90%；精比例档区域名 ≥12px。

## F-06 · 网页版侧栏最窄时登出键溢出

**现状**
- 侧栏最小宽度硬值 `minWidth: 200`（`Sidebar.tsx:170`）
- 崩溃点：`Web.tsx` 的 `WebDataBar` 第二行 `[☁ 已用 611.7 KB / 200.0 MB]` + `AccountExit`（`shrink-0` 图标键）
- 200px 时文本放不下，退出键被挤出圆角框

**改法（两条一起）**
1. `minWidth` 200 → **224**（并同步把手柄拖拽下限）
2. 该行改成**真的可收缩**：用量文本 `min-w-0 truncate`，退出键 `shrink-0` 保持可见；
   极窄时文本先缩（必要时退化成 `611.7K/200M` 短写法），**绝不允许按钮出框**
3. 桌面/便携/游客不受影响（`AccountExit` 在 `WEB_CLOUD` 为 false 时返回 null）

**验证**：网页版实机把侧栏拖到最小截一张；断言退出键右边界 ≤ 圆角框右边界；桌面端同样拖到最小不出现新换行。
