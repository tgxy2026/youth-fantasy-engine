这不等于"L5 已验收"。下一轮在**真实浏览器（Edge profile）或桌面安装包**上复验一次即可闭环。

## 6. 另外一条环境观察（不是产品缺陷，但会影响验证）

在旧的 `127.0.0.1` origin 上，此前失败的队列任务残留在 IndexedDB 里，

### L8 是最值得记的一条

它同时解释了两件事：

1. 第一轮把「页面还是旧文案」误判成浏览器强缓存（真实原因是服务端一直给旧 HTML）；
2. **真实部署也会踩**：只要进程不重启，覆盖 dist 之后用户拿到的永远是上一版——
   JS 文件名已变、旧文件已被删，运气好是旧界面，运气差是白屏。

修完后不需要重启服务端：重建 dist ⇒ 下一次请求自动读到新 HTML（本轮就是这样验的）。

# 第三轮：桌面版实机（2026-10-31 08:30–08:50）

目的：`B-1 跨设备接续`需要「一台云端 + 一台本地」，而网页版的第二个 origin 共享服务端数据，
不构成两台设备 ⇒ 必须把桌面进程真跑起来。

环境：`electron .`（本地 `node_modules/electron`）+ 独立 `--user-data-dir`
+ `--no-sandbox` + `env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS`。

## 13. 桌面版抓到两个 P0 —— 都属于"桌面版根本不能用"

| 编号 | 现象 | 根因 | 处置 |
|---|---|---|---|
| **L11** | 桌面进程启动即抛 `ReferenceError: safeStorage is not defined`；因为是 `app.whenReady()` 的同步段，**后面所有 IPC 注册与窗口创建全被跳过** ⇒ 桌面版双击没反应 | `require('electron')` 的解构列表漏了 `safeStorage`（3.3.2 新加的桌面登录要用它） | ✅ 补上并加注释说明为什么会漏 |
| **L12** | 浏览器授权走完后，换令牌那步服务端回 400「缺少授权码」 ⇒ **桌面登录永远不可能成功** | `startLoopbackServer` 的 `onCode` 返回值同时用于「渲染结果页」和「`waitForCode()` 的解析值」，第一版只返回了标题/说明，把 `code` 丢了 | ✅ 返回值带上 `code` |

为什么之前没发现（两个都是同类）：

- `node --check` 只查语法，未定义变量是运行时错误；
- `scripts/verify/desktop-client-332.cjs` 直接 `require('./desktopAuth.cjs')`，测的是**模块本身**，
  不是 `main.cjs` 的装配；
- 从来没真机启动过桌面进程。

⇒ 为此把登录流程抽成 `runDesktopLogin({baseUrl,name,openBrowser})`，并加
`--desktop-auth-selftest=<baseUrl>` 开关（与 `--smoke-test` 同级、跑完即退、不建窗口），
让"装配层对不对"以后能自动化验。

## 14. 桌面登录真机全链路（通过）

```
electron --desktop-auth-selftest=http://localhost:8322
  → 打印 DESKTOP_AUTH_URL http://.../auth/desktop?challenge=...&port=...&state=...
  → 用已登录会话请求该地址（服务端 302 到 127.0.0.1:<port>/callback?code=...&state=...）
  → 回环收到 code → PKCE 换令牌 → safeStorage 加密落盘
  → DESKTOP_AUTH_OK user=live3 persisted=true
```

| 断言 | 结果 |
|---|---|
| 回环端口只绑 `127.0.0.1`、只认 `/callback` | ✅ |
| `state` 不匹配的伪造回调被拒 | ✅ 输出 `DESKTOP_AUTH_FAIL state 不匹配` |
| 令牌文件是**加密二进制**（126 字节，开头 `v10`），不是明文 JWT | ✅ |
| 服务器 origin 单独记在 `desktop-origin.txt`（不含凭据） | ✅ |
| `--smoke-test` 输出 `SMOKE_OK`（L11 修复后） | ✅ |

⚠️ 排障记一笔：Windows 上 `HTTP_PROXY` 会让 curl 把**回环**请求也交给代理（返回 404），
验证时需 `--noproxy '*'`。产品侧不用改（Chromium/系统浏览器对 localhost 默认绕代理），
但以后写这类自检要先想到这一点。

## 15. 顺带纠正一个此前的错误判断

我曾判断「下载为新书不建绑定，所以换设备接着写没有路」。**这是错的**：

绑定存在项目级 `settingsKV`，`exportProject` 会带出去、`importProject` 按新项目 id 写回 ——
所以副本**本来就带着绑定**，接续路径是通的。

真正的问题在别处：带过来的 `baseRevision` 是**源项目当时的**值（实测 9），
而下载的是云端第 10 版 ⇒ 下一次 tick 立刻判"云端有新版本"，弹冲突。

已修（`98277f8`）：下载完成后把基线钉在「刚下载的那一版」。
真机验证：点「下载为新书」→ 新项目绑定 `base = 10`（旧副本仍 9）→ 云端版本仍是 10、无多余推送。

## 17. 做法：让主进程去操作它自己的窗口

自动化工具控制不到 Electron 窗口，但**主进程是那个窗口的宿主**：
`webContents.executeJavaScript()` 能把脚本注入**真实渲染层**（同一份 React、同一份 IndexedDB、
同一条 IPC 与令牌通道），主进程侧再用令牌直连服务器读云端状态做判据。

新增 `electron/syncSelftest.cjs` + 开关 `--desktop-sync-selftest=<服务器地址>`
（与 `--smoke-test` / `--desktop-auth-selftest` 同级，只在显式传参时生效，跑完即退）：

```
electron . --no-sandbox --user-data-dir=<临时> \
  --selftest-user=<一次性账号> --desktop-sync-selftest=http://127.0.0.1:8323
```

注入的脚本只做三件事：读 `document.body.innerText`、派发 `click`、给 textarea 设值并派发 `input`。
**不 import 任何应用模块、不调用任何内部函数** —— 走的全是用户点击的同一条路。
理由是本项目已经吃过 L7 的亏（补丁打在死代码上、单测全绿而线上无变化），
判据必须落在"界面上真的出现了 / 云端真的变了"。

## 20. 两个观察（记录，未改）

- **打开一本已同步的作品会推一个版本**：`touchProject` 会刷新 `updatedAt`（记录「最近打开」），
  自动同步据此判"有改动" ⇒ 云端 revision +1，内容其实一模一样（对象哈希相同）。
  不算错误（内容寻址保证不重复存），但版本号会虚涨；要不要按"内容是否真变"再判一次，等你定。
- **单账号 20 台设备上限会被自检跑满**：每次运行都新建一条桌面会话。所以自检约定用
  **一次性账号**（`--selftest-user=<名字>`，首次自动注册），别拿常用账号跑。
