## 1. ① 可用模型列表加筛选

### 落点（源码实证）
- UI：`components/AIConfigPanel.tsx:651` —— 「从端点获取的可用模型（N 个）」的原生 `<select>`
- 取数：`fetchOpenAIModels()`（:224）→ `lib/aiCore/transport.ts:63` 的 `listOpenAIModels()`（`GET {base}/models`）
- Ollama 侧：同文件另一处 `fetchOllamaModels()`（拉 `/api/tags`），列表形态相同

### 改法
1. 新增一个受控 state `modelFilter: string`（**每处列表各一份**：OpenAI 端点 / Ollama）。
2. 过滤函数（纯函数，放 `lib/` 便于单测）：
   ```ts
   // lib/modelFilter.ts
   export function filterModels(list: string[], keyword: string): string[]
   // 规则：keyword 去首尾空格 → 按空白切词 → 每段都需命中（忽略大小写）→ 空关键词原样返回
   ```
3. UI：列表上方加一行
   `[🔍 筛选模型名] 命中 12 / 共 386` —— 输入即过滤 `<select>` 的 options；
   **命中为 0** 时显示「没有匹配的模型」，且保留下方「手动填写模型名」这条既有退路。
4. 既有提示语「列表较长时可在选择框内直接键入模型名前缀定位」→ 改为指向新的筛选框（**承诺↔实现要一致**）。
5. 选中后**不清空**筛选词（作者可能还要换一个看看），但 `value` 仍绑定 `editing.model` ✓ 不受影响。

### 改动

## 2. ② 颉文姬「编辑」：自定义指令 + 期望字数

### 落点（源码实证）
- UI：`components/JieWenJiEdit.tsx`（5 个按钮 → `setInstruction(ins)`）
- 状态：`components/useJieWenJiModel.ts:275` `const [instruction, setInstruction] = useState('润色')`
- 调用：`useJieWenJiModel.ts:293` → `aiRewritePassage(snapSel, snapInstruction, styleCtx, {signal})`
- 提示词：`lib/aiTasks/jieWenJi.ts:87` 的 `P_rewrite_passage`（**动作纪律写死在这里**）；
  user prompt 里有 `【修改要求】${instruction.trim() || '润色'}`（:319）

### 🔴 关键设计：动作 + 自定义怎么拼（拍板＝并存，动作纪律保留）

现在 `instruction` 就是一个词（「润色」）。改成传**一个结构化要求对象**：

```ts
// lib/aiTasks/jieWenJi.ts
export interface RewriteAsk {
  /** 动作（5 选 1）—— 决定「动作纪律」，仍进【修改要求】首行 */
  action: string
  /** 作者自定义的**具体倾向**（可空）—— 有值时追加在动作之后 */
  detail?: string
  /** 期望字数（可空）—— 仅提示，不做本地校验 */
  targetWords?: number
}
```

拼装（**动作纪律留在系统提示词，不动**）：

```
【修改要求】
润色                      ← action（始终有）
· 作者的额外要求：偏向冷峻克制的叙述，少用形容词，对白不要书面语   ← detail（有才加）
· 目标字数：约 200 字（原文约 50 字，请扩写到这个量级）           ← targetWords（有才加）
```

- 系统提示词 `P_rewrite_passage` **同时加一条**：「作者在『额外要求』里写了什么，就以它为准补充执行；
  但它**不得放宽动作纪律**（如润色仍不得增删情节、扩写仍不得凭空造专名）」—— 这是"并存"的落地保证。
- 🔴 **不预填模板、不记忆**（拍板）：`detail` 每次打开为空；placeholder 给示例
  `例：把语气从平铺直叙改成冷峻克制 / 扩写人物的心理与微表情`。

### UI（`JieWenJiEdit.tsx`，加在 5 个按钮**下方**、执行按钮**上方**）

```
[当前选区]  50 字                            ← 已有，新增「约 N 字」只是复用现有计数
[润色] [扩写] [精简] [改语气] [换视角]        ← 既有 5 个按钮，行为不变
┌ 额外要求（选填）────────────────────────┐
│ [文本框 2 行，placeholder 给示例]        │
│ 期望字数 [ 200 ] 字    ← 数字框（走 NumberField）  │
└──────────────────────────────────────┘
[让颉文姬润色选区]
```
- 期望字数框提示：**留空＝不限**；并旁注「AI 会尽量贴近，实际字数以生成为准」（诚实说明，不承诺精确）。
- 数字输入**必须走 `NumberField`**（项目红线：受控 `type=number` 打不出小数点，2.9.2 审计刚修过同类问题）。

### 改动
| 文件 | 改动 |
|---|---|
| `lib/aiTasks/jieWenJi.ts` | `aiRewritePassage` 签名改收 `RewriteAsk`；`P_rewrite_passage` 加一条"额外要求优先但不得放宽纪律"；user prompt 拼装三段 |
| `components/useJieWenJiModel.ts` | 加 `detail` / `targetWords` state；`runRewrite` 组装 `RewriteAsk` |
| `components/JieWenJiEdit.tsx` | 加文本框 + 数字框 |
| `tests/jieWenJi*.test.ts` | 断言拼装（有 detail / 无 detail / 有 targetWords 三种形态） |

## 3. ③ 颉文姬新增「续写」

### 定位
- 与「续写方向」（`P_continuation_advice`，**只给思路不生成正文**）**并存**，职责不同。
- 与创意写作的整章续写（`rewrite.ts` 的 `continue`）区别：那个是**整章重写级别的续写**；
  本功能是**在当前章末尾往下续一段可指定字数与情节**的轻量续写。

### 结果落点（拍板：建议段）
复用编辑区既有的**建议段机制**（`ADVICE_START` 标记写在原文下方）：
- 🔴 **原文一字不动** —— 与颉文姬一贯立场一致，也比"直接追加"更可回退。
- 生成结果给一个「写入原文下方（建议段）」按钮（与改稿完全同款交互）。

### 资料清单（12 项 → 实现映射）

### 🔴 预算策略（"不静默丢"）
- `buildProjectContext({ budget, onlyTabIds, includeChapterList, focusChapterId })` —— **已有**挑选与超限丢弃机制。
- 界面实时显示：**「预计占用 N 字 / 预算 M 字」**（`ProjectContextResult.chars` 与 `budget`）。
- 超预算被丢的块，用返回的 **`dropped`** 如实列出来（「本次因预算未带入：全书总纲、前 3 章正文」），
  **绝不静默丢**。
- 预算值取 `writerBudgetFor('jieWenji-continue')`（在 `aiWriterBudget.ts` 的 kind 表里加一项）。

### 技术要点
- **必须流式**（`onToken`）：续写动辄几百上千字，非流式会撞总超时墙（项目在整章改写上有同样结论）。
- **新建提示词** `P_continue_passage` + 登记进 `JIEWENJI_PROMPTS`（`:507`）与门面 `PROMPT_ORDER`
  ⇒ 作者可在「模型设置 → AI 提示词」里改（与其它颉文姬提示词一致）。
- 输出：**纯文本**（不是 JSON）—— 长文塞 JSON 会因转义失败（`rewrite.ts` 已踩过，同结论）。
- 取数新增 ⇒ 🔴 **同步 `lib/aiDataSources.ts`**（项目红线：改了 AI 取数必须同步那份声明）。
