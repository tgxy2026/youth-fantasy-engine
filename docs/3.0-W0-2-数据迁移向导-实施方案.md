## 1. 目标

新品牌 3.0 **首启**时，把旧版（`novel-studio`）数据**无损、幂等**地导入到 `%APPDATA%\youth-fantasy-engine`；
并提供「设置 → 数据」的**重新导入**入口（防手滑 / 多 PC）与**卸载旧版**引导。

🔴 **两条关键事实**（决定方案形态）：
1. **桌面模式主数据 = JSON 文件**（`db/core.ts:98` `ops = DESKTOP ? desktopStore : idbOps`），
   IndexedDB 只在 dev / 浏览器用 ⇒ **主库 IDB 桌面下基本为空**，迁移重点是 JSON。
2. 但 `-vec`（向量）与 `-kb`（知识库）是**刻意的独立 IDB**（不进整库 JSON），桌面版也走 IDB ⇒ **必须转库**。
   依据：`docs/3.0-开发方案.md` §3.4；MEMORY「独立 IDB 库刻意不进门面 `lib/db`」。

## 3. 架构（三阶段）

### 阶段 A · 主进程「窗口前复制」（`app.whenReady` 早期，创建窗口之前）
- 探测旧 userData 是否存在且含数据（JSON 或 IDB）；
- **仅当新 userData 的 `IndexedDB\` 目录尚不存在时**（= 全新首启），把旧 `IndexedDB\` 整目录**递归复制**到新 userData。
  - 为什么必须在窗口前：Chromium 的 IDB 是进程内 LevelDB，**运行时替换目录不生效且可能损坏**；
    只有「新 app 还没打开过 IDB」时复制才安全（整目录复制保证 MANIFEST / 文件号一致）。
  - 自写 `readdirSync + copyFileSync` 递归复制（不用 `fs.cpSync` —— 本机曾见它静默杀进程）。
- 记录「待迁移」状态供渲染进程查询。

### 阶段 B · 渲染进程向导（首启弹窗）
1. 查询主进程探测结果；`exists=false` → 静默跳过，一切照旧（**零打扰**）。
2. 弹「发现旧版数据」向导 → 作者点「导入」：
   - **JSON**：主进程读旧 JSON → `app`/`kind` **remap** → 写新 `youth-fantasy-engine-data.json`
     （新文件已存在时按「覆盖 / 跳过」处理）；
   - **IDB 转库**：`novel-studio-vec` → `youth-fantasy-engine-vec`、`-kb` 同理、主库旧库直接 `deleteDatabase`；
   - **profile 复制**：`Local Storage` / `Session Storage` / `Preferences` / `WebStorage` 整体复制；
   - 汇总导入报告（成功 / 跳过 / 失败条数）。
3. 完成后提示「现在可以卸载旧版了」＋「卸载旧版」入口。

### 阶段 C · 幂等重导 + 卸载引导
- 「设置 → 数据」保留「导入旧版数据」按钮（可反复跑，幂等）。
- 「卸载旧版」：按旧 `appId=cn.novelstudio.yfe` 的注册表 `Uninstall` 键定位旧卸载器并拉起；
  找不到则引导用户去「设置 → 应用」手动卸载。

## 5. 🔴 纪律与边界

- **不保留运行时兼容**（§6）：`storeOps` / `desktop` 只认新值；旧值仅在本迁移模块内部被识别并 remap。
- **不自动迁移**：一切由作者在向导里显式点「导入」触发（呼应「AI 只辅助、作者主导」的项目红线）。
- **失败不中断**：个别记录写入失败 → 记日志、跳过、汇总进报告（§3.4 第 4 条）。
- **删除旧库/旧文件前**：只 `deleteDatabase` 旧 IDB（数据已转新库）；**不动**旧 userData 目录本身（留给旧版卸载器清理）。
- 新增能力不落新表 ⇒ 无需动 `EXCLUDED_META_KEYS` / 同步范围。

## 6. 验收

- **单测**：remap 逻辑（`app`/`kind` 命中表 / `generator.app` 中文串**不改**）+ 探测结果整形 + 报告汇总；
  负面对照：注入旧值输入 → 断言 remap 正确。
- **三闸**：`tsc --noEmit` / `eslint src tests` / 全量单测。
- **实机**（真机 + 真 Electron）：旧数据残留 → 新装 → 首启探测 → 一键导入 → 书稿 / 向量 / 知识库 / 酒馆预设到位 → 旧库不再被读。
