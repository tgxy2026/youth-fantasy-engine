## 二、🔴 四个踩坑（前三个是拆分器自己的，第四个是产品侧的真回归）

1. **hook 段起点必须含组件体第一行**：`const { ready: aiReady } = useAIReady()` 在**161 行**（签名 156-160 之后），
   我一开始从 163 起切 ⇒ 所有子组件报 `aiReady` 未定义。**症状很像"漏 import"，其实是行范围错**。
2. **多行 import 里的 `type X` 要剥前缀**：`type ProofreadIssue` 不剥就变成名字 `"type ProofreadIssue"`，
   名字交集永远匹配不上（`ProofreadIssue` / `SettingEntityType` 在 parts 里报未定义）。
3. **默认导出要单独成句**：`HelpPopover` / `AIDataSourceNote` 被写进 `import { }` ⇒ TS2614。
4. 🔴 **替换范围与原文重叠 ⇒ DOM 多包一层**：滚动区的开标签在 HEAD 尾部、闭标签在 TAIL 头部，
   我又自己补了一对 ⇒ 诊室面板被套了两层 `flex-1 overflow-y-auto`。
   **tsc / eslint / 单测全绿**，是**实机指纹的 `scrollChildren: 6 → 1`** 抓出来的。
   落点检查法：`grep -n "<那个 class>" 主文件` 应只出现一次。
   ⇒ 这条本身就是「拆分会静默改结构」的实证，也说明为什么验收必须有实机指纹。

**实机基线怎么来的**：拆分前先跑 `--label=before` 存基线 JSON（`C:/Users/18223/.agent-browser/tmp/shots/fingerprint-jiewenji-before.json`），
拆分后 `--expect=before` 逐字段 diff。判据里的**文本哈希**保证「文案一字不改」，
**滚动区子节点数 / 根子节点数**保证「DOM 层级没被动过」——这两条正好覆盖了拆分最容易出的两类静默错。
