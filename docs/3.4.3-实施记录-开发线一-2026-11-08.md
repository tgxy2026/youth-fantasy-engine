**清单口径**：43 条 registerPrompt 登记 + 10 个未登记 chat() 调用 + 4 条自动静默链整体 + 2 条旁路 + 1 项增强轨新能力；其中 3 条（chapter-rewrite-history / chapter-rewrite-latest / deai-rule）是注入条款随宿主，不独立路由。形态分类由只读盘点逐项定位 chat() 调用点得出，非静态断言。

**三场景结论**：

| 场景 | 结果 |
| --- | --- |
| A 未配置 Agent | 54 个路由功能**全部保底原样**（driver 收到参数与传入深相等）；2 旁路原通道不动；3 注入随宿主；增强新能力跳过留痕（保底轨本就不存在） |
| B 显式选 Agent（手动） | **全部 sync-json（37 项，含酒馆访谈每轮 JSON）跳过留痕** `agent-no-clean-json`；**9 项长文本/多轮可用**（editor-diagnosis、chapter-rewrite、pleasure-check、opening-check、writing-briefing、continue-passage、快照续写、assist-planner、酒馆轮次），message 事件拼装、过程文本隔离；embedding 跳过 `missing-capabilities:embedding`；增强轨产物闭环、订阅口径记账 |
| C 自动链（即使显式选 Agent） | 伴写 ghost / 连写流水线 / 章后整理 / 酒馆轮次链 / 写后设定侦测 / 双触发功能（continuity/ooc/foreshadow/extend-outline/extract-entities）**全部强制保底，Agent 零 session** |

**关键发现（写进 P4 输入）**：

1. 🔴 **§6.A 判断获实证**：Agent 产物语义（事件流 + 文件）与 A 类 JSON 消费结构性不兼容。37 项 sync-json 显式选 Agent 全部跳过留痕 —— 这不是缺陷，是「不压成 ChatDriver」的正确形态。未来若要让审读类走 Agent，须做「产物文件 → 引擎解析」的专门适配（P4 议题），**禁止靠宽松解析再猜一次**。
2. 双触发功能手动场景与自动场景互不串味：手动显式选 Agent → 跳过留痕；自动链 → 强制保底。
3. `testModelCapability` 15s 硬超时 vs Agent `latency=high`：即使未来可路由也必超时，保持保底（清单备注已标）。
4. `market-radar`（webSearch+chat 两段式）可由增强轨 Agent 自带检索承接，属新增能力，不替代现有通道。
5. 旁路（embedding / 模型清单）不经 chat()，Agent 轨永远捞不回；原通道不动，与规划 §5.2「彻底失效」口径一致。

**本轮原型修复（自身缺陷，已复跑全绿）**：router 补 `consumes` 产物形态闸（json-string 硬闸 + text 只拼 message 事件）；manifest 跑法修正增强轨场景 A 预期（新能力保底轨不存在 ⇒ 跳过留痕）与旁路标注（A/C 原通道，仅 B 演示能力闸）。

### 12.2 关键工程口径

- **写入唯一入口是页面内存 store**：桌面主进程和便携服务都不改 JSON；桌面经 `webContents.send` + IPC 回传，便携经队列由页面轮询领取。
- **失败关闭**：未开启连接 → `HOST_DISABLED`；动作未授权 → `SCOPE_DENIED`；非当前打开项目 → `PROJECT_NOT_OPEN`；无同源页面头 → 403；无 Bearer token → 401。
- **幂等账本**：`requestId` 成功 → 直接 replay；处理中 → `DUPLICATE_IN_FLIGHT`；`SAVE_FAILED` / `OUTCOME_UNKNOWN` → 记 `unknown` 并拒绝自动重试；只有确定未写入的失败才允许同 id 重试。
- **归属与并发**：写操作要求目标项目 = 当前打开项目，并用 `captureOwnedOperation` 在每步 I/O 前后核验项目 / 存储空间未切换；正文有未保存草稿（`leaveGuardDirty()`）时拒绝；追加 / 覆盖要求 `expectedUpdatedAt` 一致，冲突回传当前版本。
- **持久化确认**：写后 `flushDesktop` / `flushPortable` 必须成功，并回读 store 校验关键字段；落盘未确认如实报 `SAVE_FAILED`，不谎报成功。覆盖 / 追加前用 `createSnapshot(..., 'ai-rewrite')` 留可恢复版本。
- **授权不写作品数据**：scope / token 存本机 `agent-host.json`（桌面 userData、便携 `data/`），不随整库同步或导出；token 不回传给 Agent，界面只展示路径。
- **首期栏目范围**：只开放 card 型设定栏目（主要角色 / 次要角色 / NPC / 其他设定 / 分卷大纲 / 章节细纲）；表单型母级数据与表格型设定表不进首期写工具。

### 12.8 新增持久数据的默认值 / 迁移 / 回退 / 删除策略

本版**没有改动整库数据结构**：设定卡仍写 `cardRecords`（`id/projectId/tabId/name/data/order/createdAt`），章节仍写 `chapters`（沿用 `saveChapter` / `patchChapter` 与 `syncChapterMaster` 派生台账），写入侧与既有编辑器路径一致。新增的本机文件只有两个：

| 文件 | 位置 | 不存在时 | 迁移 | 回退 / 删除 | 同步 / 导出 |
| --- | --- | --- | --- | --- | --- |
| `agent-host.json` | 桌面 userData / 便携 `<根>/data/` | 视为「未开启 + 空授权」，并生成新 token | 无（`version=1`；升级只补字段，不读旧结构） | 删除即重置连接（需在界面重新开启并重新生成客户端配置）；旧 token 立即失效 | 不进整库、不进云同步、不随「导出全部数据」导出 |
