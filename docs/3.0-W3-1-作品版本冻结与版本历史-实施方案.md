## 一、规格（§10.3 #7 原文要点）

- **对方实现路径**：创作要求确认 → 逐章生成 / 编辑 / 采纳 → **完成检查**（读实际正文长度、章节卡、
  正文完整性，显示与目标字数偏差）→ 审校（问题带章节与证据，**审校记录绑定本次手稿内容指纹**，
  正文改动后需重新审校）→ 缺失章节 / 待处理候选 / 未解决严重问题**阻止发布** → 通过后新增
  **冻结作品版本**，后续修订保留原版 → 导出 Markdown / TXT / JSON。
- **具体功能**：完成检查、内容指纹绑定、发布闸门、冻结版本、版本历史、自动保存、完整备份。
- **本项目结合点**：已有整库备份 / 导出 + 创作轨迹 + 投稿前自检 ⇒ 版本冻结做成「**定稿快照**」，
  与既有备份 / 导出**共用 `StoreOps` 数据契约**。

---

## 二、侦察结论（源码核过，决定设计）

| 能力 | 现状 | 出处 |
|---|---|---|
| **完成检查** | ✅ 已有 —— 「投稿前自检」纯本地统计（行文分布 / 节奏 / 结构），明确不判优劣 | `components/ManuscriptCheckPanel.tsx` + `lib/manuscriptCheck.ts` |
| **发布闸门** | ⚠️ 有零件无组装 —— 投稿预检 / 本章体检 / 优化工单各自成面板，**没有「发版前统一闸门」把缺章 / 空章 / 未收回伏笔摆成一件事** | `PlatformCheckPanel` / `ChapterCheckPanel` / `OptimizeTicketPanel` |
| **内容指纹绑定** | ✅ 底层齐 —— `chapterFingerprint`（含 `updatedAt`，宁严勿松）+ `hashOf`（FNV-1a） | `lib/aiRunLedger.ts` / `lib/semantic/chunk.ts` |
| **冻结版本 + 版本历史** | ❌ 全新 | —— |
| **完整备份 / 导出** | ✅ 成熟 —— `createAutoBackup` / `restoreBackup` / `buildBackupFile`（外置 JSON）/ `exportProject(ProjectBundle)`；`backups`（元数据）＋ `backupPayloads`（载荷）双表 | `lib/db/backups.ts` / `lib/db/projects.ts` |
| **导出 Markdown / TXT / JSON** | ✅ 已有 —— `exporter.ts`（TXT / MD / DOCX / EPUB / 平台粘贴版） | `lib/exporter.ts` |
| **自动保存** | ✅ 已有 —— 桌面端 StoreOps 落盘 | `lib/desktop.ts` |

**⇒ 结论**：W3-1 = **补两块新东西**（作品级指纹绑定、冻结版本＋历史）＋ **组装一块**（发布闸门），
**不重写**完成检查与备份导出。**绝不新建孤立的快照存储** —— 冻结版本本质就是「有名字、有备注、
有指纹、不自动淘汰的一手稿快照」，与 `backups` 表同构。

## 三、设计决策

### 3.1 数据层：**扩展 `backups`，不建新表**

- `BackupKind` 加 `'frozen'`；`backupLimit('frozen')` 返回 `0`（**永不自动淘汰** —— 作者主动留档）。
- `BackupMeta` 加三个**可选**字段：`note?` / `fingerprint?` / `stats?`（只有 frozen 会写；
  旧数据没有即为 `undefined` ⇒ **零迁移**，沿用「加可选字段不加迁移」的既有口径）。
- 新增 `createFrozenVersion()` / `listFrozenVersions()`：前者走 `exportProject`（**带快照**，
  参考资料按作者 `kbInBackup` 开关），后者按 `kind === 'frozen'` 过滤。
- **复用**：`restoreBackup`（回写）/ `buildBackupFile`（外置导出）/ `deleteBackup`（双表删除）/
  `listOrphanBackups`（项目删后的孤儿）**一行不用改**。

🔴 为什么不建独立表：`restoreBackup → applyBundleToProject`（300 行，含 id 重映射 / 先写后删 /
不删快照 / 参考资料条件写入）是**不能重写的核心**；复用它是本项最大的工程收益，也正是 §10.3 #7
「共用 `StoreOps` 数据契约」的字面要求。

### 3.2 纯函数核心：`src/lib/bookVersion.ts`

| 函数 | 职责 |
|---|---|
| `bookStats(chapters, volumes)` | 完成检查的**确定性**部分：总字数 / 章数 / 已写章数 / 空章清单 / 平均字数 |
| `bookFingerprint(chapters)` | **作品级指纹** —— 各章 `chapterFingerprint` 按 `order` 排序拼起来再 `hashOf`；决定「这一版是不是同一版稿」 |
| `evaluatePublishGate(stats, chapters)` | **发布闸门** —— 返回 `{ blockers, warnings }`，每条带人话说明 |

**闸门判据（确定性、零成本、不跑 AI、不读库）**：

| 级别 | 判据 | 理由 |
|---|---|---|
| **blocker** | 全书没有任何正文 | 空书何谈定稿 |
| **blocker** | 存在「有章节行但正文为空」的章 | 对方原文「缺失章节 … 阻止发布」 |
| warn | 存在未分卷章节 | 可能是整理疏漏 |
| warn | 存在整卷零章 | 同上 |

🔴 **闸门不硬拦**：面板显示阻断项，但按钮降级为「**仍要冻结（有 N 项未通过）**」——
作者看到代价后仍可强制冻结（沿用「AI 只辅助、作者裁决」红线；闸门是提示不是锁）。
🔴 **不把伏笔 / 连续性塞进闸门自动跑** —— 那些是既有面板的事，本闸门只做**零成本确定性判据**，
面板另给一句「建议先跑投稿前自检」的指路。

### 3.3 内容指纹绑定（§10.3 #7 的「审校记录绑定手稿指纹」）

- 冻结时把 `bookFingerprint` 写进 `BackupMeta.fingerprint`；
- 历史列表把当前书的指纹与各版本指纹**并排**：一致 ⇒ 「与当前稿一致」；不一致 ⇒ 「当前稿已改过
  （比这一版新）」。这就是对方「正文改动后需重新审校」的落地形态 —— **只标注，不自动重跑**。

### 3.4 UI：`src/components/BookVersionPanel.tsx`（独立组件）

挂 **「创作轨迹」页 header**（与「AI 运行账本」并列 —— 同为「这本书的里程碑 / 留痕」）。
**不塞进 `CheckTools`**（该页已 8 块且被方案点名为拆分对象）。

面板三段：
1. **完成检查**（本地即时算）：字数 / 章数 / 已写 M/N / 空章清单；
2. **发布闸门**：blockers 红行 + warnings 琥珀行 + 全绿态；带「仍要冻结」降级；
3. **版本历史**：每行 = 名称 · 备注 · 指纹短号 · 字数 / 章数 · 时间 · 与当前稿是否一致；
   操作 = 导出外置 JSON / 恢复（二次确认）/ 删除。

### 3.5 顺手：`BackupManager` 加「定稿版本」分组

冻结版本写了 `backups` 表却不在备份管理器显示 = 记录隐身 + 计数失真。故在 `BackupManager` 加一个
折叠分组「定稿版本」（**不设上限**），让数据管理视角也能看到它们。

## 五、验收

- 三道基线：`tsc --noEmit` / `eslint src tests` / 全量单测全绿；
- 单测：闸门判据边界（空书 / 空章 / 未分卷 / 全绿）、指纹稳定性（改一字即变 / 顺序无关）、
  源码闸（不新建快照表 / 复用 exportProject / 闸门不硬拦）；
- 实机（真 Electron）：创作轨迹页 → 打开「定稿与版本」→ 完成检查与闸门渲染 → 冻结一版 →
  历史出现该版 → 指纹标注正确 → 无 JS 异常。

---

## 六、不做（边界）

- ❌ 不新建快照存储表（复用 backups）；
- ❌ 不自动重跑审校 / 不自动重冻结（正文改动只标注指纹不符）；
- ❌ 闸门不硬拦发布（降级为作者确认）；
- ❌ 不改 `ManuscriptCheckPanel` / `PlatformCheckPanel` 的既有结论口径。
