## P4 答疑地基（2026-10-29 起）

规划 §5.3 的链路是「本地检索 → 依据足够才请求模型 → 校验来源引用 → 显示回答 + 原文」。本轮先落**可测的那一半**：模型说了什么算数。

`src/lib/aiTasks/helpAnswer.ts`（新）：

- `buildHelpAnswerPrompt(question, hits)`：只喂本次召回的 3～5 个片段（单段截断 600 字），把一个片段 id 写进提示词，并要求模型只输出 `{answer, sources:[{articleId, sectionId, quote}]}`；没有召回时明确告诉模型「没有任何片段」，不诱导它凭常识答。
- `parseHelpAnswer(raw)`：走 `aiParse` 的 `parsePlainObjectDetailed`（能吃代码围栏与前后废话），缺字段的来源整条丢弃，不留半条。
- `verifyHelpAnswer(value, hits)`：**两道硬闸** —— 来源必须在本次召回里（编 id 不算）；摘录必须在该段原文里逐字出现，且不短于 8 字（「保存」这种两字摘录在任何段落里都能找到，等于没校验）。校验不过一律不给「AI 回答」。
- `HELP_ANSWER_FAILURE_TEXT`：五种失败各有给作者的话，且都写明「已退回手册检索结果」—— 不把技术失败说成「手册没写」（规划 §5.4）。

🔴 这一层**不发起任何模型调用**：调用归属（`scope:'global'`、`projectId:null`）、答疑提示词与创作提示词隔离、额度预算留到接线那一轮，避免在没想清楚归属时先把请求打出去。

## P4 手册资源混版本保护（2026-10-30）

规划 §4.4 原文要求四件事：「手册目录、正文和索引使用同一构建版本；网页残留旧资源导致版本不一致时，
停止据此生成 AI 回答，给出重新加载帮助资源的入口，并保留可读的匹配版本文章。会话旧回答携带当时内容版本，
不能悄悄替换其引用原文。」本轮补齐。

**为什么要独立的构建标识**：`isHelpContentConsistent()` 只能发现**同一次加载内**目录/正文/索引被改动
（它拿模块初始化快照比对）。而「网页缓存旧 index.html、chunk 却已是新版」的不一致发生在**模块之外**——
两边各自内部都自洽，只有跨模块的标识才能发现。

| 层 | 做法 |
|---|---|
| 构建标识 | `vite.config.ts` 生成 `helpBuild = 版本号+启动时刻`：`define __HELP_BUILD__` 进 JS，`transformIndexHtml` 写进 `<meta name="yfe-help-build">`；dev 下 define 不生效，靠 transform 插件补（与 `__APP_VERSION__` 同一坑，注释已写明） |
| 判据 | `lib/help/buildInfo.ts`：`checkHelpBuild()` 比对「外壳 meta」与「包内常量」。**读不到 meta 时按一致处理** —— 桌面版 `file://` 与老 HTML 没有该标记，不能凭缺失判坏 |
| 答疑闸 | `helpAsk` 第一步就查（**在取模型之前**）：混版本 ⇒ 返回独立 `stale`，不发请求；回答返回前再查一次，期间换版本不静默沿用 |
| 版本可追溯 | 每条索引带 `contentVersion`；`answer` 结果带生成时的 `CONTENT_VERSION`，界面显示「只依据内置手册（v2）」，过期时提示重新提问 |
| 入口 | 查手册页顶部横幅 + 问 AI 面板横幅（含两边标识，便于排查），按钮「重新加载帮助资源」= 整页刷新 |
| 文章仍可读 | 横幅只停 AI 回答，手册文章（本次加载的内存里）照常翻阅 |

**证据**：

- `tests/helpBuildGuard` **28/28**（新，已归 B 批）：判据三态（相同 / 不同 / 读不到）、索引同版本、
  答疑闸在取模型之前、stale 不带模型输出、界面入口与措辞、构建侧 define 与 meta 注入
- `scripts/verify/help-build-guard-331.mjs` **20/20**，两条独立路径：
  - **运行期改 meta**（模拟标签页里标识被换掉）：基线提问真的打到假模型端点（计数 +1）⇒ 改 meta 后再问
    **计数不变**（停止生成）⇒ 横幅、入口、措辞齐全 ⇒ 混版本时手册文章仍读得到 ⇒ 点「重新加载」后横幅消失、meta 回到本次构建
  - **服务器发来旧 HTML**（路由拦截 document 请求改写 meta，最接近网页缓存旧页面）：进查手册页**一进来就有横幅**，
    提问同样不请求模型，0 `pageerror`
- 回归：`help-ask-331` 14/14、`help-center-331` 13/13、`assistant-dock-331` 18/18；
  `typecheck`、`lint` 通过；`run-batches` **370/370** 全绿

**未覆盖**：只在开发预览验证（未部署真实网页版，也没有 CDN 缓存场景）；桌面版 `file://` 下 meta 由同一构建注入，
天然一致，因此该判据在桌面版不会触发（也不需要）；索引与正文的「版本」目前同源于一次构建，
无法检出「同一构建内被人为改成不同版本」之外的情形。
