## 1. 需求共识与版本目标

### 1.1 已确认的方向

本方案综合本轮讨论：页面层次、正文空间、角色档案、任务导向导航、品牌特色、多主题、工作现场保留、操作一致性、AI 结果呈现、分阶段帮助、界面密度、反馈机制与完整创作流程验收。

用户已明确选择“专业创作工作台，保留适量幻想与国风特色”，并认可继续围绕效率、舒适度和连续创作体验优化。方案据此采用以下默认决策，实施时无需重新从风格选项开始讨论：

1. 工作区域清楚、安静、耐看；项目管理、引导与空状态承担更多品牌表达。
2. 复用现有技术与业务机制，以公共设计规则和页面布局升级为主。
3. 先完成三个代表页面，再按页面类型推广到全项目。
4. 保留已有功能与用户习惯，新增可选偏好提供默认值和重置入口。
5. 保存、冲突、写入锁、候选过期等业务事实优先于视觉简洁。

### 1.2 作者能够感受到的变化

| 目标 | 典型变化 | 判定方法 |
|---|---|---|
| 更快进入创作 | 打开项目后能直接找到继续写作和最近工作 | 完整任务走查；入口层级与操作次数记录 |
| 正文有充足空间 | 辅助面板按可用宽度调整，常用工具清楚可达 | 窗口矩阵、正文区域测量、真实键入 |
| 资料更易阅读和填写 | 角色摘要清晰，字段分组合理，说明按需展开 | 长字段/自定义字段/无立绘样本走查 |
| 操作更一致 | 同类页面共享页头、搜索、筛选、保存与更多操作位置 | 页面覆盖表和组件规则检查 |
| 工作不中断 | 查阅角色后返回正文，恢复合理的章节、位置与布局 | 导航往返、数据变化、切项目测试 |
| 状态更可信 | 待保存、写入中、成功、失败与冲突准确区分 | 故障注入、实际回读、跨界面一致性检查 |
| 保有品牌个性 | 国风幻想元素集中于品牌区域，内容保持清晰 | 浅/深/黑白主题视觉评审 |

## 4. 视觉与设计规则

### 4.1 品牌使用分区

| 区域 | 设计方式 | 控制要求 |
|---|---|---|
| 品牌展示 | 项目管理页、欢迎、空态、关于页可使用纹样、立绘和封面 | 不遮挡主要操作，不要求装饰资源加载完才能操作 |
| 工作导航 | 轻量品牌标记、清楚分组、稳定选中态 | 不用连续发光/浮动吸引注意；设置和状态入口可达 |
| 核心内容 | 正文、表格、表单、长结果使用稳定、近乎不透明的内容面 | 装饰纹样不得穿透文本与编辑内容；不以背景图承担分组信息 |
| 辅助浮层 | 弹窗、抽屉、帮助统一表面和层级 | 焦点、遮罩和错误提示遵守现有 zLayer 管理 |

保留背景/看板娘开关和原资源。改造背景承载层，让装饰主要出现在内容外缘或品牌区；用户已选择的隐藏状态继续有效。不因“默认好看”重置老用户偏好。

### 4.2 从现有色阶建立语义角色

在现有 `ink-*`、`amber`、`danger/success/info` 上增加一层用途约定，逐步减少组件对色阶含义的猜测。下列角色名为拟定命名，先在样板中验证，再固定：

| 角色 | 用途 |
|---|---|
| surface-app / surface-nav | 应用底与导航底 |
| surface-panel / surface-raised / surface-input | 内容面、浮层、输入区 |
| text-primary / text-secondary / text-muted | 主要、次要、辅助文字 |
| border-subtle / border-control / border-strong | 装饰分隔、控件边界、重要选中边界 |
| action-primary / action-hover / focus-ring | 主操作、悬停、键盘焦点 |
| state-info / state-success / state-warning / state-danger | 信息、完成、待处理、故障 |

实施规则：

- 继续让 CSS 主题变量作为颜色基础，公共组件先迁移，业务页渐进迁移。
- 不做全仓字符串替换；每次迁移同时检查实际背景、透明度叠加和禁用态。
- 装饰分隔线与辨认输入框所需的边界使用不同角色，避免为让所有线条显眼而增加整页噪声。
- 强调色可跟随主题变化，成功/失败仍要辅以文字和图标。
- 图谱类别配色继续由 `src/lib/settings/palette.ts` 及现有图谱模块管理，不用品牌强调色覆盖所有关系语义。

### 4.3 字体、字号与排版

以下为样板初始值，F0/F1 冻结最终值。单位为未加 UI 缩放的 CSS px。

| 角色 | 舒适档建议 | 紧凑档建议 | 规则 |
|---|---|---|---|
| 页面主标题 | 22–24 / 1.35 | 20–22 / 1.35 | 短标题、明确层级，不大面积使用装饰字体 |
| 内容分组标题 | 15–16 / 1.5 | 14–15 / 1.5 | 字重和间距共同区分 |
| 常用操作/字段标签 | 14 / 1.5 | 13 / 1.45 | 避免把高频操作降到 10–11px |
| 列表与表格正文 | 14 / 1.5 | 13 / 1.45 | 长内容能换行或展开，有完整值访问方式 |
| 帮助和次要说明 | 13 / 1.6 | 12–13 / 1.5 | 不仅靠降低对比度弱化 |
| 时间、数量等元信息 | 12 / 1.45 | 12 / 1.4 | 10–11px 仅保留有明确理由的非关键例外 |
| 正文编辑 | 默认候选 18–20 / 1.8–2.0 | 不受密度影响 | 最终由已有字体/字号/页宽设置控制，尊重旧值 |

界面字体与正文字体继续独立；不强制下载大体积字体。编辑器 textarea、测量层、高亮层、ghost 层必须使用同一组字体、字号、行高、字间距、缩进和内边距。不得只改输入层造成光标、选择区或伴写错位。

### 4.4 间距、圆角、阴影和按钮

- 间距建议以 4 为基础阶梯：4/8/12/16/24/32；少量特殊值需有业务原因。
- 页面外边距根据内容宽度分为 12/20/28 左右三个档位，最终以样板实测为准。
- 控件圆角建议 6–8，面板 10–12，弹窗 12–16；胶囊主要用于标签、过滤条件和状态。
- 面板主要靠表面、间距和轻分隔组织；阴影用于弹出层，减少多层大阴影和“卡片套卡片”。
- 主操作采用稳定的实心或高辨识形态；次操作低一级；危险操作不与主要创作操作并列争夺注意。
- 同一区域原则上只设置一个最突出主操作；确需多个并列任务时明确分组。
- 图标沿用 Lucide 与现有 BrandMark，统一常见尺寸和描边；不新增另一套风格相近的图标库。

### 4.5 两档界面密度

新增“舒适/紧凑”应用级偏好。R2 明确缺省规则：**没有合法新密度值时默认紧凑档，新老用户一致；舒适档由作者主动选择。** 不通过书库是否为空、是否导入旧项目或主题键是否存在猜测用户新旧。紧凑档的最终尺寸以现有常见控件为兼容基准，F1 样板冻结；已有字号、UI 缩放和正文偏好不随其变化。初始建议：

| 项目 | 舒适 | 紧凑 |
|---|---|---|
| 常规按钮/输入高度 | 36–40 | 32–36 |
| 常规列表行高 | 40–44 | 32–36 |
| 表格普通行最小高度 | 40 | 32 |
| 面板内边距 | 20–24 | 12–16 |
| 分组间距 | 24 | 16 |

密度只改变界面节奏，不改变正文字号、行距、页宽、项目内容或导出格式；不以 transform/zoom 实现。触摸主要操作建议保留约 44px 热区，图标视觉尺寸与点击热区分离。长文本表格保持可变行高，不能为达到固定密度裁剪数据。

切换密度后保留筛选、选中对象、未保存草稿和滚动锚点；若大表采用虚拟窗口，按当前测高机制使缓存失效并重算，不能沿用旧行高。

### 4.6 主题与可访问性

保留全部预制主题、主题 ID、自定义参数和纯黑白主题独立性。浅色、深色、纯黑白分别校准，不能只在默认主题验收。

本版采用以下设计目标，来源与例外见第 15 节：

- 常规可读文字按至少 4.5:1 检查；符合大号文字定义的标题可采用 3:1。[W3C 文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 识别控件及状态所必需的视觉信息按至少 3:1 检查；纯装饰分隔线不机械套用同一门槛。[W3C 非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- 指针目标以 24×24 CSS px 为最低检查基准；符合间距、行内等例外时逐项记录。平板主操作采用更大的产品设计目标。[W3C 点击目标](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- 键盘焦点可见，不能被固定工具栏/底栏完全遮住；本产品进一步争取让完整控件可见。[W3C 焦点遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)

现有 `themeContrast.test.ts` 对部分弱提示使用较低历史门槛，不能据此宣称符合 WCAG。新规则先识别实际文字用途；应读的说明迁到合格文字角色，装饰元素单独处理，保留例外清单，不直接放宽测试或把所有灰阶一起拉亮。

纯黑白主题继续遵守项目的严格黑白绘图约定，不因新阴影、透明度、渐变或装饰重新引入灰/彩色绘图信息；用户导入的封面、立绘、参考图片保留原内容。自定义主题应校验实际派生色，不用预制主题通过替代自定义验证。

动效建议 120–200ms，仅用于状态和位置变化；尊重减少动态效果偏好。长页面阅读和输入中不使用持续脉冲、大幅位移或重复出现的吸引注意动画。

### 4.7 外观应用与资源加载

- 在第一个可见应用帧前应用已校验的主题、界面字体、缩放和密度，避免先亮后暗、先大后小；读取失败使用稳定缺省，不等待业务库或远端资源。
- 加载中、错误边界、原生 DOM 提示与 Portal 浮层也能读取同一套可用的外观变量，不只改正常页面。
- 沿用现有设置的即时生效方式，不强制添加“预览后确认”步骤。若某个现有弹窗支持预览，取消只能恢复该预览涉及的外观键，不能覆盖同期业务修改。
- 同一应用窗口中的外观入口及时同步；新密度枚举须补通知，不能假定现有仅针对布尔值的广播自动覆盖。跨窗口仅同步适合共享的偏好，不广播光标、筛选和临时草稿。
- 字体缺失、图片加载失败或延迟时有可用回落；正文各测量图层同步重排。等待字体/布局稳定必须可超时并降级，不能因字体服务不可达阻塞编辑。
- 组件样板冻结具体令牌、默认值和例外后再推广。评审每种主题需同时看普通、hover、focus、selected、disabled、error、loading，而不只看静态卡片。

### 4.8 内容极值和实际可读性

统一测试中文/英文/数字混排、长书名和姓名、无空格长串、emoji、空值、0/false、多行、超长帮助、长路径和长模型名。0 和 false 不得被当成“未填写”；省略展示必须可通过点击、聚焦或详情读取完整值，不能只依赖 title 悬停。

字段单位、必填、错误、占位提示和帮助各有明确职责：placeholder 不替代标签，颜色不单独承担错误或选中语义。复制操作复制业务原值或明确约定的内容，不夹带视觉省略号、状态图标、行号和装饰字符。

## 5. 公共布局与组件改造

### 5.1 四类工作布局

| 布局 | 适用范围 | 设计要求 |
|---|---|---|
| 概览布局 | 写作面板、项目管理、报告概览 | 一个主要任务区，辅助统计和提醒分层 |
| 主从布局 | 角色、大纲、设定、剧本、图鉴 | 列表与详情独立滚动，明确选中对象 |
| 数据布局 | 表格、章节总表、清单 | 紧凑工具栏、稳定表头、局部横向滚动 |
| 创作/画布布局 | 正文、对话、地图、情节和关系图 | 最大化核心区域，工具按任务出现 |

上述是布局约定，不要求每类新建一个巨型组件。现有组件能表达的直接复用；确有多处稳定共性才抽取。

### 5.2 公共组件任务

| 任务 | 处理方式 | 要求 |
|---|---|---|
| Button | 优化现有变体、尺寸与焦点；保留合法裸按钮例外 | 不破坏表格微操作、整行选择和内容型按钮 |
| Panel | 增加必要的内容/辅助层级用法 | 允许无边框分组，避免所有区块都套卡片 |
| MasterDetail | 补密度、窄宽度与锚点约定 | 两栏独立滚动；隐藏目录仍有返回入口 |
| 页头/操作栏 | 建议新增轻量 PageHeader、PageActions（拟新增） | 标题、简述、状态、主要/次要操作；允许编辑器特例 |
| 表单分组 | 优先改 SchemaFieldGrid 和现有字段渲染；必要时抽 FieldHelp（拟新增） | 标签可关联、帮助键盘可达、错误靠近字段 |
| 状态标记 | 建议新增展示用 StatusBadge/StatusNotice（拟新增） | 只接收事实，不拥有保存或候选状态机 |
| EmptyState/LoadingState | 区分业务空、无结果、加载、失败 | 每种状态有准确文案和合理操作 |
| Modal/Tooltip/HelpPopover | 沿用现有 Portal、层级、焦点约束 | 不用 hover 作为唯一入口；能关闭和返回原焦点 |

公共组件的 props 保持可理解，避免用几十个布尔值覆盖所有业务。组件展示样本可放在隔离开发夹具中，不向正式导航增加“组件实验室”。不为此引入整套新的文档站或 UI 框架。

### 5.3 滚动与固定区域约定

- 延续 App 主滚动容器与内层 padding 的职责，避免 sticky 表头穿透页头。
- 编辑器、会话、画布等满高布局保持确定高度、`min-h-0` 和可收缩链路。
- 主从双栏各自滚动，切换对象时按对应对象恢复详情位置。
- 表格横向滚动局限于数据容器，不让页面整体横向溢出。
- 弹出菜单使用现有浮层机制或 Portal，避免被工具栏 overflow 裁切。
- 固定输入区和状态栏为内容留出空间；软键盘弹出时输入区与发送按钮仍可达。
- 页面加载、字体加载和帮助展开后，不能通过一次固定延时判定布局永久稳定。

新页头会换行，两档密度也会改变工具栏高度。现有 `theme.ts` 中的 `CARD_SHEET_CHROME_PX`、`OUTLINE_SHEET_CHROME_PX` 等固定扣高值必须列入迁移清单：优先使用确定高度的 flex/grid 分配剩余空间；确需测量时只观察实际占高区域并批量更新。不再为不同标题长度、窗口或密度不断追加固定扣减常数。字体加载、帮助展开和多条横幅出现后，两栏仍可滚动且底部操作可达。

### 5.4 浮层归属、焦点与关闭规则

目前 Modal 的焦点循环主要依据面板 DOM 子树，而 CustomSelect、日历和帮助可能 Portal 到 body。R2 将它们的组合行为列为公共组件必做项，不能只验证每个组件单独能打开。

1. 每个浮层有所属对话框/页面和层级。弹窗内的 Portal 子浮层属于该弹窗的逻辑焦点范围；页面外的下拉不能借高 z-index 压在新确认框之上。
2. 可选择为弹窗提供合适的 Portal 容器，或登记其子浮层归属；F1 比较现有组件兼容性后选择一种主要方式，不同时建立两套互相竞争的焦点管理。
3. 下拉/帮助 → 子弹窗 → 父弹窗按顶部逻辑层消费 Esc；一次按键最多关闭一层。中文输入法选字期间的 Esc/Enter 优先交给输入法，不误关弹窗、提交表单或发送消息。
4. Tab/Shift+Tab 留在当前模态范围内，包括其合法子浮层。只设 aria-modal 不足以防止背景被点击或读屏访问；背景交互隔离与 Portal 归属一起验证。
5. 打开时选择合理焦点；长说明先聚焦标题或合适内容，不强行跳到底部主操作。关闭后回到有效触发器；触发器已卸载时回到当前页面合理入口。
6. 隐藏页头的搜索框/弹窗仍需真实可解析的可访问名称；aria-labelledby 不能指向不存在的节点。折叠、下拉与切换控件提供必要的 expanded/selected 状态。
7. 遮罩关闭、Esc、关闭按钮、业务取消分别沿用允许条件；存在未提交局部编辑时接当前保存/取消逻辑，不以样式统一取消业务保护。

此处采用 [W3C 模态对话框交互模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)作为行为参考。修复 zLayer 应先验证最小组合，不能简单把所有浮层统一抬高或降低。

### 5.5 快捷键与输入设备

快捷键按“输入法处理 → 顶层模态及其子浮层 → 当前编辑控件/页面 → 全局”的职责顺序处理，已消费事件不再触发下层动作。保留现有 Ctrl/Cmd+K、Ctrl/Cmd+S、撤销/重做等习惯，登记实际按键、条件和作用对象，不无故占用系统/浏览器保留组合。

重点检查有脏数据的父页打开另一编辑弹窗时 Ctrl+S 是否保存两处；本版要求只触发当前合适作用域的一次保存。没有待保存内容时继续尊重现有不吞浏览器快捷键的约定。输入法组合态、重复按键和焦点刚恢复时不能触发重复生成、保存、删除或发送。

分栏调宽、列表排序、卡片移动与画布操作分别盘点。分栏现有鼠标处理需要补 Pointer/触摸/笔输入、取消和失焦收尾，并提供可点击的宽度预设/步进或数值入口；键盘可用不等于满足单指免拖拽要求。章节/列表调序提供已有或补充的上移/下移/移动到入口；地图自由绘制等本质操作单列例外，并保留对象列表、缩放/复位入口。

拖拽只在必要手柄范围控制触摸行为，不能阻断整个页面滚动或原生文本选择。核对屏幕坐标、布局坐标、UI 缩放和画布缩放的换算；pointercancel、capture 丢失、切页面和窗口失焦都释放临时状态。文件拖入继续经过现有文件类型判定与导航兜底，不误伤正文选区或章节排序。

参考 [W3C 拖拽替代操作](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)：单指不拖拽替代与键盘支持是分别需要验证的能力，不用其中一项冒充另一项。

## 6. 三个样板页面

### 6.1 写作面板：围绕下一步行动

页面从上到下建议组织为：

1. 项目名/写作面板标题和轻量项目状态。
2. “继续创作”主区域：最近章节、章节状态、最近更新时间和直接进入入口。
3. 今日/近期创作摘要：本日字数、近七日变化、少量关键进度。
4. 需要处理的事项：沿用现有真实数据，区分严重故障、建议与普通提示。
5. 码字日历、分卷进度、章节规划和详细统计。

实施约束：

- 保留现有写作流程、起步清单、字数口径与数据来源，先改排列和展开方式。
- 新项目没有章节时，主区域给出创建/导入章节入口，不显示空洞的“继续写作”。
- 字数口径说明压缩为短提示，详细定义可展开；口径切换保持显式可见。
- 需要处理的事项按严重程度和可行动性排序，不把普通“未回收伏笔数量”一概做成错误警报。
- 大统计区可折叠并记忆，不能让重要写入故障折叠在统计卡里。
- 自定义项目未启用的功能不产生失效入口和虚假的缺失提醒。

验收：进入已有项目能定位继续创作；进入空项目有有效起步；统计与原数据一致；折叠无布局跳变；异常状态不被普通统计淹没。

### 6.2 正文编辑器：普通写作也舒适

#### 空间分配

在保留现有列宽拖拽和正文保底逻辑的基础上，按编辑器实际容器宽度分配空间。下表为候选布局策略，实施前用三个样板状态验证：

| 编辑器可用宽度（布局 CSS px） | 默认呈现 |
|---|---|
| ≥1200 | 章节目录 + 正文；设定检索按偏好及预算并列，正文列争取 ≥640 |
| 900–1199 | 正文优先，目录可收起；检索可用浮层/抽屉，满足预算时才并列 |
| 760–899 | 最多一个辅助面板并列；不足预算立即转抽屉 |
| <760 | 正文单列，目录与设定检索分别由明确按钮打开 |

预算应基于当前渲染的目录、检索、内边距与正文列共同计算，不只比较整窗宽度。正文空间不足时先改变辅助面板呈现，不通过缩小全文字体、清除用户拖拽值或强制横向滚动解决。

可并列时，正文编辑列保底延续现有约 560 CSS px 的防挤压目标；窗口本身不足时不机械满足此值，而是收起辅助区并使用可用宽度。阅读页宽单独控制，普通状态建议每行约 32–42 个汉字，随字号和作者偏好调整。

主导航在写作时可主动收起，保留清楚的恢复入口。设定检索与章节目录移位或切换为抽屉时，保留搜索结果、选中章节与滚动位置；窄窗口呈现不得写坏宽屏偏好。

#### 工具栏与状态

- 标题和章节状态稳定可见，标题过长时允许合理省略并可访问完整值。
- 常驻组优先包含章节导航、撤销/重做、保存、正文显示与面板开关。
- 排版、校对、审计等次操作归入清楚命名的工具分组；高频入口可保留直达。
- AI/颉文姬入口有名称和选中态，打开后仍保有合理正文空间。
- 次操作进入更多菜单后可由键盘、触摸访问，不能只靠鼠标悬停。
- 专注模式的退出入口始终可发现；保留保存异常和进行中任务的必要提示。
- 状态栏集中显示字数、保存事实和排版控制；信息不足空间时按优先级收纳。

#### 编辑行为保护

正文输入、中文输入法、撤销/重做、标点配对、粘贴归一、Tab 缩进、打字机模式、选区改写、伴写、高亮、全文检索与候选应用均列入回归。布局切换不能重挂编辑器导致草稿或撤销栈意外丢失，不能让重新获得焦点触发多余的 AI 请求。

自动化输入不能替代真实中文输入法和软键盘验证；缺设备时明确标为未测。

### 6.3 角色详情：资料档案与高效编辑

建议结构：列表搜索 → 角色身份摘要 → 分组编辑区 → 关联信息/立绘。

- 摘要包含名称、别名、身份等已有字段中稳定可获得的信息。通过现有模板语义解析取值，字段不存在时不生成空白占位；不按固定中文字段名另建映射。
- 姓名与头像/立绘形成明确视觉关联；没有图像时提供紧凑占位，避免空立绘挤占核心字段。
- 默认沿用模板分组。基础信息与当前分组展开，长经历、附加字段可折叠并记忆。
- 简短帮助保留在标签附近，长解释通过可点击帮助查看；错误、保密和 AI 使用范围等影响判断的信息保持可见。
- 桌面端侧置立绘；空间不足时移至摘要区或可展开图像区，不压缩字段为狭窄多行标签。
- 列表行突出名称和一行有效摘要，提供稳定选中态；完整姓名和摘要有查看方式。
- 模板、字段改名、导入导出、AI 补全、移动角色等次操作集中管理，不改变现有权限、退场和引用处理。

验收至少包括：无图、单图/双图、超长姓名、长经历、大量角色、字段改名、缺省语义字段、自定义模板、隐藏字段、退场角色，以及从正文/报告定位后返回。

## 7. 工作现场保留

### 7.1 先盘点，后补缺

已有“最后章节、卷折叠、检索显隐、字号/页宽、拖拽宽度”等偏好不重复新增。重点补齐编辑器切页卸载后的位置、资料列表状态、详情分组和返回来源。

不采用“所有页面永久挂载”的方式保留状态，避免所有表格、画布、模型订阅和 AI 面板一起留在内存。使用小型、受限的视图状态记录和现有持久化入口。

### 7.2 状态分类与隔离

| 状态 | 推荐存放 | 生命周期与限制 |
|---|---|---|
| 主题、界面字体、密度、一般显隐偏好 | 现有本机偏好体系 | 跨会话；读取失败回默认，不进入项目导出 |
| 目录宽度、折叠等已有偏好 | 继续原键和已有机制 | 保持默认语义，不能突然覆盖旧值 |
| 当前页、当前对象、列表排序/筛选 | 先使用会话级视图记录 | 按平台/存储身份/项目/页面隔离；退出账号或上下文失效时清除 |
| 正文选区、滚动锚点、详情位置 | 受限内存记录，必要时 sessionStorage | 不写正文；不跨账号恢复；内容变化时安全降级 |
| 未保存正文、表格草稿、AI 结果 | 原草稿、存储和任务体系 | 不能复制到 UI 偏好中形成第二份业务真源 |
| 搜索词、临时输入 | 默认仅会话内 | 不作为匿名全局偏好长期保存，防止泄露或串项目 |

视图记录建议新增版本字段和统一键构造器（拟新增 `workspaceViewState.ts`），复用 `uiPrefs.ts` 的校验习惯；不替换已有所有偏好模块。对记录数量设置上限，例如最近 10 个项目、每项目最近 50 个对象，超限按最近访问淘汰；限值在实现前固定并测试。

### 7.3 正文恢复顺序

1. 发起离页时、组件卸载前捕获当前章节、选区、滚动锚点及内容修订标识，仍按既有离页/切章屏障决定是否离开。屏障拒绝或失败时留在原工作现场，不把视图快照当作保存成功，不先卸载编辑器再等待网络。
2. 返回编辑器时，先加载当前项目的权威章节和原草稿机制；不从视图记录恢复正文。
3. 校验项目、章节和导航来源。显式搜索命中、报告定位和用户新选章优先于历史位置。
4. 章节仍在且内容修订一致时恢复选区和滚动；以布局稳定/字体测量条件为依据，避免固定 setTimeout 猜时机。
5. 仅因排版变化时使用锚点相对位置恢复；正文已变化则降级为合理段落位置或章节顶部，不把旧选区当成 AI 修改范围。
6. 章节已删除、无权限或功能已隐藏时回到有效页面并给出简短说明；不自动重建对象。

需要处理输入法 composing、图片异步加载、主题/字号变更、长文、章节外部更新、切项目和异步返回竞态。写入带捕获时的项目身份和代次，异步完成后身份不匹配即丢弃视图更新。

### 7.4 返回与恢复入口

从正文打开角色/设定详情时保留来源，提供“返回写作”或明确返回按钮。返回目标优先恢复来源上下文；普通侧栏导航保持当前语义，不强制所有导航走新的历史栈。

提供“重置工作区布局”入口，只重置布局、显隐、宽度、当前界面密度和视图位置等白名单键；保留主题、界面/正文字体、正文排版、书库、草稿、模型配置、候选和任务。执行后更新所有已挂载读取方，不能要求整页刷新才能使一半设置生效。

### 7.5 恢复合同与默认限制

以下为本版明确默认值，F0 如因当前存储身份接口而调整，需先记录原因，不在实现中各自解释：

| 对象 | 本版合同 |
|---|---|
| 临时视图记录 | 默认内存；同标签刷新需恢复的非敏感位置可用 sessionStorage。标签关闭、进程结束或浏览器主动清理后，不保证这些临时位置仍在 |
| 跨启动恢复 | 只承诺现有持久化偏好与有效的最后章节等已有能力；不新承诺恢复原生撤销栈、未保存选区或全部筛选词 |
| 身份 | 键至少分平台/存储空间/身份/项目/页面；不把用户名、密钥或完整本机路径写入可读键。用当前稳定身份 ID 和空间标识，不以“当前全局项目”异步求值替代捕获身份 |
| 记录限制 | 最近 10 个项目、每项目最多 50 个对象；单条序列化上限 16KiB，会话视图总预算 256KiB；数量或体积超限按最近访问淘汰 |
| 写入节奏 | 选择/滚动变化先更新内存；持久化仅在合适生命周期或至多约 250ms 合并写，不在每次键入/滚动里同步写盘或对全文重算哈希 |
| 内容校验 | 优先复用当前修订标识；锚点存对象 ID、段落序号/偏移/相对位置等最小数据，不保存原文片段、AI 结果或完整 DOM |
| 损坏/未知版本 | 读取前检查原始长度，再校验字段、范围和版本；丢弃该视图记录并安全回落，不修复或重写业务数据 |
| 导航优先级 | 用户新操作/显式命中定位 > 本次返回来源 > 当前会话记忆 > 已有最后章节 > 有效缺省页面 |
| 生命周期 | 登出、身份变化、导入替换书库、项目删除、数据根切换、失效代次时清理对应记录；布局重置只按白名单清理 |

恢复流程使用请求代次/取消标记；快速 A→B→A、旧异步回调、字体晚加载不能再次把作者拉回旧位置。焦点只在该导航由作者发起、当前页面仍匹配且作者尚未进行新操作时恢复；不能抢走刚打开的弹窗或后台窗口焦点。

同页换主题、密度、面板和窗口大小应保持编辑实例及撤销栈。跨页卸载后的正文与草稿仍走原业务恢复，原生撤销栈不作为本版跨卸载保证；不为恢复撤销栈保留全书页面或引入编辑器内核重写。

## 8. 全项目页面推广

### 8.1 表单、世界设定与制度

统一页头、分组、字段标签、帮助与保存区。保留母子世界/力量体系、并列制度、自定义字段和活跃/已完结等既有结构。

窄宽度时标签置顶，正常宽度使用对齐的标签列；长说明退出固定窄列，避免单个字段占据大段竖向空间。字段错误与必填信息不收进帮助弹层。引用选择器显示当前值，目标失效时提供准确提示。

### 8.2 表格、章节总表与图鉴

按“搜索/筛选 → 数据 → 行操作 → 保存状态”组织。主操作是新建/添加；列管理、批量工具、导入导出放入次操作组。列多时使用表内横向滚动，保护表头与正文对齐。

密度、换行与列宽变化必须接入现有或后续大表测高方案。筛选不丢未保存草稿；清筛选恢复完整逻辑数据；从报告跳转到远端行时必须定位到实际对象，不因未挂载就忽略。

图鉴列表/卡片/详情采用相同身份、搜索和状态语言，但保留图片与字段结构特点。不为统一外观强制把所有数据表改成卡片。

### 8.3 大纲与规划

主从布局统一，目录突出卷/章层级、名称与状态；长摘要通过详情阅读。全书总纲、分卷大纲、章节细纲之间保留明确入口，不引入另一套章节 ID、编号或排序。

章节目录展开、筛选、当前对象与详情位置使用第 7 节约定。折叠分组后仍能发现校验错误及未保存状态。

### 8.4 图谱、地图、时间线与画布

画布占据主要区域，缩放/复位/选择/编辑等工具位置固定；图例按需展开。选中对象的详情在侧栏或抽屉展示，窄窗口不同时挤入多个固定侧栏。

保留颜色、线型、纹理、标签等现有语义和黑白主题策略。隐藏或折叠不删除节点/连线。键盘可操作的列表入口与画布定位配合，不能将拖拽作为唯一访问数据的方式。

验收使用真实非空关系、时间线和地图样本。关系图在对应关系页的图视图验收，时间线在对应时间页验收；切页签后重新选择正确视图，不用空画布获得通过。

### 8.5 酒馆与对话

当前会话、正文消息和输入区为中心。会话目录、人物状态、变量、检查点及高级参数按任务展开；会话切换后保留对应滚动状态。

发送、停止、失败重试与结束本轮清楚区分。长消息、代码/结构化内容、运行中输出和失败信息都有稳定排版。新消息滚动遵循“接近底部时跟随，阅读历史时不强行拉底”；未读更新提供轻量入口。

参数帮助分基础与高级，沿用酒馆自身的模型就绪判定，不能将全局模型守卫机械套到独立 provider 场景。短内容也应有完整高度，输入区不漂移；平板软键盘弹出后能继续输入和发送。

### 8.6 模型设置、工具与资料库

设置保持可搜索，按连接、模型能力、生成参数、提示词、高级设置组织。实际分组必须与当前设置来源及搜索定位同步，不改变模型选择与能力判定。

灵感、拆书、创意写作和检查工具区分输入、运行状态、结果三个区域。输出长文以摘要/分组展示，原始内容和导出仍可访问；部分结果失败时不把已成功内容一并隐藏。

模板、知识库、字段管理和迁移弹窗同样覆盖密度、主题、错误与加载状态；迁移锁、兼容提示和导入风险不能因精简页面而消失。

### 8.7 项目管理、品牌与维护页面

项目卡片突出书名、封面、最近编辑和继续入口；新建、导入、备份管理形成清楚层级。长书名、无封面、大量项目、首次使用、游客与云端身份分别验证。

颉文姬、纹样和氛围色主要在项目管理、引导、空态和关于打赏页使用，保留隐藏/更换等现有偏好。图片按需加载并保留尺寸，避免内容跳位；已有优化后的素材继续复用，不默认增加新的大图下载。

维护操作遵循现有业务流程：备份与内部自动备份区别、同步冲突、导入格式闸等说明必须准确。精简文案可采用“简短结论 + 详细说明”，不能删去影响作者决策的信息。

### 8.8 导入、导出、图片和内容边界

本版改界面，不改变既有项目备份、卡片包、模板包、正文文档和图片的格式协议。但所有入口必须回归，避免菜单收纳后功能不可达或外观样式污染导出结果。

| 场景 | 细化要求 |
|---|---|
| 文件选择取消 | 保持原内容与页面状态，恢复按钮可用；不显示“导入失败”或空成功提示 |
| 导入解析/版本不支持 | 按现有格式闸拒绝，保留原项目；错误可完整阅读，不只闪现一条 toast |
| 替换/批量导入 | 明确目标、范围与既有确认；防重复提交，不因对话框移位改变默认危险操作 |
| 导出/下载 | 按实际能力说明范围和不包含项；浏览器触发下载不等于确认文件已落到用户磁盘 |
| 图片 | 继续现有类型/大小/压缩校验，失败保留旧图，超长宽比有合理展示，选择与拖入使用同一业务入口 |
| 图片/模型外链 | 不为新预览或主题自动请求用户未打开的远端资源；资源失败不阻塞正文 |
| 排版与导出 | 界面密度、主题、字体和控件样式不改正文字符、段落、缩进语义、统计口径或导出样式定义 |
| 复制/富文本展示 | 分清原文、建议、摘要和复制内容；保持现有转义/安全渲染边界，不把模型输出当可信 HTML |

有代表性的 JSON/文本/EPUB/DOCX 等只验证项目实际支持的格式；截图对比与结构/内容校验分别负责视觉和数据正确性。打印/导出预览若已有入口，也纳入本地回归，不新增本版未承诺的格式支持。

## 9. 保存、错误与日常反馈

### 9.1 保存展示模型

建议抽取共享的展示选择器，输入现有正文/表格草稿状态、真实后端状态、写锁/冲突和回执，输出文案、图标、可用操作与优先级。该选择器不负责实际保存，不另建保存计时器。

| 事实 | 显示建议 | 行为 |
|---|---|---|
| 尚未提交修改 | 有未保存修改 / 待保存 | 手动页保留保存操作，自动页说明自动保存状态 |
| 已提交但仍等待真实写入 | 正在保存 / 正在写入 | 允许正常编辑的场景继续编辑，不提前显示成功 |
| 权威存储确认成功 | 已保存 + 可选时间 | 轻量反馈，不反复弹出成功 toast |
| 写入失败 | 保存失败 + 原因和下一步 | 持续可见，按现有能力提供重试/查看/导出入口 |
| 条件写冲突 | 存在冲突，需要处理 | 打开现有冲突处理，不自动覆盖 |
| 写入锁/恢复核对 | 暂停写入 / 需要核对 | 明确限制范围和现有恢复入口 |
| 云盘同步中或失败 | 单独的同步状态 | 本地保存与远端同步分开呈现 |

优先显示当前操作必须处理的错误、冲突和锁，再显示写入中、待保存和成功。编辑器、页面保存区与全局存储栏可以有不同详略，但不能给出互相矛盾的结论。网页云端“已保存”指本次权威云端写入确认；游客指当前浏览器存储成功，仍须准确说明其保存边界。

手动与自动保存的现有差异先登记，不为视觉统一擅自把手动页改成自动保存。新样式需让作者知道当前页的保存方式。未来改变保存语义另行实施并回归真实存储。

### 9.2 反馈层级

| 级别 | 呈现 |
|---|---|
| 普通成功 | 行内状态或轻量 toast；不抢焦点 |
| 耗时操作 | 有任务名和阶段；无真实进度时不编造百分比 |
| 字段错误 | 靠近字段，提供文字，提交时定位首个错误 |
| 局部失败 | 保留输入和成功部分，原位展示下一步 |
| 影响数据安全的失败 | 页面/全局持续提示，入口明确，不能仅短暂 toast |
| 搜索无结果 | 区别于没有数据，提供清除筛选 |
| 空项目/空列表 | 说明用途，提供第一个有效动作 |

状态变化使用恰当的可访问播报；高频保存和流式输出不逐字刷屏。删除、批量覆盖等沿用现有确认约定，不新增原生 confirm 或重复确认步骤。

### 9.3 启动、资源加载与渲染异常

当前源码有启动前空容器、启动失败和根 ErrorBoundary，但其体验不能仅由“有错误页”判定完整。R2 增加独立任务 UX13：

1. 启动等待使用已应用外观的轻量状态，说明正在打开工作台；长时间未就绪时提供准确的等待/失败信息。只有真实阶段可知才显示阶段，不编造进度或将慢启动直接认定为库损坏。
2. 启动失败页的操作应在该失败状态真实可用。例如不能引导作者去点击此时未挂载的“左下角数据坞”。按平台列出现有可访问的重试、位置说明或诊断入口。
3. 动态模块/静态资源加载失败保留可见错误和手动重试；不通过自动刷新循环处理旧资源失效。页面加载重试与实际 AI/写入重试是不同动作。
4. 根错误边界不能无证据承诺“未造成数据丢失”。使用“页面出现异常，已保存内容以实际存储结果为准；未提交修改可能需要恢复”等与真实能力一致的文案。只有已有回执/恢复记录证实时才说明具体已保留内容。
5. 原地恢复与重新加载各自说明含义。错误边界重置会重挂子树，不能声称一定保留内存草稿；刷新、返回项目管理和清除数据不视为等价恢复。
6. 只读图表/报告等适合的局部区域可设置受限错误边界，避免一处非核心展示出错拖垮全部工作台；不随意包住正文再自动卸载重挂以“修复”异常。
7. 正常主题 CSS、图片或字体不可用时提供稳定回落；停止自动重试后仍有可操作页面。故障提示的按钮不触发删除缓存、清库或恢复出厂设置。

诊断优先保留当前内存错误记录和已有脱敏信息；错误摘要对作者可读，详细堆栈按需展开。诊断不包含正文、密钥、Cookie、密码、完整请求头和未经处理的个人路径，不自动上传。开发环境仍保留必要控制台证据，不能用吞异常消除报错统计。

### 9.4 网络、身份失效与长任务

- 网络可用性按当前请求/后端事实判定，不能仅凭 navigator.onLine 推断“已同步”或“服务器故障”。断网、超时、401 会话失效、409/412 冲突、配额及写锁各自保留正确处理入口。
- “登录过期”与“在别处登录”继续使用现有原因判定。需要转到登录或重新载入时先遵循现有草稿与保存屏障；不新增无提示跳转清空内存现场。
- 重连不自动把旧快照写回覆盖新版本，不悄悄切换到另一存储形态；本版不引入离线云端编辑/PWA 承诺。
- 导入、删除、候选应用、生成和文件迁移等动作防重复点击；防重复状态与实际调用周期绑定，不能一段固定定时器后就重新可点。
- 显示取消/停止前核实当前阶段可取消；请求已被服务端接受或已落盘时，不能把停止等待描述为撤销业务结果。
- 关闭结果面板只收起界面，后台任务继续按原机制运行。重开、切页、窗口缩小和恢复焦点不再发起同一个任务。

## 10. AI 结果与任务体验

### 10.1 展示统一，状态仍按业务归属

任务运行、候选审阅、正文提交是不同状态轴。现有 `AiRunStatus`、`RevisionCandidateStatus`、修订任务和回执继续作为真源，不合并成一个新的万能状态机。

| 状态轴 | 需要清楚表达的事实 |
|---|---|
| 任务 | 运行中、完成、失败、中止；有真实进度才显示进度 |
| 候选 | 待审阅、正在应用、已应用、过期、放弃、需核对 |
| 应用回执 | 目标章节、提交结果、持久化确认、失败原因与恢复边界 |
| 选段结果 | 仅在已有业务支持时显示部分采用，不能用前端标签虚构能力 |

特别处理：任务完成不等于已应用，候选存在不等于已写入，点击采用不等于落盘成功。旧候选过期后保留原因与可行入口，不能仅显示灰色“不可用”。

### 10.2 结果面板结构

1. 顶部：任务名称、目标对象、生成时间、真实状态。
2. 摘要：主要问题/建议数量、修改范围、需要作者处理的事项。
3. 内容：原文、建议或候选、差异；长结果分节展开，保留完整原文。
4. 操作：采用现有支持的应用/复制/放弃/重新生成，明确作用范围。
5. 失败或过期：原因、保留情况、下一步；不自动重跑或自动应用。

复用 `CandidatePanel`、`CheckReportPanel`、`DiffView`、颉文姬各面板与运行账本。跨页签切换不丢任务订阅，完成后可回到对应结果。关闭面板不等于取消任务；取消行为和文案必须与底层实际支持一致。

AI 对话/输出内容不当作可信 HTML 注入。新摘要优先由现有结构化结果或本地规则获得，不为美化新增模型调用、真实密钥读取或 API 消耗。

## 11. 导航、帮助和新旧用户兼容

### 11.1 导航与检索

保留现有分组、页面 ID、功能可见性与动态分卷规则，避免大规模重排让老用户重新找功能。改善选中层级、折叠状态和滚动定位。

全书检索在宽屏和窄屏均提供可发现入口及快捷键提示，搜索命中仍按实际项目可见性跳转。若后续扩展为页面/命令搜索，需清楚区分“搜内容”和“找功能”，并复用已有入口与权限判定。

收藏/最近访问是增强项：若实施，按项目和可见功能过滤，已删除/隐藏页面不得留下死入口；只保存有限 ID，不保存正文快照。

### 11.2 分阶段帮助

- 首次空态给一两句用途和有效示例，避免整页长教程。
- 字段旁保留一句必要说明，详细解释复用 HelpPopover。
- 熟练使用后可收起教程，但始终能重新打开；不删除使用指南。
- 根据实际内容或明确交互判断阶段，不单纯按启动次数推断熟练度。
- 不增加强制新手流程；旧用户升级后直接保留工作入口。
- 影响保存、保密、模型能力、导入兼容和破坏性操作的说明不随“熟练模式”隐藏。

### 11.3 兼容策略

旧主题、字体、宽度、折叠与显隐偏好逐项登记。只在必要时增加有版本的 UI 偏好迁移，读取旧值、校验、缺省回落；不修改项目 schema、字段键和导出数据。

新偏好写入失败只影响跨会话记忆，不使页面崩溃；不能把业务保存失败也降格为静默。跨实例同步只在现有机制覆盖的类型上复用，新枚举/复合视图记录需明确通知策略，不能假设所有 hook 自动同步。

### 11.4 独立网页与 React 外提示

新增 UX11，覆盖 `server/lib/authPage.mjs` 的登录、注册、密码重置，以及 `server/index.mjs` 注入的游客告知。它们独立于 React、Tailwind 页面路由和主主题初始化，必须单独改造与验收：

- 身份页默认沿用独立暖浅色，统一品牌、字号、输入、错误和主次操作规范；不强制加载主应用 bundle 或读取未登录书库。此默认是明确的产品边界，不把身份页伪记为已覆盖应用九套主题。
- 复用最小静态语义样式规范，不复制整份应用 CSS。服务端身份页本版只承诺该默认样式下的可读性与键盘/触摸体验；若以后增加跨主题映射，作为独立扩展记录。
- 登录/注册开放、邀请、关闭三模式和密码重置分别验收；保留 autocomplete、密码管理器、粘贴、字段长度、错误转义、限流和接口语义。样式改动不更改鉴权、Cookie 或安全策略。
- 异常提交保留允许保留的非敏感字段并恢复按钮状态，密码/邀请码不写 localStorage、URL、诊断或截图报告。提交失败原因靠近表单，键盘能定位；不因更友好的文案暴露原本刻意合并的账号错误。
- 游客转账号入口明确说明数据边界和现有导入方式，不承诺注册后自动迁移浏览器内书库，不因点击外链或注册入口绕过当前编辑的离页处理。

`mobileHint.ts`、`tabGuard.ts` 和服务端游客条共同纳入浮层占位表。对主导航、标题、正文输入、发送区、保存球、看板娘和写入锁逐一检查重叠；多条通知按优先级排列或收纳，但实际写入故障始终可发现。窄宽度允许提示换行或展开完整说明，不仅显示被省略的风险前半句。

React 外提示保留“即使主应用渲染失败仍能告知”的职责，不为复用组件把它们全部搬进 App。主应用可用时同一事实避免重复弹出；关闭普通告知不等于清除真实锁/冲突。窗口放大、身份变化和提示适用条件消失时，正确更新或撤下过期告知，避免仍显示旧的身份或窄屏信息。

### 11.5 兼容、尺寸与系统环境

F0 记录实际支持范围与参考版本：Windows Electron、桌面 Edge/Chrome、便携服务支持的浏览器，以及已有用户目标平板的浏览器和系统。已被声明支持的平台列为必测，不能仅因为开发机只有 Chromium 就把目标平板排除；无法获得环境时明确 blocked。

检查 container queries、ResizeObserver、CSS zoom、视口单位、Pointer Events、字体测量和存储访问等本版实际依赖。关键能力缺失时至少回落为稳定单栏、标准表单、可读状态；不以 UA 字符串代替能力判断。已有不支持的环境说明不能被“默认样式看似正常”自动升级为支持。

区分 UI 缩放、浏览器缩放、系统 DPI 和触摸缩放；Portal 定位、拖拽和浮层尺寸使用一致坐标系，避免重复除以缩放。单独测试实际可用的 200% 文本/页面放大路径；它不能只由 UI 缩放 160% 的已有用例替代。[W3C 文字放大](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)

登录、帮助、错误页与普通文字区检查窄布局重排；表格/地图的二维滚动例外按具体区域标注，不扩展成整个页面可溢出的理由。320 CSS px 重排作为相关文字区的补充检查，不等于承诺完整手机创作工作台或全站 WCAG 符合性。[W3C 内容重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

平板测试包含横竖屏切换、软键盘显示/隐藏、浏览器工具栏变化和安全边距；选中输入保持可见，输入完成后布局恢复。系统减少动态效果、系统高对比/强制颜色、系统字体回退作为补充兼容项，分别记录与应用纯黑白主题的差异。

### 12.3 子任务必须写明的内容

每个实现子任务采用同一张最小卡片：`ID / 对应 R、UX、AC / 当前已存在机制 / 拟改入口 / 前置接口 / 本次具体行为 / 保留行为 / 夹具 / 自动检查 / 人工检查 / 证据 / 未测边界 / 回退范围`。责任按角色分为设计规范、组件/页面、业务接口、自动化/设备验证；即使同一开发者兼任也分别检查，不使用不存在的人员姓名或隐含交接。

样板不是只交截图：必须同时交付普通/空/加载/错误/禁用/选中/溢出等状态、实际交互、所用令牌和小窗口版本。页面迁移前先归类，迁移后更新覆盖表；不能以公共 CSS 已生效推定所有页面完成。

### 12.4 测试与审计适配依赖

`UX00 → 布局/样本和状态合同 → 公共组件 → 样板 → 业务状态接入 → 全页面 → 集成验收` 是主链。审计适配与实现同步进行，F0 复用 3.2.3 已接线的 layout.affected，登记新增的恢复/焦点/身份页用例，F1 提供运行壳，F2 起能验证样板，不把所有探针都推到 F5 才编写。

新纯逻辑测试加入项目当前唯一测试清单并由 `npm test` 可发现；先核实 `run-batches.sh` 与现有 test-plan 接口，不只创建一个永远不会执行的测试文件。扩展旧结构性护栏时以保留业务约束为目标，不能为保留旧 className 或旧文案而阻碍新设计，也不能以“UI 更新”为由删除保存与权限断言。

### 12.5 实施纪律

- Tailwind v4 保持显式 source 范围，不让文档、临时克隆或历史产物进入类名扫描。
- 保持 schema 门面、tabVisible、模板语义入口和既有数据引用规则；不从展示摘要反向覆盖字段。
- 不用长全局选择器修改所有 input/button；例外先识别，迁移后再缩减旧规则。
- 不在用户端增加“技术实现说明”“迁移检查步骤”等内部流程；作者只看到必要的用途和决策信息。
- 只对恢复、隔离、状态选择、布局预算等可能判错的逻辑补纯函数测试；样式以实际渲染/视觉证据验证，不为每个 className 写镜像测试。
- 不为保存工作现场保留所有页面 DOM 或整个书库副本；不把每次按键都写 localStorage。

## 14. 性能控制与专项协同

### 14.1 基线和采样

复用大表专项的数据生成、隔离运行、生产构建及采样纪律。若该专项已有兼容的已冻结基线，复用其输入和报告；源码、夹具或环境不匹配时重新建立可比基线。

记录：机器、运行时、构建模式、Git/diff 指纹、资产哈希、窗口、UI 缩放、DPR、字体、主题、密度、数据规模和平台配置。截图视觉比较固定时钟、随机种子和动画，避免动态内容掩盖差异。

登录/游客页还需记录服务端模板和注入脚本的指纹；只记录 src 或主应用产物不足以证明这些界面匹配当前版本。服务端逻辑未变更时仍用实际临时服务渲染验证，不用拼接的截图样板冒充登录链路。

### 14.2 本版新增关注项

| 指标 | 建议采样 | 暂定验收目标 |
|---|---|---|
| 返回正文到可编辑且位置稳定 | 热往返至少 30 次，报 P50/P95/最差 | 与基线相比 P95 不退化超过 max(20%, 100ms) |
| 正文输入到绘制 | 至少 30 次独立键入，报 P50/P95/最差 | 参考机普通写作场景 P95 ≤100ms；F0 验证可行性 |
| 页面热切换 | 性能门槛代表场景各至少 30 次；其他页面做行为 smoke | P95 不退化超过 max(20%, 100ms)，无持续布局抖动 |
| 表格开表/输入/保存/定位/滚动 | 按大表专项口径 | 保留专项门槛；无兼容证据时不可声称通过 |
| 首屏前端 JS/CSS 压缩体积 | 同模式、同压缩方法下比较首屏所需总量和最大入口 chunk | 相对基线增量目标分别 ≤5%；超出需说明来源与可接受性 |
| 内存和订阅 | 同一路径往返 50 次 | 视图记录有上限、订阅/监听数量不持续增长；工具支持时附 heap 趋势 |
| 保存确认 | 原真实回读指标 | 不因隐藏工具栏、卸载页面或恢复状态而改变结果或新增等待 |

上表为拟定门槛；F0 先测参考环境，必要调整须在优化代码前固定原因和新值。不能做完后按现有结果放宽。首次测试功能错误的轮次标为失败，不因它更快而计入性能成功；保留超时、首轮失败和最差值。

默认热场景先做 1 次不计入结果的预热，再取规定独立样本；P95 使用排序后 nearest-rank（ceil(0.95×N)）并同时保存原始样本。冷启动如仅取 5 次，只报告中位数与最差，不伪装成稳定的 P95 结论。性能门槛场景在 F0 固定到具体页面/夹具/动作，避免合流时临时换成更轻的页面。没有兼容基线时相对退化项为 blocked，不能自动按“未见退化”通过。

正文输入目标用于参考环境的前端响应，不代表公网云端保存延迟；渲染、存储和网络指标分开。内存没有可靠测量能力时标明工具边界，不用“未发现卡顿”替代泄漏结论。

### 14.3 设计上的性能约束

- 不新增默认大图、字体全集、重动画和覆盖全页的模糊层。
- 延续按页懒加载；公共外观调整不将所有工具拖入首屏包。
- 折叠面板按需渲染，但必要任务/存储订阅不随可见 DOM 消失。
- ResizeObserver、位置恢复和拖拽节流/批处理，避免同步测量与写样式循环。
- 列表摘要和 AI 摘要复用已有数据，不因样式更新重新跑全书扫描或模型请求。

## 15. 验收体系与完成定义

### 15.1 测试分层

| 层级 | 内容 | 原则 |
|---|---|---|
| 纯逻辑 | 布局预算、视图键/校验/失效、状态选择、偏好迁移 | 验证真实分支和边界，不测试拼接类名本身 |
| 组件/浏览器行为 | 菜单、抽屉、焦点、切换、帮助、定位、键入 | 使用真实交互和可访问名称 |
| 全页布局 | 动态页面清单×窗口/缩放 | 局部表格/画布滚动允许，整页溢出单独判错 |
| 视觉 | 三个样板、各页面族代表、关键故障状态 | 同构建、固定数据、多主题人工对照 |

### 15.2 窗口、主题与密度矩阵

不把全部维度机械做笛卡尔积；采用全页基础矩阵、关键页加密与平台定向验证。新增/受影响规则必须在对应边界实测。

**全页基础矩阵**沿用并扩展当前探针中的七组：

| 窗口 | UI 缩放 | 用途 |
|---|---|---|
| 768×1024 | 100% | 普通平板竖屏 |
| 1024×768 | 100% | 普通平板横屏 |
| 1280×800 | 100% | 常见笔记本 |
| 1366×768 | 100% | 普通桌面工作区 |
| 1000×640 | 100% | 小窗口 |
| 1000×640 | 160% | 放大界面 |
| 768×1024 | 125% | 平板放大 |

补充 768×600 桌面最小窗口、1920×1080、2560×1440，以及真实高 DPI/系统缩放至少一组。窗口宽度、UI 缩放和浏览器缩放分别记录，不能混成同一维度。

**主题覆盖**：全部预制主题逐一验证公共组件、正文、表格、角色、AI 结果与故障提示；至少两种自定义主题样本（浅/深母版派生，含不利强调色）验证可读性或明确的纠正提示。全页基础矩阵以默认主题完成，其他主题在各页面族代表和所有专用绘图上补齐。

**密度覆盖**：全页默认档；三个样板、表格、酒馆、设置和图鉴测试两档；密度影响到的特殊组件不能只按普通表单样本替代。

**项目形态**：全功能项目与至少一个移除部分功能的自定义项目；动态分卷、自定义模板/字段与已删除对象分别提供样本。

**独立身份页**：使用其明确的默认暖浅色，单列登录/注册三模式/重置/错误/限流/取消与 200% 放大、软键盘检查；不与应用九主题矩阵混记。React 外告知在其实际平台配置、首启/项目内/错误页及多条并存时验证。

**断点边界**：对实际采用的 760、900、1200 等切换点分别验证 -1/恰好/+1 CSS px，并追加拖拽或连续缩放跨越边界；若 F1 调整断点，同步由最终配置生成这些用例。区分全窗导航断点与编辑器实际容器断点，不用相同窗口宽度推定相同可用内容宽度。

### 15.3 四配置与故障验证

| 配置 | 必测内容 |
|---|---|
| 桌面 | 实际窗口和隔离 userData/appData，写入失败/锁/恢复、缩放与菜单、离页屏障 |
| 便携 | 临时数据根的真实 HTTP/文件后端，写入失败/锁/切项目，路径状态 |
| 网页云端 | 临时账号与本地真实服务，条件写冲突、会话过期、网络失败、账号隔离 |
| 网页游客 | 独立浏览器存储，刷新恢复、配额/写入失败、真实已有导出能力与准确提示 |

四配置都至少走通一次核心创作流程和一次保存失败流程。只有对应能力存在时才提供操作入口；游客故障草稿导出等尚未落地能力不能在本版界面先画成可用。真实关页/关窗场景使用真实关闭，不用合成 beforeunload 事件替代。

### 15.4 完整创作任务

**主路径**：

1. 打开已有项目，识别当前保存/同步状态。
2. 从写作面板进入最近章节并输入一段内容。
3. 搜索并打开关联角色，查看长说明或资料，必要时修改并按当前页面规则保存。
4. 返回正文，核对章节、选区/阅读位置与草稿没有丢失。
5. 调用本地假模型完成一次建议生成，打开原文/候选/差异。
6. 按已有能力审阅或应用，核对实际目标与持久化结果。
7. 调整辅助面板/密度，继续键入，再切页面、切项目并返回。
8. 正常关闭并重开，核对已保存内容及约定内的偏好恢复。

**分支**：空项目起步；搜索无结果；目标删除；功能隐藏；正文在外部变化；AI 失败/中止/候选过期/需核对；保存失败；云端冲突；平板抽屉与软键盘；纯黑白非空画布。

F0 对主路径记录基线操作次数和寻找入口的停顿点；新版关键路径不增加无必要步骤。若能安排 3–5 名有代表性的作者，按相同任务记录完成率、耗时和困难点；无外部参与者时如实写内部走查，不虚构用户研究结果或统计显著性。

## 16. 风险与回退

| 风险 | 控制方式 | 回退边界 |
|---|---|---|
| 改全局颜色导致多主题失真 | 语义角色渐进迁移，先样板再推广，保留旧变量兼容 | 按视觉基础/页面族提交回退，不改项目数据 |
| 提高字号后空间更紧 | 同时优化说明、工具分组与有效宽度 | 撤回对应布局，不通过整体缩小界面掩盖 |
| 密度改变大表行高 | 与测高/虚拟窗口联调、保留锚点、全类型行样本 | 关闭新密度入口并保留原默认布局 |
| 位置恢复覆盖显式导航或串项目 | 来源优先级、身份键、修订校验、代次控制 | 清除仅本版视图记录，不清草稿和业务库 |
| 组件迁移破坏弹窗、sticky 与满高 | 独立验证层级、滚动与键盘焦点 | 按组件迁移批次撤回，避免巨型提交 |
| 美化掩盖存储故障 | 真源选择器、故障持续可见、真实回读 | 保留原存储栏/写锁事实展示能力 |
| AI 展示与候选状态脱节 | 分离状态轴，复用业务动作与回执 | 撤回展示包装，保持既有应用链路 |
| 状态记忆引发订阅/内存增长 | 有限记录、卸载清理，不 keep-alive 所有页面 | 禁用恢复增强，保留原导航与草稿机制 |
| 范围扩张影响交付 | 增强项独立，F0 固定必做清单 | 延后增强，不删必需故障验收 |
| 独立身份页脱离主应用规范 | 独立默认样式、真实服务验证、模板与注入条指纹 | 单独回退身份页样式，不回退鉴权协议 |
| Portal 与模态焦点互相冲突 | 逻辑归属、顶部层消费、背景隔离与组合用例 | 按公共交互批次回退，不靠 z-index 魔数遮掩 |
| 失败恢复误导或刷新丢内存现场 | 准确文案、人工触发恢复、无循环重载、原屏障 | 取消危险自动恢复，只保留可证实操作 |
| 自定义主题或字体在启动时不可用 | 首帧校验、字体回落、多层一致重测 | 单次回落到稳定显示，不覆盖业务数据或全部旧偏好 |

开发按设计基础、公共组件、样板、恢复/反馈、页面族分批提交并保留证据。仅在进入实现后根据工作区情况建立合适的隔离方式；不为编写方案重置、暂存或清理其他工作。

“源码观察”只说明 R2 复核时的实现或文案可被定位，不代表当时已通过实机复现判定产品故障；“方案缺口”指初稿尚未写清的范围或执行合同。以下是 R2 的查漏记录；此后各项实际实现与测试状态以开发进度台账为准。

| 编号 | 复核发现 | 类型与影响 | 本次补充落点 | 验收 |
|---|---|---|---|---|
| G01 | 只遍历 App/schema 会漏掉身份页和注入告知 | 源码观察＋覆盖缺口，影响网页完整性 | 3.1、11.4、UX11 | AC15、AC16、AC38 |
| G02 | 根错误文案断言“未造成数据丢失”，启动失败指向此时未挂载入口 | 源码观察＋恢复合同缺口，影响可信反馈 | 9.3、UX13 | AC13、AC14 |
| G03 | Modal 按 DOM 子树循环焦点，而选择器等 Portal 到 body | 源码观察＋组合交互风险，影响键盘/读屏 | 5.4、UX12 | AC07、AC34 |
| G04 | 多层快捷键和 IME 只有分散局部规则 | 方案缺口，可能重复保存或误关闭/发送 | 5.5、UX12 | AC09、AC12 |
| G05 | 分栏 hook 主要处理鼠标，拖拽替代没有清单 | 源码观察＋设备覆盖缺口 | 5.5、UX12 | AC10、AC11、AC28 |
| G06 | 页头扣高依赖常数，新字号/密度/提示会改变真实高度 | 源码观察＋布局迁移风险 | 5.3、UX02、UX07 | AC05、AC06 |
| G07 | 缺省密度“就近映射”不够明确，布局重置范围有歧义 | 方案决策缺口，可能覆盖用户偏好 | 4.5、7.4、7.5 | AC02、AC03、AC37 |
| G08 | 恢复生命周期、容量、焦点与撤销栈边界不够具体 | 方案执行缺口，影响性能/隔离/预期 | 7.3、7.5、UX06 | AC17–AC20、AC30 |
| G09 | 首帧闪烁、字体/图片晚加载和资源失败未单列 | 方案状态缺口，影响可读性与编辑稳定 | 4.7、9.3、UX13 | AC01、AC14 |
| G10 | 多条 React 外告知与常驻浮层并存没有统一验证 | 源码观察＋组合覆盖缺口 | 11.4、UX11、UX12 | AC08、AC16 |
| G11 | 文件取消、导出隔离、内容极值和复制边界描述较粗 | 方案回归缺口，可能“看起来正常但改坏内容” | 4.8、8.8、UX07 | AC04、AC21、AC22、AC28、AC29 |
| G12 | 网络恢复、失效会话、重复点击和取消语义未写透 | 方案业务接入缺口，可能假成功/重复操作 | 9.4、UX08、UX09 | AC23–AC27 |
| G13 | 支持环境、200% 放大、软键盘、版本资源组合未闭环 | 方案兼容缺口，影响跨端交付 | 11.5、15.2、15.9 | AC31–AC34、AC37、AC38 |
| G14 | 任务粒度、探针适配、夹具、采样和证据映射不足 | 方案执行缺口，验收可能延期或假覆盖 | 12.3–12.4、14.2、15.7–15.8 | AC35、AC36 及全组追踪 |
