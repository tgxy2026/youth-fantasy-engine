| 方案 | 机制 | 实测效果 | 增量成本 | 判定 |

| **B** 提示词反例清单（**已实施**） | 抽取时就把泛称清单塞进提示词 | 条数 74→63（-15%）；点名过的词消失 | 提示词 +62%，**每次调用都重发** | 有效但**每章都付费**，且只对点名的词敏感 |

## §1 B 方案（提示词反例清单）的实测代价

已实施（提交 `dd3cd5c`）。量化其成本：

| 项 | 值 |
|---|---|
| `EXTRACT_SYS` 长度 | 754 → **1,219** 字符（**+62%**） |
| 该提示词的重发次数 | **每次抽取调用**都重发 → 本批 9 次调用多付 ≈ 4.2K 字符输入 |
| 抽出的条数 | 74 → 63（**-15%**） |
| 耗时 | 304s → 389s（**+28%**，单样本，含运行噪声） |

**局限**：反例清单是"点名式"——模型只对**点到名的**词敏感。点名过的（`油纸`/`布老虎`/`铜钱`）消失了，没点到的（`白发长老`/`议事堂`/`黄汤`/`黑乎乎的药丸`）照旧。想继续压只能继续加名字，而每加一批都是**全局变慢**。

## §2 C 方案（二遍复核）4 个变体实测

同一条基线（缓存），一次跑完，可比：

| 变体 | 额外调用 | 复核耗时 | 模型判泛称 | 其中与登记表冲突 | 兜底后净剔 |
|---|---|---|---|---|---|
| **V1** 仅名单（两档） | +1 | 12.4s | **59 / 60** | 31 | 28 |
| **V2** 名单+类型+描述（两档） | +1 | **175.1s** | **0 / 60** | 0 | 0 |
| **V3** 名单+类型+描述（三档：确定/疑似） | +1 | 16.5s | 33 / 60 | 13 | **20** |
| **V4** 逐章复核（带本章正文）· 保守 | **+6**（调用翻倍） | 25.1s | 35 / 60 | 15 | **20** |
| **V4** 逐章复核 · 宽松 | +6 | 25.1s | 55 / 60 | 30 | 25 |

基线：60 条 / 判重已命中 31（51.7%）/ 抽取 385.1s。

### 2.1 三个致命问题

**① V1（最便宜的路线）整体报废**：模型把 60 条里的 **59 条**全判为泛称——`陈渊`/`青岚宗`/`混沌吞天诀` 一个不留。只有靠登记表兜底才救回 31 条。**单给名单、不给语境，模型等于在赌。**

**② V2 白跑 175 秒**：一条没判（输出 6,373 字全在解释）。同一模型、同一输入，第一轮实验（提示词里少了"不要因为名字像某类别就判泛称"那句）它剔了 33 条 —— 加了一句防过度删除的提示，行为直接翻到另一端。**提示词两句话之差，结果从"删 33"变"删 0"。**

**③ V3/V4 精度不足，且误伤落在核心元素上**：V3 与 V4 保守版都净剔 20 条，交集 16 条（说明有稳定的"泛称核心"），但这个核心里包含：

- `镇界塔`（镇压万族气运的塔，塔灵本体）
- `神契`（神族对苍澜大陆的控制契约）
- `叛神`（老瞎子的前世身份）
- `七道残简`（故事核心目标）
- `封仙路`（三千年被封死的仙界通道）—— 第一轮 V2 也剔了它

逐条判读：**精度约 60%**，约 8 条是真专名被误判。

### 2.2 一个指标陷阱（必须说明）

"兜底后保留里判重命中率 51.7% → 77.5%" **不是改善证据**：兜底把「判重已命中」的条目排除在剔除范围之外，分母自然变好，属**循环论证**。真实评价只能看上面的人工判读精度。

### 2.3 运行稳定性

同一模型、同一输入、同一批 60 条，三次独立运行的结果：

| 轮次 | 抽出条数 | 判重命中 | 耗时 |
|---|---|---|---|
| 第 1 轮 | 63 | 54.0% | 389s |
| 第 2 轮 | 60 | 56.7% | 496.9s |
| 第 3 轮 | 60 | 51.7% | 385.1s |

条数 ±5%、命中率 ±2.5pp、耗时 ±25%。**结论：任何小于 5pp 的"改善"都在噪声内，不能当成果。**

## §3 🔴 两个改变判断的发现

### 3.1 项目自己的登记表里**本来就有**泛称

标准答案（已登记设定）中：`演武场`、`杂役院`、`大比`、`残简`、`玄脉` —— 全是"任何小说都有"的词，**但作者确实把它们登记进了设定表**。

→ 「泛称 = 噪音」这个前提**要修正**。自动剔除会和作者既有的登记习惯打架：把作者本来就要的东西删掉。

### 3.2 真正的噪音是「同一实体的多种写法」

对基线 60 条做纯字符串分析（无模型）：

| 簇 | 组成 |
|---|---|
| 玄脉 | `玄脉` / `三品玄脉` / `四品玄脉` |
| 胎记 | `胎记` / `左腕胎记` / `暗金胎记` |
| 残简 | `残简` / `无名残简` / `七道残简` |
| 塔 | `镇界塔` / `青铜小塔` / `锈塔`（同一物件三种叫法） |
| 功法 | `混沌吞天诀` / `吞天诀` |
| 体质 | `混沌神体` / `神体` |
| 地名 | `南荒秘境` / `南荒`、`山门` / `山门口` |
| 家族 | `陈家` / `陈家先祖` |
| 同名异类 | `[地理]封仙路` + `[术语]封仙路`（同名两条并存） |

**9 簇 / 可合并冗余 12 条 / 占 20%** —— 比 C 净剔的 20 条只少 8 条，但**零幻觉、零额外调用、可单测、可复现**。

（注意：`陈家` vs `陈家先祖` 这类**不是**同一个对象，所以规则要带类型相容 + 长名是短名修饰位的判据，且**以「合并建议」呈现、由作者确认**，不做静默合并。）

## §4 建议

1. ✅ **保留 B**（已在），但**不要再往里加名字** —— 边际收益递减、成本线性上升。
2. 🔴 **C 不上"自动剔除"形态**：精度约 60%、误伤核心专名、提示词微调即行为翻转。
   若仍要 C，只能上**安全形态**：`登记表兜底` + **只降级不删除**（默认不勾 + 行内标注理由），且**固定提示词**保证可复现。收益是默认视图干净些；代价 +1 次调用 / ~15s。
3. ✅ **新增 D（确定性归并）**：把"同物多写法"合进一条（短名进 `aliases`），或以"合并建议"呈现。**这是本轮最确定的收益**。
4. 📌 评价口径固定为：**抽出条数 / 判重命中 / 耗时** 三项，且改动需超过噪声带（条数 ±5%、命中率 ±2.5pp、耗时 ±25%）才能算改善。
