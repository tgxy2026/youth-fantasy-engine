| 归档只读 | `endedAt` 落库；`send()` 守卫 + **整个输入区换成只读提示 + 新开一场入口** | TavernFree | ✅ |

> `runRoundEnd` 实装在 `src/lib/tavern/roundEnd.ts`：①记忆（**一次调用同时产出六栏档案 + 本场小结**）→ ②数值 → ③设定审查。
> 🔴 唯一的硬失败点是①；②③ 失败一律吞掉，面板少一块也不能把已落库的记忆弄丢。

### 3.1 两处实装时才定的细节（与草案不同）

1. **会话要存 `storyId`**。草案打算「按在场角色反推故事」，实装发现会自己搬家：角色卡被删或被改归属后，
   反推就得出另一个故事。所以 `FreeSession` / 索引项都加了 `storyId?`，
   反推只在旧会话（没有该字段）时兜底，见 `sessionStoryId()`。
2. **归档后不能只靠 `send()` 守卫**。输入框还活着的话，作者一定会敲下去，然后发现发不出去，
   只会以为软件坏了 —— 所以整块输入区换成只读提示 + 「新开一场」。

## 七、已确认决策（老大 2026-09-16 06:15 拍板）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 故事的数据归属 | **跨项目**（`db.meta`），与剧本/角色卡同性质 |
| 2 | 老库兼容 | **不需要**。测试阶段无保留数据，直接开发新功能，不做迁移 |
| 3 | 字段化范围 | **第二章、第三章全部字段化**（不分批试点） |
| 4 | 批次优先级 | **架构先行**（P0-A → B → C → D） |
| 5 | 用户扮演的角色 | 仅**状态区不显示**；记忆与日记**照常处理** |
| 6 | 结束本轮对话后 | 会话**归档只读**，后续在新建对话窗口开新对话 |

> 说明 5 的连带影响：`vars`（好感/心情）由 `extractSessionVars` 在整理记忆时一次算清，
> 而用户扮演角色的记忆仍要整理 → 其 vars 也会更新，只是**不在右侧状态区显示**。
