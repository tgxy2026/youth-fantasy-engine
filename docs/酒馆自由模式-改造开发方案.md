## 二、P0-B　角色卡：字段化 + 归属故事 + 日记

### 2.1 字段化（`src/components/TavernCard.tsx`，1048 行，本次最重）
按 §四 of 汇总文档：2.1 外在拆 `姓名/别名/年龄/性别/身份种族/外貌/体型/衣着/其他`；其余章节同类拆分；**每区块保留「其他」兜底**。
- 移除第1章「世界」整块 → 迁到故事层；卡内**只留「角色与设定的关系」**。
- 新建卡表单增「所属故事」下拉（必选）。
- 角色列表改树状：故事（父，并列）→ 角色（子）。

### 2.2 日记窗口
- 位置：角色卡最下方、**记忆之下**。
- 内容：每次对话发生的事件与总结，**不注入 AI**，仅供用户回顾。
- 存储建议：`tavern.free.journal.<charId>`（按会话条目追加），或并入 session。建议前者便于列表展示。

### 2.3 导入导出兼容
`cardFile.ts` 的外部格式需带上 `storyId` 与新增细分字段；缺 `storyId` 的旧卡导入时按待确认策略处理。

## 七、已确认决策（老大 2026-09-16 06:15 拍板）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 故事的数据归属 | **跨项目**（`db.meta`），与剧本/角色卡同性质 |
| 2 | 老库兼容 | **不需要**。测试阶段无保留数据，直接开发新功能，不做迁移 |
| 3 | 字段化范围 | **第二章、第三章全部字段化**（不分批试点） |
| 4 | 批次优先级 | **架构先行**（P0-A → B → C → D） |
| 5 | 用户扮演的角色 | 仅**状态区不显示**；记忆与日记**照常处理** |
| 6 | 结束本轮对话后 | 会话**归档只读**，后续在新建对话窗口开新对话 |

> 说明 5 的连带影响：`vars`（好感/心情）由 `extractSessionVars` 在整理记忆时一次算清，
> 而用户扮演角色的记忆仍要整理 → 其 vars 也会更新，只是**不在右侧状态区显示**。
