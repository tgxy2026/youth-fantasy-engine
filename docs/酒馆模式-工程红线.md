## 1. 导出文档（B5）

- `src/lib/tavern/exportDoc.ts`：**先建中立 DocModel，再渲染 md / html**。
  两种格式各自去读一遍会话，等于把「谁是说话人 / 隐藏消息怎么办 / 行怎么分类」写两遍 ——
  本项目对「两处各写一份必然漂移」已踩过多次（TavernMessage、paramGuide）。
  renderer **完全不认识** `TavernSession`。
- 行分类 `classifyTavernLine` 与界面**共用**：`TavernMessage.tsx` 只剩样式映射（`KIND_CLASS`）。

  只留 `prefers-color-scheme` 与 `@media print`；正文一律 HTML 转义（正文可能含任意符号，这是本节唯一真实风险）。
- Markdown **每行各成一段**（Markdown 会把相邻行并成一段，（动作）会跟对白糊在一起）；
  只转义行首 `#` / `>` / `1.`，正文里的 `* _ \`` 一律不动（那是作者的正文，替它转义等于篡改）。
- **默认导出已隐藏的消息**（隐藏＝"先别让 Ta 记得"，不是销毁）。
- 三页共用 `TavernExportDialog`，页面只传 `build` 回调 + 摘要文案 + 元信息项的叫法。

## 2. 头像（C3 轻量部分）

- `FreeCharacter.avatar` / `TavernProfile.avatar` 都是 dataURL，**必须先压缩再入库**：
  `src/lib/imageAvatar.ts` 的 `readAvatarFile` —— 居中裁方（`fitSquare`，不拉伸）→ canvas 缩到
  `AVATAR_SIZE = 256` → WebP（不支持回落 JPEG）；解码失败再回落原图（仍受 `AVATAR_MAX_INPUT_BYTES = 4MB` 约束）。
- 🔴 **压缩是硬要求不是优化**：桌面版整库一个 JSON、云同步载荷也是整库，2MB 原图 base64 后约 2.7MB。
  实测：**104KB PNG → 落库 15KB WebP**。
- 渲染统一 `Avatar`（有图用图、没图名字首字；首字用 `Array.from` 取，防 emoji 被切半）；
  设置统一 `AvatarPicker`（选完立刻清空 `input.value`，否则同一张图选第二次不触发 change）。
- 🔴 **图片规格说明的唯一真源**是 `AVATAR_HINT_SPEC`（imageAvatar.ts）—— 两处调用点不许各写一份，
  规格与实现不一致比没有说明更坏（作者会按错的比例裁图）。
- 头像改动走**显式保存**（与卡片其它字段一致），不是偷偷落库 —— 实机专门验了这条。
- 接入点：角色卡编辑区 / 卡片列表 / 自由对话气泡（多角色必挂、单角色仅设过才挂）/ 在场者一览 /
  记忆页签（仅设过才占位）/ 新建对话选角列表 / 「我的档案」。
- 老库兼容：`mergeDeep` 会把默认值里的新键照抄进去，所以 `TavernProfile.avatar` 自动补 `''`，不用写迁移。
- 回归：`tests/tavernAvatar.test.ts`（22 条）。

## 4. 示范卡「按来源标记」认卡（A 方案）
- `FreeCharacter.seededFrom`（值＝种子原名，如 `'洛汐'`）。播种 / 格式升级 / 「恢复内置版本」三处
  **都改成先按标记、再退回按名字**（`findSeedFor` / `isSeedCard`）。

## 5. 本场变量（C2 第二步）

- 集合：`VAR_KEYS` / `VAR_DEFS`（types.ts）—— **只有五个**：好感 / 信任 / 剧情进度 / 心情 / 当前地点。
  作者只能**逐项关闭**（`settings.vars.off`），不开放自定义：变量要进提示词，自定义数值没有语义
  （模型不知道「金钱 320」算多算少），开放自定义等于让作者去写协议。
- 存储：`FreeSession.vars`（**会话级**）。设置：`settings.vars = { enabled, off[], everyTurns, maxStep }`，
  默认 **开 / 每 3 轮 / ±5**。
- 🔴 **不进协议常量**：变量可开关（关掉就该一个字都不出现），而协议是固定常量、两模式共用。
  规则挂在自由模式的 `modeExtra`（`buildVarsBlock`），排在协议之前、离生成点很近；
  关掉时它返回空串 —— 顺带满足「空层不占额度」。
  规则只在「该请求增量」的那一轮出现（`shouldAskVars(turnSeq, everyTurns)`），其余轮次只给当前值。
- 🔴 **解析严格到宁可不认**（`parseVarLine`，四道闸）：
  ① 只认**最后一个非空行**；② 必须以 `〔数值〕` 开头；③ 每项必须是白名单变量（中文名或英文键）；
  ④ 数值必须带符号（`±N`）或直接赋值（`N`）。
  解析出 0 个操作 → **连那一行都不剥**。变量是锦上添花，正文是命根子。
  `〔数值〕无变化` 是**认得出**的写法：剥行、不产生操作（与"认不出"必须区别对待）。
- **唯一写入关口**是 `applyVarOps`：单步幅度先按 `maxStep` 夹取、再按 0–100 夹取；
  文本变量的长度截断**也只在这里**做（解析侧不各截一次，免得两处规则漂移）。
- 🔴 **重说**（`userText === null`）：先 `undoLastVarChanges` 退回上一次变化，再应用这一轮的新变化 ——
  数值不该停在"那个已经被丢掉的回复"上（实测 53 → 50 → +1 = 51）。
- 🔴 **顺序**：先解变量、**再**跑输出后处理（`postRules` 会把半角括号转全角、去 markdown 记号，
  万一动到那一行就再也解析不出来了）。
- 认不出数值行时只标记 `varParseFailed` 供界面提示，**正文原样保留**。
- 回归：`tests/tavernVars.test.ts`（62 条，含"认不出时一个字都不动""重说撤回""关掉开关后数值行原样保留"）。
- 待做：（已补齐，见 §6。）

## 6. 本场数值的界面（C2 第二步收尾）

**位置**：控制面板「**六、本场数值**」（右列，紧跟「五、自由对话控制」；原「六、预设方案」「七、输出后处理」
顺延为七、八 —— 改段落编号时记得把「恢复默认」「应用预设」两处文案里的段数一起改）+ 自由对话**状态栏**。

- 开关真源仍在设置层：`TavernVarsSettings{enabled, off[], everyTurns, maxStep}`；界面与引擎**共用**
  `varsEnabledKeys(st)` —— 别在组件里再写一份判定（两处不同就会出现「界面显示着、模型却不知道」）。
- 🔴 **作者手改与模型增量走同一个写入关口** `applyVarOps`：夹取 / 去重 / 变更记录只有一套规则。
  区别只有两点：① 手改是 `kind:'set'` 直接赋值，**不受 ±maxStep 限制**（那是给模型的刹车）；
  ② 变更来源标 `manual`。
- 🔴 **手改会清掉 `vars.prev`**（`recordVarChanges(..., 'manual')`）：作者的手是最终裁决 ——
  否则「手改 30 → 点重说」会把数值翻回模型算错的那个值，作者会以为软件在跟他捣乱。
- 认不出的输入（空、非数）**原样不动**，不当成 0（误把好感清零比不改更坏）；改成同一个值不记一笔
  （免得变动历史被灌水）。
- 「重置」＝把**启用中的**变量全部回初始值，弹确认（一次改 5 项，且数值回不去）。
- 状态栏数值块：值 + 进度条 + 最近差量（`lastChangeText`）+ 变动历史（展示最近 12 条，
  存储上限 `VAR_LOG_KEEP = 50`）。历史里区分「手改」与「第 N 轮」。
- 回归：`tests/tavernVars.test.ts` 第 8 组（手改 / 越界夹取 / 无效输入 / 重置 / 手改后重说不翻回）。

## 7. 剧本（自由对话专用）

**六栏**：名称 / 情境 / 开场白 / 你的位置 / 这一场的目标 / 不要发生 ——
＝ SillyTavern 的 `scenario` + `first_mes`，另加「目标 / 边界」两栏（调研结论见设计方案讨论稿 §1）。

- 🔴 **归属：全局 `db.getMeta`**（`tavern.scriptIndex` + `tavern.script.<id>`）—— 与角色卡同性质（玩法模板），
  **不绑某一本书**，换项目照样可用。
- 🔴🔴 **会话里存快照，不存引用**：`FreeSession.scriptId` 只作溯源，真正进上下文的是
  `FreeSession.script`（`snapshotOf()` 那一刻的六栏）。只存引用的话，作者改一次剧本，
  **所有历史会话的设定都会被悄悄改写** —— 这类问题几乎反推不到原因。
- 🔴 **注入边界**：情境 / 你的位置 / 目标 / 不要发生 → 进 `buildSystemPrompt` 的
  **「〖这一场〗」层**（排在设定层之后、记忆之前，空则整层不出现）；
  **名称与开场白不进 system** —— 名称是给人看的，开场白走**消息通道**（对话第一条）。
  开场白塞进 system 会让模型以为用户已经说过这句，还会白占每轮的常驻额度。
- 「六栏全空」＝ `isEmptySnapshot` ＝ 整层不出现（与其他层同一条「空的不占额度」纪律）。
- 与 `scene`（旧的手填地点 / 时间）的关系：**新建对话不再手填**，「② 对话内容」整段换成剧本选择器
  （留空 / 引用一份）；状态栏的场景行在没有 `scene` 时回落成 `scriptSceneLine()`（剧本名 + 情境首句）。
- AI 起草沿用背景设定那一套：`draftScript` + `parseScriptDraft`（复用 `parsePlainObject`，容错围栏 / 裹解释）；
  `mergeScriptDraft` 保证**AI 空着的栏不覆盖作者已写的**。空 seed 或模型乱答一律抛错，绝不写半截。
- 界面共用一份表单 `TavernScriptFields`（页签与「新建对话 → ＋ 新建剧本」弹窗），
  别各写一份（改一处忘一处的老问题）。
- 回归：`tests/tavernScript.test.ts`（47 条，含快照语义、注入边界、草稿合并、CRUD、引擎集成）。

## 8. 仓库纪律（2026-09-14 事故）

🔴 **本仓库禁用 `git stash`。** 事故当口正是一条 `git stash push` 被中断（SIGTERM），
随后发现 `.git/refs/` 整个目录消失、`objects/pack/*.pack` 两个包文件被移入回收站、
`9f780fa` 之后 **7 个提交的松散对象被永久删除**（未进回收站，无法找回）。
**代码内容零丢失**（工作区文件未受影响），丢的是那 7 个提交对象本身。

**取证与恢复流程（本次实际走通的路）**

1. `git` 报 `not a git repository` / `bad object HEAD` 时，先 `ls .git`：**查 `refs/` 与
   `objects/pack/*.pack` 是否还在**。
2. 回收站元数据 `$I*` 是二进制（8B 头 + 8B 大小 + 8B FILETIME + 4B 路径长 + UTF-16LE 原始路径），
   解析它就能知道**哪个文件的原路径**何时被删 → 本仓库的两个 pack 就在里面（`$R*` 是同名内容）。
3. 拷回 pack → `git verify-pack -v <idx>` 应报 ok；再逐个 `git rev-list --count <sha>` 找出
   **祖先链完整**的最新提交（本次 = `9f780fa`）。
4. 写回 `.git/refs/heads/main`；**`.git/index` 会指向已消失的 blob** → `git reset` 也会失败，
   必须 `rm .git/index && git read-tree HEAD` 重建。
5. 用工作区内容补一个「重建」提交，把丢失的提交内容合并回来（提交消息里写清丢了哪几个）。

**已做防护**：历史 bundle + 源码快照在 `G:/AI软件/novel-studio-git备份/`
（bundle `verify` 报 `records a complete history`，可独立克隆）。

⚠️ bundle 路径含中文时 `git bundle create` 会因无法建 `.lock` 而失败 →
**先建在纯英文路径，再用 `cp` 拷回来**（bash 的 cp 认中文路径，git 不认）。

⚠️ 这台机器上 `sort -n` / `sort -r` 有时会解析到 Windows 的 `sort.exe`（报「系统找不到指定的文件」）→
**用 node 脚本代替带参数的 sort**。

⚠️ 界面实机脚本里**别用「数 `六、` 的个数」判编号重复**：扮演协议正文自己带一节
「## 六、作者视角」，计数永远 ≥ 2（本轮假失败一轮）。要查重号就直接查那个标题字符串。
同理，断言「某段文本不含 X」时**必须把范围限定到那个 `<pre>` / 那个容器** ——
扫整个 `main` 会把页面上另一处**合法**的同名内容算进来（本轮又栽一次）。
