## 三、实测发现（逐条回源码验过）

### 🔴 真问题 · 已修：中文文本导出缺 UTF-8 BOM（4 处）

**症状**：用户导出的 `.txt` 用 Excel / 旧版 Windows 记事本打开是**乱码**。
**根因**：项目里文本导出各写各的 `new Blob([content])` —— 有的加了 BOM、有的漏了：

| 导出内容 | 位置 | 修复前 |
|---|---|---|
| 章节文本 / 表格 CSV | `exporter.ts` / `TableSheet.tsx` | ✅ 有 BOM |
| AI 使用情况说明 | `AiDisclosureDialog.tsx` | ❌ 漏 |
| 自定义敏感词 | `CheckTools.tsx` | ❌ 漏 |
| 投稿前自检 | `ManuscriptCheckPanel.tsx` | ❌ 漏 |
| 故事剧本 | `TavernScript.tsx` | ❌ 漏 |

**修法（不只补 4 个字符串，而是让它在结构上不可能再漏）**：在 `lib/zip.ts`（`downloadBlob` 的家）
新增统一入口 `downloadText(filename, content, mime?)`，内部加 BOM；四处调用点改走它。
> ⚠️ JSON / `.docx` / `.epub` **不走**这个入口 —— BOM 会破坏解析。
> ✅ 安全性已核实：敏感词导入侧用 `split(/\s+/)` 分割（JS 的 `\s` **包含 `\uFEFF`**），
>    故事剧本导入侧 `storyImport` 本就 strip BOM ⇒ 加了 BOM 不会破坏「导出→再导入」。

### 🔴 依赖供应链：27 个漏洞（**判定暂不升级**，见 §四）

### ✅ 现状良好（但原先无闸，现已纳入 `audit-sec`）

| 项 | 实测 |
|---|---|
| Electron 安全配置 | 主窗口 `sandbox:true, contextIsolation:true, nodeIntegration:false`；另一处 `sandbox:false` 属既有取舍 |
| 危险 API | `eval` / `new Function` / `document.write` / `child_process` / `shell.openExternal` **全 0** |
| 密钥边界 | `EXCLUDED_META_KEYS` 含 `aiProviders` 三键 ⇒ **不随云同步出界**；未发现密钥进日志/导出 |
| effect 清理 | 按 effect 粒度扫，**0 处**缺清理 |
| HTML 注入面 | 仅 `NovelEditor.tsx` 一处，内容经 `escapeHtml` |

## 四、依赖漏洞：为什么「记录」而不是「升级」

`npm audit` 共 **27 条**（critical 1 / high 19 / moderate 7）。逐条看过之后，**判定本轮不升级**，理由三条：

1. **全在构建工具链**：`dependencies` 为空，所有包都在 `devDependencies`（vite / tailwind / electron-builder /
   esbuild / tar / micromatch…）⇒ **不进产品产物**，最终用户不受影响。
2. **修复 = 一次大版本跳跃**，不是打补丁：
   | 包 | 实装 | 修复需升到 |
   |---|---|---|
   | electron | 31.7.7 | 44.5.1 |
   | vite | 5.4.21 | 8.3.3 |
   | tailwindcss | 3.4.19 | 4.3.3 |
   | electron-builder | 24.13.3 | 26.15.3 |
   其中 **Tailwind 4 是破坏性重写**（配置格式、默认行为都变），vite 8 亦然 —— 属「2.9 大版本」量级的工作。
3. **风险窗口有限**：这些包只在开发/构建时在本机跑，不接触用户数据；`tar`(critical) 影响的是
   electron-builder 解包路径（构建期，来源是本机缓存）。

**处置**：记入技术债，纳入 **2.9 大版本升级计划**；`npm audit` 纳入常规检查（`audit-sec` 不重复实现，
但在发布前清单里加一步手跑）。🔴 **下轮别再把它当「新发现」重复提案**。

## 七、第二轮（性能扩容 + 可观测性）

### 7.1 先修正一处**我自己的误判**

上一版报告把「性能 / 规模」写成「**无任何检测**」—— 这是错的，验尸后发现两条腿**都在**：
- `tests/perfBaseline.test.ts`：100 万字 / 300 章基线闸（15 项耗时断言，余量 20×~2000×，全绿）；
- skill 里的 `ui-perf-longbook.mjs`：真实浏览器侧的耗时（那半句「长篇不卡」的另一条腿）。

**真正的缺口不是「没有」，而是「新功能没进守护范围」** —— 基线停在 2026-09-22，之后新增的
2.7~2.8 路径（表格导入、语义切块、发布前自检）从未被盯过。

### 7.2 性能：先实测，再决定钉不钉（不盲目加断言）

| 新路径 | 实测（100 万字级） | 结论 |
|---|---|---|
| 全书切块（300 章 → 3328 块） | **3.6ms** | 正常，入基线 |
| 表格导入·解析（3000 行 TSV） | **0.8ms** | 正常，入基线 |
| 表格导入·表头映射 → 记录 | **1.9ms** | 正常，入基线 |
| 敏感词扫描（100 万字 × 千余词） | **256ms** | 正常但最重，入基线并**按本文件口径定阈值** |

⇒ `perfBaseline` 由 15 项扩到 **22 项**。

🔴 两处**测试写法**教训（不是产品问题，但会污染结论）：
1. **别把数据拼接放进计时函数** —— 第一版把 `chs.map(...).join()` 写在 `msOf` 里，量到的是「拼串 + 扫描」
   （262ms vs 真实 256ms）；
2. **`textToRows` 不是 TSV 表格映射器** —— 它是「纯文本兜底」（整段塞主列、逐行一条），
   我拿它测「表格批量导入」导致行数差 1（表头被当数据）。正确链路＝
   `parseImportText` → `mapHeaders` → `matrixToRows`。

🔴 `scanText` 的 256ms **判定不改**：它是「逐词 `indexOf`」（原生实现），复杂度 O(词数 × 字数)，
100 万字的**手动触发一次**动作，256ms 完全可接受；上 Aho-Corasick（多模式匹配）收益有限、复杂度高。
同理，该文件阈值从「实测 ×3」改回「实测 × ≈6」（`1500ms`）—— **遵守它自己写的口径**，避免抖动误报。

### 7.3 可观测性：`复制诊断信息`（本轮唯一新增的用户可见入口）

**现状空白**：只有渲染期 `ErrorBoundary`，没有全局错误捕获、没有日志导出 ——
用户遇到问题只能截屏，而作者最需要的信息（版本 / 系统 / 数据规模）往往要来回问几轮。

**做法（克制版：不加页签、不加设置项）**：
- 🆕 `src/lib/diagnostics.ts` —— `collectDiagnostics()` 采集「版本 / 系统 / 窗口 / 项目数 / 当前项目规模 /
  AI 配置概况 / 语义索引」七类信息；
- `AboutPage` 的「联系方式」段加一个 **`复制诊断信息`** 小按钮（`size=sm`，工具型）。

🔴🔴 **三条红线（写进模块顶部，改前必读）**：
1. **绝不包含作品内容** —— 章节正文 / 设定 / 角色卡 / 对话一个字都不带，只报「数量」；
2. **绝不包含密钥** —— AI 配置只报「几个模型、本地/云端各几个」；不报 `apiKey`、
   **不报 `baseUrl`**（URL 里可能内嵌令牌）、不报模型名（作者自定义名可能含隐私）；
3. **绝不包含绝对路径** —— 数据目录与系统用户名一律不带。

而且**每条红线都配了断言**（`tests/diagnostics.test.ts`，19 条）：其中 12 条是隐私断言 ——
「不含项目名 / 不含 http 地址 / 不含密钥式长串 / 不含盘符路径 / 不含用户名 / 不含 apiKey 字样」…
⇒ 将来有人加字段时**会被测试拦下**，而不是等到作者把诊断信息贴进群里才发现。

实机已在真实浏览器复验（`ui-about-diagnostics.mjs` **10/10**）：按钮在位、采集可跑、
🔴 三条红线在真机环境再验一遍（单测跑的是 Node，浏览器环境要另验）、点按钮有 toast 反馈。
