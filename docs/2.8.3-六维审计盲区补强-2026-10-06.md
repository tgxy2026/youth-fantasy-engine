## 二、新增的两支扫描器

都在 skill `novel-studio-audit-fix/assets/`，无参数即可跑（与既有八支同纪律：输出是**候选清单**，须验尸）。

### `audit-sec.mjs` —— 安全面 / 运行时资源 / 编码
| 节 | 查什么 |
|---|---|
| S1 | Electron `webPreferences` 三件套（`nodeIntegration` / `contextIsolation` / `sandbox`）逐个列出，危险取值单独点名 |
| S2 | 逃逸类 API：`eval` / `new Function` / `document.write` / `child_process` / `shell.openExternal` / 运行时 `require` 原生模块 / `exec()` |
| S3 | HTML 注入面：`dangerouslySetInnerHTML` / 裸 `.innerHTML =` |
| S4 | 敏感信息边界：同步排除表是否在位（密钥不得随云同步出界）、密钥类变量不得进日志/导出 |
| S5 | React effect 内 `addEventListener` / `setInterval` 是否都有清理或 `AbortController` |
| S6 | 文本导出是否带 UTF-8 BOM（Excel / 记事本乱码） |
| S7 | 安全关键模块的**消费者与测试覆盖** |

🔴 写这支时踩到并修掉的两个判据 bug（本身也是教训）：
- **`\bexec\s*\(` 会把满屏的正则 `.exec(text)` 全报成危险 API**（假报 14 条）⇒ 改为 `(?<![.\w])exec\s*\(`。
- **测试文件枚举必须排除 `.` 开头的构建产物**（`tests/.xxx.test.mjs` 是 esbuild 打出的**整份源码副本**）
  ⇒ 拿它判「有没有测试」**恒为「有」**，S7 静默失效。（与 skill 里「审计语料净化」那条同源。）

### `audit-coverage.mjs` —— 测试覆盖矩阵
- 判据：该文件是否被任何测试 import（路径命中）或按名提及。
- 只算**真测试（`*.test.ts`）与闸（`*-check.mjs`）**，排除构建产物、桩（`mock-*`）、运行器 ——
  桩文件也 import 产品代码，算进来会让覆盖率虚高。
- 输出分两类：**A 安全/数据/算法类**（优先看）与 B 其余（展示组件/类型/数据表，多数本就无需单测）。

## 三、实测发现（逐条回源码验过）

### 🔴 真问题 · 已修：中文文本导出缺 UTF-8 BOM（4 处）

**症状**：用户导出的 `.txt` 用 Excel / 旧版 Windows 记事本打开是**乱码**。
**根因**：项目里文本导出各写各的 `new Blob([content])` —— 有的加了 BOM、有的漏了：

| 导出内容 | 位置 | 修复前 |
|---|---|---|
| 章节文本 / 表格 CSV | `exporter.ts` / `TableSheet.tsx` | ✅ 有 BOM |
| AI 使用情况说明 | `AiDisclosureDialog.tsx` | ❌ 漏 |
| 自定义敏感词 | `CheckTools.tsx` | ❌ 漏 |
| 投稿前自检 | `ManuscriptCheckPanel.tsx` | ❌ 漏 |
| 故事剧本 | `TavernScript.tsx` | ❌ 漏 |

**修法（不只补 4 个字符串，而是让它在结构上不可能再漏）**：在 `lib/zip.ts`（`downloadBlob` 的家）
新增统一入口 `downloadText(filename, content, mime?)`，内部加 BOM；四处调用点改走它。
> ⚠️ JSON / `.docx` / `.epub` **不走**这个入口 —— BOM 会破坏解析。
> ✅ 安全性已核实：敏感词导入侧用 `split(/\s+/)` 分割（JS 的 `\s` **包含 `\uFEFF`**），
>    故事剧本导入侧 `storyImport` 本就 strip BOM ⇒ 加了 BOM 不会破坏「导出→再导入」。

### 🔴 依赖供应链：27 个漏洞（**判定暂不升级**，见 §四）

### ✅ 现状良好（但原先无闸，现已纳入 `audit-sec`）

| 项 | 实测 |
|---|---|
| Electron 安全配置 | 主窗口 `sandbox:true, contextIsolation:true, nodeIntegration:false`；另一处 `sandbox:false` 属既有取舍 |
| 危险 API | `eval` / `new Function` / `document.write` / `child_process` / `shell.openExternal` **全 0** |
| 密钥边界 | `EXCLUDED_META_KEYS` 含 `aiProviders` 三键 ⇒ **不随云同步出界**；未发现密钥进日志/导出 |
| effect 清理 | 按 effect 粒度扫，**0 处**缺清理 |
| HTML 注入面 | 仅 `NovelEditor.tsx` 一处，内容经 `escapeHtml` |

## 四、依赖漏洞：为什么「记录」而不是「升级」

`npm audit` 共 **27 条**（critical 1 / high 19 / moderate 7）。逐条看过之后，**判定本轮不升级**，理由三条：

1. **全在构建工具链**：`dependencies` 为空，所有包都在 `devDependencies`（vite / tailwind / electron-builder /
   esbuild / tar / micromatch…）⇒ **不进产品产物**，最终用户不受影响。
2. **修复 = 一次大版本跳跃**，不是打补丁：
   | 包 | 实装 | 修复需升到 |
   |---|---|---|
   | electron | 31.7.7 | 44.5.1 |
   | vite | 5.4.21 | 8.3.3 |
   | tailwindcss | 3.4.19 | 4.3.3 |
   | electron-builder | 24.13.3 | 26.15.3 |
   其中 **Tailwind 4 是破坏性重写**（配置格式、默认行为都变），vite 8 亦然 —— 属「2.9 大版本」量级的工作。
3. **风险窗口有限**：这些包只在开发/构建时在本机跑，不接触用户数据；`tar`(critical) 影响的是
   electron-builder 解包路径（构建期，来源是本机缓存）。

**处置**：记入技术债，纳入 **2.9 大版本升级计划**；`npm audit` 纳入常规检查（`audit-sec` 不重复实现，
但在发布前清单里加一步手跑）。🔴 **下轮别再把它当「新发现」重复提案**。

## 五、补测试：两个「不可逆 + 安全关键」模块从零到有守门人

| 模块 | 原状 | 现在 | 覆盖要点 |
|---|---|---|---|
| `lib/crypto.ts`（85 行） | **零测试** | 🆕 `tests/crypto.test.ts` **34 条** | 往返一致、信封格式（salt 16B / iv 12B / 版本位）、**错误密码必须抛**、**密文/iv 篡改必须抛**、salt 与 iv 不复用、边界输入（空对象/emoji/12 万字）、残缺信封、`isEncrypted` 判据 |
| `db/idbMigrations.ts`（253 行 / 11 段） | **零测试** | 🆕 `tests/idbMigrations.test.ts` **18 条** | 迁移链编号连续无跳段、`DB_VERSION` 与链尾一致、**每段都被 `core.ts` 调用且 import**、版本判断必须用 `<` 而非 `===`（`===` 会让跨版本升级跳段）、调用顺序递增、async 段必须 `await`、需要 `tx` 的段必须传 `tx`、`freshInstall` 建齐 store 与 `tabId` 索引 |

两者都刻意包含**「证明断言有判别力」**的对照项（如「正确密码仍能解开」证明「错误密码必须抛」不是假绿；
「至少存在一段 async 迁移」证明那条 await 断言不是空跑）。

> 为什么加密测试重要：加密写坏的方向是**静默返回垃圾** —— 用户以为备份是好的，等真要恢复时才发现。
> 为什么迁移测试重要：迁移**不可逆**且**只有老用户会触发**（新装用户走 freshInstall 永远看不到问题）。

## 六、判定不改（下轮别重复提案）

| 项 | 理由 |
|---|---|
| `flow/pipeline.ts:156` 的 `exec({...})` | 那是**项目自造的流程执行器**，不是 `child_process.exec` —— `audit-sec` S2 已加负向断言（前不能是 `.`）但仍会命中，属**命名撞车**而非风险 |
| `TableImportDialog.tsx` 的 `.md` 导入说明无 BOM | `.md` 是给编辑器/AI 读的，加 BOM 反而可能干扰部分 Markdown 解析器 |
| `BackupManager` / `App` / `ProjectHub` 的 JSON 导出无 BOM | JSON 规范不允许 BOM，加了会让解析失败 |
| `main.cjs:468` 的 `sandbox: false` | 既有取舍（该窗口需 node 能力）；已由 S1 每次列出，改动需单独评估 |
| `NovelEditor.tsx` 的 `dangerouslySetInnerHTML` | 内容经 `escapeHtml` 逐段转义（历史已判） |

## 七、留给下轮的（本轮未做）

4. **A 类里其余 10 个零覆盖模块**（`TableImportDialog` / `EvidenceExportDialog` / `backupReminder` /
   `webcrypto` / `syncStatusMeta` / `DesktopWriteLockBanner` …）—— 多为 UI 组件，价值低于本轮这两个。
