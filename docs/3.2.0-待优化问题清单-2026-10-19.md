## 一-a、OPT-011 社区反馈：网页版导出 ⇒ 桌面版导入失败

**反馈原文（主人 10-19 20:16 转达社区用户）**：「他在网页版导出的数据没办法导入到桌面版。」

**已知链路事实（待复现核实）**：
- 网页版导出入口：`WebDataBar`（左下角数据坞账号行的「导出」）。
- 桌面版导入入口：导入对话框（项目 JSON / 整库 JSON 两条路径）。
- 服务端 `PUT /api/data` 校验 `kind === 'portable-data'`（WEB 专项审计补的），
  导入链路同口径——若网页版导出产物与桌面导入器期望的 `kind`/`formatVersion` 不一致，
  就会整包被拒。
- 云端配额档位下，网页版**整库 JSON** 含 `portable-data` 信封；桌面导入器读的是什么形状需逐一比对。

**复现结论（2026-10-19 20:40，`verify-opt-011-web-export-desktop-import.cjs` 8/8 通过）**：

1. **整库主链路完全通**：网页云端态 `exportPortableData` 导出（信封
   `{app, kind:'portable-data', fileVersion:2, stores}`，含云端特有的 vec/kb stores，
   敏感 meta 已剥）→ 桌面态 `importDesktopData`（mock 主进程 IPC）**导入成功**。
   即"网页数据坞导出全部数据 → 桌面数据坞导入数据文件"这条正确路径没有故障。
2. **真实障碍是入口混淆**：网页版「项目中心」每本书的「导出」产出的是**单本书备份包**
   （`db.exportProject`：有 `project`、无 `kind`/`stores`），用户拿它去桌面「数据坞 →
   导入数据文件」会被拒，而旧提示只说"请选择便携版创建的数据文件"，**不指路**。
3. 次要候选：桌面版开着「云盘文件同步」时导入被拒（该提示明确，非缺陷）。

**已修复（指路，不改变两种包的语义）**：
- `storeOps.describeDataFileReject()`：识别单本书备份包 ⇒ 拒绝文案改为
  「这是单本书的备份文件（《书名》）…请到项目中心用『导入项目』…整体搬迁请用
  左下角数据坞的『导出全部数据』」；陌生 JSON 仍走通用拒绝（不瞎指路）。
- 桌面 `importDesktopData` 与网页 `importPortableData` 同口径接入；
  网页「项目中心 → 导出」toast 同步说明去哪导入。
- 单测 `tests/dataFileReject.test.ts` 13 条（含负向控制：文案不得误导成整库替换）。

**状态**：✅ **撤案（2026-10-19 21:03）**。主人转达：测试用户再次尝试后，跨版本导入导出正常，问题不再复现。

留痕：我方复现（8/8）证明整库主链路本就通，与用户复查结论一致；当时的失败大概率是
拿错文件（单本书备份）/ 桌面开着云盘同步 / 旧的错误印象，未取得具体报错，无法进一步定位。
**指路修复保留**（`7f3aa45`）：它不是为这个 bug 打的补丁，而是「拿错文件时告诉用户去哪导」
的体验改进，对同类困惑仍有价值。若社区后续再出现同类反馈，回来启用下方复现脚本。

## 二、逐条详情

### OPT-010 图鉴下拉选项：不能自定义新值、选不中候选外值

**主人原话（10-19 19:52）**：「图鉴模式中的下拉选项不能自定义新值，也不能选择在表格中自定义的新值。找时间纳入开发。」

**已核实的代码机制（2026-10-19，静态核查）**：

1. 图鉴详情编辑态的内置下拉是**原生 `<select>`**（`src/components/atlas/AtlasDetail.tsx:83`），
   选项仅取 `field.options`（`src/lib/atlas/types.ts:121`：内置列取 schema 选项、
   自定义字段取字段定义里的 options）⇒ **没有自由输入入口**。
2. 表格态单元格同样是原生 `<select>` + 同一份 `field.options`
   （`src/components/atlas/AtlasCellInput.tsx:99-108`）⇒ 表格侧**也不能**输入候选外新值，
   与图鉴行为一致。
3. 候选外的值**可能已存在于行数据**：CSV 导入（R09 只保类型不校验候选）、
   历史数据、或旧版直接录入 ⇒ 原生 select 的 `value` 不在 options 里时显示空/失配，
   作者看到的就是「选不中」。

**因此待开发时要确认的两点**（未核实，不写进结论）：

- a. 主人说的「在表格中自定义的新值」具体指哪条路径——若表格侧确有可输入新值的入口
  （与本次静态核查结论不符），需对照复现；若指「字段设置里给自定义字段加候选值」，
  则现象更可能是「加完候选值后，已填旧值的行选不中」（机制 3）。
- b. 产品口径要拍板：单选字段**允不允许自由输入**。注意 3.1.3 既有约定
  「AI 填写时单选不在候选里 ⇒ 跳过并提示」；若对人放开自由输入而对 AI 保持候选约束，
  两条口径需在字段设置里显式说明，避免又出现「看不见的栏位被悄悄填了」类纠纷（R12 同型）。

**建议开发方向（登记用，非方案）**：详情/表格下拉改「可选可输」控件（候选 + 自由值，
自由值落进行数据并提示「未加入候选值列表」）；或提供「把当前值加入候选」的一次性操作。
涉及 `AtlasDetail.tsx`、`AtlasCellInput.tsx`、字段设置三处，需同步单测与实机。

**状态**：✅ **已修（2026-10-19 21:40）**。

**真正的病灶（主人 21:03 补充后的准确描述）**：图鉴详情的**内置下拉用的是原生 `<select>`**，
只读 schema 预设选项；而表格模式的同一列走 **`CustomSelect`**（能新增自定义值、能看到别处加的值，
存储在 `customOption::<pid>::<tabId>::<列名>`）。两套控件 = 两套能力，这就是图鉴只能选预设的根因。

**修法**（提交见当日日志）：
- `AtlasDetail` 的内置下拉改走 `CustomSelect`（传 `tabId` + `colName=field.key`），
  与表格侧共用同一份存储 ⇒ 双向可见。
- `ResolvedAtlasField` 新增 `fixedOptions` 并透传列定义：**封闭枚举**（保密等级等，
  被 AI 预算排序与角色视角读取）仍不出现增改删入口，保住机器逻辑可识别性。
- `AtlasView` 给详情传 `tab.id`。

**验证**：`verify-opt-010-atlas-custom-option.cjs` 实机 **15/15** ——
图鉴下拉有「＋ 添加新值」、新增即选中、**表格侧已加的值图鉴能看到**、封闭枚举无添加入口、
保存后切表格值可见、无 pageerror。单测 `atlasCustomOptions` 9 条（含防回退静态闸）。

**未动**：图鉴/表格里的**自定义字段**（`cf_*`）下拉仍只认字段设置里的候选值 ——
那是 3.1.3 定的口径（AI 填写不在候选里跳过并提示），要放开得单独拍板，不在本次范围。
