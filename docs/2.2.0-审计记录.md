### P0-1 「切页签前落库」守卫是死代码 → 未保存改动静默丢弃

**位置**：`src/App.tsx:346,348,354` · `src/components/TableSheet.tsx:206,279-290` · `FormSheet.tsx:52-70` · `CharacterSheet.tsx:83-107`

**触发**：在表格 / 表单 / 角色卡页签里改内容后不保存，直接点侧栏切到别的页签。

**根因**：三个组件都写了「切页签前把上一页未保存草稿落库」的守卫，但 App 给它们加了 `key={tab.id}` ——
切页签时组件**整体重挂**，`useRef` 初值直接就是新的 `tab.id`：

```tsx
// App.tsx
return <TableSheet key={tab.id} tab={tab} … />

// TableSheet.tsx:281-283（永不进入的分支）
const prevId = tabIdRef.current        // 重挂后 = 新 tab.id
if (prevId !== tab.id && prevDrafts && Object.keys(prevDrafts).length > 0) { … }   // 恒假
```

**影响**：内存态草稿随卸载消失，无提示、无脏标记残留。注释自称「之前会静默丢弃」——
这个守卫就是为修它而加的，被 `key` 废掉了。

**验尸**：✅ 成立（已核对 `App.tsx` 三处 `key={tab.id}` 与 `TableSheet.tsx:206` 的 `useRef(tab.id)`）。

**建议**：把冲刷放进卸载清理
`useEffect(() => () => { if (dirtyRef.current) void save(dataRef.current) }, [])`；
或去掉 `key` 并保留 `[tab.id]` 分支。三组件同改。

### P0-2 `transientUnavailable` 单向闩锁 → 编辑进本地、又被云端旧快照回滚

**位置**：`src/lib/syncCore.ts:429,485,527,574,591,716` · `desktop.ts:427` · `db.ts:466` · `App.tsx:87`

**触发**：任何一次 push 返回 status 0（网盘客户端正占用同步目录 / 目录暂不可写 —— 代码注释自认常见）。

**根因**：该标志置位后几乎没有自愈路径。

- 置位：`:429`（pull 拿不到 code）、`:527`、`:574`
- 复位：`:422`（`ensureInit` 的 pull 成功分支）、`:699`（`configure()`，仅换目录/重开同步才走）
- `ensureInit` 被 `initPromise` 记忆化 → **正常使用中不再执行**
- `backgroundPull`（`:485`）又因该标志直接 `return` → **它锁死了自己**

```ts
// :485  拉取被自己挡住 → 无法靠成功 pull 自愈
if (!code || authFailed || transientUnavailable) return
// :591  push 也放弃，只调 fallback
if (authFailed || transientUnavailable) { fallbackHandler?.(snapshotOf(cache)); return }
// :716  包装层据此把读写全切到本地库
isCloudUnavailable: () => authFailed || transientUnavailable || Date.now() < rateLimitedUntil
```

**影响链（静默数据回滚）**：

1. 包装层把读写切到本地库（`db.ts:466`）→ 此后编辑只进本地、不再进 cache
2. 关窗/最小化触发的 unload flush 调镜像，而 `desktop.ts:427` 的 `bulkPut` 是**主键无条件覆盖**、无新旧判定
   → 用云端旧快照盖掉本地刚写的新记录
3. 紧接着 `App.tsx:87` 的 `flushDesktopSync()` 把它写盘

结果：**磁盘上不可逆丢失**，切回前台还会看到界面「跳回旧版」。

**验尸**：⚠️ 主体成立，**一处修正** —— 子代理称「唯一复位点在 `:422`」不准确，`configure()`（`:699`）也复位。
核心结论（正常轮询期间无自愈路径）不变。

**建议**：
① `backgroundPull` 在闩锁期仍周期性试拉一次（成功即复位）；
② 镜像改为「只补本地缺失主键、绝不覆盖已存在主键」，或按 `updatedAt` 判新旧。

### P1-5 `writeLocked` 未覆盖云同步入口

**位置**：`src/lib/db.ts:533-550` · `src/lib/desktop.ts`（仅 238/262/283/324/373 五处检查）

**触发**：数据文件读不出来（`writeLocked = true`）时开启云同步。

**根因**：`writeLocked`（红线：**读不出来就绝不落盘**）只覆盖了 desktop 的写路径，
**完全没覆盖云同步入口**（`CloudFileSyncBar` 不读它）。

**影响**：内存空库 → `captureSyncData` 抓到 12 个空数组 → 新目录为空 → 播种空载荷；
`pushNow` 守卫（`syncCore.ts:514`）因 `baseCache` 也为空而放行 → 云端多出 rev=1 空快照
→ 另一设备 `mergeCaches` 按「云端无该记录且本地未改」丢弃全部记录（`syncCore.ts:248-252`）
→ **两台设备一起变空**。

**验尸**：✅ 成立（已 grep 确认 `writeLocked` 在 db.ts 与 components 中 0 处引用）。

**建议**：`enableDesktopCloudSync` 入口查 `getDesktopState().writeLocked` 并拒绝；
守卫增加「本地文件被锁 → 拒绝任何推」。

### P1-9 模型能力条的「推荐值」在本地时自指空转

**位置**：`src/components/TavernControl.tsx:735,739,771` · `src/lib/modelCapacity.ts:240`

**证据**：

```
TavernControl.tsx:735  下面「上下文预算 / 上下文窗口 / 记忆三项 / 日记保留」的推荐值都跟着所选模型走

```

本地分支把**当前值原样回灌**做题 → `contextBudget` / `numCtx` 的「推荐值」恒等于当前值：

- `TavernControl.tsx:647-654` 的 `drift` 里这两项永远为 false
- `:739` 的按钮永久 disabled、停在「已是推荐值」

**影响**：本地用户（绝大多数）以为系统已按模型算出推荐、自己没偏离，实际是自指空转；
云端用户更矛盾：能力条说"窗口推荐值跟着模型走"，紧接着 `:774` 的 hint 却说"这里没有推荐值"。

**验尸**：✅ 成立（这是本轮新写的代码，属**文案与实现的语义偏差**；
设计上"本地不改用户预算"是对的，错的是文案承诺范围）。

**建议**：本地时对 `contextBudget` / `numCtx` 不产出推荐值（返回 `null`）；
能力条文案改为「**记忆三项与日记保留**按当前预算同比推荐；预算与窗口由你自己定，本地不代为更改」。

### 修正 1 · 降级：「日记保留」的天/条**语义等价，不是 bug**

- **原报**：P1「一处说条、一处说天，用户会按天理解而实际是场」

  `summarize.ts:56` 写「每条一行，格式 `- MM-DD：一句话`」。因此「保留 N 条」≡「保留 N 天」，**无行为偏差**。
- **处置**：降为 **P2「表述口径可统一」**。
  ⚠️ 若不复核，会白改一处，且可能把常量语义（`MEMORY_DIARY_DAYS`）改错。

### 修正 2 · 剔除：`TavernVarsPanel.tsx:96` 的 Enter 未挡 IME —— 误报
