## 1. A 档 · 把「填了却没人读」的登记字段接进校验（只提示、不改数据）

落点：`src/lib/continuityCheck.ts` —— 从 10 类检查扩到 **14 类**，新增 4 节（第 11~14 节），
并新增两个只读数据源（`geography` / `secrets`）。
🔴 **共同契约：只产出 `AuditIssue` 提示，绝不回写作者数据**（用例里有契约断言守着）。

| # | 检查 | 接的是什么死字段 | 判据（保守，宁可不报不误报） |
|---|---|---|---|
| 11 | 伏笔回收前置条件未铺就 | `foreshadow.回收前置条件` | ① 已回收但该列为空 → info；② 该列点名的 `F\d{3,4}` 伏笔仍未回收 → warn。⚠️ 注意：`foreshadowEngine:134` 那个**同名** issue 判的是「已回收却没埋设」，从不读本列的值 —— 本轮的才是真正兑现 schema tips 的那条 |
| 12 | 行程时间存疑 | `geography.距离与行程时间` | 相邻章换了「地理位置」、故事内时间只隔 ≤1 天、而目的地登记的行程 ≥2 天 → warn。🔴 日期或行程文本解析不出（如「半刻」「一炷香」）一律**跳过** |
| 13 | 爽点间隔登记不一致 | `hookpoints.距上个爽点间隔（章）` | 手填值 ≠ 程序按章节号算出的间隔 → info。只提示，**不自动回写** |
| 14 | 秘密计划揭晓章已到点 | `secrets.计划揭晓章节` + `泄露风险等级` | 计划「第N章」≤ 当前最大章号 → info；泄露风险为「高」时升为 warn。🔴 只认「第N章」，卷级表述（「卷五神族降世」）跳过 |

**新增工具**：`parseTravelDays()` —— 从自由文本解析行程天数；解析不出返回 `null`，
调用方必须跳过（**绝不能当 0**，那会把「没写」误判成「当天能到」）。

**覆盖率**：`tests/continuityFields.test.ts`（新增，15 条）—— 每条正面用例都配了
**「不该报的不报」的负向断言**，另有 1 条「跑完表格逐字未变」的契约断言。

## 2. B 档 · 分析结果落库 + 缓存（核心三项）

### 2.1 新增 `src/lib/checkLog.ts`

解决两个问题（正是梳理报告 B 档的两条）：
1. **结果算完即弃** —— 此前连续性校验 / 伏笔看板 / 本章体检的结果全活在组件 `useState` 里，
   切页签就重跑、关软件就蒸发，作者回答不了「这轮比上轮是变好还是变坏」。
2. **多入口重复计算** —— 检查工具页 / 稿件体检面板 / 编辑器弹窗 / 本章体检聚合各自重跑一遍。

做法：
- **落库**：每次真跑完记一条快照（统计值 + 前 12 条标题）到 settingsKV 的 `checkLog`，
  上限 240 条。🔴 刻意**不记全文** —— 体检结果若全文落库会变成"第二个数据源"，
  而它的价值只在趋势与回看。
- **缓存**：以 `project.updatedAt` 作数据版本，同版本内复用引擎结果。
  ⚠️ **已知取舍**（源码注释里也写了）：若某写路径没有 `touchProject`，缓存要到下次任意编辑才失效 ——
  代价仅是「体检提示晚一轮刷新」，**不影响任何数据**（这些引擎只读不写）。
- **兜底**：取不到版本号（`updatedAt` 为 0）时**跳过缓存**，避免 `0 === 0` 让缓存永不失效。
- **失败隔离**：记台账失败**绝不影响体检本身**（体检是主功能，台账是附属）。

### 2.2 四个入口统一切到包装

| 文件 | 改动 |
|---|---|
| `components/AuditModals.tsx` | 伏笔看板 / 连续性校验两处 → `foreshadowLogged()` / `continuityLogged()` |
| `components/ManuscriptCheckPanel.tsx` | 同上 |
| `lib/chapterCheck.ts` | 本章体检聚合里的两个引擎调用 → 同一包装（与上面共享缓存） |

### 2.3 让台账真正被用起来（否则又是一次「存了没人读」）

`AuditModals` 新增 `CheckTrendNote` 组件，在两个弹窗里各渲染一行：
「上次检查 N 条（3 分钟前）· 比上轮多/少 N 条」（增红降绿，持平中性）。
数据取自 `trendOf(engine)`；没有任何快照时整行不渲染。

### 2.4 帮助文案同步

连续性校验器的 help 与说明行原写「覆盖 **10 类**」—— 加了 4 节后必须同步。
已改为 14 类并把新增 4 条逐条写进列表（**承诺↔实现一致性**是本项目的老坑）。

**覆盖率**：`tests/checkLog.test.ts`（新增，15 条）—— 落库 / 缓存 / 趋势 / 项目隔离 / 清理。
🔴 「缓存生效」的判据刻意选的是**「第二次调用不新增台账」** ——
缓存是内部实现拿不到把手，而「没多记一条」是它唯一可观测的外部效果。

## 3. C 档 · 数据口径统一到单一权威

### 3.1 C1 · 角色出场分布改读「出场人物」登记列

`components/CharacterDistribution.tsx`
- **旧**：逐章扫正文，`countOccurrences()` 数名字出现次数。
- **新**：读《章节总表》各卷台账的「**出场人物**」列（`getAllChapterLedgerRows()` + `splitNames()`）。
- **理由**：登记列是全项目公认的出场口径 —— 一致性校验、AI 人物共现矩阵、情节推演读的都是它；
  本图先前另扫正文，两套口径必然分裂（正文提及 ≠ 出场：回忆、转述、别人提名字都会被算进去）。
  另外它是零成本的（不必把全书正文读进内存）。
- **语义变化**：矩阵从「提及次数热度」变为「该章有没有登记出场」（两态配色 + 图例 + 空态提示同步改）。
- 台账行 id 取 `ch-<章节id>`（与 `continuityCheck` / `PlotCanvas` 同款取法）。

### 3.2 C2 · 写作面板产量口径

`components/Dashboard.tsx`
- **旧**：统计卡「近 7 日产量」用《写作进度》的**手工登记**；码字日历 / 写作目标 / 创作复盘用
  `dailyStats`（**自动**）。同一面板两个「近 7 日」数字，作者无从判断该信哪个。
- **新**：统计卡改走 `autoWeekTotal`（`dailyStats`，权威口径）；
  「近 7 日写作字数」柱状图保留手工登记，但标题明确加「（手工登记）」、
  帮助文案写明它是**参考视图**；「创作健康提醒」里的无产量提醒也改用权威口径。
- **刻意不做**：没有删掉手工视图 —— 它回答的是「计划完成情况」这个不同的问题。

### 3.3 C3 + D4 · 隐藏列过滤统一（此前提为纯 bug）

问题：《地理风物》的「地图格子」（`gx,gy;gx,gy;…` 坐标串，界面隐藏）被当作正表列
**发进 AI 提示词与语义索引**，且三处过滤口径不一致
（`tableImportAI` 滤了 / `organizeRows` 与 `aiContext.renderTable` 没滤）。

修法：**不新抽抽象**，统一用全项目既有的 `!c.hidden` 写法（表格视图 / 导出 / 导入对话框等 10+ 处已如此），
对齐三处：

| 文件 | 改动 |
|---|---|
| `lib/aiContext.ts` `renderTable` | `.filter(c => !c.hidden)` 再加 `.map(c => c.name)` |
| `lib/organizeRows.ts` | `c.name !== '编号' && !c.hidden` |
| `lib/semantic/indexer.ts` `renderRow` | 新增 `hiddenCols` 参数，排除隐藏列 **+ 保密等级列** |

顺带把 `SYSTEM_META_FIELDS` 从 `aiContext` 导出给 indexer 复用（此前是私有常量）：
索引文本会经〖语义召回〗注回提示词，所以「不往提示词里写」的列在索引阶段同样要挡。

## 4. D1 · 写作进度开放只读注入（聚合摘要，不给逐日明细）

`lib/aiContext.ts` 新增 `buildPaceDigest()` + 头部 `〖写作节奏〗` 段：
- 近 30 日：有几天在写 / 合计字数 / 活跃日均
- 连续码字天数、窗口内最长断更
- 最近一次码字距今

- **数据源**：`dailyStats`（编辑器自动记录），不是《写作进度》的手工登记。
- 🔴 **只给聚合统计**（老大口径）——逐日流水对模型没用，既占预算又容易被当成需复述的内容。
- 🔴 **写入侧仍然不接 AI**（`aiScope` 的 `NO_AI_TAB_IDS` 与 `aiContext` 兜底循环的 `progress` 跳过**未改**）：
  那张表本就是纯统计流水，AI 无从代笔；这里只补**读取**侧。
- 按项目纪律同步了 `lib/aiDataSources.ts` 的 `project-diagnose` 条目
  （该文件头部明写「改 prompt 的数据来源时必须同步改这里」）。

## 4.5 E 档 · 单点功能打通（2.9.1 第二批，2026-10-08 追加）

E 档原本列了 9 个「测试很齐全、产品调用方却 ≤ 1」的模块。**本轮只打通两个**，
判据是「与日常写作流最相关、且不必新增产品决策」——其余见 §5。

### 4.5.1 `structurePace` → 写作面板「结构配比预警」

`components/Dashboard.tsx`
- **旧**：结构配比结论只在「检查工具 → 结构配比对照」里 —— 那是要作者**专门去开**的页面。
  而结构跑偏（中段塌陷、开局占比过大）属于「越写越看不出来」的问题，等想起来去查时往往已写了十几万字。
- **新**：明显偏移（引擎口径 |Δ| > 15 个百分点、且有 ≥10 章）时，在写作面板的
  「创作健康提醒」里加一行「结构配比有 N 个拍节明显偏移（…）」，并指路原面板看逐拍明细。
- 🔴 **同引擎、同模板来源**：模板取 `creativeSession.inputs.structureId`（与创意写作、
  结构配比对照共用同一份会话输入），不另建第二套存储。
- 🔴 **hooks 顺序坑**：`structureWarn` 用了 `useMemo`，**必须定义在组件任何 early return 之前**——
  第一版放错位置被 eslint 的 `rules-of-hooks` 抓住（这是它该抓的），已挪进 hooks 区。
- 顺带把「一切健康」的判据从 `weekTotal`（手工登记）改为 `autoWeekTotal`（权威口径），
  并把 `structureWarn` 纳入——否则会出现「结构偏移」与「一切健康」同时显示的矛盾（C2 的遗漏补漏）。

### 4.5.2 `platformCheck` → 导出「平台粘贴版」即预检

`components/ExportFormatDialog.tsx`
- **旧**：分平台投稿预检（按档位扫敏感词 + 标出该平台重点关注的类别）只在「检查工具」页，
  要作者专门去开 ⇒ 常见的结局是「导完才发现有几处要改」。
- **新**：在导出对话框的「平台粘贴版」页加「发布前预检」区块 —— 平台三档切换
  （通用 / 起点 / 晋江）+ 实时命中数（「命中 N 处，其中 M 处属该平台重点关注类别」）。
- 🔴 **只报数、不判定**：不给分、不说「能不能发」；逐处上下文与观察仍在原面板看
  （与 `platformCheck` / `platformRules` 的立场一致，那两个模块的立场断言也守着这条）。
- 🔴 全文用 `chapters` 直接拼，**不走 exporter** —— 免得开个对话框就要先把打包器拉起来
  （与文件里既有的「exporter 按需动态加载」约定同源）。

### E 档剩余 7 个模块的处置

| 模块 | 处置 | 理由 |
|---|---|---|
| `dataHealth` | 建议后续 | 「保存前自检」会进保存热路径（每次保存都要扫全库引用），需先实测性能；改挂「设定变更」页的冲突检查是更稳的落点 |
| `optimizeTicket` | 建议后续 | 与 B 档台账联动的价值在「按出现频率排序」，但排序口径（严重度 × 频次怎么加权）属产品决策，要先定 |
| `marketRadar` | 建议后续 | 挂「新建项目向导」是**选题阶段**的入口，涉及向导流程改动，宜单独排 |
| `readerProbe` | **建议不做** | 它是 AI 功能（需模型），而编辑器工具栏已有 13+ 个按钮 —— 再塞会让主界面变挤，收益不值 |
| `writingReview` | **不需要** | 复核后排除：它已经在写作面板（主面板）里，本就不属于「藏起来的能力」（E 档初判由子代理给出，此处更正） |
| `diagnostics` | **判定不改** | 人肉通道（复制诊断信息给开发者），本就不该做进流程 |
| `backup` | **判定不改** | 基础设施（App 启动时调用），不存在「复用面窄」的问题 |
