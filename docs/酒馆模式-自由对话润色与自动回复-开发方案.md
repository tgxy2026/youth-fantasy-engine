# 酒馆模式 · 自由对话「润色 / 自动回复」快捷按钮 — 开发方案

> 状态：**已开发完成（2026-09-17），待实机验收**。动酒馆任何功能前已读 `docs/酒馆模式-工程红线.md` §18.2/§18.3/§18.4/§18.10。
> 验证：tsc 0 错误、eslint 0 错误（11 条基线警告未变）、`tests/run-all.mjs` 43/43 通过（新增 `tavernFree.test.ts` 11 组 assist 断言全绿）。
> 目标：在自由对话输入框上方的 5 个快捷按钮之后，新增「润色」「自动回复」两个按钮。
> 两者共同点：**AI 实时生成文本回写输入框，绝不自动发送**；生成内容须与 AI 直接扮演回复**同格式**（动作/表情/环境用 `（ ）` 括起 + 对白，不含角色名前缀）。

---

## 1. 需求拆解与边界

| 按钮 | 触发前状态 | AI 做什么 | 落点 | 发送 |
|---|---|---|---|---|
| **润色** | 用户已在聊天框写了文本 | 读用户原文 + 角色卡/剧本/上下文，扩写润色成符合角色口吻、带动作表情环境描写的发言 | **覆盖**输入框原文 | 不自动发送 |
| **自动回复** | 输入框可能为空 | 结合剧本/上下文/角色卡，替用户扮演的角色写一句（小段）当下发言 | **填入**输入框 | 不自动发送 |

**角色卡 vs 档案的判定（核心）**：
- `session.userCharId` 有值 → 用户扮演一张**已建立角色卡** → AI 读取该卡（第2章人物档案 / 第3章行为规范 / 第4章示例对话）来写口吻。
- `session.userCharId` 为空 → 用户**没有角色卡**，只有控制面板「我的档案」 → AI **侧重故事剧本 + 对话上下文**，用档案里的身份/称呼/自我设定作口吻基调，不编造具体人物设定。

> 字段依据：`src/lib/tavern/types.ts:430` `FreeSession.userCharId?`；`engine.ts:494-496` `userChar = found.find(c => c.id === session.userCharId)`；`TavernFree.tsx:223/405` 已用同一字段区分「你演 X」与「你」。

## 2. 现有结构确认（改动落点）

| 文件 | 作用 | 与本功能的接口 |
|---|---|---|
| `src/components/TavernFree.tsx` | 自由对话页 | `quickActions` 数组（:915）、`fillInput`（:930）、`send`（:650）、`stop`（:942）、`streaming`/`abortRef` |
| `src/components/TavernQuickBar.tsx` | 快捷条组件 | `QuickAction` 类型（:17）、`onFill` 回调（:34） |
| `src/lib/tavern/engine.ts` | 引擎 | `buildFreeSystem`（:482，构造 system）、`runFreeTurn`（:661，调模型）、`buildFreeMessages`（:750，历史裁剪） |
| `src/lib/tavern/prompt.ts` | 提示词构件 | `renderFreeCharacter`（:399）、`buildUserProfileBlock`（:284）、`buildSceneDescriptionRule`（:332） |
| `src/lib/tavern/settings.ts` | 采样/预算 | `resolveParamsOf('free',…)`、`toOllamaOptions`、`historyBudget`、`timeoutMsOf`、`thinkOptOf` |

**关键事实**：`buildFreeSystem` 已经把「用户扮演的角色卡」做成 `〖用户扮演的角色 · X〗` 块注入 system，但**明确写着「不要代写、不要替 Ta 决定、也不要替 Ta 回答」**（`engine.ts:535-537`）。这正是两个新按钮要**突破**的红线——所以不能直接复用 `runFreeTurn`，而要给 `buildFreeSystem` 加一个 `assist` 模式翻转这段措辞。

## 3. 方案总览（三层）

```
[UI] 快捷条 +2 按钮
   │  click
   ▼
[UI handler] assistWrite(mode)         —— TavernFree.tsx 内新增
   │  校验 → 调引擎 → 流式写回 setInput
   ▼
[engine] runFreeAssist(...)            —— engine.ts 新增
   │  buildFreeSystem(assist) + buildFreeMessages(仅历史) + 末条指令
   ▼
[model] chat(provider, msgs, {onToken, think:false})
   │  流回 token
   ▼
[UI] setInput(buf) 节流刷新 → 用户手动改/发
```

复用点（不重造）：`buildFreeSystem` 已含故事世界设定层、剧本层、记忆层、协议(`PROTOCOL_CORE`)、客观描写规则——**格式对齐免费得到**，生成的台词天然符合协议 O1 / `buildSceneDescriptionRule` 的 `（ ）` 描写格式。

## 4. 改动清单

### 4.1 `TavernQuickBar.tsx` — 允许异步 `run`
`QuickAction.run` 当前是 `() => void`。改为可返回 Promise，使「点按钮 → 异步生成 → 回写输入框」成立：

```ts
export type QuickAction = {
  key: string
  label: string
  hint: string
  text?: string
  slot?: string
  run?: () => void | Promise<void>   // 原为 () => void
}
// 组件内： onClick={() => { if (a.text !== undefined) onFill?.(a.text, a.slot); else void a.run?.() }}
```
`TavernFree` 把 `disabled={streaming}` 改为 `disabled={streaming || assistBusy}`（见 4.3），避免两次生成并发。

### 4.2 `engine.ts` — ① `buildFreeSystem` 加 `assist` 选项
```ts
export async function buildFreeSystem(
  session: FreeSession,
  chars: FreeCharacter[],
  settings?: TavernSettings,
  opts?: { assist?: 'polish' | 'auto' },   // 新增可选第 4 参
): Promise<FreeSystemResult>
```
内部两处翻转（仅 `opts.assist` 为真时生效，原行为零改动）：

- **用户角色块**（`engine.ts:532-539`）：把
  `（仅供你理解对方是谁…不要代写、不要替 Ta 决定、也不要替 Ta 回答）`
  改为（assist 模式）：
  `（你正在**代这个角色撰写他这一轮要发送的发言**，请完全代入：用第4章示例对话的口吻、第2章人物档案的特质、第3章的行为规范来写）`
- **`userCharId` 为空时**（仅档案，`engine.ts:524-552` 的 `setting` 末尾追加）：
  `⚠️ 用户没有专属角色卡，只有「我的档案」。请主要依据故事剧本与对话上下文来组织这条发言，用档案里的身份/称呼/自我设定作为口吻基调，不要编造具体人物设定。`
- **`self` 块**（`engine.ts:572-577`）：assist 模式末尾追加任务说明：
  `【本次任务】你不是要回话，而是帮屏幕后的用户**写他这一轮要发送的内容**（以「用户扮演的角色」的视角与口吻）。只输出台词本身：动作/表情/环境写进（ ）里、对白直接写，不要加「角色名：」前缀，也不要加任何解释或旁白。`

### 4.3 `engine.ts` — ② 新增 `runFreeAssist`
```ts
export async function runFreeAssist(
  session: FreeSession,
  chars: FreeCharacter[],
  mode: 'polish' | 'auto',
  /** 润色模式传用户原文；自动回复传 '' */
  userText: string,
  cb: { onToken?: (t: string) => void; signal?: AbortSignal },
  deps: { chatFn?: ChatFn; settings?: TavernSettings } = {},
): Promise<{ text: string; modelName: string; fellBack: boolean }> {
  const st = deps.settings ?? await getTavernSettings()
  const { provider, fellBack } = await resolveTavernProvider(session.model, st.common.defaultProviderId)
  const { system } = await buildFreeSystem(session, chars, st, { assist: mode })  // 翻转措辞

  // 历史只取 session.messages（不含用户的"待润色原文"作为 committed 消息）
  const historyBudgetChars = historyBudget(totalBudget(st.common.contextBudget), system, '', st.common.fixedOverheadChars)
  const { messages } = buildFreeMessages(session.messages, session, chars, historyBudgetChars)

  const instruction = mode === 'polish'
    ? `【润色指令】用户已写原文：「${userText}」。请在保留其意图与关键信息的前提下，扩写润色成符合角色口吻、含动作/表情/环境描写的发言。只输出润色后的台词本身。`
    : `【代写指令】用户还没想好这一轮怎么回。请根据当前对话上下文、故事剧本、你的角色设定，替用户扮演的角色写一句（或一小段）自然、符合当下的发言，含动作/表情/环境描写。只输出台词本身。`

  const p = resolveParamsOf('free', st, session.params)
  const { temperature, ...extraOptions } = toOllamaOptions(p)
  let text = ''
  await (deps.chatFn ?? chat)(provider, [...messages, { role: 'user', content: instruction }], {
    timeoutMs: timeoutMsOf(st),
    temperature, extraOptions,
    signal: cb.signal,
    onToken: (t) => { text += t; cb.onToken?.(t) },
    think: thinkOptOf(st),   // 同 runFreeTurn：陪伴要"像人说话"，不分析腔
  })
  // 🔴 不套用 postRules：润色/自动回复是用户的草稿，套规则会篡改其本意；用户发送前还会再编辑
  return { text: text.trim(), modelName: provider.model, fellBack }
}
```

### 4.4 `TavernFree.tsx` — ③ 新增 `assistWrite` handler + 加两个按钮
```ts
const [assistBusy, setAssistBusy] = useState(false)

const assistWrite = useCallback(async (mode: 'polish' | 'auto') => {
  if (streaming || assistBusy || !session) return
  if (mode === 'polish' && !input.trim()) { showToast('输入框是空的，没有可润色的内容', 'info'); return }
  if (session.endedAt) { showToast('本轮对话已结束（只读），请新开一场', 'info'); return }
  const original = input
  setAssistBusy(true)
  const ctrl = new AbortController(); abortRef.current = ctrl
  let buf = ''
  try {
    const cast = castCards.length ? castCards : (charCard ? [charCard] : [])
    const res = await runFreeAssist(session, cast, mode, mode === 'polish' ? original.trim() : '', {
      onToken: (t) => { buf += t; setInput(buf) },   // 节流刷新见 §5
      signal: ctrl.signal,
    })
    setInput(res.text.trim())                        // 最终以 trim 后为准
  } catch (e) {
    if (isCancelled(e)) setInput(buf)               // 取消：保留已生成的部分
    else {
      showToast(`生成失败：${e instanceof Error ? e.message : String(e)}`, 'error')
      if (mode === 'polish') setInput(original)      // 润色失败：还原原文
      else setInput('')                             // 自动回复失败：留空
    }
  } finally {
    setAssistBusy(false); abortRef.current = null
  }
}, [streaming, assistBusy, session, input, castCards, charCard])
```
> 需从 `engine.ts` 导出 `runFreeAssist`、`isCancelled`（已在 engine 内部用 `import { isCancelled } from '../ai'`，直接复用同源导入即可）。

**加按钮**（排在现有 5 个之后，`quickActions` 数组末尾追加）：
```ts
{ key: 'polish', label: '润色', hint: 'AI 读取你已写的文本，结合角色卡/剧本/上下文扩写润色，结果覆盖输入框（不自动发送）', run: () => void assistWrite('polish') },
{ key: 'auto',   label: '自动回复', hint: 'AI 结合剧本/上下文/角色卡，替你扮演的角色写一句发言填进输入框（不自动发送）', run: () => void assistWrite('auto') },
```
**快捷条禁用态**（`TavernFree.tsx:1460`）：`disabled={streaming || assistBusy}`。

## 5. 流式写回输入框的节流策略

本地 27B 模型逐 token 调 `setInput` 会高频触发 `TavernFree` 整页重渲染。建议：
- 在 `assistWrite` 内用 `buf` 本地累积，每隔 ~120ms 或每累积 ~24 字符才 `setInput(buf)` 一次；生成结束再 `setInput(res.text.trim())` 兜底。
- 这样输入框里能看到"字一个一个长出来"的反馈，又不卡 UI。
- 若要更省，可改用 `requestAnimationFrame` 合并刷新。

## 6. 输出格式对齐（复用协议，不另起炉灶）

生成内容必须和 AI 直接扮演回复**同格式**，靠复用 `buildFreeSystem` 自带的三块保证：
- **协议 `PROTOCOL_CORE`**（O1 禁止角色名前缀、`（ ）` 描写约定）—— 已钉在 system 末尾。
- **`buildSceneDescriptionRule`**（客观描写：动作/表情/环境写 `（ ）`）—— 已按控制面板档位注入。
- **`buildUserProfileBlock` / 用户角色卡块** —— 提供口吻来源。

assist 模式只需在末条指令里补一句「动作/表情/环境写进（ ）里、不要加角色名前缀」即可，不重复定义格式规则（避免与协议打架，也符合 §18.10「反重复提示词只有钉在 system 末尾才有效」的纪律——我们不另起一套格式指令）。

## 7. 红线 / 边界自检

| 项 | 处理 |
|---|---|
| 绝不自动发送 | `assistWrite` 全程只 `setInput`，从不调 `send` ✅ |
| 绝不覆盖用户已锁定设定 | 仅写输入框（草稿），不落库、不写卡 ✅ |
| 归档态只读 | `session.endedAt` 时按钮禁用 + toast ✅ |
| 取消可中断 | 复用 `abortRef` + `isCancelled`，现有「停止」按钮对 assist 同样生效（需让停止按钮在 assistBusy 时也可见，见 §8 待确认③） |
| 本地模型零外发 | 复用 `resolveTavernProvider`（与聊天同一模型），不引入新网络 ✅ |
| 不改已有 5 按钮行为 | `buildFreeSystem` 第 4 参默认 `undefined`，`runFreeTurn` 调用点零改动 ✅ |
| 不污染记忆/日记 | assist 不调 `store.saveFreeSession`、不进 `refreshSessionVars` ✅ |

## 8. 待确认的开放问题（2026-09-17 已逐项确认）

1. **是否套用「输出后处理规则」(postRules)？** ✅ **确认套用**（`runFreeAssist` 复用 `applyPostRules`，与正常对话同一套、顺序即 `settings.postRules`）。
2. **流式刷新粒度**：✅ **节流 ~120ms**（逐 token 累积到 `buf`，每 ≥120ms 或生成结束 `setInput`）。
3. **停止按钮可见性**：✅ **`streaming || assistBusy` 时都显示**（停止按钮复用同一 `abortRef`，可中途取消生成）。
4. **纯旁观（userCharId 为空）时**：✅ **禁用「润色」「自动回复」两个按钮**（`canAssist = !!session.userCharId && messages.length>0`）。
5. **首轮对话（无历史）**：✅ **禁用两个按钮**（同上 `messages.length>0` 条件）。
6. **按钮规格/位置**：✅ 与现有 5 枚同走 `TavernQuickBar`（`variant="secondary" size="xs"`），排在之后；文案即「润色」「自动回复」。

## 9. 测试与验收口径

- **单元/集成**：`buildFreeSystem` 加 `assist` 参后——
  - assert assist 模式下 system 含「代这个角色撰写他这一轮」措辞、且**不含**「不要代写」；
  - assert `userCharId` 为空时 system 含「没有专属角色卡…主要依据故事剧本与对话上下文」；
  - assert `runFreeAssist` 的末条指令在 polish 时内联原文、在 auto 时不内联。
- **UI 实机（novel-studio-ui-livecheck）**：
  - 在输入框打一段简陋文本 → 点「润色」→ 输入框被覆盖为扩写版、**未发送**（消息列表无新增）、可手动编辑后发送；
  - 清空输入框 → 点「自动回复」→ 输入框出现 AI 写的发言、**未发送**；
  - 归档会话（endedAt）下两个按钮禁用；
  - 生成中点「停止」可中断，输入框保留已生成部分。
- **回归**：原有 5 个快捷按钮、正常对话、重说、结束本轮对话均不受影响（tsc + 现有 43 测试 + 实机）。
