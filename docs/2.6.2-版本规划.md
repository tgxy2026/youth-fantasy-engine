## 已定版条目

### E1 · 正文编辑器「撤销 / 恢复」按钮（量级：极小）

- **需求**：正文写作组正文编辑页签，给文本编辑器加显式的「撤销 ↶ / 恢复 ↷」按钮。
- **现状（已核源码）**：`NovelEditor.tsx` 是 textarea 纯文本编辑器；Ctrl+Z **已经可用**——程序化写入刻意走 `execCommand('insertText')` 留在浏览器原生撤销栈（该文件 107-149、849 行注释），`FormatModal` 排版同样吃原生栈。缺的只是按钮化 + 恢复（Redo）入口。
- **做什么**：编辑器工具区加「撤销 / 恢复」两个按钮，内部调 `document.execCommand('undo' / 'redo')` —— 直接驱动**原生撤销栈**，与既有 Ctrl+Z / Ctrl+Y 语义完全一致，不另建自绘撤销栈。
- **涉及模块**：`NovelEditor.tsx`（按钮 + 禁用态：栈空时置灰不做也可，保持简单）；无主进程/存储改动。
- **验收**：输入 → 撤销多步 → 恢复多步，与 Ctrl+Z / Ctrl+Y 行为一致；AI 插入、缩进（execCommand 写入的）均可被按钮撤销；`tsc` / `eslint` / 全量测试全绿；web 版同效。
- **🔴 中止判据**：无（改动面极小，失败即 revert）。

### E2 · docx 导出排版选项（量级：小~中）

- **需求背景**：社区想要「编辑器内选中文本调字号 / 段落对齐」。2026-09-28 主人哥哥定版：**放弃在编辑器内做**（textarea 富文本化是周级工程，且网文平台发布时会剥掉全部排版，价值低），真实诉求（导出给别人看时排版好看）转由 **docx 导出排版选项**满足。
- **现状（已核源码）**：`exporter.ts` 的 `exportDOCX` 是**手写 OOXML、零运行时依赖**；现有 `docxRun(text, bold)` / `docxPara(inner)` 两个组装函数，`styles.xml` 为空壳，正文无任何 pPr/rPr 样式。扩展点就在这两个函数——加参数即可，不必引 docx 生成库。
- **做什么**：导出 docx 时提供**排版选项**（一次导出内全局统一，不做选区级——编辑器内容仍是纯文本）：
  1. **正文字号**（默认 12pt 小四，可选 10.5/14 等）；
  2. **对齐**（左 / 两端对齐，标题恒居中加粗）；
  3. **首行缩进**（2 字符 / 无，默认 2 字符——与「平台粘贴版」A5 口径一致）；
  4. **行距**（1.5 倍 / 单倍）；
  5. **字体**（宋体 / 黑体，标题默认黑体）；
  6. 预设档：「网文投稿标准」（宋体小四 + 首行缩进 2 字 + 1.5 倍行距）/「紧凑阅读」/「跟随默认」。
- **技术落点**：`docxRun` 加 rPr（`w:sz`/`w:szCs`/`w:rFonts`），`docxPara` 加 pPr（`w:jc` 对齐、`w:ind` 首行缩进、`w:spacing` 行距）；选项通过参数对象传入 `exportDOCX`，调用方（导出入口 UI）加一个「排版设置」弹窗（可搜索下拉先例在 `TableRefSelect`，本处选项少用普通控件即可）；选项记忆走 `settingsKV`（项目级）或 `uiPrefs`（本机偏好，与既有惯例一致，开工时定）。
- **涉及模块**：`src/lib/exporter.ts`（OOXML 组装）、导出入口所在组件（弹窗）、`settingsKV`/`uiPrefs`（选项持久化）。
- **验收**：默认选项导出与**现状逐字节级观感一致**（不加选项时行为零变化）；每种选项组合在 Word / WPS 打开正常（字号/缩进/行距/对齐生效）；`tsc` / `eslint` / 全量测试全绿。
- **🔴 中止判据**：若 OOXML 手写样式在主流 Office/WPS 兼容性实测问题多（老版本 Word 打不开/样式丢失）→ 降级为「仅字号 + 首行缩进」两选项；再不行整项放弃，维持现状导出（零沉没成本，改动集中在 exporter.ts 一个文件）。
- **明确不做**：编辑器内富文本 / 选区级排版（本条目的由来，已定版放弃）；EPUB 排版选项（如需另立条目）；页眉页脚/页码（投稿场景用不上）。
