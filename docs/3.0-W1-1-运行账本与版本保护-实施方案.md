> 状态：**设计中 → 实现中** ｜ 编制：2026-10-10
> 定位：AI 可控性底座（第 1 批 P0 命门）。**在既有 preview / 轨迹上扩展，不另起炉灶**（§10.3 #1 结合点）。

---

## 1. 目标（§10.3 #1 原文要求）

1. **候选机制**：AI 先产出**候选**，作者确认后才写回正式作品，**不自动落库**。
2. **校验与写回**：字段登记 ＋ 采纳模式（identity / required / fkChecks）→ 采纳后**事务写入并回读**。
3. **版本保护**（🔴 有回归反例钉住）：**正文或上游设定变化后，旧候选不得覆盖作者编辑**。
4. **恢复**：章后候选中断后可从检查点恢复，**已有候选无需再次调用模型**。
5. **可检查**：上下文装配结果、运行证据、验收回执均可查。

| 运行账本 | —— | 🔴 **完全缺失** |

## 3. 设计

### 3.1 数据模型：新增 `aiRuns` 表（照 `tavernReports` 先例）

> 选**独立表**而非塞 `settingsKV`：账本是长期累积的一等记录（几百上千条），需按项目 / 时间查询索引，且要随项目同步与备份。

```ts
/** 一次 AI 任务 = 一条运行记录（持久化，重启不丢）。 */
export interface AiRun {
  id: string
  projectId: string
  kind: string            // 'creative' | 'rewrite' | 'continue' | 'ghost' | 'tavern-free' | ...
  title: string           // 界面显示名（如「创意写作」「第 12 章 整章改写」）
  status: 'running' | 'done' | 'failed' | 'aborted'
  startedAt: number
  finishedAt: number
  /** 🔴 版本基准：候选基于什么状态产出（版本保护的核心） */
  basis: AiRunBasis
  /** 候选摘要（只存引用/指纹/条数，**不存全文**，避免账本膨胀） */
  candidates: AiRunCandidateRef[]
  /** 调用账（给 §10.3 #6 消耗统计 + §14 拒答感知共用同一份） */
  calls: AiRunCall[]
  /** 验收回执 */
  outcome: { created: number; updated: number; skipped: number; failed: string[] } | null
  error: string
}

/** 版本基准 —— 判断「候选产出后，基准是否被改动过」 */
export interface AiRunBasis {
  /** 章级基准：候选覆盖到哪些章 + 当时的正文指纹 */
  chapters?: { chapterId: string; fingerprint: string }[]
  /** 上游设定基准：设定最后一次变更的版本戳（无则 null） */
  settingsRev?: number | null
  at: number              // 基准采集时刻
}

export interface AiRunCandidateRef {
  target: string          // 落点，如 'chapter:<id>' / 'table:characters' / 'outline'
  count: number           // 候选条数
  fingerprint: string     // 候选内容指纹（用于判重 / 恢复时比对）
  state: 'pending' | 'adopted' | 'stale' | 'discarded'
}

export interface AiRunCall {
  model: string
  ms: number
  promptTokens?: number
  completionTokens?: number
  finishReason?: string   // §14 拒答感知的判据来源（一并铺路）
  at: number
}
```

### 3.2 版本保护（本项「命门」）

- **指纹函数** `chapterFingerprint(ch)`：`sha256(title + content + wordCount + updatedAt)` —— 任一改动即变。
  （为何含 `updatedAt`：作者**手改后又改回同样内容**，也该视为"动过"，宁严勿松。）
- **候选产出时**：采集 `basis`（涉及章指纹 + 设定版本戳）写进 `AiRun`。
- **采纳前** `isBasisStale(basis)`：比对当前状态 → 任一指纹不符 ⇒ **候选标 `stale`，拒绝静默覆盖**；
  提示：「这版候选生成后，正文 / 设定已被改动，直接采纳会覆盖作者的编辑 —— 请重新生成或逐条确认」。
- 🔴 **不自动丢弃、不自动重跑**（沿用 `isSuspectRewrite` 的克制口径，与 §10.3 #4「失效不自动重试」一致）。

### 3.3 统一采纳入口 `adopt`

```
adopt(runId, candidates) → 校验 basis（未失效）→ 写库 → 回读校验 → 记账（outcome + 候选 state）
```

- **复用**现有着陆路径：表格/卡片走 `commitDraftRows`；章节走既有 `saveChapter` + `createSnapshot`。
- **不重造**一套写入逻辑，只在其外包一层「校验 + 记账」。

### 3.4 接线点（哪些任务入账）

| kind | 入口 | 候选 | 版本保护 |
|---|---|---|---|
| `creative` | `runCreativeWriting` | 设定 / 大纲 / 逐章 | ✅ 章指纹 + 设定戳 |
| `rewrite` | `chapterRewrite` | 整章改写稿 | ✅ 章指纹 |
| `continue` | `autoContinue` | 续写增量 | ✅ 章指纹 |
| `ghost` | `useNovelEditorGhost` | 伴写建议（**不落库**） | ➖ 只记账不保护 |
| `tavern-free` | 酒馆自由对话 | 轮次文本 | ✅ 会话水位线 |

## 5. 红线与风险

- 🔴 **改数据结构必问「写入侧都改了吗」**：新表 8 处登记一处不漏（见 3.1）。
- 🔴 **AI 只辅助**：候选不自动落库；失效**不自动重试**、**不自动丢弃**。
- 🔴 **不写「反检测 / 洗痕迹」**：账本只记录「怎么写的」，不做掩饰。
- ⚠️ **账本膨胀**：候选只存引用/指纹，不存全文；调用账可设保留上限（待定，先不做裁剪）。
- ⚠️ **同步体积**：`aiRuns` 参与 `.yfe` 同步会把账本写进网盘 —— 需评估是否改为**本地专属 store**
  （像 `backups` 那样，见 `LOCAL_ONLY_STORES`）。**倾向：本地专属**（账本是本机过程记录，
  跨设备同步意义低、体积高）。⚠️ 此点待实现 W1-1a 时定稿。

## 6. 验收

- **三闸**：`tsc --noEmit` / `eslint src tests` / 全量单测（`bash tests/run-batches.sh all`）。
- **负面对照**：注入「候选产出 → 改正文 → 采纳」→ 断言**被拒**（stale）；还原后 sha256 逐字节一致。
- **实机**：真 Chromium 驱动，走一次「创意写作 → 改一章 → 采纳旧候选 → 见到失效提示」。
