## 一、「整理关系」的材料上限变成旋钮

上轮把材料上限写死在代码里（每类 50 条 / 单条 130 字 / 开篇样本 1500 字 / 总量 8000 字 / 单表 20 条），
是明知短板：超长篇的关系召回会掉，而作者既看不到、也改不了。

**做法**：新增 `lib/bookbreak/relationMaterial.ts` —— 五个参数各自带 **label + 单位 + 上下界 + 为什么这么推荐**，
理由**直接显示在界面上**（不藏在文档里）。持久化到全局 meta，改一次记住；读失败回落推荐值（绝不因读设置挡住拆书）。

接线：`BookBreakPanel → runBookBreak({ relationMaterial }) → buildRelationDrafts({ limits })`，
面板上「调整材料上限」与「整理关系」开关联动，调过会标「已调整」，带「恢复推荐值」。
顺手把材料规模显示出来（节点摘要与草稿区文案都带「材料 N 字」）——作者刚调了上限，跑完总得看见调完是多少字。

### 推荐值不是拍脑袋，每条都写了理由（节选）

| 参数 | 推荐 | 为什么 |
|---|---|---|
| 每类实体条数 | 50 | 决的是「哪些角色进得了关系整理」；群像大长篇可调到 100~200。⚠️ 别调太小：**实测压到 10 条时，同一段文本一条关系都没整理出来**（名单里没那个角色，关系就落不了地） |
| 单条实体字数 | 130 | 一条实体带的信息越多，模型越能判断身份与立场（关系依据多半藏在这里）；调到 200+ 能带全外貌/境界/剧情作用，但材料成倍增长 |
| 开篇原文样本 | 1500 | 关系靠原文互动才看得出来；但它和实体清单**抢同一份额度**，长书里调大反而挤掉清单 |
| 材料总字数 | 8000 | 与模型窗口挂钩（材料 + 提示词 + 项目资料要留在窗口内）；本地 32K 窗口建议 ≤8000，云端大窗口可上调 |
| 单表关系条数 | 20 | 一次最多整理多少条；超出的再跑一次即可（已有条目会作为「不得重复」清单带上） |

**验证**：单测 11 项（钳制上下界与交叉约束、非数字回落、小数取整、保存/读回/恢复推荐，
以及「上限真的进材料」——同批实体按 5 条 / 30 条 / 限 2000 字三种设置，材料字数必须依次变化）；
Edge 实机 12/12（含真跑一次流水线并报出「材料 764 字」）。

## 二、保密等级 D·终结（弃用）

### 定义与硬保证

> **D = 终结（弃用）**：已经用完或不再使用的数据。**任何情况下都不提供给 AI 模型做参考。**

关键理解：**不是"排最后"，是压根不带**。它的定义就是"不再使用"，再喂给模型只会拿过时的结论
污染新判断（旧版设定、已废弃的路线、退场的人物）。

硬保证在 `lib/aiContext.ts` 的 `isPrunedForAI`（认裸键与复合键两种存储口径），**三处都过滤**：

| 入口 | 不过滤的后果 |
|---|---|
| 内容装配 `renderTable` / `renderCards` | D 级条目内容被当作参考资料（连「另有 N 条未列出」的计数都不该算它） |
| 姓名清单 `loadCharacterNames` | 它是 AI 整理的**候选值来源**，带上 D 就等于告诉模型「这个已弃用的人物还在用」 |
| 判重清单 `organizeRows` 的 `existingKeys` | 模型会以为"这条已登记过"从而跳过本该登记的新内容 |

另给 `rankOf` 一个大数（`D: 99`）当**第二道保险** —— 万一某处漏了过滤，它也会排到最后被预算先丢掉。
**与角色视角无关**：作者侧同样排除（这才是"任何情况下"）。拆书势力关系的候选名单（读《国家势力》）同样过滤。

### 锁定为固定枚举（不允许手动添加新值）

作者加一个自定义值、或把 S 改名、或把某档移除，**两套机器逻辑**就认不出来：AI 预算排序与角色视角可见性
（静默失效）。所以这类列必须是封闭枚举：

- `TableColumn` 新增 `fixedOptions`，schema 用 `cFixed()` 统一设置；六张表的保密等级列全部改用它
- `CustomSelect` 新增 `fixedOptions`：不渲染增 / 改 / 删 / 移除入口，底部换成一行说明
  （**不是静默变哑巴**），`submitDraft` / `submitRename` 另加防御性 `return`
- TableSheet 两处、SettingSearch 一处同步传参
- 顺手消除一处**硬编码副本**：`SettingSearch.CARD_SELECT_FIELDS` 曾自己抄了一份 `['S','A','B','C']` ——
  加 D 档时正是这里会漏，改为引用 schema 的 `SABC` 单一源

### 注解两字化（保持原意）

`S · 绝密（剧透管控）` → `（剧透）`；`A · 重要（主线关键）` → `（主线）`。`SABC_DESC` 与注释同步。

### 验证

- 单测 `contextRank` +10 项：档位常量含 D、S/A 注解两字、六个保密等级列都标了 `fixedOptions`、
  `isPrunedForAI` 认两种口径且不误伤其它档、**D 级表格行与角色卡都不进上下文**、
  对照 C 级仍在（证明不是整段没带上）、D 级不进姓名清单
- 全局排除项进界面：`AIDataSourceNote` 的「不读」清单固定追加 `AI_PRUNE_NOTE`（一处生效，14 个功能人人可见），
  `aiDataSources` 用例静态盯住这行渲染 —— 防重构时被删
- **负面对照**：`isPrunedForAI` 改成恒 false → `contextRank` 如期 FAIL（已还原）
- **Edge 实机 16/16**（含对照组）：五个档都在、两字注解、保密等级下拉**没有**「添加新值…」
  且有固定档位说明、**对照普通分类列仍可加新值**（证明没误伤别的列）、
  D 级真实数据不进 AI（用**只存在于该行的探针串**验证，改回 A 又可逆）、角色卡下拉含 D、问号气泡写明 D 级不读
