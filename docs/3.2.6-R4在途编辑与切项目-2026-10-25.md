# 3.2.6 · 在途编辑 / 切项目 / 关窗写失败（三端，2026-10-25）

> 承接 [桌面与云端四子场景](3.2.6-R4桌面与云端四子场景-2026-10-25.md)。
> 这一轮补的是 `storage.four-profiles` 里最后一块欠项：**保存在途时继续打字 / 切到另一本书 / 写失败时关窗**。
> web-cloud 早已有 `close-during-save`（真关页），portable / web-guest / desktop 三端此前一条都没有。

## 1. 三个场景到底在验什么

| 场景 | 危险的错法 | 断言（判据） |
|---|---|---|
| `inflight-edit` | 在途那笔把后来的字盖掉；或界面说「已保存」而最新一笔根本没发出去 | 最终落盘 = **最新那笔**；文件仍是完整 JSON；界面与磁盘一致；再等 2 秒不许被迟到的在途回包盖回旧文 |
| `project-switch` | 切走时那笔跟着项目一起丢；或者串写进另一本书 | 原书那笔**必须落盘**；另一本书内容与 `projectId` 一个字节都不许动；切回来读到的是新内容 |
| `close-write-failure` | 关窗把文件写半截；或者失败那笔被静默当成已保存 | 关窗后文件仍可解析、内容只可能是「关窗前那笔」或「关窗兜底那笔」；重开读到的与磁盘一致；不许再挂「保存出错」 |

## 2. 「在途」怎么造（这是本轮最要紧的设计）

三条探针都**不靠「等一会儿看看」冒充在途**，各自在自己的真实写入路径上造窗口：

| 端 | 注入点 | 为什么可信 |
|---|---|---|
| portable | `context.route` 延迟 `PUT /api/data` 4 秒，并记录每笔请求体与结束时间 | 请求轨迹能算出「改字那一刻这笔还在途」，不是推测 |
| web-guest | 把 `IDBObjectStore.prototype.put` 换成「立即返回、延迟落库」：`idb` 对非 `IDBRequest` 返回值直接 await（视为已接受），事务无挂起请求立刻 commit，真写入由探针在**新事务**里串行延迟执行 | 等价于「后端已收下、还没落库」；顺序与真实后端一致（先 A 后 B） |
| desktop | `bootstrap.cjs` 在**真实 `store:save` handler 内部**（与保存屏障同一处）加探针可控延迟 | `barrier.state.active === 1` 就证明有一笔保存在跑；IPC 结果与落盘回读都还是产品自己的 |

🔴 踩过的坑（写在这里省下一轮）：游客那版最初在「延迟落库」里又调了被打补丁的 `put`，
于是**自己重入自己** —— 每 3 秒排一笔、`tx.oncomplete` 照常触发、数据一笔都没落库，
表现成「最终内容一直是原始稿」。改成 `nativePut.call(...)` 才真的落库。

## 3. 三端各自的环境

| 端 | 服务/运行时 | 数据落点 | 真关 |
|---|---|---|---|
| portable | `scripts/portable-server.mjs --root <临时目录>` + msedge | 临时应用目录下的 `data/youth-fantasy-engine-data.json`（磁盘读回） | `page.close()` |
| web-guest | `server/index.mjs`（`/guest`，注册关闭）+ 持久化 profile | 真 Chromium IndexedDB | `page.close()` |
| desktop | 真 Electron（preload/IPC/文件系统），隔离 appData/userData，网络全断 | `userData/youth-fantasy-engine-data.json`（磁盘读回） | `app.close()` |

关窗一律是**真关页面/真关应用**，不派发合成的 `beforeunload`（那是自欺）。

## 5. 为什么不往 policy 里加格子

`policy.json` 的 `runtimeCases` 是**产品能力矩阵**（boot-store / write-failure / roundtrip / concurrency / network …），
加一条就等于宣布「四端都要过这套」。这三条场景目前只在三端取证完（web-cloud 的关页在途已在 `concurrency/web-cloud`），
为了「把格子点亮」去改 policy，是本末倒置 —— 上一轮 `concurrency/portable` 也是同一处理（无会话概念，不改 policy 凑格）。

所以走的是**契约**这条线：新增 `storage.inflight-portable` / `storage.inflight-guest` / `storage.inflight-desktop` 三条业务契约，
各自挂一个探针、一份证据校验器 `scripts/verify/inflight-evidence.mjs`（指纹、构建哈希、场景清单、检查项、artifact 哈希逐项核）。

## 6. 边界（别当已验）

- 安装包（`Setup.exe`）与实体设备仍未验：`storage.four-profiles` 仍报 blocked，**需封装口令**。
- 游客的延迟落库是**探针在 IDB 层造的窗口**，不是真实磁盘写慢；桌面/便携是真文件系统。
- 只覆盖「单窗口在途 + 切项目 + 写失败关窗」；多服务进程共享同一数据目录、sidecar 并发仍未覆盖。
- 真实输入法、U 盘拔盘、原生弹窗、真实模型调用仍不在本轮范围。
