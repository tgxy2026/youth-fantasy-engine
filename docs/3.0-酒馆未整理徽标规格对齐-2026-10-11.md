# 酒馆自由对话「未整理 N 轮」徽标 UI 规格对齐（3.0 收尾）

日期：2026-10-11
涉及文件：`src/components/tavern/TavernFree.tsx`、`tests/tavernTaskState.test.ts`

## 一、需求

> 酒馆模式中右上角显示未整理对话的轮数页面，ui 不美观，调整为与右侧功能按钮一致的规格，美观一点。

## 二、根因

`TavernFree.tsx` 的 header 是「标题 + 会话名 + flex 撑开 + 右侧按钮组」结构。
右侧按钮组统一规格为 `<Button variant="secondary" size="md">`，
而「未整理 N 轮」徽标是独立手写的 `<span>`：

```tsx
// 改前
<span className="rounded border border-amber/30 bg-amber/15 px-1.5 py-0.5 text-11 text-amber shrink-0">
```

对照 `Button.tsx` 的 size 基线：

```ts
const SIZE: Record<Size, string> = {
  xs: 'h-6 px-2 text-11',
  sm: 'h-8 px-3 text-12',
  md: 'h-9 px-4 text-13',   // ← 右侧按钮组用的就是这档
  lg: 'h-10 px-5 text-14',
}
```

| | 徽标（改前） | 右侧按钮（`size="md"`） |
|---|---|---|
| 高度 | 内容撑开 ≈ **18px** | **36px** |
| 内边距 | `px-1.5 py-0.5` | `px-4` |
| 字号 | `text-11` | `text-13` |
| 圆角 | `rounded`（4px） | `rounded-lg`（8px） |

⇒ 并排时徽标明显「塌一截」，视觉节奏断裂，这就是「不美观」的来源。

同 header 里还有一条同病相怜的文案（第 169 行）：

```tsx
<span className="text-11 text-amber/80">本轮已于 {agoText(session.endedAt)}结束（只读）</span>
```

## 三、施修

### 决策：保留 `<span>`，不改成 `<Button>`

源码注释明确写着这条纪律：

> 只提示、不新增入口 —— 整理仍走「结束本轮对话」。

徽标**不是可点入口**。若套上 `Button`，作者会本能去点它（`disabled` 态又会导致「点了没反应」的困惑），
与设计意图相悖。因此走「保留语义 + 对齐盒模型」的方案：**把盒子规格逐项对齐 `size="md"`，但仍是 `span`**。

### 改动内容

```tsx
// 改后 —— 盒子规格与 SIZE.md 同源，配色取 toggle 选中态令牌
<span
  className="inline-flex shrink-0 items-center justify-center gap-1.5 rounded-lg h-9 px-4 border border-amber/30 bg-amber/15 text-13 text-amber"
  title={`本场还有 ${n} 轮对话没进长期记忆 —— 点「结束本轮对话」才会整理（各角色记忆 / 日记 / 数值 / 设定建议）`}
>
  未整理 {n} 轮
</span>
```

```tsx
// 归档说明同步收口
<span className="inline-flex shrink-0 items-center rounded-lg h-9 px-4 text-13 text-amber/80">
  本轮已于 {agoText(session.endedAt)}结束（只读）
</span>
```

要点：

- `h-9 px-4 text-13 rounded-lg` —— 与 `SIZE.md` 逐项一致（**不写 `text-*` 之外的尺寸叠加**，遵 `Button.tsx` 的 U-2 口径）。
- `inline-flex ... items-center justify-center` —— 让文字在 36px 盒内垂直居中（`span` 默认 baseline 对齐会偏）。
- `gap-1.5` + `justify-center` —— 与 Button 的 `inline-flex items-center justify-center gap-1.5` 同构，
  多字符内容（如「未整理 12 轮」）不会贴边。
- 配色沿用 `border-amber/30 bg-amber/15 text-amber` —— 与 `Button` 的 `toggle` 选中态令牌一致；
  比右侧 `结束本轮对话`（`variant="danger"` 的实心红 CTA）弱一档，**不抢主操作视线**。
- 保留 `shrink-0` —— 防止窄窗口下被 flex 压缩变形。

### 为什么「顺手改归档说明」

两条文案同处一个 header、同一段逻辑分支（`endedAt` 互斥），规格不一致时不论哪个状态都有一条「矮一截」。
一并收口才叫「与右侧功能按钮一致的规格」。

## 五、教训

### 1. 跨行「邻近性」断言不要用固定字距

首版「不是 Button」的断言写成：

```ts
/className="[^"]*rounded-lg h-9 px-4[^"]*"[\s\S]{0,120}未整理 \{n\} 轮/.test(free)
```

意图是「className 后面紧跟文字 ⇒ 不是 Button 的 children 结构」。但**中间的 `title={...}` 整行超过 120 字符**，
断言**恒假红**（代码完全正确）。

改法：按**结构**找，不按字距 —— 从 `未整理 {n} 轮` 往回找最近的 `<`，判它是不是 `<span`。
这样与中间隔多少内容无关。

> 通用版：断言「A 紧邻 B」时，若 B 附近有不定长的属性/注释，一律改成「找结构锚点」而非「数字符距离」。

### 2. 3.0 G3 重组会影响实机脚本的动态导入路径

写实机脚本时 `import('/src/lib/seedData.ts')` → **404 失败**。
3.0 G3 重组后 `lib/` 顶层只剩 6 个门面（`ai` / `db` / `schema` / `schemaShared` / `types` / `constants`），
`seedData.ts` 已迁到 `src/lib/app/seedData.ts`。

同时踩到 API 归属错误：`listStories` / `createStory` 在 **`lib/tavern/story.ts`**，不在 `store.ts`
（`store.ts` 只管 char / session / memory）。

> **纪律复述**：实机脚本里的每一次动态 import 与 API 名，都要**先 grep 源码**再写，
> 别凭记忆 —— 这类错误的表现是「脚本报错」或「静默拿不到数据」，与产品 bug 极像。

### 3. 「不是按钮」的语义要专门钉一条断言

「盒高一致」的断言只能证明**长得一样**，证明不了**行为一致**。
若哪天有人图省事把它改成 `<Button disabled>`，「长得一样」的断言会全绿，
而交互语义已经变了（作者会去点一个不可点的东西）。

⇒ 单独钉一条「标签必须是 `<span`」，并用负面对照确认它会红。
