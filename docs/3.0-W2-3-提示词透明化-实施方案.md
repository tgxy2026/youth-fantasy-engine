## 一、目标（方案 §10.3 #5 原文口径）

1. 提示词**全透明可改**：内置任务提示词**可见、可覆盖**。
2. **创作规则**：作者写自己的写作要求。
3. **上下文查看**：可检查本次任务实际装配的上下文与**运行证据**。
4. AI 对话副驾：对话式辅助。

🔴 结合点（§10.3 #5 末）：*「已有自定义系统提示词 + `PROMPT_ORDER`（还原注册序）⇒
提示词库基于 `PROMPT_ORDER` 暴露并可覆盖，**保留内置默认且可复位**。」*

**⇒ 四条规格表面上都已具备。** 但深挖登记链路时抓到一个**真缺口**：

### 🔴 缺口：懒加载导致「提示词漏注册」

- `PROMPT_ORDER` = **34 条**，逐条走 `aiTasks.ts` 的中央注册循环 ⇒ 一定可见 ✓
- 另有 **6 条「就地注册」**（各自模块 `registerPrompt`）：`fill-template` / `fill-outline-master` /
  `fill-outline-volume` / `fill-outline-chapter`（`aiCore/prompts.ts`，被 `ai.ts` **静态** import ✓）/
  `setting-update-detect`（`autoContinue.ts` ✓）/ **`assist-planner`**（`components/AIAssist.tsx` 🔴）
- 而 `AIAssist.tsx` 只被 `components/InspireTools.tsx` import，**`InspireTools` 在 `App.tsx` 里是
  `lazy(() => import(...))`** ⇒ **只有打开过「灵感工具」页，`assist-planner` 才注册**；
  没打开过的作者，在「AI 提示词」设置页里**根本看不到这条**（`listPrompts()` 里没有它）。
- ⚠️ 更一般地：**任何在懒加载组件里 `registerPrompt` 的写法都会踩同一个坑**，
  而现有保护只有 `aiTasks.ts` 运行时的一句 `console.warn`（只管 `PROMPT_ORDER` 那一侧，
  且只在控制台，作者与测试都看不到）。

## 三、设计

### 3.1 W2-3a 消除漏注册（把提示词注册移出组件）

- 新增 `src/lib/aiAssistPrompt.ts`：`SYSTEM_PROMPT` 常量 + `getAssistPrompt()` / `setAssistPrompt()`
  + `registerPrompt({ id: 'assist-planner', … })`（🔴 **注册随模块加载即发生**）。
- `components/AIAssist.tsx` 改为 import 该模块的读写函数（行为一字不变）。
- 该模块由 `src/lib/ai.ts` **静态 import**（`ai.ts` 已是主链路的静态汇聚点，与 `aiCore/prompts` 同款做法）⇒
  **不论作者有没有打开过哪个页签，40 条提示词全部在设置页可见**。

### 3.2 W2-3b 注册完整性闸（单测 · 把运行时警告变成测试期硬断言）

`tests/promptRegistry.test.ts`：
1. **静态闸**：`components/**` 里**禁止**出现 `registerPrompt(`（源码扫描）——
   提示词注册必须落在 lib 层（静态可达）。
2. **一致性闸**：从源码解析出 `PROMPT_ORDER` 的 id 集合与各 `*_PROMPTS` 集合的 `id`，
   断言**双向包含**（既不许 `PROMPT_ORDER` 里有找不到的、也不许有没登记的）。
3. **关键条目在册**：断言 `assist-planner` / `fill-*` / `setting-update-detect` 都在
   静态可达的注册路径上（源码级）。
4. **可复位契约**：`PromptEntry` 必须带 `defaultText` / `overridden`（源码闸）。

### 3.3 ~~W2-3c 账本记「本次调用涉及的功能」~~ ⇒ **评估后不做**

原计划给 `aiRunLedger.createRun` 加 `feature?: string`（提示词 id），让账本能回答
「这次跑的是哪套指令」。**开工前实测后撤回**：

- 🔴 **全仓 `createRun` 只有 1 处调用**（`creativeSession.ts:537`）—— 账本目前**只有创意写作在建 run**，
  其余 AI 功能（审读 / 校对 / 改写 / 补登 / 整理…）根本不建 run ⇒ 加这个字段**只覆盖 1 条链路**，
  收益不抵改动面；
- 「上下文查看」这一条（§10.3 #5 第 3 项）**W1-2c 已经做完**，本节不是方案硬要求；
- 更合理的前提是「**让所有 AI 功能都入账本**」—— 那是独立一批的工作，届时把提示词 id 一并带上更自然。

（已征得判断后自行收敛范围，理由留档在此，避免下次重复评估。）

## 五、边界与红线（照做）

- 🔴 **不改任何提示词文本**（本节只动「注册位置」与「可观察性」）。
- 🔴 **不改 `PROMPT_ORDER` 的顺序**（它 = 设置页 UI 顺序，属既定界面）。
- 🔴 不改 `promptSettings` 的存储契约（避免丢作者已有的覆盖）。
- 🔴 账本**不存提示词全文**（只记 id + 是否改过）—— 防止第二数据源。
- 🔴 不动酒馆扮演协议的独立管理（它有自己的版本与出厂对照，HelpPopover 已明示）。
