# 酒馆模式 · 本轮改动实机验收清单（2026-09-16）

> 用途：13 条反馈全部改完之后，按本清单走一轮实机测试。
> 每条写清三件事：**看哪里** / **该是什么样** / **什么算不对**。
> 代码侧已过 `npm run verify`（tsc 干净 + eslint 0 error + 43/43 测试入口通过），
> 但**协议与提示词这两块必须用真模型跑一遍**才算验完（单测绿不等于模型听话）。

---

## 一、先做三件准备

1. 起本地 dev（`http://localhost:5199` —— 别用 127.0.0.1，那是另一份 IndexedDB）。
2. 想验**老数据迁移**（#3 的刻度归零）就别清站点存储；想从干净状态开始就清一次。
3. 控制面板里确认：模型选的是本地 Ollama；「八、本场数值」开关是开的。

---

## 二、逐条验收

### #1　聊天窗口上方不再有角色状态
- **看**：自由对话聊天区**正上方**。
- **该是**：只有标题栏与「想指挥他」提示，**没有**横着的角色状态条。
- **不对**：还挂着一条状态栏。

### #2　右栏统一为「角色状态 / 本场状态」双标签
- **看**：聊天区右侧那一栏。
- **该是**：顶部两个可切换按钮 ——
  - 「角色状态」：人物关系、关键事实、未爆的雷、纪念/待办、记忆条数 + 「N 人在场」总览；
  - 「本场状态」：好感 / 信任 / 精神 / 心情 / 地点 五项。
- **🔴 重点**：**只有 1 个 AI 角色时右栏也要出现**（旧版被「多角色才有右栏」的条件挡住 —— 这正是当初看不到数值的直接原因）。
- **不对**：单选一个角色时右栏整块不见了。

### #3　数值五项：新刻度、新名字、有档位
- **看**：右栏「本场状态」。
- **该是**：
  - 名字是 **好感 / 信任 / 精神 / 心情 / 地点**（不再有「剧情进度」「当前地点」）；
  - 三项数值 **−100 ~ +100、起点 0**；
  - 每项数值后面有一个**档位词**（中立 / 亲近 / 亲密依赖 / 反感 / 极度厌恶；精神那头是 崩坏 / 混乱 / 正常 / 清醒 / 澄澈），鼠标悬停显示这一档的行为说明；
  - 心情与地点仍是纯文字，没有刻度条。
- **老会话**：第一次打开会提示「刻度已改为 −100~+100」，三项数值归零、**心情与地点保留**；关掉再开**不该**再弹、也不该再归零（迁移幂等）。
- **控制面板对照**：「八、本场数值」的说明文案已同步成 −100~+100 与「精神」的说法。

### #4　每轮回复后数值自己动
- **看**：聊两三句，盯右栏「本场状态」。
- **该是**：每轮 AI 回复之后数值/心情/地点按剧情起伏；生成时状态提示会短暂显示「正在结算本场数值…」。
- **不对**：从头到尾一动不动 → 先查控制面板的「总结模型」是否可用（数值抽取是**单独一次调用**，失败会静默跳过，不拦对话）。

### #5　用量明细按「角色卡 / 故事 / 剧本 / 协议」拆开
- **看**：输入框下方「用量明细」。
- **该是**：自由对话页签下是五行 —— **角色卡（人设说明书）/ 故事的世界设定 / 本场剧本（这一场）/ 角色扮演协议 / 长期记忆**，外加「其他固定部分」兜底。
- **🔴 连带前置**：本次顺带补上了**故事的世界设定注入**（以前这层根本没进过 system，`getStory` 是零调用）。所以要一起验：
  - 新建对话时选了故事 → 「故事的世界设定」那一行**有字数**（不再是 0）；
  - 改了故事设定之后，**已建的那一场不受影响**（快照语义），新开的才用新设定；
  - 老会话（没有快照）实时读那份故事；故事被删就当没有这一层，**不该报错**。

### #6　「想指挥他」的复制按钮移到最左
- **看**：聊天区上方那三条指令示例。
- **该是**：**复制按钮在最左**，右边紧跟示例文本与说明。
- **两处都验**：剧情推演 + 自由对话（同一个组件，应当一起变）。

### #7　描写改第三人称（协议 v1.9）—— 本轮风险最高的一条
- **看**：AI 回复里所有**括号内的描写**。
- **该是**：
  - 括号里**不出现「我」「你」**：写名字、写「他/她」，或按中文习惯省略主语 ——
    `（把杯子推到她面前）✓` / `（我把杯子推到你面前）✗`
  - **对白里照常说「我」「你」**（这条限制只管括号里的描写）。
- **⚠️ 需要你知道的一处施工**：dev 那两张测试卡原来写的「人称：全篇固定第一人称『我』」与新规则**直接打架**
  （那正是模型把「我」写进描写的源头），所以这次一并对齐成
  「认知视角第一人称 + 描写第三人称」。
  **若你要的是全篇第一人称（含描写）**，那是另一种取向 —— 说一声，改回来。
- **还该看**：控制面板里的协议正文标题是 **v1.9**；存过 v1.8 全文的旧库会自动升级到 v1.9。

### #8　日记：只写 AI 角色 + 正常分段
- 用**用户扮演某个角色**的会话聊几轮 → 点「结束本轮对话」。
- **该是**：
  - 只有 AI 演的角色生成了日记，**用户演的那个角色没有日记**（记忆照旧更新）；
  - 日记是 3–6 个自然段，**不是一句一段**。

### #9　角色卡管理页：顶部也有一组动作按钮
- **看**：角色卡编辑页，左侧人物列表选中之后。
- **该是**：**上传图片按钮右侧**也有「复制为新卡 / 删除 / 保存」，与页面底部那组功能一致（同一份 JSX，两处不会走样）；未保存时两处按钮的可用状态**同时**变化。

### #10　AI 起草角色卡：以原型创建时内容更丰富
- **看**：用「以现实中 / 作品里存在的某个人物为原型」起草一张卡。
- **该是**：外貌细节、说话习惯、日常偏好、对别人的态度都写足了；不再出现大片「不详」「待作者补充」；重大设定（身世、结局、隐藏秘密）仍不编造。

### #11　结束本轮对话后卸载本地模型（默认**关**，需自己去开）
- **开**：控制面板 →「七、自由对话控制」→「收尾与释放」→ 打开开关。
- **看**：点「结束本轮对话」，等收尾三步（记忆/日记/数值/设定建议）全部跑完。
- **该是**：**收尾全部完成后**才提示「已让本地模型退出显存（下一场开场会慢一点）」；`ollama ps` 能看到模型已不在显存里。
- **不对（这两条都是硬约束）**：
  - 收尾**途中**就卸载 —— 后面还有模型调用，会让收尾变慢甚至失败；
  - 卸载失败把「结束」判成失败 —— 卸载失败只能提示，绝不能影响收尾。
- **云端模型**：开关开着也不会去卸（提示「没有可卸载的本地模型」），这是设计。

### #12　描写重复（**本轮未做**）
- 「指节因为过度用力而泛白」这类反复出现，属诊断类问题，按你的安排另开一轮。
- 已定位两个可能源头供接手者参考：① `paramGuide.ts` 的 `GUIDE_REPEAT_PENALTY` 推荐段「极轻 1–1.1」偏低；② 角色卡是否把某个小动作锚成了标志动作。

### #13　发送后输入框焦点不丢
- **看**：在输入框打字 → **回车**发送。
- **该是**：焦点**仍在输入框**，可以直接接着打下一句，不用再点一次。
- **顺带验**：生成过程中**允许继续打字**（只禁用发送按钮），不再整框变灰。
