## 1. 本版交付范围

- Windows x64 桌面版在「模型设置」提供 API 模式、MCP 模式、ACP 模式。ACP 模式下的「ACP Agent」首版只提供 Antigravity。组件位置、登录配置、模型和推理档位按适配器独立保存。
- 3.5.4 的 ACP 业务范围为作者手动发起、可独立完成、以正文或文本报告交付的纯文本功能。已完成的手动续写和选区润色继续使用现有预览与确认采纳流程。新增纯文本入口按第 3 节逐项核对和接入。
- **3.5.5 开发范围**包括依赖 JSON、固定字段或结构化落库的功能、后台伴写、酒馆和嵌入。选区润色继续保留已完成的 ACP 纯文本分支和 API JSON 分支。其他 ACP Agent 另行验证。便携版保留 API 和 MCP 两种模式，网页版沿用原模型入口。

稳定状态只接收当前模式的业务请求。切换或阻断期间只允许状态查询、取消和清理。切换须先记录并回读切换中状态，排空旧任务并确认运行时退出，再提交和回读目标状态。ACP 内切换适配器也走这套门禁，顶层仍为 ACP。桌面通用租约只接受 API 请求，MCP 与 ACP 租约分别由宿主和主进程创建。旧内部值 `agent` 保留，用户界面显示「MCP 模式」。

## P0 · Windows 文件隔离实测与选型（2026-11-13）

- **AppContainer**：容器内读写、越界读写阻断、子进程继承令牌、授权目录只读执行、出站 HTTPS、出站环回与同容器环回均通过。两项硬阻断：宿主机浏览器 → 容器内 OAuth 回调监听被 Windows 环回策略阻断（`-is` 对无包标识 AppContainer 挂起，入站防火墙规则无效）；Antigravity 1.5.0 的 PyInstaller 3.14 组件在容器内解包未完成即加载 `python314.dll` 失败。受限令牌（`S-1-5-12`）实测仍可读写用户目录。**结论：AppContainer 不适用于当前官方组件。**
