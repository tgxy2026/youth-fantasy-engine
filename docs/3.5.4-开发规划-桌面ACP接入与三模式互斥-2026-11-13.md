## 1. 版本目标

- Windows 桌面版内置通用 **ACP（Agent Client Protocol）客户端**，Google Antigravity 为唯一随版交付的适配器。模型设置从首版就提供「ACP Agent」选择入口，首版列表只有 Antigravity。以后新增通过验证的适配器，用户从同一入口选择或切换。每个 Agent 有各自的安装或检测、登录、模型和推理档位、连接状态及停用入口。
- **API 模式、MCP 模式、ACP 模式为三个互斥选项。** 桌面稳定状态只允许其中一种执行任务，切换和故障阻断状态下不接收三类新任务。
- 首批业务入口为正文手动续写和选中文本润色。保留现有生成预览、候选采纳及项目归属保护。结构化任务、嵌入、后台伴写、酒馆和其他 Agent 的兼容验证列入后续。
- 便携版继续提供两种连接模式，界面统一显示「API 模式」「MCP 模式」。网页版继续使用原有模型入口。本版的实际桌面交付目标为现有 Windows x64 安装包。

## 3. 三模式的执行规则

| 桌面状态 | API 调用 | 外部 Agent 的 MCP 业务工具 | ACP 安装／登录／选模／生成 |
| --- | --- | --- | --- |
| API 模式 | 允许，沿用原配置 | 拒绝 | 允许查看本机静态状态。联网安装、登录、建会话和生成需进入 ACP 模式 |
| MCP 模式 | 拒绝，含 API 模型列表、嵌入和联网检索 | 按既有项目授权及工具权限放行 | 仅可查看本机静态状态 |
| ACP 模式 | 拒绝，含后台自动触发 | 拒绝，在进入页面、写业务账本之前拦截 | 允许。组件缺失或未登录时可配置，生成需组件、登录和模型均就绪 |
| 切换中／阻断 | 拒绝新任务 | 拒绝新任务 | 拒绝新任务；允许取消和既有任务清理 |

**名称与兼容映射。** 「API 调用」改称「API 模式」，「Agent 模式」改称「MCP 模式」，新增「ACP 模式」。用户可见的设置、状态、切换与恢复提示、拒绝文案、帮助和发布说明统一使用新名称。内部模式值为 `api`、`agent`、`acp`，沿用 `agent` 读取旧记录及现有 MCP 接口。旧授权和连接配置可继续使用。「ACP Agent」是 ACP 模式内的选择项。

**模式和连接就绪分别展示。** 用户可先切换至 ACP，再安装和登录，避免要求「先登录才能切换、先切换才能登录」。安装、登录、获取会话选项和生成均归主进程管理，登记在同一模式的任务租约下。登录等待浏览器回调也占用租约。纯状态查询、既有任务取消和安全恢复有各自入口，不能启动业务任务。

切换沿用现有事务。主进程先记录并回读 `switching`，封住三类新任务，等待或由用户显式取消在途任务。离开 ACP 时须确认相关安装、登录、生成已停止，子进程及其受管后代已退出，再持久化并回读目标稳定状态。取消通知发出、窗口关闭、超时或收到最后一段文字，均不能单独作为释放租约的依据。切换失败、退出未确认或持久化异常进入 `blocked`，沿用用户确认后恢复到 API 的流程。恢复前核实旧 ACP 进程已结束，保留损坏记录、作品、API 配置和 Agent 授权。

### 切换、崩溃与恢复的实现约束

- **持久化提交点。** 切换事务依次执行「写入并回读切换中 → 停收新任务 → 排空或取消旧任务 → 确认来源运行时已停 → 提交并回读目标」。把取消与最终提交串行化。提交点之前接受取消，提交点之后返回已生效或待核对的状态。专测稳定记录写入后回读失败、取消与写入交错、提交前后强杀。凡无法确认的切换须留下重启可识别的阻断证据，覆盖当前实现只在内存置 `blocked` 的分支。
- **退出和进程所有权。** 现有 `before-quit` 的 5 秒兜底需要接入 ACP 关闭结果。模式锁释放必须晚于进程树退出确认。强退后若仍可能残留子进程，重启保持阻断，避免双实例；恢复按可核验的进程身份处理，避免只凭 PID 对旧进程下结论。静止的 ACP 模式重启后恢复设置，等待用户操作再启动组件。
- **租约与 IPC。** 现有桌面通用模式 IPC 允许渲染层传模式值，并使用固定租约所有者。桌面通用租约入口仅接受该入口原有的 API 用途，Agent 业务租约由宿主管理，ACP 租约由主进程按操作创建。ACP 的启动、取消、配置和结果订阅校验主窗口、顶层页面和会话代次，区分正式页面与开发来源。窗口销毁只触发取消，实际停妥后才回收租约。
- **MCP 兼容。** 桌面设置页和随包文档迁移到受控实时只读路径，保留外部客户端的配置迁移说明。验收覆盖旧桌面默认连接与显式指定实时库的官方入口，避免靠隐藏按钮实现互斥。用户自行复制的旧脚本或直接操作导出文件超出桌面宿主的控制范围；Agent 宿主状态、工具清单与历史回执可读，但三态只放行对应业务调用。

旧版稳定 `api`／`agent` 记录原样读取，首次初始化默认 API，升级不自动启用 ACP。优先沿用现有记录结构，让 3.5.3 遇到 `acp` 或未完成的切换记录时失败关闭。计划内降级先在 3.5.4 退出 ACP 并确认已切回稳定 API；异常降级走原有安全恢复。ACP 配置留在桌面本机，补丁的账号会话、组件路径和便携作品库无需迁入。

### ACP 模式内的 Agent 选择与切换

- **设置有两层选择。** 顶层在「API 模式」「MCP 模式」「ACP 模式」之间单选。进入 ACP 模式后，第二层从主进程提供的适配器清单中选择一个 ACP Agent，再选择该 Agent 的模型和推理档位。首版显示 Antigravity 为唯一选项，未适配的 Agent 不进入可选列表。新增适配器只需登记稳定 ID、显示名称、平台和能力，并实现发现、安装、启动、登录及选模，通用界面根据清单显示。
- **配置按 Agent 独立保存。** 本机记住所选适配器 ID，每个 ID 独立保存组件位置、模型和推理档位，并使用独立的组件登录配置与会话目录。切回此前的 Agent 时恢复其设置，重新确认登录和模型可用性。退出 ACP 后保留所选项，重新进入时由用户发起连接。已保存的适配器被移除或当前平台不支持时，提示重新选择，避免静默改用其他 Agent 或 API。
- **同一时刻只运行一个 ACP Agent。** ACP 内切换保持顶层模式为 ACP，主进程复用模式服务的租约与排空机制，在交接期间暂停全部 ACP 新操作，同时继续拒绝 API 请求和 MCP 业务工具。等待或由用户取消旧 Agent 的安装、登录、生成，确认其进程树退出后，才保存并回读新选择。旧会话和迟到回执失效，目标 Agent 按自身就绪状态显示安装、登录或连接入口。切换失败时明确显示最后已确认的选择和故障；旧进程状态不明时保持阻断。切换和退出 ACP 的请求由同一宿主串行处理。
- **首版验收实际入口和扩展机制。** Antigravity 走真实桌面配置流程。另用两个仅供测试的适配器验证清单驱动界面、双向切换、配置隔离和重启恢复。Codex、Claude Agent、Gemini CLI、OpenCode 后续分别验证登录、模型清单、纯文本约束和取消，通过后才加入正式列表。

### Antigravity 适配的待验证项

- **组件来源与版本。** 区分补丁采用的独立 ACP 二进制和 Google 文档中的 `agy acp` CLI，首版只选一个验证过的入口。登记实际组件与 helper 的版本、架构、摘要和可核实的签名，按该版本验收。补丁依赖滚动注册表，且已有组件仅检查文件名及存在性。正式适配须记录验证过的版本及来源，手选文件与自动下载采用同样的身份和路径核对，组件替换失败可恢复上一可用版本。
- **登录、停用与退出账号。** 单独展示组件已安装、已登录、选模成功、可生成。根据握手和会话返回值确认可用选项，拒绝失效模型；默认模型与用户显式选择分别处理。停用只关闭连接，退出账号需走官方注销能力或给出明确的官方操作入口。组件或账号变化后，使模型缓存及外发确认失效。只在可信浏览器入口处理官方登录，记录脱敏状态，不把 OAuth 链接参数或凭据交给业务页面。
- **子进程和数据。** 补丁会在收到取消指令时提前把运行标为取消，会在异常退出时清连接引用，也会把成功会话留给后续格式修复。桌面首版应把请求终态、会话回收和进程退出分别确认，处理无响应取消及清理重试，限制单条消息、总输出和保留会话数。补丁的独立工作目录、环境白名单和拒绝 ACP 工具只约束应用交互。真实组件的文件与进程权限须用隔离 Windows 环境验证，不能据此推定其无法访问同用户文件。
- **桌面载体。** 核对 `app.asar` 与外部 helper、解压脚本的实际落点。以 Electron 自带运行时为目标，在无系统 Node.js 的环境验证安装、登录和启动；避免把补丁中的 `ELECTRON_RUN_AS_NODE` 或 PowerShell 启动方式当成桌面必需条件。检查安装包增量及当前发布检查的体积上限。

### 两条写作入口与数据范围

首版定位到「正文编辑 → 颉文姬 → 编辑」的手动续写和选区润色，由 [颉文姬模型](../src/components/jiewenji/useJieWenJiModel.ts) 接到以下两条路径。以功能标识明确放行，避免把所有返回纯文本的调用都交给 ACP。

- **续写**走 [现行续写快照与执行路径](../src/lib/creative/continuationPlan.ts)。复用勾选资料、预算、流式预览、生成前快照核对和冲突时转候选审阅。需把 ACP 的能力与预算接到预览和发送两处，避免继续依赖 API 用途模型才可运行。
- **选区润色**当前走 [`aiRewritePassage`](../src/lib/aiTasks/jieWenJi.ts)，API 请求使用 `json-object` 并解析正文和修改说明。ACP 首版增加纯文本润色分支，输出映射到现有建议段的正文，修改说明可空。API 侧继续走原有 JSON 路径。现有采纳检查主要比对选中文本，还需记录并核对选区起止和草稿版本，覆盖同一段文字在两处重复时换选区的情况。

生成前展示接收方与本次资料范围。续写沿用勾选资料，润色仅发送选区、作者要求和实际选用的写作规范。ACP 的采样、上下文上限和用量按已验证的能力显示，缺失用量记为未知。发起时记录窗口、项目、章节、草稿或选区版本，收到结果及采纳时复核归属。用户显式采纳才写入编辑器。失败、拒绝、截断、取消和空结果分别反馈，流式片段可供核对，不能以完整结果采纳。

**发布前确认两项外部边界。** Google 的 ACP 文档介绍自定义客户端的接法，注册表将其组件标为专有软件。桌面包随附 YFE 接入层及其可分发依赖，Google 二进制由用户单独取得；若无法确认 YFE 场景可用的登录方式、分发范围或可靠的纯文本权限边界，适配器保留在受控联调范围，正式版入口保持关闭。首次联网生成前告知用户将发送的正文、设定与对话上下文，按任务只发送所需内容。Google 账号凭据留在官方组件管理范围，避免进入 YFE IPC、日志、云同步和作品备份。[ACP v1 握手](https://agentclientprotocol.com/protocol/v1/initialization) · [Google ACP 接入与登录](https://antigravity.google/docs/ide/extensions/acp/) · [官方组件注册表](https://raw.githubusercontent.com/agentclientprotocol/registry/main/antigravity-acp/agent.json) · [Google Antigravity 条款](https://antigravity.google/terms)

## 5. 验收矩阵与实施顺序

| 验收组 | 必测场景 | 通过条件 |
| --- | --- | --- |
| 模式矩阵 | 三个稳定模式各试三类真实入口，六个切换方向，快速重复点击、多窗口、第二实例、运行中切换、取消与重启 | 每次仅目标模式可接新任务；非活动模式未发出请求、未启用业务工具、未启动 ACP 进程；故障时能定位阻断原因 |
| 模式命名 | 桌面设置、状态、切换及恢复提示、拒绝文案和帮助；便携两项；升级含旧 `agent` 记录 | 桌面显示「API 模式」「MCP 模式」「ACP 模式」，便携显示前两项。旧 `agent` 显示为「MCP 模式」，原授权仍有效 |
| ACP Agent 选择与切换 | 正式界面仅列 Antigravity；两个假适配器双向切换，覆盖任务在途、旧回执晚到、退出失败、重启及已选适配器被移除 | 顶层始终为 ACP，旧进程确认退出后才生效新选择；各自的登录、模型和配置不串用，缺失适配器时提示重新选择 |
| 持久化与降级 | 从 3.5.3 稳定 `api`／`agent` 记录升级，模拟回读失败和切换中强杀，验证旧版打开 ACP 记录时的拒绝与恢复 | 任何未确认的提交或进程退出在重启后仍阻断；作品、授权、配置和账本核对通过 |
| MCP 与旁路 | 桌面随包新旧只读配置、写入工具、手工 IPC 调用、API 后台入口、便携直接请求 ACP | 所有受管业务在服务端门禁被拒绝或正确放行；拒绝项留有未读取作品、未写账本或未发出请求的证据 |
| 生命周期 | 登录回调晚到、生成取消、网络中断、组件崩溃、子进程退出失败、切项目／账号／窗口、关闭应用 | 旧结果不能写入新项目；切换须等退出确认；未结束的内容不得被标成完整或自动采纳 |
| 组件和安全 | 错误摘要、安装中断、旧组件仍可检测、架构不匹配、OAuth 回调、工具请求、非可信 IPC 来源、并发上限 | 文件与进程边界有正反两类证据；无凭据或稿件写入日志和作品备份；配置故障不损伤作品 |
| 业务入口 | 用合成作品跑续写和选中段润色，检查提示词范围、文本分片、预览、采纳、撤销与重启读回；覆盖同文不同选区、无 API 模型配置、原有 API 结构化润色 | 输出关联原项目和任务；采纳走现有编辑链。用假 Agent 覆盖错误分支，再用官方组件完成真实登录与生成复核 |
| 基线与安装包 | `npm run verify`、`npm run test:server`、`npm run build`、发布检查、六维审计；扩充 `agentModeExclusive`、`portableAgentHost`、`protocolDrivers` 和已安装桌面探针 | 当前候选的全量回归和桌面实装验收有独立记录；便携／网页旧路径无回归；构建、报告、安装包按同一提交核对 |

实施顺序为 **模式门禁与假 Agent → Antigravity 适配与权限验证 → 设置和两个创作入口 → 正式安装包验收**。组件适配预研可与假 Agent 开发并行；正式启用以实际使用范围、隔离验证和安装包验收全部达成为准。验收记录应列明候选提交、ACP 组件版本、实际可用模型、阻断证据和未覆盖项。规划阶段未运行旧补丁、登录真实账号或更改发布环境。
