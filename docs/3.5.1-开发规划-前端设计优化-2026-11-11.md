## 一、目标与边界

### 1.1 目标

在**不改变现有设计语言**（ink 墨阶 + amber 强调的令牌体系、9 套主题、字号阶梯 9–17、语义状态色）的前提下做「减法」与层级打磨，让作者少费神（更好用）、让门面与细节更耐看（更美观）。整体判断：设计地基已成熟（令牌化换肤、语义色 + 对比度闸、响应式专项、无障碍细节均已就位），本版是打磨而非重做。

主观巡检评分（复查台口径，供优先级参考，非量化门禁）：设计一致性 9.0 ／ 好用度 7.5 ／ 美观度 7.8 ／ 信息密度控制 6.5。密度与状态噪音是短板，故 P0/P1 向其倾斜。

### 1.2 本版不做（边界）

- 不改 ink/amber 令牌体系、不新增/删除主题、不改字号阶梯语义（A3 若需「增间距档」见 §六待决 2）。
- 不做社区功能逻辑变更（投稿/评论/排行/审核为 3.5.0 已交付能力，本版只动其**展示层状态与文案密度**）。
- 不做实名/合规/运营事项（属社区运营线，见 3.5.0 规划 §五，不在本版）。
- 不重构组件架构、不引入新依赖/新字体/新图标库（复用既有 `HelpPopover`、`Modal`、lucide 图标）。
- 不动服务端数据模型与接口契约；U5 的 auth 视觉统一仅服务端渲染页的**样式层**，不改登录/注册/找回逻辑。

### 1.3 形态覆盖

桌面 Electron ／ 便携 ／ 网页（云端账号 + 游客）／ 移动窄屏。注意：**便携版不支持投稿广场**（3.5.0 跨端决定），故 U1 仅适用桌面 + 网页；其余各条按形态适用性在验收中分别覆盖。

### U1（P0）广场离线 / 未登录：多横幅堆叠 → 单一可操作空态

- **现象**：同一「连不上 / 没登录」状态，外壳渲染 warn + error + notice + 未登录提示（最多 4 条），`FeedPanel` 与 `RankPanel` 又各自渲染一遍 error；且「未登录」这一**非危险**状态用了危险红，与项目「危险色禁常驻」原则相悖。作者首屏看到一屏警报，而非「下一步该做什么」。
- **证据**：`src/components/community/CommunitySquare.tsx:215-222`（外壳四条）、`src/components/community/FeedPanel.tsx:269`（重复 error）、`src/components/community/RankPanel.tsx:98`（重复 error）。
- **改法**：① 单一真相源——连接/登录状态只在外壳渲染**一条**中性（info）提示 + 明确登录 CTA；`endpointReady=false` 或未登录时子面板抑制各自 error（经 prop / context 下发抑制标志）。② 语义归位——「未登录」用 info/中性色，危险红只留给真实失败。③ 空态即引导——把「还没有已发布的投稿」换成「登录后能做什么 + 登录按钮」。
- **验收**：离线 / 未登录 / 已登录 / 广场关闭四态首屏横幅 ≤1；未登录不出现 danger 色；子面板不重复报错；连接恢复后自动加载；真实失败仍可见（不得误吞）；四主题对比度达标；窄屏不溢出。
- **风险**：低（纯展示层）。注意抑制重复报错时**不能吞掉真实错误**；便携版不适用本条。

### U2（P0）编辑器四栏挤压：章节标题变「第…」 → 标题优先 + 面板让位

- **现象**：1366–1440px 且「设定检索」中栏展开时，四栏（侧栏/章节/检索/正文）把章节标题列压到约 30px，`truncate` 后每行只剩「第…」，目录失去「凭标题找章」的基本功能；拉宽到 2000px 才恢复 ⇒ 空间分配优先级问题，非数据问题。
- **证据**：`src/components/editor/NovelEditorChapterTree.tsx:260-261`（标题 `truncate` + `title={ch.title}`）。
- **改法**：① 标题列设最小可读宽度（`min-w`），字数移到次行或悬停 tooltip，拖拽/删除图标悬停才显。② 设定检索/本章资料中栏在窄工作区改为可折叠抽屉或覆盖层，默认把宽度还给正文与目录。③ 断点自适应：<1500px 自动收起检索中栏（保留一键展开），与既有「窄工作区上下排列」口径一致。
- **验收**：1366/1440/1536/2000px × 检索展开/收起，章节标题可读（不截成「第…」）；正文宽度不回归变窄；双击改名、键盘焦点、拖拽排序不回归；3.5.0 窄屏上下排列专项不回归。
- **风险**：中（编辑器布局联动多）。需回归编辑器各面板组合与 3.5.0 窄屏专项；默认收起行为见 §六待决 3。

### U3（P1）说明文字墙：长段口径常驻表单 → 渐进披露

- **现象**：「类型赛道」把整段「作品题材 vs 类型赛道」口径（含 ⚠️ 与 🔴）常驻标签列，单行撑到约 8 行；酒馆「温度/核采样」把每个取值区间写成段落，两个输入框淹没在文字墙里。说明有价值，但不该默认全量铺开。
- **证据**：`src/lib/schemaTabs/part1.ts:23`（类型赛道整段 inline）、`src/components/common/SchemaFieldGrid.tsx`（inline 说明渲染）、酒馆控制面板温度/核采样区间文案。
- **改法**：① 短标签 + ⓘ（复用既有 `src/components/common/HelpPopover.tsx`）承载长口径，标签列只留一句必要提示。② 温度/核采样改「死板→保守→平衡→活跃→放飞」档位按钮 + 当前档说明，区间表折叠进帮助。③ 去掉信息性说明的常驻 ⚠️/🔴（与 A4 联动）。
- **验收**：表单行高恢复节奏；ⓘ 可键盘/触控展开且**口径信息不丢失**（尤其「类型赛道会随设定发给 AI」这类关键告知，移入帮助但保留一句首屏提示）；档位与数值双向同步；四主题 + 窄屏；文案经复核（口径是产品资产）。
- **风险**：中（文案迁移易丢信息）。需与 `docs/3.5.0-界面文案与手册复核-2026-11-10.md` 口径对齐，改后同步手册。

### U4（P1）首次进示例即弹备份催促 → 延后、非阻断

- **现象**：390px 首次进入示范项目立刻弹「导出一份备份吧 · 距上次导出超 7 天」**全屏模态**，盖住写作面板；对刚点「先看看示例」的新用户是第一次交互就被打断，且示范项目本就可随时删除，催促时机不当。根因：从未导出过则首次即弹，且 `shouldRemind` 无示范豁免。
- **证据**：`src/components/app/BackupReminder.tsx:42,61`（`shouldRemind` 命中即 `Modal`）、`src/lib/sync/backupReminder.ts:16,81`（`REMIND_AFTER_DAYS=7`、`shouldRemind` 无 demo 豁免）。
- **改法**：① 时机——示范项目 / 首次启动不弹模态，等用户真正写入自己的作品后再提醒。② 形态——改数据坞 / 侧栏**非阻断内联条**，「立即导出」降为可选动作。
- **验收**：新建示范 / 首启不弹模态；真实作品超期仍提醒（内联、可发现）；「稍后/导出」路径不回归；自动备份（每 5 分钟/每日）说明不丢。
- **风险**：低-中。备份是数据安全提示，**延后不能弱化真实超期提醒**，须保留可发现入口（见 §六待决 5）。

### U5（P2）网页入口：游客 CTA 层级 + 登录/重置配色统一

- **现象**：入口页整体精致（分栏叙事 + 插画 + 无障碍细节），但①多数新访客想先试用，「免费以游客身份开始创作」却是描边链接，实心金按钮「进入创作空间」（登录）更抢眼，主次略反；②重置页用另一套金/米色 + 深紫面板，与登录页护眼绿不是同一套视觉语言。
- **证据**：`server/lib/authPage.mjs:192`（guest 为 `<a class="guestBtn">` 描边链接）、`:170`（登录用 `AUTH_STYLE`）、`:43` + `:252`（重置 `renderResetPage` 用独立 `STYLE` 金/米 + 深紫）。
- **改法**：① 主次对调——游客试用作新访客主 CTA（实心），登录/注册收为次级、老用户一键直达。② 统一 auth 视觉——登录/注册/重置/找回共用 `authStyle` 一套令牌，去掉重置页独立配色。
- **验收**：入口主次符合「先试用」动线；重置页与登录同视觉语言；`forced-colors` / `reduced-motion` / `focus-visible` / aria 不回归；登录/注册/找回**功能**不回归（只改样式不改逻辑）；登录注册专项（3.5.0 为 169/169）重跑。
- **风险**：低（服务端渲染样式层）。注意 auth 页有既有专项与检查脚本，改后须重跑。

### A1（P1）项目中心：空封面 + 主按钮靠后 → 自动字封 + 清晰主次

- **现象**：单本书时项目中心大片留白，封面是虚线框 + 羽毛占位，缺乏「这是我的书」的质感；顶部按钮排把主操作「新建小说项目」放到第 5 位（创建示范/导入/投稿广场/云同步之后），视觉动线不顺。
- **证据**：`src/components/app/ProjectHub.tsx:312-343`（按钮排：创建示范 312 / 导入 315 / 投稿广场 318 / 新建 343）、`:601`（项目卡片）。
- **改法**：① 自动字封——无封面时按书名竖排 + 题材色生成排版封面（纯 CSS，无需 AI/图片）。② 主次前置——「新建小说项目」放第一位，低频操作收进「更多」菜单。③ 卡片增密——加「续写入口 + 最近活动 + 备份状态」，让单本书也撑得起门面。
- **验收**：0 书 / 单书 / 多书三态门面撑得起；字封四主题可读、长书名不溢出；主按钮首位且键盘可达；「更多」收纳**不丢功能**（创建示范/导入/云同步仍可发现，见 §六待决 4）；窄屏按钮排不溢出（保持 3.5.0 已修换行）。
- **风险**：中（按钮收纳降低低频功能可发现性）。需帮助文案/首次提示补偿。

### A2（P2）右缘吉祥物：idle 切片像被裁切 → 更可读的 peek

- **现象**：颉文姬精灵平时只露 `IDLE_VISIBLE=50px`（共 150px），立绘居中带透明边，右缘 50px 切片看不出是角色，更像一条被裁切的橙色异常，在编辑器与各页签右缘反复出现；项目中心整幅立绘很出彩，工作区 peek 反而削弱它。
- **证据**：`src/components/jiewenji/JieWenJiSprite.tsx:15-18`（`SPRITE=150 / TUCK=20 / IDLE=50 / HOVER=124`）。
- **改法**：① idle 露出约 80px 或改用头像/剪影，让人一眼认出是颉文姬。② 避让——不覆盖右缘滚动条与面板控件；窄屏自动收为小圆钮。
- **验收**：idle 一眼可认是角色；不压滚动条/控件；悬停全出、双击收进不回归；窄屏不遮内容；各页签右缘表现一致。
- **风险**：低-中（露出更多可能遮右缘内容）。需避让与窄屏策略。

### A3（P1）留白与密度：给密集信息一点呼吸

- **现象**：功能页信息量大是对的，但模块间距偏紧、说明与控件混排，长页一路滚下去缺乏视觉停顿，易疲劳。字号阶梯已收敛，下一步是间距与层级节奏。
- **证据**：`src/index.css` 字号阶梯（9–17）与模块间距；模型设置 / 酒馆控制面板 / 表单页。
- **改法**：① 间距阶梯——模块间 / 模块内 / 字段间用统一间距档，避免「忽挤忽空」。② 标题层级——模块标题用更强字重/字号差，扫读先见结构。③ 长页分节——模型设置这类长页加 sticky 子导航 / 锚点（已有 `src/components/settings/SettingSearch.tsx`，可再加视觉分节）。
- **验收**：长页扫读先见结构；间距档一致；sticky 子导航不遮内容、锚点落在顶栏下；四主题 + 窄屏无新溢出；与既有「界面密度」设置兼容。
- **风险**：中（全局间距调整影响面大）。需逐页回归防新溢出；「增间距档」是否触碰令牌边界见 §六待决 2。

### A4（P2）语义色归位 + 裸图标补标签

- **现象**：① 信息性说明常驻 ⚠️ / 红色圆点，与真正危险状态混用，稀释红色警示力（项目已有「危险色禁常驻」闸，可扩大覆盖）。② 个别工具栏有无文字裸图标（如人物关系页「导入导出」旁单独的 🗑），靠猜。
- **证据**：`src/lib/schemaTabs/part1.ts:23` 等信息性警示符号；人物关系工具栏裸删除图标；既有 `visualEmptyStates` / 危险色闸。
- **改法**：① 红色专款专用——只用于破坏性操作与真实失败；信息提示用 info/中性 + ⓘ。② 图标可读——裸图标补可见文字或 tooltip + `aria-label`，破坏性图标加文字「删除…」。
