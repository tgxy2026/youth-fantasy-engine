## 1. 目标（§10.3 #2 原文要求）

1. **按需读取**（非全量塞上下文）＋ 原文溯源；
2. **分层召回**：**远 / 中 / 近**证据；长篇规模门覆盖 **10 万 / 30 万 / 100 万字符**三档；
3. **缺失检查**：必需证据缺失时**停止生成**，不硬写；精确编辑目标不能退化为「截取前缀」；
4. **上下文查看**：作者可检查本次任务实际装配的上下文。

## 3. 设计

### 3.1 规模门（✅ 已实现 · `src/lib/contextLayers.ts`）

```ts
export type ContextScale = 'short' | 'medium' | 'long' | 'epic'
export const SCALE_GATES = { medium: 100_000, long: 300_000, epic: 1_000_000 } as const
export function scaleOf(totalWords: number): ContextScale
export function planFor(totalWords: number): LayerPlan   // { budget, relatedChapters, semantic, digestChapters }
```

| 档 | 起始字数 | 预算 | 相关章召回 | 章节清单 |
|---|---|---|---|---|
| short | < 10 万 | **12 000**（= 旧值） | **8**（= 旧值） | **200**（= 旧值） |
| medium | ≥ 10 万 | 20 000 | 12 | 300 |
| long | ≥ 30 万 | 32 000 | 16 | 500 |
| epic | ≥ 100 万 | 48 000 | 20 | 800 |

🔴 **小项目档位与改造前逐项相等** —— 中短篇手感零变化（单测冻结，防回退）。
接线：`buildProjectContext` 的 `budget` / `relatedChapterLimit` / `buildChapterDigest` 三处改走 `plan`；
**显式传参时仍以传参为准**（伴写等低延迟场景不受影响）。

### 3.2 缺失即停（待做）

- **必需证据的定义**（按任务类别）：
  - 续写：焦点章必须存在（`getContinuationSources.found === true`）；
  - 整章改写：目标章必须存在且**有正文**（已有守卫）；
  - 一致性审计：至少 2 章有正文。
- **行为**：缺失 ⇒ **返回结构化缺项**（而非空串「硬发」），调用方**停止生成**并如实提示作者。
  - 🔴 沿用 `getContinuationSources.found` 已有口径（注释就写着「调用方要据此提示作者，而不是当没有素材硬发」）——**把这句注释变成硬约束**。
- **精确编辑不退化为截取前缀**：改写 / 润色类任务的上下文组装必须**带全目标章正文**（不许被 `charCap` 截断到前缀）。
