**A1 · 四条分发路径对比**

📌 **2026-08-31 方案调研（老大提问触发，只讨论未开发）**：自动更新的前提是**必须有一个公开可访问的更新源**，托管两类文件：①`latest.yml`（几 KB，版本清单，每次启动都拉）②安装包本体（**当前 80.6 MB 全量**）。该源要的是「扛并发下载的存储+带宽」，不是算力。**四条路径对比**：**A GitHub Releases**——配置最简、零成本，但**国内访问慢且不稳**（致命），私有仓库 token 会打进客户端有泄露风险；**B 现有腾讯云服务器**——零新增成本，但**自签 HTTPS 会导致 electron-updater 证书校验失败**（需 HTTP 或等 #004 域名证书），且轻量机带宽 3–8Mbps，80MB 约需 2 分钟，多人并发更糟；**C 对象存储 COS/OSS + CDN**——业界标准，**约 ¥5/月**（存储约 ¥0.1 + 流量 0.5 元/GB，100 用户各更新一次 ≈ 8GB ≈ ¥4），自带 HTTPS、下载快；**D 只做检测+跳转下载**——托管一个几 KB 的 `version.json`，弹窗提示后跳浏览器下载，零成本零带宽压力、绕过证书问题，但**半自动**（用户手动装）。**建议分两步**：测试期先做 D；待 #004 域名+备案完成后升级为 C 全自动。**三个待验证的坑**：①**便携版无法优雅自动更新**（无安装程序，8.65MB 文件夹需整体替换），建议只提示、让用户自行覆盖；②**80MB 全量偏大**——NSIS 不支持差分更新（blockmap 在 NSIS 上支持有限），动手前值得先查包内冗余资源；③**更新前须提示备份**——新版本若改数据格式，需确认 v1→v2 迁移机制在自动更新后仍能跑通。

**A2 · 方案 D 实现细化（下载走网盘时如何做版本检测）**

🛠 **方案 D 实现细化（2026-08-31 老大提问：下载走网盘，如何做版本检测）**：①**服务端**：nginx 静态托管 `/version.json`，内容仅 `{version, releasedAt, notes}`，**不含下载 URL**；②**查询必须在主进程**（渲染进程受 CORS 限制）：新增 `ipcMain.handle('app:version')` 取 `app.getVersion()`、`ipcMain.handle('app:check-update')` 用 Electron `net.fetch` 拉 version.json，失败一律静默返回 `{ok:false}` 不打扰用户；preload 补 `appVersion`/`checkUpdate`/`openExternal`（开浏览器用 `shell.openExternal`）；③**版本比较**：按 `.` 切分逐段比数值（`x>y` 即新，注意用 `?? 0` 处理位数不齐）；④**证书问题（唯一权衡点）**：自签证书会让主进程请求失败。可选 HTTP（有劫持风险）、`ignore-certificate-errors`（**不推荐，全局降安全**）、**证书固定（推荐）**、或等 #004 真证书。证书固定写法：`session.defaultSession.setCertificateVerifyProc((req,cb)=>{ if(req.hostname==='154.8.178.240') cb(req.certificate.fingerprint===KNOWN?0:-2); else cb(-3) })`；⑤**安全关键：下载 URL 硬编码在应用内、指向服务器上的中转页 `/download`（静态 HTML，可随时改），再由中转页跳网盘**——这样即使 version.json 被劫持，最坏只是「误报有更新」，绝不会把用户引到恶意下载；且网盘地址更换时只需改中转页，**无需重新发版**；⑥**体验**：启动延迟 3~5 秒静默检测，localStorage 记住「已忽略的版本」避免反复弹窗，设置页加手动「检查更新」；⑦**待确认**：便携版若非 Electron（纯浏览器打开），需服务端为 version.json 加 CORS 响应头。**工作量估算**：服务端 1h + 主进程 2h + 前端 3h + 测试 1h ≈ 小半天到一天，无带宽成本。

**A3 · 无自有服务器的三层降级路径**

🆓 **无自有服务器的降级路径（2026-08-31 老大追问：以后没服务器了怎么办）**：核心认知——**不需要自己的服务器，只需要「一个能返回一小段文本的公开地址」**。三层叠加，任一失效仍有提示：**L1 借免费 CDN（首选）**：`https://cdn.jsdelivr.net/gh/<账号>/<仓库>@main/version.json`（jsDelivr，国内良）、`https://<账号>.gitee.io/<仓库>/version.json`（Gitee Pages，国内优，需实名+改完手动触发构建）、`https://registry.npmmirror.com/<包名>/latest`（淘宝 npm 镜像，速度优但需发 npm 包）。维护成本≈0：只需一个只装 version.json 的公开仓库，发版时改号推送即可。**⚠️ 反直觉的好处：免费 CDN 自带正规 HTTPS 证书与域名，直接绕开自有服务器「IP+自签证书」导致的 Electron 证书校验失败**——没服务器在这件事上不是退化而是简化，连证书固定那一步都省了。代码上用 `CHECK_URLS` 数组依次尝试，取首个成功者，全失败则静默跳过。**L2 内置过期时间（兜底）**：构建时注入 `BUILD_DATE`，启动时算 `days=(now-BUILD_DATE)/86400000`，超过阈值（如 90 天）提示。**措辞必须是「建议检查更新」而非「发现新版本 X.Y.Z」**——内置日期无法确知是否真有新版，谎报版本号会让用户不再信任该提示。此层零依赖、零网络请求。**L3 运营层**：应用内常驻官方群/公众号入口，人工发布公告。另注：应用商店（微软商店 $19 一次性）自带更新机制，但 Electron 需打 MSIX 且国内用户无此习惯，**不推荐**。
