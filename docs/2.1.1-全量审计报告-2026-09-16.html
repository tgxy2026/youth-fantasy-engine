二、P1 发现（建议修复）

P1src/lib/db.ts:474 & :531

云端空快照判定用 Object.keys().length，违反存储红线 #2

问题：两处用 snap.rev === 0 && Object.keys(snap.stores).length === 0 判云端快照是否空。但 liveStores() 恒给每个 store 放一个键（哪怕空数组），12 个空数组就能骗过去。

const snap = await pullDesktopSnapshot() const empty = snap.rev === 0 && Object.keys(snap.stores).length === 0 // :474 / :531 同款

触发条件：A 机空库首次播种写 rev=1 空文件（seedFromLocal 走 pushNow(0) 放行），B 机随后选同一云端目录→B 机真实本地数据被云端空缓存遮蔽，未重编辑的记录丢失。

修复建议：从 syncCore.ts 导出 totalRecords（已存在于 :330，并在 :458/:515 正确用于同语义判空），改为 const empty = snap.rev === 0 || totalRecords(snap.stores) === 0。低风险替换，不改行为。

三、P2 发现（文案 / 注释 / 规范漂移）

P2src/lib/tavern/report.ts:119

报告等级分类用子串匹配，「无矛盾」会被误判为「矛盾」

let level: TavernFindingLevel = levelRaw.includes('矛盾') ? '矛盾' : levelRaw.includes('漏洞') ? '漏洞' : '存疑'

影响：模型若输出「无矛盾 / 无明显矛盾」会被归到「矛盾」档，污染审计报告结论。先判否定词或精确等价匹配后再回退 includes 即可修复。

P2src/lib/tavern/types.ts:448 + 红线文档 §

#6 改名（进度→精神 / 当前地点→地点）后，注释与红线文档残留旧名

types.ts:448 注释仍写「好感 / 信任 / 剧情进度 / 心情 / 当前地点」，与全部用户可见文案（VAR_DEFS labels、TavernControl.tsx、protocol.ts）的「精神 / 地点」脱节。仅内部维护可读性问题，但易被误读为两套变量。

修复建议：同步注释与红线文档为「精神 / 地点」。

P2src/lib/schema.ts:841 vs src/components/TavernCard.tsx:1105

角色卡说明写「世界」、卡片标题写「设定」，术语不一致

schema.ts:841 description：卡里只写「角色与世界的关系」；但 TavernCard.tsx:1105 第 1 章标题为 角色与设定的关系。用户侧可见的术语漂移，建议统一为「设定」与卡片标题对齐。

P2src/components/TavernCard.tsx:1033

数值备注示例「好感 20 → 从陌生到熟悉的朋友」与新刻度量级略出入

新刻度为 −100~+100、0 为中立起点（TavernControl.tsx 已教授），20 仅属「略亲近」。示例可能让读者低估数值含义，建议改为更贴近量级的值（如 45）或措辞对齐 0=中立框架。

P2src/lib/tavern/ai.ts:285-287（注释）

注释称 think:false 仅 testProvider 用，与酒馆实际恒带 think:false 矛盾

酒馆 disableThink 默认 true → 实际恒传 think:false。注释若不补「酒馆是有意例外」，后续维护者可能「修正」掉酒馆的 think:false，破坏红线。补充一句即可。

P2src/lib/db.ts:461-493（启动恢复 IIFE）

启动恢复云端同步是未 await 的 IIFE，且切到云端 ops 后未按注释 reload

恢复分支切到 desktopCloudFileStore 后，UI 在 reload 前可能仍读旧本地 data。影响极小（仅启动瞬间），建议补 location.reload() 或显式刷新 store 引用。

P2src/components/DataDock.tsx:35 / SaveFab.tsx:26

浮层层级用 Tailwind 魔数（z-40 / z-20），未走 zLayer.ts 单一真源

二者均非禁止的 z-[9999]，但绕过层号真源 Z。建议从 zLayer.ts 取号，消除魔数残留（与 SaveFab 全局 fixed 同属已登记例外，见下）。
