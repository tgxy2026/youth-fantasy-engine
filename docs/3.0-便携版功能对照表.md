## 五、需要主人哥哥拍板的「待确认项」

### ① 语义检索 / 知识库的独立 IDB 库（#19）
- **现状**：`novel-studio-vec`（向量）/ `-kb`（知识库）是**独立 IDB 库**，刻意不进门面 `lib/db` ⇒ 不进整库 JSON / 同步 / 备份（项目红线）。
- **便携版困境**：浏览器 IDB 不跟随 U 盘 ⇒ 若照搬，便携版数据就**不全**（换机丢失向量/KB）。
- **方案 A（推荐）**：便携模式下把这两库**并入整库 JSON** 的 `stores`（新增 `vecRows` / `kbRows` 两个 store），随 `./data` 落盘。代价：整库 JSON 变大；需改 `storeOps.ts` 的 key 表。
- **方案 B**：便携版**关闭语义检索/知识库**，界面提示「便携版不含向量检索」。
- **方案 C**：保持独立 IDB，文档注明「便携版向量库不随盘走」。

### ② 证据包导出（#10）
- 建议按现成分支：便携版**下载 HTML**，不另做 PDF（中文 PDF 红线要求走 Electron `printToPDF`，浏览器做不到）。

### ③ 联网检索（#18）
- 建议**保留入口**，仅在失败时按 `HAS_NET_BRIDGE=false` 给「浏览器跨域限制」的说明（已有该提示）。不主动隐藏。

### ④ 云端模型跨域（#14）
- 建议**保留**。若某些 API 商不允许浏览器跨域，属其服务端策略；文档提示用户可用支持 CORS 的服务或本地模型。

## 八、根治：外置 store（sidecar）—— 2026-10-11 落地

主人哥哥拍板「先做 A+B，保证老数据自动迁移；桌面版同步做、保持双端同构」后实施。

### 要解决的问题

512 MiB PUT 上限只是**最后一根稻草**，真正的病是「改一个字也要 PUT 全库」：
备份载荷（60 份 × 整包项目正文，写完就再也不变）占了整库大头，
作者每敲一个字都在重传上百 MB 完全没动过的历史。

### 设计

| 项 | 内容 |
|---|---|
| 通用层 | `src/lib/storage/sidecar.ts` —— `withSidecar(baseOps, api, spec)` 包装器，**双端共用** |
| 两种布局 | `per-id`（一条一文件：备份载荷）／`whole`（整表一文件：向量 / KB，避免数千次 IO） |
| 便携版 | `/api/blob` GET/PUT/DELETE + `list`，落 `data/blobs/<store>/<id>.json` |
| 桌面版 | IPC `payload:read/write/del/list`，落 `<数据文件同目录>/blobs/<store>/<id>.json` |
| 外置范围 | 便携版：`backupPayloads` + `vecRows`/`kbDocs`/`kbBodies`；桌面版：**只** `backupPayloads` |

🔴 桌面版**只外置备份载荷**是刻意的：桌面端的向量与参考资料本来就在两个独立 IDB 库
（`-vec`/`-kb`）里、从不入整库 JSON（红线）。便携版把那两库搬进整库只是因为「IDB 不跟 U 盘走」，
现在同样换成外置文件 ⇒ 两端回到同一语义：**大块数据都不进主 JSON**。

### 对外契约不变

导入 / 导出**仍是单文件**：导出时把外置数据内联回副本，导入后再拆开落盘。
🔴 少了「导出内联」这一步，导出的文件会**静默丢掉全部备份载荷**（列表还在、看着正常，
等要恢复时才说"载荷缺失"）—— 最危险的失败形态。

### 老数据自动迁移

启动时检测主 JSON 里残留的外置数据 ⇒ 逐条迁出 ⇒ 从主库删除 ⇒ 落盘一次，**幂等**：
迁完即删（再跑不动）；没迁完则重复覆盖（upsert 语义）；单条失败不中断整批。
`fileVersion` 1 → 2。

### 实施中实机抓到的两个真 bug

| # | 问题 | 根因 |
|---|---|---|
| 1 | 迁移白做：载荷写出去了，主 JSON 却原地不动 | 迁移写在 `try` 内，而 `inited = true` 在 `finally` ⇒ `flush*` 的 `if (!inited) return false` 守卫拦下所有写盘。**双端同病** |
| 2 | 桌面版写备份载荷 100% 失败（ENOENT） | `payload:write` 用了给主 JSON 设计的 `writeAtomic`（不建目录），而外置目录是按需生成的 ⇒ 缺 `mkdirSync` |
