## 五、需要主人哥哥拍板的「待确认项」

### ① 语义检索 / 知识库的独立 IDB 库（#19）

- **现状**：`novel-studio-vec`（向量）/ `-kb`（知识库）是**独立 IDB 库**，刻意不进门面 `lib/db` ⇒ 不进整库 JSON / 同步 / 备份（项目红线）。
- **便携版困境**：浏览器 IDB 不跟随 U 盘 ⇒ 若照搬，便携版数据就**不全**（换机丢失向量/KB）。
- **方案 A（推荐）**：便携模式下把这两库**并入整库 JSON** 的 `stores`（新增 `vecRows` / `kbRows` 两个 store），随 `./data` 落盘。代价：整库 JSON 变大；需改 `storeOps.ts` 的 key 表。
- **方案 B**：便携版**关闭语义检索/知识库**，界面提示「便携版不含向量检索」。
- **方案 C**：保持独立 IDB，文档注明「便携版向量库不随盘走」。

### ② 证据包导出（#10）

- 建议按现成分支：便携版**下载 HTML**，不另做 PDF（中文 PDF 红线要求走 Electron `printToPDF`，浏览器做不到）。

### ③ 联网检索（#18）

- 建议**保留入口**，仅在失败时按 `HAS_NET_BRIDGE=false` 给「浏览器跨域限制」的说明（已有该提示）。不主动隐藏。

### ④ 云端模型跨域（#14）

- 建议**保留**。若某些 API 商不允许浏览器跨域，属其服务端策略；文档提示用户可用支持 CORS 的服务或本地模型。

## 八、根治：外置 store（sidecar）—— 2026-10-11 落地

主人哥哥拍板「先做 A+B，保证老数据自动迁移；桌面版同步做、保持双端同构」后实施。

### 要解决的问题

512 MiB PUT 上限只是**最后一根稻草**，真正的病是「改一个字也要 PUT 全库」：  
备份载荷（60 份 × 整包项目正文，写完就再也不变）占了整库大头，  
作者每敲一个字都在重传上百 MB 完全没动过的历史。

### 设计

| 项    | 内容                                                                              |
| ---- | ------------------------------------------------------------------------------- |
| 通用层  | `src/lib/storage/sidecar.ts` —— `withSidecar(baseOps, api, spec)` 包装器，**双端共用**  |
| 两种布局 | `per-id`（一条一文件：备份载荷）／`whole`（整表一文件：向量 / KB，避免数千次 IO）                            |
| 便携版  | `/api/blob` GET/PUT/DELETE + `list`，落 `data/blobs/<store>/<id>.json`            |
| 桌面版  | IPC `payload:read/write/del/list`，落 `<数据文件同目录>/blobs/<store>/<id>.json`         |
| 外置范围 | 便携版：`backupPayloads` + `vecRows`/`kbDocs`/`kbBodies`；桌面版：**只** `backupPayloads` |

🔴 桌面版**只外置备份载荷**是刻意的：桌面端的向量与参考资料本来就在两个独立 IDB 库  
（`-vec`/`-kb`）里、从不入整库 JSON（红线）。便携版把那两库搬进整库只是因为「IDB 不跟 U 盘走」，  
现在同样换成外置文件 ⇒ 两端回到同一语义：**大块数据都不进主 JSON**。

### 对外契约不变

导入 / 导出**仍是单文件**：导出时把外置数据内联回副本，导入后再拆开落盘。  
🔴 少了「导出内联」这一步，导出的文件会**静默丢掉全部备份载荷**（列表还在、看着正常，  
等要恢复时才说"载荷缺失"）—— 最危险的失败形态。

### 老数据自动迁移

启动时检测主 JSON 里残留的外置数据 ⇒ 逐条迁出 ⇒ 从主库删除 ⇒ 落盘一次，**幂等**：  
迁完即删（再跑不动）；没迁完则重复覆盖（upsert 语义）；单条失败不中断整批。  
`fileVersion` 1 → 2。

### 实施中实机抓到的两个真 bug

| # | 问题                       | 根因                                                                                                    |
| - | ------------------------ | ----------------------------------------------------------------------------------------------------- |
| 1 | 迁移白做：载荷写出去了，主 JSON 却原地不动 | 迁移写在 `try` 内，而 `inited = true` 在 `finally` ⇒ `flush*` 的 `if (!inited) return false` 守卫拦下所有写盘。**双端同病** |

| 2 | 桌面版写备份载荷 100% 失败（ENOENT） | `payload:write` 用了给主 JSON 设计的 `writeAtomic`（不建目录），而外置目录是按需生成的 ⇒ 缺 `mkdirSync` |

### 验证

- 便携版端到端 **23/23**（真服务 + 真 Chromium）：白名单挡穿越 / blob 读写删列 / 老库迁移内容完整 / fileVersion 升 2 / 二次启动幂等
- 桌面版真 Electron **8/8**（CDP 连接）：IPC 读写删列 / 路径穿越拒绝 / 未登记 store 拒绝
- 单测：`sidecar` 42 条 · `desktopSidecar` 12 条（含**双端布局一致性守卫**）
- 质量闸：tsc 0 / eslint 0 / 全量 **205 全绿** / structureGates **20/20**

## 九、3.0.3 · 免安装运行时（移除 Node 依赖）＋ 跳过更新检查

> 背景（2026-10-13）：主人明确 **「便携版的定义就是免安装使用」** —— 解压即用、数据随盘走、不进设备。
> 而便携版原先要求作者自装 Node.js（约 30MB），与这一定义冲突。
> ⇒ 目标：**本机不装任何东西，双击就能跑**；便携版做不到的功能可以削弱/阉割。

### 9.1 做法：Node SEA 单文件运行时

| 项 | 说明 |
| --- | --- |
| 原理 | 把 `scripts/portable-server.mjs` 与 **Node 运行时**打包成**单个 exe**（Node SEA，Single Executable Application） |
| 构建 | `npm run build:portable-server` → `release/便携版运行时/青春幻想引擎-便携版.exe` |
| 组装 | `npm run build:portable-pkg` → `release/便携版-<版本>/` ＋ `青春幻想引擎-便携版-<版本>.zip` |
| 体积 | exe **83.46 MB** ⇒ 便携版 zip 由 6.2 MB 变为 **38.9 MB**（增量全部是内嵌运行时） |
| 冷启动 | **336 ms**（与 `node` 直跑脚本无实质差异） |
| 回退 | 自带运行时缺失 / 被安全软件拦下 ⇒ `启动.bat` / `启动.sh` **自动回退到系统 Node**（双保险） |
| 否决的替代 | 把 Node 安装包塞进 zip 再「唤醒安装程序」—— 要管理员权限、写注册表、公司电脑可能被策略拒绝、换机还要再装 ⇒ **那就不是便携版了** |

🔴 **两条构建约束（实测得出，勿改回去）**：

1. **顺序：先写图标/版本信息，再注入 SEA blob** —— 反了资源写不进去（注入后 PE 多出一个 section，rcedit/resedit 都会失败）。
2. **写资源用 `resedit`（纯 JS），不要用 `rcedit.exe`** —— 从 Node 进程 spawn `rcedit` 会 **EBUSY**（经 cmd / bash 中转同样失败）；
   `resedit` 是 electron-builder 自带的纯 JS PE 资源编辑器，零外部进程、跨平台一致，还顺带避开了
   rcedit 的「路径含中文即失败」那个坑（桌面版主 exe 当年就是被它坑过）。

### 9.2 便携版跳过更新检查

`src/App.tsx` 的启动自动检查原先**没有 `PORTABLE` 分支** ⇒ 便携版仍会请求 Gitee API；
而本文档与 `portable/使用说明.txt` 都写明便携版**没有**自动更新检查 ——
且便携版没有安装器，**查到新版本也无法自动更新**（只会弹一个作者做不到的提示），
还会消耗 Gitee 匿名配额（实测密集调用会 403 限流，让「检查更新」看起来像坏了）。现已在两处收口：

| 位置 | 改动 |
| --- | --- |
| `src/App.tsx` | 启动自动检查加 `if (!PORTABLE)` 守卫 |
| `src/components/app/AboutPage.tsx` | 便携版隐藏「检查更新」按钮与「启动时自动检查」开关，改为静态指引（到发布页下载新包、把 `data/` 拷过去即可） |
