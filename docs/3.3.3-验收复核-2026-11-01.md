## 发现与阻断项

1. **B6 预览失效后仍能提交类型转换**：`AtlasFieldManager.tsx` 的 `previewConversion` 形成 plan；`applyConversion` 重新读取行，但没有用新行重新调用 `planFieldConversion`，也未比较预览时的数据指纹。预览后另一窗口将值改为不可转换值，仍可能用旧 plan 修改类型，违反规划 §14.2。需在受保护提交边界中重新校验值与配置版本并对竞态做真实存储测试。
2. **B6 清值失败被当作永久删除成功**：`AtlasFieldManager.tsx` 的 `purgeFieldValues(...).catch(() => 0)` 把部分失败吞为 0，并提示永久删除成功；可能留下残余字段值，无明确修复提示。应保留失败状态/恢复记录，不能虚报全部清理成功。
3. **A4/B3 任务执行权并非原子接管**：`taskLedger.ts` 的 `claimTask` 先读 head 后写 `generation + 1`，两窗口可读到同一旧代次并分别写相同新代次；`saveTaskUnit` 的代次读取和后续写入也不是同一原子操作。旧执行者可在检查后被接管仍写入，需用真实 IDB 并发复现并实现跨后端可证明的串行/条件写。当前交接已承认双窗口未验，不能据单测认定互斥。
4. **A4/B3 存储所有权守卫未实际阻止失效写入**：`openTaskOwner` 的 `assertCurrent: () => guard.current()` 仅返回布尔值，调用方忽略返回值；`claimTask` 也直接调用并忽略。切账号/后端后需要中止的链路没有因 false 抛错。应在首次异步操作前捕获后端并让失效守卫明确拒绝。
5. **A3 能力测试可能错误升级结构化输出**：`capabilityTest.ts` 测一次后只以可解析 JSON 记录 `jsonObject`；`modelCapabilities.ts` 据此设置 `structuredOutput: json-object`。需要核实这次测试真实请求是否已下发结构化协议；仅靠提示词得到 JSON 不能证明端点支持 `response_format`。另 `normalizeEndpoint` 去除 http/https、路径大小写及 query，可能把能力不同端点合并；配置指纹也未涵盖凭据变化，与规划缓存隔离要求不符。
6. **B3 创意写作恢复仍未完成**：拆书记录文档明确创意写作尚未接入本轮台账；不能以拆书单元测试替代创意写作跨重启只补剩余、产物校验与不重复写章的验收。
