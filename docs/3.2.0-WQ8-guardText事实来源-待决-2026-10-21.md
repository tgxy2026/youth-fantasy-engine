# WQ8 · `guardText` 的「已知事实来源」——设计待决（2026-10-21）

> 结论先行：**没接**。这是 `docs/3.2.0-WQ线实现台账` 里唯一一项"属设计决策而非接线"的缺口，
> 硬接只会产出「可能丢失事实」噪音 —— 而**噪音比没有守卫更糟**（作者学会无视它之后，真问题也一起被无视）。
> 本文给出三个候选与推荐，等主人拍板再动代码。

## 1. 卡点在哪

`ai/qualityGuard.ts` 的 `guardText(original, revised, knownFacts, newClaims)` 本身是纯函数、
已有测试；缺的是 `knownFacts`（"哪些事实必须保留"）的**可靠来源**：

```ts
factRetentionRate = 保留的 knownFacts / 全部 knownFacts
passed = factRetentionRate >= 0.8 && falsePositives === 0
```

🔴 风险全在分子分母上：只要 `knownFacts` 里混进一条"本来就该被删掉的实体提及"，
`passed` 就会假阴性，UI 上刷一条「可能丢失事实：王铁柱」——
而实际情况可能只是润色时少提了一次人名。十条里九条是这种，作者两周后就不再看了。

## 2. 三个候选

| 方案 | knownFacts 从哪来 | 好处 | 代价 / 风险 |
|---|---|---|---|
| **A. 本章设定实体名**（`settingLedger` 登记项 ＋ 图鉴解析出的实体名，筛出**在正文出现过**的） | 作者自己登记的，可解释、零新写代码 | 实体"被改写删掉"常是合理润色 ⇒ 噪音主力；要压噪音就得给实体分权重（高频/关键/普通），权重规则又是新的拍板项 |
| B. 结构位置事实（人名＋称谓＋时间锚点＋数字，重新写提取器） | 精准、直接对"事实"而非"词" | 等于新写一个抽取器，它自己就会错；且与既有的实体登记**两套口径**，作者要维护两份 |
| **C. 作者勾选的事实清单**（改写前在界面上勾"这几条必须保留"） | 零噪音（作者自己选的） | 多一步交互；作者可能一次都不勾 ⇒ 事实等同没接 |

## 3. 推荐：**A ＋ 只报告不判定**

- **用 A 取集合**（零新写代码，来源可解释：每个实体都能指回设定表哪一页哪一行）。
- **不接 `passed`/阈值**：只用 `guardText` 的 `issues` 与 `factRetentionRate` 做**只读呈现**，
  不产生"通过/不通过"结论 —— 没有阈值就没有假阴性。
- **接入位置**：`runTicketChapter`（工单改写）与候选应用之后，与「改后复检」同一处旁路，
  同样**全程不抛**（跑了更好，跑不成不影响已落库的正文）。
- **呈现**：接在 10-21 已做的「检查报告」回看面板旁（同一类"过程留痕"），
  形如「改写后 3 个实体名没再出现：王铁柱（角色·第 12 行）、玄天宗（势力）」。
  每个实体带来源 ⇒ 作者能自己判断"该不该在"，而不是被告知"你丢了事实"。

若主人更想要"确定结论"而不是"只读提示"，那就得选 **C**（勾选），并接受多一步交互。

## 4. 拍板后要做的事（先记在这里，未拍板不动代码）

1. 新建 `lib/ai/factGuard.ts`：装配 knownFacts（实体名 + 来源 + 是否在正文出现），
   只调 `guardText` 的报告字段，**不用 `passed`**。
2. 接两处：`optimizeTicket.runTicketChapter` 落库后、`revision/candidateRunner` 应用成功后
   （都是旁路，catch 只 warn）。
3. 呈现：与「改后复检」并列（工单每章标题旁一行 ＋ 检查报告面板一段）。
4. 测试：实体在正文 ⇒ 不算丢失；实体本就没在正文出现 ⇒ 不进集合（否则必然误报）；
   全空集合 ⇒ 不出面板段落（不刷"0/0"）。

> 🔴 未拍板前 `qualityGuard.guardText` 保持零调用方状态，台账照实记录。
