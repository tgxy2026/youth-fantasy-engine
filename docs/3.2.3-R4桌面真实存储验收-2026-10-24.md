# 3.2.3 R4：桌面真实存储验收

> 2026-10-24，承接游客真实存储验收。仅使用本轮临时数据，不封装、安装、发布或部署；package.json 保持 3.2.2。

## 1. 本轮范围

新增 `scripts/audit/probes/desktop-save-probe.cjs`：显式接收本次生产构建，用实际 Electron、生产 main/preload、file URL 渲染页面与真实 IPC/文件读写运行保存故障场景。appData/userData 均指向新建的 `.workbuddy/tmp/desktop-save-*`，旧版迁移探测也位于隔离根目录。生产代码未增加故障开关。

故障由测试把目标 JSON 暂存，再在原路径创建空目录触发真实 rename 失败。原字节留在同一隔离目录；恢复时只移除本轮刚创建的空目录并放回原文件，不递归删除历史资料。IPC 包装器只记录实际生产 handler 的调用与返回值，不替换保存结果。

为自动验收故障期间的导出，测试只替换原生保存框的目标路径；可见导出按钮、数据收集和 IPC 文件写入仍走生产逻辑。该结果不证明原生对话框交互、真实磁盘写满、安装器或实体设备已经验收。测试会阻止 HTTP/HTTPS 请求，不调用真实模型或生产服务。

## 2. 自动检查

| 检查 ID | 实际断言 |
|---|---|
| initial-flags | preload 注入桌面桥，未出现网页/游客/便携标记 |
| isolated-paths | appData、userData、真实 dataPath 与本次临时目录一致 |
| fixture-readback | 编辑器与真实 JSON 初始正文一致 |
| failure-visible | 真实 store:save 返回文件替换错误，UI 显示保存出错 |
| failure-preserves-draft | 编辑器仍含新草稿 |
| accepted-vs-persisted | 被保留的原文件哈希和旧正文未变，写入目标仍被空目录阻断 |
| dirty-retry | 无新输入仍出现后续真实失败写入，确认 dirty 留待自动重试 |
| failure-export | 故障期间点击生产导出按钮，实际导出文件含最新草稿 |
| export-preserves-failure | 导出未解除故障、覆盖旧文件或清空输入 |
| retry-readback | 恢复路径后不重输、不再点保存，自动重试后磁盘正文正确 |
| recovery-visible | 恢复后显示已保存，保存出错状态消失 |
| backend-selection | 真实 IPC load 指向临时 JSON，save 成功返回与新正文相符 |
| restart-readback | 关闭 Electron 进程再启动，UI 与 JSON 新正文一致 |
| no-pageerror | 本次捕获的页面运行异常为零 |
| unchanged-inputs | 平台源码指纹与生产构建哈希在探针前后均一致 |

保留写失败、故障导出、重启回读截图，以及导出 JSON、正文回读、IPC 调用与 Electron 日志；每项产物登记 SHA256。

新增 `desktop-evidence.mjs` 与 `desktopEvidence.test.ts`：15 项正反对照验证当前构建、源码、完整场景、隔离目录、产物数量/存在性/哈希与边界；旧构建、缺少故障导出、重复场景、页面异常和越界产物均不能通过。测试归入唯一 B 批清单。

## 3. 统一验收与平台矩阵

统一入口新增 `storage.desktop-save`，要求至少 15 项检查。桌面与游客探针顺序运行，共用本次新构建。证据校验后生成累计 ledger，再调用原平台工具独立核验，不能仅凭探针进程退出 0 点亮矩阵。

桌面证据仅覆盖 `boot-store/desktop` 与 `write-failure/desktop`。游客仍仅覆盖 `boot-store/web-guest`。累计结果及当前统一运行目录见下方检查点；不提升跨形态 roundtrip、云端账号、安装产物或其他未运行单元。

本轮没有补桌面保存中继续输入、切项目、关窗同步写失败、sidecar 故障导出或跨形态完整往返。因此 `storage.four-profiles` 继续 blocked，桌面保存契约通过不等于 R2 全部完成。
