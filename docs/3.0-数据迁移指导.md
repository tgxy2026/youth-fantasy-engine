# 青春幻想引擎 3.0 · 老用户数据迁移指导

> 适用对象：**此前用过旧版（novel-studio / 更早的「青春幻想引擎」）**，现在升级到 **3.0** 的作者。
> 上一版：2.9.3（2026-10-10）｜本文对应：3.0.0（2026-10-11）

---

## 一、先说结论：你的数据不会丢

| 你可能担心的 | 实际情况 |
|---|---|
| 书稿、章节、设定表要重录吗？ | **不用**。装完 3.0 首次打开，软件会**自动探测**旧版数据并弹出「发现旧版数据」向导，点一下「**导入旧版数据**」即可 |
| 数据会被自动搬走 / 被覆盖吗？ | **不会**。真正搬数据的是你**亲手点的那个按钮**，软件绝不静默动你的数据；且导入是**只读搬运**，**旧数据原文一个字都不改** |
| 一旦点了「暂不导入」，以后还能补吗？ | **能**。随时可以到 **设置 → 关于 → 旧版数据迁移** 里再来一次 |
| 重复导入会怎样？ | ⚠️ **导入是「把旧版整库覆盖到新版」**：同一台机器上**不要反复导入**。**正常只需导一次**；若已在新版里写了新内容，再导一次会用旧数据盖回来 |
| 旧版能一直留着吗？ | 3.0 **只在这一版**提供一次性导入。**建议先导入确认无误，再卸载旧版** —— 更晚的版本将不再识别旧数据 |

> ⚠️ **最要紧的两条**：
> 1. **先完成导入、确认书稿都在，再去卸载旧版。** 顺序反了会失去这次便利。
> 2. **正常只需导一次。** 导入动作＝「把旧版整库覆盖到新版」；若你在新版里已经写过内容，再导一次会用旧数据盖回来。确需重来，先把新版当前进度备份好。

## 二、为什么 3.0 需要「迁移」这一步

3.0 把软件正式更名为「**青春幻想引擎**」（旧名 **novel-studio**，见下「名字变了」小节）。改名带来一个物理后果：

**软件存放数据的目录跟着变了。**

| | 旧版 | 3.0 |
|---|---|---|
| 程序数据目录 | `%APPDATA%\novel-studio` | `%APPDATA%\youth-fantasy-engine` |
| 整库数据文件 | `novel-studio-data.json` | `youth-fantasy-engine-data.json` |

> `%APPDATA%` 一般指 `C:\Users\你的用户名\AppData\Roaming`。
> **注意：这是「数据目录」，跟你把软件装在哪个盘（安装目录）是两回事**，装到 D 盘也不会改变数据位置。

换句话说：**新版打开时看到的是「新家」，旧数据还躺在「老家」。** 迁移做的事，就是把老家里的东西**安全地搬一份到新家**。

---

## 三、迁移向导会搬哪三样东西

首次启动 3.0，若探测到旧版数据，会弹出这样一个窗口（标题「**发现旧版数据**」）：

| # | 项目 | 内容 | 说明 |
|---|---|---|---|
| 1 | **书稿与全部设定** | 项目、章节、设定表、角色卡、酒馆内容（整库数据文件） | 最核心的一份，**必须导入** |
| 2 | **向量索引 + 知识库** | 语义检索索引（向量库）、「参考资料」里的文档（知识库） | 有则一并带过来；没有会显示「未检出」 |
| 3 | **界面偏好** | 界面缩放、主题、字体等本机设置 | 让你在新版里手感不变 |

每一项右侧会标 **「可导入」（检出）/「未检出」**，导入前就能看清**将带走什么**。

## 四、操作步骤（照做即可）

### 步骤 1 · 安装 3.0

- 双击 `青春幻想引擎-Setup-3.0.0.exe`，按提示安装。
- **不需要先卸载旧版** —— 新旧版可**共存**，这样万一导入有问题，旧版还在、心里有底。

### 步骤 2 · 首次启动，等向导弹出

- 打开 3.0，若本机有旧数据，会自动弹出「**发现旧版数据**」窗口。
- 若**没弹**（比如你之前点过「暂不导入」）：走 **设置 → 关于 → 旧版数据迁移 → 导入旧版数据**，同样能唤起。

### 步骤 3 · 点「导入旧版数据」

- 窗口里会先列清「将导入什么」（上面第三节那三样）。
- 确认后点右下角 **「导入旧版数据」**，稍等片刻（**导入中请勿关闭窗口**）。
- 中间那句提醒请留意：**旧版数据仅能在 3.0 一次性导入**。

### 步骤 4 · 看导入报告

导入完成会逐项报告结果：

| 报告行 | 期望结果 |
|---|---|
| 书稿与设定 | **已导入**（若品牌标识有改写，会附注「改写 N 处品牌标识」） |
| 向量索引 | 已迁移 N 条向量 / 或无（旧版没建过索引） |
| 知识库 | 已迁移 N 篇资料 / 或无 |
| 界面偏好 | 已复制：Local Storage、Preferences… / 或「无（或已存在，跳过）」 |

若某一行显示**失败**并给出原因，把该行原文记下来，到 QQ 交流群反馈即可 —— 其余没失败的部分**已经搬完了**，不影响使用。

### 步骤 5 · 点「开始使用」

- 整库导入成功的，点「开始使用」会**自动刷新**让新数据立即生效，随后就能在项目列表里看到你的书。
- 仅搬了向量/知识库、或你跳过了整库 JSON 的，点一下直接关闭即可。

### 步骤 6 · （可选）卸载旧版

- 导入报告下方提供 **「卸载旧版」** 按钮：能自动找到旧版卸载程序就直接拉起；找不到会提示你去系统的 **设置 → 应用 → 已安装的应用** 手动卸载。
- 旁边 **「打开旧数据目录」** 会帮你在资源管理器里打开老家文件夹，方便你**确认数据都在新版里之后**，再自己清理残留。
- 🔴 **要不要删旧数据，由你决定**。软件**不会**替你自动删除 —— 那个目录里可能还混着它无法判定的东西（旧字体、缓存、自定义路径文件等）。

## 五、名字变了，但「内容」没变

| 变的东西 | 没变的东西 |
|---|---|
| 软件名、程序数据目录、整库文件名 | 你的项目、章节、设定、角色卡、剧本、会话记录 |
| 备份包 / 证据包里的品牌标识（`novel-studio` → `youth-fantasy-engine`，**自动改写**） | 备份包**内容**与**可导入性** |
| 酒馆预设等文件里的品牌标识（自动改写） | 你写的每一个字 |

**你的项目本身：完全兼容，不需要做任何手工转换。** 打开就能继续写。

## 六、三种常见情况的处理

### 情况 A · 全新安装、以前没用过旧版
不会弹向导，正常新建项目即可，忽略本文。

### 情况 B · 想从另一台电脑搬数据
用**备份 / 导出**功能带过去，别手工拷贝数据目录（`APPDATA` 里的整库文件与向量/知识库分属不同物理文件，手工只拷一个会缺东西）。
3.0 起备份载荷改为**独立文件存放**（双端同构），**导入导出仍是单文件**，跨设备搬移不受影响。

### 情况 C · 以前改过「数据存放位置」（自定义数据目录）
旧版目录里记着一份 `data-location.json`，向导会**自动读它拿你的自定义路径**去取整库数据，无需手动指路。

## 七、万一出问题

| 现象 | 先试这里 |
|---|---|
| 首次打开没弹向导 | 设置 → 关于 → 旧版数据迁移 → 导入旧版数据 |
| 报告里某一项失败 | 截图该行原文 → QQ 交流群反馈（其余部分已完成，可先用） |
| 导入后没找到旧项目 | 确认报告里「书稿与设定」那行是否显示「已导入」；若显示失败，按上行截图反馈 |
| 想重来一次 | 正常**只需导一次**。⚠️ 导入是「把旧版整库覆盖到新版」，若已在新版写过内容，重复导入会盖回旧数据 —— 确需重来前，先备份新版当前进度 |
| 旧版卸载程序找不到 | 系统「设置 → 应用 → 已安装的应用」手动卸载 |
