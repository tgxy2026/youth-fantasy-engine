## 二、已拍板的四个决策（含一处技术纠正）

| 问题 | 决定 | 落地方式 |
|---|---|---|
| 证据包要不要直接出 PDF | **要** | ⚠️ **不走 jsPDF** —— jsPDF 默认字体不含中文，硬套会输出豆腐块，且中文字体子集化/嵌入是独立大坑。采用 **HTML + 打印样式** 为唯一真源：① 桌面版走 Electron `webContents.printToPDF`（零依赖、中文无问题、一键存盘）；② 便携版/浏览器走 `window.print()` 调系统打印对话框另存 PDF；③ JSON 原件同时导出，供机器核验。 |
| AI 占比统计是否默认开启 | **默认开启** | 只**静默统计**并写入记录，不弹提示、不打断写作；申报草稿由用户**按需生成** |
| 创作轨迹要不要独立页签 | **要** | 新增页签「创作轨迹」（理由充分：过程材料需要独立入口才能演示、导出、截图，且它是 2.4 对外主卖点之一）→ 必须同步 schema + `SETTING_SUBTABS` + `aiContext.PRIORITY` + 种子/迁移 + 单测 |
| 爽点节奏是否提级 | **提级** | 从 P2 提到 **P1**，进 2.4.1（章节快照与自检先落地，节奏分析依赖 AI 且判据偏主观，放后面） |

### A1 · 新用户首启闭环

- **涉及模块**：`NewProjectAdvice`（已有）、模型设置相关组件、`src/lib/useAIReady.ts`、`src/lib/modelCapacity.ts`（`adviseCapacity` / `recommendTuning`）、`src/lib/ai.ts`（错误分类）

### A2 · 长篇性能基线

- **风险**：压测库必须放仓库外、import 带时间戳（既有红线）；性能闸阈值先宽后紧，避免偶发抖动误报

### A3 · 章节级快照

- **涉及模块**：`src/lib/db/chapters.ts`、新增 store 与迁移（参照 `migrateMiscSettingsToCards` 的写法）、行级 diff
- **步骤**：① 新增独立 store 存章节快照（**不进主数据表**，避免膨胀主数据文件）；② 触发点＝「AI 动这一章之前」（改写 / 续写 / 生成），手动保存不触发；③ **每章上限 5 份**，超限丢最旧；④ 版本列表（时间 + 来源）→ 行级对比 → 一键回滚
- **体积账**：约 3000 字/章 ≈ 6KB，5 份 ≈ 30KB/章，300 章 ≈ **9MB**（独立 store，可接受）
- **验收**：改写三次后能回到任意一版并看清改了哪些段落
- **风险**：回滚必须只改 content / wordCount / updatedAt（既有红线）；快照 store 也要进备份与迁移路径

### A4 · 创作轨迹页签 + 证据包

- **涉及模块**：新增页签（schema + `SETTING_SUBTABS` + `aiContext.PRIORITY` + 种子/迁移 + 单测，一处都不能漏）、`src/lib/exporter.ts`、桌面版 `electron/main.cjs`（`printToPDF`）、`dailyStats`

- **验收**：能一键导出「这一章我是怎么写出来的」材料，HTML 可打印、JSON 可核验

### B2 · 投稿前自检（不出 AI）

- **涉及模块**：`src/lib/continuityCheck.ts`、`foreshadowEngine.ts`、`src/lib/textStats.ts`（新增统计）、报告 UI
- **步骤**：① 设定一致性：复用连续性检查与伏笔引擎，报「前后矛盾 / 伏笔未收 / 人设漂移」；② 行文指纹：**纯本地统计**——句长方差（越均匀越像机器）、重复句式率、高频套句密度、段落长度分布；③ 轨迹合理性：章节字数分布是否异常均匀、更新节奏是否超人类规律（**提示而非判定**）；④ 出「投稿前自检报告」，可随证据包导出
- **验收**：跑一次能指出「这章 3 处前后矛盾、句式偏均匀、2 处伏笔未收」
- **风险**：🔴 措辞必须是**质量自检**而非「规避检测」——不写「降低 AI 命中率」一类表述（红线）

### B3 · AI 辅助占比统计与申报

- **涉及模块**：章节记录（**先核是否已有 AI 来源标记，没有则加字段 + 迁移**）、`aiTasks/rewrite.ts` / `creative.ts` / `stream.ts` 的产出落点、导出
- **步骤**：① 按章/按书统计 AI 产出占比，区分 生成 / 改写 / 续写 / 润色 四类来源；② 默认**静默统计**，不打断写作；③ 一键生成申报说明草稿（用了哪些 AI 功能、用在哪些环节、人工改写比例），供平台如实勾选与留存
- **平台口径参考**（2026-08 核查；阈值易变，仅作提示不作判定）：起点 AI 占比 >10% 触发处理、人工改写需 >30% 才算合规；晋江最严（仅允许校对 / 要素整理 / 粗纲）
- **验收**：数字来自真实记录而非手填，能与证据包联动导出

### A5 · 编辑器排版与手感（自由缩进）（原 B4）

- **需求（老大 2026-09-21 提）**：优化文本编辑使用体验，**允许用户自由缩进排版**
- **批次说明（2026-09-21 老大决策）**：本项由 2.4.1 的 B4 **提入 2.4.0**、编号改 **A5** —— 2.4.0 就带这套手感；独立项，可与 A 组其余项并行
- **涉及模块**：`NovelEditor.tsx`（双图层 textarea）、`useNovelEditorGhost.ts`（键盘分发，**Tab 已被占用**）、`lib/textTools.ts`（`formatNovelText`）、`index.css`（`.novel-textarea`）；导出侧 `exporter.ts`
- **现状（已核源码）**：编辑器**没有任何缩进编辑能力** —— Enter 不继承缩进、Tab 归伴写、粘贴不归一。唯一的排版能力是工具栏「一键排版」`formatNovelText()`，它是**整篇重排**：去行尾空白 → 空行折叠成 1 → **每行强制 `　　`（两个全角空格）前缀** → trim 首尾空行 ⇒ **手写的自定义缩进会被抹平**，这正是本项要解决的痛点
- **步骤**：① **回车自动缩进**（新行沿用当前行缩进；空行回车删掉缩进、回到段首层）；② **Tab / Shift+Tab 缩进与反缩进**（行首插/删一个缩进单位；选中多行则整块）；③ **缩进单位可选**（全角空格 ×1/×2（默认）／半角空格／Tab 字符）；④ **粘贴归一**（多行粘贴按当前单位归一，开关默认开）；⑤ **一键排版升级**为「保留既有缩进深度、只清异常空白 + 折叠多余空行」，旧的「强制统一为段首两格」保留为**独立可选项**；⑥ 可选：段首缩进标记显示
- **🔴 与伴写的键位（2026-09-21 老大决策，已推翻原「Tab 双态」方案）**：`useNovelEditorGhost.ts` 原用 Tab 采纳伴写建议 —— 现改为**键位彻底解耦**：
  - **`Tab` / `Shift+Tab` 无条件归缩进**（不再看有没有建议，消除"同一个键两种含义"的心智负担）；
  - **`Ctrl+Enter` ＝ 采纳伴写建议**（原 Tab 的职责）；
  - **`Alt+/` ＝ 换一句**（原 `Ctrl+Enter` 让位；判断用 `e.code === 'Slash'`，避免布局差异）；
  - 不变：`Alt+\` 手动触发一句、`Esc` 丢弃、`→`（光标已在正文末尾时）采纳。
  - ⚠️ **联动（发布时再改，别现在改）**：推广帖第 1 篇的版本口径是 **2.3.1**、描述的也是 2.3.1 的键位（Tab 采纳／Ctrl+Enter 换一句），**该文不动**。键位变更属 2.4.0 —— 等 2.4.0 出包时随版本号一起写进新帖或修订版，避免"帖子描述的功能与读者装到的版本对不上"。
- **🔴 实现约束**：① 双图层 —— 缩进即改文本，叠层必须经 `scanRefHighlight` 重建、盒模型逐项一致；② **撤销栈**：程序化插入必须走 `setRangeText()` / `execCommand('insertText')`，**禁直接改 `value`**（一改 Ctrl+Z 就断）；③ 只动 `content`/`wordCount`/`updatedAt`；④ 输入法 `isComposing` 期间不抢键；⑤ **缩进是作者的排版主权** —— 伴写/改写/续写/拆书一律不得增删缩进，`promptGuard.authorBlock()` 不动正文；⑥ 历史章的手动排版**不**受「改写档冻结」限制（冻结只管 AI 改写）
- **⚠️ 与 #004 字数口径联动**：`countWords` 只数 CJK 与 `[a-zA-Z0-9]+`，**缩进空格不计入**；网文平台的「汉字＋标点」口径是否含全角空格须一并确认（影响看板数字与平台对齐）
- **验收**：① 手写三级缩进各自**延续**（段首 / 缩进一级 / 缩进二级，回车后仍在该级）；② Tab 与 Shift+Tab 对单行、多行都对；③ **Tab 恒为缩进**、伴写采纳改用 `Ctrl+Enter`（键位已换，见上文）；④ Ctrl+Z 能逐步回退、不跳段；⑤ 一键排版跑完后自定义缩进**仍在**；⑥ 导出 TXT / MD / 平台粘贴版的缩进与编辑器一致
- **量级**：中（改动集中在编辑器，但**必须实机验证**：双图层、撤销栈、输入法三处都易出隐性回归）

### B5 · 章末钩子与爽点节奏（提级项）✅ 已完成（2026-09-22）

- **涉及模块**：`aiTasks/pace.ts`（新）+ `lib/paceAnalysis.ts`（新）+ `components/PaceAnalysisPanel.tsx`（新）
- **步骤**：① 章末钩子检测（是否有悬念/未完成事件/信息缺口）；② 章内爽点密度曲线；③ 信息增量评估（本章是否推了主线）
- **验收**：能给出「本章爽点集中在前段、后段空转、章末无钩子」一类可操作结论
- **风险**：判据偏主观 → 只给**观察与建议**，不做分数排名，避免误导作者机械迎合
- **实现（2026-09-22）**：
  - 🔴 **段位由本地算**：AI 只出「原文引用 + 类型 + 说明」，前/中/后段由 `paceAnalysis.locateQuote()`
    拿引文在正文里的字符下标换算 —— 位置是**算出来的**，不是模型说了算；引文没定位到会显式标「未定位」。
  - 落点＝**检查工具页的新面板**（不新增页签）。与既有「投稿前自检」分工：那个看**全书**分布（纯本地），
    这个看**单章**节奏（需 AI）。两者并列，且**不重复**已有的「颉文姬⑥爽点/毒点检查」（那是自由文本编辑视角）。
  - 章末钩子区＝正文末 12%；AI 的钩子判定旁边并列显示**本地事实**（钩子区字符数），便于对照。
  - 🔴 立场：面板与提示词都只给结构观察，不给分、不排名；`tests/paceAnalysis.test.ts` 带**立场断言**
    （直接读源码，禁词一个都不许出现 —— **连注释里也不行**，已因此修过两次）。

### B6 · 左下角工具栏可折叠（2026-09-22 老大新增）
