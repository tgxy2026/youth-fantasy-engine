## 三、三个新约束（D2 没遇到，决定方案形状）

### 约束① 提示词必须"就地声明"，不能集中搬走

`src/lib/promptSettings.ts` 第 9–11 行是**上一轮定下的架构决策**，原文：

> **默认值仍住在原文件**（就地声明 `let X = \`…默认…\``），这里只登记「读它 / 写它」的访问器
> —— **不把提示词正文搬到一个中心文件里**，否则「提示词 ↔ 用法」被打散，改代码时要满仓库找。
> ⚠️ 因此被登记的提示词必须是**模块级 `let`**（函数内的局部常量改不了）。

→ 否决了"建一个 `aiTasks/prompts.ts` 集中放 24 句提示词"的省事做法。

### 约束② D2 的"活绑定"招式在这里**不成立**

D2 里 `ops` / `currentProjectId` 只需**被兄弟模块读**，所以 `export let` + ESM 活绑定就够。
但这里注册表要**写**：

```js
() => P_chapter_review, t => { P_chapter_review = t }   // ← setter 在别的模块里赋值
```

而 **ESM 中对 import 进来的绑定赋值是编译错误（TS2632）**。所以"把 `P_*` 直接 export 给外部改"这条路是死的。
→ 必须让**提示词变量与它的 setter 处在同一个模块内**。

### 约束③ 🔴 注册顺序 = 设置页显示顺序（有语义，会被改坏）

`promptSettings.ts::listPrompts()`：

```ts
all.sort((a, b) => GROUPS.indexOf(a.meta.group) - GROUPS.indexOf(b.meta.group))
// 只按 group 排序，组内保持「登记顺序」（V8 sort 稳定）
```

`AIPromptSettings.tsx` 直接消费它 → **组内逐条顺序 = 源码里 `registerPrompt` 的书写顺序**。

现状 24 条注册的书写顺序（与所在功能块的先后**并不一致**）：

| 序 | id | 序 | id | 序 | id |
|---|---|---|---|---|---|
| 1 | organize-rows | 9 | term-dedup | 17 | chapter-rewrite-latest |
| 2 | proofread | 10 | style-audit | 18 | extend-outline |
| 3 | name-suggest | 11 | editor-diagnosis | 19 | continuation-advice |
| 4 | sensitive-recheck | 12 | chapter-review | 20 | pleasure-check |
| 5 | continuity-audit | 13 | ooc-check | 21 | opening-check |
| 6 | feedback-analysis | 14 | **rewrite-passage** | 22 | writing-briefing |
| 7 | project-diagnosis | 15 | **chapter-rewrite** | 23 | extract-entities |
| 8 | foreshadow-review | 16 | chapter-rewrite-history | 24 | deai-rule |

⚠️ 注意第 14/15 条：**选区改稿（`#18` 块）排在整章改写（`#17` 块）之前** —— 因为注册表在文件末尾按"另一套顺序"写的。
若简单按功能域分组注册（organize→…→rewrite→review），`#18` 会跑到 `#17` 前面，**设置页顺序就变了**。

**`listPrompts` 按 group 稳定分组后的现状顺序**（正文写作组）：
`rewrite-passage → chapter-rewrite → ch-rewrite-history → ch-rewrite-latest → extend-outline → continuation-advice → writing-briefing → deai-rule`

## 四、解法

### 4.1 提示词跟域走 + 每域导出「可注册项」

```ts
// src/lib/aiTasks/rewrite.ts （域模块内部）
let P_rewrite_passage = `你是小说文字编辑…`          // ← 就地声明，模块私有，不导出
let CHAPTER_REWRITE_BASE = `你是长篇小说文字编辑…`

export const REWRITE_PROMPTS: PromptDef[] = [
  { id: 'rewrite-passage', /* order: 14 */ meta: {group:'正文写作', name:'选区改稿', …},
    read: () => P_rewrite_passage, write: t => { P_rewrite_passage = t } },
  …
]
```

- ✅ setter 与变量**同模块** → 合法，无 TS2632
- ✅ 提示词正文**仍住在用它的文件里** → 满足约束①
- ✅ `P_*` **不进公开 API**（对外仍是 75 个导出，与现在一致）

### 4.2 门面用「顺序表」严格还原注册次序（解约束③）

```ts
// src/lib/aiTasks.ts （门面末尾）—— 顺序即界面顺序，改动前先看 promptSettings::listPrompts
const PROMPT_ORDER = [
  'organize-rows', 'proofread', 'name-suggest', 'sensitive-recheck',
  'continuity-audit', 'feedback-analysis', 'project-diagnosis', 'foreshadow-review',
  'term-dedup', 'style-audit', 'editor-diagnosis', 'chapter-review', 'ooc-check',
  'rewrite-passage', 'chapter-rewrite', 'chapter-rewrite-history', 'chapter-rewrite-latest',
  'extend-outline', 'continuation-advice', 'pleasure-check', 'opening-check',
  'writing-briefing', 'extract-entities', 'deai-rule',
]
registerAllPrompts(PROMPT_ORDER)   // 逐 id 查表注册；查不到的 console.warn（不静默丢）
```

- 顺序**逐条还原**（含 `#18` 早于 `#17` 这个反直觉项）
- 新增提示词若忘了登记进 `PROMPT_ORDER` → **warn 出来**，不会静默丢
- `PROMPT_ORDER` 是"唯一真相"，注释里写明"顺序 = 设置页顺序"

> 备选（更省事但会改 UI）：直接按域注册、接受组内顺序变化。**不建议** —— 老大的要求是"原有功能不变"。
