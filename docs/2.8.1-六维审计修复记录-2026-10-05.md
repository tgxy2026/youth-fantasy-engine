### B. 本轮新功能的真 bug（3 项，全部由审计/实机抓出）

**B1 · 动态额度百分比从未接线**（`useTavernQuota`）

界面三处调用都写 `useTavernQuota(undefined, undefined)` —— 第三个参数 `dynamicPct` 一次都没传，
于是**界面永远按默认 15% 显示、并按 15% 卡「超额度不许保存」，而引擎按作者设的 30% 注入**。
（作者把比例调到 30% 后，本页仍显示 15%，保存拦截线也错。）

修法：**不让调用方传** —— hook 内部自读 `getTavernSettings().dynamicQuotaPct`（切页签会卸载组件，
重进必读最新值）。显式传参仍优先。这样「漏传」在结构上不可能发生。

**B2 · 回滚到不足 12 条时旧索引不重建**（`lib/tavern/recall.ts`）

原代码把「消息太少就不建索引」的早退放在「消息数变少」判断**之前** ⇒ 作者回滚检查点、
可用消息退到 12 条以下时直接 `return`，**旧索引原封不动**，召回继续把「已经退回去、不曾发生」
的片段捞回来（比不召回更糟）。

修法：把「变少」判断提到最前；变少且不值得重建时**显式清掉本场索引**
（新增 `deps.removeRef` 注入点，默认走 `removeByRef`）。

**B3 · 「固定层」额度从未用于注入**（设计核心，`world.ts` / `story.ts` / `engine.ts`）

设计是**两层**：固定层 = 一句话总纲 / 世界设定（全量注入），动态层 = 四色灯控制的词条。
但引擎两处调用都只传了 `maxChars: dynamicQuotaOf(...)` 一份额度，`fixedQuotaOf` **全项目零调用点**
（只被界面用来卡保存）。后果很具体：**8K 窗口下 `dynamic`（≈1229）< `fixed` 下限 2400** ⇒
作者按界面提示存了 2400 字总纲，进上下文时被砍掉一半 —— **「存得下、注不进」**。

修法：`buildPlotWorldBook` / `buildStoryWorldBook` 各拆成**两层分别渲染**
（判据是 `WORLD_BRIEF_ID` / `STORY_SETTING_ID` 两个新抽的常量真源），
`engine` 两处用 `quotaProfileOf()` 一次算清两层传下去。

> ⚠️ **B3 落地时漏了一个调用点，被实机抓到**：`TavernScript` 与 `TavernWorld` 里各有一处
> 「本轮最少注入 = 空上下文下必带的那些的完整长度」探测，原本只传 `maxChars: 0`。
> 拆层后固定层回落到默认 2400，把 9999 字的世界设定**截断** ⇒ `minChars > cap` 恒为 false ⇒
> **「超额度」告警永不出现**（实机 `ui-tavern-quota` D2 变红）。两处补上 `fixedMaxChars: 0`。
> 单测全绿、实机才响 —— 这条正是「实机验证不可省」的例证。

### D. 死代码与规范（6 项）

- **删死导出 3 个**（`audit-dead` 确定死代码 3 → 0）：`useTavernQuota.quotaFromWindow`、
  `tavern/worldBook.ENTRY_MAX_CHARS`、`lib/theme.contentMinH`
  （最后一个正是主从双栏改造的副产品 —— 三处调用点全换成 `contentHeight` 之后它就没人用了）。
- **四色灯走主题 token**：`EntryStatePicker` 写的是裸 `bg-sky-400` / `bg-emerald-400`，
  而文件注释自称「色值走主题 token，不写裸色值」—— **自我矛盾**。改为 `bg-info` / `bg-success`
  （`--info` = sky 系、`--success` = emerald 系，色相一致且随主题切换）。
- **行内删除键尺寸对齐**：`CharacterSheet` 的删除键漏传 `iconOnly size="xs"`（回落到 sm，32px），
  同项目 `OutlineSheet` 的同款操作已是 24px ⇒ 补齐。
- **面板首屏 effect 加卸载守卫**：`useTavernFreeModel` / `useTavernControlModel` 的首屏加载
  没有 `alive` 标记（同批其它面板都有）⇒ 加载途中关面板会往已卸载组件 setState。
- **`shouldInjectWorld` 大小写口径**：整份闸用未小写化的 `includes`，而词条层两侧都 `toLowerCase()`
  ⇒ 同一关键词可能在两层判出不同结果。已对齐。
- **逐条取舍改「累进删」**（`worldBook.renderEntries`）：原写法对每条**单独试删**
  （试删后仍超就跳过、去试更高优先级那条）⇒ 会出现**优先级反转**：低优先级但很大的条目留着、
  高优先级但很小的条目被砍掉。改成从最低优先级开始**累进地砍**，一装下就停。

### E. 存储层「静默失败」（7 处，全部只加留痕或补查返回值）

| 位置 | 问题 | 处置 |
|---|---|---|
| `db/core.ts` 关同步前落盘 | `await flushDesktop().catch(...)` **丢弃了布尔返回值** —— 而写失败时它 `return false`（不 reject）⇒ 「没落盘」被整个漏掉，下一步却要切 ops 并 reload | 显式查返回值并留痕 |
| `db/core.ts` 镜像删除 | `catch {}` **全空** ⇒ 镜像删不掉 = 本地多余记录残留，下次开同步可能被当「本机新增」播回云端（「删了会复活」家族） | 加 `console.warn` |
| `db/core.ts` 冲突副本 | 同上全空 ⇒ 副本存在的**唯一意义**就是「云端那版不再被静默丢弃」，连副本都存不下还不吭声等于又回到静默丢弃 | 加 `console.warn` |
| `db/projects.ts` 删项目后清独立库 | 两处 `catch(() => {})` ⇒ 向量/资料残留无迹可查 | 加 `console.warn` |
| `db/projects.ts` 备份开关读取 | `catch { return false }` —— 而 `false` 的语义是「作者没勾选」⇒ **导出会悄悄剔掉参考资料**，作者以为备份里有 | 保持返回 false（保守），但如实留痕 |
| `tavern/store.ts` 幽灵清理前置 | 只挡「写盘锁」，**没挡云同步闩锁期** —— 那时 `getSession` 读到的是「开启同步那一刻冻结的本地库」，分条其实在云端 ⇒ 一律读成 null ⇒ 被判幽灵删掉索引 ⇒ 云端恢复后该会话成孤儿 | 增判 `isDesktopCloudUnavailable()` |
| `db/migrations.ts` 时间回填 | 用**赋值之前**读到的 `start` 去补「结束时间」⇒ 纯老行第一次打开漏补（第二次才自愈） | 把 `start` 的读取移到回填之后 |

**另修**：`TavernUsageDialog` 的「用量明细」原本调用完整的 `buildFreeSystem` ⇒
**打开发用量明细会触发嵌入请求**（花钱/联网，且召回结果让显示值每次都漂移）。
给 `buildFreeSystem` 加 `skipRecall`，测量路径传 `true`。
