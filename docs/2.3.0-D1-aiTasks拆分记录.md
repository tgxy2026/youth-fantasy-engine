## 四、提示词注册顺序（D1 的头号风险 · 有语义，会被静默改坏）

`promptSettings.ts::listPrompts()` 只按 group 稳定排序，**组内保持登记顺序** → 登记顺序 = 设置页显示顺序。
而原注册表里 `rewrite-passage`（属颉文姬）**排在** `chapter-rewrite`（属整章改写）**之前**，与功能块先后**不一致**。
若按域分组注册，设置页顺序就变了 —— **测试不报、实机不崩的静默 UI 回归**。

解法：门面保留一张 `PROMPT_ORDER` 表（24 条逐条还原），并做双向兜底：

```ts
for (const id of PROMPT_ORDER) { const p = byId.get(id); if (!p) { console.warn(...); continue } registerPrompt(...) }
for (const id of byId.keys()) if (!PROMPT_ORDER.includes(id)) console.warn(...)  // 新增漏登记 → 喊出来
```

**独立机械比对**（`.workbuddy/tmp/prompt-order-check.mjs`，从「备份的旧文件」与「新门面」两边解析源码）：

```
原注册表条数: 24  门面 PROMPT_ORDER 条数: 24
1 ✅ organize-rows … 14 ✅ rewrite-passage  15 ✅ chapter-rewrite … 24 ✅ deai-rule
✅ 注册顺序逐条一致（设置页顺序不变）
```

## 七、审计工具的两处增强（D1 暴露的盲点）

### ① `audit-arch.mjs` A3：门面靠**白名单**认，不靠启发式

原逻辑 `if (ls.length > 40) continue` + `转发占比 ≥ 60%`。新门面 112 行（含 `PROMPT_ORDER` 与注册编排）
且转发仅 19/80 → **被启发式静默漏报**（第一次跑只认出 `db.ts` 一个门面）。
改法：已声明门面**无条件列出**，不参与占比筛选；白名单里有但文件不在 → 报警（防删了文件忘清白名单）。
结果：`待清理 0 个 · 已声明门面 2 个`，`db.ts` 与 `aiTasks.ts` 都标 🏛。

### ② `audit-graph.mjs`：环输出**标注边类型**

原脚本只看语法边，把 `aiTasks → extract → flow/fieldMap → aiTasks` 报成 🔴 环。
真因：`fieldMap.ts` 对 aiTasks 是 **`import type`**（为共用 `SettingEntityType` 声明），编译后边消失 → 运行时不成立
（`importCycles` 闸的 `stripTypeOnlyImports` 已擦除它，所以闸是绿的，两者对不上就会让人懵）。
改法：解析时记录每条边是「值边 / 纯类型边」，环输出里逐条标注：
- 环上**存在** type-only 边 → 编译后环断开，**运行时不成立**（✅ 无需处理）
- 环上**全是**运行时边 → **真环**（🔴 必须处理）
