# 2.9.3 · 故事剧本「追加到已有故事」（2026-10-09）

> 承接 2.9.1 前后做的「故事 / 词条 / 剧本 文本导入导出」（`lib/tavern/storyImport.ts` +
> `TavernScriptImportDialog.tsx`）。原功能**只能新建故事**；本轮补上「追加进已有故事」。

---

## 1. 需求与拍板

主人原话：「之前做了一键导入酒馆模式自由对话的故事剧本功能，当时的功能仅限新增，
需要开发在原有故事中追加剧本的功能。」

三个设计点先请主人拍板，结论：

| 决策点 | 拍板 |
|---|---|
| 入口形态 | **弹窗内切换模式**（复用现有「导入」按钮，顶部加两段式切换；追加时露出目标故事下拉，默认选中左栏当前那个故事） |
| 文本里的 `〖世界设定〗` | **忽略**，只导词条与剧本（已有故事的世界观是它自己的，从别处复制来的并进去只会两份设定打架） |
| 重名（剧本 / 词条） | **当场拦下**，由作者改名后重来（不自动加序号 —— 那样会悄悄造出一个作者没写过的名字，列表里也更难分辨） |

## 3. 🔴 本轮唯一的坑：整段世界设定会**静默失效**

`story.ts` 的 `storyEntriesOf` 有一条判据：**有 `entries` 就以 `entries` 为准，`setting` 被忽略**
（老数据没有 `entries` ⇒ 整段 `setting` 退化成一条常驻词条）。

于是「追加词条」不能天真地写成 `[...story.entries, ...新增]`：

- 老形态故事（只有整段 `setting`、`entries` 为空）被这么一写，**那段设定当场不再注入**；
- 而且**不报任何错** —— 界面正常、保存成功，只有聊起来才发现模型不知道这个世界。

**处置**：追加前统一走 `storyEntriesOf(story)` 取池子（老形态会先把整段设定退化成
`id = 'story-setting'` 的常驻词条，继续按固定层每轮注入，与升级前注入结果等价），
再往后接新词条。由 `entriesToAppend` 收口，界面**提前**用 `willMigrateSetting` 判断并提示作者。

## 4. 验证

| 项 | 结果 |
|---|---|
| `tsc --noEmit` | 0 |
| `eslint src tests` | 0 problem |
| `bash tests/run-batches.sh all` | **168 全绿**（A17 / B19 / C59 / D73） |
| 实机 · 追加链路（新脚本） | **24 / 24 PASS** |
| 实机 · 新建链路（回归） | **20 / 20 PASS** |

实机断言要点（全部**直读库**核对，不看界面自报）：

- 目标故事下拉**默认选中界面当前那个故事**；
- 撞已有剧本名 ⇒ 红字「剧本「旧戏」与目标故事里已有的同名」+「追加」禁用；
- 追加后：**世界设定一字未动**、词条与剧本各 +1 且挂对 `storyId`；
- 老形态故事追加词条 ⇒ 设定被搬成**第一条常驻词条**（`id = story-setting` / `constant = true`），
  `setting` 字段本身保留（还能切回整段模式）。

## 5. 踩坑记录

1. 🔴 **实机断言判据太松会假绿** —— 第一版 C1 只判 `includes('同名')`，而弹窗**说明条**里本来就有
   「撞上同名的剧本 / 词条会拦下」，于是「冲突压根没出现」也会变绿。改为判冲突行**独有的整句**。
   （D3 的 `已忽略`、F1 的 `整段` 同理，已一并收紧。）
2. **Edge 起不来**（`Target page, context or browser has been closed`）⇒ 两个 tavern 导入脚本
   都加了 `--chrome` 兜底开关。
3. **脚本必须放在 workspace 目录里跑** —— ESM 从**脚本路径**向上找 `node_modules`；
   放别处即便 cwd 是 workspace 也会 `ERR_MODULE_NOT_FOUND: playwright-core`。

## 6. 未做的（有意）

- **不做「追加时更新已有同名剧本」** —— 那是「覆盖」，与「重名拦下」的拍板相冲，宜独立提案。
- 不在左栏故事行加「＋ 追加」快捷入口（主人选了「弹窗内切换模式」这一种）。
