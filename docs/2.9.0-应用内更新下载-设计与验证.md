## 二、为什么这么做（现状与缺口）

**2.6.3 起就已经有「检查更新」**：

- `lib/versionCheck.ts`：查 Gitee `releases/latest`（**匿名 API，无需令牌**）、语义化版本比较、每天最多一次、跳过此版本、自动检查默认开；
- 已经**在解析 assets 里的安装包直链**（`pickInstallerUrl` 挑 `.exe`）；
- 主进程桥 `net:fetch`（主进程栈、**无 CORS**、跟随用户代理设置）；
- `UpdateDialog.tsx` 渲染 Gitee 更新说明 + 夸克网盘兜底。

**缺的只是最后一步**：点「下载」= `openExternalUrl(直链)` → 交给系统浏览器，用户自己在浏览器里下完再手动装。

⇒ 本批就是把这一步改成回内完成。

## 三、🔴 口径变更（原来的红线写死了「不下载」）

`versionCheck.ts` 原来的三条红线第 ② 条是：

> **只提示，不静默下载 / 不自动安装 / 不阻断使用** —— 决定权永远在作者手上。

改成：

> ② **自动检查绝不下载任何东西**（只比版本、只弹提示）。**下载必须由作者点按钮触发**，
> 且有进度、可取消、不静默安装（安装向导由作者自己点完）。

**精神没变**（决定权仍完全在作者手上）：变的只是「点下载之后」——从「开浏览器」改成「在程序里下」。三条不可越的底线（① 只发一个匿名 GET、不带任何用户数据 ② 不静默下载/不自动安装 ③ 失败一律静默）**全部保留**。

## 四、实现结构

### 4.1 新增：`electron/updateDownload.cjs`（主进程下载内核）

| 能力 | 说明 |
|---|---|
| `downloadInstaller({url, dir, fileName, onProgress})` | 返回 `{ok:true,path,size}` 或 `{ok:false,cancelled?,error}`；**永不 throw** |
| `cancelActiveDownload()` | 中止进行中的下载（同一时刻只允许一个） |
| `sanitizeInstallerName(raw)` | 只取 basename、剔控制字符与 Windows 非法字符、**强制 .exe**、限长 120 |

### 4.2 IPC 契约（main.cjs 注册 / preload 暴露为 `window.electronUpdate`）

| 通道 | 作用 | 关键约束 |
|---|---|---|
| `update:download` | 下载安装包 | 目录由主进程钉死 `app.getPath('downloads')` |
| `update:cancel` | 取消下载 | 返回 `{ok}` |
| `update:launch-installer` | 拉起安装向导 | 先过 `isDownloadedInstaller` 校验；`closeApp=true` 时 3 秒后退出本程序 |
| `update:reveal-file` | 在资源管理器里定位 | 同样过校验 |
| `app:quit` | 退出本程序（安装前腾文件） | 走 `app.quit` ⇒ 触发渲染层 `beforeunload` 同步存盘 |
| `update:progress`（主→渲染推送） | 下载进度 | 主进程侧**节流 ≥200ms** 一次 |

### 4.3 渲染层

- `desktop.ts`：`HAS_UPDATE_BRIDGE` + 五个封装函数（**全部永不抛**，失败走 `ok:false`）+ `onUpdateDownloadProgress`；
- `UpdateDialog.tsx` 重写为五阶段状态机：`idle → downloading（进度条＋取消）→ launching → launched（已下载，可「关闭本程序」/「打开所在文件夹」）／ error（重试 / 夸克网盘兜底）`；
- 下载中**禁止关闭弹窗**（避免用户以为取消了其实还在下）；组件卸载有 `alive` 守卫（分钟级长任务回来时组件可能已不在了）。

## 五、🔴 安全边界（六条，逐条都可被闸验证）

1. **只有用户点按钮才下载** —— 自动检查那条链路（`versionCheck.ts`）**不引用任何下载 API**；
2. **落盘目录由主进程钉死**（渲染层给的是文件名，不是路径）；
3. **文件名在主进程清洗**（只取 basename + 强制 `.exe`，防路径穿越与控制字符）；
4. **先写 `<name>.part`，成功后才 rename** —— 中断/失败不会留下半截 `.exe` 被用户误当成品双击；
5. **内容判定**：`content-length` 精确比对（挡截断）＋ **PE 文件头 `MZ`**（挡兜底页，见 §六.1）；
6. **拉起安装器前再校验一次**「在下载文件夹里 + `.exe` + 真实存在」—— 这个口子不能变成「执行任意 exe」的万能入口。

## 六、🔴 实机探针抓到的两个真问题（不实测发现不了）

### 6.1 兜底页拦截被绕过：Gitee 把网页以 `text/plain` 返回

第一版按「`content-type` 含 `text/html` 就拒绝」挡兜底页。**实机探针直接证伪**：

```
FAIL ④ HTML 页被拒 :: {"ok":true,"path":"…\\probe-html.exe","size":45975}
```

curl 实测 `/tgxy2026/youth-fantasy-engine` 的响应头是 **`Content-Type: text/plain; charset=utf-8`** —— 那个 45KB 的仓库网页被当成安装包存了下来。

**修法**：改以**文件头**为准 —— 真安装包是 PE 可执行文件，**头两字节必为 `MZ`**（`0x4D 0x5A`）。
这一条同时挡住 HTML 页 / JSON 报错页 / 登录墙截断的响应，且**对真安装包零误判**（已用交付的 `Setup-2.9.0.exe` 自证）。

> 分工：**`content-length` 挡「下到一半断了」，`MZ` 挡「下到的是个网页」** —— 两者互补，都不能省。

### 6.2 仓库默认分支是 `main`，不是 `master`

探针里 `/raw/master/...` 一律 404 ⇒ 改成 `/raw/main/...`。这条对以后写 Gitee 链接也有效。

## 八、已知限制（如实记录，不粉饰）

1. **不做静默全自动升级** —— NSIS 是 assisted installer（`oneClick=false`），安装向导必须由人点完；
   下载完只是**自动把向导拉起来**（这也是主人选的口径）。
2. **没有摘要校验** —— Gitee 的 assets 不提供 sha256，本批按主人口径只比对大小（＋PE 文件头）。
   界面文案如实写明，不假装有校验。
3. **直链可能不稳/需登录** —— 大文件（113MB）从 Gitee 拉可能慢或偶发限流；失败时界面保留**夸克网盘**兜底按钮。
4. **需要 Release 才生效** —— 得先建 v2.9.0 的 Gitee Release（含安装包附件），否则取不到直链。
5. **本批改了代码 ⇒ 交付包需重出** —— `release/桌面安装版/青春幻想引擎-Setup-2.9.0.exe`（16:41 那份）
   **不含本次改动**，发布前须重新封装。
