## R1 · 看板娘设置（弹窗化 + 自定义图片）

### 社区反馈原文要点
用户想更换项目管理首页的看板娘。把现有「开关看板娘」的按钮升级为「看板娘设置」：点开是弹窗，里面可以 ①开关看板娘 ②上传自定义图片替换；弹窗内要有文字说明图片要求（是否透明背景、规格比例等）。

### 现状侦察（2026-09-27 源码核实）
- 看板娘本体：`ProjectHub.tsx:581-588`，`<img src={jiewenjiGufeng}>`（`src/assets/jiewenji-gufeng.png` 静态 import，**编译进产物**）；fixed 右下角、`Z.sprite` 层、`foldVh('min(380px, 20vw)')` 宽度、`pointer-events-none`。
- 开关：操作条按钮「看板娘」（`ProjectHub.tsx:230-237`，toggle 选中态），偏好键 `yfe-ui:home-mascot-hidden`（`usePersistedBool`，默认显示）。
- **注意区分两位**：项目管理首页这位（古风立绘，本批对象）与正文页右侧「颉文姬 Q 版精灵」（`JieWenJiSprite.tsx`，开关在颉文姬面板底部）是**两套资源两个开关**。本批只做首页这位；颉文姬精灵是否同样支持自定义 → 拍板项。

### 方案（待拍板）
1. **按钮改造**：操作条按钮文字「看板娘」→「看板娘设置」，点击不再直接 toggle，改为开弹窗（尺寸口径：弹窗 md）。
2. **弹窗内容**（三块）：
   - **开关**：沿用 `home-mascot-hidden` 偏好键与语义（默认显示），toggle 控件；
   - **自定义图片**：上传 → **先压缩再入库**（🔴 红线：图片必压）→ 存 `settingsKV`（随本机全局，还是随项目？→ 拍板项，建议全局：看板娘是界面偏好不是项目数据）→ 渲染时自定义图优先、无则用内置默认；提供「恢复默认」；
   - **说明文案**：透明背景 PNG 推荐（非透明会带白底压在界面上）、建议尺寸比例（参考现有图约 1:2.2 竖幅、宽度展示上限 380px）、体积上限（压缩后阈值）、支持格式（png/webp/jpg）。
3. **渲染适配**：自定义图的比例不可控 → 保留 `min(380px, 20vw)` 宽度上限 + `maxHeight: 82vh` 现有钳制，超比例图自动缩入；不因自定义图改布局红线。
4. **工程红线对照**：压缩管线复用现有图片压缩工具；`NumberField`/弹窗尺寸/HelpPopover 跟功能名等 UI 红线照常过闸；新增 AI 无 → 无 aiTasks 注册面。

### 验收判据
- 默认状态观感与现状零差异（未上传时走内置图）；
- 上传透明 PNG 后首页立绘替换、重启仍在；「恢复默认」一键回退；
- 开关关掉后 `img` 不渲染（与现状同路径）；
- 实机：上传超规图被压缩/拦截并有提示；弹窗问号紧跟「看板娘设置」。

## R2 · 一键拆书：章节切分支持「标题示例」（AI 识别路径）

### 社区反馈原文要点
把「AI 自动划分识别切分章节」的提示词从原提示词中去掉；一键拆书提供前端输入窗口，让用户填写**章节标题示例**，作为单独提示词给 AI，让它更好地识别和拆分章节；原文没有明显章节可切时，仍按原方式保留**按字数拆分**。

### 现状侦察（2026-09-27 源码核实，⚠️ 与反馈描述有出入）
- 切分是**纯本地正则，零 AI**：`src/lib/bookbreak/split.ts` 的 `CHAPTER_TITLE_RE`（支持 第X章/第一章/第壹回/第12节/Chapter N/卷X：【…】），命中 ≥2 个标题行走「章节模式」，否则走「字数兜底分块」（`chunkText`，token 上限 + 句界回退 + 重叠）——文件头明示「纯函数，零 AI 依赖，可单测」。
- **AI 只参与切完之后的逐块抽取实体**（`run.ts` 六阶段），不存在「AI 切分章节」的提示词。
- ⇒ 反馈里「去掉原提示词」实际无可去掉；真实痛点是**标题格式不在正则覆盖内时（如「01|风起」「★第一章★」「风起（一）」这类变体），正则认不出 → 整本掉进字数兜底**。方案据此调整形态。

### 方案（待拍板）
1. **切分优先级变为三级**（`splitNovelText` 保持签名兼容）：
   - ① **本地正则**（现状规则不动，先跑）；
   - ② **AI 章节边界识别**（新增，独立提示词——不是塞进抽取提示词）：仅当 ① 命中 <2 且用户填了标题示例时触发。把「原文前 N 千字（采样头部+若干中部切片）+ 用户示例」发给 AI，让它返回章节起始行的**原文引用列表**（🔴 防幻觉：AI 只能从原文里挑行，程序按 `charStart` 精确回定位，AI 报的行必须在原文中逐字命中才采信，命中 <2 就弃用）；
   - ③ **字数兜底**（现状 `chunkText` 原样保留，② 失败/未启用时走）。
2. **前端输入窗**（`BookBreakPanel`）：
   - 新增「章节标题示例」输入框（textarea，几行即可，placeholder 给格式示例），内容随拆书设置持久化（`settingsKV`，键名建议 `bookbreak.title-samples`，全局——同一批书的格式习惯通用）；
   - 触发条件展示：① 已识别出章节 → 提示「本地规则已识别 N 章，无需 AI」（省调用）；② 未识别 → 显示「将用 AI 按你的示例识别章节边界（约消耗 X 次调用）」（复用 `recommend.ts` 的调用估算口径）；
   - 说明文案写清：示例越接近真实标题行越好，一行一个，3~5 条为宜。
3. **四件套登记**：新 aiTask（如 `bookbreakSplit`）须注册 `aiTasks` 门面（import+export+`PROMPT_ORDER`+`PROMPT_SETS`）、`aiDataSources`、`aiWriterBudget`（同步 tests LEGACY）——🔴 漏一处静默半残。
4. **解析纪律**：AI 返回走 `parseLooseObject`；结构化任务温度固定 0.3。

### 验收判据
- 标准标题文本：行为与现状完全一致（① 命中，不触发 AI）；
- 非标标题（如「01|风起」）+ 填示例：AI 识别出的边界行在原文逐字命中、切分结果 `mode:'chapters'`、章数合理；
- 非标标题 + 不填示例：仍走字数兜底（现状行为不变）；
- AI 报不存在的行 → 全部弃用回退兜底（防幻觉闸生效）；
- 单测：split 纯函数部分 + 边界采信逻辑；实机：真模型跑一轮非标文本。

## 七、追加修复 · 章节树折叠保持 + 打开项目定位最新章（2026-09-28，两条社区反馈）

### 核实
- **折叠被强制展开（属实）**：`load()` 每次无条件 `setExpanded(全部卷)`，增删卷章/改名都走 `load()`；且正文编辑页是条件渲染 ⇒ **切页签再切回也重挂重跑**，比反馈的「新增章节」多一条复现路径。
- **不定位最新章（属实）**：`load()` 默认恒落第一卷第一章。

### 落地（useNovelEditorModel + NovelEditorChapterTree）
- 折叠偏好按项目持久化（`editor-vol-collapsed:<projectId>`，🔴 存偏离默认侧＝已折叠集合）；`setExpanded` 换签名兼容的持久化包装，树组件零改动。
- `load()` 首跑以持久化折叠集为准 + 落点章所在卷强制展开；重载只并入新卷（`seenVolIdsRef` 区分「新卷」与「用户折叠的卷」），**不**强制展开落点卷（防同 bug 换入口复发）。
- 上次编辑位置持久化（`editor-last-chapter:<projectId>`）；恢复链 = 上次位置 > updatedAt 最新 > 第一卷第一章；落点章所在卷自动展开。
- 新建章 / 跨页签跳转显式展开目标卷；树加 `data-chapter-id` + 激活章 scrollIntoView。
