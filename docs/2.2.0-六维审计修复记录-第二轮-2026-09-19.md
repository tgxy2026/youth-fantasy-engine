## 一、字号阶梯（原 1495 处任意值 / 15 种 px）

**做法**：在 `tailwind.config.js` 立 9~17 的整数档，再把 `text-[Npx]` 全部换成 `text-N`。

```
fontSize: { '9':'9px','10':'10px','11':'11px','12':'12px','13':'13px','14':'14px','15':'15px','16':'16px','17':'17px' }
```

⚠️ **只给字号、不给行高**（值是字符串而非 `[size, lineHeight]`）——
原来 `text-[12px]` 只设 font-size、行高继承；若在此指定行高会全站行距突变。

半像素统一向下取整：`10.5→10`、`11.5→11`、`12.5→12`、`13.5→13`、`9.5→9`、`8→9`（最小档 9）。
最大视觉差 0.5px。

**替换规模**：1498 处 / 96 个文件。

**验证**（不只是"跑通了"）：构建后从产物 CSS 逐个核对 ——
```
.text-9{font-size:9px}   .text-10{font-size:10px}  .text-11{font-size:11px}
.text-12{font-size:12px} .text-13{font-size:13px}  .text-15{font-size:15px}  .text-17{font-size:17px}
```
且产物中 `text-[…]` 已归零 —— 证明 Tailwind 真的生成了这些类，不是留下一堆不存在的类名。

## 二、下拉浮层定位逻辑去重（5 个组件各写一遍）

`CalendarSelect / CalendarPicker / CharacterSelect / CustomSelect / TableRefSelect`
各自抄了一份「下方不够就上翻 + 算可用高度 + 夹住左边」，参数还漂移了：
估算高度 256 / 264 / 288、翻转阈值 200 / 220 / 240 / 248、留白 8 / 12。

**做法**：抽出**纯几何** `src/lib/dropdownPos.ts` → `computeDropdownPos(rect, opts)`。
组件仍各管各的 effect 与 state（保留各自的生命周期，不动行为），只把那 14 行算法换成一次调用。

```ts
setPos(computeDropdownPos(btn.getBoundingClientRect(), { estH: 288, flipBelow: 220, margin: 12, minWidth: 180, clampRight: 200 }))
```

参数按各组件**原值**传入（不做行为统一），`CalendarSelect` 传 `estH: null`
（它的浮层靠自身 `max-h-72` 限高，不产出 `maxHeight`，形状与其他四个不同）。

同时把 4 个组件的 pos state 类型统一为 `DropdownPos`（原来写死 `maxHeight: number` 必填，与可选字段冲突 → TS2345）。

**效果**：A1 最长重复块由 14 行降至 9 行；`CharacterSelect ↔ TableRefSelect` 重合度 51% → 48%。
剩余 9 行是各组件的 effect 样板（"什么时候重算"），属有意为之，未合并。

> ⚠️ 这里保留 `getBoundingClientRect()` 是正确的：算的是**视口坐标**（浮层 fixed 定位），
> 与 `window.innerHeight` 同坐标系，界面缩放下依然成立 —— 这正是"量尺寸走 offsetHeight"
> 红线的例外情形（那条管的是量元素自身尺寸）。

## 三、复核后判定不改（附理由）

| 项 | 复核结论 |
|---|---|
| `Button.tsx` 的 `text-white` / `bg-black/60`（U1，11 处） | 是**白字配实心色底**（`bg-red-500 text-white`、`bg-sky-500 text-white`）。改 ink token 会破坏对比度，属正确设计 |
| `FactionGraph` 十六进制色（U2） | 「同盟=绿 / 敌对=红」是**语义色**，本就该固定，不该随主题变 |
| `seedData` 播种失败 2 处（仍只 log） | 失败只影响**示范内容**（背景设定 / 演示会话），不影响用户数据；弹「示范背景设定播种失败」对作者是噪声。与"备份失败"性质不同 —— 后者是数据安全，必须可见 |
| `syncTransport:269` 损坏文件备份失败 | 外层已有用户可见路径：`syncStatusMeta` 有 `同步失败` 态 + 状态栏展示 + toast |
| 8 个面板缺 AI 就绪守卫 | 均无禁用态，但每个都有 catch → toast / setError，用户看得见报错。属 UX 优化 |
