## 一、2.5.0 的定位与两个目标

| 目标 | 一句话 | 对应条目 |
|---|---|---|
| **构思层补强** | 吸收故事织机的长处：把权威叙事结构变成可用的脚手架，补上「全书配比」这块真空白 | A1 结构模板库、A2 全书配比偏差 |

**总原则（主人哥哥 2026-09-25 明确）**：照竞品调研的方向开发，**但不是照单全收**——结合项目自身情况逐项评估；达不到预期效果、产生新冲突、或收益不高的，**适当放弃**。故本规划为每项都写明**「中止判据」**（见第四节各条目与第六节），触发即记录理由、干净止损、不留半成品。

## 四、逐项实施要点

> 每项的「涉及模块」为开工前必读位置，实施时以实际源码为准（若与文档不符，以源码为准并回改文档）。

### A1 · 结构模板库

- **做什么**：内置若干权威叙事结构模板（节拍名 + 全书占比区间 + 一句话定义 + 引导问题），供细纲生成与情节推演当「可填空的脚手架」。这是故事织机口碑的核心来源，也是我们真空白。
- **涉及模块**：新增 `src/lib/storyStructures.ts`（纯数据 + 类型，**内置静态数据不进库**）；`aiTasks`（细纲生成提示词注入）；创意写作参数区（「参考结构」下拉）；情节推演画布（「按模板铺节点」）；模板选择存 `settingsKV`（项目级键，如 `structureTemplate`）
- **模板清单（首批固定 4 套，不加页签不改 schema）**：
  1. **三幕式**（建置 / 对抗 / 解决，占比 25/50/25）
  2. **Save the Cat 15 拍**（开场画面→主题呈现→铺垫→催化剂→争执→进入第二幕→B 故事→游戏时光→中点→坏人逼近→一无所有→灵魂黑夜→进入第三幕→结局→终场画面，采用通用公开的节拍占比）
  3. **起承转合**
  4. **网文三卷式**（含黄金三章与卷末钩子的本土口径）
- **🔴 版权红线**：节拍名 / 占比 / 方法论**思想**不受版权保护，可放心内置；但**定义与引导问题的文字全部自撰**，绝不搬运任何书籍原文，也绝不抓取对方产品的模板内容库
- **步骤**：① 写模板数据（含类型与校验，封闭的模板 id 枚举）；② 创意写作：细纲生成前若选了模板 → 节拍表压缩注入提示词当骨架约束（文本量控制在预算内，复用细纲生成既有 budget kind，**不新增 kind**）；③ 情节推演画布：一键按模板铺出节拍节点（内容留空由作者填 / 或走既有推演链）；④ 模板选择持久化 + 默认「不使用」
- **验收**：选模板生成细纲，产出能看出节拍骨架（如中点大致落在 45%~55%）；不选则与现状完全一致（零回归）；模板数据有单测（占比单调、定义非空）
- **🔴 中止判据（触发即止损）**：
  - 提示词注入后细纲质量**下降**（同输入对比测试）→ 模板退化为「仅参考视图 / 铺节点」，**不再注入生成链**；
  - 模板文本注入导致预算超限或解析失败率上升 → 只保留②③两处本地用法；
  - 数据维护成本失控 → 收缩到 2 套（三幕式 + 网文三卷式）

### A2 · 全书配比与偏差分析（MVP，纯本地）

- **做什么**：对方独家功能「预测分量」的我们版——以 A1 的结构模板为理想曲线，叠加**实际章节字数占比**（后续可扩爽点密度），高亮偏差大的区段（如「中点该在 50% 处，实际高潮提前到 30%」）。**MVP 零 AI 依赖**：无模型配置也全功能，数据全部本地。
- **涉及模块**：新 `components/StructurePacePanel.tsx`（挂**检查工具页**，与 B2 / C3 / B5 / C4 / C5 面板并列，**不新增页签**）；数据源＝既有卷-章-字数统计 + A1 模板数据；字数口径复用 `lib/wordCountMode.ts` 单一真源
- **与 B5 的分工（不重复）**：B5 PaceAnalysisPanel（2.4.1 已完成）看**单章内部**节奏（需 AI）；本项看**全书卷章结构**配比（纯本地）。并列互补，界面文案写明分工。
- **步骤**：① 计算实际占比序列（按章字数 / 全书总字数）；② 与所选模板节拍区间逐段对照，算偏差并给三档提示（贴合 / 轻微偏移 / 明显偏移，**只描述不给分**）；③ 双条带可视化（理想节拍带 vs 实际章节带）；④ 最小样本门槛：全书 < 10 章时显示「样本不足」引导文案而非硬算
- **验收**：示范项目《吞天神脉》上能出合理对照图；章节增删后实时刷新；无 AI 配置下功能完整
- **🔴 中止判据**：可视化若与故事线 / 检查工具页既有视图**重叠造成混淆**（实测分辨不出「看哪个」）→ 砍面板，只保留「在 A2 之前先出文字版偏差结论」的最小形态；数据稀疏项目噪音大到无参考价值且门槛挡不住 → 整项放弃

### B1 · 恢复安装时自定义安装目录

- **背景（已核配置）**：`electron-builder.yml` 现状为 `oneClick: false` + `perMachine: false` + **`allowToChangeInstallationDirectory: false`**——当年锁定是**有意为之**（注释：杜绝误装 Program Files 再次引入管理员需求）。本次恢复「可改目录」，但当年担心的风险必须接住。
- **涉及模块**：`electron-builder.yml`（**仅 1 行**）＋ 发布说明
- **步骤**：① `allowToChangeInstallationDirectory: true`；`oneClick` / `perMachine` / 默认安装路径**全部不动**（默认仍是用户目录，无需管理员）；② 本批出包时合并实测三条路径：**默认路径安装 / 自定义到非系统目录（如 `D:\Apps\...`）安装 / 老版本覆盖升级**（NSIS 记住旧路径，确认无路径漂移）；③ 发布说明写明：「安装目录可选，请选择当前用户有写权限的目录；默认目录即可正常使用，装到系统目录（如 Program Files）会因权限不足安装失败」
- **明确不做**：安装向导内做目录写权限探测与自动提权（成本高、破坏「无需管理员」的既定体验）；`perMachine` 改 true（回到需要管理员的老路）
- **验收**：三条路径全部安装成功、启动正常、卸载干净；`after-pack.cjs` 的 rcedit 补偿链不受影响
- **🔴 中止判据**：出包实测若发现覆盖升级路径漂移、或卸载残留较锁定时恶化 → 回滚该行配置，维持锁定现状并在 bug 清单记录原因（该需求天然带一条退路：改动只有 1 行，零沉没成本）
- **⚠️ 流程注意**：验收依赖安装包构建，**合并到本批出包流程一次做掉**，不单独打包；正式封装仍等主人哥哥明说（红线）

### C1 · 自定义主题（三参数派生，主人哥哥 2026-09-25 拍板追加）

- **需求**：用户想要自定义主题。原始设想「给调色板，用户设定颜色参数，其他颜色配置随之调整」——方向认可，但**收窄参数面**：不让人调 14 个变量（门槛高、易出对比度灾难），改为三参数派生。
- **方案（已与主人哥哥确认）**：
  1. **母版主题**：从现有 8 套里选一套打底（人工调好的明度/饱和度结构直接继承）；
  2. **强调色**：拾色器取色 → 替换 `--amber`，`--amber-soft` 自动生成提亮版；
  3. **色相偏移**：滑杆 −180°~+180°，整个 ink 阶梯（12 档）+ 深色母版的 `--graph-*`（中性色 6 个）做色相旋转；`--graph-accent*` 3 个跟随强调色（语义一致）。
- **核心技术论据（为什么天生安全）**：WCAG 对比度只取决于**明度**——色相旋转不动明度，母版又是过闸的，故 ink 系对比度**自动守恒**，运行时唯一要守卫的是用户自选强调色（amber ≥4.5 / amber-soft ≥3.4，对 ink-900/950，阈值与 themeContrast 闸一致；不达标自动调明度）。
- **涉及模块**：新增 `src/lib/customTheme.ts`（纯函数：RGB↔HSL / 派生 / 守卫，**零 DOM 依赖**，母版变量由调用方传入）；`src/lib/theme.ts`（`ThemeId` 加 `'custom'`、THEMES 第 9 项、`applyCustomTheme`、离开 custom 时**逐个 removeProperty 清内联变量**——写与删必须同源一份清单）；`src/components/CustomThemeDialog.tsx`（新弹窗：母版下拉 + 拾色器 + 色相滑杆 + 实时预览）；`Sidebar.tsx`（主题区加「自定义…」入口，弹窗独立成文件避免 Sidebar 继续膨胀）。
- **存储原则**：🔴 **存参数不存派生值**（localStorage `yfe-custom-theme` = `{ baseId, accent, hueShift }`，启动时重算应用）——以后改进派生算法，所有用户的自定义主题自动升级。主题仍走 localStorage（本机偏好，不进云同步，与现有 8 套一致）。
- **实现要点**：读母版 = 临时 `applyTheme(baseId)` 后 `getComputedStyle` 读变量（浅色母版 `--graph-*` 是 `var()` 引用，不读——派生只改 ink 值后引用自动跟随）；`accent` 允许为空 = 用母版原 amber 一起旋转；`color-scheme` 跟随母版；浅色主题 ink 阶梯反向的语义由母版继承，派生不感知方向。
- **明确不做**：逐色值高级模式（放二期）；主题导入导出/分享（放二期）；权限探测式亮度适配；动 index.css 的 8 套内置主题（themeContrast 闸的解析器因此不受影响）。
- **验收**：8 母版 × 色相全程旋转下守卫全过（单测）；切换 custom ↔ 内置主题无变量残留（写/删同源清单 + 实机）；实时预览流畅；重启后自定义主题自动恢复。
- **🔴 中止判据**：若派生观感普遍差（大面积色相旋转后出现脏灰、饱和度失控，实机截图对比不达标）→ 降级为「仅强调色自定义」（砍色相偏移），再不行整项放弃、记录 bug 清单、revert 干净（改动集中在 3 个新文件 + theme.ts，沉没成本可控）。
- **流程注意**：随本批出包，不单独打包；封装等主人哥哥明说（红线）。

### A3 · 灵感 → 情节一键转化（2.5.1）

- **做什么**：对方「素材攒够 → 一键转情节」的我们版——灵感启发页签内多选若干灵感卡，AI 融合生成情节卡/细纲卡，产出直接落大纲或情节推演画布。
- **前置（开工第一步）**：**核灵感启发页签源码**——数据形态（卡片/表格）、能否低成本支持多选、既有结构是否会被波及。涉及模块以核实结果为准；生成链走既有 AI 红线（`aiParse.ts` 解析、`parseLooseObject` + 空结果重试、**整理产出两道本地兜底**：候选值＝库里已有 ∪ 选中灵感内容、产出按名单本地过滤＋给原文依据）
- **步骤（按核实结果择一）**：
  - 形态顺畅 → 多选模式 +「融合为情节卡」按钮 + 产出落点选择（大纲 / 推演画布）；
  - 多选改造成本高 → 降级为**单条灵感「扩写为情节卡」**；
  - 波及既有结构 → **放弃整项**，在 bug 清单记录，把该痛点留给「创意写作工作流的灵感输入」去消化
- **验收**：转化产物可在目标页签看到、来源灵感可追溯（给依据）；灵感页原有功能零回归
- **🔴 中止判据**：见上（三条路径本身就是判据阶梯）；另外若生成结果「换汤不换药」（只是把灵感原文拼接）的对比测试不达标 → 放弃，不硬上

### D1 · C5「导师提问」角色预设（2.5.1，择机）

- **做什么**：竞品的「问答式引导设定」不独立立项——C5 读者视角审问（2.4.2 已完成）已有完整的问答式框架，给它加一个「写作导师」角色预设（按编剧方法论逐题提问：主题句 / 核心冲突 / 人物弧光 / 代价），复用同一套面板与守护。
- **🔴 中止判据**：若新增预设导致 C5 既有「读者三问」的提示词互相污染或行为漂移 → 放弃，维持 C5 原样
- **量级**：小（一个预设 + 提示词 + 测试）
