## 3 · 批次 C：酒馆三处静默失败

### C-1 收尾失败被吞，界面照样报成功（`roundEnd.ts`）
`②本场数值` 与 `③设定审查` 各自 `catch { varChanges = [] }` / `catch { proposals = [] }` ——
作者看到的是「本轮已结束 —— N 位角色的记忆已更新」，实际两步都没成。

- `RoundEndResult` 新增 **`warnings: string[]`**；两处 catch 各写一条；
- `TavernFree.tsx` 的收尾 toast 带上 `⚠️` 明细（有 warning 时降为 `info` 且停留 6 秒）。

### C-2 记忆解析失败 = 整份档案被静默清空（`memory.ts`）
原先只有 `APPEND_ONLY = ['facts','mines']` 两栏有 `prev` 兜底，而模型的真实失败形态是
**四栏一起空**（长期摘要 / 关系 / 纪念日 / 日记）→ `store.saveMemory` 无条件落库 → 失忆当成功。

新增纯函数 **`isMemoryDegraded(next, prev)`**（旧档案 >200 字且新档案不足其 40%），
`parseMemoryText` 加第 5 个参数 `onDegraded`：判为退化时**整份回退旧档案**并上报。
调用链打通 `summarizeRound` / `summarizeMemory`（`SummarizeArgs.onDegraded`）→
`roundEnd` 收进 `warnings`、`TavernPlot` 直接改提示文案。

### C-3 水位线两侧口径不一致（`memory.ts`）
`nextWatermark` 用 `filter(m => m.role !== 'system')`（**含 hidden**），
`messagesAfterWatermark` 用 `filter(... && !m.hidden)` —— 末尾消息一旦被隐藏，
水位线记的 id 在消费端被过滤掉 → `i < 0` → **整场重喂**（旧剧情重复总结、数值按同一批事件反复累加）。

- `nextWatermark` 补 `!m.hidden`，与消费端对齐；
- `i < 0` 的兜底从「返回全部」改为**按水位线时间戳取它之后的**（老数据没有 `at` 时才退回全量）。

**#3 `matchSectionTitle` 收紧，防串栏**（`memory.ts`）

光「行首命中」还不够 —— `SEP` 允许「标题：内容」同行，于是正文里一句 `关系：与小满已冷淡`

### 🔍 #4 `cardFields` 半角冒号：**建议不改**（收益不显著）

先把实际影响面说窄一点（比审计报告里写的面小）：

- `unpackField` 的**唯一调用方**是 `TavernCardStructField.tsx`（卡片页的结构化小项输入框）；
- `packField` 产出**固定全角** → **软件自己写出来的数据永远是全角**（作者在卡片页填的、界面回写的都不受影响）；
- 唯一会踩到的是「**AI 起草的卡里混了半角冒号**」或「外部工具导入的卡」——
  而 `draft.ts` 的格式要求里**没有**"冒号必须全角"这一条，所以理论上模型确实可能写半角。

再看项目对"半角冒号"的既有立场：`postRules` 里有一条「半角冒号 → 全角」规则，
**出厂默认关**，注释写着「会误伤『注意：』『他说：』这类以短词加冒号开头的正常叙述（这条是唯一会删字的规则）」
—— 团队对这个符号的态度本来就是保守的。

**结论**：收益只有"模型偶发半角时的归位"，且**发生频率没有任何实测数据**；代价是把歧义引进数据层。
→ **判定不改**。若将来实弹测出模型确实爱写半角，正确的修法是**写入侧规范化**
（AI 起草产出落库前把 `:` 统一成 `：`），而不是放宽读入侧。

### 🔧 #1 巨型组件拆分：方案（**本轮只出方案，不动手**）

| 组件 | 行数 | `useState` | memo/回调 | 候选块（按"依赖少→多"排） |
|---|---|---|---|---|
| `TavernControl` | 1397 | **7** | 1 | 八段天然分块：左列（一通用 / 二我的档案 / 三预设 / 四后处理 / 五协议）→ `TavernControlShared`；右列（六剧情 / 七自由 / 八数值）→ `TavernControlModes` |

| `NovelEditor` | 1764 | 21 | 14 | 工具栏（1165-1479 ≈310 行）→ `NovelEditorToolbar`；设定检索栏（1144-1160） |
| `TavernFree` | 1935 | **25** | 28 | 左栏会话列表（1308-1420）→ `TavernFreeSessionList`；消息行 → `TavernFreeMessage` |

**为什么按这个顺序**：`TavernControl` 与 `TableSheet` 的 `useState` 最少（各 7 个）——
**state 少 = 要当 props 传的面窄 = 拆分风险最低**。`TavernFree` state 最多（25 个 state + 28 个回调），
放最后，且只先切依赖最少的左栏。

**做法**（照抄上轮拆 `TavernCard` / `NovelEditor` 的成功经验）：

1. **先量化再下刀**：取「该块用到、且在父文件里有声明」的标识符集合大小，选**小的那头**切
   （上轮实测：`TavernCard` 左栏 18 / 右栏 119；`NovelEditor` 左侧栏 39 / 编辑区 240）；
2. **只搬视图，state 留父组件当 props** —— 父组件别处还在读那些 state（拖拽落点、导出、状态栏…），
   一起搬走就会出现两份真相；
3. JSX 用**脚本从原文逐行抽取**（统一 dedent），不手抄；
4. **一次只拆一个组件**，拆完立刻四件事：① `tsc` + `eslint` + `tests`；
   ② 实机**指纹比对**（`novel-studio-ui-livecheck` 的 `ui-refactor-check.mjs`：拆前存基准、拆后逐项比对）；
   ③ **真点交互往返**（折叠/展开、切章、点卡片）；④ **负面对照**（故意改坏一处，确认断言真会红）；
5. 不好就回滚（工作区干净时 `git checkout -- <file>` 即可）。

**节奏建议**：一次拆一个、验证一个、各自独立提交 —— 别一轮拆四个（出问题时无法定位）。

## 9 · 过程记录（两条值得留下的）

### 9.1 补丁脚本：分隔符式比 JSON / 内联字符串都稳
本轮 C 批的片段里含**反引号模板串**（`` `本轮已结束 —— ${n} 位…` ``），
塞进 JSON 要转义 `"`、塞进 JS 字符串字面量要转义 `` ` `` 与 `${` —— 两条路都容易写坏。

改用「`@@@FILE` / `@@@OLD` / `@@@NEW` / `@@@EDIT` 分隔标记 + 逐行收集」的纯文本补丁文件，
