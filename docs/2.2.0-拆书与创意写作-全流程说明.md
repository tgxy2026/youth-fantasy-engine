# 一键拆书 / 创意写作 · 全流程说明（2.2.0）

> 这份文档回答一句话：**点下按钮之后，AI 模型从头到尾被安排了哪些活**。
> 每一步都写清四件事：**谁在做**（代码 / 模型 / 人）、**要求模型产出什么**、**产出怎么被读懂**、**写不写库**。
> 内容按源码核对（2026-09-18），不是设计设想 —— 凡与代码不符，以代码为准并回来改这份文档。

---

## 〇 两条流水线共用的骨架

两者都跑在 `lib/flow` 的**状态机**上（`pipeline.ts`，域中立，与业务无关）：

| 能力 | 说明 |
|---|---|
| 顺序推进 | 阶段数组的顺序就是执行顺序；每个阶段自己 `report(比例, 一行说明)` |
| 加权进度 | 阶段声明带 `weight`（按实测耗时给），否则总进度会"卡在 5% 很久然后跳到 90%" |
| 随时中止 | 走 `AbortSignal`；**已完成阶段的产物保留在 bag 里**（这是能续跑的前提） |
| 条件提前结束 | `ctx.skipRest(reason)`：本阶段照常完成，其后阶段记 `skipped` + 原因（创意写作「只保存大纲」用它） |
| 人机闸门 | **没有专门的暂停机制** —— 闸门就是 executor 里的一个 `await`（等用户点击时 resolve） |
| 可视化 | `WorkflowTimeline` 竖向节点时间线：进行中转圈 + 实时明细；**跑完保留** + 产物摘要 + 耗时 |

**写库原则（两条线一致）**：**能落库的只有两件事** —— ① 你明确勾选并确认的草稿；② 拆书的"原文结构写进正文"（可用开关关掉）。
闸门处放弃 = 整条流程中止，**不留半成品**。

# 一 · 一键拆书

**它解决什么**：拿一本**别人写好的书**，把里面的设定（人物 / 势力 / 地点 / 物品 / 术语）+ 全书级设定抽出来，落进你的项目，省掉手工录入。

## 1-1 总览

| # | 阶段 | 谁在做 | 调模型 | 典型耗时 | 写库？ |
|---|---|---|---|---|---|
| ① | 切分原文 | 纯代码 | ❌ | <1 秒 | ❌ |
| ② | 写入正文 | 纯代码（IO） | ❌ | 21 章约 2 秒 | ✅ 建卷 / 章（可关） |
| ③ | 逐块抽取 | **模型** | **N 次**（一块一次） | 云端 ~51 秒/次·本地 60~150 秒/次 | ❌ |
| ④ | 整理草稿 | 纯代码 | ❌ | <1 秒 | ❌ |
| ⑤ | 汇总全书级设定 | **模型** | **1 次** | 云端 ~30 秒·本地 1~2.5 分钟 | ❌ |
| ⑥ | 审阅 → 落库 | **人 + 代码** | ❌ | 看你勾多少 | ✅ 设定表 / 表单 |

> N = 抽取单元数。一章 ≤4000 字算 1 个单元，超长自动按段落切细（避免撞本地窗口被静默截断）。上限 120 个单元。

## 1-2 逐阶段

### ① 切分原文（纯代码，零模型）

- **怎么切**：先找章节标题（`第X章 / 第X回 / 第X节 / 卷一 / Chapter N / 【序章】`，支持中文数字）。识别得到就按章切；**识别不到**就退化成按段落 + token 分块（**1200 token/块，块间重叠 100 token**，重叠是为了不让跨块的句子被切断丢掉）。
- **不切断句子**：单段超长时不在中间硬切，**退到最近的句末标点**（回溯窗口 = 块末 40%，下限 200 字）。
- **上限**：最多 60 章 / 块；超了会截断，**界面必须提示**"本轮只处理前 N 章"（否则你会以为整本都抽了）。
- **开跑前先预览**：面板给"识别为 N 章 / 共 M 字 ≈ K 词元 / 预计 N 次模型调用"，粘错文本不用白跑一轮。

### ② 写入正文（纯代码）

- 把切分结果**真实写进「正文编辑」**：建卷（`卷一` 是卷边界，自带正文落成"卷首"章）+ 建章，并同步该卷的章节台账（「一句话事件」等）。
- 🔴 **只追加，绝不覆盖**：新卷接在已有卷之后，章号接续（不会从 1 重来）。
- 🔴 **重复导入守卫**：同名卷 + 同章数 + 同章标题集合 → 判"已导入过"，整体跳过（避免把同一本书复制成两份）。
- 导入章节状态 = **完稿**（原文本来就是写完的文本）。

### ③ 逐块抽取（模型，N 次）★ 主力

- **每次只喂一块**（≤4000 字）+ 该块所属章标题。不整本喂 —— 逐块抽不但不撞窗口，还能保住"证据原句"。
- **要求模型产出**：JSON 数组，每条一个实体：

```json
[{
  "name": "陈渊", "type": "人物",
  "aliases": ["小渊"], "desc": "一句话描述，只写正文写明的",
  "evidence": "正文原句（照抄，≤60 字）",
  "fields": { "identity": "杂役弟子", "realm": "淬体一重", "traits": "坚韧" }
}]
```

- **硬规则（写进提示词，且代码里还有一道兜底）**：
  1. **只抽本章确实出现的**，严禁虚构、推测、"合理补充" —— 这是资料整理，不是创作；
  2. 每条**必须附证据原句**，找不到原句就别抽；
  3. **只抽本作独有的专名**，明确排除四类噪音：场合设施（演武场 / 识海 / 后山）、通用物品与货币（铜钱 / 灵石 / 干粮）、泛称统称（长老 / 弟子 / 大比）、通用器物泛称（长剑 / 丹药 / 秘籍）；
  4. `type` 只能取 6 个值：人物 / 势力 / 地点 / 种族 / 物品 / 术语；
  5. **必抽别称**（`铁柱`＝`王铁柱`、`吞天诀`＝`混沌吞天诀`）—— 不并别称会让判重失效、设定表里冒出重复条目。
- **走流式**：B2 全字段抽取的输出是旧版的数倍，非流式会撞 180 秒总超时墙；流式首字节即清，面板上显示"已收到 N 字"。
- **单块失败不中断整本书** —— 跳过并继续，最后如实报告"共抽到 N 条实体"。

### ④ 整理草稿（纯代码，零模型）

- **判重**：拿抽出的名字（含别称）与项目**已有设定登记表**比对（`settingLedger`，纯字符串运算）→ 已有的标「疑似已有」，**默认不勾选**；同名的标为冲突。
- **跨章归并**：同一实体在多章出现 → 合成一条，来源章节累积（"首次出场"取最早的）。
- **同物多写法归并**（`draft.foldNameVariants`，**确定性规则、零模型调用**）：短名是长名的**后缀**且只被一个长名包含 → 自动并入（`铁柱` → `王铁柱`）；有歧义时**只标核心词**、不牵连长名；数字量词（`三品玄脉`）不并；**前缀位完全不处理**（会把 `青岚宗` 错并进 `青岚宗藏经阁`）。
  > 曾经的 C 方案（让模型二遍复核）实测精度仅 ~60%、会误伤核心专名、提示词微调即翻，**已弃用**。
- **冲突只在硬事实字段报**（类别 / 境界 / 品级 / 实力 / 危险 / 掌权者）—— 全字段报冲突会让 38% 的草稿被标红、真矛盾反而被埋；「包含＝详略」不算矛盾。**冲突不替你猜，交给你**。

### ⑤ 汇总全书级设定（模型，1 次）★

- 🔴 **放在最后、只跑一次**。为什么不跟着逐章增量写：表单型是**整项目单份**，逐章往同一个表单里累加会越写越长，还会覆盖你手改的内容。
- **吃什么**：**已抽出的实体清单**（不是重新读全文 —— 便宜两个数量级，而且专名天然与前面抽出的一致）+ **开篇原文样本**（600 字，开篇最能定调性）。
- **材料层层封顶**：每类取前 40 条 / 单条截 120 字 / 总材料 8000 字，超限**明说"已省略"**（不静默截断）。
- **要模型填什么**：**全部表单型页签**的字段，按「页签 → 模块 → 字段」三层给清单（**108 个字段**）：

  | 页签 | 字段数 |
  |---|---|
  | 作品定位 | 15 |
  | 世界设定 | 28 |
  | 力量体系 | 35 |
  | 全书总纲 | 18 |
  | 写作规范 | 12 |

  > 覆盖范围是**动态**取的（schema 里所有 form 型页签），新增 form 页签自动纳入。不想落哪张，在闸门处不勾即可。
- **硬规则**：只填材料里有依据的字段，**没把握就不写**（"一张表只填三五个字段是完全正常的"）；不许新造专名；用档案体而不是剧情简介；单字段 ≤60 字。
- **重试换策略**：本地大模型偶尔会在长输出里**截断**（JSON 少收尾括号），所以第二次重试会收紧体量并点明"上次被截断"；解析侧还有 `parseTruncatedJson` 兜底（只修剪补齐、绝不编造）。

### ⑥ 审阅 → 落库（人 + 代码）

- 抽出的一切都变成**草稿行**（条目型一条一行；全书级设定**一张表一行**）→ 同一个界面里勾选 / 改名 / 改值 / 全选新建 / 仅高可信 / 全不选。
- **落库前先预览**"将新建 N / 将更新 M / 将跳过 K"，**预览与实际落库走同一套判断**（看到的和将要发生的对得上）。
- 写入规则：

| 目标 | 命中已有同名条目时 |
|---|---|
| 卡片 / 表格（人物、地理…） | 默认 `keep-existing` —— **分毫不动**；可选"只补空字段"或"用新值覆盖"（危险，需二次确认） |
| 表单（作品定位、世界设定…） | 表单**没有"同名条目"**这回事，策略作用在**字段**上：`keep-existing` 与 `fill-empty` 都是**只填空字段**，你的手改内容一律不动 |

> ⚠️ 表单那条看起来"不够保守"，其实相反：表单字段天生"存在但可能为空"，若按条目型那样"已存在就整条不动"，**汇总将永远写不进任何东西**（而且是静默失效）。

## 1-3 中断 / 失败行为

| 情况 | 行为 |
|---|---|
| 你在抽取中点了中止 | 已抽到的实体**保留**；**正文可能已经写进去一部分**（写入在抽取之前），面板如实提示 |
| **中止后想接着抽** | 点「**继续抽取**」：断点装在**块**上，从"已抽完的那一块之后"接着抽，**已抽过的块不重跑**（60 章书抽到一半中止，接着抽只花剩下那一半的时间）。⚠️ 若你改过原文，断点会自动失效、从零重跑 —— 否则抽出的内容会与章节整体错位 |
| 单块抽取失败 | 跳过该块继续；最后报告共抽到多少条 |
| 汇总失败 / 模型没产出 | 只是少了几张表单草稿，**不影响前面抽好的条目型草稿** |
| 切分被截断 | 面板明确提示"本轮只处理前 N 章" |

# 二 · 创意写作

**它解决什么**：给一句话想法，AI 从零把一本书**开出来** —— 设定 → 大纲 → 正文，两个人工闸门卡在关键处。

## 2-1 总览

| # | 阶段 | 谁在做 | 调模型 | 实测耗时（本地 27B） | 写库？ |
|---|---|---|---|---|---|
| 0 | 想法与参数 | 人（可让 AI 对话引导） | 引导时每次 1 次 | — | ❌ |
| ① | 设定奠基 | **模型** | 1 次 | 1 分 16 秒 ~ 4 分 | ❌（等闸门①） |
| — | **闸门①** | **人** | — | — | ✅ 勾选的草稿 |
| ② | 分卷大纲 | **模型** | 1 次（失败时再 1 次） | 43 秒 ~ 1 分 26 秒 | ❌（等闸门②） |
| — | **闸门②** | **人** | — | — | ✅ 卷 / 卷大纲卡 / 章节细纲卡 |
| ③ | 逐章连写 | **模型** | **每章 5~8 次** | 每章 2~4 分钟（目标 800 字） | ✅ 正文（逐章落库） |

## 2-2 逐阶段

### ⓪ 想法与参数

- **想法**：一句话直写，或点「**对话引导**」聊出来 —— AI 按「题材与基调 → 主角 → 核心冲突 → 世界与风格」一路问（一次只问 1~3 个相关问题，按提纲推进），聊完把要点用中文标签拼回输入框，你还能逐行改。
- **参数**：卷数（1~8）/ 连写章数（1~60）/ 每章目标字数（800~8000）。
- **体量推荐**（面板实时显示）：`推荐章数 = 20 分钟 ÷ 单章最慢耗时`，保守取慢侧。
  🔴 **口径修正（09-18 核对源码后改的）**：连写**不是**"一章一次调用"，而是**一章 5~8 次**，所以面板会明确写出来 —— 否则你会以为"写 5 章＝5 次调用"，真跑起来差一个数量级。三档提示：`ok` / `large`（建议先跑几章看文风）/ `long`（建议分几轮跑）。

### ① 设定奠基（模型，1 次）

- **只依据你的想法**展开，**此时不读**项目现有设定。
- **要模型产出**：人物 / 势力 / 地点 / 名词术语 / 物品的设定草稿，**条数上限 28 条**（主要角色 2 / 次要 4 / NPC 4 / 势力 4 / 地点 5 / 术语 6 / 物品 3）。
  > 有上限是因为生成型入口不设上限时，模型偶尔会一口气给 20 个角色，你光删就删到手软。
- **硬规则**：每条都要有存在理由（能撑起冲突 / 爽点 / 悬念 / 世界规则）；**留白**，不要把故事写死。温度 0.85（创意档）、宽底解析 + 空结果重试。
- **闸门①**：全部草稿摊在界面上按表分组（带置信度），你勾选要的、可以改名字，确认后才落库。

### ② 分卷大纲（模型，1 次）

- **吃什么**：**项目设定摘要**（按当前预算裁剪，保证大纲里的人名地名与设定表对得上）。
- **要模型产出**：

```json
{
  "volumes": [{ "title": "", "positioning": "本卷一句话定位", "stage": "主角境界区间",
                "scope": "舞台范围", "opening": "卷首状态", "climax1": "第一大高潮",
                "turn": "卷中转折", "climax2": "卷末高潮", "ending": "卷末状态",
                "events": "事件链 起→承→转→合", "subplots": "支线事件" }],
  "chapters": [{ "title": "", "event": "本章一句话事件", "function": "推进主线/铺垫/爽点/情感",
                 "cast": "出场人物", "hook": "章末钩子", "scenes": ["场景1", "场景2"] }]
}
```

- **硬规则**：只输出指定卷数 / 章数（多写的会被丢弃）；**不许新造专名**（只能用设定资料里已有的名字）；每章都要有"事件 + 钩子"，**严禁过渡章 / 日常章**；事件链要有递进；`title` 不带"第X章"前缀（系统自动编号）；**体量纪律** —— 单字段 ≤40 字、整份 JSON ≤ `300 + 卷×420 + 章×160` 字（都是卡片摘要，不是正文）。
- **闸门②（三选一）**：看完大纲再决定 ——
  1. **保存大纲并开始连写**（默认）；
  2. **只保存大纲**（不写正文）→ 连写阶段记 `skipped`，界面明确显示"已跳过（已选择：只生成大纲）"，进度照常到 100%；
  3. **放弃本次创作** → 整条流程中止，不留半成品。

### ③ 逐章连写（模型）★ 每章 5~8 次调用

连写复用「AI 一键续写」那套（`autoContinue`），一章的完整内部环节：

| 序 | 环节 | 模型做什么 | 能否关 |
|---|---|---|---|
| 1 | 组装上下文 | —（代码拼 prompt） | — |
| 2 | **续写正文** | 按细纲 + 设定 + 最近章节摘要写本章 | — |
| 3 | 去 AI 味儿 | 按你给的指令改写（去套话 / 去"不是…而是…"） | 默认**关**（创意写作未启用） |
| 4 | 字数校准 | 低于下限要"补足篇幅"、超上限要"压缩"，最多 2 轮 | — |
| 5 | 作者确认初稿 | — | 创意写作**不等待**（一键续写界面才会等） |
| 6 | **AI 编辑自检** | 审读连续性 / 人设 / 伏笔，有问题就列出 findings | — |
| 7 | 改写修正 | 按 findings 改（单轮，≤2 轮约束，杜绝自检死循环） | — |
| 8 | 二次字数校准 | 改写后可能跑偏，再校准一次 | — |
| 9 | **二次闸门** | —（代码判断）字数异常则**本章不落库** | — |
| 10 | 生成标题 | 给本章起名 | — |
| 11 | 生成摘要 | 压成约 1/10 的连贯摘要（存 `summary`） | — |
| 12 | **落库** | —（代码写卷 / 章 + 同步台账） | — |
| 13 | 抽取并补登设定 | 从本章正文抽设定，补进设定表 | — |
| 14 | 滚动摘要回灌 | —（代码）把本章摘要拼进下一章的上下文 | — |

- **按大纲写**：读已落库的《章节细纲》卡的「本章一句话事件 / 功能 / 场景 / 章末钩子」，按章号钉进 prompt 末段。没有细纲就退回"自由发挥"（仍能跑通，只是不保证贴合大纲）。
- **数据来源**：每章读一次设定 + 最近章节摘要；章数**不受模型窗口限制**（单章只带设定与摘要）。
- **任何一章失败就停下**并如实报错，已写完的章保留。
- **中止后想接着写**：点「继续写作」—— 断点装在**章**上，从第 N+1 章接着写，**已落库的章不会重写**。
  ⚠️ 改了「连写章数」会让断点失效（从零跑）；在闸门处主动「放弃」则不会给续跑入口（放弃是你的终态决定，不该再劝你继续）。

# 三 · 两条线共用什么、差在哪

| | 一键拆书 | 创意写作 |
|---|---|---|
| 方向 | 已有的书 → **抽出**设定 | 一句话 → **生成**全书 |
| 状态机 / 节点时间线 / 中止 | 共用 `lib/flow` | 共用 `lib/flow` |
| 判重 / 草稿 / 勾选审阅 / 落库 | 共用 `draft` + `commit` + `DraftReviewPanel` | 同左（设定奠基那一关） |
| 表单通道 | 末尾汇总 1 次 | 不用 |
| 闸门 | 无（一次到底，中途可中止） | **两个**（设定、大纲） |
| 逐章调用 | 一块一次抽取 | 一章 5~8 次（续写 / 自检 / 校准…） |
| 写正文 | ✅ 写入原文结构（可关） | ✅ 写入 AI 生成的正文 |

**共用件的意义**：新增一条流水线时，只要走 `lib/flow` 就自动获得进度、中止、可视化；只要产出 `DraftRow` 就自动获得勾选 / 预览 / 落库界面。

# 四 · 调用次数与耗时速查

| 场景 | 模型调用次数 | 云端（实测口径） | 本地 27B（实测口径） |
|---|---|---|---|
| 拆书 · 6 章书 | 6 次抽取 + 1 次汇总 = 7 | 约 5~6 分钟 | 约 12~17 分钟 |
| 拆书 · 60 章书 | 60 + 1 = 61 | 约 50~60 分钟 | 2 小时以上 |
| 创意写作 · 只出大纲 | 2 次 | 约 1 分钟 | 2~5 分钟 |
| 创意写作 · 写 1 章（800 字） | 5~8 次 | — | 2~4 分钟 |
| 创意写作 · 写 10 章（2500 字/章） | 50~80 次 | — | 按每章 5~9 分钟估 |

> 数字都是**粗估**（本地受模型大小 / 量化 / 显存影响极大）。面板上的推荐值按当前选中的模型算，别照抄上表。

# 五 · 已知缺口（如实列出）

1. **拆书的关系表**：`人物关系` / `势力关系` 两张表还没有写入通道（抽得出人，但抽不出"A 是 B 的师父"）。
2. **语义级跨块同指**：字符串看不出的同指（`玄真子`＝`国师`）识别不了 —— 只有确定性字符串规则（后缀归并）。
3. **字段错位与"提及≠出场"**：模型偶尔把场景描写当"外貌"填；「首次出场」可能取的是"被提及"而非"真正出场"。提示词已在收紧，未彻底解决。
4. **form 汇总不覆盖手改**：这是刻意的（只补空），但若你想让 AI 改写你已填的字段，目前只能手工改或删掉原值再跑。
5. **续跑的断点在内存里**：刷新页面 / 关掉软件后断点就没了（不落盘）。同一次会话里可以反复"中止 → 继续"。
