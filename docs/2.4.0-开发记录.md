### 四、关键实现

**1. 首启判定为什么用全局 meta 而不是 localStorage**

`db.setMeta('welcomeDone', '1')` 写在**全局 meta** 区（与 `lastProject`、`ai.promptOverrides` 同一区），
随数据文件走 —— 换设备、导入备份都认。判定条件是**两个条件的与**：

```
未走过向导(meta.welcomeDone 未写) 且 库里一个项目都没有(projects 为空)
```

两个都要，缺一个都会误弹：只有前者 → 删光项目会反复弹；只有后者 → 用户主动清空书库后又弹。

🔴 **写盘被锁时不弹**（`DESKTOP && getDesktopState().writeLocked`）：此刻内存是空库，
"库里没有项目"是**假象**，弹向导只会误导用户去建第二本书、还可能覆盖原文件。
（这条沿用了原先"写盘被锁不播种"的守卫。）

**2. AI 配置步骤为什么「测试并启用」只有一个按钮**

别处是「测试 → 保存 → 设为当前」三步，向导里合成一步：测试真发一次最小对话，
**通过了才**保存为当前模型、并按该模型把写作额度调成推荐值；**测不通不落库**。
首启场景下"测通了"基本等于"我要用它"，少一次点击。

额度回显取自 `currentModelAdvice()` 的真实推荐值，并且**确实写进了设置** ——
显示值与实际生效值同一个来源，不会出现"面板说 2 万、实际还是 8 千"。
同时按既有路径调 `syncTuningWithModel()`（酒馆上下文预算 / 记忆档跟随模型，按模型指纹判定，同模型不动用户手调值）。

**3. 向导里「不配也能写」这件事被反复说**

首启向导第一步的 AI 屏与「模型设置」页的说明卡，都明确写了：
配模型只影响 AI 按钮是否可点，**正文、设定、大纲、角色卡全部照常手动写**。
这与项目第一原则（AI 只做辅助，见 `lib/aiScope.ts` 顶部）一致，也保证「5 分钟出第一段」不被配模型堵住。

**4. 无 AI 清单为什么新起一份常量，而不复用 `aiCapabilityOf`**

`aiCapabilityOf(tab)` 只回答「某个**页签**接哪种 AI 写入」（fill / organize / none）；
而编辑器伴写、颉文姬、AI 助手、拆书、创意写作、看板诊断这些入口**不在页签体系里**，
它们挂在功能模块上。两套问题，各记各的。

## A5 · 编辑器排版与手感（自由缩进）（2026-09-21 · 已完成）

### 一、目标

编辑器此前**完全没有缩进编辑能力**：Enter 不继承缩进、Tab 被伴写占用、粘贴不归一；
唯一的排版能力是工具栏「一键排版」，而它会**把每行强制压成段首两个全角空格** ——
作者手写的多级缩进（对白、补充说明）跑一次就没了。本项就是解决这件事。

### 二、决策：键位彻底解耦（老大 2026-09-21 当场拍板）

| 键 | 改前 | 改后 |
|---|---|---|
| `Tab` | 采纳伴写建议（有建议时） | **缩进一级**（无条件） |
| `Shift+Tab` | — | **反缩进一级** |
| `Ctrl+Enter` | 换一句 | **采纳伴写建议** |
| `Alt+/` | — | **换一句** |
| `→`（光标在末尾时） | 采纳 | 采纳（不变） |
| `Alt+\` | 手动触发一句 | 不变 |
| `Esc` | 丢弃建议 | 不变 |

**为什么推翻规划里原定的「Tab 双态」方案**：原方案是「有建议时 Tab＝采纳、无建议时 Tab＝缩进」，
一键两义 —— 作者按下 Tab 之前无法预判会发生什么（建议落进正文？还是缩进？）。
老大提出「给伴写采纳换个键」，正好把这件事彻底切开。

⚠️ **推广帖没有跟着改**（这一点是刻意的）：第 1 篇的版本口径是 **2.3.1**、描述的也是 2.3.1 的键位，
而键位变更属 2.4.0 —— 现在改会让"帖子描述的功能"与"读者实际装到的版本"对不上。
已记入规划文档：等 2.4.0 出包时随版本号一起写。

### 四、关键实现

**1. 程序化插入一律走 `document.execCommand('insertText')`**
本项最容易踩坏的地方在这里：若直接 `setState` / 改 `value`，浏览器**不把程序化赋值记进撤销栈**，
作者按 Ctrl+Z 回不来（还常会跳掉好几步）。改成"先 `setSelectionRange` 铺好选区 → execCommand 插入"，
算一次真实编辑；受控组件再手动把 `ta.value` 同步回 state（否则 React 下次渲染会把 DOM 改回旧值）。
> 实机第 ⑲ 条就是这条契约的证据：排版后按一次 Ctrl+Z，全文**精确回到排版前**。

**2. 伴写与缩进的分层：靠 `defaultPrevented` 分流**
`handleEditorKeyDown` 先调伴写的 `onEditorKeyDown(e)`（它处理时会 `preventDefault()`），
缩进只有当 `e.defaultPrevented === false` 时才接手。两层互不知道对方存在 ——
以后新增任何按键处理都能按同一模式插进去。

**3. 回车继承的两条规则**
当前行**有正文** → 新行继承它的缩进；当前行**是空行或只有缩进** → 回段首层。
第二条是防「连按回车越缩越右」：只写第一条的话，在缩进段落后敲几个回车会一路缩下去。

**4. 一键排版不再是"抹平机"**
默认 `preserve`：只做去行尾空白、折叠连续空行、去首尾空行，**逐行原缩进保留**。
旧的"全篇统一段首一格"作为 `uniform` 保留在同一个弹窗里，并写清代价。
弹窗还会显示「本章共 N 段、其中 M 段带缩进」，让作者知道选 `uniform` 会动多少行。

**5. 导出侧的三处 `trim()` 是隐形杀手**
统一成 `splitParagraphs` 后的口径是「只清行尾、保留行首缩进」。
EPUB 另加 `indentToNbsp`：HTML 会把连续半角空格折叠成一个，行首缩进必须靠 `&nbsp;` 才立得住
（全角空格不折叠，原样即可）。Markdown 默认单位是全角，**不会**被渲染成代码块；
只有把单位切成「半角空格 ×4」时才有此风险，已在 `bookToMarkdown` 注释里写明。

### 六、与其他约定的关系

| 约定 | 说明 |
|---|---|
| 「缩进是作者的排版主权」 | 本项只做**作者手动触发**的动作；AI 伴写 / 改写 / 续写 / 拆书一律不碰缩进（`promptGuard.authorBlock()` 不动正文那条口径不变） |
| 历史章冻结 | 🔴 手动排版**不受**「改写档冻结」限制 —— 冻结只管 AI 改写 |
| 字数口径（#004） | `countWords` 不数缩进空格，本次未改动；「汉字＋标点」是否含全角空格仍待确认（已记在规划风险表） |
| 缩进单位存哪 | `uiPrefs` 的 `yfe-ui:` 命名空间 —— 本机偏好，不进项目数据、不随导出 / 云同步走 |

### 七、遗留

1. **平台口径未定**：网文平台「汉字＋标点」是否含全角空格缩进，尚无实测结论 —— 影响「平台粘贴版」的字数对齐。
2. **Markdown + 半角 ×4 单位的组合**：行首 4 个半角空格会被 Markdown 渲染成代码块。
   当前策略是如实导出 + 注释说明，未做自动转换；若该单位确实常用，可再议。
3. **粘贴归一目前没有开关**（规划里写的是"默认开的可选开关"）：先只做默认开 ——
   多一个开关就多一处要维护的偏好；等真有作者反馈"不想被归一"再加。
4. **段首缩进标记显示**（规划里的可选第 ⑥ 项）未做 —— 属锦上添花，优先级最低。
