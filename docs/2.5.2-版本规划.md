## 二、本批开发项

### A1 · 字数口径扩展（Bug 清单 #004 尾巴）

- **需求**：用户反馈网文平台按「汉字＋标点」计字数。2.4.x 已在**数据看板**做了口径切换（`countWords(text, mode)`：`cjk` / `cjk-punct`，偏好存 `lib/wordCountMode.ts`）；其余展示位仍走老口径。
- **本项**：让**编辑器底部状态位**（当前章字数）跟随同一显示偏好；其他展示位（全文检索结果、导出统计等）逐个评估——**能跟的跟，跟不了（口径绑落库值的）保持并注明**。
- 🔴 **两条既有红线不变**：①**不改落库**——章节 `wordCount` 始终是 `cjk` 老口径，含标点模式只在显示层实时重算（`useMemo`），开关随时可逆；②**逻辑层一律默认口径**（`enforceWordRange` ±300、AI 输出阈值、拆书字数等刻意不动），硬约束不随显示偏好漂移。
- **涉及模块**：`src/lib/wordCountMode.ts`（偏好源）、编辑器底部状态组件、（评估后）其他展示位。
- **量级**：小。**中止判据**：若排查发现展示位与落库值深度耦合、逐个改造成本失控 → 只做编辑器底部一处，其余在 bug 清单记录原因。

### A2 · 灵感夹 → 创意写作联动（A3 链路延伸）

- **需求**：2.5.1 建了灵感夹、能融合成情节卡落画布；但「写的时候用得上」还缺一环——**写章前把灵感直接注入本章提示词**。
- **方案**：
  1. **入口**：创意写作面板加「从灵感夹选取」——弹出灵感夹条目列表（复用 `inspirationBox` 存储，**只读**），勾选若干条 → 以「作者灵感」段拼进本章提示词；
  2. 🔴 **提示词口径**：灵感是作者手记，注入段须标注「**作者灵感，供参考、不要求全部体现**」——防止 AI 机械硬凑（与 A3「融合≠拼接」同源的风险）；
  3. 🔴 **只读复用**：创意写作侧**不新增**任何对灵感夹的写入口（增删改仍只在灵感启发页），避免两处管理同一数据；
  4. 选中即用、**不落大纲不落卡**（区别于 2.5.1 A3 的「融合成卡」——那是推演链路，这是写作输入链路）。
- **涉及模块**：`src/lib/inspirationBox.ts`（loadBox 复用）、创意写作面板组件、对应提示词拼接点（走既有 `PROMPT_ORDER` 提示词体系）。
- **量级**：小~中。**中止判据**：实测注入后 AI 输出明显被灵感带偏（跑题 / 硬塞灵感原文）→ 降级为「仅注入**细纲生成**提示词、不进正文提示词」；再不行放弃本项。

### A3 · 审计候选判定（5 个「只为测试而活」符号）

- **来源**：2.5.1 扫描器根治后，audit-dead C 段浮出 5 个真候选（外部只被 tests 引、同文件零使用）。
- **动作**：逐个查真实用途 → **有产品价值则接入口，无则删**：
  | 符号 | 文件 | 初判 |
  |---|---|---|
  | `cnToNum` | bookbreak/split.ts | 中文数字转数值——拆书章号解析的内部件？若确无调用则删 |
  | `backupsTotalBytes` | db/backups.ts | 备份总字节——数据看板「备份占用」曾想接没接？ |
  | `volumeForChapter` | outlineCard.ts | 章号→卷映射——「前往本章细纲」类功能可能用得上 |
  | `PACE_BEAT_KINDS` | paceAnalysis.ts | 节拍种类枚举——UI 展示节奏报告时可能用得上 |
  | `hookZoneSnippet` | paceAnalysis.ts | 钩子区间摘录——报告展示用？ |
- **量级**：极小（半小时级），**本批最先做**。
