# 酒馆「故事 / 世界书 / 剧本」一键导入 · 规划落地方案

> 2026-10-06 ｜ 范围：**酒馆模式 · 自由对话**（`TavernStory` + `WorldEntry` + `TavernScript`）
> 触发：作者在另一个窗口写好了《约会大作战》的故事剧本，只能一条条手抄进界面 —— 太痛苦。

---

## 一、问题（把痛感定量）

现在要把「另一个窗口写好的内容」搬进来，得逐项手敲：

| 要搬的东西 | 现在的做法 | 份数（以约战为例） |
|---|---|---|
| 故事名 + 世界设定 | 手打两栏 | 1 份 |
| 世界书词条 | 点「加词条」→ 逐条填 标题 / 正文 / 触发词 / 概率 | **十几条** |
| 剧本 | 点「新建剧本」→ 逐份填六栏 | **多份（每条角色线一份）** |

⇒ 一次搬运动辄**上百个输入框**。而且内容都在作者手里（或另一个 AI 的输出里）躺着，只是没有通道。

---

## 二、现状侦察（逐行核过，不采信印象）

### 已经有的（可直接复用，这是好消息）

| 能力 | 位置 | 说明 |
|---|---|---|
| **AI 起草范式** | `draftStory` / `draftScript` | 已经走通「给素材 → 模型吐 → 解析 → 不落库先给作者看」这条链 |
| **字段摊平** | `flattenStoryFields` / `flattenScriptFields` | 把当前内容拍成文本喂给模型 |
| **草稿合并** | `mergeStoryDraft` / `mergeScriptDraft` | **模型空着的栏不覆盖作者已写的** —— 这条纪律导入时同样适用 |
| **导入弹窗范式** | `TavernCardNovelImportDialog.tsx`（130 行） | 「从小说角色导入角色卡」已存在，形态可直接照搬 |
| **解析器范式** | `parseScriptDraft` / `parseWorldDraft` / `parseStoryDraft` | 都是 `parsePlainObject`（**JSON 导向**）+ `asText` 收口 |
| **词条结构** | `WorldEntry`（`worldBook.ts`） | `title / body / keys / prob / order / recursive` 已有，四色灯也在 |

### 缺的（正是痛点）

1. 🔴 **故事**：`StoryDraftFields = Pick<TavernStory, 'name' \| 'setting'>` —— **不带 `entries`**。
   ⇒ 就算走 AI 起草，**词条也永远进不来**，只能手加。
2. 🔴 **剧本**：没有「整份导入」，只有 `draftScript`（那是**补完**现有内容，不是灌入）。
3. 🔴 **没有批量**：一份剧本一次操作；约战一条线一份，得点很多次。
4. 🔴 **没有模板**：作者不知道「让 AI 按什么格式写」才能最省事 —— 于是只能让 AI 自由发挥，回来更难搬。
5. ⚪ **没有导出**：现有 `TavernExportDialog` 只导出**对话记录**（plot/free 会话），
   故事与剧本**定义本身**既导不出也进不来 ⇒ 换项目 / 备份 / 给 AI 当上下文全都没路。
6. ⚪ **界面无入口**：故事剧本页的按钮只有「新建故事 / AI 起草 / 保存 / 删除」。

---

## 三、方案总览

一句话：**定义一个「人写得顺手、AI 也照得出」的纯文本格式，配上解析器与导入弹窗，实现「粘一次 → 全部进库」**。

```
作者在任意窗口写好文本（或让 AI 按模板写）
        ↓  粘贴
   【解析】规则解析（首选）→ 不行再问 AI（兜底）
        ↓
   【预览】树状展示解析结果，可勾选要导入哪些
        ↓  确认
   【落库】新建 / 合并到现有故事（显式选择）
```

三条纪律（沿用项目既有判据）：

1. **不落库先给作者看** —— 与 `draftStory` 同一条：**绝不写半截结果进去**。
2. **解析不出来的不猜** —— 与 `parseScriptDraft` 同一条：形状不对就报「哪一条没读懂」，而不是硬塞。
3. **空的不覆盖** —— 与 `mergeXxxDraft` 同一条：导入只补，不抹掉已有内容（除非作者明确选「覆盖」）。

---

## 四、导入格式（本方案的核心）

### 4.1 为什么用 `〖〗`

`〖〗` 是项目既有的**输入侧结构标记**（见 `prompt.ts` 的「标记分域」纪律）：
- 它**不是**模型输出格式（输出只有 `（ ）` 与 `〔 〕`）⇒ 不会被误当成正文格式学习；
- 全角、显眼、**手写友好**（不用 JSON 转义、不用管缩进）；
- AI 也天然认识这种「中文书名号式」分节，模板贴过去它就能照着写。

### 4.2 格式定义

| 标记 | 含义 | 必填 |
|---|---|---|
| `〖故事〗` | 故事名（≤20 字） | 否（不写＝沿用当前/新建未命名） |
| `〖世界设定〗` | 整段世界设定（`story.setting`） | 否 |
| `〖词条〗名称` | 一个世界书词条的**开始** | 否（可 0~N 条） |
| `触发：` | 该词条的触发词，`、`/`,` 分隔 | 否（留空＝常驻） |
| `概率：` | 0–1 | 否（默认 1） |
| `顺序：` | 排序权重 | 否 |
| `休眠` | 该词条不参与 | 否 |
| `〖剧本〗名称` | 一份剧本的**开始** | 否（可 0~N 份） |
| `情境：` `开场白：` `你的位置：` `这一场的目标：` `不要发生：` | 剧本六栏中的五栏 | 否 |

### 4.3 完整模板（**可直接复制给任何 AI**）

```
〖故事〗约会大作战

〖世界设定〗
（整段世界设定：时代、地点、规则、势力、常识。一句一行，不抒情。）

〖词条〗精灵
触发：精灵、灵力、天使
正文：（这个设定的内容）

〖词条〗AST
触发：AST、来禅高中、装备
正文：（……）

〖剧本〗第一次相遇
情境：（此刻在哪、为什么在这儿、刚发生了什么）
开场白：（Ta 说的第一句话，按扮演协议写）
你的位置：（你在这一场里是谁、与 Ta 什么关系）
这一场的目标：（给方向，不锁死）
不要发生：（这一场不该出现什么）
```

### 4.4 解析规则（纯函数，零成本）

- 按行扫描，遇到 `〖词条〗` / `〖剧本〗` 就**开一个新块**，其后的 `键：值` 行归它；
- `〖世界设定〗` 之后到下一个 `〖…〗` 之前，整段归世界设定；
- 未知标记 → **原样留在上一块正文里**（不丢字），并在预览里标黄提示；
- 正文里若真出现 `〖`（概率极低）⇒ 该行以 `\〖` 转义，解析时还原。

---

## 五、解析策略：规则优先，AI 兜底

| 档 | 什么时候用 | 成本 | 可预期性 |
|---|---|---|---|
| **规则解析** | 文本带 `〖…〗` 标记 | **零**（纯函数、即时） | 高（同一输入永远同一结果，可单测） |
| **AI 结构化** | 文本是散文/表格/别的格式（没标记） | 一次模型调用 | 中（模型可能改字） |

🔴 **判据：先规则、规则认不出来再问 AI，且 AI 那条必须由作者点按钮才发起**（不静默烧额度）。

AI 兜底可**复用现有链路**：`draftStory` / `draftScript` 已经会「把素材整理成字段」，
只需扩一个「**解析**模式」（`existing` 传原文、要求原样结构化，而不是补完）。

---

## 六、落库与冲突处理

| 情形 | 默认行为 | 可选 |
|---|---|---|
| 故事名与现有重名 | **新建一个**（名字加后缀） | 明确选「**覆盖现有**」才覆盖 |
| 词条 | **追加**到目标故事 | 选「替换全部词条」 |
| 剧本 | 批量新建，**挂在指定故事下** | —— |
| 字段超上限 | 截断**并明确告知**（哪一栏、截了多少） | —— |

🔴 三条必须遵守：

1. **词条与剧本归属要显式选**（导入面板上有个「挂到哪个故事」的下拉，默认当前编辑中的）；
2. **超上限不静默**：`STORY_NAME_MAX=20`、`SCRIPT_FIELD_MAX`（情境 600 / 开场白 400 / 你的位置 300 / 目标 200 / 不要发生 200）——
   超了在预览里标出来，由作者决定改还是让系统截；
3. **词条受动态额度约束**：导入十几条后可能超 `dynamicQuotaOf(窗口)` ⇒ 预览里**顺带显示「注入情况」预估**（现有面板已有这个能力）。

## 七、界面

**入口**：故事剧本页（`TavernScript.tsx`）页头，在「保存」旁边加一个 **「导入 / 导出」**（`size="md"`，与同排一致）。

**弹窗**（照 `TavernCardNovelImportDialog` 的形态，新组件 `TavernScriptImportDialog.tsx`）：

```
┌ 导入故事 / 剧本 ─────────────────────────┐
│ ⓘ 把写好的文本粘进来。支持〖故事〗〖词条〗〖剧本〗标记； │
│   只认这套标记 —— 界面里有「复制模板」。              │
│                                          │
│  [   粘贴框（多行）                      ]  │
│  [                                       ]  │
│                                          │
│  挂到故事：[ 约会大作战 ▾ ]   □ 覆盖同名  │
│                                          │
│  ── 解析预览 ──                            │
│  ✔ 故事：约会大作战                        │
│  ✔ 世界设定  1,240 字（额度内）             │
│  ✔ 词条 12 条（精灵 / AST / …）  ⚠ 3 条超宽 │
│  ✔ 剧本 4 份（第一次相遇 / …）              │
│                                          │
│                    [取消]  [导入这 17 项]│
└──────────────────────────────────────────┘
```

**导出**（配套，实现往返）：同格式导出当前故事 + 全部词条 + 全部剧本 ⇒ 一个 `.md`/`.txt`。
用途：① 换项目搬；② 备份；③ **直接贴给 AI 当上下文**（比现在的「手工描述」准确得多）。

## 九、红线与风险

| 风险 | 处置 |
|---|---|
| 解析错、把脏数据写进库 | **预览 + 确认**两道；解析失败**报哪一条**，不猜 |
| 覆盖掉作者已有的内容 | 默认新建/追加；「覆盖」必须显式勾选，且弹二次确认 |
| 静默截断超长字段 | 预览里逐项标出「超了多少」，由作者决定 |
| 词条导入太多撑爆注入额度 | 预览顺带显示注入预估（复用现有「注入情况」能力） |
| 标记与正文冲突 | `\〖` 转义；未知标记不丢字，原样保留并标黄 |
| 编码 / 换行 | 解析前统一归一化（`\r\n` → `\n`），并剥 BOM |
| 只认标记、认不了自由文本 | 界面**提供「复制模板」**；解析不通过时报清「缺哪个标记、在第几行」 |

## 十、拍板结论（主人 2026-10-06 19:29 定）

| # | 问题 | 拍板 |
|---|---|---|
| 1 | 是否把角色卡也纳入批量导入 | ❌ **不纳入**。角色卡本来就有一键导入，且两者分属**不同页签**，各自分别导入即可 |
| 2 | AI 兜底做不做 | ❌ **不做**。「**给规定的导入模板，要求用户按模板形式导入**」—— 只走规则解析 |
| 3 | 导出要不要一起做 | ✅ **一起做，且格式统一**（导入/导出同一套标记，实现往返） |
| 4 | 多个故事怎么办 | 🔴 **一次导入恒为一个故事**；**多个故事要求用户分别导入**（文本里出现第二个 `〖故事〗` ⇒ 直接报错，不猜） |
| 5 | 导入前预览整份 system | ❌ **不要** |
