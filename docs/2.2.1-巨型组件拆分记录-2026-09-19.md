## 二、方法：先量化，再下刀，刀口由数字决定

### 1. 量化「props 成本」

写了 `.workbuddy/tmp/dep-cost.mjs`：给一个 JSX 区块，算出它用到**多少个组件作用域里声明的名字**
（state / setter / useMemo / 局部函数）＋导入名。数字小 = 抽出去 props 面窄 = 风险低。

第一版工具有两个盲区，害我算错过两次，记在这儿免得重犯：

- **只认 `const {…}` 不认 `const […]`** → 把 `useState` 全部漏掉（一个 91 个状态名的组件被算成 49 个）。
- **只解析 `import { … }`，漏了默认导入** → 组件名（`HistoryTimeline` 等）不在集合里。

### 2. 两条路，按「state 密度」选

| 情况 | 做法 | 例子 |
|---|---|---|
| 组件里**状态名多、视图与逻辑缠绕**（91 / 143 个状态名） | 先把**状态与生命周期**整体搬进 `useXxxModel()`，视图侧**同名解构**接回来 | `TableSheet` / `NovelEditor` / `TavernFree` |
| 视图里有**依赖窄的一整块**（≤13 个依赖） | 把这块 JSX 切成子组件，子组件只收 `model` + 少量 props | `TavernControlModes` / `TableRelationGroups` / `TavernFreeSessionList` |

**同名解构是关键手法**：`const { rows, drafts, saveAll, … } = model` 写在组件开头，
于是**JSX 一个字都不用改**（不需要 `model.xxx` 前缀）—— 把「搬家」和「改造」彻底分开，
出问题时能确定是搬家搬错了，而不是顺手改坏了。子组件同理：内部解构 `model`，JSX 逐行原样搬。

### 3. 拆前拆后**实机指纹比对**（这是能证明「没变」的唯一办法）

1. 拆之前先跑一遍实机脚本 → 存基准指纹（`--label=xx-before`）
2. 拆完再跑 → `--expect=xx-before` 逐项比对；差一项就报出来

比对项都是**结构计数与实测值**：section 数、左右列直接子节点数、数字框/下拉/文本域数、
表格总宽、行号列、叠层数与各层 `padding/字号/行高`、状态栏文案……不是"看起来差不多"。

### 4. 负面对照（证明断言真的有牙齿）

不注入故障就不知道断言是否只是"恰好通过"。本轮对照抓到两次**断言太弱**：

| 注入的故障 | 结果 |
|---|---|
| 右列子组件多包一层 `<div>` | ✅ 3 项 FAIL（右列子节点 3→1、标签 `SECTION×3`→`DIV`）+ 7 项指纹差异 |
| 行号 `index + 1` 改成 `index` | ✅ 3 项差异（`geoFirstNo` 1→0、`geoLastNo` 21→20、`geoLen` −1） |
| 高亮 HTML 置空 | ❌ **第一版没抓到**（只数叠层数）→ 改成「叠层内容总长」后 ✅ FAIL |

最后一条最值钱：原断言只验「层数 2→3→2」，而高亮层即使内容为空也会渲染 → **假通过**。
改成比对 `innerHTML` 总长（4924 → 12938 → 4924）才真正压住红线。

## 三、踩过的坑（都已修，写下来免得下次再踩）

1. **prune 工具**（按 tsc 的 TS6133/6196/6192 自动删未使用导入）三个 bug：
   - TS6192 只报声明**起始行**，import 跨多行时只删首行 → 留下 `} from 'lucide-react'` 语法错误。
     → 必须**整条声明**删（从起始行删到含 `from '…'` 的那一行）。
   - `import * as db from '…'` 被掏空成 `import * as from '…'` → 补 DROP 规则。
   - `import { type A, type B }` 只删名字会留下孤立的 `type` → 正则要连 `type ` 前缀一起吃掉。
2. **hook 文件里有 JSX 就得是 `.tsx`**：`TavernFree` 的逻辑段含 `renderSessionRow`（返回 JSX），
   写成 `.ts` 直接爆语法错误。
3. **锚点会随前一步骤漂移**：第一步拆分改完行号全变，第二次切片必须用**新文件的行号**
   （共享件那一刀就是因为沿用旧行号，切出一堆错位代码）。
4. **页签名/分组名要先核对**：`TavernControl` 不在 `schema.ts` 的 TABS 里，
   是 `App.tsx` 的 `lazy` 挂载（页签名在 schema 里叫「控制面板」）。
5. **实机脚本三个高频坑**：
   - 页签按钮要用**导航区限定 + `.first()`**：全页 `getByRole('button', {name, exact})`
     在「写作面板」这类页上会命中多处 → strict mode 抛错 → 被 `.catch` 吞掉 →
     表现成「切了页签但内容还是旧的」。
   - `main textarea` 的第一个**不一定是正文**（左栏检索框先出现）→ 用 `textarea.novel-textarea`。
   - 折叠键要用 **title 精确匹配**：`title*="子条目"` 会点到「新增子条目」（点一下多一行）。
6. **dev 数据不够就自己播种**：Vite dev 能按源码路径 import TS 模块，所以可以在页面里
   直接调应用自己的 store API —— `await import('/src/lib/tavern/store.ts?'+Date.now())`
   → `createFreeSession(...)`（`messages: []`，**不调模型**），再 reload。
   `TavernFree` 的实机验证就靠这一招收到的种子数据。
7. **指纹里别放会随测试状态变的东西**：左栏整段文本包含会话顺序（按 `lastActiveAt` 排），
   上一轮点一下就会换序 → 假差异。要覆盖就用**与顺序无关的计数**。
