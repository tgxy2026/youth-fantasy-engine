# 3.0 · 作品题材「要不要告诉 AI」——默认关闭 + 项目级开关 + 全量披露

日期：2026-10-11 ｜ 触发：社区反馈（「新建项目时选的作品题材，会影响到项目内 AI 生成的内容」）

## 一、核查结论（先实测，后动手）

**会进**，而且是**无条件进**。

| 项 | 结论 |
|---|---|
| 唯一注入点 | `src/lib/ai/aiContext.ts` 的 `buildProjectContext()` 头部「作品概览」块：`类型：${normalizeGenrePack(proj.genre)}` |
| 是否可关 | **不能** —— 无任何开关；连 `skeletonOnly`（酒馆「只用背景设定」档）也保留 |
| 覆盖范围 | 所有走 `buildProjectContext` 的功能（≈20+）：伴写（`buildInlineBriefing` 也走它）、颉文姬全部模式、校对逻辑层、连续性校验、伏笔审查、AI 整理 / 表格导入、创意写作（经 `autoContinue`）、大纲生成、取名、灵感融合、健康诊断、情节推演画布、酒馆剧情推演… |
| 题材为空时 | 整行不输出（原行为即如此） |
| 性质 | 只是一行**元数据**，**没有**「请按此题材风格写作」这类指令 —— 模型受影响是它自己按题材常识发挥 |

**为什么会这样（历史口径）**：`schemaTemplates/packs.ts` 顶部注释写明「`Project.genre` 会经 `aiContext` 直接注入成『类型：东方修真』」—— 2.7.1 定「值即包名」时就是有意为之，图的是"值天然可读、不用额外映射"。但它与「题材只管开书定位组各页签的字段名 / 示例」的**定位不符**，且从未在界面上披露 ⇒ 作者观感就是"莫名被题材影响"。

### 另两条与题材有关的路径（都不是本次要改的）
1. **《作品信息》页的「类型赛道」字段**（作者自由填，如「东方玄幻·升级流」）—— 随设定资料照常发出。这是**作者可控**的一路，也是本次推荐的替代做法。
2. `buildWorldContext`（AI 补全 / AI 新增）只读「作品信息 / 世界设定 / 力量体系」三张表的字段，**不读** `Project.genre`。
3. 题材包决定各页签的字段名 / 说明 / 默认显隐 ⇒ AI 看到的设定骨架本就不同（设计内，不动）。

## 二、处置（主人拍板：四项综合落实）

| 项 | 内容 |
|---|---|
| **B** | **默认不再注入** —— 题材回归「只管字段名与示例」的原始定位 |
| **C** | 加**项目级开关**「把作品题材告诉 AI」（默认关）；开则恢复注入「类型：XX」 |
| **D** | 引导到**《作品信息》→ 类型赛道** 字段（作者自己写的描述更具体，且一直会发给 AI） |
| **A** | **全量披露** —— 各 AI 功能问号气泡里统一说明「作品概览里有什么、题材默认不在其中」 |

### 为什么是项目级而非全局
题材本身是项目属性（每本书一个），"要不要告诉 AI" 自然也是每本书各自的决定。
走 `db.getSetting/setSetting`（`settingsKV`，键带 `<pid>::` 前缀）⇒ 随项目导出 / 云同步搬运。

### 🔴 新增 `db.getSettingFor/setSettingFor`（按 pid 读写）
项目管理页「编辑项目」改的往往**不是当前打开的书**，而 `getSetting/setSetting` 内部拼的是
`currentProjectId` ⇒ 直接用会把开关写/读到**另一本书**上（表现为"改了 A、B 的行为变了"）。
故在 `db/meta.ts` 补一对带 `pid` 的版本，并在 `aiGenreHint` 里成对提供
`getGenreToAIFor/setGenreToAIFor`。

实机验的 20 项：编辑卡片出现开关且默认未勾 → 保存后 `settingsKV` 落
`<pid>::genreToAI = true`（**带项目前缀、不写全局 meta**）→ 重开编辑卡勾选态持久 →
在**浏览器里真跑 `buildProjectContext`** 断言开/关两种口径下「作品概览」段含 / 不含「类型：」
→ 披露文案与 `hasOverview` 判据抽查。

### 🔴 实机抓到的两个"脚本自己坑"（值得记）
1. **项目管理页的内容不在 `<main>` 里** —— 用 `document.querySelector('main').innerText` 读，
   恒为空串 ⇒ 三条断言假红。该项目管理页（ProjectHub）有自己的容器，判据要用 `document.body`。
2. **「不含 X」的判定必须限定容器** —— 首轮用整篇文本判 `!includes('类型：')`，
   而设定资料段里本来就有以「类型」开头的字段（`类型：修真体系` 之类）⇒ **反向断言恒 FAIL**。
   改成只截「〖作品概览〗…下一个〖」这一段就有了判别力（与 `tests/genreHint.test.ts` 同口径）。
3. 顺带一条：编辑卡片里的「取消」按钮会命中 `dismissOverlays` 的按钮匹配表 ——
   **刚展开编辑态时不能调它**，否则自己把卡片收掉。

## 五、提交后自查抓到的一处竞态（已修 + 负面对照）

「编辑项目」里读开关是**异步**的，首版守卫写成 `f.name === p.name ? … : f`（按书名认卡片）。
作者点开编辑**顺手改掉书名**时，回调被守卫拦下 ⇒ 开关停在"未勾选"，而库里其实是开的
（最坏观感：设置被吞了）。

修法：改用 ref 记「正在编辑的项目 id」（`editPidRef`），切卡片 / 保存 / 取消三处同步，
回调按 pid 认，与书名无关。

验证（真 Chromium，临时脚本跑完已删）：

| 步骤 | 结果 |
|---|---|
| 修复后 | **6 / 6**（勾选保存 → 重开编辑卡**立刻改名** → 开关仍已勾、库里仍 `true`） |
| **负面对照**（临时改回「比书名」+ 把设置读取人为延迟 800ms 制造真竞态） | 如期**只红那一条**（读到 `false`） |
| 还原（幂等修正，非"写回读到的值"）并复跑 | **6 / 6** 全绿；`grep` 复核无 `NEGATIVE-CONTROL` 残留 |

## 六、注意事项（要写进 3.0 更新说明）

🔴 **这是一次有意改变默认行为**：升级后，作者在新建项目时选的题材**不再**出现在 AI 看到的资料里。
- 想保留旧观感：项目管理页 →「编辑项目」→ 勾上「把作品题材告诉 AI」；
- 或填《作品信息》页的「类型赛道」字段（信息量更大、作者主权更高）。
