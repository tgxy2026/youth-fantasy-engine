### P1 资料提及反向导航 · 实现要点与实机发现（2026-10-15）

- **两条链路、一个面板**：检索核心 `lib/search/mentions.ts`（`findMentions(name, aliases)`）；面板 `components/app/MentionPanel.tsx` 复用统一全文检索的 Modal 范式（align=top、bare 结果行、分批 50 章、底部状态条）；入口两处——角色卡（`CharacterSheet` 标题行，别称取本卡 `一、基础信息::别称`）与表格行（`TableSheetRow` 操作列，别称取本行 `别称` 列）。
- **不建倒排、不落库**：SearchEngine 索引构建要 tokenize 全库且滞后于最新章节；百万字级 `indexOf` 是原生快速路径，打开面板即最新数据，也因此不需要任何刷新机制（两个 Sheet 组件本来就没有 onChange）。≤2 字符纯 ASCII 词追加 `\b` 词边界（避免 `ed` 命中 `edition`），中文单字名不设边界（无词边界概念且误报在容忍度内）。
- **别名零新存储**：复用 schema 既有「别称」字段 + `readAliases()`（已有 4 处消费方）⇒ 不动 DB 版本 / 迁移 / SYNC_STORES / 桌面 KEY_PATHS / 备份清单（红线「不做平行数据」）。
- 🔴 **实机测试抓出的真问题（单元测试覆盖不到）**：relations 页签**不走扁平 TableSheetRow**，而是 `TableRelationGroups` 文件夹视图（`tab.id === 'relations'` 时 TableSheet 直接分流）——最初加在 TableSheetRow 上的放大镜在关系页签是**死代码**，主人拍板 ②「relations 行只对人物A 生效」实际从未生效。已修复：放大镜补到文件夹行卡上（`TableSheet.tsx` 透传 `onOpenMentions`）。
- **文件夹视图的目标人物适配（待主人确认）**：同一行关系会同时出现在 A、B 两人的文件夹下（`relationGroups` 对 A/B 各 push 一次）。拍板 ② 的原语境是扁平行「一行两个资料、避免按钮语义分裂」；文件夹视图里这行已按某个人归档（行卡显示「↔ 对方」），故按钮目标取**所在文件夹的人物**（`g.name`）——每张行卡仍然只有一个按钮、语义不分裂，且在 B 的文件夹里目标也是 B（扁平实现的字面「人物A」在 B 文件夹下会指回 A，反而割裂)。若主人偏好字面口径，改一行即可（目标恒取 `row.data['人物A']`）。
- **已知限制（如实申报）**：relations 表没有「别称」列 ⇒ 关系行入口只按主名称检索（角色卡里的「小渊/渊哥」不会合并进来；实测面板「林渊」3 处 vs 角色卡入口 5 处）。若要合并，需在入口处按人名反查角色卡别称（异步），列为后续增强项。
- 测试：`tests/mentions.test.ts` 20 项断言（空名/主名称/别名召回/卷章序/不跨 edition/别名去重/snippet 省略号与窗口边界/无命中）；实机 32 项断言全绿（见「已执行的检查」）。

### P0-D 实现机制（后续改色前必读）

- **两值变量只能解决一半问题**：Tailwind 的 `/alpha` 修饰符经 color-mix 生成「黑×N%」的灰底/灰边/灰字（实测 `.bg-amber/15` 叠白底 = #D9D9D9），固定调色板类名（bg-red-600 / text-emerald-400 等）与主题无关。故 index.css 增设「纯黑白 · 半透明与固定色回收」段，用**属性子串选择器**（`[data-theme='mono'] [class*='bg-amber/']` 等；特异性 (0,2,0)，且未分层样式越于 @layer utilities，无需 !important）按底色/描边/文字/光环/阴影五类一次性回收，覆盖所有 /N 与 hover: 前缀变体；固定调色板按类名含不含 '/' 区分「透明底 → 纯白」与「实底 → 纯黑」（实底上的 text-white 是纯黑白的合法形态，不碰）。
- **交互态补偿（验收第 3 条）**：底色深浅区分失效后——选中（border-amber/N 选中令牌，:not 排除 hover:border-amber）用外轮廓双线；悬停（hover:bg-*）用内嵌 1px 实线（负 offset 不被滚动容器裁掉）；聚焦环改 `--tw-ring-color` 为纯黑（不动 ring 盒影结构）；阴影只清 `--tw-shadow` 变量（`--tw-ring-shadow` 是独立项不受影响，drop-shadow 滤镜用 :not 排除）。
- **index.css 自定义类是逃逸口**：半透明色写在样式表规则里而非元素 class 属性中，属性选择器抓不到，须逐条点名——`input:focus`（border-amber/60 + ring-amber/30 → 纯黑）、`.field-example`（text-amber/70 → 纯黑）、`.card-hover:hover`（border-amber/40 + 8% 黑投影 → 黑边无投影）。
- ✅ **2026-10-16 用户改口径，当日即完成**：图谱 / 地图 / 情节画布 / 结构节奏带的语义数据色**全部收成纯黑白**，类别区分改由**线型 / 形状 / 纹理 / 文字**承担（3.1.1 第 3 项，提交 `62c75f9`，规划 §2.3）。随后一轮独立复核指出「**关系线与标签仍留不透明度 ⇒ 合成成灰**」，已一并收成**严格二值**：mono 下所有不透明度归 1，「淡化」改由**线宽**承载（`a848d6c` 后的一轮复核修复）。③ 仍为当前取舍。
- **已知边界（如实申报，待用户实机验收确认）**：① 图谱/地图/情节画布/结构节奏带的**语义数据色**（palette.ts 的 BEAT_COLORS、REL\_*、GROUP\_*、MAP\_*、PLOT\_*、GOAL_ACTUAL_COLOR）——**2026-10-16 已收进二值色**：新增 `lib/settings/monoMarks.ts` 提供第二编码（线型 / 形状 / 纹理 / 边框档位）、`lib/settings/useMonoTheme.ts` 解决「主题切换不触发重渲染」；② 时间轴轨道、正文缩进导向线、画布点格等图表内部 1px 细线级透明度混色——**图表内的那部分已收**（点阵、节奏带分隔线、图谱连线与标签的不透明度全部归为纯黑/纯白；实机断言「合成色必须是纯黑或纯白」）；③ 内置背景图案为可开关装饰、不做反色（不做全屏阈值滤镜，避免破坏文字渲染）——**仍保留**。
- 测试闸 `tests/themeContrast.test.ts` 同步扩展：主题数 8→9；块解析改「剥注释 + 选择器恰为单个 [data-theme='x']」（mono 回收段有几十条作用域规则，旧口径会把它误判成又一个 mono 主题块）；灰阶单调改非严格（mono 全刻度同值为设计使然，严格比较误报）；新增 mono 专项断言（17 个变量严格二值、面白字黑、THEMES 顺序、派生链排除、18 条回收规则在位）。
