## 一、目标（三处规格的原文口径）

| 来源 | 要解决的问题 |
|---|---|
| **§12** | 档位「行为指引」（`effect`）**只进抽取侧、扮演侧零命中** —— 演戏的模型只看得到裸数（`好感 45`），「低好感该疏远、高好感会依赖」全靠它自己领会，本地小模型领会得飘。 |
| **§13 F1** | 数值**起点档位**与卡文声称的关系不对齐 —— 卡文写着「已完全信任」，新会话数值却从 0（中立）起 ⇒ 角色演得像陌生人。 |
| **§13 F2** | `paceLock`（进度锁）与数值**不一致时没有提示** —— 数值早已跨档，卡文的进度锁还停在旧阶段。 |

🔴 **三处同属「数值 ↔ 言行 ↔ 卡文一致性」，共用 `VAR_BANDS`** —— 分开做等于把同一张表改三遍。

🔒 **不扩范围**（§12.3 / §13.4 的原文边界）：本项**只做「关系状态的起点、翻译与提示」**。
亲密内容的解锁权**仍在角色卡** `conduct.rating` / `bottomLine` / `paceLock` ——
**不因数值升高而自动放开尺度**。`paceLock` 的改写走既有 `CARD_FIELDS` 通道，且**须作者裁决**。

## 三、设计

### 3.1 W2-4a（§12）档位 + 行为指引进扮演侧（`tavern/vars.ts`）

在 `buildVarStateBlock` 的「你此刻的状态」行之后，**只加一行**：

```
〖本场数值〗
你此刻的状态：好感 45 · 信任 -10 · 精神 0 · 心情 …… · 地点 ……
当前档位：好感「亲近」— 愿意多聊、肯搭把手，但还留着分寸；信任「一般」— 按常识判断，谈不上托底……
（这是给你把握分寸用的状态，不要把它抄进正文。）
```

🔴 三条纪律（照 §12.3）：
- **只对数值项** —— 用 `bandsOf(k)` 判（返回 null 的文本项自然不进）；
- **只渲染启用中的 keys**（`keys` 参数已是过滤后的；关掉一个都不加）；
- **只输出当前档位一行**，**绝不把整张五档表塞进扮演侧**（每轮都注入、额度敏感；全表仍只在抽取侧给）；
- 保留「不要把它抄进正文」尾句；
- 取值一律走 `bandOf` ⇒ 与界面 `TavernVarsPanel` **共用同一份 `VAR_BANDS`**，不另立口径。

### 3.2 W2-4b（F1）起点档位与卡文对齐（🆕 `tavern/paceLockBands.ts`）

```ts
/** paceLock 措辞 → 目标档位名（在 VAR_BANDS 里按 name 找） */
const PACE_HINTS: { re: RegExp; key: VarKey; band: string }[]

/** 用该档的区间中点作锚点（🔴 复用 VAR_BANDS，不另造一套刻度） */
export function bandAnchorOf(key: VarKey, bandName: string): number | null

/** 从卡文「进度锁」推断起始数值（推不出 ⇒ null，调用方保持原行为） */
export function paceLockStartValues(paceLock: string): Partial<Record<VarKey, number>> | null
```

- 映射示例：`完全信任 / 毫无保留` → `trust`·「全然信赖」；`信任 / 托付` → `trust`·「信任」；
  `提防 / 戒备` → `trust`·「提防」；`亲密 / 恋人` → `affection`·「亲密依赖」；
  `亲近 / 熟络` → `affection`·「亲近」；`疏远 / 冷淡 / 陌生` → `affection`·「反感」。
- 接进 `seedSessionVarsFromCard`：**卡上没有 `card.vars` 时**才用（有持久数值就以那份为准 —— 那是
  上一场处出来的真进度，不能被一张静态卡文盖掉）。
- 🔴 推不出（卡文空 / 没命中任何措辞）⇒ **返回 null，保持现状（全 0 起点）** —— 不猜。

### 3.3 W2-4c（F2）跨档一致性提示（同模块 + UI）

```ts
export interface PaceDrift { key: VarKey; wantBand: string; nowBand: string | null }
/** 卡文声称的档位 vs 当前数值所在档位 —— 不一致才产出 */
export function paceLockDrift(paceLock: string, values: VarValues): PaceDrift[]
```

- UI：在酒馆右侧「本场状态」面板（`TavernVarsPanel`）给一行**非阻断提示**：
  「卡文写的进度锁是「已完全信任」，而当前信任是「提防」—— 要同步改卡吗？」+ 跳角色卡按钮。
- 🔴 **绝不自动改卡**（§13.4 F2 原文：会动角色卡根本，须作者裁决；沿用「设定建议默认不勾」的纪律）。
- 提示是**纯派生**（每次渲染现算），不进组件 `useState`、不落库。

## 五、边界与红线（照做）

- 🔴 **不扩范围**：不动亲密解锁逻辑（`conduct.rating` / `bottomLine` / `paceLock` 的判定权仍在卡）。
- 🔴 **不自动改角色卡**（F2 只提示）。
- 🔴 **不把五档全表塞进扮演侧**（只当前档一行）。
- 🔴 映射与锚点**一律复用 `VAR_BANDS`**，不另造刻度（否则界面与注入会漂移）。
- 🔴 推不出就**不猜**（返回 null 保持现状）。
- 🔴 模板文案改动须同步 `variable` 相关的既有单测（注入文案有契约）。

## 六、验收

- `tsc --noEmit` 0 ／ `eslint src tests` 0 problem ／ 全量单测全绿（新用例须归批）。
- 单测：
  - `buildVarStateBlock`：数值项带档位 / 文本项不带 / keys 为空返回空串 / 越界值走端点档；
  - `paceLockStartValues`：「已完全信任」→ trust 落在「全然信赖」档的区间内；
    `affection` 同理；空卡文 ⇒ null；
  - `paceLockDrift`：跨档产出、同档不产出、卡文空不产出。
- 实机（真 Electron）：进酒馆自由对话 → 右侧「本场状态」；注入文案在真机日志/上下文中正确且未撑爆额度。
- 负面对照：`paceLock` 含无关措辞（如「按剧情节奏」）⇒ 不产出起点、不产出提示。
