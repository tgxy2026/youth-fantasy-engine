## 三、🔴 清算时挖出的真问题：候选配额**只增不减**（死锁）

这不是死代码问题，是**功能性缺陷**。链条如下：

| # | 事实 |
|---|---|
| ① | `saveCandidate` 用「本项目全部载荷条数」判配额（200 份 / 32 MiB） |
| ② | 候选的**存储形态就是载荷**（`payloadToCandidate`）；放弃 / 应用 / 过期**都不删载荷**，`discardCandidate` 是纯函数只改状态 |
| ③ | 唯一能删载荷的 `deleteCandidate` **零调用** |
| ④ | 本该统一回收的 `cleanupOrphanPayloads` 也**零调用**，而 `deleteRevisionJobWithCleanup` 的注释还写着"由它统一回收" |
| ⑤ | 常量 `ORPHAN_PAYLOAD_RETENTION_DAYS`（30 天）**从没被读过** |

**后果**：载荷只增不减。攒满 200 份后新候选永远存不进来，界面提示
「请先清理旧候选再生成」——**但作者清理完再生成还是满的**，因为候选列表里根本
看不到那些已放弃的载荷（它们只是库里的孤儿）。这是一个**说不清、也修不好的死循环**。

**修法**（最小且可解释）：

- 新增 `candidateStore.reclaimStaleCandidates(projectId, now)`：
  回收「**终态 + 超龄**」的载荷，宽限期就是那个 30 天常量；
- **只在配额不够时**才跑（正常一次都不扫，零额外开销）；
- **在途状态一律不动**：`pending`（待作者审）/ `applying`（写一半）/
  `needs-reconcile`（等核对）—— 删了就是删作者的稿子。

**测试**（`tests/revisionStorage.test.ts` ⑤，已从"零调用的白名单清理器"改测真回收器）：

| 断言 | 结果 |
|---|---|
| 只回收「终态 + 超龄」的那一份 | ✅ |
| 超龄已放弃 → 已删 | ✅ |
| 🔴 **超龄但待审 → 一份都不许动** | ✅ |
| 已应用但未超龄 → 留着（宽限期内可回看） | ✅ |
| 再跑一次回收 0 份（幂等） | ✅ |

## 四、迁移中横幅：闭合 3.2.0 方案 §3.6 的最后一段

3.2.0 的「模板迁移写入隔离」**拦**的部分早就完整（`guardTabWrite` 被草稿恢复 /
自动保存 / AI 回填 / 导入四条路径调用），缺的只是**让作者知道为什么存不进去**。

新增 `components/templates/MigrationLockBanner.tsx`：

- **点名**：`activeMigrationTabIds(projectId)` 返回"哪个页签在迁移"，
  横幅写「「角色卡」正在更换模板」——只说"有页签在迁移"作者无从判断该等谁；
- **说清被拦什么**：草稿恢复 / 自动保存 / AI 填回写 / 导入；
- **说清改动没丢**（这是事实不是安慰：四条路径被拦时都返回冲突对象、不吞内容）；
- **只告知、不给按钮**：迁移由模板管理弹窗发起与收尾，在另一个入口放"取消迁移"
  会和它的状态机抢时序 —— 这是这层该有的边界。

## 六、🔴 顺带修掉一个让审计表长期算错的工具 bug

**症状**：本轮加了白名单条目后，A 类突然从 15 变成 **0**，A2 也是 0 —— 看着像"死代码清零"，
实际是扫描器**拿自己给自己作证**。

**根因**（两层）：

1. `audit-dead.mjs` 统计"外部引用"时用 `walkAny(ROOT)` 扫全仓 —— **把 `scripts/audit/` 下的审计脚本
   自己也算成引用源**。而本脚本的 `KEEP` 表 key 是字符串 `'src/lib/xxx.ts:符号名'`，
   `stripComments` **刻意保留字符串内容**（因为类名 / `data-*` 里的符号名该算命中）⇒
   凡进了白名单的符号，都被自己这张表的 key 算成"外部有人用"。
2. 连带后果：**A2「白名单保留」永远是 0 个**（`promptText` / `VolumeRange` 挂在那儿几年都没显示过，
   白名单看着像在自动消账、实际靠的是这个字符串副作用）；同轮我还在注释里列举了 15 个符号名，
   于是 A 类一度全变 0。

**修法**：`walkAny` 排除整个 `scripts/audit`（六支扫描器都在这儿，谁都不该给谁作证）。
⚠️ 第一版正则写成 `/[\\/]scripts[\\/]audit/`，**漏了路径开头没有分隔符**的情况
（`path.join` 出来的 `scripts\audit` 开头没有 `\`）⇒ 排除没生效，靠临时打点
（打印 `extFiles`）才看清"作证者是脚本自己"。改成 `/(^|[\\/])scripts[\\/]audit([\\/]|$)/` 才对。

**修完的收益**：A2 白名单第一次正常显示（5 条），并**新暴露 1 条之前被掩盖的真候选**
（`EXCLUDED_META_KEYS`）—— 与 2026-09-19 那次"排掉 bundle 污染后候选 178 → 240"是同一类经验：
**审计工具自己的 bug，方向永远是"少报"**。

## 七、结论边界

- ✅ 可以说：25 个零引用符号**逐条判完**，接 7 / 删 6 / 白名单 3 / 待接 10（各有理由）；
  顺带修掉一个会让候选生成彻底堵死的**配额死锁**、闭合 §3.6 的可见性缺口，
  并修好一个**让本表长期算错**的扫描器 bug。
- ⛔ 不能说：死代码清零。**10 个仍在**，全部是"该接未接"的入口（每条都写了接法），
  只是不该在这一轮硬塞。
- ⛔ 不能说：迁移横幅已实机验证。单元测试钉住了数据源与订阅，
  **界面呈现仍需真机过一次**（换模板时横幅出现 / 迁移结束自动消失）。
