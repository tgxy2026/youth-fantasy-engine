- **lib/chapterCheck.ts（新）**：串 `continuityCheck` / `foreshadowEngine` / `sensitiveWords` / `typoWords` / `styleAudit`
  五个既有引擎，**全部本地、不发 AI**。全书级引擎（连续性 / 伏笔）跑完再过滤：
  连续性按 `location.kind==='chapter'` 且 id 匹配取本章相关问题；伏笔按「本章埋设 / 回收」从看板挑取
  （⚠️ 口径与引擎一致 —— 看板按**章标题**认章，同名章一并命中，不另立口径）。
  单引擎失败 `.catch` 留空组，不拖垮整体。
- **ChapterCheckPanel.tsx（新）**：选章 + 「体检本章」手动触发（规划要求）+ 五组结果。
  挂在检查工具页「投稿前自检（B2，全书）」与「节奏与章末钩子（B5，单章需 AI）」之间 ——
  本面板填的是「单章 × 确定性」这个空位，三者不重叠。换章自动清空旧报告。
- **单测 11 项**（`tests/chapterCheck.test.ts`）：过滤只认本章 / 别章与 tab/row/无定位一律滤掉 /
  伏笔按标题命中且只收自己的问题 / 计数口径（敏感词错别字按出现次数、文风剔除「通过✓/未登记」两条提示性 info）。

## C4 · 分平台投稿预检 ✅（2026-09-23）

- **lib/platformRules.ts（新）**：三档 `general / jjwxc / qidian`，每档 = 重点关注类别 + 投稿提示 + 参考字数区间。
  🔴 三条边界写进文件头：只描述结构性差异、**不做风险打分不评优劣不判能否发布**；平台规则随时变，
  所有提示注明「以平台后台 / 最新公告为准」；**不做任何降低检出率的事**。
- **lib/platformCheck.ts（新）**：`scanByPlatform` 带**类别**与「是否该平台重点关注」（自定义词一律算重点关注）；
  `chapterFacts` 算每章字数 / 段数 / 最长段（字数口径与看板共用 `countWords`）；
  `precheckBook` 汇总出**观察句**——只摆事实，参考区间落在外面只说明「与常见投稿习惯不同」。
- **PlatformCheckPanel.tsx（新）**：挂检查工具页（C3 之前）。平台分段切换 + 「预检全书」手动触发 +
  观察句 / 命中（按关注度排序）/ 区间外章节（只列前 20 章防刷屏）/ 平台提示四块。平台选择存
  `settingsKV::platformCheckPlatform`（跨项目）。
- **单测 26 项**（`tests/platformCheck.test.ts`）：分章事实、两档关注类别差异（晋江关注色情低俗、起点不关注）、
  未收录平台回落通用档 + 🔴 **立场断言**（读源码全文，禁词「命中率 / 规避检测 / 反检测 / 洗稿 / 过审率 / 合格 / 不合格」
  一个都不许出现 —— 与 B5 同款机器守护）。
- 🐛 踩坑（值得记）：测试里 `const mkCh = (...): Chapter => ({...} as unknown as Chapter)` 这种
  **箭头函数返回对象字面量 + 结尾无分号 + 下一行紧跟块语句**的写法，esbuild 能打包、TS 却报
  `TS1003 Identifier expected`（把对象字面量当成参数/解构模式解析）。改成 `function mkCh(...){ return {...} }` 即过。
  ⇒ **测试辅助函数一律用函数声明，别用「箭头 + 对象字面量」**。
- ⚠️ 遗留：**实机验证未跑**（下轮与 C5 一起补）。
