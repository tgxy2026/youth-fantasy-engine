## C2 · 备份体系第二期 ✅（2026-09-23）

规划三块全部落地，另有一处**规划口径修正**：

> ⚠️ 规划原文写的「便携版备份外置同目录独立文件」，前提已不成立 —— 2.4.0 起**只做桌面版**，
> 便携版已砍。故本轮落地为：**桌面版可把任意一份备份导出成磁盘独立文件**（可放云盘 / 移动硬盘），
> 并支持**从该文件恢复当前项目**。这才是「备份外置」在单桌面版形态下的真实价值。

### ① 元数据与载荷分离（`db/backups.ts` + IDB v11）

- `backups` store 从「元数据 + 整包 bundle 同条」改为**只存元数据**：
  `{ id, projectId, kind, label, createdAt, bytes }`；载荷进新 store `backupPayloads`（`{id, projectId, bundle}`，带 projectId 索引）。
- ⇒ 列表页从「把每份备份全文读出来 + 每份 `JSON.stringify` 算体积」变成**零成本**（`bytes` 写入时算一次）。
- 写入顺序：**先载荷后元数据**（元数据是列表看得见的东西，载荷缺失会立刻暴露而非留空壳）。
- 删除顺序：**元数据与载荷一起删** —— 只删一边就是孤儿载荷白占空间。
- **数据迁移** `migrateBackupPayloads()`（`db/migrations.ts`）：把老记录的 bundle 搬到新 store、元数据补 `bytes`，
  **幂等**；🔴 放在 `runMigrations` 的 `currentProjectId` 守卫**之前** —— backups 是跨项目的本地专属 store，
  与「当前打开哪个项目」无关，放守卫之后会让从不打开项目的用户永远不迁移。
- **兼容读取**：`listBackups` 对老记录现算 bytes 并**剥掉 bundle**（元数据出库就只该是元数据）；
  `getBackupPayload` 先查新 store、回退读老记录的 bundle。⇒ 迁移没跑到也不会崩。
- IDB schema：`DB_VERSION 10 → 11` + `migrateV10toV11`（建 `backupPayloads` + projectId 索引）。

### ② 🔴 本地专属 store 收敛成单一判据（本轮最值得记的一处）

「backups 是本地专属」原先被**写死在 6 处**（上传侧 `liveStores` 剔除、`mergeCaches` 读取、`seedFromLocal` 跳过、
本机快照 `captureSyncData` 跳过、云包装层 `cloudOrLocal` 短路、`mirrorCloudCacheToLocal` 跳过）。
新增 `backupPayloads` 若漏掉任何一处，后果都是**静默**的：载荷进云端 cache 被上传，或本地写被挡在云端刷新即丢。

⇒ 抽成 `syncCore.LOCAL_ONLY_STORES` + `isLocalOnlyStore()`，**6 处全部改用它**。
现在新增本地专属 store 只需往那个数组加一个名字。（这是 09-22 那条「同一个病的所有路径要一次找齐」的固化。）

### ③ 备份外置（导出 / 恢复）

- `buildBackupFile(id)`：把一份备份打成 `{ kind:'yfe-backup', version, exportedAt, meta, bundle }` 的磁盘文件
  （文件名含书名与备份时间）。
- `parseBackupFile(text)`：格式不符**明确报错**并指路（「这可能选到了迁移包 —— 请用『导入迁移包』」），
  避免两种包互相被误吃。
- `restoreBundleToProject(projectId, bundle)`：把外置文件的包覆盖写回**当前项目**
  （与「导入迁移包 = 新建项目」语义区分）。UI 在备份行加导出按钮、在迁移区加「从备份文件恢复本项」。

### ④ 界面体积与总占用

体积改读元数据 `bytes`（不再 stringify）；总占用与孤儿备份体积同口径；孤儿备份提示里写清「只在本机数据文件里」。

### 单测（`tests/backupPayloadSplit.test.ts`，33 项）

本地专属判据 / 写入即分离（backups 无 bundle、payloads 有载荷）/ 列表项不含 bundle / 老库兼容读取（现算 bytes、
剥 bundle、payload 回退）/ 迁移幂等（跑两次第二次为 0）/ 删除两侧 / 外置文件往返 + 迁移包被拒 / 恢复覆盖生效 / 体积汇总。

### 连带修正（测试资产落后，非产品回归）

`tests/cloudStoreWrapper.test.ts` 有一条断言把「本地专属数量」写死成 `SYNC_STORES.length - 1` ⇒ 本轮红了。
改为 `- LOCAL_ONLY_STORES.length`，并补 3 条同构断言（backupPayloads 不读不写云端、云端可用时也落本地、读也走本地）。

## C9 · 一键拆书支持 .docx ✅（2026-09-23）

**落地＝手写解析，零运行时依赖**（`dependencies` 至今为空，打包体积基线不动；与写侧手写 OOXML 的
`exportDOCX` 对称）。规划原案的 mammoth 路线**未采用**（数百 KB + tree-shake 复核成本）。

**新增 `src/lib/docxImport.ts`**（约 260 行，纯手写）：
- 解 zip：**中央目录优先**（压缩方式 / 压缩后大小 / 本地头偏移都在那里），缺失时才退到顺序扫本地头；
- 解压：`DecompressionStream('deflate-raw')` —— zip 的 method 8 是 **raw deflate**（不是 zlib 包裹）；
  同时支持 method 0（store，即本软件 `ZipBuilder` 写出的那种）；
- 抽文本：`<w:p>` 段落 → `<w:t>` 取字、`<w:br>/<w:cr>` 换行、`<w:tab>` 制表；XML 实体单次解码；
- 🔴 **首行缩进按段落属性补全角空格**：Word 的中文缩进是 `<w:ind w:firstLineChars="200"/>` 这种
  **段落属性**而不是字符，纯文本化会丢 ⇒ 读到了就补 `　　`（与编辑器正文、导出侧「禁行首 trim」
  的 A5 口径对齐）；已有缩进不重复补，悬挂缩进（列表项）不补；
- 🔴 **读不到的如实回报**（`skipped`）：批注 / 脚注尾注 / 页眉页脚（看 zip 里有没有对应部件）、
  图片 / 公式 / 修订删除的文字（看 document.xml 里的标记）—— 宁可多一句提示，也不静默丢；
- 失败理由**能直接给用户看**：`.doc`（CFB 头）→「请在 Word 里另存为 .docx 或 .txt」；
  `.epub` →「请先用阅读器导出为 .txt 或 .docx」；不是 zip / 缺 document.xml 各有各的说法。

**接入**：`BookBreakPanel.onFile` 按扩展名分流（`.doc` 单独劝退），按钮与 `accept` 改为
`.txt / .docx`，帮助气泡与 placeholder 同步；`.txt` 路径一字未动。

**单测 26 项 / 实机 16 项全过**。单测抓到两个实现缺陷（都已修）：
① `String.trim()` 会把**全角空格**一起吃掉 ⇒ 手打缩进与自动补的缩进都被抹平（改为只剥半角空白）；
② `&#x110000;` 越界码点让 `String.fromCodePoint` 抛 `RangeError`，会把整次导入炸掉（补上限判断）。

实机（`ui-242-docx-import.mjs`）用 **Word 真实形态**的文件验：deflate 压缩 + `w:pStyle` + 段落属性缩进，
外加批注部件；`.doc` / `.txt` 两个分支同轮覆盖。

## C5 · 读者视角审问 ✅（2026-09-23）

**它和「AI 审稿」不是一件事**：审稿类提示词会把模型推向挑语法与结构（那些已由本章体检 C3、颉文姬校对
覆盖）。这里要的是**一个具体的人在读** —— 会走神、会看不懂、会想知道后面的事。所以提示词走

## 🔴 发布后修复：撑满型页面塌掉（酒馆对话窗口变小 / 编辑器被裁）（2026-09-23 晚，老大报障）

### 现象
- **剧情推演**：对话窗口变小，**下方留一大块空白**
- **自由对话**：同上，空白更大

### 根因（`3a9575c`「页头冻结」那次改动埋的）
那次为了修 sticky 表头贴不住顶，把 padding 从滚动容器 `main` **挪进内层 div**：
```diff
- <main className={`flex-1 overflow-y-auto ${isEditor ? '!overflow-hidden' : 'p-6 lg:p-8'}`}>
-   {renderContent()}
+ <main className={`flex-1 overflow-y-auto ${isEditor ? '!overflow-hidden' : ''}`}>
+   <div className={isEditor ? '' : 'p-6 lg:p-8'}>     {/* ⚠️ 只有 padding、没有高度 */}
+     {renderContent()}
```
`renderContent()` 从此不再是「高确定的 main」的直接子，而是「auto 高的 div」的子 ——
而 `h-full`（`height:100%`）**必须参照父的确定高度**，父是 auto ⇒ 百分比退化成 auto ⇒ 撑不满。

当时只顺手修了**加载占位**（`h-full` → `min-h-[50vh]`），**没意识到整类「撑满型页面」都受影响**。

### 实测（纯 CSS 像素，zoom 1.08，可用高 862 / 926）
| 页签 | 修复前根高 | 可用高 | 后果 |
|---|---:|---:|---|
| 剧情推演 | 372 | 862 | **下方留白 490px** |
| 自由对话 | 375 | 862 | **下方留白 487px** |
| 正文编辑 | **1391** | 926（main 为 `!overflow-hidden`） | **465px 被裁掉且滚不到**（更严重） |

🔴 **同一根因、两类症状**：内容比窗口短 ⇒ 留白；比窗口长 ⇒ 被裁。
只修报障的那两类会漏掉编辑器 —— 好在按纪律顺手量了它才暴露。

### 定位手法（值得复用）
在**改源码之前**，先在页面里注入 `main > div { height: 100% !important }` 做**阳性对照**：
三个页签的空白立刻归零（372→862 / 375→862 / 1391→926）⇒ 根因当场锁定，不必靠读代码猜。

### 修法（一行）
```diff
- <div className={isEditor ? '' : 'p-6 lg:p-8'}>
+ <div className={`h-full ${isEditor ? '' : 'p-6 lg:p-8'}`}>
```
补完后与「padding 还在 main 上」时的几何**完全一致**（内容高 = main 高 − 上下 padding）。
