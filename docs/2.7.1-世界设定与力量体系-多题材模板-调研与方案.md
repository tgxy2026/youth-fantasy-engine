## 0. 一句话结论

现有两个页签的**骨架是对的，只是"血肉"全是修真范式**。
做法不是推翻重写，而是拆成 **「共享字段（同名同键・切包保留）＋ 题材模块（随包替换）」**，
开书时选一次**题材包**，两个页签同时切换模板；换包**只隐藏、不删除**，切回即恢复。

**本轮范围：10 个题材包一次做全，包名统一四字。**

### 1.3 从「题材」到「设定维度」的通用规律

外部写作资料（网文大纲模板、都市/仙侠/科幻三类世界观构建模板等）给出的维度与现有 schema 高度重合，说明**骨架不用换**：

| 通用写作维度 | 现有 schema 对应 |
|---|---|
| 世界背景 / 时代 / 舞台 | 一、世界总览 |
| 力量来源 / 等级划分 / **使用代价** | 力量体系（力量来源、等级总表、限制规则…） |
| 社会结构 / 阶层流动 / 核心矛盾 | 三、社会与文明 |
| 势力与组织 | 现有 `nations` / `faction-rels` 页签（**不重复**） |
| 地理与地图 | 现有 `geography` 页签（**不重复**） |
| 历史脉络 / 大事年表 | 现有 `timeline` 页签（**不重复**） |
| 隐藏规则（多数人不知道的真相） | 世界终极真相 / 体系的隐藏层级 ✅ |
| 金手指 / 主角接口 | 四、与主角的接口 ✅ |

**结论**：`worldbase`＝**顶层档案**，`power`＝**规则引擎**；两者都不接管别的页签已有的东西（地图/势力/时间线）。模板化只在**这两个页签内部**做文章。

### 2.3 三个结构性问题

**问题 ①：字段级"锁死数值"靠字段名关键字猜**
`POWER_NUMERIC_HINTS = ['境界','等级','战力','寿元',…]`，判据是 `字段名.includes(hint)`。
模板化后新字段若不含这些字，就**不会被锁**（AI 补全可能乱填数字）→ 升级为**字段显式声明**（§5-#2）。

**问题 ②：「类型赛道」有两个互不通气的存储位** 🔴
- `Project.genre`（`types.ts:121`）—— `aiContext.ts:692` 会注入 AI「类型：xxx」；
  但 **`ProjectHub.create()` 传空串**（`ProjectHub.tsx:126`），只有示范项目填过 `'东方玄幻'` ⇒ 事实**已废弃**。
- 作品定位页签的「类型赛道」字段（`schema.ts:149`）—— 作者真正填的地方，**只是自由文本，且不同步**。
⇒ 本轮**复用它作为题材枚举存储位**（§4.0）。

**问题 ③：无超自然题材下「力量体系」页签无处安放**
历史文、都市日常/现实**没有力量体系**。番茄甚至明确要求"都市日常：无任何幻想元素、无金手指、无系统"。
⇒ 处置方案见 **§4.5（已拍板：弱替，不隐藏）**。

### 2.4 🔴 社区反馈：历史类的「颗粒度」对不齐（本轮新增 ⇒ 详见 §4.9）

> 反馈原文（大意）：
> 「世界设定的颗粒度对不齐。这个设定明显是为高武高魔世界观设的。可可写的历史类世界观**都统一在一个世界下**，
> 但**政治架构、经济情况、宗教信仰、司法体系极为丰富、且差异性极大**，而有关超凡力量的内容则几乎没有，该怎么办？」

这条反馈**不是字段错配**（那已由题材包解决），而是**结构颗粒度**问题。拆成四条：

| # | 反馈里的事实 | 现有结构为什么接不住 |
|---|---|---|
| ① | 「**都统一在一个世界下**」 | 明确排除「多个世界」⇒ **不能拿「子世界」当解法**（子世界＝副本/世界线，语义不符）|
| ② | 「政治架构 / 经济 / 宗教 / 司法 **极为丰富**」 | `worldbase` 是**单实例扁平表单**，每个概念只有**一格**，装不下一整套制度 |
| ③ | 「**差异性极大**」 | 需要**多份并列 + 可对比**；单份表单连「有两套」都表达不了 |
| ④ | 「超凡力量几乎没有」 | 已由 §4.5「历史古代 → 权谋实力」弱替解决 ✅ |

**缺的是一种「一个世界、多份平行档案」的容器。** 三条候选路线与判定：

| 路线 | 做法 | 判定 |
|---|---|---|
| A | 每个政权建一个**子世界** | ❌ **否**。语义＝副本/世界线；且**只有标「活跃」的才发给 AI**，而多政权需**同时在场**；且每个政权要把 20 个共享字段重填一遍 |
| B | 给 `worldbase` 题材模块加「**可重复（多条目）**」能力 | ✅ **可可建议**（§4.9）：语义最正、共享字段仍单份、随世界设定**全量注入 AI**、`东方修真` 不启用 ⇒ 零破坏 |
| C | 把制度维度**扩到既有 `nations` 表**，历史包下换列 | 🔶 **不首选**。多行天然支持，但要引入「**表列随题材包解析**」，等于把题材机制扩散到**世界构建全套表**（与「模板化只在两个页签内做文章」的既定原则冲突）；且作者在**开书定位**填表，却被要求跳去**世界构建**，心流割裂 |

**采纳 B，同时吸收 C 的优点**：`nations` 表**继续承担「势力台账」**，并在 §4.9.4 写明分工 + 做互链，避免「填两遍」。

> 🔄 **v4 更新**：主人哥哥随后提出「**把制度维度升为独立页签、世界设定降为总览**」的新结构（见 **§8**）—— 它可能**取代**本节的「可重复模块」路线（§8.3），故本节结论**暂挂**，以 §8 的拍板为准。

## 3. 设计目标与原则

| # | 目标 | 原则 |
|---|---|---|
| 1 | 各题材作者都能"对得上表" | **共享字段恒定**，只有题材模块随包替换 |
| 2 | 老项目/示范项目零破坏 | `东方修真` 包 = **现状逐字保留**（模块名、字段名一个不改） |
| 3 | 换包不丢数据 | **同名同键的字段切包保留**；不同名字段只隐藏不删除 |
| 4 | AI 链路自动适配 | AI 上下文/导出均按 schema 渲染 ⇒ 换包后模型自动只看到当前包字段 |
| 5 | 不越界 | 地图/势力/时间线仍归各自页签 |
| 6 | 可扩展 | 新增题材包 = 加一份数据文件，不改渲染层 |

**核心规则（贯穿全案）**：

> 🔴 **同名同键 = 切包保留；不同名 = 随包隐藏。**
> 承载同一概念的字段，**在所有 10 个包里用同一个字段名**（以现状命名为准），因此作者从「东方修真」切到「科幻末世」时，
> 世界名称 / 社会结构 / 体系类型 / 等级命名原则… 这些内容**原样跟着走**，不丢。

## 4. 方案设计

### 4.0 数据源：复用 `Project.genre` 作题材枚举 🔴 已拍板

不新增 DB 列，把废弃的 `Project.genre` 改为**封闭枚举**：

```ts
// 值域 = 十个四字包名（封闭集合）
export const GENRE_PACKS = ['东方修真','西方奇幻','都市异能','都市现实','历史古代',
                            '科幻末世','武侠江湖','悬疑灵异','游戏竞技','女频言情'] as const
export type GenrePack = typeof GENRE_PACKS[number]
export const DEFAULT_PACK: GenrePack = '东方修真'
export function isGenrePack(v: unknown): v is GenrePack
export function normalizeGenrePack(v: string): GenrePack   // 别名归位 + 空/未知 → 默认
```

- **别名归位表**（老数据兼容）：`'东方玄幻' / '修真' / '仙侠' / '玄幻'` → `东方修真`；`'异界大陆'/'剑与魔法'` → `西方奇幻`；`'都市修仙'/'异术超能'/'高武'` → `都市异能`；`'都市'/'现实'/'职场'` → `都市现实`；`'穿越历史'/'架空历史'/'历史'` → `历史古代`；`'科幻'/'末世'/'星际'` → `科幻末世`；`'武侠'` → `武侠江湖`；`'悬疑'/'灵异'` → `悬疑灵异`；`'游戏'/'电竞'/'体育'` → `游戏竞技`；`'言情'/'古言'/'女频'` → `女频言情`。
- **AI 注入天然可读**：`aiContext.ts:692` 现有 `类型：${proj.genre}` ⇒ 直接输出「类型：东方修真」，**不用额外映射**。
- **无需改 DB/备份/导入导出**：字段与快照链路已覆盖 `Project`（`db/backups.ts:314` 会带上）。
- ⚠️ 代价：值是中文显示名，改包名会让老数据落到别名表——所以**包名一旦发布就冻结**，改名必须走别名表。

**选择器三段式**（按顺序）：

### 4.7 切换题材包的数据策略 🔴 已拍板（保留隐藏 + 提示）

| 策略 | 说明 | 结论 |
|---|---|---|
| **保留隐藏** | 旧字段数据留在 `formData`；切回原包即完整恢复 | ✅ 默认 |
| **迁出为草稿** | 把不再适用的字段导出成只读草稿，提示手工取舍 | 🔶 二期可选 |

### 4.8 与母子结构、AI 链路、导出的关系

- **母子结构**：`WORLD_SET_TABS = ['worldbase','power']` 不变；模板只决定"渲染哪些模块"，母子两层复用同一渲染，天然跟随。
- **AI 上下文**：`aiContext.sectionOf` 走 `renderForm(tab, …)`，遍历 `tab.modules` ⇒ **自动只发当前包字段**；`PRIORITY` 顺序不变。
- **导出**：`exporter.ts` 设定集导出同样遍历 schema ⇒ 自动适配。
- **种子/示范项目**：《吞天神脉》绑 `东方修真`，字段与现状逐字一致，**零影响**。

### 4.9 🆕「可重复模块」—— 一世界多政权 / 多门派 / 多家族的颗粒度（社区反馈）

> ⛔ **【v5 已撤回 · 2026-10-02】** 主人选择「**保留母子结构**」（Q11）后，本节的诉求（一世界多份并列档案）**由「子项」承载** ⇒ 本节方案**不再实施**（替代与理由见 §8.3）。
> ✅ 下文保留作**决策记录**（说明为什么最终不走这条路）；§5 清单的 **#14 ~ #20 随之整组作废**。

**问题**：`worldbase` 是单实例扁平表单，而历史文需要「一个世界、多份政权档案、每份一套制度」（§2.4）。

**方案**：给 `FormModule` 加两个**可选**标记，把「模块」从「固定一份字段」升级为「**可添加 N 个条目、每条目一套字段**」。

```ts
export interface FormModule {
  name: string
  fields: FormField[]
  repeatable?: boolean   // 🆕 可重复：可添加多个条目
  entryLabel?: string    // 🆕 条目称谓（单数），用于按钮与默认名，如「政权」
}
```

#### 4.9.1 存储形态（沿用既有键约定，与现状无损共存）

| 内容 | 键 |
|---|---|
| 条目清单（顺序 + 空条目） | `模块名::__entries__` → `["大燕","大夏"]`（JSON）|
| 条目字段值 | `模块名::条目名::字段名` → `"三公九卿，皇权不下县"` |

- 仍以 `模块名` 打头 ⇒ 与现状「模块名::字段名」**同族**，§3 的「**同名同键＝切包保留**」规则自动适用：条目名相同则内容跟着走。
- 清单键的**字段名段**是 `__entries__`（`__` 前缀）⇒ 可被内部字段判据挡在 AI 之外（需按 §4.9.3 加固）。
- 普通模块的旧数据**一个字节不动**；`repeatable` 只对声明它的模块生效。

#### 4.9.2 界面（`SchemaFieldGrid` —— 母级/子级的**唯一**渲染点，改一处两层同时生效）

- 模块头右侧：`N 条` + 「**＋ 添加{entryLabel}**」。
- 每个条目＝一张子卡（标题＝条目名，可**改名 / 删除 / 上下移**），卡内按 `fields` 渲染，键＝`模块名::条目名::字段名`。
- 条目名默认 `{entryLabel}1/2/…`；**改名要连带迁移该条目所有字段键**（对齐「改地图名连带改归属」的既有做法）；**删除需先做引用检查**。
- 无条目时给一句轻提示（「还没有政权，先添加一个」），不渲染空卡。

#### 4.9.3 AI 上下文（`aiContext.ts:renderForm` —— AI 侧**唯一**渲染点）

条目渲染成**二级小标题 + 缩进字段**，一眼能看出「这是两个政权」：

```
三、列国政权志
· 大燕
  政体与政治架构：三公九卿，皇权不下县
  宗教信仰：以儒为表、释道并行
· 大夏
  政体与政治架构：部族议事 + 可汗推举
```

- 渲染顺序照 `__entries__` 清单（**不按字典序**，避免每次注入顺序漂移）。

| ⛔ Q12「表 / card 型页签」 | 一张「政权志」表，一行一政权、列＝政体/经济/宗教/司法 | **取消** —— 与 Q10（制度**各成页签**）**方向相反**：表型是「一个政权一条横切档案」，那就没必要再分政治/经济/宗教/司法四个页签；且表型**没有母子** |

**一句话**：**「一份政权档案」= 某个制度页签下的一个「子项」。** 作者想给「大燕」写政治，就在 `politics` 页签建一个「大燕」子项；写经济，就在 `economy` 页签建一个「大燕」子项。

**连带收益（本轮风险清零）**：§5 清单的 **#14 ~ #20 整组作废** —— 不用再改 `SchemaFieldGrid`、不用加固 `renderForm` 兜底、不用复核 7 处 `::` 键解析点、不用做条目改名/迁移。它们**全部依赖「三段键」**（`模块::条目::字段`），而子项用的是**两段键**（`模块::字段`），与现状同族 ⇒ **所有既有链路零改动**。

⚠️ **一处固有代价（源自 Q10 的选择，不是母子带来的）**：制度**各成页签**后，写「一个政权的全套制度」要在 4 个页签间跳（政治 → 经济 → 宗教 → 司法）。这正是 Q12「表型横切档案」想避免的形态 —— 但**表型与「制度分页签」不可兼得**，主人选了 Q10，故采纳此代价。缓解：§8.4 的世界总览页「目录 + 跳转」+ §8.3.1 的子项同步。

### 8.3.1 🟡 保留母子的真实代价 + 两条缓解（Q14 / Q15）

**代价**：子项清单**按页签各存各**（`worldSubActive::politics` 与 `::economy` 是两份独立清单，`worldbase-sub` / `politics-sub` 也是两批独立记录）⇒ 作者要在 **N 个制度页签里各建一遍同一批政权**（例：魏 / 蜀 / 吴 × 政治 / 经济 / 宗教 / 司法 = 12 次）。且**容易对不齐**（政治里加了「大燕」，经济里忘了加）。

| # | 缓解 | 做法 | 评价 |
|---|---|---|---|
| **Q14** | **「同步子项清单」** | 以 `worldbase` 的子项清单为**基准**，提供一键「同步到本页签」（只对齐**清单**：名称 / 顺序 / 活跃态；页面内容各存各）。存储语义**零改动**、可回退 | ✅ **可可建议**：成本低、见效快，且为二期「共享清单」留了路 |
| Q15 | **子项显示名随题材** | `东方修真` →「子世界」、历史古代 →「政权 / 邦国」、武侠江湖 →「门派」…… 复用 §4.6 的 `tabDisplayName` 思路做 `subItemLabel(pack, tabId)` | ✅ 建议做：纯文案层，让「子项」在历史包下读起来就是「政权」 |
| （二期）| 跨页签**共享一份**子项清单 | 所有母子页签读同一清单、内容各存各 | ⚠️ 语义最好，但会改 `worldSets.ts` 的读法 ⇒ **影响 `worldbase`/`power` 现有数据语义**，有回归风险，**本轮不做** |

### 8.6 与「弱替」（§4.5）的重叠重画

历史古代的 `power` 弱替为「权谋实力」（官职 / 军权 / 财力 / 声望）—— 与新增的 `politics`（政治架构）**主题重叠**（都在讲权力）。重画建议：

| 包 | `power` 弱替主题（收窄为「**个人 / 集团的实力与地位**」）| 制度页签负责 |
|---|---|---|
| 历史古代 | 实力类型（官职品级 / 军功 / 财力 / 声望）· 晋升路径 | `politics` 管「制度与架构」 |
| 都市现实 | 能力体系（专业 / 人脉 / 资本 / 信息）· 地位阶梯 | `economy` 管「行业与资本」 |
| 女频言情 | 关系体系（关系类型 / 情感层级）· 话语权 | — |

即：**`power` 弱替 ＝「人 / 集团能到什么位置」；制度页签 ＝「这个世界怎么运转」**。职责一分开，重叠即消失。
