排除是作者的否定决定，与「还没看」不是一回事。修法：

- `ReferenceCard` 增 `excluded`，由 `state === 'excluded'` 置位；
- `buildReferenceBlock` 剔除并给 `reason: 'excluded'`，摘要显示「已排除 N」；

## 九、扫描器的三个真实口径修正

1. **同文件自用不再被漏算**：原先整行跳过定义行，`export function f() { return f }` 这种单行实现
   会把唯一自用一起跳过 ⇒ 活代码判死。改为「定义行只扣掉声明那一次」。
2. **三个引用桶分开**：生产 / 测试 / 工具。旧脚本把 `tests/**` 的引用也算「有人在用」，
   于是「实现完整但只有测试在调」这类（正是该接入口的信号）被系统性掩盖。
3. **测试自指污染**：断言「某符号是死的」的测试文件本身会被扫描；只要它在**字符串**里写出符号名，
   就会给该符号造出一个测试引用，断言从 `dead.export` 变成 `dead.test-only`。夹具里的符号名一律拼出来。

## 十一、如实说明的取舍

- **为什么没直接塞进 `findings`**：`findings` 的语义是「必须 dismissed 或 confirmed 才 complete」。

## 十七、删的过程中踩到的真盲点：门面再导出

`isOllamaProtocol` 按扫描结果"零引用"被删，`tsc` 当场报错——因为 `src/lib/ai.ts` 有
`export { protocolOf, WIRE_PROTOCOL_LABELS, isOllamaProtocol } from '@/lib/aiCore/protocol'`。

**根因**：`stripReexport` 把再导出清单整段吞掉（为了不让门面把死代码洗白），于是
「只被门面再导出」的符号被当成零引用。而门面再导出恰恰是**对外 API**，删掉就编译不过。

**修法**：扫描器新增第四个桶 `facadeOnly`——只出现在再导出清单里的引用单独计数。

## 二十一、项目问题：修了 1 处

| 问题 | 判据 | 修法 |
| --- | --- | --- |
| **AI 辅助把项目资料裸拼进 system prompt** | `audit-prompt` 的 P6（疑似作者原文未包裹 `promptGuard`）；打开源码确认：`sys += 【项目资料…】${ctx.text}`，而同一份资料在 `audit.ts` 里早已走 `authorBlock()` | 改为 `${authorBlock(newAuthorFence(), ctx.text)}`，并补三条断言（包了 / 在标题之下 / 空资料不包） |

为什么这是真问题：项目资料是**作者可编辑文本**（设定表、角色卡、时间线，可能从外部导入）。
裸拼会与结构标记同层 —— 资料里夹带「忽略以上指令」会被模型当指令执行；正文里常写 `【】`，
