## 三、审计连带查出的真缺陷（已修）

### 3.1 创作参考：把「已排除」当成「未审」

`referenceCardsOf` 只区分 `kept`（是否确认），作者标为 **excluded** 的成果会显示成「未审」并且**可以被勾选发送**。
排除是作者的否定决定，与「还没看」不是一回事。修法：

- `ReferenceCard` 增 `excluded`，由 `state === 'excluded'` 置位；
- `buildReferenceBlock` 剔除并给 `reason: 'excluded'`，摘要显示「已排除 N」；
- 选择器把它设为**不可勾选**并标注「已排除（不可选）」；
- `REFERENCE_KINDS` 成为「哪些类型可当参考」的唯一判据（原先 `referenceCardsOf` 里手写了一遍 kind 判断）。

### 3.2 检索评测报告两处口径错误（G 包自检）

| 问题 | 后果 | 修法 |

| `avgChars` 分母用「有标注的查询数」 | 空结果查询的 0 字被排除，平均值虚高 | 分母改为全部查询 |

新增断言：生产默认串味 0 条、旧口径确实会串（证明这道闸不是摆设）。

# 第二轮：审计工具升级（同日 22:35 起）

## 六、为什么要改工具

第一轮把六维审计跑通了，但它有个结构性缺口：**旧扫描器（11 支）产出的候选只写进 `legacy-*.log`，
从来没有进过 `report.json`**。于是报告上永远写着「静态扫描 952 文件、**0 个候选**」——
绿着，而日志里躺着 40 条零引用导出、1500 余条导出面清单。等于「代码维度」长期无人复核，
而且没人能从报告里看出来。这是本轮补的核心。

## 七、新增了什么

| 文件 | 作用 |
| --- | --- |
| `scripts/audit/source-text.mjs` | 共享文本工具：剥注释、吞再导出清单、列具名导出、定位定义行。原先这套逻辑只活在旧死代码脚本里，新老各写一份必然「一个说 32 一个说 25」 |
| `scripts/audit/dead-exports.mjs` | **结构化**死导出扫描：输出 `dead.export` / `dead.test-only` 两类 finding（带行号与符号名），并给 `used/testOnly/dead` 三个桶的统计 |
| `scripts/audit/dead-reviews.json` | 已复核结论（**按符号匹配**，不用行号：行号随编辑漂移，复核会静默失效）；理由必须写够 10 字 |

## 九、扫描器的三个真实口径修正

1. **同文件自用不再被漏算**：原先整行跳过定义行，`export function f() { return f }` 这种单行实现
   会把唯一自用一起跳过 ⇒ 活代码判死。改为「定义行只扣掉声明那一次」。
2. **三个引用桶分开**：生产 / 测试 / 工具。旧脚本把 `tests/**` 的引用也算「有人在用」，
   于是「实现完整但只有测试在调」这类（正是该接入口的信号）被系统性掩盖。
3. **测试自指污染**：断言「某符号是死的」的测试文件本身会被扫描；只要它在**字符串**里写出符号名，
   就会给该符号造出一个测试引用，断言从 `dead.export` 变成 `dead.test-only`。夹具里的符号名一律拼出来。

## 十一、如实说明的取舍

- **为什么没直接塞进 `findings`**：`findings` 的语义是「必须 dismissed 或 confirmed 才 complete」。
  把 22 条历史欠账一次性塞进去，等于升级工具就把一个本来能发版的版本判成不合格 —— 那不是补盲，
  是把账算在当前版本头上。用「可见 + 预算只降不升」既保留了压力，也不误伤。
- **835 条 test-only 不列清单**：它是「单测覆盖」的正常形态，逐条看没有决策价值；只在统计里报数。
- **仍未做的**：旧扫描器的其余候选（架构/内容/UI/提示词等）仍在 log 里，没有结构化。
  本轮只做了价值最高、也最容易误判的「死导出」。其余各支的表格式差异大，需要各自设计解析或重写，
  不与本次混在一起。
