# 3.2.3 版本大表编辑性能优化方案

> 编写日期：2026-10-24。状态：**P0 核心指标已冻结（八组夹具 × 六项指标，计量 v9）+ P2 行窗口化已落地 + P4 合流报告已出**（2026-10-25 20:00。
> 未做：P0 余项五项（项目冷启动、远端定位、A/B 交错、longbook 正文、100 行批量保存 —— 各需独立 harness）、P3 闭环回归的剩余交互项、
> 把 `--mode compare` 接进 `reliability.mjs` 的执行链（需先决定冻结基线入库位置）。证据见 [P0 冻结基线](3.2.3-P0冻结基线-2026-10-25.md) 与 [P4 合流验收](3.2.3-P4合流验收-2026-10-25.md)。）
> 版本：按用户最新更正统一为 3.2.3，与可靠性收口同版；3.2.2 为已发布基线。原有规划中的 3.3.0 性能事项以本方案划定的范围提前承接，不表示其他 3.3.0 事项全部并入。
> 目标：降低大表首次打开、输入、筛选和保存时的主线程阻塞，并保证未显示行的草稿、编辑定位、输入法和真实持久化行为正确。
> 方法：程序生成数据 → 生产构建建立基线 → 行级更新隔离 → 行虚拟化 → 自动功能与性能回归；每一步都有机器判据。
> 初始仅编写方案；2026-10-25起分阶段落地P0。当前仅新增测量工具，未改产品渲染、版本号，未封装发布。

## 1. 范围和成功定义

本轮主路径为 TableSheet 的表格编辑视图，覆盖它承载的普通表、树形表及适用的图鉴表格视图。共用 model 的关系分组、图鉴详情、时间线和关系图需要兼容回归，但不在本轮重做这些视图。

默认实施顺序：

1. P0：把可复现的大表基准和回归工具纳入仓库，先量当前生产构建。
2. P1：隔离行级草稿订阅、稳定行数据与回调，先救输入手感。
3. P2：只挂载视口附近的行，降低打开、筛选恢复、滚动和内存成本。
4. P3：完成保存、排序筛选、树形、跨页定位和输入法的闭环回归，处理实测剩余热点。
5. P4：与可靠性工作线合流，生成同一源码、同一构建对应的验收报告。

阶段门禁、夹具规模与内部阈值由实施负责人按本方案默认值推进，不逐项请求作者拍板；只有确实需要改变产品行为或引入新的外部成本时，才集中说明差异。性能实现失败优先修正实现，不能把反复调参数变成人工验收流程。

不以“组件已经拆开”“使用了 memo”“引入了虚拟列表”作为完成判据。最终必须证明：大表可编辑、操作结果正确、性能达到冻结门槛、无数据丢失。

不纳入：列虚拟化、整库增量同步、数据文件格式重写、关系图/地图重构、全面组件拆分、通用状态框架替换。主包拆分只有在测量证明阻碍本轮目标时才局部处理；不得扩大为全应用性能重构。

## 2. 当前代码和历史证据

### 2.1 已核实的结构

| 代码位置 | 当前行为 | 优化切入点 |
|---|---|---|
| src/components/sheets/TableSheet.tsx | bodyRows.map 挂载全部行；每行收到整份 model，部分回调内联 | 行数据/动作解耦；只挂载可见行 |
| src/components/sheets/TableSheetRow.tsx | 普通函数组件，读取 model 中多项可变状态 | 订阅本行；共享配置稳定；避免依赖整个草稿对象 |
| src/components/sheets/useTableSheetModel.ts | drafts 集中在顶层；修改一格触发 model 更新 | 按项目/页签作用域建立行级草稿容器 |
| 同文件 sortedRows | 每次草稿变化为所有行重新创建 row/data 对象并排序 | 稳定未变行引用；按受影响字段决定派生失效 |
| 同文件 saveAll | 逐脏行落库，成功后合并 rows、清 drafts | 保存快照与编辑版本分开，不能清掉保存期间新输入 |
| 同文件 focusRowId effect | 直接从 rowRefs 找 DOM 后滚动 | 虚拟化后先按行 id 定位索引，再挂载并聚焦 |
| tableSheetShared.tsx | textarea 测高已有同帧批处理，上限约 78px | 保留批处理，并与虚拟行高度测量协作 |

仅给 TableSheetRow 加 memo 不足：如果 model、行对象、派生 entry 和回调每次全部变引用，未修改行仍会重新渲染。

### 2.2 历史测量：只作线索

2026-10-21 的 1000 条、60 个自定义字段压测实际有 75 个业务列、约 76,000 个单元格：

| 指标 | 历史测量 |
|---|---|
| 全表打开 | 17,432ms |
| 输入一个字符 | 3,195ms |
| 单次修改后保存并落盘 | 25,519ms |
| 清空筛选恢复全表 | 13,980ms |
| DOM 节点 | 235,754 |
| 全表读取 | 21ms |

这些是开发服务、特定浏览器与机器上的旧数值，不能直接当本轮生产构建基线，也不能据此承诺固定倍数提升。

已有 tests/perfBaseline.test.ts 主要使用内存存储桩，证明算法开销；保留它，但本轮另建浏览器+真实存储压测。500 章正文列表的历史可用结论与大表性能分开管理，不混为一项。

## 3. 自动化优先的执行方式

### 3.1 共用基础设施

复用[可靠性方案](3.2.3-可靠性收口方案-2026-10-24.md)中的环境预检、隔离目录、端口管理、进程生命周期、证据 schema、构建清单与状态规则。性能套件只增加数据生成、计时、渲染统计和行为断言，不另造一套通用执行器。

入口 scripts/verify/table-performance.mjs 已实现打开/输入/单行保存的首批测量；支持游客与便携后端，当前正式证据仅游客 small/medium。完整边界见 [P0首批报告](3.2.3-P0大表生产基线-2026-10-25.md)，接口如下：

~~~powershell
# 自动造数、检查并测量当前版本，输出报告；不覆盖已有基线
node scripts/verify/table-performance.mjs --mode measure --profile local

# 与指定的已冻结基线比较；输入不兼容时阻塞
node scripts/verify/table-performance.mjs --mode compare --baseline <baseline.json> --profile local

# 开发时缩小样本反馈；不能替代完整验收
node scripts/verify/table-performance.mjs --mode smoke --fixture medium
~~~

若可靠性执行器已有当次匹配构建，传入同一 build manifest 复用，避免重复编译。需要新构建时只写入新的临时目录，不覆盖 dist 或 release。

### 3.2 自动选择运行范围

| 改动 | 默认自动运行 |
|---|---|
| 草稿、排序筛选、保存等纯逻辑 | 定向单测 + 中等表交互 smoke |
| TableSheet / 行组件 / 测高 / 滚动 | 上述项目 + 全尺寸表浏览器交互 + 虚拟窗口结构断言 |
| 列宽、主题、缩放、表格 CSS | 断点/主题/缩放布局 + 表头与正文对齐 |
| db/文件后端/项目切换 | 可靠性保存矩阵 + 四配置持久化回归 |
| 合流验收 | 全量门禁 + 完整功能/性能套件 + 当前构建证据汇总 |

依赖图判断不确定时扩大测试范围，不静默跳过。最终合流必须完整执行，不能只依赖按变更选测。未配置 CI 时先提供本地命令，不以缺托管 CI 为开工阻塞。

## 4. P0：基准数据与测量纪律

### 4.1 程序生成的数据集

新增可入库的生成器 scripts/verify/fixtures/table-fixtures.mjs，固定 seed、固定 id 和配置 schema。大数据文件只在本次 run 目录生成，不把压测书库、真实正文或截图批量提交入库。

| 样本 | 规模 | 内容与用途 |
|---|---|---|
| small | 30 行、常用列 | 小表无退化、空表、少量筛选的快速 smoke |
| medium | 300 行、60 自定义字段 | 编辑/筛选/保存和阶段门禁 |
| large | 1000 行、60 自定义字段 | 本轮主要性能门槛 |
| tree | 1000 行、至少 4 层树 | 展开/折叠、父子编号、定位及筛选 |
| mixed | 文本、长文本、数字、布尔、单选、多选、日期等 | 类型编辑、校验、导入导出和行高变化 |
| project-switch | A/B 两项目含相同 tabId 和不同内容 | 草稿、缓存与异步写入隔离 |
| longbook | 500 章、百万字符、200 载荷 | 检查本轮没有拖慢正文编辑与项目切换 |

生成器从当前 schema 与自定义字段解析入口取得列定义，不把“75 列”写死；报告记录本轮实际行数、列数、数据字节数、seed 与完整内容哈希。tree/mixed 可复用 large 的数据底座，避免重复维护。

### 4.2 测量环境

- 主要门槛在同一参考机、相同 Chromium/Electron 版本、相同窗口和缩放、相同生产构建模式下比较。
- 不用开发服务耗时与生产构建耗时算提升倍数；旧文档数字只在“历史参考”列展示。
- 每次记录 OS、CPU/内存、浏览器版本、是否 headless、GPU模式、设备比例、缩放、产物哈希和存储配置。
- 在相同机器连续完成前后版本测量；基线可从明确指定的旧源码/产物建立，不能自动切换或重置当前工作区。
- 套件检查基线版本、夹具、测量实现和环境是否兼容。测量实现变更后先对前后版本重新建立可比结果，不能延用不同口径的旧数。
- 性能探针独占运行队列，不与全量测试、其他浏览器压测、构建并发；不能通过多试几次只挑最快结果。
- 默认无 CPU 节流；可增加固定节流作为压力观察，但不把它与主门槛混合。实际公网延迟另列观察，不作为渲染改造结论。

### 4.3 指标定义与采样

| 指标 | 起止点 | 自动证明方式 |
|---|---|---|
| 打开可编辑 | 点击目标表 → 首屏字段可见、可操作且夹具首末标识正确 | 实际用户点击、首屏输入探针、两帧稳定；不等全部行进入 DOM |
| 冷打开 | 全新浏览器上下文、已准备数据后首次进入项目/表 | 项目启动与表打开分别计时，不把造数算打开 |
| 热打开 | 已初始化应用，切离再回表 | 单独列出，不冒充冷启动 |
| 输入到绘制 | 自动键入 → 对应值提交并完成绘制 | 真实输入事件、值断言、两帧采样；支持时附 Event Timing |
| 保存确认 | 点击保存 → 实际持久化回读匹配本次快照 | IDB 新事务/独立文件或 HTTP 读回；不能靠“已保存”文字 |
| 筛选/清筛选 | 输入筛选条件 → 正确结果且首屏可交互 | 对完整数据的预期 id 集合与计数核对 |
| 定位 | 发出目标 rowId 导航 → 目标挂载、滚动到位、高亮 | 目标 id 与可视范围断言，不能以 DOM 不存在就忽略 |
| 滚动 | 固定距离、固定次数滚动 → 可见区更新 | 记录帧间隔/长任务、空白帧和行 id 连续性 |
| 资源 | 稳定打开、反复操作前后 | DOM/已挂载行数；支持时附 JS heap；工具不支持的指标标未测 |

打开与切换至少 5 次独立样本，报告中位数与最差值；输入至少 30 次独立事件，保存至少 10 次，报告 P50/P95/最大值。分位数算法、样本量和预热规则写入结果。

固定 1 次预热，不计热操作结果；冷操作不预热。功能失败时本轮性能标无效，不能因渲染少了数据而获得“更快”。必要的超时轮次也计入结果，不能剔除。

### 4.4 建议门槛与冻结规则

下表是本轮建议验收目标，尚未实测达成。P0 先量生产基线并核对参考环境可行性；需要调整时在动优化代码前一次性写明原因和新值，后续执行器不得自行放宽。

| 指标 | medium | large | 适用说明 |
|---|---|---|---|
| 热打开中位数 / 最差 | ≤1s / ≤2s | ≤2s / ≤3s | 点击进入表到可编辑，不是全应用启动 |
| 输入到绘制 P95 | ≤100ms | ≤120ms | 普通可见文本格；保留原筛选/排序语义 |
| 单行保存确认 P95 | ≤1s | ≤1.5s | 真实 IDB/本地文件，路径不同分开记录 |
| 清筛选中位数 / 最差 | ≤1s / ≤2s | ≤1.5s / ≤2.5s | 恢复的是完整逻辑数据，DOM 仍按窗口挂载 |
| 随机远端行定位中位数 / 最差 | ≤0.5s / ≤1s | ≤0.8s / ≤1.5s | 无筛选排除目标时 |
| 连续滚动 P95 帧间隔 | ≤33ms | ≤33ms | 固定环境采样；单次最长停顿同时报告 |
| 挂载业务行数 | 随视口有上限 | 随视口有上限 | 见虚拟窗口预算；不随 1000 行全部增长 |

100 行脏数据批量保存另设压力观察；P0 量出真实后端耗时后冻结该项门槛，不凭空承诺 IO 加速。应用冷启动、小表和 longbook 不得出现超过 max(基线20%, 100ms) 的中位数回退；超线按固定规则独立复测一次，两次与原因都保留，仍超线阻断验收。

绝对时间门槛用于相容参考环境；其他机器只给功能和结构门禁结论，计时另报，不因机器未知而自动判性能通过。无稳定参考机则性能验收为 blocked。

## 5. P1：行级数据与草稿更新隔离

### 5.1 作用域与订阅

建议在 sheets 域内新增轻量草稿容器，由表 model 持有；可用 React 现有 useSyncExternalStore，不默认引入新状态管理依赖。

- 容器键绑定 projectId + tabId，实例在该作用域内创建；销毁时清订阅。禁止无项目键的全局共享缓存。
- 基础行按 rowId 建索引；草稿按 rowId/fieldKey 存储，带递增编辑版本。
- getSnapshot 对未变行返回同一引用；只有该行、必要工具栏摘要及确实依赖改动字段的派生视图收到通知。
- 稳定 actions 不捕获过期 rows/drafts；保存、删除、导入、AI 填写读同一个权威数据源。
- 撤销/恢复、图鉴详情编辑、批量导入、日历联动都通过统一动作，不保留一份新 store 加一份旧 drafts 的双真源。
- 开发统计钩子仅在测试构建启用，不把全量行内容或调试 API 暴露到正常产品。

### 5.2 行视图与派生数据

TableSheetRow 接收稳定的 rowId、行级快照、结构信息和必要共享配置；不再接收整份高频变化的 model。未变 entry 保持引用，内联逐行函数改为稳定动作或 id 参数。

排序、过滤和树形保持当前业务规则；优化的是失效范围：

1. 普通非排序/筛选/分组依赖字段变化，不重建全表行对象。
2. 受影响字段变化才重算相关排序/筛选/树；允许对 1000 行做一次有界纯计算，不为追求“绝不全表计算”引入复杂且不可验证的缓存。
3. 现有排序可能依赖编号与编辑时间，必须显式列入依赖，不能只看用户当前编辑列。
4. 导出使用全量排序后且合并草稿的数据，与可见窗口无关；编号冲突检测也不能只查已挂载行。
5. 活动筛选字段改变后仍按原逻辑更新结果。组合输入期间先保留编辑单元格与草稿，结束后原子提交视图变化，避免中文未上屏行就被卸载。

### 5.3 保存期间继续编辑

保存开始时捕获不可变的脏单元格快照及版本。成功回写后只清除“当前值/版本仍与保存快照一致”的草稿；晚到的旧回执不能覆盖或清空新输入。

部分行成功、部分失败时：成功基值与失败草稿分开记录；失败行保留可重试状态；工具栏不显示整表已成功。保持各后端现有持久化确认语义，不能为了性能把内存入队当落盘完成。

切项目、切页签、卸载时捕获原作用域的 projectId/tabId，不在延迟回调中重新读取“当前项目”作为目标。刷新/关闭仍走现有草稿冲刷与失败保护；如果组件清理不能等待持久化，就复用已有退出保护，不能声称卸载时 fire-and-forget 已保证保存。

### 5.4 阶段自动验收

- 大表中编辑一个不影响排序的普通格，测试构建验证未改行不会整批重新渲染；不能仅用源码正则判断 memo 存在。
- 设置无关元数据/工具栏保存状态时，稳定行不重新创建全套输入控件。
- 自动交错“保存开始→继续输入→旧保存完成→再次保存”，最终重启回读等于最新值。
- A/B 同 tabId 交替编辑、异常保存、刷新恢复均不串数据。
- 此阶段即使尚未虚拟化，也要单独留输入/保存测量，证明收益来自行隔离而非少渲染了数据。

## 6. P2：变高行虚拟化

### 6.1 默认技术路线

优先保持原生 table、sticky 表头、列宽和行操作，新增行窗口计算与测高 hook。不在本轮改成 canvas，不做列虚拟化，不改变文件格式。

先实现小型验证：变高 tr、上下占位行、表头对齐、缩放与光标稳定。通过后再接普通表与树形表；若原生表布局无法满足既有行为，记录失败证据并调整实现，不能先大面积替换再依赖人工找问题。

- 默认虚拟化启用阈值为过滤/树展开后业务行数 ≥100，测试覆盖 99/100/101 行；阈值作为内部配置，不给作者新增设置负担。
- 以 bodyRows 的完整逻辑顺序作为行源。可见区之外用占位高度保留滚动范围，不把数据切片当成真实总记录。
- 行 key 为 rowId，不能使用窗口内索引。行号采用完整逻辑索引。
- 初始估高后由 ResizeObserver 或等价批处理收敛；列宽、内容、主题字体、缩放变化使高度缓存按条件失效。
- 缓存作用域至少包括项目、页签、行与影响高度的配置代次；清理被删除行和旧作用域，避免内存无限增长。
- 同一帧批量读写，保留现有 textarea 测高优化，不恢复逐格读写交错的布局抖动。
- 保持滚动锚点，测高修正不能导致输入中跳屏或滚动反复震荡。

### 6.2 窗口与焦点预算

overscan 初始取上下各 8 行。已挂载业务行上限为“按最小行高计算的视口容量 + 16 个 overscan + 至多 1 个活动编辑行”，报告记录实际预算与最大值。

必要时保留活动编辑行，使滚动不会丢失 IME、光标或原生下拉状态；保留的是同一 rowId 的真实实例，不能复制一个隐藏编辑器造成两份草稿。若活动行远离视口，使用分段占位区间保持原行位置；同一行全页最多一个编辑实例。

组合输入结束后可按策略释放保留行。失焦或用户明确切换筛选/排序时，先完成当前编辑到权威草稿源，再按原逻辑更新视图。不要因为优化而新增必须手点“完成编辑”才能滚动的流程。

### 6.3 跨页定位与其他视图

定位链路改为 rowId → 完整逻辑索引 → scrollToIndex → 等待目标测高/挂载 → 聚焦/高亮。目标挂载成功后才消费导航事件；有界重试后失败必须给出原因。

默认规则：显式跨页定位可展开目标祖先；不静默清除作者筛选。被筛选排除则说明目标当前隐藏并提供清筛选后定位动作，不把没找到 DOM 当作导航成功。删除/不存在的 rowId 明确报告。

关系分组、图鉴详情与其他视图继续读全量逻辑数据和同一草稿源；它们的局部展开不共享虚拟表 DOM 假设。若某复杂视图暂未虚拟化，报告明确范围，不给它套用普通表的性能结论。

### 6.4 必须自动覆盖的交互

| 交互 | 自动断言 |
|---|---|
| 首屏/中部/末尾/快速往返滚动 | 行顺序连续，无长期空白、重复 rowId 或幽灵输入框 |
| 高度变化 | 多行文本、列宽拖拽、字号缩放后不遮挡、不跳屏，表头仍对齐 |
| 未保存行离开视口 | 滚回后值、dirty 状态正确；保存后独立回读一致 |
| IME/选区/光标 | 组合态不丢字；结束后唯一提交；滚动和排序不重复写入 |
| 树形折叠/展开 | 节点深度、编号和后代集合正确，不把占位行当子节点 |
| 筛选/清筛选 | 针对全部逻辑数据；过滤隐藏的草稿不丢失 |
| 远端定位 | 能定位第 500/1000 行；高亮正确目标，重复定位也生效 |
| 新增/删行/批量导入 | 窗口和总高度正确；编号校验覆盖隐藏行 |
| 导出与恢复 | 导出全量数据及应包含的草稿，不是仅导出当前屏幕 |
| 拖拽平移与列宽 | 输入/选择操作不触发误平移；表头、正文和横向滚动一致 |

## 7. P3：功能正确性与真实存储矩阵

### 7.1 无人工对照的判断方法

每个数据集同时生成预期答案：完整行 id 顺序、筛选命中集合、父子树、修改后记录哈希、导入导出往返结果。对简单基础规则使用独立参考实现或固定小例子验证生成器，不能让预期答案直接复用待优化函数，从而把同一错误复制两次。

保留优化前行为的黄金样本，但对“保存期间清掉新草稿”等已知错误不冻结为期望。缺陷修复写清预期的新行为及负面对照。

程序化操作序列包含固定种子的随机编辑/滚动/保存/切换，每次失败记录 seed 与最短可复现步骤；固定关键用例始终执行，随机测试只是补充。

### 7.2 覆盖范围

| 套件 | 配置 | 数据/操作 |
|---|---|---|
| 纯逻辑 | 内存夹具 | 草稿版本、快照确认、排序/筛选、窗口区间、高度缓存、树 |
| 浏览器功能 | web-guest 独立 IDB | 全部表格交互、刷新、失效场景 |
| 本地持久化 | portable 真实服务 | 单/多行保存、响应丢失、重启读回、导出往返 |
| Electron | 隔离 userData/appData | 文件确认、退出冲刷、缩放、跨页签/项目 |
| 云端协议 | 本地真实 server/临时账号 | 权限/配额/会话替换后保留草稿，账号隔离 |
| 性能主测 | 固定参考浏览器的 IDB 与本地文件后端 | medium/large/tree；各后端结果单列 |

每种配置先运行确定性的关键功能场景；完整计时集中在固定参考环境，减少重复测量成本。web-cloud 的本地协议验证不代表公网性能或真实双设备通过。

功能红线：不丢输入、不串项目、不丢离屏草稿、不导出半张表、不跳过隐藏行校验、不改变稳定编号/存储键、不把保存入队当成功。

虚拟行不在 DOM 的行为差异必须同时适配测试：截图和计时不能再等待“1000 行全部挂载”；但预期数据量仍从完整逻辑集合和独立存储回读核对。仅把旧探针的行数断言删掉，不算完成适配。

## 8. 性能门禁与证据

### 8.1 机器可读报告

输出与可靠性方案相同的基础字段，并增加：fixtureHash、environmentHash、measurementVersion、baselineId、metricsSamples、thresholds、relativeChanges、mountedRowBudget、featureFlags。

报告需提供：

- 每项原始样本与统计值、超线项、无法比较项、功能前置结果；
- 前后版本的相同视角截图，以及出现遮挡/空白时的 trace；
- 每组构建哈希、执行器/夹具哈希和后端说明；
- 重跑命令；失败时的 seed、目标行/字段 id，不记录真实稿件。

门禁顺序为功能正确性 → 窗口结构预算 → 绝对性能目标 → 同环境回归比较。计时快但功能不对仍失败。未取得 JS heap 不自动失败核心套件，但不能声称内存优化已验证；若将内存列为最终必需指标，就必须先配齐测量环境。

### 8.2 实施阶段验收

| 阶段 | 必需交付 | 通过条件 |
|---|---|---|
| P0 基线 | 生成器、生产基准、环境/阈值清单、结果 schema | 当前版本可重复跑；功能前置正确；基线不可被 compare 覆盖 |
| P1 行隔离 | 草稿容器、稳定引用、保存版本确认、定向测试 | 无整表输入重渲染；交错保存不清新输入；性能单列留证 |
| P2 虚拟化 | 变高窗口、定位适配、缓存清理、交互探针 | 行挂载预算达标；离屏编辑、IME、定位全部正确 |
| P3 收尾 | 全功能矩阵、热点修复、完整比较 | 冻结目标通过；小表与 longbook 无不可解释退化 |
| P4 合流 | 同版源码与构建、可靠性+性能总报告 | 两条工作线门禁通过；证据指纹相容；缺项不冒充通过 |

新增单测归入 tests/run-batches.sh 唯一清单；tsc、eslint src tests、全量测试必须通过。运行套件后确认进程退出、工作区没有混入夹具/构建/截图。

## 9. 回退、风险与自动停止条件

### 9.1 分阶段回退

- 行隔离与虚拟化拆成独立改动单元，P1 可在 P2 尚未通过时保留。
- 设置内部虚拟化开关用于对照和定位，不增加作者操作步骤；关闭只切回渲染路径，不改变数据结构。
- 禁止“捕获所有渲染异常后自动换旧视图并报通过”。发生回退记录原因，虚拟化目标仍判未完成。
- 数据存储格式不变，避免依靠数据迁移才能回退；不会通过清草稿或重置书库恢复界面。

### 9.2 风险与对应自动检查

| 风险 | 自动防线 |
|---|---|
| memo 遮住陈旧闭包 | 修改后排序、删除、保存、AI 回填都读取最新值；反向变更也测试 |
| 新旧草稿双真源 | 同字段从表格/详情/批量入口交替修改，比较单一快照 |
| 保存回执覆盖新输入 | 受控屏障交错保存，校验版本而非时间猜测 |
| 变高测量循环 | 统计 ResizeObserver/布局次数，超过预算失败；录制跳屏 |
| 项目缓存串用/泄漏 | A/B 循环切换与挂载/卸载，统计订阅和缓存数量回落 |
| 虚拟化只让“看见的部分”正确 | 全量导出/校验、远端行随机编辑、重启回读 |
| 测试自己失效 | 夹具数量、实际操作次数、样本量和故意破坏的负面对照检查 |

出现丢稿、串项目、保存误报、无法完成中文输入时停止性能推广，先修正确性。出现环境不相容、无基线或低样本量时标 blocked，不随意改性能阈值。

## 10. 人工介入压缩方案

| 项目 | 默认自动处理 | 仍可能需要的一次性介入 |
|---|---|---|
| 数据准备 | 固定种子生成、写入隔离后端、校验数量与哈希 | 无需作者提供真实大表 |
| 基线/阈值 | 生产构建测量、原始分布、自动比较 | P0 若证明建议门槛不适用，由实施负责人一次性冻结修订；不逐轮调阈值 |
| 正确性 | 预期 id/顺序/哈希、黄金样本、负面对照 | 无需人工逐行检查 1000 条数据 |
| 视觉 | 溢出、遮挡、列对齐、行高、焦点与截图差异检查 | 只审阅超阈值且工具无法判定的差异，不要求每轮翻全量截图 |
| 输入法 | 自动回放组合态、粘贴、撤销、光标事件 | 真实微软/搜狗输入的少量 smoke 与可靠性工作线合并一次 |
| 真机和原生环境 | 有环境后自动执行同一套场景 | 缺设备/驱动时保留边界，不要求作者重复造数操作 |
| 结论整理 | 自动生成 Markdown/JSON/失败清单 | 实施负责人只处理阻塞和产品失败 |

不把“文学质量人工评审”加入大表优化的依赖，也不要求作者为性能验收手工建立或整理书库。默认功能与性能结果应由同一条流水线得出。

## 11. 与可靠性方案的合流约定

1. 两份方案都是 3.2.3 的工作线，最终只做一次版本一致性检查和一套发布候选产物，避免各自重打包。
2. 优先完成可靠性 R0 公共执行器和 R2 保存契约；大表 P0 可独立用旧实现建基线，P1 必须复用已定义的保存与错误口径。
3. 校对协议改动与表格重构尽量分文件提交；共享 db/退出保存改动先收敛后合流，不同时维护两份实现。
4. 修改 src/electron/server/构建或测试工具后按各套件范围刷新证据。开发期可复用未受影响的匹配构建，最终合流必须在同一 HEAD/工作树内容上重采。
5. 最终报告分别给出可靠性、功能正确性、性能、包验收、真实设备边界；不会以“全量单测通过”替代后四项。
