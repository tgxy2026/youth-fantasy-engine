**统一手法**（沿用 2.2.1 已验证的那套）：

1. **先量化再下刀** —— 用 `.workbuddy/tmp/jsx-deps.mjs` 算出「JSX 段真正用到哪些组件作用域里的名字」，
   那就是 hook 必须 `return` 的名单；剩下的是内部私有，**不 return**（避免 API 面虚胖）。
2. **纯搬家** —— 语句一字不改；只有三处机械动作：加 import 头、加 export、改签名行。
3. **同名解构** —— 视图侧 `const { … } = useXxxModel()` 写在组件开头，**JSX 一个字都不用动**。
   这把「搬家」和「改造」彻底分开：出问题一定是搬错了，不会是顺手改坏了。
4. **锚点校验 + 可重复执行** —— 切分脚本落盘前先验一批锚点（原文件的确切行文，D4-1 用 14 条、
   D4-2 用 99 条），任一不符立即退出；脚本**输入固定读备份原件**，绝不读回自己写的产物，
   否则跑完一次脚本就废了（想再跑得先手工还原）。落盘后还要做一次**逐行区间核对**：
   每个搬运区间逐行在目标文件里按序找得到，才算「一个字没改」。
5. **实机指纹** —— 拆前存 `--label=xx-before`，拆后 `--expect=xx-before` 逐项比对结构计数。
6. **负面对照** —— 注入真故障证明断言有牙齿，然后**自动还原并校验字节一致**。

### 2. 🔴 本项最值钱的一条：`exhaustive-deps` 为什么突然开始报警

拆完第一版后 eslint 从 **0 problem 变成 5 条 `exhaustive-deps` 警告**，全是「缺依赖」。
逐条追下去才发现机制（已用最小探针实测复现）：

> `react-hooks/exhaustive-deps` 判定「稳定量」靠的是**能不能看见 `useRef()` 那个初始化**。
> · 本地 `useRef` → 认定稳定，不进依赖数组（原 1,132 行文件因此一条都不报）；
> · 一旦把 ref 变成 **hook 入参** → 无从证明，于是如实报警。
> 连 `ghostBefore` 被报也是**连带**的：它只读 `draftRef`，而 `draftRef` 变入参后规则无法证明其稳定，
> 递归判定就跟着失效了。

**处置原则：不压制、不盲加**（工程红线：`exhaustive-deps` 别盲改）：
- 本来就是稳定量的（ref / `setState` setter）→ 如实补进依赖数组，恒等值、零行为变化；
- 两个「函数体只读 ref 与常量」的普通函数 `ghostBefore` / `syncHighlightScroll` → 改 `useCallback`，
  依赖为空也不会陈旧，于是可以如实列进依赖数组。

结果：eslint 回到 **0 problem**，且**没有新增任何一处 `eslint --disable`**。
（全项只有这两处「不只搬」，已在提交信息里单列。）

### 7. 顺带修掉的脚本 bug（与本次拆分无关，但会污染所有实机结论）

`ui-refactor-check.mjs` 在**播完种后 `page.reload()`** —— 启动默认停「项目管理首页」，
reload 会把刚打开的项目踢回首页，之后每个页签都找不到：实测 **全程 0 通过、`aside=0`、`main` 都不存在**。
这正是 D4-1 在 `ui-novel-editor.mjs` 踩过的同款坑（那次删了 reload），本脚本还留着。
处置：删掉 reload（种的数据由各页签 mount 时经 db 现读，不需要刷新），
并把「进项目」抽成 `openProject()` 带重试 + 显式断言，不再让点击失败被 `.catch()` 静默吞掉。
