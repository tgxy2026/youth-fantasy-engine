**统一手法**（沿用 2.2.1 已验证的那套）：

1. **先量化再下刀** —— 用 `.workbuddy/tmp/jsx-deps.mjs` 算出「JSX 段真正用到哪些组件作用域里的名字」，
   那就是 hook 必须 `return` 的名单；剩下的是内部私有，**不 return**（避免 API 面虚胖）。
2. **纯搬家** —— 语句一字不改；只有三处机械动作：加 import 头、加 export、改签名行。
3. **同名解构** —— 视图侧 `const { … } = useXxxModel()` 写在组件开头，**JSX 一个字都不用动**。
   这把「搬家」和「改造」彻底分开：出问题一定是搬错了，不会是顺手改坏了。
4. **锚点校验** —— 切分脚本落盘前先验 14 个锚点（原文件的确切行文），任一不符立即退出，防切错。
5. **实机指纹** —— 拆前存 `--label=xx-before`，拆后 `--expect=xx-before` 逐项比对结构计数。
6. **负面对照** —— 注入真故障证明断言有牙齿，然后**自动还原并校验字节一致**。

### 2. 工具的两个盲区（当场被编译器抓出来）

| 症状 | 真因 | 修法 |
|---|---|---|
| 落盘后 `TS6133: 'fs' is declared but its value is never read` | JSX 里 `const fs = Math.max(11, 16 - depth * 2)`（字号）是 map 回调的**局部变量**，遮住了外层 `fs` state。量化工具按「文本出现即算用到」把它列进了 return 名单 | 从名单删掉；**在脚本里写明这条教训** —— 量化工具必须能被 tsc 复核 |
| `TS2304: Cannot find name 'Marker' / 'Linked' / 'LAYER_COLORS'` | 这三者在原文件是**文件顶层声明**（不是 import），`importsFor()` 只从原 import 语句里挑 → 漏了 | `GeoMapParts.tsx` 手工补一行 `import { LAYER_COLORS, type Marker, type Linked } from './geoMapGeometry'` |

### 5. 🔴 顺带修掉一个真 bug：实机脚本的「哑报警」

第二条对照第一次跑时**没报警**（退出码 0），追下去发现是脚本尾巴的老写法：

```js
process.exitCode = failed.length ? 1 : 0     // ❌ 把上面 --expect 设的 3 覆盖成 0
```

后果：**「与基准指纹不一致」这个报警是哑的** —— 差异会打印，但退出码仍是成功，
交给自动化跑就会静默漏过。第 3–5 条对照之所以没暴露，是因为那个注入恰好也命中了 FAIL 断言（退出码 1）。

已改为 `if (process.exitCode === undefined) …`（后来几支脚本早已是这样，只有 `ui-refactor-check.mjs` 和照抄它的 `ui-geo-map.mjs` 是旧写法），**两个文件都修了**。

### 6. 另一条环境坑（写进脚本头注释了）

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'playwright-core'
    imported from …\skills\novel-studio-ui-livecheck\assets\ui-geo-map.mjs
```

ESM 的裸模块解析是从**脚本所在目录**向上找 `node_modules`，**与 cwd 无关** ——
所以脚本必须 `cp` 进 `…\binaries\node\workspace\` 再跑，光 `cd` 过去没用。
（既有注释写的是"必须在 workspace 目录里跑"，不准确，已修正。）
