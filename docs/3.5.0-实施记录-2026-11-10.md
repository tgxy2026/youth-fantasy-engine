## 一、与规划的复核差异（先核实再写）

| 规划假设 | 源码实况 | 处理 |
|---|---|---|
| 已有 invite/open/closed 注册，默认邀请码 | `server/lib/config.mjs` 默认 `invite`；注册页有邀请码必填 | 默认改为 `open`；invite/closed 仍可显式启用 |
| 账号含配额/角色 | `users.mjs` 有 `quotaBytes` / `role` / `invite`，`role` 未被任何路由使用 | 新增 `cloudSync` 资格字段与角色判定 |
| 「配额≈同步资格」 | 配额只做容量限制；`/api/data`、`/api/blob`、`/api/v2/*` 只判登录 | **新增服务端 `cloudSync` 闸**；社区接口不要求该资格 |
| `dailyStats` 可当排行数据 | 不含标点、且 `Math.max(0, …)` 截断负数 | 新建独立含标点有符号账本（`settingsKV`），不改看板语义 |
| 「草稿」状态 | 服务端无草稿概念 | 双层：本地草稿（按账号+设备）+ 服务端 `draft` 状态 |
| 双端同一前端产物 | 网页云端注入 `__YFE_PORTABLE__` 走 `/api/data`；游客走 IndexedDB | 社区组件同一份，通道复用 `cloudBase/cloudFetch` |
| 无社区/昵称/排行代码 | 全库确认不存在 | 从零实现 |

## 二、本轮交付

### 关键口径（写进代码注释，避免下轮被"优化"掉）

1. **匿名**：公开载荷只有 `displayName`（昵称或「匿名用户」）与 `byAuthor` 布尔；无 uid、无登录名、无稳定关联标识。
2. **版本绑定**：决定必须携带 `versionId`；不匹配返回 `409 STALE_VERSION`；撤回/下架后迟到回执不得恢复公开。
3. **编辑已发布**：提交后生成新版本待审，**旧版本继续展示**；拒绝/要求修改后仍回到「已发布」，不整体下线。
4. **评论分流**：仅「检查完成 + 零命中」直接可见；规则命中、不确定、异常一律待审。
5. **排行**：含标点净增量；周/月先累加有符号日增减；展示最低 0；撤回立即删数据；重新开启不恢复旧数据。

## 五、需要主人决策（影响用户数据/产品行为）

1. **无邀请码用户的找回方式**：首期注册不要邀请码，但现有找回**只认邀请码**。可选：
   - A. 保留邀请码找回 + 允许运营人工核验重置（低成本，但依赖人工）；
   - B. 引入邮箱验证（需邮件服务商、成本、反滥用）；
   - C. 引入手机号验证（触达率高，但涉及实名/运营商合规）。
   在选定前，开放注册用户的找回能力是**不完整**的，建议注册页明确提示。
2. **存量账号 `cloudSync` 迁移**：现在「缺字段=已授予」，新注册=未授予。若要收紧存量，需要盘点与灰度方案（会直接影响老用户能否继续同步）。
3. **评论自动放行的风险阈值**：当前规则较保守（联系方式/风险词/重复即待审）。若希望更宽松，需要给出可接受的误放行范围。
4. **申诉工单**是否要独立实现（含时限、状态、复核人），还是先走既有反馈渠道。
