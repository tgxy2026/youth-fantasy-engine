# 3.2.0 发布说明（对外文案底稿 + 数据格式与 AI 数据来源）

> 用途：发布条件 6 要求的「功能清单 / AI 数据来源说明 / 提示词登记 / 数据格式说明 / 更新日志」。  
> 🔴 本文件是**底稿**：README、Gitee/GitHub Release 正文从这里取，改完记得同步回 README。  
> 🔴 只写**已实测**的能力；未实机的一律标「待验证」，不写成已交付。

## 一、本版主题：修订与核对

3.2.0 不新增页签。它解决一件事：**AI 改稿靠不靠得住**——让作者能看见 AI 产出、能决定要不要、改完能核对结果。

## 二、作者可见变化（功能清单）

| 能力           | 入口                                   | 说什么                                                                                                                |
| ------------ | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| **候选审阅**     | 创作轨迹 → 候选审阅                          | AI 产出的稿子先放这里，你决定应用还是放弃。**应用前会比对正文**：你改过就拒绝，不覆盖你的编辑。整章改写的产出也会登记到这里（关掉页面仍能找回）；你在创意写作页点「替换」或「丢弃」，这里的候选会同步变「已应用 / 已放弃」 |
| **改后复检**     | 检查工具 → 工单每章标题旁                       | 改完自动用五个本地引擎复检：`原问题已清` / `N 条没解决` / `复检没跑成`。**「已改写」只代表改过了**                                                         |
| **检查报告留档**   | 创作轨迹 → 检查报告                          | 只有查到「冲突/注意」级才留档（全绿不占空间）；每条带来源、章名、引文与「引文 N/M 可定位」                                                                   |
| **证据快照**     | 同上                                   | 落库那一刻就把引文与段号记下来，回答"当时到底有没有证据"，而不是"现在还能不能定位"                                                                        |
| **诊断状态如实**   | 检查工具 → 生成工单                          | 显示「已检 X/Y 章 · 发现 N 个 · 留档 N 份」；**没检成的章会点名列出**，不再报成"诊断完成、没有问题"                                                      |
| **实体保留自检**   | 工单每章标题旁 / 候选审阅                       | 改写后哪些已登记人物/势力名没再出现。**只提示不判定**——少提一个名字常常是正常润色                                                                       |
| **结构化输出**    | 模型设置                                 | 确认端点支持后可声明，JSON 类任务更稳；**默认关**，不确定就别开（开了才发 `response_format`/`format`）                                              |
| **请求预算**     | 后台自动                                 | 整章改写 6 次封顶、一次性任务 3 次封顶；撞顶会停并如实说，不在后台空烧额度                                                                           |
| **停滞不吞内容**   | 后台自动                                 | 流式停滞时把已收到的片段带出来，并如实报「已收到 N 字未采用」；**半截正文不整章落库**（覆盖一半比不落更糟）                                                          |
| **图片可拖拽上传**  | 头像 / 项目封面 / 图鉴主图 / 地图底图 / 看板娘 / 人物立绘 | 图片直接拖到那块区域即上传（原先只能点按钮弹选择框）。与点选走**同一条**压缩与落库通路；拖错东西会明说原因（不是图片 / 拖的是文件夹 / 是空文件）。拖到空白处不会把页面顶掉                         |
| **图鉴三种排序**   | 图鉴视图右上角                              | 按编号 / 按名称 / 按最近编辑。**只改这一屏排列，不写库**；想真改顺序仍改「编号」列                                                                     |
| **中文标点自动配对** | 正文编辑器                                | 打 `“` `《` `「` `（` 自动补右半边、光标居中；英文引号与粘贴不受影响。不再依赖输入法自身设置（搜狗等未开该功能时同样生效）                                               |

> 📌 上表最后三项是**首轮打包之后**补的（图鉴排序 / 标点配对 / 拖拽上传），  
> 源码与开发版已生效，`release/桌面安装版/青春幻想引擎-Setup-3.2.0.exe`（10-21 16:10 打的那版）**不含**，  
> 需重新封装后才进安装包。

未纳入本版（别写成已交付）：计划与实际核对（`planCompare`）、世界差异（`worldDiff`）、大表虚拟化（1000 条×60 字段仍慢）。

## 三、AI 数据来源（本版无新增发送面）

| 问题                | 答案                                                                     |
| ----------------- | ---------------------------------------------------------------------- |
| 本版新增了哪些"发给模型"的数据？ | **没有**。候选审阅、检查报告、改后复检、实体自检全是**本地**能力（五引擎都是本地确定性检查），不调模型                |
| 原有发送面有没有扩大？       | 没有。`chapter-rewrite` 的登记未变：**只发本章原文 + 上一章结尾**；改历史章不读设定，改最新章落库后才跑一轮设定同步 |
| 结构化输出开关会多发什么？     | 不会。它只改**发送格式**（`response_format` / `format`），不改发送内容                    |
| 台账                | `src/lib/ai/aiDataSources.ts`：`chapter-rewrite` 等条目未变；本版未新增 key        |

## 四、提示词登记

- 本版**未新增提示词**，也未改 `PROMPT_ORDER` 顺序。
- 业务侧 29 处调用点从旧 `json:true` 显式化为 `output:'json-object' + reasoning:'off'`（与旧口径逐字段等价，有测试证明）；`json:true` 仍按旧语义兼容（且**恒不下发**格式化参数）。

## 五、数据格式变更（升级前请备份）

| 变化                                  | 说明                                  | 影响                                |
| ----------------------------------- | ----------------------------------- | --------------------------------- |
| `revisionJobs` / `revisionPayloads` | 3.2.0 新增两个 store：修订任务与载荷（候选正文、检查报告） | IDB 版本迁移自动完成；**载荷是本地专属，不上云、不进同步** |
| 检查报告载荷内的 `chapterTitle`             | 落档时存**当时的章名快照**（改章名后回看仍是旧名）         | 老报告没有该字段 ⇒ 回看退回当前章名/章号，不编名字       |
| 检查报告载荷内的 `evidence[]`               | 引文 + 段号 + 是否定位（落库时快照）               | 老报告没有 ⇒ 不显示「引文 N/M 可定位」           |
| 候选载荷内的 `chapterId`                  | 3.2.0 补的归属字段（应用落点唯一依据）              | 老候选没有 ⇒ 应用时明确报错「没有记录归属章节」，不猜      |

> 备份/恢复：载荷随项目设置一起导出（`settingsKV.<pid>::kbInBackup` 那个开关是知识库，另说）；  
> 配额：候选 200 份 / 32 MiB，检查报告每章 5 份 / 全书 200 份，超了**删最旧**。

## 六、已知限制（必须如实写进 Release）

1. **大表性能**：一张表 1000 条 × 60 自定义字段（76,000 单元格）打开约 17 秒、保存约 25 秒 —— 表格没有虚拟化。**章节列表有虚拟化**，500 章/100 万字打开 264ms（见容量基准）。本版不改，登记 3.2.x。
2. **复检结论不跨刷新**：任务中心的运行结果只在当次会话内可见；刷新后要看结论请去「检查报告」。
3. **引文定位率可能很低**：伏笔/文风类问题的引文多来自设定表比对，不是正文原句，所以显示「引文 0/3 可定位」是如实的，不代表问题不存在。
4. **实体保留自检只报告**：不判定"丢没丢设定"，也不阻断落库。
5. **主包体积**：1.67MB（gzip 540kB），网页版首屏偏慢；`seedContent` 已分包。
6. **未验证项**：真实端点三处对照、24 个固定样本对照、双设备同步、桌面/便携往返 —— 见 `docs/归档/3.2/3.2.0-发布验收记录-2026-10-21.md`。

## 七、升级建议

- 升级前先在「备份与恢复」导出一份 JSON（自动备份不等于备份：它和你的数据在同一台机器、同一个数据文件里）。
- 老项目直接打开即可，迁移自动跑；迁移会先留备份并**读回校验**，失败回滚。
- 不想冒险可先用「导出设定集」留一份模板与资料。
