# 青春幻想引擎 3.5.2 更新说明

> 一句话：**这一版把投稿广场的「评论」做准做稳了，社区数据可以备份与恢复；同时给社区昵称加了 7 天冷却，匿名投稿可以启用「每周代号」——不再是一排分不清的「匿名用户」。**
> 3.5.2 **不改动已保存的作品数据、快照与模型配置**，升级直接覆盖安装即可。
> 🔴 本版属**源码 + 隔离环境 + 组件夹具**验收，不等于整版发布验收，未覆盖范围见第八节。

---

## 一、评论：数量准了、翻页顺了、重试不会变两条

**修掉的真问题**：旧版前端只取第一页评论，还用「这一页有几条」冒充总数（第一页 20 条时显示 20，实际 21）；服务端响应里根本没有权威总数。

现在的行为：

- 服务端返回**权威总数**，前端改为**游标分页**：加载更多、失败重试、刷新、切换帖子都不会串项；待审、被拒与已删除不计入总数。
- 提交区分**已确认 / 确定失败 / 结果未确认**三种结果：同一意图复用令牌重试，**写入成功但响应丢失时不会重复发一条**；同令牌不同内容返回 `409 TOKEN_CONFLICT` 而不是静默复用旧评论。
- 限流判断移到去重之后，合法重试不再被误伤成 429。
- 顺带修了存储层：写失败不再留下未落盘的「幽灵缓存」；`posts.json` 丢失会拒绝启动而不是带着空表继续写；评论与投票计数漂移可重算。

> 说明：去重承诺**只在当前页面会话内**。刷新页面或换设备后无法保证，界面文案已写明「请先核对原评论是否已发表」。

## 二、社区昵称：首建后 7×24 小时内不可再改

- **首次创建也计入冷却**：创建后 7×24 小时内不能再改（所以第一次设昵称请看清再保存，打错字也得等）。
- 每次改名后同样进入 7×24 小时冷却；设置页与投稿页会写明「昵称有冷却期」，并显示**还剩多久**。
- 提交**相同昵称**不算变更：不消耗额度、不刷新时间。
- **老账号允许一次修正**：升级前已设过昵称、但没有时间戳的账号，第一次改名放行并开始计时，避免把存量用户一刀切锁死。
- 时间戳损坏时**拒绝修改并提示联系管理员**，而不是当成「可以改」放行。
- 冷却判断在服务端同一个写事务内完成，两个页签同时提交只会成功一次。

## 三、匿名投稿：可选启用「每周代号」

默认仍然是「匿名用户」，**只有服务端配置了密钥并启用后**才会出现代号。启用后的规则：

- 词表来自**《神祇异兽》库清洗后的 1672 个名称**（麒麟 / 白泽 / 獬豸 / 甪端 / 三足金乌…），只取 2–4 字纯汉字名。
- 按 **HMAC(账号 + 周标识 + 独立密钥)** 选名：**同一周内同一账号代号稳定**（读者能把一个人这周的内容串起来），**跨周可能不同**——既能区分谁是谁，又不会被永久绑定。
- 周标识按**北京时间自然周**（周一 00:00 起算），服务端统一计算，不受设备时钟影响。
- 同周撞名时给后来者加两位序号（`麒麟-02（匿名用户）`）。
- 投稿按内容**创建周**固定代号（老帖不会每周变），排行按**各榜单统计区间开始周**取代号 —— 所以同一账号在日榜、周榜、月榜可能显示不同代号，设置页已写明。
- 已发布内容可继续在「我的」里切换「匿名 / 显示昵称」；选了昵称就显示昵称，不显示代号。
- **存量数据**：提供停写迁移工具为历史内容补发代号；缺密钥或映射损坏时拒绝启动，不会静默退回全部匿名。

> ⚠️ **本版发布时生产密钥尚未配置**，所以线上看到的仍是「匿名用户」。启用需要单独配置密钥并跑迁移，属于运维动作，不在本次客户端升级范围内。

## 四、社区数据：可以备份、可以校验、可以恢复了

新增 `community-backup` 命令行工具（服务端）：

- 覆盖 8 个社区数据文件，做**清单哈希 / 结构 / 关联 / 计数**四类校验；
- 写入失败或中断**不会覆盖**原备份；恢复前自动留一份当前副本；
- 恢复会改变内容可见性时**默认拒绝**，必须显式确认才执行；
- 含匿名映射时校验密钥与词表版本，不匹配拒绝恢复；
- 备份/恢复期间用协作锁阻止写入（残留锁需人工清理，这是**协作式**约束，不防绕过）。

## 五、桌面版：广场登录入口不再跳网页

桌面版在广场里点「登录云端账号」时，直接打开桌面自己的账号面板，不再跳到网页登录页；未登录提示里的「登录」也是同一入口。

## 八、版本边界（未覆盖 ≠ 已通过）

1. **周代号生产密钥未配置**：功能随包提供，但线上仍是「匿名用户」，需单独配置密钥 + 迁移才启用。
2. 生产环境的加密异地备份 / 跨主机恢复 / 真实断电**未做**；本机每日停写备份与每小时监测已启用，外部告警与异地副本未配置。
3. 真实桌面 / 便携 / 真实多设备、完整应用导航下的浏览器端到端**未覆盖**（本轮用组件夹具 + 真实隔离服务）；三端运行矩阵仍 **0/35**。
4. 真实用户正文、账号、社区数据**未使用**，全部为合成数据。
5. 刷新页面 / 跨设备后的评论去重**不承诺**。
6. 备份恢复的跨进程互斥仅为**协作式锁**，不防恶意绕过；真实断电持久性未验证。
7. 存储路线：本版**保留 JSON**，SQLite 仅在隔离压测证明必要并获授权后再评估，未迁移。
