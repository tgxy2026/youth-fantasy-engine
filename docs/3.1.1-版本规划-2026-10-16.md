# 青春幻想引擎 3.1.1 版本规划

> 规划日期：2026-10-16 ｜ 源码基线：3.1.0
> 来源：3.1.0 独立复核（`docs/3.1.0-独立验收复核报告-2026-10-15.md`、`docs/3.1.0-皎皎交付独立复核-2026-10-16.md`）、第二轮全量六维审计（`docs/3.1.0-全量审计报告-2026-10-16.md`），以及读者反馈（OpenCode Go 订阅 / 自定义请求头）。
> 排序依据：**主人 2026-10-16 拍板的实施顺序** —— 冲突中心优化 → 章节规划板优化 →「纯黑白」范围补齐 → **自定义请求头（本轮新增第四项）**。

---

## 1. 版本定位

3.1.0 已把「长篇创作工作流」与「同步分叉可查看、可恢复」的主干打通（P0-A/B/C/D + P1，含两轮独立复核与两轮全量审计）。3.1.1 **不新增功能组、不引入新数据模型、不改同步协议**，只做四件收尾：

1. 3.1.0 里「能用，但量一大就不好用」的**冲突中心**；
2. 3.1.0 里「只读 MVP 够用，但缺关键提示」的**章节规划板**；
3. 3.1.0 里**主动保留了范围差异**、用户已明确要求补齐的**「纯黑白」全覆盖**；
4. **新增（本轮）**：模型配置支持**自定义请求头** —— 让需要额外请求头的订阅服务（如 OpenCode Go）与网关能够接入。

四项都在 3.1.0 的既有结构上改。前三项**不改项目数据格式、不做迁移**；第四项仅**新增一个可选字段**（缺省即旧行为），同样**不做迁移**。

### 版本成功标准

- 冲突记录上百条时，作者能**筛出想看的那几条**、看得见每条占多大体积、知道什么时候会被清掉。
- 章节规划板上能一眼看出「这一章最后动过是什么时候」「状态标着完稿但正文还是空的」这类不一致。
- 切到「纯黑白」后，图谱 / 地图 / 情节画布 / 结构节奏带里的信息**照样分得清** —— 靠线型、符号、文字，而不是靠颜色深浅。
- 需要自定义请求头的服务（以 OpenCode Go 为代表）**能在模型配置里接上并正常出字**，且相关风险（敏感值、不可设置的头、协议范围）**在界面上有明确提示**。
- 旧项目、便携版、自定义项目（未启用部分模块）**全部照常可用**。

## 2. 范围

### 2.1 冲突中心优化（优先级 1）

**现状**：`SyncConflictCenter.tsx` 全量读取并渲染冲突记录，无分页 / 无类型筛选 / 无体积显示 / 无保留期限。冲突副本正文会累计增大单文件数据量。

**交付内容**

| 项 | 说明 |
|---|---|
| 分页 / 分批渲染 | 默认按发生时间倒序，分批加载（与「资料提及」面板同一范式：`PAGE=50` + 底部状态条）；避免大型正文副本一次性全渲染 |
| 类型筛选 | 按 `store`（章节 / 项目 / 分卷 / 设定表 / 表单）与「已处理 / 未处理」筛选；未处理数量沿用现有的入口角标 |
| 记录体积显示 | 逐条显示副本大小；顶部显示冲突数据合计占用，让作者对「为什么数据文件变大了」有据可查 |
| 保留期限与大小上限 | **先定义并展示**，再谈自动清理 —— 见下方「不做」 |

**验收口径**

1. 300 条冲突样本下，首屏不渲染全部记录；筛选与分页切换无卡顿。
2. 每条冲突能看出类型、发生时间、记录名 / 键、体积。
3. 体积统计与导出 / 备份后的实际增量吻合（误差可解释）。
4. 关闭重开后筛选状态可恢复（或明确重置为默认）。

**预估**：4–6 人日；难度：中。

### 2.2 章节规划板优化（优先级 2）

**现状**：3.1.0 的规划板是只读 MVP —— 展示标题、卷、状态、摘要、字数，缺「更新时间」与「状态与正文不一致」提示；且工作面板仍**一次读入整章正文**。

**交付内容**

| 项 | 说明 |
|---|---|
| 更新时间 | 章节卡显示 `updatedAt`（相对时间，如「3 天前」） |
| 状态不一致提示 | 标着「完稿 / 已发布」但正文为空、或标着「构思」却已写了几千字 —— **提示而不自动改**（沿用项目「不擅自替作者决定」的口径） |
| 长篇读取优化 | 先测量，再决定方案（见下） |

**长篇读取优化的实施前提**：`Dashboard.tsx` 目前调 `getAllChapters()`（含整章正文）。**必须先做测量**：用 300–500 章 / 百万字级样本记录首屏耗时与内存，再在两条路线里选：

- **A. 元数据投影**：新增只读元数据查询（标题 / 卷 / 状态 / 字数 / 时间），卡片列表不再触碰 `content`；
- **B. 惰性加载**：仍走整章读取，但只在展开某张卡时读正文。

⚠️ 以测量结果为准，**不以「列表分批渲染」代替数据读取验收** —— 那是渲染层的事，不解决读取层的问题。

> **✅ 测量结论（2026-10-16 已完成，见 `docs/3.1.1-长篇读取测量-2026-10-16.md`）**：
> 真 Chromium + 真 IDB 实测 —— 521 章 / **110 万字**全量 `getAll('chapters')` 仅 **8 ms**；
> 切回「写作面板」的端到端首屏 **76 ms（121 章）→ 74 ms（521 章）**，**不随篇幅增长**（面板本就分批渲染 60 张）。
> ⇒ 判定「**读取成本可接受**」，按验收口径 1 的括号条款结案，**本轮不实施 A / B**。
> 另确认 A 并不便宜：IDB `getAll` 无法字段投影，「章节总表」台账又是作者手工维护、不能当第二真源 ——
> 真要做 A 得新建机读元数据存储（牵动同步 / 备份 / 迁移），成本远高于它省下的 8 ms。
> 触发条件：章数 > 1000 或正文 > 500 万字、或首屏 > 300 ms 时**重测再议**。

**验收口径**

1. 300+ 章样例下，首屏渲染不读取整本正文（或经测量确认读取成本可接受并记录数据）。
2. 更新时间与状态提示来自现有章节字段，不新增持久化字段。
3. 提示文案是「提示」而非「质量判断」（如「状态标为完稿，但正文为空」而非「这章没写完」）。

**预估**：3–5 人日（含测量）；难度：中。

### 2.3 「纯黑白」范围补齐（优先级 3）

**现状**：3.1.0 的 P0-D 完成了界面、弹窗、交互状态与**码字热力图**（3.1.0 审计补），但**主动保留**了三处范围差异。**主人 2026-10-16 已明确要求全部收成黑白**，故该取舍作废。

**交付内容**

| 处 | 现状 | 目标 |
|---|---|---|
| 图谱 / 地图 / 情节画布 / 结构节奏带的**语义数据色** | `palette.ts` 的 `BEAT_COLORS`、`REL_*`、`GROUP_*`、`MAP_*`、`PLOT_*`、`GOAL_ACTUAL_COLOR` 为渲染时取值的固定 hex，主题切换不触发重渲染 | 全部收成二值；类别区分改由**线型 / 符号 / 文字标记**承担 |
| 图表内部 1px 细线级透明度混色 | 时间轴轨道、正文缩进导向线、画布点格保留原样 | 一并收进二值 |
| 内置背景图案 | 可开关装饰、不做反色 | 保持（不做全屏阈值滤镜，避免破坏文字渲染）—— **仍豁免** |

**验收口径**

1. 纯黑白下，图谱 / 地图 / 画布 / 节奏带里**同类节点同形、异类节点异形**，无需依赖颜色即可分辨。
2. 图例同步更新（图例本身也不得用颜色区分）。
3. 切回其他主题时，语义色**恢复原样**（不因本轮改动而丢失）。
4. 在 Windows 桌面端与预览环境检查，最终由提出需求的用户确认。

**预估**：4–6 人日；难度：中高。主要成本在各图表的「颜色 → 形状」映射设计与图例改造。

> **✅ 实施完成（2026-10-16）**：新增 `src/lib/settings/monoMarks.ts`（第二编码：线型 / 形状 / 纹理 / 边框档位）
> ＋ `src/lib/settings/useMonoTheme.ts`（主题响应式读取，用 `MutationObserver` 观察 `data-theme`，
> 顺手修掉「切主题不触发重渲染」）。六处落地：**人物关系图 / 势力关系图**（边＝线型、节点＝形状，图例换线型示意）、
> **地图编辑**（图层环＝线型、地块层级＝深度线型、点阵收二值）、**情节画布**（卡片＝边框线型 × 粗细，图例同步）、
> **结构节奏带**（填充纹理 + 二值分隔线）、**写作目标燃尽图**（实线 vs 目标虚线）。
> 实机核对（真 Chromium，脚本 `.workbuddy/tools/verify-mono-charts.cjs`）：六个图表**画面就位后**
> mono 下彩色元素 **0**、切回彩色主题后语义色 **5459** 个仍在 —— 26/26 通过。

### 2.4 自定义请求头（OpenCode Go 等订阅 / 网关兼容）（优先级 4 · 本轮新增）

**来源**：读者反馈 —— 大模型能否添加 OpenCode Go 的订阅预置；Go 的订阅需要自定义请求头，一般自定义无法添加，报错
`Request is missing x-opencode-session and cannot be routed efficiently.`

**背景（已联网核实）**：OpenCode Go 是 OpenCode（SST）的订阅（$10/月 Go、$40/月 Go Plus），提供 OpenAI 兼容端点
`https://opencode.ai/zen/go/v1`（官方新文档作 `https://opencode.ai/inference/go/openai/v1`），`Authorization: Bearer` 认证；
自 **2026-09-06 起强制要求 `x-opencode-session` 请求头**（每个会话一个稳定 UUID），缺失即返回 400。

**现状（已逐点核实源码）**：`AIProvider`（`src/lib/aiCore/core.ts`）**没有 headers 字段**；`src/lib/aiCore/chat.ts` 两处
OpenAI 兼容请求头**硬编码**（`Content-Type` + `Bearer`）；`transport.ts` 的 `listOpenAIModels` 同样只带 Authorization；
`ONLINE_PRESETS` 只有 `label + baseUrl`；`AIConfigPanel.tsx` 有「自定义系统提示词」但**无自定义请求头入口**。
⇒ 反馈成立：界面没有任何地方能加自定义头，填上 Go 的地址也必然 400。

**采纳方案（方案 B：通用能力，而非专用后门）**：给模型配置加一张**「自定义请求头」键值表**，在请求出口统一注入。
它同时覆盖中转站、企业网关、需要额外鉴权头的服务 —— 不只为 OpenCode Go 服务。

**交付内容**

| 项 | 说明 |
|---|---|
| 数据字段 | `AIProvider` 新增**可选** `headers?: Record<string, string>`（缺省即旧行为，**不需要迁移**；写入侧＝模型配置保存 / 导入，需一并核对） |
| 配置界面 | `AIConfigPanel.tsx` 在 openai 兼容类型下新增「自定义请求头」键值对编辑器（可增删行；Ollama 原生不需要，隐藏或置灰） |
| 请求注入 | `chat()` 的 OpenAI 兼容出口（含 `variant` 分支）与 `listOpenAIModels` 统一注入；**不得静默丢弃** |
| forbidden headers 拦截 | `User-Agent` / `Cookie` / `Host` / `Content-Length` / `Origin` / `Referer` 等浏览器不可设置的头，**明确拒绝并提示**，避免「设了但没生效」 |
| 预置（可选） | 新增 `OpenCode Go` 平台预设：baseUrl `https://opencode.ai/zen/go/v1`，并附 `x-opencode-session` 头占位与说明 |
| 用户提示 | 三处必给的说明，见下 |

**用户可见提示（三处，必须做）**

| # | 场景 | 提示内容（面向作者，中文，不吓人、讲清后果） |
|---|---|---|
| ① | 自定义头编辑区 | 「自定义头会随本机配置保存，并**一起写进导出 / 备份文件** —— 请不要在这里填长期有效的密钥。」 |
| ② | 填了不可设置的头 | 「`User-Agent` / `Cookie` 等头浏览器不允许设置，已忽略；如果服务商要求固定 User-Agent，本项目暂无法满足。」 |
| ③ | OpenCode Go 预设 | 「Go 订阅：地址 `https://opencode.ai/zen/go/v1`，需在自定义头里填 `x-opencode-session`（可填任意 UUID）；**仅 OpenAI 兼容的模型可用**（走 Anthropic /responses 的那批接不了）。」 |

**验收口径**

1. 填入 `x-opencode-session` 后，对 Go 端点发起的请求**确实带上该头**（用 mock / 抓包验证，不依赖真实订阅）。
2. 填入不可设置的头时，界面给出**明确拒绝提示**，不静默丢弃。
3. 存量模型（无自定义头）的请求体与请求头**逐字节不变**（升级不改变任何既有模型行为）。
4. 自定义头随导出 / 备份一起走，且说明文档已同步告知。
5. 旧版本导入含 `headers` 的数据**不报错**（未知字段忽略；向前兼容）。

**预估**：2–3 人日；难度：中低。改动集中在 `core.ts` / `chat.ts` / `transport.ts` / `AIConfigPanel.tsx` + 单测。

> **✅ 实施完成（2026-10-16）**：新增 `src/lib/aiCore/headers.ts`（`rejectReasonOf` / `sanitizeCustomHeaders` / `mergeHeaders`，
> **明确拒绝**浏览器禁止的头而非静默丢弃）＋ `tests/aiHeaders.test.ts`（22 断言，B 批）。
> `AIProvider.headers?` 落库；`chat.ts` 两处出口与 `transport.listOpenAIModels` 统一经 `mergeHeaders` 注入；
> `ONLINE_PRESETS` 新增 **OpenCode Go**（baseUrl `https://opencode.ai/zen/go/v1` + `providerFromPreset` 预置随机 `x-opencode-session`）；
> 配置界面新增键值对编辑器与三处提示（勿填长期密钥 / 被拒头点名 / Go 仅 OpenAI 兼容模型可用）。
> 门禁：tsc 0 / eslint 0 / 全量单测 **218/218** / 生产构建通过；实机（`verify-custom-headers.cjs`）**10/10**
> —— 预置端点与会话 id 均正确、禁止头会被明确提示。

## 3. 明确不做

- **冲突副本的自动清理 / 自动删除** —— 保留期限与大小上限**先定义、先展示**，自动删除策略须主人单独确认（数据不可逆）。
- **章节规划板的拖拽改序 / 跨卷移动 / 一章多场景** —— 会动到卷序、编号、时间线，属独立立项。
- **图谱的自动布局算法重做** —— 本轮只改配色承载方式。
- **请求头的「伪装 UA / 反检测 / 绕过平台流量监控」** —— 本项目只做通用自定义头能力，**不写任何绕过合规的东西**；订阅方与平台之间的事由用户自负。
- **Anthropic `/messages` 与 OpenAI `/responses` 端点** —— 本项目只支持 OpenAI 兼容 `/chat/completions`，Go 里走这两个端点的那批模型（MiniMax M3、Qwen3.8 系、GPT 系等）本轮**不支持**。
- **移动端、实时多人协作、平台自动发布** —— 沿用 3.1 的边界。
- **数据格式 / 同步协议变更** —— 3.1.1 不动这些，因此**不需要迁移**。

## 4. 风险与应对

| 风险 | 级别 | 应对 |
|---|---|---|
| 自动清理误删作者数据 | 高 | 本轮**不做**自动删除；只做展示与上限定义 |
| 语义色改二值后图表可读性下降 | 中 | 先做一版形状映射并在真实项目上看效果；必要时按图类型分别设计 |
| 长篇读取优化方向选错 | 中 | 先测量后决策，两条路线的数据都要落到文档里 |
| 自定义头随备份外泄 | 中 | 编辑区明示「勿填长期密钥」；导出 / 备份说明同步补一句 |
| forbidden header 误配导致「以为生效了」 | 中 | 提交前拦截 + 明确提示，绝不静默丢弃 |
| 四项并行导致回归面扩大 | 中 | 按 1 → 2 → 3 → 4 顺序做，每项独立提交、独立跑门禁 |

## 6. 与 3.1.0 的关系

3.1.0 已发布的内容**不回改**：3.1.1 只做上述四项补齐。若四项之间出现资源冲突，**按主人拍板的顺序执行**（冲突中心 → 规划板 → 黑白 → 自定义请求头）。其中第四项为**兼容性增强**，不修 bug、不影响主流程，故排在前三项之后。
