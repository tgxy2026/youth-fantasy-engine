## 1. 现状（源码事实）

| 项 | 现状 | 位置 |
|---|---|---|
| 令牌 | 无状态签名 `uid.exp.hmac`（HMAC-SHA256） | `server/lib/auth.mjs:58-62` |
| 期限 | 固定 30 天绝对过期（`now + SESSION_TTL_MS`），无滑动 | `server/index.mjs:142`、`config.mjs:28` |
| 服务端状态 | **每账号只记 1 个** `u.session = { token, at }` | `server/lib/users.mjs:176-181` |
| 顶号 | 新登录覆盖旧 token；旧设备下次请求得 `REPLACED` | `server/index.mjs:87-88`、`sessionCode()` |
| Cookie | `HttpOnly` + `SameSite=Lax` + 条件 `Secure`（`x-forwarded-proto=https`） | `server/lib/http.mjs:101-108` |
| 撤销 | 只有「退出当前」与「重置密码清会话」 | `users.mjs:150-156、185-189` |
| 设备信息 | 无（不记 UA、不记 IP） | — |

🔴 单会话是**故意的**：注释写明「从根上消除多端并发」（`users.mjs:166-175`，对应 WEB-02）。3.3.2 要的就是多端，**这是一次有意的安全取舍反转**，不是简单加个按钮。

### 1.1 反转过后的风险，必须先说清

- `/api/data`（整库）要求 `If-Match`，缺失返回 **428**、不匹配返回 **409**（`userdata.mjs:73-75`）⇒ 多端并发**不会**静默覆盖整库。⚠️ 这条是既有保护，别拆。
- `/api/blob` 的 PUT/DELETE **无版本保护**（P0 盘点 §11）⇒ 多端并发在 blob 上是「最后到达者赢」。当前 blob 只装 `backupPayloads`/`vecRows`/`kbDocs`/`kbBodies`，其中后三者可重建、前者本地专属，所以风险可接受；**但新增任何 blob 类数据前必须重新评估**。
- 结论：多会话可以放开，前提是**整库写继续强制 If-Match**，且新协议（P2）不依赖 blob 的并发语义。

## 2. 会话模型（目标）

### 2.1 数据结构（`users.json` 内，按账号）

```jsonc
"sessionList": [
  {
    "sid": "s_7f3a…",            // 随机 16 字节，base64url
    "tokenHash": "…",           // 令牌全文的 HMAC（不存明文，防 users.json 泄漏即得会话）
    "createdAt": 1761800000000,
    "lastSeenAt": 1761803600000,
    "kind": "web",              // web | desktop | portable
    "label": "Chrome · Windows",// 用户可改；只放最小信息，不存完整 IP
    "revokedAt": null
  }
]
```

- 令牌格式改为 `uid.sid.exp.sig`（仍无状态验签，`sid` 参与签名）。
- 校验顺序：验签 → 验 `exp` → 查 `sid` 是否在 `sessionList` 且未撤销 → 更新 `lastSeenAt`（节流）。
- 撤销 = 在列表里打 `revokedAt`；**不是**删行（保留审计痕迹 7 天后再清）。

### 2.2 上限与期限

| 项 | 默认 | 说明 |
|---|---|---|
| 软上限 | 10 个活跃会话 | 超出时登录**仍成功**，返回 `sessionLimitExceeded: true` + 会话列表，界面提示先撤销（规划 §12 明确不自动踢人） |
| 硬上限 | 20 | 防止列表无限增长；触顶时拒绝新会话（409 `SESSION_LIMIT_REACHED`），提示用「重置密码」或联系管理员 |
| 不活动过期 | 30 天 | `now - lastSeenAt > 30d` ⇒ 失效 |
| 绝对过期 | 90 天 | `now - createdAt > 90d` ⇒ 失效，活跃使用也不能越过 |
| 续期 | 滑动 `exp`，但**只延长不活动期限** | 每次请求不必重签 Cookie；`lastSeenAt` 落盘**每 1 小时最多一次** |

🔴 `lastSeenAt` 必须节流：`persist(db)` 会重写整个 `users.json`，逐请求写会变成磁盘风暴（现有代码只在登录/退出时写）。

### 2.3 撤销触发

| 事件 | 行为 |
|---|---|
| 用户撤销单设备 | 该 `sid` 置 `revokedAt`，其他会话不受影响 |
| 退出当前 | 同上，只针对本会话 |
| 退出全部设备 | 全部置 `revokedAt`，并清当前 Cookie |
| 修改密码 / 重置密码 | 全部撤销（沿用现有 `resetPasswordByInvite` 的语义，`users.mjs:150-156`） |
| 账号禁用 | 全部撤销，且 `authCheck` 直接拒（新增状态字段） |

### 2.4 降级与兼容

- 老 `users.json` 只有 `session` 单字段 ⇒ 迁移为 `sessionList` 单元素；**旧 token 仍有效**（视为已登记会话），避免全员被踢。
- 老客户端收到 `SESSION_EXPIRED` 的处理不变；`SESSION_REPLACED` **将不再因新登录产生**（只在管理员强制下线时出现）。
- 保留 `REPLACED` 文案，避免老前端把未知 code 当崩溃。

## 3. 桌面授权交换（目标）

桌面不共用浏览器 Cookie，走一次性授权码：

```
1. 桌面生成 verifier（32B 随机）→ challenge = base64url(SHA256(verifier))
2. 打开系统浏览器：https://<host>/auth/desktop?challenge=<c>&port=<回环端口>&state=<随机>
3. 浏览器侧沿用现有登录；未登录则先登录
4. 登录态确认后，服务端签发一次性 code（TTL 60s，绑定 challenge + 回环端口 + 账号）
5. 302 到 http://127.0.0.1:<port>/callback?code=<code>&state=<state>
6. 桌面校验 state 全等、端口匹配 → POST /api/auth/desktop/exchange { code, verifier }
7. 服务端核对 code 未被使用、未过期、challenge 匹配 → 返回长期令牌
8. 桌面把令牌写入系统安全存储（Electron safeStorage），**不写数据目录、不写 U 盘**
```

必须做的校验（任何一条缺失就是漏洞）：

- `state` 全等（防 CSRF 把攻击者的授权塞给受害者）；
- 回环端口与申请时一致（防网页向任意本地端口投递）；
- `code` 单次使用 + 60s 过期 + 绑定 `challenge`；
- 回调只在 `127.0.0.1`，不监听 `0.0.0.0`；
- 令牌不进 URL、不进日志、不进错误上报；
- `safeStorage` 不可用 ⇒ **退回会话内登录**，绝不落明文（规划 §12「便携凭据」同口径）。

## 4. 接口草案

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/api/auth/sessions` | 列出当前账号会话（sid、kind、label、createdAt、lastSeenAt、是否当前） |
| `POST` | `/api/auth/sessions/:sid/revoke` | 撤销指定会话 |
| `POST` | `/api/auth/sessions/revoke-others` | 退出其他所有设备 |
| `PATCH` | `/api/auth/sessions/:sid` | 改设备名（只允许改 label） |
| `POST` | `/api/auth/desktop/start` | 登记 challenge + 端口，返回一次性 code 签发凭据（或由第 4 步直接 302 携带） |
| `POST` | `/api/auth/desktop/exchange` | 用 code + verifier 换令牌 |

所有写接口加 Origin 校验（现有 `SameSite=Lax` 之外的第二道），只信任明确配置的反向代理头（`http.mjs:111-115` 现在直接取 `x-forwarded-for`，需按部署条件收紧）。

## 5. 与数据协议的关系（顺序约束）

| 结论 | 理由 |
|---|---|
| P1 可以单独上线 | 整库写已有 428/409 保护，不会静默覆盖 |
| 但 P1 上线后、P2 之前，**不能宣传「多设备接续」** | 多端能登录 ≠ 能安全合并；此时仍是「同一账号整库，最后写入者按 ETag 分支」 |
| P2 上线前，桌面不应把「已同步」写在界面上 | 没有 revision 就没有可展示的确认 |

### 8.1 实现期抓到的一个真 bug（记下来防复发）

`getSessionListIn()` 迁移时会把 `db.users[id]` **换成一个新对象**，而调用方若在调用前就 `const u = db.users[id]`，之后写 `u.sessionList` 写的是已被摘掉的孤儿对象 ⇒ `persist(db)` 存下去的那份没有新会话。
表现：**注册后第二台设备登录，第一台凭空掉线**（正好是这版要消灭的行为）。修法是统一走 `readSessions()`，它同时返回迁移后的用户对象。纯函数单测抓不到这类问题，是端到端自检第 3 条抓到的。

### 8.2 一条契约变更（必须留痕，不是"顺手改测试"）

`tests/cloudConditionalWrite.test.ts` 原有一条：

> 「请求体在途时**会话替换**不能落库」—— 具体做法是 PUT 发到一半时**重新登录**，要求该请求 401。

这条判据编码的是**单会话**时代的语义（新登录顶掉旧设备）。多会话之后「别处登录」不再使本设备失效，所以触发方式必须换，但**安全属性不变**：

| 项 | 旧 | 新 |
|---|---|---|
| 触发 | 另一处登录（顶号） | 显式撤销原会话 |
| 断言 | 提交点重新鉴权、失效会话不落库 | **完全相同** |
| 覆盖点 | 会话失效发生在请求体传输中 | 同上 |

改动只换了「怎么让会话失效」，没有放宽任何一条判据；该文件仍 30 条全 PASS。已在测试注释里写清变更理由，避免下一个人误以为「为了过测试而改断言」。

### 8.3 桌面授权交换（P1-5 后端已实现）

| 文件 | 内容 |
|---|---|
| `server/lib/desktopAuth.mjs` | 参数校验（challenge/state/port）、待授权参数编解码（10 分钟）、一次性授权码（60 秒、内存表、只存摘要）、`redeemCode`（**先删后验**） |
| `server/index.mjs` | `GET /auth/desktop`（已登录直接签发并回跳；未登录存 httpOnly Cookie 后跳首页）、`POST /api/auth/desktop/exchange`、`Authorization: Bearer` 支持 |
| `scripts/verify/desktop-auth-332.mjs` | 真服务端到端 **18/18 PASS** |

流程（与 §3 一致，未改动设计）：

```
桌面 → 浏览器 /auth/desktop?challenge&port&state
     → 未登录：Set-Cookie yfe_dp（httpOnly,10min）→ 首页登录
     → 登录后访问 / ：服务端看到 yfe_dp，签发 code，302 到 http://127.0.0.1:<port>/callback?code&state
     → 桌面校验 state/端口 → POST /api/auth/desktop/exchange { code, verifier }
     → 返回 { token }（4 段，写入系统安全存储）
```

端到端已验：已登录直接签发、回跳只到 `127.0.0.1`、state 原样带回、code 单次使用、verifier 不匹配即拒且 code 作废、非特权端口拒绝、过短 state 拒绝、未登录时参数暂存与登录后自动续上、桌面会话在设备列表标为 `desktop`、`Bearer` 头可用。

🔴 一条设计取舍：**授权码表放内存**。码只活 60 秒，落盘反而多一处可读到的凭据；代价是服务重启后那 60 秒内要重来一次（用户重点一下即可）。这条不是偷懒，是权衡后写进代码注释的决定。

几条刻意的取舍：

1. **本机那条不给撤销键** —— 允许一键把自己踢下线只会制造「我点了怎么黑屏了」的困惑，要退出请用旁边的「退出登录」。
2. **文案明确「不删除云端数据」** —— 否则用户会以为撤销= 那台机器上的稿子没了，不敢点。
3. **`WEB_CLOUD` 为 false 时不渲染** —— 桌面/便携/游客没有这些路由，不摆一个点了报 404 的按钮。
4. **错误一律显示原文**（HTTP 状态或服务端 error），不吞成「操作失败」。
