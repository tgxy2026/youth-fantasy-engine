## 〇、为什么这些依赖「归 2.9，不归 2.8.x」

`npm audit` 报出 **27 条漏洞**（第一批落地后收敛到 **20 条**，见 §4.4），但**全部落在 devDependencies（构建期）**：

- 🔴 **不进最终 exe 产物、不影响终端用户** —— 漏洞来自打包/构建链路自身（tar 解包、dmg、NSIS 元数据等），日常写字读书完全无关。  
- 🟡 **修复全部需要大版本跳跃**（critical 1 / high 19 / moderate 7 均绕不开 semver-major），小版本补丁修不掉。  
- 🟠 **四件绑在同一条链上**：Tailwind 4 改 CSS 架构 → postcss 换插件 → vite 8 改构建管线 → builder 26 改打包配置。**任一环单独跳，另外三个就失去验证基准** —— 这是本轮只出规划、不一次跃完的根本原因。

## 一、四件目标版本与破坏性清单

### 1. electron-builder：`^24.13.3` → **26.15.3**（大版本跳跃）

**修复**：critical 1（`tar`，12 次重试 EBUSY / 5 次 volume exhausted）+ high 19（app-builder-lib / builder-util / builder-util-runtime / chokidar / dmg-builder / electron-publish / esbuild / extract-zip / fast-glob / global-agent / http-cache-semantics / micromatch / postcss-nested / roarr / source-map-js / sprintf-js 等整条链）。

**破坏性清单**：
- NSIS / exe 元数据字段调整：`win.target=nsis` 段、`perMachine`、`allowToChangeInstallationDirectory`、`artifactName` 等字段需按 26 的映射重审。
- `electron-builder.yml` 的 `files` / `asar` / `win` / `nsis` 配置块要逐字对照 26 的 breaking changes。
- ⚠️ **主 exe 元数据写入时机是本项目已知痛点**：当前靠 `afterAllArtifactBuild` 钩子 + 外层 `rcedit`（在 builder 进程退出后写，26 下 `afterPack` / `afterAllArtifactBuild` 回调时机若变化，主 exe 元数据会被覆盖回默认）。已知 24.13.3 下的稳定解是 `signAndEditExecutable: false` + 外层 rcedit。

**回滚判据**：`git bundle` 快照回退到 tag；若 26 下 rcedit 写不进主 exe 元数据 / NSIS 打包失败 ⇒ 退回 24.13.3（保持现稳定解）。

### 2. tailwindcss：`^3.4.19` → **4.3.3**（🔴 **破坏性重写**，非换版本号）

这一件必须单独拎出来 —— 它不是「升版本」，是**配置驱动方式重写**。

**破坏性清单**（逐项，每一条都可能静默失效）：
1. **PostCSS 插件改名**：`postcss.config.js` 里 `tailwindcss: {}` → `@tailwindcss/postcss: {}`。不改 ⇒ 构建直接报错。
2. **CSS 指令改名**：`src/index.css` 首行 `@tailwind base / components / utilities` 三件套 → `@import "tailwindcss"`（CSS-first 单一入口）。
3. **`theme.extend` → `@theme` 块**：`tailwind.config.js` 里 350+ 行的自定义 ink/amber 色板、`fontSize` 9~17 整数档、`minWidth/maxWidth/borderRadius/spacing` 等，要迁到 CSS `@theme`。
4. **默认值变更**（最危险，会「全局变色但不报错」）：
   - `border` 默认色 `gray-200` → `currentColor` ⇒ 本项目大量 `@apply border-*` 会静默变色。
   - `shadow` / `ring` / `blur` 尺度重命名、`outline-none` → `outline-hidden` 等语义调整。
5. **`<alpha-value>` 占位符**：本项目一键换肤**完全靠** `rgb(var(--ink-N) / <alpha-value>)`；v4 改推 `color-mix()`，旧写法能否原样保留**必须实测** —— 这是换肤链路的核心风险点。
6. **dark 策略**：本项目走**手写 `[data-theme='dark']` + CSS 变量**（不是 Tailwind class 策略）；v4 下 `@custom-variant` 或等效 `:root` 选择器是否仍触发需验证。
7. **content 扫描**：`content: ['./index.html', './src/**/*.{ts,tsx}']` → v4 自动检测，需确认仍覆盖 electron 侧 TS。

**回滚判据**：**先在隔离分支实测**（跑 `vite build` + 对产物 CSS 做逐字节 diff + 实机目视核对 7 套主题对比度）。若任一主题对比度崩 / 大量 `@apply` 失效 / alpha 换肤静默失效 ⇒ **保持 v3.4.19，不跳**。

### 3. vite：`^5.3.4` → **8.3.3**（大版本跳跃）

**破坏性清单**：
- `vite.config.ts` 的 plugins（`@vitejs/plugin-react` / `vite-plugin-singlefile`）API 变更。
- 构建产物（`dist` 单文件内联）结构与 rollup 版本随之变化。
- dev server port 5199 与 `ELECTRON_START_URL=http://localhost:5199` 注入方式可能需适配。

**回滚判据**：tag 回退 + 重跑 `bash tests/run-batches.sh` 全量基线；若 dev / build 管线任一环断 ⇒ 退回 5.3.4。

### 4. vite-plugin-singlefile：`^2.3.3` —— 🔴 **实为死依赖**（2026-10-07 实测修正）

原判为「连带项」。实测发现：**全仓无任何引用**（`vite.config.ts` 的 plugins 里没有它，`scripts/` / `electron-builder.yml` 也没有）。
便携版如今走的是同一份**多文件 `dist`**（靠 `base: './'` 相对路径加载），不再需要单文件内联插件。

它留在账上只带来 **1 条 high**（来自其传递依赖 `micromatch`），且 npm 给出的"修复"是**降级到 `0.9.0`**（semver-major）。
→ **处置建议：直接从 devDependencies 移除**（属待拍板项，见 §五）。

### 4.3 纸上没写到、实操才暴露的三个坑

**① `@vitejs/plugin-react` 必须连带升，否则 vite 8 装不上**
`plugin-react@4.x` 的 peer 是 `vite ^4 || ^5` ⇒ vite 8 下 npm 直接 ERESOLVE 报错。升到 **6.1.2**（peer `vite ^8.0.0`）后才通。
> 补充：它另三个 peer（`oxc-transform-react` / `@rolldown/plugin-babel` / `babel-plugin-react-compiler`）在 `peerDependenciesMeta` 里全是 `optional: true`，缺失只出警告、**不阻塞安装**。

**② vite 8 不再带 esbuild ⇒ 测试工具链断裂（表现为「测试全红」）**
`tests/build-test.mjs`（及另外 5 个脚本）**直接 import `node_modules/esbuild/lib/main.js`**，而 esbuild 原本只是 vite 5 的**传递依赖**。vite 8 改用 rolldown 后 esbuild 从依赖树消失 ⇒ 测试脚本 `ERR_MODULE_NOT_FOUND` ⇒ 结构闸 13 个全红。
🔴 **这是假红，不是代码坏了** —— 一装上 esbuild 就 20/20 通过。
> 修法：把 `esbuild ^0.28.2` 补成**显式** devDependency（工具链的真实依赖，本就该直接声明）。

**③ 装 esbuild 会被本机 EBUSY 拦（安装脚本自杀）**
esbuild 的 `install.js` 用 `execFileSync` 校验二进制版本 —— 本机 `spawnSync/execFileSync` **恒返回 EBUSY**（已知环境红线），于是 `npm install` 整体回滚。
> 修法：`npm install --ignore-scripts` 绕过（二进制走 `@esbuild/win32-x64` optionalDependency 落盘，**不依赖 postinstall**，运行时正常）。`electron/dist` 亦已存在，跳过脚本不影响 electron。
