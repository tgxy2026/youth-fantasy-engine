## 3. 一个容易忽略的细节：它**会**进提示词（但纯属噪音）

`aiContext.ts` 的渲染函数是把 schema 的字段/列**全量**铺出去的：

- `renderForm()`（`:197`）：遍历 `tab.modules[].fields`，跳过空值 → 卡片里的「保密等级」照样出现
- `renderTable()`（`:232`）：表头 = `tab.columns.map(c => c.name)` → 表格里的「保密等级」作为**一列**出现在表头与每行

而 `aiContext` **没有** import `SABC_LABELS` → 模型看到的就是裸字母：

```
编号 ｜ 名称 ｜ 保密等级 ｜ 类别 ｜ …
F0028 ｜ 黑台底座刻符 ｜ S ｜ …
```

**两端都没受益**：作者以为标了 S 会有什么效果（没有），模型则白读了一个自己无法解释的字母。
（唯一"有点用"的场景是：模型可能自己猜到 S=secret 而这影响它的表达——但这靠不住，也不可控。）

## 4. 真正的防剧透机制：四道闸（+ 酒馆两道补充）

全部在 `src/lib/aiContext.ts`，**由调用方传参启用**；四处开关互相独立。

| # | 闸 | 参数 | 代码位置 | 效果 |
|---|---|---|---|---|
| **1** | **段落级排除** | `viewMode: 'character-view'` | `:489-491` | 把 `AUTHOR_SIDE_TABS`（10 张作者侧页签）**整表**排除 |
| **2** | **字段级排除** | 同上（复用 `hideAuthorFields`） | `:202/213/234` | 在**保留的**页签里，把 `AUTHOR_SIDE_FIELDS`（约 40 个列名）整列/整字段不渲染（**连列名都不出现**，免得模型追问） |
| **3** | **时序锚点** | `anchorChapterId` | `idsUpToAnchor()` `:257`；`buildChapterDigest(200, anchor)` `:580` | ① 章节清单只到锚点章 ② 相关章节召回过滤到锚点及之前 |
| **4** | **知情者过滤** | `knowerName` | `sectionOf()` `:278-281` | `secrets`（知情权限）只带「知情者」字段命中该角色的条目 |
| 5 | 角色认知范围 | 扮演设定 `2.6 知识边界` | `tavern/engine.ts:415`、`cardFields.ts:109` | 与闸 4 互补：secrets 管**事实**边界，扮演设定管**认知**范围 |
| 6 | 未带入声明 | `prompt.ts:149-155` | `〖未带入的资料〗` 层 | 因预算被丢的段落**如实声明**，并明写"请当作你的角色不知道，也不要凭空推测" |

### 6.3 酒馆模式（唯一做了分层的链路）

`buildPlotSystem` 组装的 system 层次（`tavern/prompt.ts` 顺序，**顺序即优先级**）：

```
〖世界与角色设定〗（= buildProjectContext，受四道闸管控）
〖本场背景设定〗（作者提炼过的世界资料，关键词命中才注入）
〖这一场〗（场景机位）
〖本场记忆 / 长期记忆〗
〖你在戏里的身份与知识边界〗
〖扮演设定 · 角色名〗（含 2.6 知识边界）
〖发言规则〗（多角色时）
〖通用补充要求〗〖本场补充要求〗
〖未带入的资料〗（如实声明被预算丢掉的部分）
〖协议〗（钉在**绝对末尾**）
```

**key 数字**：设定层只占 `总预算 × settingRatio`；`contextSource: 'digest'` 档会改用 `skeletonOnly`
（只留作品概览 + 章节清单），实测设定层从 4662 字降到约 2200 字，省下的全还给对话历史。

## 7. 给后续两项开发的三个提示（缺口与机会）

1. 🔴 **保密等级目前是"死字段"**。拆书抽出来的「结局 / 真相 / 隐藏设定」这类内容，作者标了 S
   **也不会被任何机制保护**。若要让它有意义，最自然的两条路：
   ① 让 `AUTHOR_SIDE_FIELDS` / `character-view` 支持**按等级过滤**（S 一级直接不进角色视角）；
   ② 让**预算抢占**按等级排序（S 先塞，C 最后，预算不够先丢 C）——这正好解「长篇时后面章节的设定挤不进来」。
2. ⚠️ **保密等级进模型是纯噪音**（裸字母、模型无法解释）。若不做第 1 条，建议至少在
   `renderForm`/`renderTable` 里**跳过该列**，省 token 又不误导。
3. 🎯 **工作流（C）会大量产出 S 级内容**（Bible 里的结局/真相、伏笔的回收计划）。
   它天然需要一套"哪些内容能进哪一档上下文"的规则 —— **保密等级是现成的载体**，
   建议在 B1/C 动工前先把这套规则定下来，否则工作流生成的东西会直接漏给"角色视角"。
