# 青春幻想引擎 3.6.2 开发规划 · 交付闭环、真机规模与 AI 质量度量

> 起点：3.6.1 发布版（`v3.6.1`，2026-11-19）。
> 依据：本机实测（970 个源文件 / 495 个测试文件 / 自检 26 项 / `tests/perfBaseline.test.ts` 百万字内存桩）
> ＋ 外部规范（Electron 官方性能清单、local-first 失效模式清单、2026 AI Copilot UX 留存数据、WCAG 2.2）。
> 一句话定位：**3.6.1 及以前解决的是「代码写得对不对」，3.6.2 解决「发出去之后还管不管得住」。**

## 1. 版本目标与边界

**目标（四条，都要有数字或可复现动作）**

1. **交付闭环**：版本可发现、可校验、网页不跑旧包。旧版用户能从应用内知道"该升级"，且下载的包能验证完整性。
2. **故障可回收**：一次点击产出可诊断材料（版本 / 形态 / 存储 / 近期错误），**不含正文、不含密钥**，由作者决定发给谁。
3. **真机规模**：把"百万字不卡"从内存桩变成**真机数字 + 周检阈值**，并给出主线程长任务分布。
4. **AI 质量可度量**：建立固定评估集 + 本地接受率统计，让"AI 变好/变坏"从体感变成曲线，**数据不出本机**。

**边界（本版不做）**

- **不加创作向新功能**。听校（TTS）、写作目标/打卡、系列级设定共享，只在本版产出**一页评估**，实现排 3.6.3 候选（见第 6 节）。
- **不做静默自动安装**：桌面仍保持「作者点按钮 → 有进度 → 自己走安装向导」的口径，只补完整性与可用性。
- **不做任何自动上传**：错误、统计、评估数据一律不出本机；"诊断包"是本地文件，由作者手动发送。
- **不改 3.6.1 已发布契约**：成果记录三态、候选 `checkPayloadIds`、图鉴字段判定、搜索替换的范围口径，一律不动。
- **不做 ghost text（行内灰字自动建议）**：2026 的留存数据显示这是最差形态（见附录 A），与本项目"显式调用 + 可追溯"的方向相反。

**贯穿纪律**

- 先红后绿：每个工作包先写会失败的断言，再改实现。
- 涉及存储、下载、恢复的改动，**必须**同时给出失败路径断言（中断 / 校验不符 / 磁盘满 / 权限拒绝）。
- 每个工作包结束跑四件套：`typecheck` / `eslint --max-warnings 0` / 相关专项 / 全量单测。
- 收工前跑：`node scripts/audit/self-check.mjs` + 六维审计 + `node scripts/release-check.mjs --source-only`。
- 文档与台账同步：任何"欠账减少"必须在本版记录里逐条对应，不允许只在提交信息里说。

### W1 · 更新通道与完整性（P0，3 天）

**现状（已核实，不是推测）**

| 事实 | 位置 |
| --- | --- |
| 版本源只有 Gitee 公开 API 一个，匿名调用；代码注释已记「密集调用会 403 限流」 | `src/lib/app/versionCheck.ts` |
| 自动检查有"每天一次"节流，失败完全静默（这条口径正确，保留） | 同上 `checkUpdate(manual)` |
| 下载只做**字节数比对**（`content-length`），**无摘要校验**；注释明写"不假装有校验" | `electron/updateDownload.cjs` |
| 有兜底：以文件头 `MZ` 判定真安装包，防把 Gitee 的限流网页存成 .exe | 同上 `looksLikeExe` |
| **便携版在启动时显式跳过检查**（注释给的三条理由仍然成立） | `src/App.tsx` |
| 网页版**无 Service Worker**，缓存响应头未入仓（服务器配置不在仓库里） | 全仓 grep 无 `serviceWorker`；`server/deploy.sh` 无缓存处理 |
| 关于页的"获取最新版本"只给网盘链接，不联网检测 | `src/components/app/AboutPage.tsx` |

**方案**

1. **自建版本清单**（托管在自有域名，与安装包同域）：新增 `version.json` 契约，字段如下。

   | 字段 | 用途 | 约束 |
   | --- | --- | --- |
   | `version` | 最新版本号（不带 `v`） | 与 tag 一致 |
   | `releasedAt` | 发布时间（ISO 8601，带时区） | 用于"多久没更新"的提示 |
   | `channel` | `stable` / `beta` | 本版只发 stable，字段先留 |
   | `minSupported` | 低于此版本给"建议尽快升级"的强提示 | 只在真有破坏性变更时抬 |
   | `assets[]` | 每个产物：`kind` / `url` / `size` / `sha256` | `sha256` 必填 |
   | `notesUrl` | 更新说明地址 | 指向本仓 docs 的发布页或 Release |
   | `webBuiltAt` | 网页版构建时间 | 供网页版比对"是否跑的是旧包" |

2. **双源读取，Gitee 降级为兜底**：先读自建清单；**任何失败**（断网 / 404 / 结构不符）回落到现有 Gitee 逻辑，一行行为都不变。这样既摆脱限流，又不会因为自家服务器抖一下就"查不到更新"。

3. **下载后校验**：
   - 清单里有 `sha256` → 下载完成后计算并比对，不符则**删除 `.part` + 明确提示"文件校验不通过，请重试或换下载渠道"**，绝不拉起安装器；
   - 清单缺失或走的是 Gitee 兜底（无摘要）→ 保持现状（只比大小），并在界面**如实写明"本次未做完整性校验"**。
   - 诚实边界：同源托管的摘要能防传输损坏与镜像不一致，**不能防服务器被篡改**（那需要代码签名）。这条写进更新弹窗的说明，不夸大。

4. **三形态各自的更新入口**（现状是三种不同的沉默，本版统一为"能知道、不乱来"）：

   | 形态 | 本版行为 |
   | --- | --- |
   | 桌面安装版 | 检查 → 下载（带进度、可取消）→ 校验 → 拉起安装器（现有流程 + 校验） |
   | 便携版 | **只提示**"有新版本，需重新下载便携包"，给可复制的下载页地址；**不**提供自动下载（它跑在浏览器里，装不了） |
   | 网页版 | 读到 `webBuiltAt` 与当前构建不一致时，角落给一条"有新版本，刷新以应用"的轻提示（可关，不打断输入） |

5. **缓存策略入仓**：服务器加 nginx 配置片段并纳入版本管理（建议新建 server/nginx/ 目录，本版首份配置放这里）—— `index.html` 为 `no-cache, must-revalidate`，`/assets/*` 为 `public, max-age=31536000, immutable`。理由：Vite 产物名带 hash，改配置不会误伤；而 `index.html` 一旦被缓存，用户会长期跑旧包。

6. **关于页显示"我这一版到底是什么"**：版本号 + 构建时间 + 存储形态（桌面 / 便携 / 网页）。现在用户报障时连"哪一版"都要靠截图猜。

**判据（六条，缺一不算完成）**

1. 断网时检查更新仍静默、不弹错误框（回归，不能因新逻辑变吵）。
2. 自建清单 404 → 自动回落 Gitee，结果与改动前一致（用假 fetch 注入，两条路径各有断言）。
3. 篡改一个字节的假包 → 校验失败、`.part` 被清、安装器**未被拉起**（断言调用次数为 0）。
4. 清单无 `sha256` → 流程仍可完成，界面文案含"未做完整性校验"（不允许静默降级）。
5. 网页版旧包 → 出现刷新提示；点关闭后当天不再出现。
6. 缓存头：`index.html` 响应含 `no-cache`，`/assets/*` 响应含 `immutable`（部署后 curl 实测，结果写进发布记录）。

### W2 · 诊断包（P0，2 天）

**现状**：`src/components/app/WriteLockBanner.tsx` 已有「复制诊断信息」（纯文本，拼 `src/lib/app/lockBannerCopy.ts` 的 `writeLockDiagnostics`）；错误只落在本地 `src/lib/app/errorLog.ts`；无聚合、无统一出口。上一轮真实事故就是"只有一张截图，靠猜"。

**方案**：新增一个**本地诊断包**生成器（纯函数为主，便于测），产出一份 `.json`（或打包成 zip）供作者另存/复制。

内容清单（**白名单式**，只挑这些，不"排除敏感字段"——排除法永远会漏）：

| 段 | 内容 | 为什么需要 |
| --- | --- | --- |
| `schema` | 诊断包格式版本 | 以后能兼容旧包 |
| `app` | 版本、构建 hash、形态（桌面/便携/网页）、是否开发态 | 定位"哪一版" |
| `runtime` | Electron / Chromium / Node 版本、OS、内存、界面缩放、窗口尺寸 | 复现环境 |
| `storage` | 存储形态、路径**类别**（默认/自定义，不含完整用户名路径）、数据文件大小、最近修改时间、是否处于写锁 | 判断是否落进云盘目录 |
| `health` | 数据体检摘要：按类别计数（悬空引用 / 孤儿 / 编号冲突 / 必填空 / 酒馆残留） | 不读正文也能判断结构伤 |
| `errors` | 最近 20 条：时间、级别、消息、栈前 5 行（路径脱敏为 `<user>`） | 真正能定位的那段 |
| `prefs` | 白名单偏好：主题、界面缩放、面板位置、模型**名称**（不含密钥、不含 baseUrl 凭据） | 复现"只有我会"的问题 |
| `redaction` | 显式列出"被排除的类别"：正文、章名、设定内容、API Key、账号标识、同步令牌 | 让作者敢发 |

**判据**

1. 构造一个"正文含唯一标记串 + 设置里有假 API Key"的夹具 → 生成诊断包 → 两者**均不出现**（负向断言，这是本包最重要的一条）。
2. 错误栈里的绝对路径被脱敏，但仍保留"在哪一层"的信息（不能脱敏到无法定位）。
3. 数据体检失败（存储打开失败）时，诊断包**仍能生成**，并在 `health` 段写明"体检不可用及原因"——不能在最需要它的时候崩掉。
4. 生成过程不写库、不改任何项目数据（断言写操作调用次数为 0）。

### W3 · 恢复演练（P0，2 天）

**现状**：`src/lib/db/backups.ts` 有 5 分钟滚动备份与每日备份，且各有保留上限（30）；`scripts/verify/backup-roundtrip-probe.mjs` 已能验"备份 → 破坏 → 恢复"，但它是**手动脚手架**（依赖先起 dev 服务）。

**方案**

1. 把恢复往返抽成**可重复运行的确定性探针**：固定夹具（含章节、表格行、图鉴图片），断言"恢复后逐字段一致 + 不复活已删内容 + 备份不含敏感 meta"。
2. 补三个**未覆盖的失败路径**：① 恢复中途失败 → 原有数据不被半途覆盖；② 备份文件本身损坏 → 明确拒绝并保留现场，不"尽力恢复"出半个项目；③ 保留上限到顶时淘汰的是**最旧**的，不是最新的（这条最容易写反）。
3. 应用内给一个「备份可恢复性检查」入口（只读）：列出"最近 7 天可恢复的时间点 + 最近一次演练结果"。**不做**自动恢复，只做"能证明它能恢复"。

**判据**：探针在 CI 可跑（无需人工起服务）；三个失败路径各有断言；界面上的"最近一次演练"时间真实来自本次运行，不写死、不假装。

### W4 · 真机性能与主线程（P1，4 天）

**现状（数字来自 `tests/perfBaseline.test.ts` 注释，2026-09-22 本机实测）**

| 项 | 值 | 口径限制 |
| --- | --- | --- |
| 造数 / 冷启动 / 切章 / 保存 | 105ms / 6–17ms / 0.1ms / 1.4ms | **内存存储桩**，无真实 IndexedDB IO |
| 建索引 / 查询 | 121–151ms / 3.2–4.5ms | 同上 |
| 真实 UI 耗时 | 注释指向"`ui-perf-longbook.mjs`（手动跑）" | **仓库内未找到该脚本**，需确认是否只存在于本机工具目录 |

另外三条结构性事实：全仓 **0 个 Web Worker**；`navigator.storage.estimate` **0 处**；`debounce/throttle` 全仓仅 **2 处**。

**方案**

1. **补齐真机脚本并入库**（`scripts/verify/` 下，与既有 `table-performance.mjs`、`perf-board-500.mjs` 并列）：真实 IndexedDB、800 章 / 约 120 万字 / 3000 表格行，测首屏、切章、全文检索、图鉴大表筛选、保存。输出 P50 / P95 + 长任务计数（`PerformanceObserver` 的 `longtask`）。
2. **阈值沿用本项目既有纪律**：先宽后紧（当前宽度 = 实测 × 6~10 倍），且**阈值旁边必须写本次实测值与机型**，否则下一个人分不清"量出来的"还是"拍出来的"。这条来自 `tests/perfBaseline.test.ts` 自己的注释，继续遵守。
3. **Worker 只搬最重的 1–2 项**，候选按"卡顿感知"排序：语义分块 + 向量打分（百万字数千块）、DOCX 导入、大表筛选。要求：
   - 必须保留**同步回退路径**（Worker 构造失败 → 走原实现），否则老机器上会从"卡"变成"不能用"；
   - 迁移前后用同一夹具对拍，输出必须逐字节一致（有断言）。
4. **配额预警**：网页版启动与每次保存成功后读 `navigator.storage.estimate()`，到 80% 给一次轻提示（可关），并给"导出备份"入口。到 95% 时把"保存可能失败"如实说出来。

**判据**

1. 有一张真机数字表（含机型、缩放、数据规模），能被复跑对比。
2. P95 与长任务计数进入周检；超阈值即红，不是"看一眼"。
3. Worker 迁移项：对拍一致 + 构造失败可回退（两条都有测试）。
4. 配额提示在 80% / 95% 两档各自触发一次，且不重复骚扰。

### W5 · AI 质量度量（P1，4 天）

**现状**：方向已经对了——「看依据（改前 → 改后）」「未来计划待重审」「创作轨迹」「成果三态（保留/草稿/已排除）」「创作参考预算裁剪」。缺的不是设计，是**度量**。

**外部依据（反直觉但关键）**：2026 的公开数据里，**显式调用型写作助手 90 天留存约 67%，行内自动建议型仅约 12%**。结论不是"加个灰字补全"，而是继续走"用户发起 → 结果可见 → 可采纳/可放弃 → 可追溯"。

**方案**

1. **固定评估集**（fixtures，纯文本 + 期望的结构性断言）：选 5–8 个代表性章节场景（长章压缩、伏笔回收检查、章末钩子、读者视角审问、设定一致性）。断言**不评判文笔好坏**，只判"结构是否守约"：是否超预算、是否引用了不存在的编号、是否把范围结论说成全书结论、失败是否如实标注。
2. **本地接受率**（不上传）：按功能记录 `shown / accepted / rejected / regenerated / undone` 五种事件，聚合存本机 meta，提供"查看 + 一键清空"。指标口径写进手册，避免用户误解为"上传了行为数据"。
3. **延迟与成本分布**：按功能聚合 P50/P95 的耗时与 token，界面上给作者看"哪些功能贵而慢"，也给你自己判断"哪个功能该改造或下线"。
4. **回归对比**：换模型 / 改提示词前后各跑一次评估集，输出对比表（通过项数、超预算次数、失败路径命中）。**没有对比表就不算改过提示词。**

**判据**

1. 评估集能在 CI 跑（不依赖真实模型时可只用固定响应夹具；真实模型跑法另附说明，标注"需密钥，非 CI"）。
2. 接受率统计：清空后归零、跨项目不串、换账号不串（三条断言）。
3. 某功能连续 4 周接受率 < 20% → 触发一次"保留 / 改造 / 下线"的评估结论，写进当月记录。

### W6 · 键盘与可达性（P1，2 天）

**现状**：`aria-` 约 290 处，但 `focus/tabIndex` 仅 33 处 —— 覆盖不均；`uiUxGuards` 95 条偏"文案与色板"，不测焦点。

**方案**

1. **三条主流程纯键盘走通**（写一章 → 保存 → 导出；改设定 → 在正文检索到；问 AI → 采纳/放弃）。逐项记录"Tab 顺序 / Esc 关闭 / 关闭后焦点回到触发元素"。
2. **焦点不被遮挡**（WCAG 2.2 新点）：弹窗打开时 Tab 不逃逸到背景；面板浮起时不盖住当前焦点。
3. **拖动的非拖动替代**：颉文姬面板已有"左右箭头 + 复位"，天然满足"拖动类操作需提供非拖动替代"，**补一条验收把这条写实**（不是新增功能，是把已有能力写进验收）。
4. **触摸目标**：主操作按钮有效命中区 ≥ 24×24（WCAG 2.2 AA 下限），正文密集区另议。
5. **缩放**：132% 与 200% 下，弹窗、面板、表格工具栏不互相遮挡（3.6.1 刚踩过 zoom 的坑，这条要变成常规项）。

**判据**：三条主流程的键盘走查表（谁在第几步、焦点落在哪）+ 零 focus trap 逃逸 + 24px 命中检查截图；不达标项要么修，要么在记录里写明"为什么接受"。

## 3. 批次与依赖

| 批次 | 内容 | 依赖 | 风险 |
| --- | --- | --- | --- |
| B1 | W0 版本基线 + W1 清单契约与双源读取（先不动下载） | 无 | 低 |
| B2 | W1 下载校验 + 三形态入口 + 缓存头 | B1 的清单字段定稿 | 中（涉下载器与服务器配置） |
| B3 | W2 诊断包 | 无（可与 B1 并行） | 低（白名单式生成） |
| B4 | W3 恢复演练探针 | 无 | 中（要造破坏夹具，注意别碰真实项目目录） |
| B5 | W4 真机脚本 + 配额预警 | 无 | 中（数字受机器负载影响） |
| B6 | W4 Worker 迁移（1–2 项） | B5 有基线数字，否则无法证明"变快了" | 高（须有同步回退） |
| B7 | W5 评估集 + 接受率 | 无 | 中（断言写得松=测不出问题，写得紧=天天红） |
| B8 | W6 可达性走查 | 无 | 低 |

> 顺序理由：B1/B3/B4/B5/B7/B8 互不阻塞，可并行；B2 必须在 B1 之后（先用清单字段，再改下载器）；B6 必须在 B5 之后（没有基线数字的"优化"无法验收）。若本版时间紧，**先保 B1–B4**，B6 可整体推到 3.6.3，但 B5 的脚本必须留下。

## 5. 风险与对策

| 风险 | 后果 | 对策 |
| --- | --- | --- |
| 自建清单所在服务器故障 | "查不到更新"或误判 | 双源回落 Gitee；清单读取失败静默；清单本身不做写操作 |
| 摘要校验挡住正常用户 | 下完不能用 | 校验失败给"重试 / 换渠道（网盘）/ 复制下载页"三条出路，不让人卡死 |
| Worker 改造引入新 bug | 从"卡"变"错" | 同步回退路径 + 迁移前后逐字节对拍；不达一致不合并 |
| 真机数字抖动大 | 阈值天天红，最后被无视 | 多次取中位、记录机型与负载；先宽后紧；超阈值先看趋势再看单次 |
| 评估集固化当前标准 | 越写越"守旧" | 基线可更新，但每次更新必须留档"为什么放宽/收紧" |
| 诊断包泄露隐私 | 最严重的一类事故 | 白名单式生成 + 负向断言（正文/密钥必须不出现）+ 生成后展示"包含哪些段、排除了哪些段" |

## 6. 明确不做（以及排到 3.6.3 的）

**本版不做**

- ghost text / 行内自动建议（数据与定位都不支持）。
- 静默自动安装、后台强制更新。
- 任何形式的自动上传（错误、统计、评估数据）。
- 实时多人协作、平台一键发稿、云端违禁词库订阅（与"本地优先 + 单人创作"定位冲突）。

**3.6.3 候选（本版只出一页评估，不写实现）**

| 候选 | 价值 | 主要成本 | 需要先回答的问题 |
| --- | --- | --- | --- |
| 听校（TTS 朗读本章） | 高（竞品标配，对"拗口句"最有效） | 低（`speechSynthesis` 纯本地） | 长章分段朗读的断点与暂停手感 |
| 写作目标 / 连续天数 | 中（留存） | 低（统计已有基础） | 目标是否按"有效字数"算、跨时区怎么算 |
| 系列级设定共享（跨书 codex） | 高（写续作/同世界观的真实痛点） | 高（数据模型 + 同步 + 冲突） | 共享是"复制"还是"引用"；一本书改了另一本要不要变 |

## 附录 B · 与 3.6.1 规划的关系

3.6.1 处理的是"代码内部的欠账"（覆盖率、未接线模块），验收靠静态检查与单测就能闭环。
3.6.2 处理的是"发出去之后的欠账"（版本、诊断、真机、AI 质量），**验收必须包含人工动作**（装一次、断一次网、拖一次窗口、用键盘走一遍）。

两者不重叠：3.6.1 的台账已清零，本版不重开；本版新增的门禁（真机数字、恢复演练、AI 对比）反过来会成为 3.6.3 的常规项。
