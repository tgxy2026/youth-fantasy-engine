## 1. 版本目标与边界

**目标（四条，各自可判定）**

| # | 目标 | 判定方式 |
| --- | --- | --- |
| G1 | 交付闭环：旧版能知道"该升级"，下载的包能验完整性 | 六条验收（见 W1），其中"篡改一字节必被拒"是硬线 |
| G2 | 故障可回收：一次点击产出可诊断材料 | 负向断言（正文/密钥/路径不出现）+ 用户实际能发出去 |
| G3 | 真机规模：百万字不卡有数字、有阈值 | 一张含机型的真机表 + 连续 3 次波动 < 30% |
| G4 | AI 质量可度量：评估集 + 本地接受率 | 换模型前后有对比表；数据不出本机 |

**边界（本版不做）**

- **不加创作向新功能**：听校（TTS）、写作目标/打卡、系列级设定共享，只出**一页评估**（第 9 节）。
- **不做静默自动安装**：保持「作者点按钮 → 有进度 → 自己走安装向导」。
- **不做任何自动上传**：错误、统计、评估数据一律不出本机。
- **不改 3.6.1 已发布契约**：成果记录三态、候选 `checkPayloadIds`、图鉴字段判定、搜索替换范围口径。
- **不做 ghost text**：2026 留存数据（显式调用 ~67% vs 行内建议 ~12%）与本项目方向都指向"不要做"。

**贯穿纪律**

- 先红后绿；涉及存储/下载/恢复的改动必须附失败路径断言。
- 每包结束跑：`typecheck` / `eslint --max-warnings 0` / 相关专项 / 全量单测。
- 收工跑：`node scripts/audit/self-check.mjs` + 六维审计 + `node scripts/release-check.mjs --source-only`。
- **改文案必须同步改断言**：本项目已有多支文案闸（如 `tests/uiStatusCopy.test.ts`），只改代码不改断言 = 下一轮红。

#### W1.5 验收标准（人工动作，缺一不算完成）

1. `node tests/build-test.mjs versionManifest versionCheck updateDownload webVersionNotice` 全通过。
2. **断网**启动 → 3 秒后无弹窗、无错误提示、控制台无未捕获异常。

## 5. 发布与回滚

**发布顺序（固定，不跳步）**

1. 全量门禁绿（第 7 节）。
2. 打包三件产物 → `node scripts/release-version-manifest.mjs` 生成 `dist/version.json`。
3. `node scripts/verify/version-manifest-check.mjs` 自校验清单（体积 + sha256 与产物一致）。
4. `bash server/deploy.sh www`（含 version.json 与 BUILD_ID）→ 线上 `curl -I` 三项缓存头核验。
5. 上传 Release 附件（保留最近三个版本）→ 推送 Gitee / GitHub → 打 tag。
6. 把第 4 步的 curl 结果与第 3 步的清单校验输出写进发布记录。

**回滚手段（按影响面从大到小）**

| 场景 | 手段 | 边界（必须如实说明） |
| --- | --- | --- |
| 网页新包有问题 | `server/deploy.sh` 自带备份与自动回滚；必要时手动指回上一版 | 回滚后 `version.json` 也要跟着回，否则客户端仍被告知"有新版" |
| 清单写错（版本号/摘要） | 只替换 `dist/version.json` 重新部署，**不改代码、不发版** | 已下载到本地的旧清单不影响（客户端每次现取） |
| 桌面新包有严重问题 | 把清单 `version` 回退到上一版 | **只能阻止更多人升级，不能回滚已升级用户** —— 只能尽快发 3.6.3 |
| nginx 配置导致白屏 | 恢复上一份配置并 reload（片段入仓，可回放） | 缓存头错配会让用户"看到旧页面"，回滚后要提示用户强刷 |

| 真机数字抖动 | 阈值被无视 | 连续 3 次取中位；先宽后紧；超阈值先看趋势 |
| 评估集固化标准 | 越写越守旧 | 基线可更新，但每次更新留档理由 |
| 缓存头配错 | 用户长期看旧页面 | 配置入仓可回放；部署后 curl 断言；回滚脚本就绪 |
| 本版范围膨胀 | 延期、半成品 | B9（Worker）默认不做；B7 可降级；任何新想法进 3.6.3 清单 |

## 9. 明确不做

### 9.1 本版不做

- ghost text / 行内自动建议。
- 静默自动安装、后台强制更新。
- 任何形式的自动上传（错误、统计、评估数据）。
- 实时多人协作、平台一键发稿、云端违禁词库订阅。
- 代码签名（提升摘要可信度需要证书，本版只做"传输与镜像一致性"，并在文案里说清边界）。

### 9.2 本版只做"评估"，不做实现

| 候选 | 价值 | 成本 | 需要先回答 |
| --- | --- | --- | --- |
| 听校（TTS 朗读本章） | 高（竞品标配，对"拗口句"最有效） | 低（`speechSynthesis` 纯本地） | 长章分段断点与暂停手感 |
| 写作目标 / 连续天数 | 中（留存） | 低（统计已有基础） | 按"有效字数"还是"输入字数"、跨时区怎么算 |
| 系列级设定共享（跨书 codex） | 高（续作/同世界观痛点） | 高（数据模型 + 同步 + 冲突） | 共享是"复制"还是"引用"；一处改动是否传导 |

### 9.3 可选包（明确推后）

- **W4b Worker 迁移**：默认推 3.6.3。触发条件：真机表显示某单一操作的长任务占比 > 40% 且 P95 > 200ms。届时要求同步回退 + 逐字节对拍。

## 附录 B · 与 3.6.1 规划的关系

- 3.6.1 处理"代码内部欠账"（覆盖率、未接线），验收靠静态检查与单测闭环。
- 3.6.2 处理"发出去之后的欠账"（版本、诊断、真机、AI 质量），**验收必须含人工动作**（装一次、断一次网、拖一次窗口、用键盘走一遍）。
- 两者不重叠：3.6.1 台账已清零，本版不重开；本版新增的门禁会成为 3.6.3 的常规项。
