**一个刻意的语义修正（规划没写，但不改就是假绿）**：写锁状态下内存是空库，
跑体检会得出「未发现问题」——而真实情况是「数据没读出来」。已在采集器里前置判断：
写锁时 `health.ok=false` 且 `reason='数据文件读取失败（写锁中），本次体检结果不可用'`。

**一处如实降级**：`storage.dataSizeBytes` 本版**未采集**（返回 null）。原因：主进程没有
stat 接口，而 `src/lib/app/desktop.ts` 已贴着 1200 行硬线，不为一个排障字段破它。
`null` 与「0 字节」是两回事，代码与包结构里都写明了。「最近修改时间」用桌面桥现成的
`lastSavedAt`（本应用自己写盘的时刻，比文件 mtime 更可信）。

**红条与诊断包的路径口径差异（有意，不是漏改）**：红条那条文本**仍带数据文件路径**
（判断"是否落在云盘同步目录"必须看路径，且是用户主动复制给作者的）；诊断包（.json，
可能被贴到公开 issue）**不带路径**，只报「默认/自定义位置」类别。两处共用同一套
采集与同一套判定函数，但渲染口径不同。

**一处实现细节值得记**：`planBackupRetention` 返回的删除顺序做了 `reverse()`，
让它是"最旧优先"而不是"次新→最旧"。这不影响调用方逐个删的结果，但**语义与注释必须一致** ——
否则下一个人照着注释理解，会在别处复用时写出反序逻辑。测试里有一条正向闸钉住这点。

**规划没写、但不做就是假绿的一处**：`runBackupDrill` 有 `maxPoints` 上限（默认 24）。
超出的份数**必须**带出来并写进结论（"另有 N 份未检查"）——
把"没检查"说成"没问题"是这类体检最容易犯的错。

🔴 **写测试时抓到一个真 bug（已修）**：`recordAiMetric` 最初写成
`void (async () => { const list = await load(); cache = append(list) })()` ——
连续五次点击几乎同时进入，五次都拿到同一个旧 cache、各自 append 一次，
**最后只剩最后一条**（前四条被吞）。改成把「读-追加-写」整体排进 `writeChain` 逐条执行后计数才对得上。
这类"并发记录丢数据"的缺陷靠人工点几下**看不出来**，必须靠连续调用 + 断言计数才能暴露。

关键几条：
- 采纳率 = `accepted / shown`；`shown = 0` 时为 **null**（不是 0，不把"没展示过"算成 0%）。
- 环形上限滚动：超了丢最旧。
- **键空间隔离**：落在全局 `meta`（不是项目 `settingsKV`），换项目不串、重启不丢、清空后不复活。

**本轮修的真缺陷**：投稿广场浮层有 `role="dialog"` + `aria-modal`，但**没有键盘出口、也不接管焦点** ——
键盘用户打开后只能靠 Tab 一路摸到关闭按钮，关闭后焦点掉回 `body`。已补三件套缺失的两件。

**刻意不做焦点陷阱**：广场是长滚动容器，把 Tab 锁在首屏反而让人到不了下面的投稿流；
WCAG 2.1.2 要求的是「不能被键盘困住」，Esc 随时可退出已满足。

**静态验收到的正项**：全仓**没有**正 `tabIndex`（不会打乱 Tab 顺序）；有全局 `focus-visible` 样式；
`xs` 档按钮高 24px（WCAG 2.2 下限）、图标键 32px、触摸设备有 44×44 热区规则。

顺带修的脚本缺陷（不是规划条目）：

- 网页版验收脚本原假设「首屏就是 SPA」，实际线上首屏是**独立静态登录页**（`server/lib/authPage.mjs`），脚本会停在登录页把入口全判红。已加：无 `--login` 时自动走 `<a href="/guest">` 游客入口，并在结果里标注「游客/账号本机（IndexedDB，未验服务端存储）」。
- `carrier.web-cloud` 原要求 `__YFE_WEB__ && __YFE_PORTABLE__` 同时为真，但 `__YFE_PORTABLE__` **只在已登录且云同步时才注入**（`server/index.mjs:490`）⇒ 游客/账号本机必然误判。改为只要求 `__YFE_WEB__`，存储形态写进 detail。
