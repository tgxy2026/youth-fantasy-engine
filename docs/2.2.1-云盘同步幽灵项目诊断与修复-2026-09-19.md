# 云盘同步「幽灵项目」诊断与修复（2026-09-19）

> 现象：**删掉的项目，每次打开软件又出现在项目管理页** —— 反复出现，删多少次都没用。
> 老大原话：「好像有一个历史阶段的备份，总是在打开软件的时候，就莫名其妙地被读取并被推送到前端，
> 然后它需要一点时间才能替换成当前最新的版本。」

## 一、老大的观察直接锁定了问题（这份记录要留着的方法论）

| 老大的观察 | 对应到的代码 |
|---|---|
| 打开软件先显示「设云同步时候的样式」 | `ensureInit()` 里 `cache = 解密后的云端快照` —— **内存被整体替换成云端那一版** |
| 过一会儿 / 打开项目后才变成正确样子 | 云盘目录短暂不可用时包装层**闩锁切到本地库**，读到真正的最新数据 |
| 删掉的项目总会回来 | 三路合并没有「删除记忆」：基线为空时把「云端有、本地没有」一律判成**另一端新增** |

**先取证再下结论**（没猜）：读老大机器上的真实数据 → 挖出 4 个项目、其中「青春幻想录」是
`0 卷 0 章` 的空壳（数据被级联删过、项目壳又回来），且备份区有**两条内容相同、ID 不同**的孤儿备份
——「建了又删」的循环痕迹。

## 二、根因（两条代码缺陷 + 一条环境因素）

### 缺陷 ① 合并没有「删除记忆」——这是幽灵项目的主因

```ts
// syncCore.ts（修复前）
let baseCache: Record<string, any[]> = {}        // ← 内存变量，每次启动都是空的
...
if (lo === undefined) {          // 本地没有这条记录
  if (b === undefined) {         // 基线里也查不到 → 无法判断是谁删的
    arr.push(sv)                 // 一律判成「另一端新增」→ 采用云端 ❌
```

于是：云端还留着的旧记录（含早已删掉的项目）被搬回来；**搬回后又被推回云端** →
自此云端、本地、基线三方都有它 → **删多少次都会回来（自锁）**。这正是「每次打开都出现」。

### 缺陷 ② `ensureInit` 用云端快照**整体替换**内存，而不是合并

```ts
if (resp.enc) {
  cache = await decryptObj(resp.enc)   // ⚠️ 整体替换
  adoptCloudBackup(cache)
}
```

启动后界面先显示**云端那一版**（老大看到的「旧样式」），本地数据要等闩锁后才生效。

### 环境因素（放大了上面两条）

老大的同步目录选在 **`WPSDrive\...\WPS云盘\...`** —— 那是 WPS 的**虚拟盘**（按需下载），
**不是** WPS 的「同步文件夹」功能（真实本地目录）。虚拟盘的读写一致性没有保证，
`.yfe` 未必等于云端版本，于是「云端长期停在旧版本」被放大成常态。

实测证据：`青春幻想引擎-同步数据.yfe` **确实在写**（17:00，1.66MB），
但 `WPS Cloud Files\<id>\` 下**只有「漫游文档」** —— 说明「同步文件夹」功能根本没启用。

## 三、修复（纯代码侧，已提交 `02a29c0`）

| 改动 | 说明 |
|---|---|
| **新增 `src/lib/syncTombstone.ts`** | 删除墓碑：本机明确的删除记忆，落 localStorage。挂在 `cloudStore` / `desktopStore` 的 `del` / `bulkDel`（关闭同步期间的删除同样要记）；`put` / `bulkPut` **自动清墓碑**（允许「删掉又重建」，避免变成删得掉、进不来的死记录） |
| **`mergeCaches`** | 「本地没有这条」时查墓碑 → 有墓碑 = 尊重删除；无墓碑 = 采用云端 |
| **⚠️ `localHasContent` 安全闸** | 本地整库为空时（新设备首同步 / 启动瞬间）**不启用**墓碑判定，必须采用云端 —— 否则会把整库云端数据丢掉，**比幽灵项目严重得多** |
| **`ensureInit` 改走三路合并** | 并通过新增的 `onLocalSnapshot` 注入「**本地库快照**」作为 `local` 路 —— 云模式下内存 cache 启动时是空的，拿它当 local 根本判断不了「本机删了」还是「还没拉下来」 |

**为什么用墓碑而不是「曾存在过名单」**：后者无法区分「本机删了它」和「本机还没见过它」，
在整库为空时会误判成删除 → 丢云端数据。墓碑表达的是明确的**删除意图**，语义无歧义。

## 五、环境侧建议（待老大操作）

**把同步目录从「虚拟盘」换到「真实本地文件夹」**：

| 做法 | 说明 |
|---|---|
| ✅ 推荐：WPS 云盘设置里开启「**同步文件夹**」 | 指向一个普通目录（如 `D:\YFE同步`），再把软件的同步目录选到它 —— 云盘客户端负责搬运，app 只跟真实文件系统打交道 |
| ✅ 备选 | 用 OneDrive / 坚果云等的**本地同步文件夹**（同类且更常见） |
| ⛔ 避免 | 任何「虚拟盘 / 在线占位文件」路径（`WPSDrive`、`WPS云盘`） |

**验证方法**：换完后在软件里改一点东西 → 等 10 秒 → 看那个 `.yfe` 在**另一台设备或网页版云盘**上
是否也变了。若变了，说明「写入 → 上传」这条链路真的通了。

**已复活的「青春幻想录」怎么清**：修复后**正常删一次**即可 —— 墓碑会记住这次删除，
并把删除后的快照正常推上云端，不会再复活。

## 六、2026-09-19 17:30 补记：实际清理过程（含两条新踩的坑）

### 🔴 坑 1：只清本地没用 —— 启动时会自动恢复云模式

```ts
// db.ts:492
if (CLOUD_FILE_SYNC) {
  const ok = await applyDesktopCloudFromPersisted()   // ← 启动即恢复云模式
  if (ok) {
    let empty = true
    try { empty = totalRecords((await pullDesktopSnapshot()).stores) === 0 } catch { return }
    if (empty) { clearDesktopCloudEnabledFlag(); return }   // 云端为空 → 留在本地
    ops = desktopCloudFileStore                             // 云端非空 → 切过去
  }
}
```

**云端非空就切过去** → 光改本机数据文件，一启动又被云端覆盖回来。
所以「云端那份」也必须处理。

### 🔴 坑 2：WPSDrive 虚拟盘上，「改名」会被回滚，「删除」才生效

| 操作 | 实测结果 |
|---|---|
| `mv 青春幻想引擎-同步数据.yfe 同名.yfe.旧-<时间戳>` | ❌ **被回滚** —— WPS 又把云端那份同步下来，名字变回原样 |
| `rm 青春幻想引擎-同步数据.yfe` | ✅ **生效**（等 5 秒未见回滚） |

所以要让云端变空，**只能删**（删前先复制一份到别处留档）。这也解释了这个虚拟盘为什么
会把「app 刚写的 .yfe」用云端旧版本盖掉 —— 正是幽灵项目被放大的环境原因。
