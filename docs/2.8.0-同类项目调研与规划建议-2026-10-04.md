> 目的：联网核查近几个月发布的同类开源项目，逐项与「青春幻想引擎（novel-studio 2.8.0）」对比。
> **已实现的剔除、不重复规划；只在「我们没有」或「他们路线更优」时才进规划。**
> 本次只做调研与规划记录，**不动任何源码**。

## 一、调研范围与方法

- **自家基准**：`src/` 全量功能盘点（11 个功能域、约 115 条已实现能力）+ `docs/优化清单.md` 台账（12 条）。
- **同类样本**：联网检索 2026 年近几个月活跃的开源 AI 小说/长文创作项目，覆盖「单机 GUI / CLI Agent / 本地 Web 工作台」三种形态。
- **判定口径**：
  - 🟢 **已有**（我们已实现，含路线更优者）⇒ 不重复规划
  - 🔵 **建议纳入**（我们没有，或他们路线明确更优）⇒ 进规划
  - ⚪ **观察项**（有价值但优先级低 / 与「只做桌面版」定位不合 / 边界待定）

| 能力 | 我们 | 同类做法 | 判定 |

## 四、结论

### A. 已有能力（**不重复规划**）

三级大纲、结构化设定体系、关系图/时间线/地图、**伏笔状态机 + 超期告警**、**爽点节奏管控**、**10 类吃书静态检测**、章节摘要滚动、每章设定同步、拆书/续写导入、去 AI 味、逐章审核 + 自动连写、多模型配置、上下文预算按窗口自适应、云盘同步/备份/加密迁移、多元导出、酒馆模式 —— **共约 30 项已具备，同类中多为领先或持平**。

### B. 建议纳入规划（🔵 按优先级）

| 优先级 | 条目 | 差距性质 | 要点 / 落地口径 |
|---|---|---|---|
| **P1** | **语义检索 / 向量 RAG 长程记忆** | 我们从「关键词 + 结构化挑选」→ 提升为「语义召回」 | **可选启用**：云端用 embedding API，本地用 Ollama embedding 模型；把「当前章相关的历史片段 / 设定 / 事件」按语义相似度召回后注入。**与既有 `aiContext` 结构化选材互补**，不是替换。注意保持离线可用（未配 embedding 时自动回退到现方案） |
| **P2** | **多 Agent 模型路由** | 我们现在只有一个当前模型 | 允许给「创作类」与「审校/整理类」分别指定模型（创作用好模型、批量整理用便宜模型），落到模型设置页；与现有门禁/预算体系衔接 |
| **P3** | **文风指纹（从参考文本分析并注入）** | 我们只有预设维度多选 | 让作者投喂 1~2 段参考文本 → AI 提炼「文风指纹」（句长分布 / 用词倾向 / 节奏 / 修辞习惯）→ 存为可命名的风格档，供伴写/续写/改写注入。与 `companionStyle` 并存 |
| **P4** | **全书优化工单 + 逐章自动修订 + 修改前后 diff** | 我们停在「诊断 + 手动改写」 | 完稿后一键诊断 → 汇总为可勾选的优化工单 → 逐章自动修订 → 提供**修改前后对照视图**。复用既有「整章改写五档」与「创作轨迹」 |
| **P5** | **知识库挂载（外部文档长期参考）** | 拆书是一次性 | 允许长期挂载外部参考文档（设定集 / 资料），写作时按需检索注入。与 P1 的 RAG 天然合流 |
| **P6** | **市场雷达（选题趋势分析）** | 手填 → AI 分析 | 「作品信息」旁增设趋势分析入口（可选联网），给赛道/题材/平台偏好建议。**依赖联网检索，默认关闭** |

### C. 观察项（⚪ 不排期，记录备查）

- 章后「核查不通过自动重写」的自动化程度 —— 待核对现状后决定是否升级
- 同人 / 番外「保持正传 canon」的专门模式
- 对话式创作 / 自然语言操作书籍
- Token 用量台账
- InkOS 式「33 维审计」的维度体系化（我们颉文姬 8 件套已覆盖主干，是否细分待定）
- InkOS 式「状态结算阶段（JSON delta + schema 校验 + 不可变更新）」——可作 P4 的实现路线参考

### D. 差异化优势（**不建议跟风**）

- **网文商业性体系**：爽点节奏表、黄金三章检查、爽点/毒点管理、开书商业档案 —— 同类几乎都没有
- **伏笔体系**：编号 + 计划回收位置 + 回收前置条件 + 状态机 + 闭环看板
- **结构化选材 + 保密等级**（防剧透的上下文治理）
- **数据自控**：云盘同步 + 每日备份 + 加密迁移包（同类多为纯本地单机，无同步）
- **可视化三件套**：关系图 / 时间线 / 地图编辑
- **酒馆模式**（角色扮演）
- **桌面端 + 离线优先**（同类多为 CLI 或需自部署服务器）
- **工程质量体系**：结构闸门 + 循环依赖闸 + 六维审计

> ⚠️ **红线声明**：本调研**不引入任何「反检测 / 洗 AI 痕迹」类功能**。InkOS Studio 的「AI 检测」若对照到我们，只允许做「AI 味**自检报告**（如实呈现给作者）」这一口径，不得用于掩盖或伪造创作过程。

## 五、建议落地顺序

```
P1 语义检索/RAG  ─┬─→ P5 知识库挂载（同源，可合并设计）
                   └─→ P3 文风指纹（可复用 embedding 管线）
P2 多 Agent 路由 ──── 独立，工程改动小，可先行
P4 优化工单+diff ──── 复用既有改写链路，可作为「完稿后」闭环
P6 市场雷达 ──────── 依赖联网，最后做
```

**给主人的一句话**：我们真正该补的，是**「语义记忆」这一块底层能力**（P1/P3/P5 同源），其余多为锦上添花；而「网文商业性 + 伏笔闭环 + 数据自控」这些是我们的护城河，不必向 CLI Agent 型项目靠拢。
