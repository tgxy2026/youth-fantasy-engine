# 3.2.3 R4 · P0 缺口：游客模式导入「桌面/便携导出文件」会静默清库

> 日期：2026-10-24｜发现：可可（在做跨形态往返测试时撞出来）｜基线 `main` / `76e22ec`
> 性质：**已实测复现的数据丢失缺陷**。按红线「未点名禁动代码」——**本轮只记录，未改产品代码**。
> 影响面：游客（浏览器本地）模式下的「导入数据文件」。

## 1. 一句话

游客点「导入数据文件」选了一份**桌面版或便携版导出的 JSON**：界面提示「导入成功」并刷新，
然后**库里一条数据都没有** —— 既没导进来，原来浏览器里的稿子也被清空了。

## 2. 为什么会这样（三处叠加）

| 环节 | 代码 | 事实 |
|---|---|---|
| 三端导出格式 | `guestDataObject()`（游客）/ `data.stores`（桌面、便携） | 都叫 `kind:'portable-data'`，但 **`stores` 的行形态不同**：游客是**行数组**，桌面/便携是**主键→记录的对象** |
| 导入校验 | `guestData.ts:120` | 只查 `app`/`kind`/`stores` 是对象 ⇒ **键化形态能通过校验** |
| 逐 store 写入 | `guestData.ts:126-137` | `const incoming = Array.isArray(o.stores[name]) ? o.stores[name] : []` ⇒ 键化形态被当成**空数组**；随后 `bulkDel` 先清空既有数据 |

于是：**校验放行 → 清空 → 写入 0 条 → 返回 `{ok:true}`**。界面据此提示成功并 reload。

## 3. 实测证据（手动探针，非门禁）

`tests/importGuestShapeProbe.ts`（跑法：`node tests/build-test.mjs importGuestShapeProbe`，不进分批清单）

```
PASS 前置：本地已有 1 项目 / 1 章
PASS 键化文件：importGuestData 返回成功
FAIL 键化文件：导入后项目仍在（不丢） :: {"projects":[],"chapters":[]}
FAIL 键化文件：导入后正文仍在（不丢） :: {"projects":[],"chapters":[]}
FAIL 键化文件：确实换成了文件里的内容 :: {"projects":[],"chapters":[]}
PASS 数组文件：导入成功
PASS 数组文件：内容正确
PASS 自往返：游客导出 → 游客导入 成功
PASS 自往返：正文与标识不变
———— importGuestShape：6 通过 / 3 失败 ————
```

即：`importGuestData` **返回成功**，但两个 store 都变成空数组 —— 本地原有内容消失，文件内容也没进来。

## 4. 触发面与后果

| 维度 | 判断 |
|---|---|
| 谁会遇到 | 从桌面/便携迁到网页游客的人；或把朋友发来的备份丢进游客导入的人 |
| 数据后果 | **双向丢**：本地原有数据被清空 + 导入文件的内容没落地；且界面说"成功" |
| 可恢复性 | 若此前没导出过，浏览器里那份**不可恢复**（除非有导出副本） |
| 与已知提示的关系 | 导入弹窗写的是「用所选文件的【全部内容】替换当前浏览器里的全部数据」，并没有说"只接受游客导出的文件" |
| 严重度 | **P0（数据丢失 + 假成功）** |

## 5. 建议修法（一行级，等主人点头）

`src/lib/db/guestData.ts` 的逐 store 取值改成两种形态都收（与 `normalizePortableData` 同口径）：

```ts
// 现在
const incoming = Array.isArray(o.stores[name]) ? (o.stores[name] as unknown[]) : []
// 建议
const raw = o.stores[name]
const incoming = Array.isArray(raw)
  ? raw as unknown[]
  : (raw && typeof raw === 'object' ? Object.values(raw as Record<string, unknown>) : [])
```

再补一条**门禁**用例（把 `tests/importGuestShapeProbe.ts` 的键化那段改成正式 `.test.ts` 进 BATCH_B），
这样「反向导入」就不会再退化。改动范围：一个函数 + 一条测试，不碰导出链路、不碰服务端。

**替代方案**（更保守）：不改行为，只**拒绝**：校验到 `stores` 里存在非数组的 store 时直接报错
「这是桌面/便携导出的文件，请到对应版本导入」——不丢数据，但游客也无法从桌面迁移过来。

## 6. 顺带确认没问题的部分

同一轮跨形态往返测试（`tests/profileRoundtrip.test.ts`，15 条断言，已进 BATCH_B）证明：

- 游客**数组形态** → `normalizePortableData`：主键索引、正文、备份载荷全部保留；
- 桌面/便携**键化形态** → `normalizePortableData`：原样保留（说明"键化"本身不是坏数据，只是 `importGuestData` 不认）；
- 归一化**幂等**：反复导入不会越导越少；
- 被数组展开污染的老文件（`{"0":…,"1":…}`）能按真实主键重建；
- 游客**自往返**（导出→导入）内容逐字一致。

也就是说：**格式契约本身是好的，缺的是游客导入这一侧对键化形态的兼容。**
