## 二、候选池（按推荐优先级）

### A1 · 世界设定 / 力量体系 自由文本草稿框（2.5.0 期备忘，建议本批必做）

- **需求**：C10 母子结构（`lib/worldSets.ts`）已落地——母级 form 不动、子级外挂 `cardRecords`；但两个页签都还缺一块**自由文本草稿区**（不成字段的随手设定、备忘）。
- **方向**：每页签（含母集与各子项）加一块自由文本编辑框，随项目存储；🔴 不进 AI 上下文默认喂送名单（如要喂须显式设计，防长文本撑爆预算）；🔴 编辑器走既有 `textarea.novel-textarea` 双图层口径（若带高亮）或普通 textarea（若纯文本，则不碰双图层）。
- **量级**：小~中。**中止判据**：若与 cardRecords 活跃态/草稿落库机制冲突难解 → 只做母集一处。

### A2 · 2.5.1 验收债补验（随本批首批实机一并带走，不单独立项）

- B2 实机 F11 真全屏（安装包环境）；A3 灵感融合「换汤不换药」对比测试；D1 导师预设无污染实机验。
- **量级**：极小（纯验证）。全部通过即在开发记录核销。

### B 组 · 大项（择一作重头戏，或都不选保持轻量版）

#### B-候选① · 一键拆书（大项，规划稿已在库）

- **输入**：现成小说文本（txt / docx）→ **处理**：AI 结构化抽取 → **输出**：以**草稿**形式回填世界设定、角色卡、关系、地理、势力等模块（人工校对后采纳，绝不自动覆盖）。
- 方案底稿：`docs/一键拆书-方案规划.md`（基于调研 + 项目实情，AI 层/解析层/回填通道均可复用）。
- 🔴 **动工前先做侦察**：该规划稿基于 2.1.3，而 BookBreak / `docxImport` / 实体抽取（`extract-entities`）等已有部分能力——先盘点「已消化多少」，只补缺口，不重造。
- 🔴 **AI「整理」产出须两道本地兜底**（红线）：候选值＝库里已有 ∪ 本次刚抽实体名；产出后按名单本地过滤＋给原文依据。
- **量级**：大（多批次）。

#### B-候选② · 自绘标题栏（#006 方案②，桌面体验向）

- frame:false + 自绘 最小化/最大化/关闭 + 拖拽区 + 与 F11 全屏态联动（全屏时隐藏自绘栏）。
- **量级**：中。**中止判据**：与系统窗口管理（Snap 布局 / Win+方向键）冲突难解 → 保持「另行评估」不动。
