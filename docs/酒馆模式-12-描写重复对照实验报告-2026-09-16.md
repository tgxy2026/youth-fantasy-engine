## 一、结论先说

## 二、实验设计

| 项 | 设定 |
|---|---|
| 载体 | 本机 `orcarouter/Qwen3.8-27B-Uncensored:q6_K`（Ollama 0.34.1），RTX 5090 |
| system | **真实产物** —— 走 `buildFreeSystem()`（真协议 v1.9 全文 + 真角色卡层），非手工拼的 |
| 角色 | 苏念（AI 扮演）× 楚楠（用户扮演），行为脚本 5 轮，各组**逐字相同** |
| 采样 | 固定 seed（101 + 37n）、固定 `num_ctx 32768`；除被检变量外与出厂一致 |
| 规模 | **11 组 × 8 次 × 5 轮 = 440 次生成**（约 8.5 分钟）|
| 主指标 | 手部专项词动作行 ÷ 动作行总数 |
| 副指标 | 同拍复现率（相邻两轮用了**同一个**手部词）、与上一轮的 3-gram 重合、动作行密度 |

**三条控制变量纪律**：① 固定 seed（随机流起点相同）；② 用户台词逐字相同（唯一变量是参数或 system）；③ 跑**多轮**而不是单轮 —— 症状本身就是「跨轮复读」，单轮量不出来。

**⚠️ 一个必须交代的坑**：这个模型是**思考型**，不传 `think: false` 时整段产出进 `message.thinking`、`content` 为空（实测 `num_predict` 被思考吃光，一个字都拿不到）。实验全程 `think: false` —— 这与 app 出厂设置 `disableThink: true`（`settings.ts:361`）一致，所以也是最贴近真实配置的跑法。

**手部词口径**（只认专项词，**不含光杆「手」**）：指节 / 指尖 / 手指 / 拇指 / 指甲 / 手掌 / 掌心 / 手腕 / 手背 / 手臂 / 手肘 / 拳头 / 攥 / 捏 / 抠 / 握 / 摩挲。
（第一版用了裸「手」，把「顺手拿下一罐」也算成手部动作，噪声很大 —— 已改掉。）

### 3.3 拧大重复惩罚为什么会把格式打崩（机制）

B 组的原始输出（第 1 次）节选 —— 四处都是**协议硬性格式的坍塌**：

```
第1轮：便利店外的雨声没停过。（灰色围裙被雨水打湿了一角）楚楠站在货架旁扫视商品，左手腕上的旧疤在灯光下格外显眼。“要什么。”…（拿起杯子开始制作饮品
        ↑ 旁白跑到括号外        ↑ 代写了用户角色楚楠        ↑ 对白加引号        ↑ 括号没闭合，断了
第2轮：雨点敲打着玻璃门。苏念停下手里的动作，看着面前空无一人的收银台区域。（左手拇指无意识地摩挲着指甲边缘）那杯刚做好的热美式还冒着热气。”要拿吗。“
        ↑ 整段无换行            ↑ 引号配反（”要拿吗。“）
第4轮：（挑了挑眉，手上整理货架的动作停了）行。（转过身去继续理货不再看你咖啡杯上的热气慢慢散掉雨声还在下玻璃门外的路灯昏黄一片…）
        ↑ 一整轮回合成一段，标点丢失
```

**机制**（与诊断报告的射程分析同源，但结论更狠）：
`repeat_penalty` 是**乘性**惩罚，作用在**窗口内 token 的 logit** 上。而 `（` 与 `）` 这对括号**每一行动作都要出现一次** —— 它们在 64 词的窗口里是出现频率最高的符号之一。把系数调到 1.4，模型被惩罚得**不敢再吐括号**，于是：
1. 干脆不写动作行（2.08 → 0.43 行/轮）；
2. 硬要写时，括号只开不闭（避免重复出现 `）`）；
3. 旁白被挤到括号外，直接违反 O1；
4. 行结构崩掉后，R2（不代写用户角色）也跟着破。

**这正是「调参数不看射程」的典型下场：旋钮拧的不是重复，是格式。**

### 3.4 提示词的位置比内容更关键

同一段反重复文案，放两个位置，效果天差地别：

| 位置 | 手部率 | 同拍复现率 |
|---|---|---|
| 埋在协议中段（改 B7 + 新增 O5）| **28.2%**（基线 28.9%）→ 等于没改 | 2.6% |
| 钉在协议末尾「最后提醒」| **22.9%**（−21%）| 2.6% |

原因：`protocol.ts` 文件头自己就写了 ——「最后提醒」**紧贴生成点，近因效应权重最高**。协议有 3200 多字、30 多条规则，中段加两条等于扔进海里。

> ⚠️ 顺带一条实践结论：**往这份协议里加规则，只有加在「最后提醒」才可能生效。** 以后改协议优先考虑这个位置，别默认往中段加。

### 3.5 扩窗与词频惩罚必须同时开

| 做法 | 手部率 | 结论 |
|---|---|---|
| 只开窗（512）| 27.7% | **无效** —— 窗口拉大只是让同一个小惩罚作用于更多 token |
| 只加词频（0.1，窗仍是 64）| 26.1% | 略有效，但射程只到半句话，跨轮仍够不到 |
| **两者同时** | **20.3%** | ✅ 词频惩罚的**按次数累加**特性，只有在窗口够长时才碰得到「上一轮用过的词」|

**换句话说：射程是「能不能够到」，词频惩罚是「够到之后扣不扣分」。缺一个都不成。**

### 3.6 词频惩罚的强度是「效果 ↔ 描写密度」的取舍

| 强度 | 手部率 | 动作行/轮 | 备注 |
|---|---|---|---|
| 0（关）| 28.9% | 2.08 | 基线 |
| **0.1** | 20.3%（+提示词后 13.4%）| 1.73（+提示词后 1.68）| ✅ **选定** |
| 0.2 | 15.6% | **1.13** | 更干净，但描写密度掉 46% |

0.2 的效果更强，代价是**模型宁可不写动作也不重复用词** —— 与老大要的「客观描写/沉浸感」背道而驰。所以默认取 **0.1**，0.2 作为面板上的可选项保留给追求极致去重的人。

## 四、端到端复核：落地之后实机到底发出去什么

实验里的参数是我在脚本里写的 —— 「脚本写对了」不等于「实机发的是这个」。所以补一组 **V**：
options **现算**，走真实链路 `getTavernSettings() → resolveParamsOf('free', st) → toOllamaOptions()`，
system 也走真实产物（协议 **v1.10**，含末尾那条反重复提醒）。

**实机链路算出来的 options（逐字打印）：**

```json
{"temperature":0.95,"top_p":0.92,"top_k":60,"repeat_penalty":1.05,
 "frequency_penalty":0.1,"repeat_last_n":512,"presence_penalty":0.55,"num_ctx":32768}
```

**结果（各 40 轮）**

| 组 | 动作/轮 | 手部率 | 手部轮次率 | 同拍复现率 | 3gram 重合 |
|---|---|---|---|---|---|
| A 旧出厂（窗 64 / 无词频，协议 v1.9）| 1.70 | 25.0% | 40.0% | 2.6% | 0.5 |
| **V 实机默认（窗 512 / 词频 0.1，协议 v1.10）** | **1.80** | **16.7%** | **27.5%** | **0.0%** | **0.1** |

→ 手部率 **−33%**、同拍复现 **归零**，而**动作行密度不降反升**（1.70 → 1.80）。落地是通的。

### ⚠️ 噪声披露（必须说）

同一份 baseline 配置跑了两次，拿到 **28.9%** 和 **25.0%** 两个数（差 3.9 个百分点）。
原因：**固定 seed ≠ GPU 上逐位可复现** —— llama.cpp 的 CUDA 归约顺序不定，同样的 seed 也会有微差。

所以解读口径是：**基线噪声带约 ±4pp，而落地组稳定落在 13–17%** —— 差异远在噪声之外，结论成立；
但**不要把「15.6% vs 17.1%」这种组间小差距当成真的**（C 与 E 的差别就属于这一类）。

## 六、落地清单（已实施）

### 5.1 两把新旋钮（老大要求：汉化标签 + 取值范围 + 文字说明，两个窗口分别设置）

| 项 | 内部字段 | Ollama 字段 | 面板中文标签 | 出厂值 | 取值范围 | 单位 |
|---|---|---|---|---|---|---|
| 词频惩罚 | `frequencyPenalty` | `frequency_penalty` | **词频惩罚** | 0.1 | 0 ~ 2（步进 0.05）| — |
| 惩罚射程 | `repeatLastN` | `repeat_last_n` | **惩罚射程** | 512 | 0 ~ 4096（步进 64）| 词元 |

两项目都进了 `GUIDE_SAMPLING`（与温度/核采样/候选词上限/重复惩罚/新话题倾向同规格），
各自带**分段表**（每段有档名 + 说因果的影响说明 + 恰好一个推荐段），面板会自动渲染「取值范围 + 当前值落在哪一段」。

**改动落点（六处，与既有参数完全同构）**

| # | 文件 | 改了什么 |
|---|---|---|
| 1 | `src/lib/tavern/paramGuide.ts` | 新增 `GUIDE_FREQUENCY_PENALTY` / `GUIDE_REPEAT_LAST_N`，并入 `GUIDE_SAMPLING` |
| 2 | `src/lib/tavern/types.ts` | `TavernParams` 加两字段；`TAVERN_DEFAULTS.plot/free` 各加 `frequencyPenalty: 0.1` + `repeatLastN: 512` |
| 3 | `src/lib/tavern/params.ts` | `toOllamaOptions()` 输出 `frequency_penalty` / `repeat_last_n` |
| 4 | `src/lib/tavern/settings.ts` | 两个模式设置类型 + `DEFAULT_TAVERN_SETTINGS` + `modeParamsLayer()` |
| 5 | `src/components/TavernControl.tsx` | **六、剧情推演控制**与**七、自由对话控制**各加两个 `NumField`（排在「重复惩罚」之后）|
| 6 | `tests/` | `paramGuide`（5 项 → 7 项、默认值落推荐段、单位断言）、`tavernPrompt`（字段映射断言）|

**老库怎么办**：`getTavernSettings()` 走 `mergeDeep(DEFAULT, 存库值)` —— 存库里没有这两个键时**取默认值**，所以老用户升级后自动获得新出厂值，**无需** `upgradeLegacyDefaults`。

**云端通道**：`frequency_penalty` 本来就在 `OPENAI_SAFE_SAMPLING` 白名单里（`ai.ts:450`），所以云端模型也会收到 0.1 —— 这是 OpenAI 的原生参数、量级很轻，属于顺带受益；`repeat_last_n` 不在白名单，会被正确丢弃（Ollama 专有字段，发过去会 400）。

### 5.2 协议升 v1.10（反重复条款钉在「最后提醒」）

`src/lib/tavern/protocol.ts` 的 `PROTOCOL_CORE` 末尾「最后提醒」新增：

```
⚠️ 不许复读自己：上几轮写过的身体反应，这一轮换一处 ——
手部动作（攥 / 捏 / 抠 / 指节 / 掌心 / 指尖）在最近三个回合里出现过，这一轮就别再写手；
改用停顿、语气、答非所问；非要写身体，就换一个部位。
```

**三处同步（红线）**：正文版号 `v1.9 → v1.10` ✅　`PROTOCOL_VERSION = 'v1.10'` ✅　v1.9 全文原样追加进 `LEGACY_PROTOCOLS` ✅（现共 10 份：v1.10 + v1.1~v1.9）。
⚠️ 本次**没有**采纳诊断报告建议的「改 B7 + 新增 O5」—— 实验显示那个位置基本无效，加了只是徒增维护面。

- 手部率只统计**专项词**。落地组仍会用「伸手从货架底层抽出」「拿抹布擦着手背」这类**动词式**手部动作 —— 它治的是**noun 型陈词**（指节/指尖/指甲），不是「一切手部动作」。而老大反馈的症状恰恰是 noun 型陈词，所以口径是对的。
- 「手部率 13.4%」不等于「没有手部描写」，而是「不再是每轮一个手部名词」。
