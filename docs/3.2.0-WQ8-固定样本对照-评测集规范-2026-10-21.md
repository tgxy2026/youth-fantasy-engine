# WQ8 · 固定样本对照 · 评测集规范（2026-10-21）

> 用途：`qualityGuard.compareWithFixedSample` / `batchCompareWithFixedSamples` 已有实现与通路，
> 缺的是**样本本身**。本文说明怎么填、填在哪、哪些红线不能破。
> 代码入口：`src/lib/ai/factSamples.ts`（示例与自检）｜`tests/fixedSamples.test.ts`（通路与消费）。

## 1. 样本放在哪

| 内容 | 位置 | 是否入库 |
|---|---|---|
| 示例样本（虚构，2 条） | `src/lib/ai/factSamples.ts` 的 `DEMO_SAMPLES` | ✅ 入库 |
| **真实样本**（作者自己的书） | `.workbuddy/eval-samples/samples.json` | ❌ **不入库**（`.workbuddy/` 已 git 忽略） |

🔴 **真实正文绝不进 `src/` 或 `docs/`**。样本是作者的作品原文，和 `.arts/`、`.workbuddy/` 同级对待。
🔴 也不进同步与备份（`.workbuddy/` 本就在排除表里），换机时需要手动带走。

## 2. 文件格式

```json
{
  "samples": [
    {
      "sampleId": "typo-basic-01",
      "input": "改写前的正文（一段，200–800 字）",
      "expectedOutput": "作者手工改定的版本",
      "tolerance": 12
    }
  ]
}
```

| 字段 | 怎么填 | 常见错 |
|---|---|---|
| `sampleId` | 稳定可读，`问题类型-场景-序号`（如 `typo-basic-01`、`sensitive-battle-02`） | 用中文长句、或每次跑都换 id（历史结果对不上） |
| `input` | **改写前**的正文，取一章里的一次真实片段 | 用 AI 生成的假文（那样对照没意义） |
| `expectedOutput` | **作者手工改定**的版本 —— 这是"期望"，不是模型输出 | 🔴 把模型输出粘进来当期望（等于让模型给自己打分） |
| `tolerance` | 允许的字符数差 | 填 0（真实改写必然有字数变化，填 0 等于必挂） |

## 3. 容差怎么定（别拍脑袋）

1. 先按 `tolerance: 20` 跑一轮，记录每条的 `charDiff`；
2. 取这组 `charDiff` 的 **P90 的 1.5 倍**作为该类问题的容差（留余量，但不放到"随便怎么写都过"）；
3. 同一类问题的样本共用容差区间（如错别字 5–10、敏感词改写 10–20、文风润色 20–40）；
4. 🔴 定完写进样本文件，别每次改 —— 容差会漂就意味着对照结果不可比。

## 4. 建议规模（够用就好，别做测评集工程）

| 问题类型 | 条数 | 说明 |
|---|---|---|
| 错别字 | 3–5 | 改动极小，容差窄，最容易看出"模型乱改" |
| 敏感词 | 3–5 | 必须换说法，容差中等 |
| 文风润色 | 3–5 | 改动大，容差宽，看的是"有没有面目全非" |
| 节奏/精简 | 2–3 | 看缩短比例是否合理 |

合计 **11–18 条**足够回答一个问题："这一版模型比上一版改得好还是差。"

## 5. 怎么跑

```bash
bash tests/run-batches.sh C        # 其中 fixedSamples 会消费本地样本
```

- 没有 `.workbuddy/eval-samples/samples.json` ⇒ 输出「未提供真实样本」，**不下任何结论**（不假装通过）。
- 有样本 ⇒ 先做字段自检（缺 id / 重复 / 空正文 / 负容差会被点名），再做**自对照**（期望对期望必过，证明文件格式对）。
- 🔴 真正"模型改得好不好"的对照，需要把模型的 `actualOutput` 喂进 `batchCompareWithFixedSamples` ——
  那一步依赖真实端点，属实机；本文只负责把**样本与通路**备好。

## 6. 判据含义（别误读）

| 判据 | 含义 | 不意味着 |
|---|---|---|
| `charDiff ≤ tolerance` | 字数在预期区间 | 内容正确 |
| `similarity ≥ 0.5` | 与期望共享足够多的字符 | 语义等价（相似度只是筛"面目全非"） |
| `passed` | 两条都满足 | 可以发布 |

🔴 `passed` 是**粗筛**：它只能挡住"改得面目全非"和"字数跑偏"，不能替代作者通读。
把它当发布门禁会出事 —— 这也正是 `guardText` 不接 `passed` 阈值（WQ8 方案 A）的同一个理由。
