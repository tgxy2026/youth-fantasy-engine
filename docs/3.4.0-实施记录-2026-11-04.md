### 10.2 纵切暴露并修复的缺陷（A.2）

**现象**：把规划板当前锚点章删到回收站后回到写作面板，规划板提示的是
「上次进入的『未命名章』**不在当前筛选结果里**；筛选条件已保留，可**清除筛选**后再找。」
—— 作者会以为清除筛选就能找回，实际那一章在回收站。

**根因**：`locateBoardAnchor(anchorId, ids)` 只拿「当前筛选结果」判断，不在结果里就一律返回 `filtered-out`，
无法区分「被筛掉」与「已不在项目中」。规划 §三.A.2 明确要求这两种情况分别提示。

**修复**（最小改动，集中在纯函数与众唯一调用点）：

| 文件 | 变更 |
| --- | --- |
| `src/lib/app/chapterBoardState.ts` | `locateBoardAnchor` 增加可选第三参 `existingIds`（本项目仍存在的章节 id）；先判存在性 → `missing`，再判筛选 → `filtered-out`；不传时保持旧口径，向后兼容 |
| `src/components/app/WritingWorkflow.tsx` | 挂载时把 `chapters.map(c => c.id)` 作为 `existingIds` 传入 |
| `tests/chapterBoardState.test.ts` | 新增 3 项：被筛掉 → `filtered-out`；已删除 → `missing`；不传第三参 → 旧口径 |
