## 0. 目标与范围

1. **AI 伴写（新增）**：尽量复现 WPS AI 伴写交互——
   - 停笔后自动感知前文，在**光标后**以**浅灰色**文字显示一句话续写建议；
   - 按 **Tab（→ 为辅）** 一键采纳，文字正式落进正文；
   - **继续打字 / 移动光标 / Esc** 即忽略，AI 悄悄退场，绝不打断心流；
   - 全程**本地模型**（Ollama + Qwen3.8-27B），零外发，符合商业机密红线。
2. **引用名内联高亮（小改）**：把工具栏「荧光笔」按钮的默认态由**开启**改为**关闭**，需手动开启。

与既有 AI 能力的关系：**伴写是最轻量的一档**，与「续写方向（只给方向）」「一键续写+设定补完（大块生成）」互补，不替代。

## 3. AI 伴写 · 详细设计

### 3.1 触发与状态机

- **触发防抖**：停笔后 **500ms**（小说场景本地模型较慢，取 400~600ms 区间，常量可配）才发请求；打字/移动光标即取消在途请求（`AbortController`）。
- **手动触发**：可选 `Alt+\`（复刻 WPS 的手动伴写键），与自动并行存在、互不冲突。
- **显示前置条件**（全部满足才请求/显示）：
  1. 正文非空（至少已有一句）；
  2. 无选区（`selectionStart === selectionEnd`，即纯光标态）；
  3. 已配置 AI 模型（`requireActiveProvider()` 非空）；
  4. 未触发「连续失败静默禁用」。
- **状态机**：`idle → requesting → showing →（accept | dismiss）→ idle`。

### 3.2 上下文拼装（复用既有模式）

- **续写前文** = 光标前最近 **~2000 字**（`draftContent.slice(0, selectionStart)` 的尾部切片）；长章可调上限。
- **system**：`composeSystemPrompt(伴写系统提示, cfg)`，并挂 `projectContext`（现有「设定资料摘要」机制，与 `aiContinuationAdvice` 同源）。
- **作者正文保护**：走 `authorBlock()` 封装前文（与 `aiTasks.ts:14` 既有用法一致），绝不清洗作者原文。
- **新增函数（落点 `src/lib/aiTasks.ts`）**：
  ```ts
  export async function aiInlineSuggest(
    contextBefore: string,                 // 光标前正文
    opts: { projectContext: string; signal?: AbortSignal; onToken?: (d: string) => void },
  ): Promise<string>                        // 返回纯文本续写片段（非 JSON）
  ```
  内部拼装与 `aiContinuationAdvice` 同构，但 `json:false`、要求纯文本。

### 3.3 请求约束（控制质量与成本）

- 复用 `chat(cfg, messages, { timeoutMs: CHAT_TIMEOUT_MS, signal, onToken, json: false })`。
- `max_tokens` 小（**48~64**），`temperature` 低（**0.3~0.6**，创意写作可到 0.7）。
- **系统提示强制约束**（钉在 system 末尾才有效，沿用酒馆模式已验证结论）：
  > 只输出续写片段本身，不要任何解释、不要引号、不要 markdown、不要重复前文最后一句、保持作者文风与视角。
- **反重复**：复用 `paramGuide` 已验证的采样惩罚（`repeat_last_n=512` + `frequency_penalty=0.1`），避免手部动作重复；**绝不调高 `repeat_penalty`**（酒馆实测会把括号打不闭合）。
- 输出后处理：剥离模型可能返回的引号/前缀/空行；长度守卫 **4~120 字**，越界丢弃并视为无建议。

### 3.4 渲染层（关键，复用双图层）

- **新增 `ghostRef` 叠层**，盒模型**逐字照抄高亮层**（保证对齐）：
  `absolute inset-0 z-0 overflow-hidden pointer-events-none px-6 md:px-8 pt-6 pb-[40vh]`，`fontSize/lineHeight:1.9, whiteSpace:pre-wrap, wordBreak:break-word`。
- **渲染内容**：
  ```
  beforeText(透明) + <span class="ai-ghost">suggestion</span> + afterText(透明)
  ```
  `before`/`after` 透明 → 不与 textarea 实字冲突；ghost 段用浅灰（暗主题 `rgba(255,255,255,.35)`，亮主题对应灰，走 CSS 变量）。
- **前提**：textarea 背景必须透明（现状无显式 bg，但需在亮/暗主题实机验证不串色）。ghost 段落在「光标后无字区」，textarea 透明处即透出灰字。
- **光标在中段**：`before = text[0:sel]`、`after = text[sel:]`，ghost 插在光标处（WPS 同款）。
- **与高亮层共存**：高亮层默认关（见 §4）；若用户同时开高亮，ghost 层 `z-0` 置于高亮层 DOM 之后，互不遮挡文字（两者均为「透明基 + 局部着色」）。

### 3.5 接受 / 拒绝

- **接受（采纳）**：
  - 主键 **Tab**：拦截 textarea 默认 Tab 行为 → 把 `suggestion` 插入光标处，受控组件走 `onContentChange`；
  - 辅键 **→（右箭头）**：在「光标已在末尾」时也采纳（避免与 Tab 抢占焦点）。
  - 采纳瞬时：ghost 文字变黑融入正文，无闪烁。
- **拒绝（清除）**：任意可打印字符输入 / `Esc` / 光标移开 / 滚动 / 切章 → 清空 ghost、`abort` 在途请求。

### 3.6 健壮性

- **速率限制**：如 30 次/分（`min` 间隔守卫）。
- **静默禁用**：连续 3 次 provider 错误 → 自动停用伴写，状态栏给轻提示，可手动重开。
- **LRU 缓存**：同前文 hash → 直接命中，省 token、降延迟。
- **防抖丢弃**：防抖窗口内若已离开编辑区/失焦，丢弃本次结果。

## 7. 风险与开放问题（待拍板）

1. **Tab 拦截冲突**：textarea 默认 Tab 会跳焦点，拦截后是否影响其他快捷键？→ 兜底用 `→` 或自定义键，需实机确认。
2. **textarea 背景透明前提**：ghost 透出依赖此前提，亮/暗主题需实机验证不串色、不挡 caret。
3. **前文切片上限**：2000 字对超长章够不够 → 可调，或取「最近 N 句」。
4. **引用名高亮持久化**：是否做 localStorage 记忆？默认仅改初始值即满足需求。
5. **与「续写方向」提示词口径**：伴写是纯续写、方向档是结构化建议，二者 prompt 独立，注意别让伴写误带「建议」口吻。

## 9. 决策定案与实施记录（2026-09-17）

### 9.1 与老大讨论后拍板的五条

| 议题 | 定案 | 为什么这么定 |
|---|---|---|
| **文风预设** | **三层锚定，不做文风枚举**：①光标前 ~2000 字正文（必带）②《写作规范》摘录（可关）③自定义补充一句（可空） | 枚举永远不够用（做到第 11 种还会有人要第 12 种）、选错标签模型会强行套风格反而更假；且伴写是低打扰场景，每多一个选择就是多一次打断。**前文样本比任何标签都准**（贴合前文靠 few-shot，不靠标签） |
| **去 AI 味** | **默认开启**（轻量档） | 伴写是"同一章连续续写几十次"，AI 味累积效应最强。⚠️ **不能直接复用 `autoContinue.ts` 的 `DEAI_TEMPLATES`** —— 那 4 条写的是「把正文改得…」的**改写**指令，放进生成场景会让模型先去找正文再改写，甚至输出「以下是修改后的内容：」。只抽共性另写生成向短约束 |
| **字数限制** | **三档**：短句 ≤20（`40` token）/ **一句话 ≤40（默认，`64`）** / 两句 ≤80（`110`） | 给数字输入框是伪自由度——用户不知该填多少，填大了 ghost 会糊住半个屏幕 |
| **触发方式** | 总开关**默认关闭**；开启后默认**自动（停笔 800ms）**，另有 `Alt+\` 手动 | 自动档是 WPS 的手感；总开关默认关保证写作者主导权 |
| **接受键位** | **Tab** 主、**→** 辅（仅当光标已在正文末尾） | WPS 同款；Tab 在 textarea 默认会跳焦点，必须 `preventDefault` 拦截 |

### 9.2 实际落地（阶段一）

| 文件 | 改动 |
|---|---|
| `src/lib/aiTasks.ts` | 新增 `aiInlineSuggest(contextBefore, opts)`、纯函数 `trimInlineSuggestion(raw, maxChars)`、`INLINE_SUGGEST_LIMITS`、`DEAI_INLINE_RULE`（生成向去 AI 味，钉在 system **末尾**） |

| `src/index.css` | 新增 `.ai-ghost`（`rgb(var(--ink-100) / 0.42)`，由正文色推导浅灰，暗/亮双主题自适应） |
| `tests/inlineSuggest.test.ts` | **新增 21 条用例**（清洗 / 句末截断不半句悬空 / 宁缺毋滥 / 档位自洽），含反例守卫 |
| 长期记忆 | `MEMORY.md` 记入伴写定案 + glob 覆盖事故教训 |

**关键实现点（后人勿随手改）**
1. ghost 叠层 `z-0` 与**高亮层同层**、盒模型逐项照抄（`inset-0` + 同一套 `px/pt/pb` + 同一字号行高），`syncHighlightScroll` 一并同步它的 `scrollTop`。
2. `before` / `after` 用**透明 span 且三分行写** —— 靠 JSX「吃掉含换行的空白」避免多插一个空格把 ghost 挤偏一个字宽。
3. **光标后已有正文时不显示**（ghost 没有宽度，压到后面的字上会糊成一片）。
4. 🔴 **切章必须清 ghost**（`[activeId]` 清理 effect + 光标 `Math.min(caret, len)` 夹取 + 采纳时再夹一次），否则 Tab 会把上一章的建议插进新章的同一偏移处 —— 数据事故。
5. 采样：`repeat_last_n=512` + `frequency_penalty=0.1` 显式下发；**绝不调高 `repeat_penalty`**；温度**不手填**（走全局创意档）。

### 9.3 与本文前述设计的偏差（如实记录）

| # | 设计稿 | 实做 | 原因 |
|---|---|---|---|
| 1 | 防抖 500ms | **800ms** | 本地 27B 出一句话 1~3s；太快会在正常停顿处反复起请求、空占 GPU |
| 2 | `max_tokens` 48~64 | 改 Ollama `num_predict` + prompt 软约束 + 客户端句末截断 | `chat()` 的 `extraOptions` 对 OpenAI 端点只放行 `top_p`/`presence_penalty`/`frequency_penalty`，`max_tokens` 发不出去；**本轮不动 `ai.ts` 传输层**（见 P2） |
| 3 | 光标在中段也插 ghost | 光标后**有正文就不显示** | ghost 无宽度，压字必糊；实测没必要为此引入复杂排版 |
| 4 | `temperature` 0.3~0.6 | **不传**（走全局创意档） | 项目铁律「温度不手填，唯一真源在 `ai.ts`」 |
| 5 | §3.2 的函数签名 | 扩了 `styleSpec` / `styleNote` / `length` / `deAiFlavor` | 承载三层锚定与三档长度 |
| 6 | §4 引用名高亮的 localStorage 记忆（P2） | **未做** | 只改默认值即满足「默认关闭、手动开启」 |
| 7 | 未列测试 | 新增 `tests/inlineSuggest.test.ts` | 纯函数必须锁死行为（项目惯例） |

### 9.4 仍待实机验证的 P0（下一步）

1. textarea 透明背景下 ghost **真的能透出来**、不串色、不挡光标（暗/亮双主题）。
2. **Tab 拦截**是否与既有快捷键冲突；`→` 备选键手感。
3. 停笔 800ms 在本地 27B 上的实际等待是否可接受（可能要放宽到 1000~1200ms）。
4. 长章 2000 字切片是否够稳（必要时改「最近 N 句」）。
5. 引用名高亮默认关闭后，是否需要在侧栏/帮助里加一句引导。

### 9.5 P2 候选（记下不急着做）

- 给 `ChatOptions` 补 `maxTokens`（OpenAI 走 `max_tokens`、Ollama 走 `num_predict`），让云端端点也能限长。
- 伴写设置“本机记忆”目前只在本机 localStorage —— 若要多设备一致，需进 StoreOps 设置表（跨项目）。
- `aiInlineSuggest` 复用 `promptGuard.authorBlock()` 已防注入；若日后接入云端模型，需复核「导入文本零外发」红线。
