# 青春幻想引擎 3.1 版本开发规划书

> 文档类型：版本开发规划与需求基线  
> 规划日期：2026-10-15  
> 项目基线：v3.0.4  
> 关联调研：[3.1 开发规划建议书](./3.1-开发规划建议书-2026-10-15.md)  
> 说明：本文根据当前仓库结构、既有数据模型、已落地能力及长篇创作平台/开源 AI 小说工具调研编写。人日为工程量级估算，不是交付承诺；正式排期应在需求冻结和技术拆分后校准。

## 1. 版本定位

### 1.1 版本主题

**让长篇创作工作流更容易进入，让同步分叉可查看、可恢复。**

3.1 不以继续增加独立页签为目标，而是把 v3.0.4 已有的项目、章节、规划、检查、快照和同步能力串起来。优先解决作者每天会遇到的三类问题：

1. 打开项目后，不清楚下一步该从哪里继续。
2. 想从全书/分卷规划快速找到需要写或修改的章节。
3. 跨设备同步出现分叉时，虽有云端副本保护，但难以定位和恢复。

### 1.2 目标用户与使用场景

- 已有长篇项目、需要在章节规划与正文之间频繁切换的作者。
- 初次使用软件、尚未熟悉 10 个功能组和约 51 个页签的新作者。
- 使用目录中转、WebDAV 或 S3 在多台设备间同步项目的作者。
- 使用 AI 完成检查或修改建议，但希望继续逐步确认内容写入的作者。

### 1.3 版本成功标准

- 作者能从项目工作面板直达当前最相关的章节或待办事项。
- 章节规划视图不产生第二份大纲数据，不改变现有正文和排序规则。
- 同步冲突发生后，作者能找到冲突副本、查看版本信息，并按明确步骤恢复或另存。
- 旧项目、便携版项目和现有备份可继续打开；不要求启用 AI 或远端服务才能使用核心改进。

## 2. 项目现状与实施边界

### 2.1 可直接复用的能力

| 现有实现                                                         | 3.1 可复用方式                           |
| ------------------------------------------------------------ | ----------------------------------- |
| 项目工作面板 `Dashboard` 已聚合章节、字数、伏笔、灵感、进度、健康提醒和结构预警               | 扩展为“继续创作”入口，复用查询和跳转，不另建统计体系         |
| 项目管理页 `ProjectHub`、首启向导 `WelcomeWizard`、新手指南 `GuidePage` 已存在 | 在项目内增加可关闭、可重开的步骤清单；不要再做第二套全局首启向导    |
| 章节数据含卷、顺序、标题、摘要、状态、正文和字数；章节快照已有自动留存机制                        | 第一版规划板以章节为卡片，读取现有数据；正文跳转沿用编辑器现有打开路径 |
| 剧情线视图已聚合时间线、爽点和伏笔                                            | 规划视图链接已有剧情线资料，并显示数据缺口；不复制伏笔、支线等业务记录 |
| AI 任务中心、运行账本、工单和章节快照已存在                                      | 只为后续工作流原型提供基础，3.1.0 不承诺通用 Agent 编排  |
| 桌面和 Web 同步已实现基线合并、版本冲突重试与冲突副本回调                              | 3.1 增加作者可见的冲突列表和受控恢复；不扩展为自动语义合并     |
| 项目导入导出、备份管理和健康检查已有                                           | 冲突副本可导出/恢复时优先复用既有备份与导入能力            |

### 2.2 需要避免的实现方式

- 不把“场景规划板”实现为新的平行场景数据库。当前 `Chapter` 没有独立场景实体；每章多场景拆分会影响编辑器、章节排序、导入导出、快照、同步和历史项目兼容。
- 不把工作面板改成 AI 自动决策入口。现有 AI 能力是分布在专用面板中的，跨模块自动写入需要任务持久化、读写范围、审批、恢复和撤销机制。
- 不把冲突副本直接自动合并回主数据。章节正文、卡片表、删除墓碑和外置载荷的冲突语义不同，自动合并会扩大不可逆风险。
- 不在 3.1 承诺移动端完整创作、实时多人协作或平台账号自动发布。它们需要新的运行/鉴权/同步边界，超出当前本地优先架构的安全小步扩展范围。

## 3. 3.1.0 范围

### P0-A：项目下一步与快捷回到创作

**目标：** 作者打开项目后，能直接回到最近章节，并看见少量有依据的下一步入口。

**交付内容：**

- 在现有工作面板新增“继续创作”区域：最近编辑章节、最近打开卷、未完成章节快捷入口。
- 从既有数据计算建议项：无正文章节、草稿/修改状态章节、未处理的检查异常、未用灵感、到期未回收伏笔、待处理优化工单。
- 每个建议项说明来源和跳转目标；支持忽略/稍后处理，忽略状态仅作为本机界面偏好保存。
- 空项目显示建卷、建章、写正文、备份等步骤；作者可跳过并可随时重新打开。
- 复用现有首启向导和项目管理页入口，不改变首次启动流程。

**不做：** AI 自动判断创作计划、强制推荐步骤、新增待办数据库、要求逐步完成才能写作。

**验收口径：**

1. 空项目在不配置模型的情况下，可通过面板跳转完成建章、编辑正文和打开备份管理。
2. 已有项目的所有建议均能追溯到现存数据来源；关闭或忽略后不会删除原始资料。
3. 300+ 章项目中，面板首屏不加载整本文字正文；聚合查询按现有索引/批量读取方式执行。

**预估：** 4–6 人日；难度：中。主要成本在数据聚合口径、功能模块开关适配及跳转状态正确性。

### P0-B：章节规划板（章节级 MVP）

**目标：** 在一个视图中查看分卷章节顺序、规划摘要、写作状态和已关联的剧情资料，并快速进入编辑。

**交付内容：**

- 以现有章节作为卡片，按卷分组，展示标题、章节摘要、状态、字数和更新时间。
- 可按卷、状态和关键词筛选；支持章节卡直接打开正文编辑器。
- 对接已有时间线、爽点、伏笔等资料时只做摘要/入口展示，明确标注“来自某功能页签”。
- 第一版只支持只读查看、搜索筛选和跳转；如需调整章节顺序，跳到现有章节管理能力处理。
- 空摘要、空正文、状态与正文不一致等情况给出提示，不自动修正数据。

**不做：** 独立场景对象、拖拽改序、跨卷移动、人物/地点自动实体识别、多场景拆章与合章。

**验收口径：**

1. 规划板展示的标题、卷、状态、摘要和字数均来自现有章节记录。
2. 打开卡片进入正确章节；筛选和排序不写回项目数据。
3. 自定义项目未启用相关模块时不报错、不显示失效入口。
4. 300+ 章样例下滚动、筛选和打开章节可用；视图不会一次性渲染整本正文。

**预估：** 5–8 人日；难度：中高。若产品评审坚持可拖拽或“一章多场景”，应另立数据模型与迁移设计，不能塞入此 MVP。

### P0-C：同步冲突中心与安全恢复

**现状：** 同步层已有冲突检测/重试；冲突回调会将另一侧版本另存为本地冲突副本，并通过提示告知用户。作者缺少持续可见的冲突清单、内容查看入口和恢复工作流。

**交付内容：**

- 数据坞增加“同步冲突”入口和未处理数量提示；显示发生时间、数据类型、记录名称/键、设备或同步目标等可获得信息。
- 支持查看当前版本和冲突副本的可读摘要；章节正文可查看差异或分屏内容，其他记录至少可查看结构化值。
- 提供“导出副本”“复制到新记录/新项目”“用副本替换当前记录”等有明确确认的动作。恢复前自动建立当前数据快照。
- 对不支持安全逐条恢复的载荷，提供导出完整冲突数据和打开备份管理的路径；不伪装成可精确合并。
- 冲突记录能标为已处理；清理副本前显示影响并要求确认。
- 记录副本保存失败时显示可理解的错误和建议检查事项，不只写控制台日志。

**实现原则：** 尽量沿用现有 `syncConflict:*` 本机 meta、`SyncConflictInfo`、冲突副本保存逻辑和备份管理。先定义冲突记录 schema 版本、保留期限与大小上限，再做界面。冲突数据仍不回传云端。

**验收口径：**

1. 并发改同一章节、并发改不同记录、删除与修改冲突、同步重试、断网恢复和副本保存失败场景均有结果提示。
2. 每条冲突至少能导出/恢复一份冲突前或冲突后的完整数据；应用关闭重开后仍可找到未处理冲突。
3. 恢复动作有二次确认和恢复前快照；失败时当前主记录不被部分写坏。
4. 目录中转、WebDAV、S3 和本地/网页版同步路径的冲突处理行为一致或明确说明差异。

**预估：** 8–14 人日；难度：高。取决于冲突副本当前粒度、记录关联关系、附件/向量索引重建和现有恢复 API 的覆盖范围。此项须先完成技术 spike 和故障场景表，再锁定 UI 方案。

### P0-D：第九个预制主题“纯黑白”（2026-10-15 新增）

**状态：规划中，尚未开发。** 用户反馈当前自定义主题编辑器无法调出纯白背景、纯黑文字及界面的组合，要求在 3.1 增加这一显示选项。

**目标：** 满足包括干眼症用户在内、偏好白底黑字的用户对界面配色的明确需求。产品名称采用“纯黑白”，描述为显示偏好，不作缓解或治疗干眼症的效果承诺。

**现状核查：** 当前自定义主题采用“母版主题 + 强调色 + 色相偏移”派生，并维持母版亮度和对比度约束；没有直接设置完整背景与前景颜色的入口。因此，仅把强调色调为黑色，不能得到严格的纯黑白界面。组件还存在透明度、固定语义色、图谱和图表绘制等独立颜色路径，需要一并适配。

**交付内容：**

- 在左下角主题栏新增第九个预制主题“纯黑白”，一键启用；排列顺序固定为“现有八个预制主题 → 纯黑白 → 彩色自定义主题按钮”。界面背景、面板、输入框、菜单、弹窗及选中项背景统一使用 `#FFFFFF`，文字、图标、边框、光标和焦点轮廓使用 `#000000`。
- 覆盖正文编辑器、章节树、工作面板、表格与卡片、AI 面板、提示与确认弹窗、滚动条及应用控制的图谱/图表等界面，排查硬编码颜色、透明度混色、渐变和阴影，避免出现灰色或彩色界面元素。
- 悬停、选中、聚焦、禁用、成功、警告和错误状态通过轮廓粗细、线型、勾选标识、图标及文字区分；保留键盘焦点和真实禁用语义。输入占位文字也使用黑色，通过内容说明区分用途，避免依赖灰色表示。
- “纯黑白”作为独立预制主题，与前八个预制主题使用相同的选择方式；不在自定义主题弹窗增加专门的启用入口。彩色自定义主题按钮继续位于其右侧。严格黑白预设保持独立，不让强调色或色相派生重新引入其他颜色。
- 主题偏好沿用现有本机保存机制，重启后恢复；支持切回其他主题，并清理自定义主题的内联变量，避免颜色残留。

**范围说明：** “纯黑白”约束应用自身绘制的界面和绘图元素；用户导入的封面、参考图片等作品素材保留原内容，操作系统原生窗口按系统能力处理。字体及矢量图边缘的抗锯齿过渡不作为配色不合格，不采用全屏阈值滤镜破坏文字渲染。

**验收口径：**

1. 左下角主题栏的顺序为现有八个预制主题、“纯黑白”、彩色自定义主题按钮；点击第九个预制主题即可启用，重启后仍保持该主题；切换主题后无变量残留。
2. 主要界面及交互状态的背景计算值为 `#FFFFFF`，文字、图标和轮廓为 `#000000`；检查半透明样式及固定色，不仅检查主题变量声明。
3. 选中项、键盘焦点、禁用操作及危险提示能在纯黑白下辨认，无黑字黑底、白字白底或仅靠颜色传达状态的问题。
4. 图谱、图表通过线型、符号或文字标记区分信息，正文选择、搜索命中和编辑光标可辨认；导入图片保持原内容。
5. 在 Windows 桌面端和预览环境检查工作面板、正文编辑、表格、AI 面板及弹窗，最终由提出需求的用户确认显示效果是否符合个人偏好。

**预估：** 3–6 人日；难度：中高。主题变量可复用，主要成本在全界面颜色路径和交互状态适配。此项为原排期外新增范围，纳入里程碑后重新校准总工期。

### P1：资料提及反向导航（仅在容量允许时）

**目标：** 从角色、地点、术语等资料项快速找到相关章节，减少手工搜索往返。

**范围：** 先复用全文检索/知识库索引，提供提及结果及章节跳转；名称别名可手工维护，结果允许误报。不可在未确认时自动合并同名实体。

**预估：** 5–9 人日；难度：中高。索引精度、增量更新和自定义项目模块边界需验证。若 3.1.0 P0 延期，本项自动移入 3.1.1。

开源 AI 创作工具的趋势是把规划、写作、审阅、修订组织成可暂停、可恢复的任务，并展示改动供作者确认。青春幻想引擎已有任务中心、运行账本、工单、快照和多模型路由，薄弱点在“跨页面任务编排和持久化恢复”，而非缺少 AI 续写按钮。因此 3.1.0 先把作者工作流与数据安全做稳，AI 编排先做受控原型，不引入通用自主 Agent。

## 5. 技术实施方案

### 5.1 数据与兼容策略

- 下一步面板、章节规划板优先使用投影/派生数据，不增加持久化业务字段。
- 本机界面偏好使用已有本地偏好命名空间保存；不得混入项目备份或云同步载荷。
- 冲突中心若需补充字段，新增版本化冲突记录；老 `syncConflict:*` 条目读取时兼容，不要求批量升级用户数据。
- 涉及主记录恢复时复用数据库事务/项目快照机制；附件、语义索引和缓存按既有恢复后重建流程处理。
- 导出/导入的新结构需提供 schema 版本和未知字段处理策略，老版本数据不得因打开 3.1 被静默清除。

### 5.2 性能策略

- 规划板使用章节元数据和摘要，不把所有正文载入卡片列表。
- 工作面板使用批量查询和轻量统计；较慢的健康检查维持显式触发或后台分段执行。
- 冲突中心默认分页/按类型筛选，避免大型正文副本一次全部渲染。
- 验收样本建议包含 300–500 章、百万字级项目以及大量设定表记录。

### 5.3 交互与可访问性

- 新入口优先放在现有工作面板、章节树和数据坞，不新增顶层功能组。
- 所有自动建议展示来源、更新时间和跳转目标；无来源的“AI 判断”不作为事实状态显示。
- 危险恢复动作显示受影响数据和可用备份；恢复完成后可撤回或从恢复前快照还原。
- 空状态明确告诉作者如何开始，同时保留跳过路径。

## 6. 里程碑与排期建议

按 1 名主要开发者、需求评审和回归并行估算，整体建议预留 **6–9 周**；若同步冲突需要重做数据层或缺少可复用恢复 API，排期相应增加。

| 阶段           |    时间建议 | 工作与退出条件                                             |
| ------------ | ------: | --------------------------------------------------- |
| M0 需求冻结与技术验证 |   3–5 天 | 确定建议项定义、章节卡字段、冲突样本/恢复 API；同步冲突 spike 证明两侧数据能稳定导出与恢复 |
| M1 项目下一步面板   |     1 周 | 基于真实项目数据完成聚合、空状态、跳转和忽略；不新增项目数据模型                    |
| M2 章节规划板 MVP | 1–1.5 周 | 章节只读投影、筛选、分卷、正文跳转；长篇样本达到可用性能                        |
| M3 同步冲突中心    |   2–3 周 | 冲突列表、查看、导出/恢复、快照与失败提示；完成冲突场景矩阵                      |
| M3-D 纯黑白主题（新增） | 3–6 人日 | 左下角第九个预制主题、固定色和透明度适配、黑白状态辨识及用户显示效果验收 |
| M4 整合与兼容检查   | 1–1.5 周 | 老项目/备份/便携版兼容，模块开关、窄窗口和本地数据恢复路径检查                    |
| M5 发布准备      |   3–5 天 | 更新帮助文档、升级说明、数据风险说明和已知限制；形成 3.1.0 发布候选               |

排期使用顺序依赖，不等于每一阶段都必须串行。若团队实际只有开发者一人，M3 的冲突中心是最长路径，应避免同时启动场景实体、移动版或 Agent 编排。

## 7. 验收与发布门槛

| 验收领域  | 通过条件                                     |
| ----- | ---------------------------------------- |
| 功能闭环  | 从工作面板进入章节、从规划板打开正文、从冲突通知进入冲突详情均无断链       |
| 数据安全  | 冲突恢复前自动留存快照；冲突双侧可导出；副本删除前有确认；错误路径不静默覆盖   |
| 旧数据兼容 | v3.0.4 项目、历史项目、导出的项目包、自动备份和便携版数据均可打开与恢复  |
| 模块组合  | 全功能项目及未启用角色/伏笔/时间线等模块的自定义项目均可正常使用        |
| 长篇性能  | 300+ 章/百万字项目可滚动浏览、筛选和进入章节；记录主要操作的耗时与卡顿情况 |
| AI 可选 | 未配置 AI 时，下一步面板、章节规划和冲突恢复核心路径仍完整可用        |
| 可理解性  | 冲突、忽略建议、空摘要、模块未启用、恢复失败均有明确中文提示和下一步动作     |
| 纯黑白主题 | 白底黑字及界面轮廓覆盖主要页面和交互状态；主题持久化、切换、焦点与选中状态均可用 |

发布前建议做专项场景验证：

1. 两台设备先同步同一基线，再分别修改同一章节正文后同步。
2. 一端删除记录、另一端修改记录，再分别从两侧启动同步。
3. 同步过程中断网/退出应用，重开后确认冲突记录和副本仍在。
4. 冲突副本导出、恢复、再次同步，确认不会重复生成冲突或覆盖不相关记录。
5. 对章节规划板执行项目导出、导入、备份恢复，确认不产生额外场景数据。

## 8. 主要风险与应对

| 风险                           | 级别 | 应对                                                  |
| ---------------------------- | -- | --------------------------------------------------- |
| 冲突副本可能包含不同存储类型和关联数据，逐条恢复边界复杂 | 高  | M0 先盘点冲突 `store/key` 类型并做恢复 spike；无法证明安全的类型先只允许完整导出 |
| 建议项口径可能误导作者，例如把未填写摘要当成缺陷     | 中  | 每项标注数据来源和判定条件，提供关闭/忽略；文案表达为提示而非质量判断                 |
| 章节规划板被扩大为独立场景数据库             | 高  | 3.1.0 采用现有章节的只读视图；一章多场景作为独立立项，先做用户需求验证              |
| 工作面板重复现有统计，增加信息噪声            | 中  | 仅展示可操作的下一步和最近工作；统计仍留在已有区域，不新增重复图表                   |
| 开源 AI Agent 趋势推动过早自动化        | 中  | 只将单工作流列为后续原型；以可观察步骤、人工确认、任务恢复和回滚为前置条件               |
| 单人维护下 3.1 范围超载               | 高  | P0 按 A、B、C 顺序；C 完成前不启动移动端或 Agent 原型；P1 超期自动后移       |

## 9. 版本内外清单

### 3.1.0 必须完成

- 项目工作面板的继续创作/下一步入口和项目内可重开的起步清单。
- 基于当前章节模型的只读章节规划板 MVP。
- 同步冲突的持久列表、查看、导出和安全恢复路径。
- 左下角主题栏第九个预制主题“纯黑白”（现有八个主题之后、彩色自定义按钮之前），完成主要页面和交互状态的配色验收（2026-10-15 新增）。
- 旧项目、备份导入、便携版和自定义模块的兼容验收。

### 3.1.0 可裁剪项

- 若同步冲突技术验证发现无法安全恢复，先发布“冲突可见、双侧可导出、提供快照恢复”的保守版；逐条原位替换移至 3.1.1。
- 资料反向导航不属于发版阻断项，资源不足时后移。

### 明确不纳入 3.1.0

- 新建完整场景实体与一章多场景编辑。
- 全自动跨模块 Agent、未经确认的正文/设定写入。
- 手机端远程编辑服务器、实时多人协作。
- 官方平台自动登录、发布或稿酬数据同步。
- 世界包自动覆盖式更新。

## 10. 立项结论

3.1 应以“现有能力的工作流整合 + 同步安全可恢复”为主线。项目已经有首启引导、工作面板、章节树、剧情线视图、章节快照、AI 任务中心和冲突副本机制；本版主要补齐作者可见的连接层和操作层，而不是重做已有模块。

建议立项顺序：

1. 先做项目下一步面板，快速验证聚合数据与跳转路径。
2. 再做章节级规划板，保持只读模型，避免数据结构膨胀。
3. 并行完成同步冲突技术验证，再实现冲突中心和恢复工作流。
4. 只有前三项稳定后才启动资料反向导航；AI 编排、世界包差异、移动伴随模式进入 3.1.x 需求验证。

若 3.1 只能保证一个高风险主线，应优先确保同步冲突双侧数据可恢复；若冲突处理范围超出版本容量，应收缩恢复动作而不是降低数据安全验收门槛。
