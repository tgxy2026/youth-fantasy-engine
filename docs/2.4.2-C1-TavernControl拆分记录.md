## 二、🔴 唯一一处「非纯搬家」：early return 从 JSX 改成数据

组件体里有一处 early return JSX（原文件 394 行）：

```tsx
if (!s) return <LoadingState />
```

搬进 `.ts` 的 hook 后**编译不过**（`TS1005`：`.ts` 里不能写 JSX）。落地方式：

```ts
// useTavernControlModel.ts —— early return 只出数据、不出 JSX
if (!s) return null
// ...
/** NonNullable：hook 可能在前置数据未就绪时返回 null */
export type TavernControlModel = NonNullable<ReturnType<typeof useTavernControlModel>>
```

```tsx
// TavernControl.tsx
const m = useTavernControlModel()
if (!m) return <LoadingState />
```

语义完全等价：**所有 hooks 仍在这一行之前**（原代码就是按这个约束写的 —— 原文件 406 行的注释特意说明过「刻意不用 useMemo，因为 early return 之后不能有 Hook」，本轮把这个引用片段同步改成了 `if (!s) return null`）。
`NonNullable<>` 是必要的：否则子组件收到的 `m` 类型含 `null`，解构会报错。

## 三、🔴 三条拆错了就会现形的红线

1. **左列 div（`leftColRef`）/ 右列 div（`rightColRef`）必须留在本组件** —— 协议窗高度同步量的是它们的**直接子节点**。子组件一律返回 Fragment（不产生 DOM 节点）⇒ 这层子节点数恒为 **5**（左）与 **3**（右）。
2. **两列等高的高度同步 effect**（含 `ResizeObserver` / `MatchMedia` 清理）随组件体进了 hook，一字未改；它引用的两个 ref 由主组件提供。
3. **分段说明的显隐走 `ShowBands.Provider`**，Provider 本身留在主组件（在 `grid` 外层）。
