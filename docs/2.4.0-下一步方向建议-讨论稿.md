## 一、先说判断前提

| 现状事实 | 推出的结论 |
|---|---|
| 功能面已铺满：**10 分组 / 49 页签**；AI 任务 **11 域**（audit / creative / extract / formSummary / inline / jieWenJi / organize / proofread / rewrite / stream / suggest）；连续性检查、伏笔引擎、敏感词、错字库、数据体检、地图、时间线、酒馆全套都在 | **横向加功能的边际收益，已经低于把现有链路做深** |
| 一个新页签的固定成本：schema 登记 + `SETTING_SUBTABS` + `aiContext.PRIORITY` + 种子/迁移 + 单测 + 文档 ≈ 六处改动 | 每加一个页签都要给出充分理由（老大已放宽，但成本仍在） |
| 护栏已厚：**91 个测试/脚本文件**、结构闸、种子闸、功能依赖闸、any 账本 | 工程质量的**边际风险下降**，人力可挪向体验与性能 |
| 外部变量：小黑盒推广第 0 篇已出、21 张截图已备，即将对外拉新 | **新用户前 30 分钟体验 = 当前最大杠杆** |
| 内部变量：老大自己写长篇，字数与章数会持续涨 | **长篇下的性能与数据安全会变成真痛点** |
| 可量化的质量债：6 个 700+ 行组件（JieWenJi 1032 / CreativeWritingPanel 982 / TavernControl 913 / NovelEditor 741 / TavernFree 728 / useTavernFreeModel 702）；备份元数据与载荷未分离（#012 残留） | 债是**明确且可排期**的 |
| 🔴 **新增**：2026 年 6–8 月网文平台全面严打 AI 正文，判定标准转向「人类是否有实质主导权 + 创作过程是否可举证」 | **「能证明这是我写的」从加分项变成刚需** —— 见第三章 |

**总判断**：下一阶段不横向扩张，收口到三件事——
① 让新用户活下来（转化）；② 让长篇跑得动（性能与数据安全）；③ 把已铺好的能力串成闭环，**并且让创作过程留得下痕迹**。

## 三、联网核查结果（09-21）

### 3.1 🔴 最重要的行业信号：平台严打 AI 正文，判定标准变了

| 时间 | 事实 |
|---|---|
| 2025-03 | 《人工智能生成合成内容标识办法》出台 → 番茄等平台投稿**强制勾选「是否使用 AI」** |
| 2026-06 | 番茄公告：49 位金番作者因 AI 全篇代写被罚、17 账号永久封禁；单月拒签低质书 11.27 万本 |
| 2026-08 | 起点对 AI 痕迹过重作品限流：约 100 本月票榜作品被移出榜单与推荐位；番茄、晋江、纵横同步升级检测 |

**各平台底线（大同小异）**：AI 辅助**大纲 / 人设 / 校对 / 排版**＝允许；AI 生成**正文**＝严禁。
起点口径：AI 占比 **>10%** 触发处理；人工改写需 **>30%** 才算合规。晋江最严（仅允许校对、要素整理、粗纲）。

**平台检测抓三类信号**：
① **行文指纹**——用词过于标准、排比结构单一、语言模板化；
② **设定一致性**——前后文脱节、情节逻辑错乱、人设变化僵硬；
③ **创作轨迹**——更新速度、章节字数分布是否符合人类写作规律。

**法律界给出的判定核心**：*人类是否对核心表达拥有实质性主导权并作出创造性投入*。
AI 辅助的场景通常有**完整大纲、多版修改稿、创作日志**；AI 代写往往只有提示词和成稿，**中间过程缺失**。

> → **对产品的直接含义**：「中间过程」正在从"写作习惯"变成"举证材料"。
> 我们天生就在产生这些材料（细纲 → 正文 → 每次改写 → 每日字数），只是**没有把它们组织成可导出、可举证的形态**。
> 这就是 P0-4 / P1-9 的由来 —— 也是市面工具几乎没人做、而我们做起来最顺手的一块。

### 3.2 核查挖出的三个新方向

| 新方向 | 来源信号 | 为什么我们做最合适 | 落位 |
|---|---|---|---|
| **创作轨迹存证** | 合规判定看「中间过程」 | 细纲、快照、每日统计**我们本来就在产生** | P0-4 |
| **投稿前自检** | 检测抓「行文指纹 + 设定一致性」 | 一致性引擎已有；句长/句式统计纯本地可算，**不需要 AI** | P1-8 |
| **AI 占比自披露** | 平台强制勾选是否用 AI | AI 产出来源**我们本来就有标记** | P1-9 |

### 3.3 国外工具对标（我们差什么 / 已有什么）

| 工具 | 它的卖点 | 我们 | 差在哪 |
|---|---|---|---|
| **Novelcrafter** | Codex 设定库：写某场景时 AI 自动知道该地点的既有设定 | ✅ 已有（设定资料 + `aiContext.PRIORITY` + 别名） | 不差 |
| **Sudowrite** | Describe / Brainstorm / Rewrite / Feedback（标出节奏与一致性问题） | ✅ 大部分已有（伴写、灵感、整章改写五档） | 缺「Feedback 式一章体检」→ P2-10 |
| **ProWritingAid** |  pacing 节奏分析、对话评估、风格一致性、25+ 报告 | ⚠️ 部分（styleAudit、错字、敏感词） | 缺**节奏/张力曲线** → P2-11 |
| **NovelAI** | Lorebook 世界观记忆 | ✅ 已有（跨表引用 + 保密等级 + 防剧透） | 不差 |
| **通用模型（Claude/GPT）** | 长上下文、散文质量强 | ⚠️ 我们只是调用方 | 战略提示见下 |

> ⚠️ **战略提示（核查里最扎心的一条）**：2026 年的评测认为**通用前沿模型的散文质量已超过多数专用写作 App**，
> 专用工具只能靠「便利性与项目记忆」竞争。
> ⇒ **别再去卷"生成质量"**（卷不过，也没必要），我们的护城河是**结构化项目数据 + 本地不出本机 + 全流程闭环 + 过程可举证**。
> 这与「不横向加生成功能」的判断完全一致。

### 3.4 中文作者实证痛点对照（某全职作者自测的时间分布）

| 阶段 | 时间占比 | 他的卡点 | 我们现状 |
|---|---|---|---|
| 大纲 / 世界观 | 15% | 逻辑闭环难、容易写偏 | ✅ 卷纲 + 细纲 + 缺口补齐 |
| 细纲 / 章纲 | 20% | **爽点节奏把握不准** | ⚠️ 部分 → P2-11 |
| 正文初稿 | 45% | 卡文、水字数、情绪断层 | ✅ 伴写 / 续写 / 创意写作 |
| 修改润色 | 15% | **前后文一致性检查** | ✅ 连续性检查（串成闭环见 P2-10） |
| 发布 / 排版 | 5% | 格式调整、**各平台敏感词库不统一** | ⚠️ 有词库无分平台 → P2-12 |

他自搭的三件套：**卡文急救（给 3–5 个走向，不直接用 AI 正文）＋ Obsidian 设定卡片化（防"第三章死了第十七章又出场"）＋ 自建敏感词脚本**。
——这三件我们分别对应：灵感工具 ✅ / 设定与跨表引用 ✅ / 敏感词 ⚠️（缺分平台与投稿前一键跑）。

### 3.5 明确不做（含合规红线）

| 项 | 决定 | 理由 |
|---|---|---|
| 🔴 **反检测 / 洗 AI 痕迹** | **坚决不做** | 帮人规避平台审核＝帮人违规，产品会背锅，也与老大"AI 只做辅助"的公开立场冲突。我们做的是**保留创作主权、提升作品质量、如实申报**三件事 |
| 语音输入 / 口述写稿 | 不做 | 桌面端可借用系统输入法，性价比低 |
| 自动生成正文赚钱流水线 | 不做 | 与产品立场和平台规则都冲突 |
| 跨设备自动同步（#001）/ 域名备案（#004）/ PWA（#014）/ 自动更新（#016）/ 上架市场（#024）/ i18n（#028） | 已拒绝，不再议 | 见历史决策 |
| #033 服务器资产处置 | **老大决定搁置** | 本版不再列入 |

## 四、如果只做一件事

**P0-2 长篇性能基线** 仍然排第一（它是唯一能用数据决定后续动作、且不碰现有功能的动作）。
但如果要选**最有独占价值的**，是 **P0-4 创作轨迹存证** —— 市面几乎没人做，中文网文作者在 2026 年却正需要它，而我们 80% 的基建已经躺在仓库里。

依赖顺序：**P0-4 的存证需要快照**，所以快照先落地，存证包随后。
