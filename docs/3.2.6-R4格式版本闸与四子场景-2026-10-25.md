# 3.2.6 · R4 格式版本闸与四子场景实测（2026-10-25）

> 承接 [R4 游客端到端往返](3.2.6-R4游客端到端往返-2026-10-25.md)。
> 本轮做两件事：① 修一个**真会丢数据**的导入缺陷（格式版本完全不校验）；
> ② 把矩阵 `roundtrip` 要求的四个子场景在 **portable / web-guest** 两端真跑出来，矩阵 8 → **10 / 26**。

## 1. 🔴 缺陷：导入从不校验格式版本

`lib/revision/faultInjection.ts` 里早有 `checkDataVersion()`，但它**只被单测调用**，
三条导入路径（桌面 / 便携+云端 / 游客）**一处都没用**。

而 `normalizePortableData` 是**容错归一化**：`fileVersion` 原样搬过来、不认识的新字段直接丢。于是：

> 用新版本软件写的数据文件，在旧版本里导入 → **静默接受** → 再存一次，
> 就把新版本才有的字段整库抹平。**不可逆**，而且作者完全不会预期。

### 修复口径（三条路统一）

| 文件 `fileVersion` | 行为 |
|---|---|
| **> 当前**（`PORTABLE_FILE_VERSION` = 2） | 拒绝，理由写明「由更新版本的软件导出（格式 vN，本版本最高支持 v2）」+ 「已取消导入，本机数据未改动」 |
| **= 当前**，或**没有这个字段**（1.x 老文件按 v1） | 照常导入 —— 重装/换机拿旧备份是主路径，不能因为缺字段就打不开 |
| 脏值（0 / 负数 / 小数 / 字符串） | 拒绝，理由里带出原值 |

**闸的位置是关键**：必须放在 `replacePortableData` / `data = ...` / 「先清空再写入」**之前**。
放在后面就等于"已经清过库了再告诉你不许"。

### 读入侧也一起修了

`initPortableStore` 与 `decideDataFileLoad`（桌面）原本对"更新版本的数据文件"照常 `ready`，
于是**打开旧版软件就会把新格式库覆盖成旧格式**。现在：读出来给人看，但**锁写盘**，
红条写「数据文件格式版本高于本版本…请升级软件后再打开」。

### 顺带对齐的两处

- 游客导出把 `fileVersion` 写死成 **1**（应用早已是 v2）⇒ 改为 `PORTABLE_FILE_VERSION`：
  否则游客备份会自我标注成"老格式"。
- 游客导出**不含**语义向量与知识库（两个独立 IDB，按设计不进整库 JSON），
  但提示语写的是「已导出本机全部数据」「完整副件」——**少说了范围**。
  已补一句「（语义检索索引与知识库不在这份文件里，换设备后需要重新建档）」。

## 2. 四子场景怎么验的（portable / web-guest 各一套）

| 场景 | 便携 | 游客 |
|---|---|---|
| `schema-version` | 把导出文件的 `fileVersion` 改成 999 再导入：**被拒 + 磁盘逐字节未变** | 同（判定改为 IndexedDB 指纹） |
| `sidecars` | 先用真实 HTTP 写一行 `vecRows` 到 `/api/blob`；导出必须**内联进单文件**；导入后必须**再拆回 blob** | 断言导出文件里没有 `vecRows/kbDocs/kbBodies`，**并且界面如实说了没包含** |
| `secret-stripping` | 先用服务端条件写 PUT 一枚 `aiProviders.apiKey`；导出文件里**不得出现**该字符串与 `aiProviders` 行 | 同（种子写在 IndexedDB 的 meta） |
| `restore-failure` | 损坏 JSON 导入 → 被拒 + 数据文件未变 | 同（IndexedDB 未变） |

三处避免"假通过"的设计：

1. **先证明种子真的在**（`secret-present-before`）——否则"导出里没有密钥"是句空话；
2. 场景清单是**算出来的**：`scenarioGroups` 里任一检查没走过/没过，该场景就不写进 `payload.scenarios`；
3. `reliability.mjs` 的 `promoteRoundtrip()` 拿 `payload.scenarios` 与 `policy.json` 要求的四项比对，
   缺一项就**这一步失败**，宁可格子不亮 —— 不拿"脚本跑过了"冒充"四个场景都验了"。

| 项 | 值 |

## 4. 踩到的坑（都写进注释了）

- 🔴 **`page.evaluate` 没有超时**：里面碰 IndexedDB 的 Promise 一旦不 resolve，脚本会**静默挂死**
  （实测挂到 7 分钟、一个字节输出都没有）。现在所有碰 IDB 的 evaluate 都包 `withTimeout()`。
- 🔴 **`page.evaluate` 的函数体在浏览器里执行**：Node 侧的常量必须当参数传，否则是 `ReferenceError`。
  本轮就因此把"播种"卡死了 —— 而超时机制上线前，它表现为"整脚本无输出"。
- 探针跑之前**必须重建 dist**：本轮第一次跑版本闸没生效，就是因为拿的是改代码之前的构建产物。

## 5. 边界（别当已验）

- **desktop 与 web-cloud 的同样四个子场景还没做**（矩阵那两格仍 unverified）。
- 在途编辑、切项目、关窗时的写失败仍未覆盖。
- 版本闸只覆盖**导入**与**读入锁写盘**；跨版本字段级迁移（v1→v2 的语义转换）沿用的是 `migrateSidecar`，
  没有针对"未来版本字段"的降级映射 —— 这也是拒绝而不是尝试理解的原因。
