## 经验教训（下次照做）
1. **282 行别肉眼数**：`ssh ... > 临时jsonl` 后写 node 脚本重建整份 md（明细+概览表累加+last_id），用完 `rm -rf` 临时目录。脚本里概览表要解析已有表格行做累加，不能覆盖。
2. **ts 是 UTC，概览按本地日期分组必须 +8h**，否则跨日统计错位。
3. **异常先证伪再下结论**：本次初判"服务端换同步码导致老码集体 401"，实际 `grep` systemd 发现旧码仍在 20 码白名单内、服务 12:56 就启动（早于故障时段），假设被推翻。改从前端代码找根因才定位到 `initPromise` 永不重置。**脚本自动生成的推测结论必须人工复核后改写，别让猜测留在文档里误导老大。**
4. **authfail 的 GET/POST 比例是关键指纹**：全 POST 无 GET ⇒ `ensureInit` 缓存未重置、只剩 seed 的那次 POST。
5. 红线：只立案不改码、不封装。
