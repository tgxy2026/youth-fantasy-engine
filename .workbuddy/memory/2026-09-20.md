## 第三轮（下午）：整章改写 —— 补「续写」动作 + 字数硬校准 + 口径统一

**老大三个反馈**：
① 「有润色 / 扩写 / 精简 / 改写四个，但没有**续写** —— 改写是整章重写，续写是在**原有基础不变**的情况下达到目标字数」；
② 「目标字数限制不严：3000 字要求改写到 4000，实际改到了 5000」；
③ 「上下最多 300 字波动；所有字数要求都要确认口径 —— 前端以**汉字**为基础，AI 按 token / 字符算的话要转换」。

### 诊断（三条都不是"调参"能解决的）

| 现象 | 根因 |
|---|---|
| 目标 4000 实际 5000 | `aiRewriteChapter` **只靠提示词**要求字数（而且写的是"±10%"），**没有任何事后校准** |
| 没有「续写」 | 动作表只有 4 个；且「扩写」是**通篇加料**（会重写原文），不是"原文不动、往后接" |
| 口径 | `countWords` **本来就是汉字口径**（CJK 逐字 + 拉丁词，标点不计）✓ —— 缺的是**把口径写进给模型的提示词**，模型按 token / 字符估必然偏长 |

### 改造

- **抽出 `lib/wordRange.ts`**：`WORD_TOLERANCE = 300` + `askSoft` + `enforceWordRange` 从 `autoContinue.ts` 迁来。
  🔴 **必须抽**：整章改写（`aiTasks/rewrite.ts`）也要用它，而 `autoContinue.ts` 依赖 `aiTasks` 门面
  → 直接 import 就是**循环依赖**（会被 importCycles 闸拦）。抽到只依赖 `ai` + `textStats` 的一层后方向干净。
  `autoContinue.ts` 再导出 `WORD_TOLERANCE`，保持面板等既有 import 路径可用。
- **新增「续写」动作**（`polish | expand | condense | continue | rewrite`；界面顺序：润色→扩写→精简→续写→改写）。
  🔴 **实现走结构保证，不靠提示词**：「原文一字不动」如果交给模型（"请保留原文只往后写"），
  它**总会顺手把原段润色一遍** —— 所以续写时**原文由代码保留**、模型只吐**新增片段**，拼接后返回；
  直接复用 `enforceWordRange` 的增量补写循环（它本来就是"紧接着上文往下写"）。
  🔴 `maxShrink: 0`（绝不压缩 —— 原文是作者写的）、`maxExpand: 8`。历史章续写给红色劝阻。
- **字数硬校准（±300）**：改写 / 扩写 / 精简 / 续写的结果**一律过** `enforceWordRange`；
  精简 `maxExpand: 0`（压到一半又补回去很荒谬），其余补 2 轮 / 压 2 轮。
  提示词从"一个数 + ±10%"改成 **区间 + 口径**（`必须落在 3700~4300 个汉字之间…按汉字个数计，标点与空白不计`）。
- **口径统一**：**所有**给模型的字数都写明「按汉字个数计，标点不计」。
- **顺手修（推演中发现）**：缺口超单批上限时，状态行/提示词会说"补第 22-100 章"而实际只排 60 章 ❌
  → 现在 `sealing.gapTo` 在构造时就被 `MAX_OUTLINE_CHAPTERS` 夹住，界面明示「单批上限 60 章，剩下的下次继续」。
- 文案同步：面板帮助（扩写 vs 续写的区别）、`RW_ACTIONS`、`RW_SCOPE_NOTE`、文件头注释。
