## 恶性 bug 修复：表格页签黑屏
- 现象：访问人物关系网及其下方所有表格页签黑屏
- 根因：上一轮自动排序功能在 TableSheet.tsx 中把 `sortedRows = useMemo(...)` 写在了 `if (!loaded) return ...` 提前返回之后，违反 React Hooks 规则——首次渲染（loaded=false）不执行 useMemo，数据加载后重渲染执行，两次 hooks 数量不一致，React 抛 "Rendered more hooks than during the previous render" 导致整树崩溃黑屏
- 修复：useMemo 移到提前 return 之前（TableSheet.tsx 现约 163 行），已验证 tsc 通过 + Vite 热更新生效
- 教训：tsc 无法发现 Hooks 顺序问题；后续给 TableSheet/CharacterSheet 等带 `if (!loaded) return` 的组件加 hook 时必须放在该 return 之前。已扫描全部组件，仅此一处违规

## 1.0 便携（U 盘单文件）版打包

### 目标
"双击即用 + 跨设备数据不丢 + 无需环境"——把 Web App 封装成可放在 U 盘里的应用。

### 关键架构决策
1. **数据跟随 U 盘，而非浏览器**：原 IndexedDB 是"每台设备每个浏览器"独立存储，违反换电脑不丢的要求。改为把整个数据库序列化到 U 盘上的一个 JSON 数据文件，通过浏览器 File System Access API（showOpenFilePicker/showSaveFilePicker/createWritable）直接读写该文件
2. **整个 App 打成单个 HTML**：用 `vite-plugin-singlefile` 把所有 JS/CSS/资源内联进 index.html → novel-studio.html（0.43 MB），双击即在浏览器里运行，无需 Node/HTTP 服务器
3. **存储层加适配器**：db.ts 内部把 `getAll/get/put/del` 4 个原语路由到 `idbOps`（开发/网页）或 `portableStore`（便携，内存+防抖写盘），上层 30+ 个函数签名零改动 → 组件零改动

### 实现细节
- 新增 `src/lib/portable.ts`：便携引擎。`PORTABLE` 常量由构建时 `define: { __PORTABLE__: 'true/false' }` 注入；800ms 防抖写盘；空文件视作新建；DOMException AbortError（用户取消）静默不当作错误
- 新增 `src/components/Portable.tsx`：PortableGate 启动页（打开/新建数据文件 + 浏览器不支持提示 + 迁移提示）+ PortableBadge 左下角保存状态徽标（保存中/待保存/已保存/出错四态，点击立即写盘）
- `db.ts` 重写：getDB+迁移代码原样保留（仅 IDB 模式走），所有数据函数改走 `ops` 适配器；导入项目/导入备份接口沿用网页版 JSON 格式做迁移入口
- `App.tsx`：新增 `fileReady` 状态 + 便携模式订阅 + beforeunload flush；未连接时全屏渲染 PortableGate
- `vite.config.portable.ts`：define true + viteSingleFile + 自定义 `stripExternalFonts` 插件（移除 Google Fonts 链接+改 title，离线设备不再阻塞首屏）
- `scripts/make-portable.mjs`：构建后 rename index.html → novel-studio.html，复制 portable-assets（START.bat + 使用说明.txt）到 release/
- `START.bat`（**纯 ASCII 内容，避免 Windows bat 编码问题**）：通过注册表 App Paths 优先找 chrome.exe（HKLM→HKCU），再 msedge.exe，最后默认浏览器
- 使用说明.txt：UTF-8，含从网页版迁移、首次使用流程、注意事项、FAQ

### 浏览器要求
Chromium 内核（Chrome / Edge），因依赖 File System Access API。Firefox 不支持（仅保留 JSON 导入/导出兜底）。file:// 协议下 API 可用。

### 启动安全策略
每次启动必须用户点一次"打开数据文件"（浏览器要求文件读写必须由用户手势授权）——这是不可绕过的安全要求，已在启动页明确说明。

### 本环境打包踩坑（重要，复现时按此处理）
1. **下载失败**：electron zip 与 electron-builder 组件需国内镜像：ELECTRON_MIRROR / ELECTRON_BUILDER_BINARIES_MIRROR = npmmirror.com/mirrors/...
2. **损坏缓存**：AppData\Local\electron\Cache 里损坏的 zip 删不掉（沙箱禁删）→ ELECTRON_CACHE 指向项目本地目录绕过
3. **winCodeSign 解压失败**：7z 包内 2 个 darwin 符号链接无权限创建（Windows 非管理员/非开发者模式）→ 手动 7za 解压到最终缓存目录名 `winCodeSign-2.6.0`（ELECTRON_BUILDER_CACHE=release/eb-cache），符号链接留 0 字节占位（macOS 专用，Windows 打包不读）
4. **下载后 rename 被拒**：本机安全策略禁止文件改名/删除（bash rm/node fs.rmSync/Go rename 全被拦）→ 所有"解压到临时名再改名"的步骤改为手动 cp 到最终名；nsis-3.0.4.1、nsis-resources-3.4.1 同法处理
5. **UAC 插件缺失**：nsis-resources 的 plugins/x86-unicode/*.dll（UAC.dll 等）需手动 cp 进 nsis-3.0.4.1/Plugins/x86-unicode/
6. **输出目录必须全新**：重复构建 EnsureEmptyDir 删旧产物会失败 → 每次换新 outDir（desktop-out）
7. **冒烟测试坑**：环境有 ELECTRON_RUN_AS_NODE=1 和 NODE_OPTIONS（WorkBuddy shim）会破坏打包应用运行，测试时需 `env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS`；GPU 报错是虚拟环境无显卡，`--disable-gpu --in-process-gpu` 绕过；验证用 `--remote-debugging-port=9333` + curl /json + node 内置 WebSocket 查 DOM（console.log 在 Windows GUI 子系统下不可见）
