## #025 云同步推送 413 根因实锤与修复（22:0x）
- **推翻上一条假设**：用户机器 `182.200.137.106` 的 pull 一直带有效码(4edd6fb4)且 200，说明"会话没带码"不成立。真实根因是**体积上限**：nginx `/api/sync` 未设 `client_max_body_size`→走默认 1m；node `feedback-server.mjs:320 readRaw(req,1MB)` 是第二道 1MB 闸。用户项目数据已涨到 ~1MB，`{rev,enc}` 推送包超 1MB 即被 nginx 直接 **413**（413 在 nginx 层返回，不进 feedback-server，故 access.jsonl 全空白——这就是"服务端毫无痕迹"的真相）。GET 不带 body 不受限→pull 永远成功；POST 受限→push 失败→`pushNow` 未处理 413→走 else 置 `error`→角标"同步失败"。
- **修复（已部署+验证）**：①`server/yfe.conf` `/api/sync` 加 `client_max_body_size 20m`；②`feedback-server.mjs` `readRaw` 1MB→20MB；③客户端 `pushNow` 补 413→新增 `SyncStatus='too-large'`，`WebTools` 角标显示"数据过大"（#025）。实测 5MB/10MB POST 不再 413、直达 feedback-server 返回 409(rev 不符，预期内)。commit **b979e8d**。部署：`sudo cp yfe.conf→/etc/nginx/sites-available/yfe`+`nginx -s reload`；`sudo cp feedback-server.mjs→/opt/yfe-server`+`chown www-data`+`systemctl restart yfe-feedback`；web `npm run build:web`→scp dist-web→`/var/www/yfe`+`chown www-data`。用户需**硬刷新(Ctrl+Shift+R)部署版**重测。
- **快照成分分析（22:1x）**：用同步码 `YFE-SYNC-7Q3K-2X9M` 本地复刻 PBKDF2+AES-GCM 解密线上 `sync-4edd6fb4...json`(rev29, 982KB加密/736.5KB明文)。占比：**backups 50%(单条完整项目副本 368KB)**、chapters 30.6%(15章/225KB)、tableRows 11.5%(180行)、cardRecords 6.1%(34张)、formData 1.4%、其余<1%。**结论：活数据仅 ~368KB，另一半是冗余备份副本**——这正是 #025 被 1MB 顶穿的主因。优化项 A「云同步排除 backups(或 gzip/滚动)」可砍半体积，但当前 20MB 余量足，暂不做。
