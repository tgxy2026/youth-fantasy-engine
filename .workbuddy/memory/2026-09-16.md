## P1：反馈 #1 修复（用量明细不跟控制面板预算变）— 当天追做

**结论先说：是「用量明细」的显示 bug，配置本身一直是生效的。**
- 引擎那条路对：`resolveParams('free', commonParamsLayer(st.common), modeParamsLayer('free', st), session.params)`
  —— 控制面板的通用层压过会话层，请求早就按新预算在跑。
- 明细那条路错：`TavernUsageDialog` 直接读 `session.params.contextBudget`，空了就回落
  **硬编码常量** `TAVERN_DEFAULTS.*.contextBudget`（24000），完全绕过控制面板。
- 🔴 根因是「同一个数在两处各算一遍」，不是取值取错 —— 所以修法是**消除分叉**而不是各修一遍：
  1. `settings.ts` 新增 `resolveParamsOf()` / `effectiveContextBudget()`；

## 第五批：dev 环境 origin 归一化（老大问「localhost 和 127.0.0.1 有什么区别」）

**老大原话**：「我一直用 localhost:5199 做开发预览测试，跟 127.0.0.1 有什么区别为什么不能合并成一个？」

### 根因（也是他之前「看不到测试数据」的真相）

浏览器只按 **origin = 协议 + 主机名 + 端口** 判断同源，**不会**推断「localhost 与 127.0.0.1 是同一台机器」。
所以同一个 dev server、同一个端口，两个写法是**两个 origin**，同源策略给每个 origin 各存一份
IndexedDB / localStorage —— 他日常用 localhost（主库在那边），而按我上次的指示去 127.0.0.1 注入，
数据进了另一份库，两边互相看不见。

### 已修

- `vite.config.ts` 新增 dev 专用插件 `normalizeDevHost()`：`127.0.0.1:5199` 的请求 302 → `localhost:5199`。
  · `configureServer` 里**直接** `server.middlewares.use` 是**前置**中间件（返回函数才是后置）——
    必须在 Vite 内部中间件之前拦下文档请求。
  · 只匹配 `127.0.0.1`：局域网 IP（手机调试）不受影响；只在 dev 生效，构建产物与 Electron 不受影响。
  · `host: true` 保持不变（= 0.0.0.0，与 `npm run dev` 一致）→ localhost 走 IPv4/IPv6 都通。
- `dev-seed/diagnose.js` 的 origin 断言改为「应为 `http://localhost:5199`」+ ✅/⚠️；
  `dev-seed/fengyang.js` 与 04 交付 README 的口径统一到 localhost，并补「为什么以前会看不到」根因段。
- 提交 `d348bbc`。验证：curl 302 → 200；真 Chromium 5 条断言全绿（跳转后 origin 就是 localhost、
