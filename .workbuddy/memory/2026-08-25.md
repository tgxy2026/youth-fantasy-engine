# v2.0 功能建议书（竞品对标分析）

产出 `docs/v2-roadmap.html`（自包含 HTML 报告，暗色主题对齐 app 配色）。

## 对标样本
- 平台侧：起点作家助手 v5.11（阅文）、番茄作家助手
- 开源侧：Arboris-Novel 818★、awesome-novel-agent 636★、NeuroBook 561★、StoryForge、Show Me The Story、bibisco、Manuskript、Plottr、Campfire、LivingWriter、NovelPad

## 核心判断（重要，后续开发的主线依据）
**v1.0 的数据模型（32 页签）深度已超过所有对标项目**——伏笔追踪表（含重要度+回收前置条件）、知情权限表、爽点节奏表、设定变更表这套结构，818★/636★ 项目都没做到这个粒度，世界构建细度超过商业产品 Campfire。
**真正短板不是"表不够"，而是表与表之间是死的**：数据录入后系统不对账、不告警、不反推。所以 v2.0 主线应是「让已有数据活起来」，而非继续加表。

关键断链实例：
- `chapter-master` 有「埋设/回收伏笔编号」，`foreshadow` 有「状态」列 → 两表描述同一件事但需人肉同步，Dashboard 防烂尾告警建立在手填脏数据上
- `timeline` 有「时间线检查」列但检查动作纯人工，`StoryTimeline` 只排序不校验
- `style`（写作规范）让作者立了「视角切换规则/坏习惯清单」的法 → **全项目无一处执法**

## 建议分档
- **P0**（数据已就绪、零 AI、做完即拉开差距）：① 伏笔闭环引擎 `foreshadowEngine.ts` ② 正文↔设定联动侧栏 `entityIndex.ts` ③ 连续性校验器 `continuityCheck.ts` ④ 错别字检测 `typoWords.ts`（复用 SensitiveCheck 整条链路）⑤ 文风体检 `styleAudit.ts`（激活 style 表单）
- **P1**：角色出场分布图、人物关系力导向图、写作目标与完稿预估、导出增强（MD/EPUB/DOCX + **设定集导出** + 平台粘贴模式）、结构模板库
- **P2**：场景层级（不建议 2.0 动，会伤数据模型）、可选 AI 接入（OpenAI 兼容、仅起名/一致性提问/卡文锦囊，**不做整章代写**）、备份加固（单文件 JSON 风险）

## 明确不建议做
云同步/账号体系（摧毁本地数据主权卖点）、一键发布平台（阅文番茄不开放第三方 API）、平台数据看板（数据源拿不到）、社区/拼字 PK（依赖用户规模，单机做了即死功能）、重构为 scene-first 架构。

## 关键技术决策
正文实体高亮**不改 textarea 为 contentEditable** —— 会连带重构撤销栈、输入法组合输入、光标定位、时光机快照取值口径，对已稳定的 1.0 编辑器风险过高。改走「本章设定引用侧栏」方案，编辑区零改动拿到八成收益。

# 1.3 背景图迭代修复

用户反馈：白屏修好后，主题切换再次失效，且背景图变成「黄不拉几的一片」。

## 根因
`src/assets/workbench-bg.png` 原图并非透明线稿，而是奶黄底+黑色噪点+金色线稿的实底图。直接作为背景叠加后，整张图把界面糊成一片，主题切换自然被盖住看不出来。

## 改动
- `scripts/reprocess-bg.py`：用 Pillow 按色相/饱和度/明度过滤，去除白/奶黄底和黑色噪点，仅保留金色线稿并设 alpha 0.20~0.45，输出透明 PNG。
- `src/assets/workbench-bg.png`：从 1.9 MB 压到 ~68 KB，已是真正的透明底线稿。
- `src/App.tsx`：根容器从 `bg-ink-950`（不透明）改为 `bg-transparent`，让 -z-10 装饰层能透过 body 背景和半透明面板显示；装饰层 CSS `opacity-70` 改为 `opacity-100`（不透明度由 PNG 自身 alpha 控制）。

## 验证
- `tsc` 通过（0 错误）。
- `vite build` 通过（1567 modules，dist/assets/workbench-bg-*.png 仅 67.92 kB）。

## 结论
背景图务必先处理成透明底再投入使用；容器若带不透明背景色，负 z-index 装饰层会被盖住。

## 续改（用户验收后）
- 项目管理页 `ProjectHub.tsx` 也接入同一金色线稿背景（`-z-10` 装饰层 + `bg-transparent` 根容器），与项目内页视觉一致。
- 用户嫌线稿偏淡，将 PNG alpha 由 0.20~0.45 上调到 0.35~0.65（`scripts/reprocess-bg.py` 改两处常量后重跑），构建通过。
- 验证：`tsc` 0 错；`vite build` 1567 模块通过（dist/assets/workbench-bg 约 67 KB）。

# 三项修复（问号崩溃根因 + Ctrl 文本 + 项目编辑）

用户复验后再提 3 项：① 使用指南 ? 点击跳空白页；② 部分 ? 提示里 Ctrl/⌘+S 错误文本；③ 项目首页已建项目无法改书名/封面。

## ① 根因（关键，已复现验证）
`HelpPopover.tsx` 的 `useLayoutEffect` **没有依赖数组**，每次渲染都执行 `update()`→`setPos`→重渲染→再执行 → **Maximum update depth exceeded** → React 卸载整棵组件树 → 白屏。所有 `?` 共用该组件，故全部中招（含使用指南）。
- 修复：`update` 改为 `useCallback([width, side])`；`useLayoutEffect` 依赖 `[open, update]`（仅 open 变化时定位一次，rAF 二次校正高度）；原 `useEffect([])`（外部点击/Esc/滚动关闭监听）同样补 `[open, update]` 依赖，否则监听永不挂载。
- 验证：用 Edge(headless)+playwright-core 写 repro 脚本，点击使用指南/写作面板 `?` 均正常弹出不崩溃（root 不空白、popoverVisible=1、无 pageerror）。验证后已删除 `_repro` 临时目录。

## ② Ctrl/⌘+S 文本
编辑器确有 Ctrl+S 保存 + 停止输入 2 秒自动保存（状态栏「自动保存已开启」属实，非错误）。问题仅是 `CharacterSheet/OutlineSheet/TableSheet` 的 ? 文案写 `Ctrl/⌘+S`，与其余页面（及按钮 title「保存（Ctrl+S）」）不一致。统一改为 `Ctrl+S`；`FormSheet/GuidePage/NovelEditor` 本就用 `Ctrl+S`，无改动。grep 确认已无 `Ctrl/⌘` 残留。

## ③ 项目书名/封面编辑
`db.updateProject(patch)` 已存在。ProjectHub 项目卡片新增「编辑」按钮（铅笔图标，title=编辑书名与封面）：点击进入行内编辑态——复用新建表单的封面上传/移除逻辑 + 书名输入框（autoFocus），保存调用 `updateProject({id,name,cover})` 后 `load()` 刷新，取消则还原。编辑会 bump `updatedAt`（项目置顶，符合预期）。
- 验证：repro 改名「改名测试书名XYZ」→ 保存 → 卡片即时显示 → 刷新页面后仍在（持久化 OK）。

## 收尾补丁：dev 服务器崩溃修复
