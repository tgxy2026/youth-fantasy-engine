  歧义从源头产生，整条链路据此把「文件存在但读不到」当空库，随后一次 push 覆盖云端真实数据。

### 🔴 关于 lint 那 11 条 exhaustive-deps（更正一个可能的误解）
本轮**逐条核实**了缺失依赖的声明性质，结论：**它们全是组件体内未包 `useCallback` 的普通箭头函数**
（`load` / `calValueOf` / `validateCodes` / `cellVal` 等），身份**每次渲染都变**。
→ 因此**不存在「可证明安全」的批量修法**：直接补进依赖数组会让 useMemo 每次重算，

# 第六轮：协议窗**真正**对齐（连错两轮的根因）+ 楚楠示范卡 + 默认我演 + 无用户角色的答复（老大第六批）

## 1. 🔴 协议窗对齐：老大说「还是差一大截」是对的，我上一轮的**验证口径本身就是错的**
上一轮我比的是「协议段底部 vs **右列容器**底部」——网格 `stretch` 会把列容器拉成等高，所以两边永远相等、
把真 bug 遮住了。这次改比「**协议段底部 vs 自由对话控制那一段的底部**」，立刻现形：**3239 vs 2346（差 906px）**。

顺着查，一共三层原因（每层都单独能坏事）：
1. **包装层写了 `xl:flex-1`** —— 主轴是高度时，`flex-basis` 会**压过** inline 的 `height`，
   包装层被「填充剩余空间」接管，JS 设多少高度都无效 → 删掉 flex-1，改 `shrink-0`。
2. **flex item 的 `min-height:auto`（=内容高度）** 把定高顶回去（1452 被顶到 1568）→ 加 `overflow-hidden`
   （规范里 `min-height:auto` 唯一的例外就是 overflow≠visible），包装层与 Section 都要加。
3. 🔴🔴 **界面缩放**：`<html>` 上有 `zoom: 1.08`（`theme.ts` 的 `yfe-ui-zoom`，默认 108%），
   而 `getBoundingClientRect()` 返回的是**缩放后的视觉像素**、`style.height` 收的是 **CSS 像素** ——
   我拿 rect 量出来的差（1453）直接当 CSS 值写回去，恒定偏大 8%，所以**怎么调都差一截**。
   → 改用 `offsetHeight`。**实测：协议底 2345 / 自由对话控制底 2346（差 1px）** ✓
   📌 项目里 `useResizable.ts` 早就处理过同一件事（拖拽位移换算回布局像素），我该先搜一下已有的坑。
   🔴 三条已写进 MEMORY.md 新开的「布局与尺寸坑」小节，并补进 skill。

  两个解析器（六栏记忆、日常三段）改成**同时容忍** 〖〗 与 【】（模型会照抄我们的，也会习惯性写旧符号）。

### 第十一批 · 路线图第 1 批：消息级操作（重说 / 编辑 / 隐藏 / 删除）+ 快捷指令条

**1) 数据层**
· `TavernMessage` 增 `hidden?: boolean`；顺手删掉从未被用过的 `alternatives`（老大已明确"重说不做多候选"，
  留着它只会误导后来的人）。
· `store.ts` 新增四个**只构造新会话、不落库**的纯函数：`patchMessage` / `dropMessage` /
  `toggleMessageHidden` / `lastAssistantId`（泛型同时服务剧情会话与自由会话）。
· 隐藏的**排除唯一出口**：`prompt.ts` 的 `toChatMessages`（两条线都走它）+ `memory.ts` 的
  `messagesAfterWatermark`/`countUnsummarized`（隐藏的内容也不该被整理进记忆）。

**2) 引擎：重说**
`runPlotTurn(session, userText)` / `runFreeTurn(session, chars, userText)` 的 userText 改成 `string | null`：
**null = 重说** —— 不追加用户消息，先 `dropTrailingAssistant` 丢掉末尾那条 AI 回复，于是新生成的结果
天然替换掉它。两处细节：
· 自由模式的角色轮转按**基座**（已丢末尾）来数，否则重说会顺延到下一位说话人，观感很怪；
· **重说失败（空回复）时保留原来的 messages** —— withUser 已经把那条丢掉了，不特殊处理就会
  「一次失败把回复删没了」（这个是写的时候差点漏掉的）。
另外定了条契约：末尾没有 assistant 时**直接抛错**，不悄悄凭空造一轮。

**3) 界面**
· 新增两个共用组件：`TavernMessageBody`（正文 + hover 工具条 + 就地编辑）与 `TavernQuickBar`
  （快捷指令条）。两页共用是因为「各写一份必然漂移」是本项目反复踩的坑。
· 快捷指令条走协议 **R4 的「」导演指令通道** —— 用户本来就能手打，做成按钮即可，**不必改引擎**，
  而且不会污染「角色说过的话」这层语义。剧情推演 7 个（含重说）、自由对话 5 个。
· 「重说」只给**末尾那条 AI 回复**（改中间那条，后面是按旧版接的，必然打架）；编辑过的标「改过」；
  隐藏的灰显 + 标「已隐藏 · 不进上下文」；删除走 confirmDialog 二次确认。

**4) 踩坑（已进 skill）**
· 🔴 **组件在编辑态换掉外层容器，会让"按行号定位"的测试假失败**：我原先编辑态直接 `return` 一个
  不带 `group/msg` 的 div，行数从 5 变 4、行号错位 → 改成外层容器**恒定**。
· 🔴 **一进编辑态，正文就跑到 textarea 的 value 里**，`filter({hasText})` 再也匹配不到 → 定位目标行
  必须**按行号**（`evaluateAll` 找 index 再 `nth`），不能在点完编辑后还用文本筛。
· 🔴 进项目后会弹**备份提醒浮层**，它会把后面所有点击挡掉（报 `intercepts pointer events`）——
  切到页面后要**再关一次**浮层。
· ⚠️ 调试脚本自己写错参数（put 少传一个）导致注入写飞、白查一轮 —— 调试脚本也要保持和正式脚本同样的严谨。
