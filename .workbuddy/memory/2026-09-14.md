  歧义从源头产生，整条链路据此把「文件存在但读不到」当空库，随后一次 push 覆盖云端真实数据。

### 🔴 关于 lint 那 11 条 exhaustive-deps（更正一个可能的误解）
本轮**逐条核实**了缺失依赖的声明性质，结论：**它们全是组件体内未包 `useCallback` 的普通箭头函数**
（`load` / `calValueOf` / `validateCodes` / `cellVal` 等），身份**每次渲染都变**。
→ 因此**不存在「可证明安全」的批量修法**：直接补进依赖数组会让 useMemo 每次重算，

# 第四轮：协议窗严格平齐 + 推演报告左栏 + 自由对话改版 + 角色卡滚动（老大第四批）

## 1. 控制面板：协议窗底部与右列平齐（上一轮改过头了）
老大反馈：「之前比右边短，现在变成左边比右边长了」。**根因**：协议正文是**可滚动块**，
它的**内容高度会参与外层网格 auto 行的尺寸计算** → 正文一长就把行高撑大，左列反而比右列长。
纯 CSS 修不掉（`flex-basis:0` 也拦不住内容参与 max-content 贡献），所以改成 **JS 量**：
　`协议窗高 = 右列高 − 通用设置高 − 间距`（`ResizeObserver` + `matchMedia('(min-width:1280px)')` 只在两列布局生效，
单列时回到自然高），最低 240px 兜底。正文超出走它自己的滚动条。
**实测**：协议底 **3239** / 右列底 **3239**（差 0）·两列高 3068/3068·正文框 2166px（文本 2729 字）。
🔴 这条已写进 MEMORY.md：**别把这段 JS「优化」成纯 CSS**，会把老问题放回来。
