### A2 · 同步文件读失败保护（审计 P0-2，动的是用户数据安全）
- 病根在**主进程**：`electron/main.cjs` 的 `sync:readFile` 注释原文「文件不存在（首次）**或读取失败**，视为空」——
  歧义从源头产生，整条链路据此把「文件存在但读不到」当空库，随后一次 push 覆盖云端真实数据。
- 主进程改为**结构化返回**：`{ok:true,text}`（ENOENT → text:null）/ `{ok:false,reason}`。
  🔴 刻意**不 throw**：Electron 会重新包装跨 IPC 异常，`err.code` 在渲染端丢失，届时同样无法区分。
- `syncTransport.ts`：`fsaRead`/`nodeRead` 改返回三态 `RawRead`（absent / text / failed），
  `isNotFoundErr` 只认 `NotFoundError`/`ENOENT`；`parseRev` 新增 `{corrupt:true}` 分支**彻底摘掉「损坏当空库」**；
  `pull`/`push`/`startWatch` 遇读失败或损坏一律返回 `status: 0`（上层 `syncCore.ensureInit` 按「不可用→回退本地」处理，见 #011 语义），
  并把损坏文件另存 `.corrupt-<ts>`（**只隔离一次**，避免 8 秒轮询刷满目录）。
  兼容旧主进程：识别到旧的 `string|null` 契约时维持旧行为，待下次打包自动走新契约。
- **自愈性已核实**：read 失败 → status 0 → transientUnavailable → 同步暂停但本地编辑保留；
  用户继续写作时 `put → schedulePush → flushNow → ensureInit` 会重试，文件恢复可读即自动转 ok。不会永久卡死、不丢数据。
- **上了回归测试** `tests/syncTransport.test.ts`（17 用例）锁定三态语义与「不覆盖」。
- ✅ **做了负向对照验证**：把 corrupt 分支临时改回 `rev:0`，测试立刻 **8 条 FAIL**，
  其中「损坏文件原内容未被覆盖」实测值变成 `{"rev":1,"enc":"ENC-LOCAL"}`——
  **数据被覆盖的场景活体复现**，证明这套测试真能抓 bug（不是摆设），随后已还原并复跑全绿。
