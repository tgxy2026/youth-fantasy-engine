- 病根在**主进程**：`electron/main.cjs` 的 `sync:readFile` 注释原文「文件不存在（首次）**或读取失败**，视为空」——
  歧义从源头产生，整条链路据此把「文件存在但读不到」当空库，随后一次 push 覆盖云端真实数据。
- 主进程改为**结构化返回**：`{ok:true,text}`（ENOENT → text:null）/ `{ok:false,reason}`。
  🔴 刻意**不 throw**：Electron 会重新包装跨 IPC 异常，`err.code` 在渲染端丢失，届时同样无法区分。

- **自愈性已核实**：read 失败 → status 0 → transientUnavailable → 同步暂停但本地编辑保留；
  用户继续写作时 `put → schedulePush → flushNow → ensureInit` 会重试，文件恢复可读即自动转 ok。不会永久卡死、不丢数据。

### 🔴 关于 lint 那 11 条 exhaustive-deps（更正一个可能的误解）
本轮**逐条核实**了缺失依赖的声明性质，结论：**它们全是组件体内未包 `useCallback` 的普通箭头函数**
（`load` / `calValueOf` / `validateCodes` / `cellVal` 等），身份**每次渲染都变**。
→ 因此**不存在「可证明安全」的批量修法**：直接补进依赖数组会让 useMemo 每次重算，
