## 补充查证（老大追问）：本地 Ollama 到底能不能联网

**老大反馈**：「我通过 Open WebUI 调用 ollama 本地模型的时候是可以使用联网功能的啊」——
**他说得对，我上一条讲得太绝对。** 但结论方向不变，得说准：

- 🔴 **联网不是 Ollama 的能力，是调用方的能力。** Open WebUI 自带 Web Search 模块（15+ 个搜索后端），
  由**它的 Python 后端**去查、抓正文、注入模型上下文 —— 架构上就等于我们面板里的「搜索接口」档。
  本地 Ollama 自始至终只负责读提示词。
- 🔴 **它能在我们这里跑通，是因为它在服务端跑**（Node/Python 后端不受浏览器 CORS 限制）。
  我们桌面/便携版是**前端直连**，只能连带 `Access-Control-Allow-Origin` 的接口（博查实测可以）。
  ⚠️ 注：网页体验版有服务器反代（`toProxyUrl` → `/api/ai/<host>`）**不受此限**，但网页版已停服。
- Open WebUI 支持的引擎（官方 env 列表）：`searxng` / `google_pse` / `brave` / `kagi` / `mojeek` /
  `serper` / `serply` / `serpstack` / `searchapi` / `duckduckgo` / `tavily` / `jina` / `bing` / `exa` /
  `perplexity` / `sougou` / `yacy` / `firecrawl` / **`bocha`（博查，就在它列表里）** /
  **`ollama_cloud`（Ollama 自家云搜索，需 `ollama signin`）** / `external`（自定义端点）。
- 🔴 **一条明确的缺口**：我们的「自定义接口」是 `POST {query, count}` ＋ Bearer，
  而 **SearXNG 是 `GET /search?q=&format=json`** → 想接自建 SearXNG（免费、无 key）**现在填不进去**。
  要做的话得让「接口地址」支持 `{query}` 占位符 + GET（顺带兼容 Jina/Exa 这类）。
  **已告知老大，等他定，没自动动手。**

### 追加：DuckDuckGo 能不能内置？（结论：不能，三道坎）

- **实测网络**（本机 curl，带对照）：`html.duckduckgo.com` / `lite.` / `duckduckgo.com` / `api.duckduckgo.com`
  **全部 10s 超时**（http=000）；同批对照 `baidu.com` 200、`api.github.com` 200、`api.bochaai.com` 405（存在）→
  链路正常，是 DDG 不可达（另有 Google 同样超时）。⚠️ 本机出口有沙箱代理 `http_proxy=127.0.0.1:52209`，会过滤，
  但**DDG 在国内本就长期不可达**，结论方向不变。
- **结构上也不通**：DDG 没有面向浏览器的公开搜索 API（官方只有 Instant Answer API，给的是词条摘要、不是网页结果），
  HTML 端点不带 ACAO。Open WebUI 能用是因为它**在 Python 后端**抓（`ddgs`），不受 CORS 限。
- **第三道坎**：HTML 抓取要新写解析器（现有 `harvestItems` 只认 JSON），且限流/反爬/改版频繁 ——
  社区高频报错就是「搜索结果为空」。
- 🔴 **顺带查到一条有价值的架构事实**：`electron/main.cjs` 是 `contextIsolation: true` + `nodeIntegration: false`，
  **webSecurity 未关** → 渲染进程受 CORS 限（与上述判断一致）。但桌面/便携**已有 10+ 个 IPC 通道**
  （`store:*` / `sync:*`）→ **把搜索请求改走主进程 fetch 就能彻底绕开 CORS**，之后任何搜索源都能接
  （SearXNG / Bing / Jina / Exa…，有梯子的话 DDG 也行）。网页版已停服，不受益也无所谓。
  → 已作为候选方案交给老大（B 加 GET+`{query}` 占位符 / C 加 IPC 转发），未动代码。

### 追加：核实「网页版到底能不能联网搜索」—— 结论：当时的网页版也不能

上一条我讲了「网页版有服务器反代所以不受 CORS 限」——**机制对，但当时的部署并没有开这条路**。上服务器核了实物：

- nginx `/etc/nginx/sites-enabled/yfe` 的 `/api/ai/` 是**逐域名白名单**（13 个，全是 AI 模型服务商）：
  `api.siliconflow.cn` / `api.deepseek.com` / `dashscope.aliyuncs.com` / `open.bigmodel.cn` /
  `ark.cn-beijing.volces.com` / `api.moonshot.cn` / `api.minimax.chat` / `api.hunyuan.cloud.tencent.com` /
  `api.baichuan-ai.com` / `api.lingyiwanwu.com` / `api.groq.com` / `openrouter.ai` / `api.openai.com`。
  **没有任何搜索域**（无 `api.bochaai.com`）。
- 实测未白名单路径：`POST /api/ai/api.bochaai.com/v1/web-search` → **405**（落到静态兜底，没进代理）。
  → 即「当时的网页版**同样搜不了**」，要搜必须加一行 `location` + reload。
- 反代本身设计是好的（`yfe_proxy_params`：携带用户 Authorization、关 access_log 不落 key/内容、SSE 关闭缓冲）。
- 站点仍活着（本地 `GET /` 200），关服日 2026-09-29 08:49:53（`SHUTDOWN_NOTICE`）。

**对老大问题的准确回答**：走「搜索接口」档时，**联网与模型无关** —— 我们自己查好把结果当文本喂进去，
所以本地 Ollama（自己不会联网）照样能用，**桌面版现在就能用博查**，不需要回网页版。
网页版唯一多给的是「CORS 豁免」，但那只是把发起方从浏览器换成服务器，**不是让模型变聪明**；
且服务器也在国内，DuckDuckGo 在服务器侧同样到不了。
→ 要扩搜索源，正确做法仍是**桌面/便携加 IPC 转发（C）+ 自定义接口支持 GET+占位符（B）**。

## 第 12 批：B+C —— 搜索源扩到「任意 JSON 接口」

**需求（老大 2026-09-15 定）**：做 B+C，走免费可持续路线。

### B：自定义接口支持 `{query}` 占位符（GET）
- `webSearch.ts` 抽出 **`buildSearchRequest(settings, query, count)` 纯函数**（构造/发送分离，可脱离网络单测）：
  **地址含 `{query}` ⇒ GET**，否则 POST JSON `{query,count}`。一份配置覆盖两类接口，不用再加「方法」下拉框。
  `{count}` 也替换；检索词 `encodeURIComponent`（不编码接口收到乱码）。
- 🔴 选了 SearXNG 却给了没有 `{query}` 的地址 → **当场报错**，而不是 POST 过去再报「没返回结果」。
- 新增 **SearXNG 预设**：`http://127.0.0.1:8080/search?q={query}&format=json&language=zh-CN`。
  界面提示两个前提：① `settings.yml` 的 `search.formats` 要含 `json`（**默认只有 html**）；② 端口与 docker 映射一致。
  选了 SearXNG 时「密钥」栏自动收起（自建不需要密钥）。

### C：桌面版由主进程代发（`net:fetch`）
- `electron/main.cjs` 新增 `ipcMain.handle('net:fetch')`；`preload.cjs` 暴露 `window.electronNet.fetch`；
  `desktop.ts` 加 `ElectronNetAPI` / `HAS_NET_BRIDGE` / `netFetch()`。
- 主进程没有同源策略 → **CORS 这道坎在桌面版直接消失**，任何返回 JSON 的搜索接口都能接；请求不出本机。
- 🔴 边界收窄（它是通用 HTTP 客户端）：只允许 http/https（**拒 `file:`**，否则等于给渲染进程开读本地文件的口子）；
  剔除 `cookie/referer/origin/host/content-length`；限时 30s；响应超 2MB **流式中止**（不是先全读再判）；
  跟随重定向后校验最终 URL 协议；**永不抛**，失败返回 `{ok:false,error}`（跨 IPC 的异常会被重新包装、信息丢失）。

  `searchBlockedReason` 里加了提前提示（便携版选 SearXNG 会被跨域拦）。
- `tests/mock-desktop.ts` 补 `HAS_NET_BRIDGE=false` + `netFetch` 桩（Node 环境等价便携版）。
