## 踩坑记录（供后续执行参考）
1. **`/tmp` 路径坑**：git-bash 的 `/tmp` 与原生 Python 的 `/tmp` 不是同一目录。拉取服务端日志后必须 `cp` 到工作区绝对路径（如 `G:/AI软件/novel-studio开发源码/access_full.jsonl`）才能被原生 Python 读到；用 Grep 工具查 `/tmp/xxx` 也会落空。
2. **last_access_id 更新顺序 bug**：先 `lines[la_idx:la_idx]=insert` 再 `lines[la_idx]=新id` 会误改插入块里的空行（在条目中间留 stray `last_access_id` 行）。正确做法：用内容匹配删除所有非末尾的 `last_access_id:` 行，再把真正的末行改成新 id。
3. **rev 跨槽位混淆**：`too_large`/`authfail` 自测用的是另一个测试槽位 `1456edc9…`（rev 从 1 起），不能和主槽位 `4edd6fb4…` 的 rev 混算；要点里的 rev 范围只取主槽位 push。
4. **ts 去重基准**：文档正文不含 uuid id，仅存 ts/IP/动作。增量判定优先用「服务端第 last_access_id 行之后的行」，必要时用 ts 集合做差集复核（本次两者一致，76 条）。
5. 临时产物（access_full.jsonl / *.py）用后即从工作区 `rm -f` 清掉，避免污染 git。
