### 🔴 本次最重要的发现：「第二台接入会架空本地数据，但不是删除」

`db.ts:491 enableDesktopCloudSync(handle)` 的真实顺序：
1. `enableDesktopCloud(handle)` 建 FileTransport + `configure(DEFAULT_CLOUD_KEY)`
2. `pullDesktopSnapshot()` → `ensureInit()` 拉取云盘文件，`rev = 云端 rev`，`cache = 云端数据`
3. **仅当 `rev === 0 && Object.keys(stores).length === 0`** 才 `seedDesktopFromLocal()` 播种本地数据
4. `setStoreOps(desktopCloudFileStore)` → 此后所有读写走云盘 cache

结论：只要云盘目录里已有一份数据，**第二台机器本地原有的稿子不会播种上去**，UI 此后读的是
云盘那份 → 用户视角「稿子不见了」。但**本地 JSON 文件仍在磁盘上未被删除**，属于「架空」。
**救法：关闭云盘同步即切回本机存储，原稿回来。** 这点必须写进任何面向用户的说明。

### 其他确认的机制细节
- **轮询**：`syncCore.ts:637` `configure(c)` 里 `if (c) transport.startWatch(() => backgroundPull())`，
  FileTransport 每 **8 秒** 读一次 rev，变化则三路合并 `mergeCaches(baseCache, serverCache, cache)`（本地优先）。
- **写盘**：`nodeWrite` 优先走 Electron IPC `syncWrite`；回退分支用 tmp + .bak + rename 原子写。
- **冲突**：`push(baseRev)` 若 `cur.rev > baseRev` 返回 409 → 合并后按新 rev 重试；写后还有一次回读校验。
- **空推防护**：本地 cache 空但 baseCache 非空 → 抛错拒绝推送（#027/#030 防整库清空）。
- **状态灯**（`syncStatusMeta.ts`）：idle/syncing(黄闪)/ok(绿)/error(红)/auth-failed/rate-limited/
  too-large/offline(灰，编辑留本机，恢复后自动接管)。
- **轮询盲区（真正的 kill scenario）**：A 写完关机但云盘未传完 → B 打开读到**旧 rev** → B 编辑后
  `cur.rev === baseRev` 不触发 409 → **直接覆盖 A 的改动且不报冲突**。所以「换设备前必须等网盘
  同步完成」不是建议，是硬纪律。

### 给老大的两条路径判据（已画成图）
1. **内置云盘同步**（推荐）：数据坞 → 云盘文件同步 → 选目录 → 生成 `青春幻想引擎-同步数据.yfe`，
   加密 + rev 合并 + 原子写。适合多设备、有并发编辑需求。
2. **#033 更改数据文件位置**：数据坞 → 本机存储 → 更改位置 → 把 `novel-studio-data.json` 挪进网盘目录，
   网盘做**文件级整库覆盖、无合并**。适合单机轮流用、图省事。
   ⚠️ **两条路绝对不要同时指向同一目录**，否则两个文件 + 两套机制在同一目录打架。

## 🔄 更正 + 执行（2026-09-02）：关服准备项老大裁定 + P0-1 已修

### ⚠️ 推翻上面那段判断：便携版写盘本来就是原子的
上一段写「FSA 无 rename、便携版非原子写会损坏数据文件、发 2.0 前必须处理」——**这个判断错了**。
查 MDN `FileSystemFileHandle.createWritable()`：*"This is typically implemented by writing data
to a temporary file, and only replacing the file represented by file handle with the temporary
file when the writable file stream is closed."* 即 **swap file 语义本就内置**，写到一半拔盘最坏
留一个 `.crswap` + 数据退回上一版，**不会**产生半截 JSON。便携版只支持 Chrome/Edge（见
`isFSASupported`），两者均按此实现。
**结论：不要在便携版重复实现 tmp+rename。**
> 教训：下结论前先查规范/权威文档，别拿桌面版 IPC `writeAtomic` 的做法往浏览器 API 上类推——
> 两次误判都栽在「以为浏览器 API 和 Node fs 一样裸」。

### 真问题换了个位置：最后一批编辑来不及落盘（#034，已修 提交 315d472）
